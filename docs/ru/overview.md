# Обзор

MAIster — это control plane для AI-разработки. Он не заменяет Claude Code,
Codex или другие coding agents. Вместо этого MAIster даёт над ними рабочую
оболочку: проекты, доски задач, запускаемые Flow, изолированные workspaces,
человеческие подтверждения, журнал событий, diff и безопасное приземление
изменений в целевую ветку.

## Зачем нужен инструмент

Когда AI-агенты запускаются вручную, рабочий процесс быстро распадается:

| Боль | Что делает MAIster |
| ---- | ------------------ |
| Много терминалов и потерянный контекст | Показывает портфель проектов, активные workspaces и единый inbox |
| Неповторяемые прогоны | Запускает задачи через версионированные Flow-пакеты |
| Непонятно, что сделал агент | Сохраняет run, логи, события, артефакты, evidence и diff |
| Агенту нужно разрешение | Выводит HITL-запросы в UI и возвращает ответ в живую ACP-сессию |
| Риск испортить рабочую копию | Создаёт отдельный git worktree на run |
| Нужно несколько агентов | Поддерживает ACP runners: `claude`, `codex` и readiness-gated адаптеры |
| Нужно контролировать стоимость и автономность | Использует бюджеты, политики, readiness-гейты и review-поток |

Главная идея: агент делает работу не в “чёрном ящике”, а внутри управляемого
процесса, где человек видит состояние, может вмешаться и принимает итоговый
diff перед merge.

Часть адаптеров, включая Gemini, OpenCode и MiMo, нельзя считать готовыми
только потому, что они добавлены в каталог: их запуск проходит через readiness
diagnostics и сохранённое ACP smoke evidence.

## Что можно делать в MAIster

- Зарегистрировать несколько проектов и видеть их в одном портфеле.
- Создать задачу в backlog проекта и запустить её через выбранный Flow.
- Запустить scratch-сессию для свободной работы агента вне board-задачи.
- Ответить на HITL-запрос: разрешение, форма, комментарии для доработки.
- Открыть run, посмотреть ход выполнения, workspace, evidence, timeline и diff.
- Принять работу: локальный merge или PR-mode promotion, если настроен провайдер.
- Управлять runners, Flow-пакетами, MCP, агентами и настройками инстанса.

## Где границы

MAIster — это не новый агентный runtime. Агентные процессы живут снаружи:
`claude-agent-acp`, `codex-acp` и другие ACP-адаптеры выполняют работу.
MAIster отвечает за оболочку вокруг них: запуск, состояние, доступы,
изоляцию, UI, события, HITL и интеграцию с git.

## Основные экраны

| Экран | Для чего нужен |
| ----- | -------------- |
| Portfolio `/` | Обзор проектов и активных workspaces |
| Project board `/projects/{slug}` | Backlog, задачи, запуск Flow, проектный inbox |
| Runs `/runs` и `/runs/{id}` | История и детали прогонов |
| Scratch run `/scratch-runs/{id}` | Свободная агентная сессия |
| Inbox `/inbox` | Все pending HITL и упоминания |
| Studio `/studio` | Flow-пакеты, локальные пакеты, редактор Flow |
| Settings `/settings` | ACP runners, Brain, webhooks, системные настройки |
