# Ключевые понятия

Эта страница помогает читать интерфейс и документацию MAIster без погружения в код.

## Project

Project — зарегистрированный внешний git-репозиторий. Он описывается
`maister.yaml`: имя, путь к репозиторию, ветка по умолчанию, префикс для
веток, Flow-пакеты и настройки исполнителей. Один `repo_path` соответствует
одному Project.

## Flow

Flow — воспроизводимый сценарий доставки: какие шаги выполнить, какого агента
запустить, где нужны проверки, формы, проверка человеком или consensus. Flow
может быть установлен из пакета или источника и привязан к проекту по версии.

## Task

Task — работа в Backlog проекта. У задачи есть запрос и выбранный Flow.
Связь Task к Run — один ко многим: одну задачу можно запускать повторно,
получая новые попытки.

## Run

Run — конкретная попытка выполнить задачу или scratch-сессию. Run хранит
статус, снимок исполнителя, рабочую копию, события, HITL, доказательства и
итоговые изменения.

## Workspace

Workspace — изолированная рабочая копия, чаще всего `git worktree`. Агент
меняет код не в основной директории репозитория, а в рабочей копии конкретного
Run. Это снижает риск смешать чужие изменения и упрощает проверку.

## Supervisor

Supervisor — отдельный Fastify-процесс на Node.js. Он владеет ACP-сессиями,
запускает исполняемые файлы адаптеров, следит за живостью процессов,
принимает ответы на запросы разрешения и публикует события через HTTP+SSE.
Веб-интерфейс не запускает агентов напрямую.

## ACP

ACP (Agent Client Protocol) — стандартный протокол взаимодействия с агентами.
Для MAIster это граница между центром управления и реальным агентом
разработки. Благодаря ACP можно поддерживать разные адаптеры: Claude, Codex и
другие совместимые среды выполнения.

## Runner

Runner — настроенный способ запустить агента: адаптер, модель, провайдер,
политика разрешений, sidecar и готовность. На практике Runner отвечает на
вопрос: “каким агентом и с какими настройками выполнять этот узел или Run?”

## HITL

HITL (human-in-the-loop) — момент, когда Flow или агент ждёт человека.
Это может быть разрешение или запрет, заполнение формы, комментарии к
доработке или ручной перехват. HITL делает автономность управляемой, а не
бесконтрольной.

## Evidence

Evidence — проверяемые артефакты результата: изменения, логи, проверки, вывод
узла, комментарии проверки и сводка готовности. MAIster использует Evidence,
чтобы человек принимал итог не на вере, а по наблюдаемым данным.

## Package

Package — поставка нескольких Flow, навыков, агентов и связанных файлов из
git-источника. MAIster хранит установки как неизменяемые версии и позволяет
доверять, подключать и обновлять пакеты контролируемо.

## Статусы Run

| Статус | Значение |
| ------ | -------- |
| Pending | Ждёт свободный слот выполнения |
| Running | Выполняется сейчас |
| NeedsInput | Ждёт человека, сессия ещё жива |
| NeedsInputIdle | Сессия сохранена в checkpoint, ответ человека возобновит Run |
| HumanWorking | Человек забрал `worktree` в ручную работу |
| Review | Работа остановлена для проверки: агент вышел успешно или оператор остановил Run |
| Crashed | Процесс или сессия оборвались |
| Failed | Агент завершился с ненулевым кодом без пути восстановления |
| Done | Работа завершена и принята |
| Abandoned | Run остановлен и больше не продолжается |

Ручной перехват, восстановление и сброс — это отдельные переходы между
статусами. Например, `Crashed` можно попытаться вернуть в `Running` через
`recover`, а `HumanWorking` возвращается в автоматический путь только после
явного `return`.
