# ADR-216: Durable Flow waits

> Part of the ADR log. See the [index and editing rules](../decisions.md).

**Date:** 2026-11-20
**Status:** Implemented

**Context:** A graph needs to await an external or timed fact across web and
host restarts without keeping an ACP process and a scheduler slot.

**Decision:** Record an occurrence in `run_waits`, owned by the project, run
and exact attempt. The compiler verifies a finite outcome vocabulary and
bounds cycles. Serialize resolution, result evidence and Pending wake in one
transaction. Admission retains the assigned host and mints the next epoch.
Use one domain resolver and the scheduler's clock. Restrict token authority
to named signal delivery. Preserve session-authorized actions and audit
overrides separately from source attestations.

**Consequences:** Waiting participates in activity and workspace retention.
Its duration is excluded from execution. A restart resumes from the
durable occurrence, producer fact and command receipt. A related run can
satisfy a wait within the same project.

**Alternatives considered:** Hold an executor while idle, or use separate
state machines for timer, comment and signal. Both add unnecessary ownership
and recovery paths.

See [the wait state machine and acceptance contract](../system-analytics/waits.md)
and [ADR-166](adr-166.md), [ADR-167](adr-167.md), [ADR-180](adr-180.md) and
[ADR-208](adr-208.md).
