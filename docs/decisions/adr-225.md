# ADR-225: Root client-message pruning

> Part of the ADR log. See the [index and editing rules](../decisions.md).

**Date:** 2026-11-25
**Status:** Implemented

**Context:** The root layout rendered `NextIntlClientProvider` without a
`messages` prop. next-intl then inherits the whole request catalog, so every
document and every `router.refresh()` Flight payload serialized the complete
EN (about 310 KB minified) or RU (about 486 KB minified) catalog, although
most strings are resolved on the server through `getTranslations()`.

**Decision:** The root provider receives only the message paths that
client-reachable code reads:

- `web/i18n/client-namespaces.ts` exports `CLIENT_NAMESPACES`, the minimal
  covering set of the literal namespaces passed to client `useTranslations()`.
  A dotted path (`run.runStatus`) is used whenever no client code asks for its
  parent namespace.
- `web/i18n/pick-messages.ts` copies those paths out of the request catalog by
  reference. An unknown path throws outside production and is omitted with a
  WARN in production.
- `web/app/layout.tsx` is the only production `NextIntlClientProvider`.
- A repository test computes the minimal cover of client-reachable
  `useTranslations` literals and requires `CLIENT_NAMESPACES` to equal it.

Owner decision (2026-11-25): optimize the root provider only. Per-route
providers are deferred to Phase 2 because the tabbed UI is being regrouped
into sections and route-level owners would churn.

**Consequences:**

- Choosing paths at namespace granularity saves at least about 16% of the
  catalog per document and per refresh; dotted subkeys raise the saving where
  the client uses part of a large namespace. The large saving needs Phase 2
  per-route scoping.
- A missing client message does not throw in next-intl: it logs
  `MISSING_MESSAGE` and renders `namespace.key`. The equality test is
  therefore the enforcement point, backed by an E2E console check.
- Adding a client `useTranslations("ns")` requires adding `ns` to
  `CLIENT_NAMESPACES`; the equality test fails until the list is updated and
  prints the expected list.
- Server components keep reading the full request catalog through
  `getTranslations()`.

**Alternatives considered:**

- *Per-route providers.* Deferred to Phase 2 because of the UI regrouping; a
  nested `messages` set replaces its parent instead of merging, so every
  owner would need the shell's paths too.
- *`messages={null}`.* Rejected: the shell's client components need messages.
- *A client `onError` that throws.* Rejected: functions cannot cross into the
  client provider from a server component.
- *Key-level pruning.* Rejected: dynamic keys such as `t(status)` make a
  static key inventory unsound.

**Amendments:**

- 2026-11-28 — Validation recomputed at HEAD. The saving is 15.5% (EN) and
  15.1% (RU) of the catalog, not the "at least about 16%" stated in
  Consequences: the earlier figures were taken on the pre-rebase catalogs, and
  the minimal cover is 56 paths. Per document that is about 50 KB EN / 77 KB RU,
  roughly 6% and 8% of the measured `/` document. 17 client components still call

  every payload; converting them to dotted subkeys needs no per-route provider

  conversion is only verifiable in the browser.
