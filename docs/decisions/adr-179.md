# ADR-179: MCP configuration values — literal-or-reference env/header maps, a bearer token field, value-replacing project overlays, host env-ref readiness, and an adapter transport gate

> Part of the ADR log — hub, index, and editing rules: [`../decisions.md`](../decisions.md).

**Date:** 2026-09-21
**Status:** Accepted

**Context:** The platform and project MCP forms show env and header entries as a
single column of NAMES because that is what the model stores: `env_keys` and
`header_keys` are name lists, and the supervisor resolves each name out of its
own environment. Five defects follow from that one modelling choice, none of
them caught by the current suites. The full analysis, the owner's decision
session, and the alternatives are in the design doc
[`../plans/2026-09-21-mcp-configurator-env-model-design.md`](../plans/2026-09-21-mcp-configurator-env-model-design.md)
(D1–D12 frozen there); this record states the decision and the consequences.

1. **`Authorization: Bearer <token>` cannot be expressed.** The supervisor sends
   one header per key whose NAME is the env-var name and whose VALUE is that
   variable's value (`supervisor/src/acp-client.ts`). The MCP authorization spec
   fixes the header name and the `Bearer` scheme, so no authenticated remote MCP
   is reachable.
2. **No non-secret literal can be passed** (`FASTMCP_LOG_LEVEL=ERROR`, a flag
   value) without an operator first defining a host variable.
3. **The per-project overlay renames the child variable.** `applyMcpOverlays`
   replaces the KEY `GITHUB_TOKEN` with `PROJ_A_GH`; the server never receives
   the variable it reads. The behaviour is green in CI and wrong in production.
4. **Readiness is falsely red.** `evaluateMcpReadiness` flags every name absent
   from the supervisor's fixed `GET /diagnostics.envRefs` list, which enumerates
   provider credentials — so every MCP referencing `env:GITHUB_TOKEN` is
   `NotReady` until an operator edits an unrelated supervisor variable.
5. **SSE breaks a codex session.** `codex-acp` 1.10.0 `createMcpSeverConfig`
   throws `invalidRequest` for transport `sse`, failing `session/new` for the
   WHOLE session. `adapter-support.ts` declares `sse` for all five adapters and
   `mcpTransports` is read nowhere, so the "agent-unsupported transport"
   edge case in `mcp-management.md` was documented, never implemented.

Two ground-truth facts shape the decision and are not visible from the defect
list. First, a literal-value channel **already exists end-to-end**, keyed `env`:
`McpServerInputSchema` carries `env: Record<string,string>` (the ADR-089 channel
for the server-generated facade credentials) and `acp-client.ts` already merges
it over `envKeys`. The change is therefore a *collapse* of two fields into one
map whose values are `literal | env:NAME`, not the introduction of a map.
Second, `capability_records.material` for `kind='mcp'` holds three different
shapes today (project rows, platform-from-YAML rows, and package requirement vs
template rows), and `resolveBindTarget` reads only `material.envKeys` — so an
overlay against a package TEMPLATE can name no slot at all.

**Decision:**

**One value grammar, one validator.** Every MCP value — platform row, project
row, package manifest, binding overlay — is whole-value `literal | env:NAME`
(`^env:[A-Za-z_][A-Za-z0-9_]*$`), with no interpolation: a literal containing
`${X}` reaches the server unchanged. A value that starts with `env:` and fails
the regex is refused (`CONFIG` 422 web-side, `PRECONDITION` 409 supervisor-side);
an unset reference resolves to `""`. Keys are env names
`^[A-Za-z_][A-Za-z0-9_]*$` and RFC 7230 header tokens; a LITERAL header value is
additionally held to the RFC 7230 field-value alphabet so CR/LF never reach a
`fetch`. The canonical grammar table lives in
[`../configuration.md`](../configuration.md); the single implementation is
`web/lib/mcp/value-grammar.ts` (isomorphic, consumed by the form, the four
routes, the binding schemas, the package manifest and the Studio editor) with
`supervisor/src/types.ts` reusing its existing `runnerEnvValueSchema` twin. This
replaces the three `env:` grammars and the four verbatim copies of the MCP one.
A literal is the operator's declaration that the value is not a secret; the form
warns inline under secret-shaped keys and the routes accept the value (D9).

**Wire and storage.** `env: Record<name, value>` and `headers: Record<name,
value>` replace `envKeys`/`headerKeys` on `platform_mcp_servers`, on
`capability_records.material` for every source, in `AgentMcpServer`, and on the
supervisor's `POST /sessions` and `POST /mcp-probe` bodies, in one cut-over with
no legacy acceptance (D12). Bearer auth is a dedicated `bearerTokenEnv`
(`env:NAME`, http/sse only) which the supervisor composes into
`Authorization: Bearer <value>` LAST; declaring it alongside an `Authorization`
header row is refused on both sides (D10). A `description` column lands beside
them. Normalization is by transport on both sides: stdio drops
`url`/`headers`/`bearerTokenEnv`, sse/http drop `command`/`args`/`env`.

**Overlays replace values, never keys.** `envRemap`/`headerRemap` keep their
wire shape and their write-time slot validation, but application replaces the
VALUE for a declared key and preserves the KEY — which is what the operator
always meant. Overlay values use the same grammar as server values, so a project
can point one key at a different host variable OR at a plain literal such as a
`GH_HOST` override. `bearerTokenEnv` is overridable for http/sse targets.
Existing rows stay valid and are not rewritten by the migration. Slots are the
keys of the target's `env`/`headers` maps, which closes the package-template
defect by construction.

**Readiness is host-scoped presence.** A new unauthenticated supervisor route
`POST /diagnostics/env-refs` answers `{ names[] } → { refs: [{name, present}] }`
— presence only, values never returned, at most 64 names per call, one entry per
distinct name in request order, malformed names refused 409.
`HostAdminClient.checkEnvRefs(names)` dedupes and chunks to that cap and merges
in request order, so a caller may pass any number of names. `evaluateMcpReadiness(row, { presence,
adapters })` collects names from `env:` values across `env`, `headers` and
`bearerTokenEnv` — a literal never produces a reason — and keeps the adapter
gate unchanged. The result is cached at WRITE time on all three row kinds:
platform rows in `readiness_status`/`readiness_reasons`, project rows in
`material.readiness` on create/update, package rows in `material.readiness` at
attach/upgrade ingestion. The host reads happen before the transaction and any
failure yields `Unknown` plus one WARN — they are reads, never side effects.
Reasons are rendered, not merely stored. `GET /diagnostics.envRefs` is untouched
and stays the runner-readiness source.

**The adapter transport gate becomes real.** `mcpTransportsForAdapter(adapter)`
is the accessor for the previously dead `mcpTransports` data; codex is corrected
to `["stdio","http"]` (verified against the shipped `codex-acp` binary), claude
keeps `["stdio","sse","http"]` (also verified), and the remaining three carry an
explicit unverified marker. A REQUIRED ref whose transport the adapter cannot
use refuses the launch at the existing precondition
(`firstAgentUnsupportedRequiredMcp` → `EXECUTOR_UNAVAILABLE`), before a worktree
or a run row exists; an ADDITIONAL ref is withheld by a third
`partitionWithheldMcps` pass with the persisted reason
`agent-unsupported-transport`, after the two trust passes. `sse` remains
creatable, labelled `sse (legacy)`.

**One gate for every launch surface.** `gateAndOverlayMcpServers` claimed in its
own header to be shared by flow, agent and scratch launches; scratch in fact
handed `materializeCapabilityProfile` output straight to the create payload,
bypassing trust, overlay and now transport. Both scratch launch sites are routed
through the shared gate. The local-package assistant launch has no project and
therefore no catalog MCPs; that remains a proven non-path, not an exemption.

**`maister.yaml` values are carried.** `capabilities.mcps[].env/headers` values
reach `capability_records.material` under the shared grammar rather than being
reduced to their names. The YAML is the operator's own host file, at the same
trust level as `supervisor/.env`; the D1 declaration applies, and
`configuration.md` states the exposure: a literal YAML value is returned by
`GET /api/projects/{slug}/mcp` to every caller that passes the catalog read gate.

**Migration.** One migration `0172_mcp_env_values` adds the four columns,
backfills both key spellings (`env_keys` rows hold `GITHUB_TOKEN` and
`env:GITHUB_TOKEN` alike, so every derivation strips `^env:`), rewrites all
three `capability_records.material` shapes to the map form, and drops
`env_keys`/`header_keys`. The backfill is fully SQL-derivable, so there is no
abort guard. Overlay rows are untouched.

**Consequences:**

- An authenticated remote MCP server is reachable for the first time, and a
  non-secret literal no longer forces an operator to define a host variable.
- The overlay stops corrupting the child environment. Any project that relied on
  the rename behaviour was already broken in production; nothing that worked
  stops working.
- Readiness answers the question it claims to answer, against the host that will
  actually run the server, with the reason visible in the UI.
- codex + `sse` fails at launch with a named cause instead of killing the whole
  ACP session at `session/new`. The required-vs-additional distinction now covers
  two reasons — `supported_agents` and transport.
- **Accepted exposure.** `POST /diagnostics/env-refs` is a presence oracle for
  host environment variable names, bounded by the 64-name cap and the name regex
  and returning no values. It inherits `GET /diagnostics`' unauthenticated
  posture (ADR-166); supervisor host auth (Stage D) closes both together.
- **Accepted exposure.** A literal value is stored and returned in catalog reads.
  That is the point of D1 — the operator declares it is not a secret — and the
  UI warns under secret-shaped keys. The invariant that survives unchanged:
  MAIster never stores, returns, streams or logs the value behind a REFERENCE.
- The package manifest relaxes from uppercase-only `env:NAME` to the shared
  case-insensitive grammar and gains `headers` / `bearerTokenEnv`, additively,
  with no `schemaVersion` bump; the legacy `string[]` form stays accepted and is
  normalized to a map at load, so `attach.ts` and Studio see one shape.
- OAuth stays a note (D8): the Agent SDK does not run the flow, our supervisor
  advertises only `fs` client capabilities, and `bearerTokenEnv` covers
  pre-obtained static tokens. The feature earns its place with platform-wide
  per-user token issuance, not before.
- JSON import of `.mcp.json`-shaped configs and an ACP-shape preview are
  deferred (D5); the source formats and the mapping are recorded in the design
  doc's §10 so the later work starts from research, not a blank page.
- The facade entry is appended to `mcpServers` by a plain concat with no dedupe
  by name; ADR-089 precedence holds only because no catalog server is named
  `maister`. Unchanged here, and recorded as the known trap it is.

**Alternatives Considered:**

- **Resolve values web-side and push them to the host:** rejected — it puts
  secrets on the web→supervisor wire, into the command ledger's input payload,
  and into web process env. Host-side resolution is the invariant.
- **Refuse literals and keep `env:NAME`-only:** rejected — it is the status quo
  that forces a host variable for `FASTMCP_LOG_LEVEL=ERROR`, and it cannot be
  reconciled with the runner `env` precedent (ADR-065), which has accepted
  literals since it shipped.
- **A server-side refusal for secret-shaped literals:** rejected (D9) — the
  heuristic has no honest false-positive story (`TOKENIZER_MODE`), and a refusal
  the operator cannot override converts a warning into a support ticket.
- **Keep the overlay renaming keys and teach servers the new names:** rejected —
  the child variable name is the server's contract, not ours.
- **A dual-accepting supervisor schema (`envKeys` OR `env`):** rejected as the
  end state (D12) — one supported host, both processes deployed from one commit,
  and a permanently dual schema is a permanent ambiguity. One intermediate
  commit accepts both so every commit on the branch stays bisectable; the
  branch tip does not.
- **Per-host readiness matrix:** deferred — presence is host-scoped by
  construction; with one registered host a matrix is shape without content.
- **An `Authorization` header row instead of a `bearerTokenEnv` field:**
  rejected — the MCP authorization spec fixes the name and the scheme, so a free
  header row makes every operator retype a constant and gets the `Bearer ` prefix
  wrong. Non-standard API-key headers stay ordinary header rows.
