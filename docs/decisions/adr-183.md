# ADR-183: Outbox pressure means the manager is behind

> Part of the ADR log — hub, index, and editing rules: [`../decisions.md`](../decisions.md).

**Date:** 2026-09-26
**Status:** Implemented

> **Amends [ADR-167](../decisions.md#adr-167-durable-execution-host-event-and-runtime-data-plane)**
> (D2: the replay grace is a retention target, cut short under retained
> pressure; D4: backpressure refuses new work only, and only while rows are
> unacknowledged), **[ADR-180](../decisions.md#adr-180-permission-deadline-has-one-owner)**
> (a second host-initiated checkpoint cause, `outbox_pressure`; a host park no
> longer needs an open deferred) and
> **[ADR-161](../decisions.md#adr-161-operator-node-interrupt-with-corrective-restart)**
> (a system-caused `node_interrupt` answered by the manager itself; `resume`
> claims through `claimGraphResumeSlot` and keeps the node's ACP context). Each
> record carries a dated amendment bullet.

**Context:** The execution host's SQLite outbox has two row counts per
partition: *retained* (every row still on disk) and *unacknowledged* (rows the
manager has not yet ACKed). ACKed rows stay retained for a 24 h replay grace
before the hourly pruner removes them. Before this decision the soft-pressure
bit was set when EITHER count reached the soft budget, and the bit did four
things at once: it refused every command without a teardown admission
(`session.create`, `session.prompt`, `session.input`, `session.steer`,
`workspace.adopt`, runtime-object writes), it paused every producer's next ACP
frame, it moved completion evidence onto producer wallets, and it was reported
on `/health?includeStream=true` as `stream.pressured`.

Four defects followed, all measured or read on `881619a5`:

- **A healthy stream tripped it.** The R20 load harness, whose manager kept up
  (lag 46–60 rows), crossed the 80 000-row soft budget with *retained* rows in
  about 3.4 minutes at ~394 rows/s. The harness raised the three row budgets to
  pass. At the defaults, any busy host enters "pressure" once a day's traffic
  sits in the grace window, although the manager is fully caught up.
- **The operator's answer was refused.** `session.input` and `session.steer`
  carried no teardown admission, so the soft gate refused a permission answer —
  the one command that lets a paused turn finish.
- **A paused producer froze without bound.** A producer waiting for frame
  capacity waited forever. While it waited the host emitted nothing for its
  open prompt, and after `MAISTER_EVENT_STREAM_STALL_SECONDS` (300 s) the
  manager's stall pass repaired and then degraded the stream to `lost`, and
  reconcile crashed the run `stream-lost`.
- **The manager read `pressured` nowhere.** The health sample was fetched every
  sweep and discarded; no admission, stall, driver or admin decision branched
  on it, and the host's refusal reached the run as an ordinary definitive
  `PRECONDITION` failure.

**Decision:** Outbox pressure means exactly one thing — **the manager is
behind**: unacknowledged rows reached the soft budget. Retained rows are
housekeeping with a retention target. The soft gate refuses new work and never
an answer or a teardown. A paused producer has a bound that ends in ADR-180's
graceful checkpoint. The manager records pressure durably and treats a host
park as a pause it resumes itself.

**D1 — Pressure is unacknowledged-only (host).** `refreshOutboxPressure`
enters `pressured` when `unacknowledgedCount + reservedFrameRows ≥
eventSoftRows` or `unacknowledgedBytes + reservedFrameBytes ≥ eventSoftBytes`,
and clears only when BOTH lanes are below `eventLowRows` / `eventLowBytes`.
Retained counts leave the predicate. A frame reservation stays in the
unacknowledged lane, because a reserved frame cannot have been ACKed. The two
threshold tests are separate exported predicates, `unacknowledgedAtThreshold`
and `retainedAtThreshold`.

**D2 — The pressure episode is host state.** `runtime_event_pressure` (host
SQLite schema v14) records `since_ms`, `unacknowledged_count_at_start` and
`unacknowledged_bytes_at_start` on the 0→1 flip, clears them on the 1→0 flip
and increments `episodes` on it; `since_ms` is non-null exactly while
`pressured = 1` (a CHECK). `/health?includeStream=true` adds
`stream.pressure: {since, unacknowledgedCountAtStart,
unacknowledgedBytesAtStart, episodes}` while pressured and `null` otherwise.
`stream.pressured` is the unacknowledged bit and nothing else: runtime-file
pressure and physical SQLite headroom keep their own refusals
(`runtime_storage_pressure` 503, `event_outbox_backpressure` 409 for physical
admission) and never set it. Every flip logs `outbox-pressure-changed`.

**D3 — Retained rows are housekeeping (host).** The 24 h replay grace is the
retention *target*. When retained rows reach the soft budget (either lane) the
pruner runs a `retained_pressure` pass: the cutoff is "any confirmed-ACKed
row", with the same bounds as the grace pass — at most 100 rows and 1 MiB per
`BEGIN IMMEDIATE` page, oldest-first, a contiguous prefix only, never at or
beyond the smallest `accepted_sequence` of a v2 command whose terminal is not
yet ACKed, never an unacknowledged row — and it stops when retained rows are
below the low budget in both lanes or a page finds nothing prunable. Between
pages it yields (`setImmediate`), so ACK and publisher writes interleave with
it. The trigger is every committed capacity change (an ACK, an append, a
receipt), not only the hourly timer, which stays as the grace-mode backstop;
kicks coalesce to one pass in flight. The replay floor advances only over rows
a page deleted, so it never passes the manager's confirmed watermark. A pass
that prunes nothing because a protected span or an unacknowledged prefix pins
the oldest rows logs `outbox-retained-pressure-prune-stalled` once per episode,
and the hard bound stays the last line. A completed episode logs
`outbox-retained-pressure-prune` with pages, rows and duration.

**D4 — Hard stays retained, physical stays physical.** The hard bound is
unchanged: `retained ≥ eventHard*` refuses every non-teardown admission and
every frame reservation. `MAISTER_EXECUTION_HOST_STATE_MAX_BYTES` and the
runtime-file budget keep their own admission paths.

**D5 — One admission table, one closed enum.** Every receipt names its
admission; there is no default.

| Command / receipt | Admission | Soft (unACKed pressure) | Hard (retained ≥ hard) | Physical / file pressure |
| --- | --- | --- | --- | --- |
| `session.create` | `producer` (wallet) | refuse | refuse | refuse |
| `session.prompt` | `new_work` | refuse | refuse | refuse |
| `workspace.adopt`, `runtime_object.reserve`, `runtime_object.upload` | `new_work` | refuse | refuse | refuse |
| `session.input` | `resolve` | **admit** | refuse | refuse |
| `session.steer` | `resolve` | **admit** | refuse | refuse |
| `session.cancel`, `session.checkpoint`, `session.delete` — whatever the session record's liveness | `teardown` | admit | admit | admit |
| `workspace.release`, `runtime_object.delete` | `teardown` | admit | admit | admit |
| producer frame (`beforeFrame`) | `producer` | pause, bounded (D6) | refuse the reservation → drain / terminal wallet | — |

A refusal is `409 PRECONDITION` with `details.reason:
"event_outbox_backpressure"` and writes no receipt; it logs
`outbox-admission-refused` once. A teardown whose session still owns an open
producer wallet takes that wallet's terminal credit exactly as before; a
teardown with no open wallet (an exited session, a workspace, an object) is
admitted without credit. A `resolve` command's events are funded from the
regular partition, never from the producer wallet, so answers cannot drain the
credit a producer needs for its own terminal evidence. The unused
`assertCanAcceptMutatingCommand` is deleted.

**D6 — A paused producer is bounded.** A producer that waits for frame capacity
records `outputPausedSince` and arms one unreferenced timer of
`PRODUCER_PAUSE_MAX_MS = 5 min` (a code constant, not an env var). If the
producer is still paused when it fires, the host runs ADR-180's
`checkpointSession` with `cause: "outbox_pressure"`: pending deferreds are
cancelled as `checkpoint` (a late `/input` then answers `410
session_checkpointed`), the session is marked intentional, output teardown
drains the captured frames onto the credited wallet, SIGTERM, and
`session.exited{reason: "checkpoint", cause: "outbox_pressure"}`; SIGKILL only
after the kill grace. The bound equals one stall window, is ≥ 7× the row-lane
drain and ≈ 2× the byte-lane drain at the measured manager throughput, and a
shorter bound would multiply the ~$0.28 respawn cost under brief pressure.
It logs `producer-pause-exceeded` once. `CheckpointCause` and the AsyncAPI
`cause` become the enum `permission_cap | outbox_pressure`.

**D7 — The interrupted prompt names the park.** When a prompt's ACP call fails
because its session was intentionally checkpointed, its rejection receipt keeps
`code: "ACP_PROTOCOL"` and gains `details: {reason: "session_checkpointed",
cause}` — the token the `/input` route already mints. The ADR-180 order holds:
`session.exited` first, the rejection after.

**D8 — The manager keeps a pressure record.** Migration `0182` adds
`execution_hosts.pressured_since` and `pressure_unacknowledged_at_start` (a
CHECK: the second requires the first). Two writers: the `system_sweep`
observation step sets `pressured_since` (preserving an earlier value) from a
health sample with `pressured: true` and clears both from one with `pressured:
false`; and the command deliverer, on a `PRECONDITION` refusal whose
`details.reason` is `event_outbox_backpressure`, sets `pressured_since = now()`
where it is NULL, before rethrowing. A successful ACK never clears the record —
the host is the authority. The manager's own token for this state is
`host_pressured`; the host's refusal token stays `event_outbox_backpressure`.

**D9 — Admission fence.** Every reader of the concurrency cap goes through one
helper, `effectivePoolCap`, which answers a zero cap with fence `host_pressured`
while the local host's record is set. A launch is queued `Pending` with
`queueReason: "host_pressured"` (`POST /api/runs` still answers 201, never
503), an idle resume stays queued (`resume_requested_at`), and a parked agent
stays parked. When the sweep clears the record it calls `promoteNextPending`
for each pool, which starts the queued launches and resumes.

**D10 — The stall pass classifies pressure.** A silent stream with open
commands on a `ready` host whose record is set is `pressured`: counted in the
stream-health summary, logged `runtime-event-stream-pressured`, never repaired
and never degraded to `lost`. An unreachable host is not `ready` and keeps the
existing rules.

**D11 — A host park is a pause the manager resumes (per run kind).** The
manager recognises a host park from D7's token (`isHostParkedPromptRejection`)
or from the create/prompt refusal of D5, and the token is checked before the
ambiguous-outcome (`turn_lost`) arm.

- *Flow run.* The node's prompt completion is persisted as
  `{ok: false, errorCode: "EXECUTOR_UNAVAILABLE", reason: "host_pressured"}`,
  and the runner's common failure branch parks instead of failing the node: an
  ADR-161 `node_interrupt` whose `schema` carries `cause: "host_pressure"` and
  `actor: {type: "system"}`, the run `Running → NeedsInput`, the SAME attempt
  `NeedsInput`, and `node_attempts.action_resume = {kind: "interrupt", cause,
  acpSessionId, assignmentId, ordinal}` so the resumed node restores its ACP
  context. The keep-alive sweeper idles it to `NeedsInputIdle` as any other
  park. When a health sample reports `pressured: false` the sweep answers each
  open host-pressure interrupt `resume` itself — at most 25 per tick, oldest
  first, under the row lock and the `responded_at` idempotency guard — through
  the same internal application the operator's `resume` uses
  (`applyNodeInterruptResume`), never through `respondToHitl`. The answer
  records `response = {optionId: "resume", actor: "system", cause}`.
- *Agent run.* The owner application supersedes the parked turn with a
  successor carrying the same variant and prompt (`message:requeue:<turnId>`)
  and parks the run through the existing agent park (`NeedsInputIdle`,
  `resume_requested_at`, assignment released `parked`), now for one-shot runs
  too; the agent continuation worker resumes it with `session/resume` once the
  fence lifts. The message is delivered at least once.
- *Scratch dialog.* The retryable arm records `error_metadata.cause =
  "host_pressure"` and the dialog shows a notice; the send-time resume of a
  checkpointed scratch session is A4's.

**D12 — `resume` claims a slot and keeps the context (widened).** ADR-161's
`resume` answer called a bare `scheduleResume`, which only claims `Running |
NeedsInput`, so a `resume` given after the keep-alive sweeper idled the run was
a silent no-op; and it re-entered the node on a fresh ACP session because no
resume handle was written. Both are fixed for every interrupt, operator or
system: `resume` claims through `claimGraphResumeSlot` (cap-checked, queued as
`resume_requested_at` when full), and every interrupt park writes the
`action_resume{kind: "interrupt"}` handle when a session exists. A
`node_interrupt` is still answerable only by a human through `respondToHitl`;
the sweep's system answer is a server-internal call with no token, route or
body field.

**Recovery windows (normative).**

| # | State after the crash or gap | Owner that finishes it |
| --- | --- | --- |
| W1 | Host parked; `session.exited{cause}` and the rejection not yet ingested | catch-up ingest → lifecycle projector → owner application classifies (D11) |
| W2 | Rejection folded, park transaction not committed | prompt-owner worker re-applies; reconcile skips on the evidence |
| W3 | `NeedsInput` interrupt, incarnation `checkpointed`, not yet idled | keep-alive Pass 1b (idempotent CAS) |
| W4 | Auto-resume answered, claim not taken | the HITL already-delivered self-heal through `claimGraphResumeSlot`; over cap, `resume_requested_at` for `promoteNextPending` |
| W5 | Host pressured again during the resumed create | a new park (a new interrupt row), logged per cycle |
| W6 | Operator answered `stop` / `restart_*` before the auto-resume | the operator's arm; the auto-resume finds no open row |
| W7 | Manager restart with open host-pressure interrupts and a stale record | the next sweep re-samples health: clears and resumes, or keeps them parked |
| W8 | Agent successor queued and the run parked, not yet resumed | agent continuation worker arm 3 once the fence lifts |
| W9 | Refusal set the record; the host cleared within the sweep interval | at most one sweep of unnecessary queueing |

**Consequences:**

- A busy host with a caught-up manager is never "pressured"; at the default
  budgets the R20 profile runs without a refusal and retained rows are pruned
  before the 24 h grace, so the replay floor moves sooner. A consumer resuming
  from below it gets `replay_floor_lost` exactly as before (EDGE-EVT-03).
- Operators can always answer and tear down: the soft gate refuses new work
  only. Under the hard bound an answer is refused, and the manager keeps it
  retryable instead of failing it (`isRefusedPermissionDelivery`).
- A paused producer costs one respawn (~$0.28) after 5 minutes instead of a
  `stream-lost` crash. An agent message interrupted by a park is delivered at
  least once.
- The manager's view of pressure is up to one sweep (60 s) stale; a refusal
  sets it at once, so the common case is immediate.
- ADR-161's `resume` now claims a slot and restores context for operator
  interrupts too — a behavioural fix for a gap nothing had covered.
- One additive Postgres migration (`0182`), one host SQLite migration (v14),
  jsonb widenings on `hitl_requests.schema/response`, `node_attempts.action_resume`
  and `scratch_runs.error_metadata`, no new env var and no new `MaisterError`
  code.

**Alternatives Considered:**

- **Keep retained rows in the pressure predicate and raise the budgets:**
  rejected — it measures the operator's disk, not the manager; any budget is
  crossed by a day's healthy traffic inside the grace window.
- **A new `runs.status` for a host-parked run:** rejected — `NeedsInput` /
  `NeedsInputIdle` already mean "parked, resumable", and every consumer of the
  status enum would have to learn a synonym.
- **SIGKILL a paused producer:** rejected — it loses the turn's context, the
  ACP handle and the captured frames; ADR-180's graceful checkpoint keeps all
  three.
- **A manager-only pressure record in memory:** rejected — five readers (the
  fence, the stall pass, the auto-resume, the admin page, the driver) in two
  processes and two writers need one durable value.
- **Letting a machine actor answer its own `node_interrupt`:** rejected — the
  ADR-161 human-only rule is a security rule; the sweep calls the shared
  internal application instead.
- **A 503 from `POST /api/runs` under pressure:** rejected — the run row would
  be lost; a queued `Pending` run keeps the operator's intent.
