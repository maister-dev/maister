**Context:** The personal librarian ([brief](../pv/personal-librarian.md)) is one
durable conversation per user (LIB-01) whose context is platform-owned and
independent of any ACP process, tab, runner or model (LIB-06), executed on the
supervisor, the execution-host command ledger and durable prompt ownership, with
no repository or project invented to host it and no idle slot held (LIB-15).
Facts verified against the working tree at `8c77218` (2026-09-26):

- `runs` knows three kinds (`flow | scratch | agent`), enforced only in
  TypeScript. The project-less precedent is the local-package assistant
  (ADR-097): `run_kind='scratch'`, `project_id` NULL, adopted as a `directory`
  under its package slug (`web/lib/execution-host/adoption.ts:64-68`,
  `:178-180`). A run with neither a project nor a package is refused
  (`adoption.ts:182`).
- Persistent agents park and resume through primitives that belong to the agent
  kind: `applyPersistentAgentPark` CASes on `run_kind='agent'`
  (`web/lib/agents/park.ts:26-45`) and writes `resume_requested_at` from
  `agent_turns`, whose trigger refuses any run that is not `agent`
  (`web/lib/db/migrations/0180_agent_turn_steering.sql:34-40`).
- The keep-alive sweeper never TTL-abandons a `persistent=true` run
  (`web/lib/runs/keepalive-sweeper.ts:274`), and a slot is held only in
  `Running | NeedsInput | HumanWorking` (`web/lib/runs/run-status-sets.ts:48-52`).
- The run stream authorizes a project-less run by `created_by_user_id` alone
  (`web/app/api/runs/[runId]/stream/route.ts:337-346` →
  `assertLocalPackageAssistantActor`, `web/lib/scratch-runs/authorization.ts:6-17`).
- The scheduler has two pools, `flow` and `agent` (`web/lib/scheduler.ts:92-102`).

**Decision:** A conversation owns exactly one `runs` row of a new kind
`librarian`. Each turn is a durable `librarian_turns` row executed as one ACP
session on that run and deleted when the turn ends. The durable records are the
source of truth; the ACP session is a cache that a turn resumes only when it is
provably current. Plan traceability: D1–D3, D6 and D11 ratify plan D2; D4–D5
plan D3; D7 plan D17; D8 plan D5's runner guard; D9 plan D19; D10 plan D20.

**D1 — Run kind and row shape.** The run is inserted by the conversation's first
turn, in one transaction with its `run_sessions` row and `mintPlacement`, and
reused by every later turn: `run_kind='librarian'`, `project_id` NULL, `task_id`
NULL, `flow_version='librarian'` (sentinel precedent `"scratch"`, `"agent"`),
`persistent=true`, `created_by_user_id` = owner, `agent_workspace='none'`.
Migration `0183` adds `runs_run_kind_check` (four kinds) and
`runs_librarian_shape_check`; `librarian_conversations_run_uq` (`0182`) keeps
the row one-to-one with the conversation (LCV-01, LCV-04; `IT-LCV-01`,
`IT-LCV-04`). The run's statuses are `Pending → Running ⇄ NeedsInputIdle`; it
never enters `NeedsInput`, `HumanWorking`, `Review`, `Done`, `Abandoned` or
`Crashed` (D9).

**D2 — Placement and prompt owner.** `PLACEMENT_REASONS`
(`web/lib/execution-host/types.ts:26-37`) gains `librarian_turn`; every turn
start mints it through `mintPlacement` (`web/lib/execution-host/placement.ts:28`)
inside its claim, and the assignment-reason CHECK regenerates from the list. A
new prompt owner kind `librarian_turn` has variants
`owner_message | explain | summary` and ref `{turnId, promptOrdinal}` plus the
common fields; its logical key is
`librarian_turn:<variant>:<assignmentId>:<promptOrdinal>`. It joins
`PROMPT_OWNER_SHAPES` (`web/lib/execution-host/prompt-owner-contract.ts:160`), so
`execution_commands_request_v2_check` regenerates; the hard-coded `owner_kind`
enum (`web/lib/db/schema.ts:2316`) and `execution_commands_owner_shape_check`
(`schema.ts:2527`) are re-derived in `0183`;
`execution_commands_create_intent_check` (`schema.ts:2424`) gains owner variant
`librarian` with keys `{variant, turnId, promptOrdinal}` and
`operationKey = 'librarian-create:' || turnId || ':' || promptOrdinal`. The
registry `librarianPromptOwners` joins `PRODUCTION_PROMPT_OWNER_REGISTRIES`
(`web/lib/workers/runtime.ts:46`), whose `composePromptOwnerRegistry` (`:63`)
fails boot on drift. `execution_commands_prompt_owner_required` (`schema.ts:2523`)
is unchanged: a librarian prompt without an owner cannot be written (LCV-04).

**D3 — Workspace: project-less `directory` adoption under a reserved slug.** The
run adopts `<runtimeRoot>/.maister/_librarian/<conversationId>/` as a
`directory` workspace with `projectSlug='_librarian'`. The web creates the
directory (recursive, owner-only mode) from `runtimeRoot()`
(`web/lib/runtime-root.ts:14`) before adopting it, because the host refuses a
missing path. `WorkspaceSpecInput.run.runKind` (`adoption.ts:25`) gains
`librarian`; `workspaceSpecFor` (`adoption.ts:54`) and the refusal in
`loadWorkspaceSpecInput` (`adoption.ts:182`) gain a `librarian` arm that reads no
`projects` row. The directory holds no repository and the run carries no
`context_repos`, so the adopt payload has no `repoPath` and no `contextMounts`.
The directory survives parking (releasing an assignment releases no handle,
`web/lib/execution-host/assignments.ts:240-270`); only history deletion
releases it (ADR-188). The one wire change is in the supervisor:
`projectSlugSchema` (`supervisor/src/types.ts:413-417`) accepts the literal
`_librarian` in addition to the kebab-case pattern. Test: `IT-LCV-04`.

**D4 — Session per turn, context epoch.** Each turn composes a bounded context
(instructions version, active-segment summaries and newest messages within
`MAISTER_LIBRARIAN_CONTEXT_MAX_CHARS`, memory items, subject, the segment's
operation receipts) and commits a `librarian_context_snapshots` row before its
prompt command is queued — CHECK `librarian_turns_running_has_snapshot_check`
(LCV-07, `IT-LCV-07`). `librarian_conversations.context_epoch` bumps on reset,
forget and clear history (ADR-188) and whenever the authz fingerprint changes
(sha256 over the owner's active flag, global role and sorted
`(project_id, role)` visibility set, computed at admission). `run_sessions`
gains `librarian_context_epoch`, the epoch its ACP session was created under,
and `librarian_turns.runner_snapshot` records the runner. The composer resumes
(`session/resume` on `acp_session_id`) only when both equal the current values
and otherwise starts `session/new` from the composed context, so retained ACP
context can never repeat a revoked fact (LCV-06, `IT-LCV-06`). After the turn
the session process is deleted (persistent-agent precedent
`stopAgentPromptSession`, `web/lib/agents/prompt-owner.ts:515`).

**D5 — Park and resume primitives.** `applyLibrarianPark(tx, runId)` CASes
`run_kind='librarian' AND status='Running'` → `NeedsInputIdle`, stamps
`checkpoint_at` and calls `releaseAssignmentForRun(tx, runId, "parked")`.
`claimLibrarianResumeInTransaction(tx, runId, turnId)` CASes
`status='NeedsInputIdle'` → `Running`, mints `librarian_turn` and checks the pool
cap under the scheduler advisory lock. Neither touches `agent_turns` or
`resume_requested_at`: `librarian_turns` is the turn ledger. After `end_turn`
the owner adapter's `apply(tx)` stores the reply, completes the turn, revokes
the token (ADR-184) and parks; `afterCommit` runs `releaseSlotOnIdle` and
`promoteNextPending` and admits the next queued turn. Every failure path after
the prompt was issued cancels it through `BoundClient` before returning.
Test: `IT-LCV-05` part 2.

**D6 — Pool.** `SchedulerPool` gains `librarian`, and `POOL_RUN_KINDS`,
`poolForRunKind`, `capForPool` (`web/lib/scheduler.ts:92-156`) and the C1/C3
dispatch (`scheduler.ts:886`, `:1166`) become three-way. The cap is
`MAISTER_MAX_CONCURRENT_LIBRARIAN_TURNS`, counted over
`SLOT_HOLDING_RUN_STATUSES`, so a parked conversation holds nothing. The
`librarian` arm of `promoteNextPending` admits, FIFO by
`librarian_turns.admitted_at`, either a `Pending` librarian run (first turn) or
a `NeedsInputIdle` librarian run whose conversation has an `admitted` turn;
there is no C2 source. A full pool queues and never refuses with `CONFLICT`
(LCV-05, `IT-LCV-05`). Admission itself is serialized per conversation by the
`librarian_conversations` row lock and `librarian_turns_one_active_uq` (LCV-03,
`IT-LCV-03`).

**D7 — Budgets (web-only env, finite; defaults proposed for owner confirmation in T0.17).**

| Variable | Default | Enforcement |
| --- | --- | --- |
| `MAISTER_MAX_CONCURRENT_LIBRARIAN_TURNS` | 3 | D6 pool cap; queue, never refuse |
| `MAISTER_LIBRARIAN_TURN_MAX_MINUTES` | 10 | `deadline_at`; token `expires_at`; keep-alive budget pass arm cancels the prompt → `failed{deadline}` |
| `MAISTER_LIBRARIAN_CONTEXT_MAX_CHARS` | 60000 | composer drops oldest non-latest material, `truncated=true` in the snapshot |
| `MAISTER_LIBRARIAN_DAILY_TURNS_PER_USER` | 200 | conversation row counter under its lock; `owner_message` and `explain` turns count |

A non-positive or non-integer value refuses boot with `CONFIG`. The daily cap
refuses at admission with `BUDGET_EXCEEDED`: the message stays stored and its
turn ends `failed{reason:"daily_turn_cap"}` so the panel shows why. A message
body longer than the context cap is refused `CONFIG` at
`POST /api/librarian/messages` before it is stored, so the owner's latest
message always fits and is never truncated away (LCV-10, `UT-LCV-10`,
`IT-LCV-10`).

**D8 — Enablement and runner guard.** `platform_runtime_settings` gains
`librarian_enabled` (default false) and `librarian_runner_id`
(`ON DELETE SET NULL`). The runner must be enabled, ready,
`readOnlyCapable === true`, never `permission_policy='dangerously_skip_permissions'`
(the predicates of `web/lib/acp-runners/resolve.ts:215-233`) and of capability
`claude` or `codex` — the only adapters whose host transcripts the ADR-188 purge
covers. `PATCH /api/admin/platform/librarian` refuses any other runner; every
admission re-checks, because the runner can change between turns. Disabled →
`CONFIG`; no ready runner → `EXECUTOR_UNAVAILABLE`; queued turns stay queued,
admitted operations still reconcile, nothing is deleted (LCV-11, `IT-LCV-11`,
`EDGE-LCV-03`).

**D9 — Turn recovery windows (normative).**

| Turn status × run status | Arm |
| --- | --- |
| `queued` × any | admitted by the next admission pass (event-driven + `system_sweep` backstop) |
| `queued`, owner withdraw or reset barrier | `withdrawn` (terminal; message `withdrawn` / `withdrawn_by_reset`) |
| `admitted` × `Pending` | pool promotion (`promoteNextPending` librarian arm); no token issued yet |
| `admitted` × `NeedsInputIdle` (pool was full at claim) | pool promotion by `admitted_at`; no token issued yet |
| `admitted` × `Running`, no prompt command after 60 s | re-issue start (the logical key makes it idempotent); 3 failures → `failed{reason:"start_failed"}` |
| `running` × `Running`, live session | none (deadline watchdog); after a web restart the prompt command is settled by the owner-registry worker (`web/lib/workers/runtime.ts`), which is registry-generic |
| `running` × run not live (restart, adapter loss) | reconcile `librarian` arm → turn `failed{reason:"host_lost"}`, token revoked, run parked `NeedsInputIdle`, next queued turn admitted |
| `running` past `deadline_at` | watchdog: cancel prompt, `failed{reason:"deadline"}` |
| `running`, guard halt observed | owner adapter → `failed{reason:"capability_trip"}` (ADR-184) |
| `stopped`, `failed` or `completed` × `Running` | park the run (idempotent) |

The reconcile crash dispatch (`web/lib/reconcile.ts:1947` agent arm, `:2005`
scratch arm, `else` → `crashRunningRun` at `:2034`) gains a `librarian` arm
before the `else`, so a librarian run is parked and never `Crashed` (LCV-09,
`IT-LCV-09`). Stop cancels the turn's prompt through `BoundClient`, revokes its
token and never touches a task run or an operation row (LCV-08, `IT-LCV-08`).

**D10 — Background automation (normative).**

| Loop | Progress | Retries / poison | Wiring test |
| --- | --- | --- | --- |
| turn admission | FIFO by `seq` per conversation; pool FIFO by `admitted_at` | 3 start attempts → `failed` | `runSchedulerTick({jobKind:"system_sweep"})` admits a stranded `admitted` turn |
| `librarian_followup` consumer (ADR-185) | domain-event cursor | ≤ 5 attempts; deterministic failure → `failed`, cursor advances | dispatcher test through `dispatchDomainEvents` |
| summary turns (ADR-188) | one pending per segment | ≤ 2 attempts, then truncation | end-of-turn hook test |
| retention pass (ADR-188) | keyset cursor in sweep state, batch 500 | per-row failure logged, batch continues | `runSchedulerTick` |
| card expiry (ADR-185) | lazy on decide + sweep | none | sweep test |
| reset barrier backstop (ADR-188) | per conversation in `resetting` | idempotent | sweep test |

The four sweep passes (admission backstop, retention, card expiry, reset
barrier) are sequential calls inside `runSystemSweep`
(`web/lib/scheduler/system-sweeps.ts:295`), each wrapped like the existing
passes so one failure never blocks the next. The deadline watchdog is the
`librarian` arm of the keep-alive budget pass that `runSystemSweep` already runs
(`runSweepTick`).

**D11 — `run_kind` fan-out.** Every branch on `run_kind` becomes an exhaustive
`satisfies Record<RunKind, …>` map (T2.3 lists every file). Librarian runs are
excluded from every project-scoped read model and metric (board, portfolio,
`/runs`, work table, decisions, Observatory), never gain a `workspaces` row, never
write `agent_turns`, and are never GC candidates (`IT-LCV-04` part 2). Every
`/api/runs/[runId]/*` session route except the stream answers `404` for a
librarian run (ADR-184 D9).

**T0.4 verification — how the host derives and validates the reserved slug.**

1. The slug's only gate is the wire schema. `AdoptWorkspacePayloadSchema`
   (`supervisor/src/types.ts:808-833`) parses `projectSlug` with
   `projectSlugSchema` (`:413-417`, kebab-case `^[a-z0-9]+(?:-[a-z0-9]+)*$`,
   ≤ 64), so `_librarian` is refused today; D3 adds the one literal.
2. The path is validated by realpath against the configured roots, never by
   slug (`WorkspaceRegistry.validate`, `supervisor/src/workspace-registry.ts:284-355`):
   absolute with no `..` segment (`:287-295`); `realpath` must exist, else
   `not_found` (`:297-299`); not inside the host state dir (`:301-303` — the
   default `<runtimeRoot>/.maister/execution-host/`,
   `supervisor/src/host-state.ts:463`, is a sibling of `_librarian/`); under a
   root, else `outside_roots` or `symlink_escape`
   (`:305-321`). The default roots include `<runtimeRoot>/.maister`
   (`supervisor/src/workspace-roots.ts:13-22`), realpath'd at boot (`:50-71`).
   An operator who sets `MAISTER_WORKSPACE_ROOTS` must keep `<runtimeRoot>/.maister`
   (or a parent of `_librarian/`) in it; otherwise adoption answers
   `outside_roots` and the admin readiness line says so (T2.13).
3. The slug derives only the run directory,
   `<runtimeRoot>/.maister/_librarian/runs/<runId>`
   (`workspace-registry.ts:38-40`, stored at `:163-167`), created on spawn
   (`supervisor/src/spawn.ts:132`). A conversation id is a UUID, so a cwd
   `_librarian/<conversationId>/` never collides with `_librarian/runs/`. For a
   `directory` handle `cwd` and `confineRoot` are the adopted path
   (`workspace-registry.ts:241-243`).
4. No supervisor code resolves the slug against registered projects: its other
   readers are the session record (`supervisor/src/spawn.ts:278`), the
   workspace GET echo (`supervisor/src/http-api.ts:2298`) and cost metadata
   (`http-api.ts:2547`).
5. It cannot collide with a project or package: the web `projectSlugSchema`
   (`web/lib/flow-paths.ts:43-47`) is the same kebab pattern, and local-package
   slugs are `[a-z0-9-]` (`slugifyName`, `web/lib/local-packages/paths.ts:48-56`).
   The web builds the librarian path with its own helper, never through a
   `flow-paths.ts` builder that validates `projectSlugSchema`.

**Consequences:**

- The librarian reuses the whole ACP, command-ledger and prompt-owner substrate
  without inventing a project or repository, and a restart of either process is
  recovered by the same owner-registry worker and reconcile sweep as every
  other run kind.
- Every turn spawns an adapter process and pays for it: a fresh-context turn
  pays the full prompt, a resumed turn roughly the `$0.28` cache-creation cost
  of a cross-process resume. The epoch rule resumes only when safe; D7 bounds
  the spend.
- A new run kind touches every `run_kind` consumer; the exhaustive-map rule
  turns a forgotten branch into a type error instead of a silent flow-path
  fallthrough.
- The reserved slug is a special case in the supervisor's wire schema, bounded
  to one literal that no web slug can produce.
- The per-turn directory lives under the runtime root until history deletion;
  it holds adapter settings and, for codex, the composed `CODEX_HOME`.

**Alternatives Considered:**

- **Widen `run_kind='agent'` to be project-less:** rejected — every agent path
  (attachments, triggers, `agent_turns`, the agent pool, token issuers) assumes
  a project, and the brief asks to preserve those constraints.
- **One long-lived ACP session per conversation:** rejected — it holds a slot
  and an adapter process while idle (LIB-15) and would carry revoked facts in
  its context across an access change (LIB-13).
- **Reuse `applyPersistentAgentPark` / `agent_turns`:** rejected — both are
  agent-kind by CAS and trigger; giving `resume_requested_at` a second meaning
  would couple two turn ledgers.
- **Adopt the directory under a synthetic registered project:** rejected — it
  would appear in every project-scoped read model and RBAC surface.
- **Run turns inside the web request handler:** rejected — LIB-15 forbids an
  unowned background promise; the prompt owner makes every turn restartable.
