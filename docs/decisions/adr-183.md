# ADR-183: Outbox pressure means the manager is behind

> Part of the ADR log — hub, index, and editing rules: [`../decisions.md`](../decisions.md).

**Date:** 2026-09-26
**Status:** Implemented; amended 2026-09-27 (an open prompt no longer pins the retained-pressure prune); amended 2026-09-28 (the refusal names its cause and the fence follows the host's new-work signal; the drain is a backstop; host parks survive the TTL)

> **Amends [ADR-167](../decisions.md#adr-167-durable-execution-host-event-and-runtime-data-plane)**
> (D2: the replay grace is a retention target, cut short under retained
> pressure; D4: backpressure refuses new work only, and only while rows are
> unacknowledged), **[ADR-180](../decisions.md#adr-180-permission-deadline-has-one-owner)**
> (a second host-initiated checkpoint cause, `outbox_pressure`; a host park no
> longer needs an open deferred) and
> **[ADR-161](../decisions.md#adr-161-operator-node-interrupt-with-corrective-restart)**
> (a system-caused `node_interrupt` answered by the manager itself; `resume`
> claims through `claimNodeInterruptResume` and keeps the node's ACP context). Each
> record carries a dated amendment bullet.

**Context:** The execution host's SQLite outbox has two row counts per
partition: *retained* (every row still on disk) and *unacknowledged* (rows the
manager has not yet ACKed). ACKed rows stay retained for a 24 h replay grace
before the hourly pruner removes them. Before this decision the soft-pressure
bit was set when EITHER count reached the soft budget, and the bit did four
things at once: it refused every command without a teardown admission
(`session.create`, `session.prompt`, `session.input`, `session.steer`,
`workspace.adopt`, runtime-object writes), it paused every producer's next ACP
frame, it moved completion evidence onto producer wallets, and it was reported
on `/health?includeStream=true` as `stream.pressured`.

Four defects followed, all measured or read on `881619a5`:

- **A healthy stream tripped it.** The R20 load harness, whose manager kept up
  (lag 46–60 rows), crossed the 80 000-row soft budget with *retained* rows in
  about 3.4 minutes at ~394 rows/s. The harness raised the three row budgets to
  pass. At the defaults, any busy host enters "pressure" once a day's traffic
  sits in the grace window, although the manager is fully caught up.
- **The operator's answer was refused.** `session.input` and `session.steer`
  carried no teardown admission, so the soft gate refused a permission answer —
  the one command that lets a paused turn finish.
- **A paused producer froze without bound.** A producer waiting for frame
  capacity waited forever. While it waited the host emitted nothing for its
  open prompt, and after `MAISTER_EVENT_STREAM_STALL_SECONDS` (300 s) the
  manager's stall pass repaired and then degraded the stream to `lost`, and
  reconcile crashed the run `stream-lost`.
- **The manager read `pressured` nowhere.** The health sample was fetched every
  sweep and discarded; no admission, stall, driver or admin decision branched
  on it, and the host's refusal reached the run as an ordinary definitive
  `PRECONDITION` failure.

**Decision:** Outbox pressure means exactly one thing — **the manager is
behind**: unacknowledged rows reached the soft budget. Retained rows are
housekeeping with a retention target. The soft gate refuses new work and never
an answer or a teardown. A paused producer has a bound that ends in ADR-180's
graceful checkpoint. The manager records pressure durably and treats a host
park as a pause it resumes itself.

**D1 — Pressure is unacknowledged-only (host).** `refreshOutboxPressure`
enters `pressured` when `unacknowledgedCount + reservedFrameRows ≥
eventSoftRows` or `unacknowledgedBytes + reservedFrameBytes ≥ eventSoftBytes`,
and clears only when BOTH lanes are below `eventLowRows` / `eventLowBytes`.
Retained counts leave the predicate. A frame reservation stays in the
unacknowledged lane, because a reserved frame cannot have been ACKed. The two
threshold tests are separate exported predicates, `unacknowledgedAtThreshold`
and `retainedAtThreshold`.

**D2 — The pressure episode is host state.** `runtime_event_pressure` (host
SQLite schema v14) records `since_ms`, `unacknowledged_count_at_start` and
`unacknowledged_bytes_at_start` on the 0→1 flip, clears them on the 1→0 flip
and increments `episodes` on it; `since_ms` is non-null exactly while
`pressured = 1` (a CHECK). `/health?includeStream=true` adds
`stream.pressure: {since, unacknowledgedCountAtStart,
unacknowledgedBytesAtStart, episodes}` while pressured and `null` otherwise.
`stream.pressured` is the unacknowledged bit and nothing else: runtime-file
pressure and physical SQLite headroom keep their own refusals
(`runtime_storage_pressure` 503, `event_outbox_backpressure` 409 for physical
admission) and never set it. Every flip logs `outbox-pressure-changed`.

**D3 — Retained rows are housekeeping (host).** The 24 h replay grace is the
retention *target*. When retained rows reach the soft budget (either lane) the
pruner runs a `retained_pressure` pass: the cutoff is "any confirmed-ACKed
row", with the same bounds as the grace pass — at most 100 rows and 1 MiB per
`BEGIN IMMEDIATE` page, oldest-first, a contiguous prefix only, never at or
beyond the smallest `accepted_sequence` of a v2 command whose terminal is not
yet ACKed, never an unacknowledged row — and it stops when retained rows are
below the low budget in both lanes or a page finds nothing prunable. Between
pages it yields (`setImmediate`), so ACK and publisher writes interleave with
it. The trigger is every committed capacity change (an ACK, an append, a
receipt), not only the hourly timer, which stays as the grace-mode backstop;
kicks coalesce to one pass in flight, and after a stalled pass a kick waits for
the ACK watermark to move. The replay floor advances only over rows
a page deleted, so it never passes the manager's confirmed watermark. A pass
that prunes nothing because a protected span or an unacknowledged prefix pins
the oldest rows logs `outbox-retained-pressure-prune-stalled` once per episode,
and the hard bound stays the last line — reached by a long-running turn while
the manager is caught up (see Consequences, "Measured limit"). A completed episode logs
`outbox-retained-pressure-prune` with pages, rows and duration.

*2026-09-27 amendment ([ADR-184](../decisions.md#adr-184-an-open-prompt-does-not-pin-the-outbox--the-span-feed-reads-its-acked-prefix-canonically)).*
The cutoff no longer stops at an open v2 span, in either mode: the manager's
span feed reads a span's ACKed prefix from `execution_events`, so no host
reader needs those rows. A stall now means only unacknowledged rows remain
above the low budget, and the stall line logs `retainedCount`,
`unacknowledgedCount` and `acknowledgedThrough` instead of
`protectedFromSequence`.

**D4 — Hard stays retained, physical stays physical.** The hard bound is
unchanged: `retained ≥ eventHard*` refuses every non-teardown admission and
every frame reservation. `MAISTER_EXECUTION_HOST_STATE_MAX_BYTES` and the
runtime-file budget keep their own admission paths.

**D5 — One admission table, one closed enum.** Every receipt names its
admission; there is no default.

| Command / receipt | Admission | Soft (unACKed pressure) | Hard (retained ≥ hard) | Physical / file pressure |
| --- | --- | --- | --- | --- |
| `session.create` | `producer` (wallet) | refuse | refuse | refuse |
| `session.prompt` | `new_work` | refuse | refuse | refuse |
| `workspace.adopt`, `runtime_object.reserve`, `runtime_object.upload` | `new_work` | refuse | refuse | refuse |
| `session.input` | `resolve` | **admit** | refuse | refuse |
| `session.steer` | `resolve` | **admit** | refuse | refuse |
| `session.cancel`, `session.checkpoint`, `session.delete` — whatever the session record's liveness | `teardown` | admit | admit | admit |
| `workspace.release`, `runtime_object.delete` | `teardown` | admit | admit | admit |
| producer frame (`beforeFrame`) | `producer` | pause, bounded (D6) | refuse the reservation → drain / terminal wallet | — |

A refusal is `409 PRECONDITION` with `details.reason:
"event_outbox_backpressure"` and writes no receipt; it logs
`outbox-admission-refused` once. A teardown whose session still owns an open
producer wallet takes that wallet's terminal credit exactly as before, and
keeps the wallet's own serialization — a teardown of the same wallet already in
progress, or, while pressured, an already-admitted step under a new command id,
is refused (replay the original id); a teardown with no open wallet (an exited session, a workspace, an object) is
admitted without credit, and its evidence is written to the regular partition,
falling back to the emergency floor when regular is at its hard budget. A
`resolve` command's events are funded from the regular partition, never from
the producer wallet, so answers cannot drain the credit a producer needs for
its own terminal evidence. Completion and teardown evidence keeps its wallet
funding whenever the host is *constrained* — unACKed pressure, retained rows at
soft, runtime-file pressure or physical headroom — which is not the pressure the
manager reads. The unused `assertCanAcceptMutatingCommand` is deleted.

**D6 — A paused producer is bounded.** A producer that waits for frame capacity
records `outputPausedSince` and arms one unreferenced timer of
`PRODUCER_PAUSE_MAX_MS = 5 min` (a code constant, not an env var). If the
producer is still paused when it fires, the host runs ADR-180's
`checkpointSession` with `cause: "outbox_pressure"`: pending deferreds are
cancelled as `checkpoint` (a late `/input` then answers `410
session_checkpointed`), the session is marked intentional, output teardown
drains the captured frames onto the credited wallet, SIGTERM, and
`session.exited{reason: "checkpoint", cause: "outbox_pressure"}`; SIGKILL only
after the kill grace. The bound equals one stall window, is ≥ 7× the row-lane
drain and ≈ 2× the byte-lane drain at the measured manager throughput, and a
shorter bound would multiply the ~$0.28 respawn cost under brief pressure.
It logs `producer-pause-exceeded` once. The bound applies to a frame wait the
outbox refuses (unACKed pressure, or no room under hard for one frame); a pause
caused by runtime-file or physical headroom re-arms and keeps waiting, as
before. A test process (`NODE_ENV=test`) may shorten the bound through
`MAISTER_TEST_PRODUCER_PAUSE_MAX_MS`; production ignores it. `CheckpointCause`
and the AsyncAPI `cause` become the enum `permission_cap | outbox_pressure`.

**D7 — The interrupted prompt names the park.** When the pause bound
checkpointed a prompt's session, the prompt's rejection receipt keeps
`code: "ACP_PROTOCOL"` and carries `details: {reason: "session_checkpointed",
cause: "outbox_pressure"}` — the token the `/input` route already mints — even
when the adapter answered before it died, because the turn was cut short. A
route or permission-cap checkpoint already has a manager owner and keeps its
existing rejection evidence. The ADR-180 order holds: `session.exited` first,
the rejection after.

**D8 — The manager keeps a pressure record.** Migration `0182` adds the table
`execution_host_pressure` (`execution_host_id` PK → `execution_hosts` CASCADE,
`pressured_since` NOT NULL, `unacknowledged_at_start` nullable, CHECK `>= 0`);
a row exists exactly while the host is recorded as pressured. The same
migration re-creates `node_attempts_action_resume_check` to admit the
`kind: "interrupt"` handle of D11. It is a table and
not two `execution_hosts` columns because the staged upgrade runs the current
registrar against the additive stage's `execution_hosts`, and a Drizzle
select, insert or `returning()` names every column the current schema
declares — that row's shape cannot change after `0133` (found by AT-11). Two
writers: the `system_sweep` observation step inserts the row (an existing row
keeps its `pressured_since`) from a health sample with `pressured: true` and
deletes it on one with `pressured: false` (amended 2026-09-28, item 3: the
host's `newWorkRefusedBy` decides); and the command deliverer — for an
immediate command, and for an async prompt whose receipt lookup definitively
finds none — on a `PRECONDITION` refusal whose `details.reason` is
`event_outbox_backpressure` inserts `pressured_since = now()` ON CONFLICT DO
NOTHING, marks the command failed with the host's verbatim error, and throws
`EXECUTOR_UNAVAILABLE {reason: "host_pressured", hostReason, commandId}`. A
successful ACK never clears the record —
the host is the authority. The manager's own token for this state is
`host_pressured`; the host's refusal token stays `event_outbox_backpressure`.

**D9 — Admission fence.** Every former `capForPool` reader — launch,
`promoteNextPending`, the C2 auto-launch poll, the agent turn and rework
claims, the orchestrator wake, `resumeRun`, the sync resolver and the HITL
resume claims — goes through one helper, `effectivePoolCap`, which answers
a zero cap with fence `host_pressured` while the local host's record is set; a
grep guard keeps it that way. A launch is queued `Pending` with
`queueReason: "host_pressured"` (`POST /api/runs` still answers 202, never
503), an idle flow resume stays queued (`resume_requested_at`; an interrupt
resume is deferred instead, D12), and a parked agent stays parked. The scratch
and package-assistant budgets and the `maxConcurrentRunsCap` readers (crash
recover, rework claim, schedule dispatch, orchestrator bounds) are not fenced:
work they start under pressure meets the host's own refusal, which D11 turns
into a park. When the sweep clears the record it first auto-resumes the
host-paused interrupts (D11), then drains each pool with `promoteNextPending`
up to its cap (amended 2026-09-28, item 4: on every admitting sample).

**D10 — The stall pass classifies pressure.** A silent stream with open
commands on a `ready` host whose record is set is `pressured`: counted in the
stream-health summary, logged `runtime-event-stream-pressured`, never repaired
and never degraded to `lost`. An unreachable host is not `ready` and keeps the
existing rules.

**D11 — A host park is a pause the manager resumes (per run kind).** The
manager recognises a host park with one classifier, `isHostPressureFailure`:
D7's token, the create/prompt refusal of D5, or the deliverer's
`host_pressured` rethrow (D8); it is checked before the ambiguous-outcome
(`turn_lost`) arm.

- *Flow run.* The node's prompt completion is persisted as
  `{ok: false, errorCode: "EXECUTOR_UNAVAILABLE", reason: "host_pressured"}`,
  and the runner's common failure branch parks instead of failing the node: an
  ADR-161 `node_interrupt` whose `schema` carries `cause: "host_pressure"` and
  `actor: {type: "system"}`, the run `Running → NeedsInput`, the SAME attempt
  `NeedsInput`. The park clears `action_completion`, advances
  `action_prompt_ordinal` N → N+1 (a late ordinal-N application is then
  superseded) and, when the parked prompt ran on a session, writes
  `node_attempts.action_resume = {version: 1, kind: "interrupt", cause,
  sourceCommandId, sourceAssignmentId, assignmentId, promptOrdinal: N+1,
  resumeSessionId}` so the resumed node restores its ACP context; a refused
  create or prompt writes no handle and resumes on a fresh session. A park the
  driver cannot commit becomes a driver yield, replayed by the flow
  continuation worker from the stored completion. The keep-alive sweeper idles
  the run to `NeedsInputIdle` as any other park — unless the completion was
  applied before the projector saw `session.created` (the manager was behind,
  so either order happens): the create is then judged stale, the incarnation
  projects `lost`, Pass 1b cannot fast-idle, and the run keeps its slot until
  the auto-resume resumes it from `NeedsInput`. When a health sample reports
  `pressured: false` — whether or not the manager had recorded the pressure —
  the sweep answers each open host-pressure interrupt `resume` itself — at
  most 25 per tick, oldest first, under the row lock and the `responded_at`
  idempotency guard — through the same internal application the operator's
  `resume` uses (`applyNodeInterruptResume`), never through `respondToHitl`.
  The answer records `response = {optionId: "resume", actor: {type: "system"},
  cause}`. Every tick the sweep also re-drives an interrupt answered `resume`
  whose run is still parked (at most 25); a row whose resume throws three times
  in one process is left to the operator (withdrawn 2026-09-28, item 5).
- *Agent run.* The owner application settles the parked turn by variant: a
  message (`live_message` / `persistent_message`) is superseded by a successor
  carrying the same variant and text (`message:requeue:<turnId>`); an
  `initial` / `resume` generation is closed `applied` with no successor, and
  the resume generation repeats it on the same ACP session (the shape the
  resume invariant admits); `rework` and `consensus_draft` keep their existing
  failure settlement, because their input is not the agent's base prompt. The
  run then parks through `applyAgentPark(tx, runId, {cause: "host_pressure"})`
  (`NeedsInputIdle`, `resume_requested_at`, assignment released `parked`), now
  for one-shot runs too; the agent continuation worker resumes it with
  `session/resume` once the fence lifts. A dispatch the host refused
  re-queues a message the same way; a refused generation dispatch — its
  workspace adoption or its create — fails the run through the create-failure
  settlement (`agent_session_create_failed`), never left `claimed`. The message is delivered at least once, and a same-key
  retry of a superseded message answers with its successor.
- *Scratch dialog.* The retryable arm records `error_metadata.cause =
  "host_pressure"` and the dialog shows a notice; the send-time resume of a
  checkpointed scratch session is A4's.

**D12 — `resume` claims a slot and keeps the context (widened).** ADR-161's
`resume` answer called a bare `scheduleResume`, which only claims `Running |
NeedsInput`, so a `resume` given after the keep-alive sweeper idled the run was
a silent no-op; and it re-entered the node on a fresh ACP session because no
resume handle was written. Both are fixed for every interrupt, operator or
system: `resume` claims through `claimNodeInterruptResume` — a `NeedsInput` run
is re-driven directly; a `NeedsInputIdle` run mints a new generation through
`markResumed` under the fenced flow cap, whose hook
`authorizeNodeInterruptResume` rebinds the parked attempt and its handle to
it; over cap or fenced the claim is deferred (never `resume_requested_at`,
whose promotion re-enters through crash recovery and would close the attempt)
and the `system_sweep` re-drives it every tick — and every interrupt park
writes the `action_resume{kind: "interrupt"}` handle when a session exists. A
`node_interrupt` is still answerable only by a human through `respondToHitl`;
the sweep's system answer is a server-internal call with no token, route or
body field.

**Recovery windows (normative).**

| # | State after the crash or gap | Owner that finishes it |
| --- | --- | --- |
| W1 | Host parked; `session.exited{cause}` and the rejection not yet ingested | catch-up ingest → lifecycle projector → owner application classifies (D11) |
| W2 | Rejection folded, park transaction not committed | the driver yields and the flow continuation worker replays the stored completion into the park; reconcile skips on the evidence |
| W3 | `NeedsInput` interrupt, incarnation `checkpointed`, not yet idled | keep-alive Pass 1b (idempotent CAS) |
| W4 | Auto-resume answered, claim not taken | the `system_sweep` re-drive (every tick) through `claimNodeInterruptResume`; over cap or fenced the claim stays deferred |
| W5 | Host pressured again during the resumed create | a new park (a new interrupt row), logged per cycle |
| W6 | Operator answered `stop` / `restart_*` before the auto-resume | the operator's arm; the auto-resume finds no open row |
| W7 | Manager restart with open host-pressure interrupts and a stale record | the next sweep re-samples health: clears and resumes, or keeps them parked |
| W8 | Agent successor queued and the run parked, not yet resumed | agent continuation worker arm 3 once the fence lifts |
| W9 | Refusal set the record; the host cleared within the sweep interval | at most one sweep of unnecessary queueing |

**2026-09-28 amendment — the refusal names its cause; the fence follows the
host's new-work signal (D2, D5, D8, D9, D11).** Found by the whole-branch
review. One wire token covered five host conditions, and the manager's record —
set by any of them, cleared by the unacknowledged-only `pressured` bit —
flapped every sweep under a condition that bit does not see (low disk, a full
state file, retained rows at hard): each clear resumed and promoted work
straight into a fresh refusal, a new `node_interrupt` per flow run per tick and
a failed agent generation.

1. *The refusal names its cause.* The host's internal reasons are one per
   cause: `event_outbox_soft_limit` (unacknowledged pressure),
   `event_outbox_hard_limit` (retained rows at hard), `event_outbox_physical_limit`
   (SQLite headroom, formerly minted as the soft reason),
   `event_outbox_terminal_reserve_exhausted` (the control partition cannot fund
   a new producer wallet) and `event_outbox_wallet_exhausted` (a wallet's own
   teardown serialization or credit). The wire keeps `409 PRECONDITION
   {reason: "event_outbox_backpressure"}` and adds `details.outboxLimit:
   "unacknowledged" | "retained" | "physical" | "control" | "wallet"`, present
   on every such refusal; `outbox-admission-refused` logs it.
2. *Health names what refuses new work.* `/health?includeStream=true` adds
   `stream.newWorkRefusedBy`: the first host-wide limit a `session.create`
   without output bindings or a `session.prompt` would meet now, in the order
   an admission checks them — `physical` (recomputed on read, its WAL
   checkpoint accepted, because a cached answer could keep a healed host
   fenced forever), `unacknowledged` (the pressure bit), `retained` or
   `control` — and `null` when it would meet none. Per-wallet limits and the runtime-file budget (`503
   runtime_storage_pressure`) are not host-wide outbox limits and are not
   reported. `stream.pressured` keeps its meaning.
3. *The record means "the host refuses new work" (D8).* The refusal writer
   records for every `outboxLimit` except `wallet` — a per-command refusal:
   the command parks, the fence stays open — and for a refusal without
   `outboxLimit` (an older host). A sample carrying `newWorkRefusedBy` sets or
   keeps the record while it is non-null and deletes it when it is `null`; a
   sample without the field keeps the `pressured` rule. `unacknowledged_at_start`
   is filled only for `unacknowledged`. A sample deletes only a record set
   before its own fetch began: the sweep takes `sampledAt` before the health
   request and the delete matches `pressured_since <= sampledAt`, so a refusal
   that lands while the sample is in flight keeps the fence closed. The admin
   panel's pressure cell shows "refusing new work" with the limit whenever
   `newWorkRefusedBy` is set.
4. *The drain is a backstop, not a transition (D9).* The sweep drains both
   pools on every sample on which the host admits new work (`clear` and
   `cleared`), and runs the interrupt auto-resume, the flow drain and the agent
   drain each under its own error boundary, their failures recorded in the
   sweep's `errors`. A process death between the record delete and the drain, a
   throw in either step, and a re-registered local host (whose old record stops
   fencing without a `cleared` transition) no longer strand `Pending` work;
   `promoteNextPending` is lock-, cap- and fence-checked and returns at once
   when nothing is queued. While the record exists the sweep does not call it.
5. *The auto-resume backs off; it never gives up (D11, flow run).* "A row whose
   resume throws three times in one process is left to the operator" is
   withdrawn — an answered row has no card, so there was no operator. After k
   consecutive throws a row is retried after 2^(k−1) ticks (at most 16), for
   the auto-resume and the re-drive alike; `run-host-pressure-resume-stuck`
   logs at ERROR on the third consecutive throw and at every doubling after
   it; a success resets the count.
6. *Keep-alive Pass 2 never abandons a host park (D11).* The TTL measures
   operator silence. Pass 2 skips a flow run whose latest `node_interrupt` at
   its current node carries `cause: "host_pressure"` and is open or answered
   `resume`, and every run whose `resume_requested_at` is set — the only
   durable trace of an agent host park (its cause is not persisted) and of any
   answered resume still waiting for a slot.
7. *The refused generation stays a failure (D11, agent run).* A refused
   `initial` / `resume` generation dispatch still fails the run through
   `agent_session_create_failed`. With (1)–(4) the fence no longer reopens into
   a refusal, so this is confined to pressure that arises between the fence
   read and the dispatch (W9).
8. *Corrections.* D5's last column is two gates: physical SQLite headroom
   refuses every non-teardown receipt (`event_outbox_backpressure`,
   `outboxLimit: "physical"`), while runtime-file pressure refuses only
   `session.*` receipts (`503 runtime_storage_pressure`). A teardown is refused
   for its wallet's own serialization *or* for exhausted wallet credit
   (`outboxLimit: "wallet"`). D11's flow slot hold, when the incarnation
   projects `lost`, is bounded: keep-alive Pass 1 idles the run at
   `keepalive_until` unless the auto-resume resumed it first.

| # | State after the crash or gap | Owner that finishes it |
| --- | --- | --- |
| W10 | A sample fetched before a refusal committed | the delete matches `pressured_since <= sampledAt`: the record survives, the transition reads `held` |
| W11 | Record deleted, drain not run (process death or a throw) | the next sample on which the host admits new work drains |
| W12 | Local host re-registered while its old row held a record | the next admitting sample drains; the retired row's record fences nothing |
| W13 | Auto-resume or re-drive keeps throwing | per-row backoff and an ERROR line; retried until it succeeds or an operator answers |

**Amendment (2026-09-26, as built in T2.1–T2.16).** Where the implementation
departs from the text above:

- **Sequence allocator.** `librarian_conversations.last_seq` allocates
  `librarian_messages.seq` (`last_seq + 1` under the conversation row lock), so a
  deleted tail can never hand a seq out twice; `read_through_seq` is clamped to it.
- **Start restarts.** `librarian_turns.start_attempts` counts restarts of a turn
  whose host was lost before its prompt command was queued; the D9 recovery pass
  restarts at most three times, then fails the turn `host_lost`. A failed
  `session/resume` falls back to `session/new` with create ordinal 1 inside the
  same start.
- **History-clear barrier.** `reset_state` also takes `clearing` (ADR-188's
  clear), distinct from a context reset's `resetting`; both refuse admission with
  `CONFLICT` `reset_in_progress`. The stream reports `clearing` as `resetting`.
- **Project-less run on session routes.** A librarian run reached through a run
  route (`/api/runs/{id}/…`) is refused by the central guard with 403
  `UNAUTHORIZED` `project_less_run`, not 404; the run stream is the one run route
  that admits it, for its owner only.
- **Codex L2.** Codex has no adapter-home deny file; its librarian session is
  held by L1 (the supervisor capability guard on the MCP-only profile) and L3
  (auto-approved permissions, no HITL). Claude gets all three layers.
- **System messages** store a code (`turn_stopped`, `turn_failed:<reason>`) that
  the panel localizes, never prose.
- **Live tokens (D8 of ADR-189).** The transcript projector skips
  `run_kind='librarian'` runs, and the browser run stream carries only canonical
  event ticks without bodies. The panel therefore shows a live "responding"
  status driven by the run stream, and the durable reply replaces it; streamed
  token text needs a body-bearing read and is not delivered in this release.
- **Deferred to ADR-188's tasks (T6.x):** purging the per-turn directory on
  history deletion and nulling retired execution-event payloads of a cleared
  conversation.
- **Boot validation.** All eight D7 budgets are read once at web boot
  (`instrumentation-node.ts`); a non-positive or non-integer value refuses boot
  with `CONFIG` naming the variable.

**Consequences:**

- A busy host with a caught-up manager is never "pressured" and never refuses a
  command for it; retained rows below every open prompt are pruned before the
  24 h grace, so the replay floor moves sooner. A consumer resuming from below
  it gets `replay_floor_lost` exactly as before (EDGE-EVT-03).
- **Measured limit (resolved by ADR-184).** An open v2 prompt's span stays protected (ADR-167
  D5: every completed v2 prompt is host-span eligible), and the replay floor is
  a contiguous prefix, so the OLDEST open prompt pins every later row of the
  stream, whatever session wrote it. When that turn's duration × the host-wide
  row rate reaches the hard budget, the prune stalls, frames are refused with
  the manager fully caught up, and the pause bound checkpoints every producer.
  R20 at the default budgets (nine turns of ~10 minutes at ~390 rows/s)
  reached soft at 205 s and hard at 253 s; all nine sessions were checkpointed
  at the bound and parked, none crashed, `pressured` stayed false. Pruning
  inside an open span (holes in the outbox, or ACKed rows given up by the span
  feed) changes ADR-167 D5 and the replay floor, and is left to a decision of
  its own. *Resolved 2026-09-27 by
  [ADR-184](../decisions.md#adr-184-an-open-prompt-does-not-pin-the-outbox--the-span-feed-reads-its-acked-prefix-canonically):
  the host prunes ACKed rows inside open spans and the span feed reads them
  canonically; these numbers stay as the record of why.*
- Operators can always tear down, and can answer under soft pressure: the soft
  gate refuses new work only. Under the hard bound an answer is refused, and
  the manager keeps it retryable instead of failing it
  (`isRefusedPermissionDelivery`). While the prompt waits on the permission its
  v2 span pins every later row, so the host cannot prune below hard; the
  keep-alive checkpoint (a teardown) releases it, and ADR-180's
  checkpointed-permission resume delivers the stored answer. *Since ADR-184 (2026-09-27) the
  waiting prompt pins nothing: its ACKed rows are pruned like any other, so
  the hard bound is reached only while the manager is behind.*
- A paused producer costs one respawn (~$0.28) after 5 minutes instead of a
  `stream-lost` crash. An agent message interrupted by a park is delivered at
  least once.
- The manager's view of pressure is up to one sweep (60 s) stale; a refusal
  sets it at once, so the common case is immediate.
- ADR-161's `resume` now claims a slot and restores context for operator
  interrupts too — a behavioural fix for a gap nothing had covered.
- One additive Postgres migration (`0182`: the table and the widened
  `node_attempts_action_resume_check`), one host SQLite migration (v14), jsonb
  widenings on `hitl_requests.schema/response` and
  `scratch_runs.error_metadata`, no new operator env var (the test-only
  `MAISTER_TEST_PRODUCER_PAUSE_MAX_MS` is read only under `NODE_ENV=test`) and
  no new `MaisterError` code.

**Alternatives Considered:**

- **Keep retained rows in the pressure predicate and raise the budgets:**
  rejected — it measures the operator's disk, not the manager; any budget is
  crossed by a day's healthy traffic inside the grace window.
- **A new `runs.status` for a host-parked run:** rejected — `NeedsInput` /
  `NeedsInputIdle` already mean "parked, resumable", and every consumer of the
  status enum would have to learn a synonym.
- **SIGKILL a paused producer:** rejected — it loses the turn's context, the
  ACP handle and the captured frames; ADR-180's graceful checkpoint keeps all
  three.
- **A manager-only pressure record in memory:** rejected — three readers (the
  admission fence, the stall pass, the run page's queue reason) and two writers
  (the health sample, the refusal) across processes need one durable value.
- **Letting a machine actor answer its own `node_interrupt`:** rejected — the
  ADR-161 human-only rule is a security rule; the sweep calls the shared
  internal application instead.
- **A 503 from `POST /api/runs` under pressure:** rejected — the run row would
  be lost; a queued `Pending` run keeps the operator's intent.
