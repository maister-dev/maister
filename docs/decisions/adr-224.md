# ADR-224: Supervisor diagnostics snapshot cache

> Part of the ADR log. See the [index and editing rules](../decisions.md).

**Date:** 2026-11-25
**Status:** Implemented

**Context:** The authenticated app layout awaits supervisor runtime
diagnostics before it streams the page body. Supervisor `GET /diagnostics`
recomputed the whole report on every request: it re-read the adapter smoke
cache, walked `PATH` for every adapter binary and spawned `gemini`,
`opencode` and `mimo --version` probes with a one-second timeout each. Every
navigation and every attention-driven `router.refresh()` paid that cost, and
concurrent navigations multiplied the child processes.

**Decision:** The supervisor serves `GET /diagnostics` from one in-memory
snapshot per process, owned by the pure policy module
`supervisor/src/diagnostics-cache.ts`:

- A snapshot younger than 30 seconds is fresh and is returned as is.
- A snapshot younger than five minutes is stale-servable: it is returned and
  exactly one background recompute starts.
- Otherwise the request awaits a compute. At most one compute runs at a time
  for non-forced readers (singleflight).
- `refresh=1|true` forces a compute. A forced reader joins an in-flight
  compute only when that compute started at or after the forced request
  arrived.
- A result is stored only when its generation is newer than the stored one.
- A change of the smoke-cache file `mtimeMs` invalidates the snapshot.
- A failed compute is never stored. Every joined waiter receives the failure;
  a background failure is logged and never thrown.
- `checkedAt` is the probe start time of the returned snapshot.
- An invalid `refresh` value answers 409 `PRECONDITION` with
  `details.reason: "diagnostics_query_invalid"`.

Web callers declare a freshness class. Snapshot-class callers (the chrome
layout and MCP readiness) never send `refresh`. Fresh-class callers (the
`/settings` default-runner reconcile, the admin ACP runner routes and launch
evidence) always send `refresh: true`.

**Consequences:**

- The left-rail readiness indicator may lag a host change by up to the TTL, or
  by up to the stale window on the first request after an idle period.
- On `/settings` the rail (snapshot) and the page (fresh) may briefly differ.
- The seven-day smoke freshness boundary shifts by at most the snapshot age.
- A background compute has no retry loop; the next request retries.
- No env var, config file, sidecar, port or mount is added, so the Dockerfile,
  compose files and `.env.example` are unchanged. The TTL values are constants
  with test-only `RegisterRoutesOptions` overrides.
- The snapshot lives in process memory only; a supervisor restart starts
  empty.

**Alternatives considered:**

- *A web-only cache.* Rejected: it does not protect the other callers of the
  supervisor route and still spawns per web process.
- *Suspense-streaming the rail readiness.* Kept as a follow-up: it hides the
  latency of the first compute but does not remove the per-request spawns.
- *A blanket TTL for every caller.* Rejected: the `/settings` reconcile is the
  single writer of runner readiness and launch evidence must describe the
  host at launch, so both need live data.

**Validation:** Measured on 2026-11-27 (production `web` build + live
`supervisor` + seeded Postgres test container, idle supervisor):

- `GET /diagnostics` latency (10 samples, host probes): median **0.49 ms**
  cached (range 0.37–2.84 ms) vs median **1007.2 ms** forced (`?refresh=1`,
  range 1003.8–1011.6 ms).
- 20 concurrent `GET /diagnostics` requests (3 probed shims — `gemini`,
  `opencode`, `mimo`): **3** shim spawns total in 158.9 ms (singleflight; 0
  spawns on steady-state reads) vs **60** shim spawns uncached (`20 × 3`).
- Authenticated page TTFB (`curl -w "%{time_starttransfer}"`, 10 samples):
  `/` median **62.6 ms** (59.1–68.7 ms), `/projects/e2e-m11a` median
  **62.1 ms** (55.5–66.7 ms) — removing ~1 s of per-request probe latency.
- Per-render query counts (`LOG_LEVEL=debug` on `/` and `/inbox`):
  `"decisions queue"` fires **1×** per render (2 `[decisions.cache] key`
  lookups coalesced) and `"[authz] loadUser"` fires **1×** per render.
