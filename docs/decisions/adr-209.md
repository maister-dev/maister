# ADR-209: Active sidebar membership by attention reason

> Implementation status is maintained in the [current contract](../screens/chrome/active-workspaces.md). The accepted decision below retains its original design-stage wording. Amends [ADR-181](adr-181.md) D14.

[Back to ADR index](../decisions.md#adr-209-active-sidebar-membership-by-attention-reason)

**Date:** 2026-11-15
**Status:** Accepted

**Context:** The left-rail "active" list included every `ACTIVE_RUN_STATUSES` Run (including `Failed` per ADR-181 D14) plus `Done`/`Abandoned` Runs with a TTL-scheduled workspace, and its counter counted all of them. Successful and superseded failed attempts of a finished task stayed in the sidebar.

**Decision:** One read-only predicate (`web/lib/runs/active-attention.ts`: SQL fragment plus an exhaustive classifier over `RunStatus`) decides rail rows and the counter together. Members: `Running`, `NeedsInput`, `NeedsInputIdle`, `HumanWorking`, `WaitingOnChildren`, `Review` (each with a reason label); `Crashed` and `Failed` only when they are the newest attempt of an open task, or task-less with a retained workspace. `Done` and `Abandoned` are never members. Excluded Runs stay reachable from the task history, `/runs`, Run pages, the inbox and the project "Runs and working copies" surface, which also lists `Done`/`Abandoned` Runs that still hold a TTL-scheduled workspace.

**Consequences:** No status, workspace, archive or GC change; TTL predicates are untouched. `ACTIVE_RUN_STATUSES` keeps its other consumers.

**Alternatives Considered:** Removing `Failed` entirely (loses the retry prompt for the newest attempt); keeping TTL rows in the rail (shows finished work as active).
