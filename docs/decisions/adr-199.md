# ADR-199: Immutable per-schedule agent requests

[Back to ADR index](../decisions.md#adr-199-immutable-per-schedule-agent-requests)

**Date:** 2026-11-02
**Status:** Accepted

**Context:** Timing-only cron bindings cannot express different recurring requests without changing reusable agent instructions. Reading a mutable binding at execution time would make queued and historical work change after edits.

**Decision:** Keep desired request text on each cron schedule, freeze a versioned protected input envelope in the atomic trigger claim, and copy it immutably to runs and authorized successors. Deliver it as literal current input through existing owned prompt protocols. Repository-content authorization gates disclosure. Permission policy, HITL and completion contracts remain independent.

The contract is **Designed**. [Scheduled agent requests](../system-analytics/scheduled-agent-requests.md) owns transitions, API/DB design, compatibility and acceptance.

**Consequences:** Additive nullable storage preserves legacy behavior. A complete compatible runtime must precede request-bearing writes; rollback retains evidence and drains request-bearing work. Unsupported input consumers refuse explicitly.

**Alternatives Considered:** Definition edits, mutable schedule lookup at dispatch and raw input in viewer-safe trigger metadata do not preserve independent requests, immutable evidence or disclosure boundaries.
