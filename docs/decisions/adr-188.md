# ADR-188: Librarian memory, summaries, reset barrier and history deletion

> Part of the ADR log — hub, index, and editing rules: [`../decisions.md`](../decisions.md).

**Date:** 2026-09-26
**Status:** Accepted

> **Amends [ADR-166](../decisions.md#adr-166-local-execution-host-contract--durable-host-identity-epoch-fenced-assignments-command-ledger-opaque-adopted-workspaces)**

> adapter transcript for it) and
> **[ADR-167](../decisions.md#adr-167-durable-execution-host-event-and-runtime-data-plane)**

**Context:** The brief ([personal librarian](../pv/personal-librarian.md), LIB-12
to LIB-14) requires durable, versioned personal memory separate from Project Brain
and agent memory; automatic summaries; retrieval that re-checks access on every use;
and three distinct controls — reset context, forget a memory, clear personal
history — none of which may claim an effect that does not happen. Facts verified in
the current tree:

- **Release deletes nothing today.** `WorkspaceRegistry.release`
  (`supervisor/src/workspace-registry.ts:192-203`) only stamps `releasedAt`; a
  released handle is then refused (`workspace_released`) and the web re-adopts once
  (`web/lib/execution-host/adoption.ts:249-256`). Releasing an assignment releases
  no handle (ADR-183 D3).
- **Adapter transcripts (T0.9 spike).** `claude-agent-acp` persists each session at
  `~/.claude/projects/<encoded cwd>/<sessionId>.jsonl`, outside the cwd; `/` and `.`
  in the cwd become `-`. codex runs with a per-session `CODEX_HOME` composed inside
  the cwd under `.maister/capabilities` (`web/lib/capabilities/adapter-home.ts:184-208`),
  so its rollouts live under the cwd; the composed home symlinks the global
  `auth.json` and `config.toml`. gemini keeps its native user home
  (`adapter-home.ts:181-183`); opencode and mimo use their own homes.
- **The run also holds turn content.** Every turn's composed prompt is stored in
  `execution_commands.request_canonical_json`, and `classifyCommandRetirement`
  (`web/lib/execution-host/retirement.ts:158-164`) protects every command of a run
  in `NeedsInputIdle` (`RETAINED_RUN_STATUSES`, `:35-42`) — the status a librarian
  run parks in between every turn (ADR-183 D5), so those commands are never
  compacted. Streamed replies and tool-call arguments sit in `execution_events.payload`,
  retained for the run's life (ADR-167 D2). The canonical transcript projector is
  run-kind-agnostic and would copy both into `run_messages`
  (`web/lib/execution-host/events/transcript-projector.ts:103-113`).

**Decision:** Personal memory and summaries are fenced, versioned records the
librarian may only write under the current generation. Reset is a server-side
barrier. Clearing history deletes the personal records, purges the host workspace
and the adapter transcript through the same barrier, and every other copy of turn
content is either never written or compacted on a stated bound.

**D1 — Records and separation.** Migration `0188` adds `librarian_memory_items`
(`kind ∈ {preference, goal, commitment, fact}`, `scope ∈ {general, project}`,
`project_id`, `source_refs`, `source_project_ids`, `origin ∈ {explicit,
accepted_suggestion}`, `valid_until`, `revision`, `forgotten_at`),
`librarian_memory_item_revisions` (PK `(item_id, revision)`),
`librarian_memory_tombstones` (PK `(user_id, content_digest)`) and
`librarian_segment_summaries` (UNIQUE `librarian_segment_summaries_revision_uq`,
with `from_seq`, `to_seq`, `source_project_ids`, `forget_generation`,
`history_generation`, `invalidated_at`). The fence columns live on
`librarian_conversations` (`0182`): `context_epoch`, `forget_generation`,
`history_generation`, `current_segment_id`, `reset_state`,
`memory_enabled_next_segment`. Personal memory never reaches Project Brain or an
agent's `memory.md`: an ESLint `no-restricted-imports` fence forbids
`web/lib/librarian/**` from importing `lib/brain/**` and
`lib/agents/memory-store` (LMM-11; `IT-LMM-11`).

**D2 — Memory writes.** An item is written only by an explicit "remember" inside an
`owner_message` turn (`POST /api/v1/ext/librarian/memory`, scope
`librarian:memory`; the route refuses a token whose turn variant is `explain` or
`summary`) or by the owner accepting a visible `memory_suggestion` card (ADR-185
D7). Anything the librarian infers stays a suggestion. Content is immutable in
place — trigger `librarian_memory_items_content_immutable` — so an edit inserts a
revision row and bumps `revision`. The snapshot records the used revisions
(`librarian_context_snapshots.memory_item_revisions`) and the reply renders them as
"used in this reply" (LMM-01, LMM-02, LMM-12; `IT-LMM-01`, `IT-LMM-02`,
`IT-LMM-12`).

**D3 — Summaries.** After a turn ends, when the active segment's unsummarized tail
exceeds half of `MAISTER_LIBRARIAN_CONTEXT_MAX_CHARS`, a `summary` turn is queued;
it is admitted only when no `owner_message` or `explain` turn is queued, at most one
is pending per segment (partial UNIQUE `librarian_turns_one_summary_uq` on
`segment_id` where `variant='summary'` and the turn is not terminal), and it gets
at most 2 attempts, after which the composer truncates and records `truncated` in
the snapshot. The summary turn attaches no MCP server and carries no token
(ADR-184's summary profile); any tool call fails it (`EDGE-LAU-04`). Its output is
validated against a summary schema that keeps `decisions[]`, `proposals[]` and
`uncertainties[]` apart and names the covered range `from_seq..to_seq` (T6.3).

**D4 — The generation fence.** Every summary and memory write — summary insert,
suggestion card, accepted suggestion, remember — carries the triple it started
under, `(segment ordinal, forget_generation, history_generation)`, and writes in a
statement guarded by the current values on `librarian_conversations`; a writer
that lost the fence writes nothing and logs `warn` fenced. Before writing, the
summary and suggestion writers digest each item —
`sha256` over the NFC-normalized, trimmed, case-folded, whitespace-collapsed text —
and drop any item whose digest is in `librarian_memory_tombstones`
(LMM-06, LMM-07; `IT-LMM-06`, `IT-LMM-07`, `EDGE-LMM-01`).

**D5 — Retrieval, masking and search.** Every use re-reads the owner's visible
projects (`getVisibleProjectIds`): a memory item or summary with an invisible
`source_project_ids` entry is dropped from context — a mixed summary is also marked
`invalidated_at` and queued for rebuild — and a librarian or update message with an
invisible source is both excluded from the composed context and rendered as an
explicit unavailable marker by `GET /api/librarian/messages`; the owner's own
messages always render. Automatic context reads only the active segment; an older
segment is reachable only through `librarian_history_search`
(`GET /api/v1/ext/librarian/history/search?q=`, librarian token only), a `simple`
`tsvector` over `librarian_messages.body` (`body_tsv`), at most 20 hits, masked
messages excluded, each labelled `from earlier conversation` in the reply
(LMM-03, LMM-04, LMM-09; `IT-LMM-03`, `IT-LMM-04`, `IT-LMM-09`).

**D6 — Reset is a barrier.** `POST /api/librarian/reset` runs one transaction under
the conversation row lock: `reset_state='resetting'`, queued messages
`delivery_state='withdrawn_by_reset'` and their turns `withdrawn` (ADR-183 D9), a
stop request for the current turn and revocation of its token. While
`reset_state <> 'none'`, `POST /api/librarian/messages` refuses
`CONFLICT{reason:"reset_in_progress"}` and admission admits nothing. The barrier
pass (`web/lib/librarian/reset.ts`, called inline and by the `system_sweep`
backstop) acknowledges only when no operation of the old segment is `admitted` or
`unknown` and no turn is `admitted` or `running`; the acknowledgement inserts the
next `librarian_segments` row, bumps `context_epoch`, marks pending cards
`cleared_by_reset`, clears `subject` and sets `reset_state='none'`. Memory is used
in the new segment only when `memory_enabled_next_segment` is true. Tasks, statement
revisions, clarifications and launched runs are untouched (LMM-05; `IT-LMM-05`).

| State at crash | Left as | Recovery owner |
| --- | --- | --- |
| reset committed, turn still running | `resetting`, turn `running` | barrier pass re-sends the stop; the ADR-183 deadline watchdog is the last resort |
| turn stopped, operations `admitted` | `resetting` | ADR-185 operation reconcile, then the barrier pass |
| barrier pass crashed mid-acknowledgement | transaction rolled back, `resetting` | next pass (idempotent) |
| late summary or memory writer | fenced (D4) | none — it writes nothing |
| late update for an old-segment task | delivered into the new segment as a bounded update card | ADR-185 D11, by design: tasks continue |
| clear committed, host release not yet succeeded | `clearing` | barrier pass re-issues `workspace.release` (D8), acknowledges on success |

The two-racer test for reset against admission asserts either the turn is admitted
into the old segment and then stopped, or refused — never admitted into the new
segment with old context (plan D15).

**D7 — Forget.** `DELETE /api/librarian/memory/{id}` sets `forgotten_at`, writes the
item's tombstone digest (D4), bumps `forget_generation` and `context_epoch`, and
marks summaries of the conversation with an older `forget_generation`
`invalidated_at`. The next snapshot cannot include the item; the ADR-183 epoch rule
forces `session/new`, so the adapter never resumes a context that held it. A reply
already running may still cite it, because its snapshot predates the forget
(`EDGE-LMM-02`). Remembering it again is a new explicit action and a new item.
Honest bound: the tombstone refuses an exact normalized match, not a paraphrase;
the guarantee against paraphrase is that forgotten items never enter context and
summaries are rebuilt from the active segment only (LMM-06; `IT-LMM-06`).

**D8 — Clear history.** `GET /api/librarian/history/clear-preview` returns counts
(messages, summaries, snapshots, cards, links that become unavailable, operations
kept) and `previewDigest = sha256(history_generation, max seq, counts)`.
`POST /api/librarian/history/clear {previewDigest}` refuses
`CONFLICT{reason:"conversation_busy"}` unless the conversation is quiescent (no turn
`queued`, `admitted` or `running`, no operation `admitted` or `unknown`,
`reset_state='none'`), and a stale digest with `409`. Then one transaction under the
conversation lock deletes messages (with their `body_tsv`), summaries, snapshots and
cards; lets the message references of links, turns, updates and clarifications
(`source_message_id`) fall to NULL through their `ON DELETE SET NULL` keys; bumps
`history_generation` and `context_epoch`; inserts the next segment; and sets
`reset_state='clearing'` — a third value of the `reset_state` CHECK, refused by
admission like `resetting`. Operations, audit rows,
tasks, statement revisions, published excerpts and memory items are kept. After
commit the web issues a driverless `workspace.release` for the run's newest
assignment's handle (the `releaseAdoptedWorkspace` precedent,
`web/lib/gc/workspace-reconciler.ts:461-483`; a stopped host leaves the ledger
command for recovery to re-deliver), and the barrier pass sets
`reset_state='none'` only once that command has succeeded. Because admission is
closed until then, the next turn's re-adoption of the same path can never race the
purge (LMM-08, TST-06; `IT-LMM-08`, `IT-TST-06`).

**D9 — Host purge on release (T0.9 outcome; ADR-166 amendment).** When
`WorkspaceRegistry.release` is asked to release a handle with `kind='directory'`
and `projectSlug='_librarian'`, the supervisor first refuses with `409` while a live
session still uses the handle; otherwise it stamps `releasedAt` and purges:
it re-validates that the handle's `realPath` lies under
`<runtimeRoot>/.maister/_librarian/`, removes that directory recursively without
following symbolic links (the composed `CODEX_HOME` links the global codex files),
and removes `<claude config dir>/projects/<encoded realPath>/`, where the config
dir is `$CLAUDE_CONFIG_DIR` when the supervisor's environment sets it, else
`$HOME/.claude`. A missing path counts as removed and a repeated release of an
already-released `_librarian` handle re-runs the purge, so the purge is idempotent;
any other failure fails the release, which leaves the ledger command retryable and
the barrier closed. The first removal covers codex's rollouts, the second claude's
transcripts. Runner scope: ADR-183 D8 admits `claude` now; `codex` remains
ineligible until its built-in host-read boundary is qualified (ADR-184 D10).
this decision adds that a runner whose `executor.env` sets `HOME` or
`CLAUDE_CONFIG_DIR` is refused as the librarian runner, because its transcripts
would live outside the purged path. gemini, opencode and mimo are not selectable in
this release; their transcript locations are not purged, and admitting one later
requires extending this rule. In every case the `context_epoch` bump forces
`session/new`, so a retained transcript is never resumed (`IT-LMM-08`, supervisor
part).

**D10 — Turn content outside the conversation tables (ADR-167 amendment).** The
durable transcript is `librarian_messages`; runtime copies are transient:

- **Projection.** The canonical transcript projector writes no `run_messages` for a
  `librarian` run; it already reads `runs.run_kind` (`transcript-projector.ts:105`).
- **Prompt bodies.** `classifyCommandRetirement` does not return `run_retained` for a
  `librarian` run in `NeedsInputIdle`: an ADR-183 turn never replays an earlier
  turn's prompt. Its commands are therefore compacted by `retireEligibleCommands`
  (`retirement.ts:239`) after `COMMAND_REPLAY_GRACE_DAYS` (7, `:24`) through the
  unchanged two-sided handshake, which nulls `request_canonical_json` and the other
  request and result columns (`compact`, `:200-219`). This also bounds the
  persistent run's command ledger, which would otherwise grow with every turn.
- **Event payloads.** Once every command whose span covers an event of a
  `librarian` run is retired, the retention pass (D11) sets that event's `payload`
  to NULL. Rows, sequences, `payload_sha256`, `payload_bytes` and a retired
  command's `terminal_event_id` reference stay, so ingest contiguity, stream
  positions and the foreign key are untouched; `GET /api/runs/{runId}/stream`
  skips a redacted event instead of sending an empty frame.

Residuals, stated: until compaction — at most `COMMAND_REPLAY_GRACE_DAYS` after a
turn plus one retention pass — its prompt body and streamed content remain in the
manager, readable by no one but the owner through `GET /api/runs/{runId}/stream`
(project-less authz `created_by_user_id`, `app/api/runs/[runId]/stream/route.ts:337-346`).
The host's per-session output logs under
`<runtimeRoot>/.maister/_librarian/runs/<runId>/` follow the host's runtime-object
retention for the run; neither clear history nor the retention pass removes them
in this release (`IT-LMM-08` asserts compaction and the absent `run_messages`).

**D11 — Retention.** A librarian pass in `runSystemSweep`
(`web/lib/scheduler/system-sweeps.ts:295`), wrapped like the existing passes, walks a
keyset cursor in sweep state in batches of 500 and: deletes `librarian_messages`
older than `MAISTER_LIBRARIAN_HISTORY_RETENTION_DAYS` (default **365**); deletes a
summary whose whole range was purged; deletes `librarian_context_snapshots` older
than `MAISTER_LIBRARIAN_SNAPSHOT_RETENTION_DAYS` (default **30**) unless their turn is
`admitted` or `running`; and redacts retired librarian event payloads (D10). A
per-row failure is logged and the batch continues. Memory items are not subject to
age retention: they are explicit personal records the owner edits and forgets. Both
variables are read by `web` only, must be positive integers (garbage refuses boot
with `CONFIG`), and land in `.env.example`, the compose files and
`docs/configuration.md` (LMM-10; `IT-LMM-10` through `runSchedulerTick`).

**Consequences:**

- Reset, forget and clear history are three different effects with three different
  guarantees, and each one's guarantee is exactly what the code performs.
- The owner cannot talk to the librarian while a reset or clear is in progress; the
  panel shows the barrier state. A host outage extends a clear's `clearing` window,
  never lets a turn race the purge.
- The supervisor gains its first deleting release path, bounded to one reserved
  slug, one root and one adapter-config directory.
- A librarian run's command ledger and event payloads stop growing without bound;
  the run's stream is useful only for the running turn's live tokens (ADR-189).
- Honest residuals remain: a paraphrase of a forgotten fact is not detected; turn
  content lingers up to the replay grace in the manager; host output logs are not
  purged; adapter-global state outside the verified transcript directory is not
  inspected.

**Alternatives Considered:**

- **Rotate the conversation to a new run on clear history.** Rejected: nothing
  deletes run rows today, a rotated run still retains its events for its life, and
  ADR-183 fixes one run per conversation that never ends.
- **Delete the run's `execution_events` rows.** Rejected: a retired command's
  `terminal_event_id` references its event `ON DELETE RESTRICT`, and deleting canonical
  rows would change what an ingest or replay position means; redacting the payload
  keeps the plane's invariants.
- **Claim that the epoch bump alone makes history "deleted".** Rejected: it makes
  retained transcripts unreachable by the librarian, not absent from the host.
- **Summaries produced inline by the owner turn.** Rejected: a summary written with
  the owner turn's tools and token could act; a tool-less, token-less turn cannot.
- **Semantic (embedding) matching for tombstones.** Rejected for this release (brief
  §5 excludes embedding-based search); the exact-digest bound is stated instead.
- **Delete memory items by age.** Rejected: they are the owner's explicit records,
  managed by forget.
