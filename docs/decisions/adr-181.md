# ADR-181: Run git panel: status-independent worktree git operations, public branch names, and PR before promotion

> Part of the ADR log — hub, index, and editing rules: [`../decisions.md`](../decisions.md).

**Date:** 2026-09-22
**Status:** Implemented

**Context:** A run's worktree already has every git primitive it needs —
snapshot commit, export push, handoff branch, archive/drop with a local
preservation ref, `sync` with the target ([ADR-141](adr-141.md)),
provider-dispatched PR creation ([ADR-049](adr-049.md)), reopen
([ADR-140](adr-140.md)), the rework claim ([ADR-160](adr-160.md)) — but they
are scattered over three surfaces and gated by run status in ways that leave the
operator with no path in exactly the cases where the work is most at risk. The
priority installation is a server the operator has no shell on, so each gap
below is a hard stop, not an inconvenience. All of them were verified against the
code on 2026-09-22:

- **Visibility.** `Failed` is absent from `ACTIVE_RUN_STATUSES`
  (`web/lib/queries/portfolio.ts`), and the board derives a `Failed` latest run
  to the Backlog `TaskCard`, which renders no lifecycle actions. A `Failed` run's
  Archive/Drop/Export exist only on its detail page. The left-rail menu never
  offers export for any status.
- **Missing workspace rows.** Agent runs with `workspace=none|repo_read`,
  non-allocator shared-tree children and project-less assistant runs have no
  `workspaces` row; the policy answers `missing-workspace` while the run
  inspector still lists "Export branch" as inert text.
- **Vanished worktree.** A `Crashed` run classified `worktree-gone` keeps its
  row, so the policy enables export, but `handoff-metadata` fails on `git status`
  and the Push/Handoff buttons stay disabled forever. Archive and drop preserve
  into a local-only `maister/archive/<runId>` ref and set `removed_at`, after
  which every git action is refused and nothing re-creates the worktree (reopen
  does, but only for a `Done` run with an open or conflicted PR).
- **The ADR-160 carve-out never opens.**
  `defaultWorkbenchLifecycleDeps.requireActiveSession` discards the user, so
  `viewerUserId` is always `null` in production, and both read models
  (`lifecycleActionsForWorkspace`, `deriveInspectorActions`) hard-code
  `claimOwnerUserId: null`. A `HumanWorking` run renders zero lifecycle buttons
  for its claim owner — the one actor the carve-out was written for.
- **Publish is invisible.** `exportWorkbenchBranch` pushes the internal branch
  as-is, never sets upstream and records nothing; `isBranchPublished` is
  `pr_url != null || branchHasUpstream`, so an exported branch without a PR reads
  as unpublished and a later `sync` will not push it by default.
- **PR is a promotion.** The only `pr_url` writer is `promoteRun(pull_request)`,
  admitted from `Review` alone, with a hard-coded title and body, no draft flag,
  `origin` hard-coded, a target the UI cannot edit, and a `createOrUpdatePr`
  that returns an existing open PR untouched. `pull_request` promotion marks the
  run `Done` at PR-open time.
- **Update is `Review`-only.** `sync` refuses every other status, syncs only onto
  the target (never the base, which flow runs may set differently) and cannot
  bring the operator's own remote pushes back into the worktree except through
  the rework-claim return, which is fast-forward-only and flow-only.
- **Names.** Flow branches are `<prefix>task-<uuid>/attempt-N`, agent branches
  `<prefix>agent-<id>-<8hex>`; the human-readable `task_key` and title are used
  nowhere. No rename path exists; `branch_prefix` is read-only in the UI.
- **Discard.** Uncommitted work can be committed (snapshot) but never discarded
  outside a review-gate banner, while both return routes refuse a dirty tree.
- **Scratch.** The scratch promote select offers `rebase_merge` and
  `pull_request`; the server refuses anything but `local_merge`.

The operations an operator needs are the same in every parked status: take the
work out (commit, publish under a name a reviewer recognises, open a PR), bring
the outside world in (fetch and rebase/merge onto base, target or the operator's
own remote pushes), and see or clean the tree. The invariants that protect the
worktree — one writer, preserve-before-destroy, host credentials only, typed
errors, no filesystem polling — do not depend on the run's status either.

**Decision:** One **git panel** per run, one **policy**, one **read model**, and
a **public branch name** decoupled from the internal branch identity.

1. **Status-independent policy.** A single predicate admits every git action
   (`commit | discard | publish | update | openPr | finalizePr | reattach`, plus
   the existing `archive | drop`) when ALL hold: `runs.status ∈ {Review,
   Crashed, Failed, Done, Abandoned}`, OR `runs.status = 'HumanWorking'` and the
   viewer is the open rework claim's `owner_user_id` (the ADR-160 carve-out,
   now for the whole set including `discard`); a `workspaces` row exists; the
   worktree is usable (`removed_at IS NULL` and the path exists) — except
   `reattach`, admitted precisely when it is NOT usable and the branch is still
   resolvable; no active `execution_assignments` row; the
   `lifecycle_operation_*` slot is free or stale. Live statuses (`Pending` …
   `NeedsInputIdle`, `WaitingOnChildren`) and unknown statuses admit nothing.
   The three defects hiding the ADR-160 carve-out are fixed here: the production
   deps return the session user, and every run-detail read model passes viewer
   and claim owner. Cards and the rail keep the ADR-160 rule (no `HumanWorking`
   actions off the run detail).
2. **`Failed` is a parked workbench.** `Failed` joins `ACTIVE_RUN_STATUSES`
   (portfolio, project workspace list, rail — without the terminal TTL), the
   Backlog `TaskCard` renders the lifecycle menu when the latest run's worktree is
   usable, and `Failed` stays OUT of the [ADR-169](adr-169.md) attention counters:
   a failed run owes a git decision, not an answer.
3. **One lazy read model.** `GET /api/runs/{runId}/git-state` returns the
   internal branch, the public name and upstream, the remotes, dirty counts
   (tracked + untracked), ahead/behind against base, target and the published
   remote ref, the unpushed-commit count, the PR fields, the busy lifecycle op,
   worktree presence and the re-attach sources. It is fetched on panel open and
   after every action, never computed in a page RSC.
4. **Public branch name.** The internal branch stays the identity — unique by
   construction and bound to scheduled-launch reservations. Publish pushes the
   refspec `refs/heads/<internal>:refs/heads/<public>` with `--set-upstream` and
   records `workspaces.published_branch`, `published_remote`, `published_at`.
   The public name resolves in this order: (a) the branch's existing upstream —
   no name is asked; (b) an explicit `branchName` in the request — the override;
   (c) the project template `projects.public_branch_template`, default
   `feature/{task_key}-{slug}`, mirrored in `maister.yaml` as
   `project.public_branch_template` through the existing settings write-back.
   `{task_key}` resolves to `run-<8hex>` when the run has no task; `{slug}` is
   the task title transliterated (Cyrillic → Latin by a fixed table),
   lower-cased, `[a-z0-9-]`, at most 40 characters, and empty when nothing
   survives so the name collapses to the key; `{attempt}` is available and unused
   by the default. A remote branch already at another head (a prior attempt) is
   the ordinary non-fast-forward refusal with the existing force-with-lease
   retry — no suffix rule. The lease is an explicit-SHA lease captured by
   `ls-remote` BEFORE the push (the ADR-141 safety property), not git's implicit
   tracking-ref lease. Every consumer that assumed "remote name = local name"
   reads `published_*` instead: the sync push, the rework-claim return ingest and
   `isBranchPublished`.
5. **Update is the ADR-141 core, generalised.** `POST /api/runs/{runId}/sync`
   gains `onto: "target" | "base" | "published"` (default `target`) and is
   admitted by the policy in D1 instead of `status = 'Review'`.
   `onto:"published"` fetches `<published_remote>` and fast-forwards, or rebases
   with `strategy`, the internal branch onto
   `<published_remote>/<published_branch>` — the way the operator's laptop pushes
   come back. A conflict ALWAYS aborts and restores the pre-operation SHA
   (`abortSyncOperation` + `restoreWorktreeToCommit`), returning
   `outcome:"conflict"` with the conflicting paths; the AI resolver
   (`agent:true`) stays admissible ONLY from `Review`, because it is the one path
   that flips the run to `Running`. `run_sync_attempts.target_ref` records
   whichever ref was chosen. The push-after-update default remains "iff
   published".
6. **PR before promotion.** `POST /api/runs/{runId}/pr` opens — or finds by
   head/base — the provider PR from the published branch to `targetBranch`
   (default `workspaces.target_branch`, else the project main branch) with
   `title`, `body` and `draft` from the request, pre-filled by the UI from
   `task_key`, the task title and the run link, through the existing
   `PrAdapter` (`gh --draft`, `glab --draft`; the Gitea family maps `draft` to a
   `WIP:` title prefix because its API has no draft flag). It writes
   `workspaces.pr_url`, `pr_number`, `pr_state='open'` and changes NO run
   status; `pr_state_scan` already tracks any non-scratch workspace with a
   `pr_url`. `POST /api/runs/{runId}/pr/finalize` is the finalize step of
   `pull_request` promotion extracted into its own operation: from `Review` it IS
   `promoteRun(mode:'pull_request')`, so the readiness gate still applies; from
   `Crashed | Failed | Abandoned` there is no graph readiness to assert, the
   operator's click is the decision, and the run goes `Done` with
   `promotion_state='done'`, `promoted_head_sha`, the GC schedule and the
   `run.promoted` / `run.done` events exactly as today, attributed
   `source:"pr_finalize"`. Finalize is admitted while `pr_state` is `NULL`,
   `open` or `merged`; a `closed` PR is refused. An externally merged PR is
   surfaced by the scan and finalized manually — promotion stays manual by
   default. (Amended 2026-09-26, Codex review.) The parked finalize reads the
   recorded PR from its provider and binds to the head it carries, since the
   latest publication is not the PR: an open PR at another head is
   `publish_stale`, a merged one without the worktree's `HEAD`
   `merged_pr_behind`, one the provider reports closed `pr_closed`.
7. **Discard is preserve-first.** `POST /api/runs/{runId}/discard-changes`
   snapshots the dirty tree (tracked + untracked) into
   `refs/maister/rescue/<runId>/<n>` by a detached commit, then `git reset
   --hard` + `git clean -fd`. A clean tree is refused. The rescue ref is listed
   in `git-state` with a copyable restore command; per-file discard is Phase 2.
   (Amended 2026-09-26, Codex review.) The index as it stood is the rescue's
   second parent whenever it holds something the rescued tree does not — a file
   staged at one version and edited to another, a staged file since deleted —
   so the reset never takes the only copy of staged work. The preserve step of
   every removal (GC, archive, drop) writes the same rescue ref first when a
   path is staged and then changed again, which its `add -A` would overwrite.
8. **Re-attach.** `POST /api/runs/{runId}/reattach` re-creates the worktree for
   an unusable workspace from the first resolvable source: the local internal
   branch, else `<published_remote>/<published_branch>` (fetched, the internal
   branch re-created at its head), else `archived_branch`. It nulls `removed_at`,
   keeps `archived_*` as history, re-stamps provenance v2 and records
   `lifecycle_operation_name='reattach'`. Reopen keeps its own revival path;
   both call the same helper. (Amended 2026-09-26, Codex review.) A run the GC
   collects (`Done | Abandoned | Failed`) gets a fresh `scheduled_removal_at` of
   now + `MAISTER_GC_AGE_DAYS`, since the tree was taken for age and the next
   sweep would take it again; any other status gets `null`, as its own terminal
   transition stamps the window (and `Failed` stamps none, so an earlier one
   would carry into it).
9. **Unpushed-work guard.** The Archive and Drop dialogs show the commits and
   dirty files that exist on no remote (from `git-state`) and offer "Publish,
   then archive/drop" or "Archive/drop anyway". Operator archive/drop honour
   `MAISTER_GC_ARCHIVE_PUSH` like the GC path; the archive ref remains a local
   safety net by default — the deliverable is the public branch.
10. **Scratch.** `promoteScratchRun` admits `rebase_merge` and `pull_request`
    (the target stays the scratch base); the scratch inspector hosts the same
    panel.
11. **Surfaces.** The panel replaces the Export dialog on the run detail (flow,
    agent, scratch) and absorbs the ReviewPanel sync dialog; `promote` stays in
    the ReviewPanel with the same state chip. Cards and the rail get the panel's
    actions as menu items from the same DTO. The inspector Actions tab lists
    only href-bearing items. The lifecycle op slot gains the TS-only values
    `discard | reattach | prOpen | prFinalize`; `publish` reuses `exportBranch`
    and `update` reuses `sync`.

**Consequences:**

- One migration: `workspaces.published_branch`, `published_remote`,
  `published_at` (nullable) and `projects.public_branch_template` (`text NOT
  NULL DEFAULT 'feature/{task_key}-{slug}'`); the ERD is regenerated. No
  `runs.status` value and no `MaisterError` code is added
  (`docs/error-taxonomy.md` gains cells only).
- New routes `git-state`, `discard-changes`, `pr`, `pr/finalize`, `reattach`;
  extended bodies on `export-branch` (`branchName`) and `sync` (`onto`). The
  contracts live in `docs/api/web.openapi.yaml` and
  [`../system-analytics/workbench-git.md`](../system-analytics/workbench-git.md).
  The ext API and the MCP facade are unchanged (Phase 2).
- `PrAdapter` grows `draft`; the Gitea family maps it to a `WIP:` title prefix.
- Two consumers change meaning: `isBranchPublished` reads `published_*` before
  the upstream probe, and the rework-claim return ingest fast-forwards from
  `<published_remote>/<published_branch>`.
- A `Failed` workbench appears wherever `Crashed` does; portfolio counts and the
  rail grow accordingly, the attention counters do not.
- A `Done` run finalized from `Failed` carries `promoted_head_sha` = the head
  its PR carries and no `merge_commit_sha`, exactly like a `pull_request`
  promotion; `repo_delivery_scan` closes the loop from provenance once the PR
  merges, as for any `promotion_state='done'` workspace.
- Crash windows are recovered, not prevented, and each is idempotent by
  construction: a pushed-but-unrecorded publish re-pushes as a no-op and
  records; a created-but-unrecorded PR is found by head/base on retry; finalize
  rides the existing promotion claim; a discard whose reset was lost creates a
  second rescue ref; a re-attached-but-unrecorded worktree is reconstructed by
  the workspace reconciler (`workspace_reconstructed`).
- Tests: every policy and guard is falsified by reverting its fix;
  publish/update/discard/reattach run against real git fixtures; the provider
  boundary stays mocked in CI, so a live `gh`/`glab` PR-open with the draft flag
  MUST be exercised manually against a real remote, as ADR-049 already requires.
- Delivered as one plan, internally ordered so the branch stays green: panel +
  `git-state` + commit/discard/publish + visibility + the carve-out fix; then
  update + reattach; then PR open/finalize + scratch modes.

**Alternatives Considered:**

- _Patch the status matrix only_ (keep the Export dialog, the ReviewPanel sync
  and the scratch promote block): rejected — three surfaces with three gates is
  how the `Failed`, `worktree-gone` and `HumanWorking` dead ends arose; a fourth
  would follow.
- _Hand every git operation to the operator's machine_ (export + copyable
  commands + "open in editor"): rejected as the primary path — the priority
  installation is a server the operator has no shell on; it survives as the
  copyable checkout and restore commands the panel prints.
- _Adopt a `Failed` run into `Review` so the existing Review machinery applies_:
  rejected — `runs.status` is execution history ([ADR-148](adr-148.md)),
  readiness would still block a flow run, and the Observatory would count a lie.
- _One task-level public branch and PR shared by all attempts_: rejected for
  now — attempt N+1 is cut from the base, so its push replaces the branch content
  under reviewers; the per-task default name plus the ordinary non-fast-forward
  refusal gives the same ergonomics without a new entity.
- _`promote` with a readiness override from `Failed`/`Crashed`_: rejected — it
  breaks the readiness contract (`docs/system-analytics/readiness.md`);
  `finalizePr` outside `Review` asserts nothing it cannot know and says so in its
  attribution.
- _Run the AI resolver from `Failed`/`Crashed` via a `Failed → Running → Failed`
  excursion_: rejected — every status consumer (board, portfolio, the sweeps,
  the caps, the promote/sync fences) would need the excursion; the escape hatch
  is the mechanical abort plus a scratch run cut from the failed branch, which
  the scratch launch already admits.
- _A suffix rule (`-a{N}`) for a public name taken by a prior attempt_:
  rejected — the non-fast-forward refusal with force-with-lease retry plus an
  editable name already covers it.
- _Push the archive ref to the remote on every archive/drop_: rejected —
  `maister/archive/<uuid>` refs are noise on a shared remote; the unpushed-work
  guard plus the existing `MAISTER_GC_ARCHIVE_PUSH` knob cover the loss case.
- _Rename the internal branch to the public name_: rejected — the internal name
  is bound to scheduled-launch reservations and the attempt-uniqueness
  invariant; a refspec push decouples identity from presentation at zero cost.

**Amendments:**

Non-direction refinements recorded before implementation (2026-09-23); each
corrects a premise the code refutes or fills a gap the decision leaves open.

- **Op and action name `discardChanges`.** `discard` is already the crashed-run
  workspace removal (`POST /api/runs/{runId}/discard`, lifecycle op `discard`),
  so D7's operation is `discardChanges` (route `discard-changes`), and D11's
  TS-only op values read `discardChanges | reattach | prOpen` (as built, a PR
  finalize holds the promotion claim, so `prFinalize` is not a lifecycle op
  value).
- **The execution-assignment arm is implied, not checked.** A `Crashed` or
  TTL-abandoned run keeps its `active` `execution_assignments` row by ADR-166
  design (the recover CAS fences against the retained generation), so D1's "no
  active `execution_assignments` row" read literally would refuse the primary
  case. Every re-entry flips `runs.status` inside its CAS before it touches the
  tree, so a parked status is the no-live-writer witness. `git-state` reports
  `hasActiveAssignment` as information only.
- **Finalize's status allow-list is D6's.** `finalizePr` is admitted from
  `Review` (via `promoteRun`) and `Crashed | Failed | Abandoned` only. D1's
  "whole set" wording and the analytics table's `HumanWorking`-owner and `Done`
  cells over-stated it: the owner keeps `finalizePr` refused as `human-owned`
  (a status change while the claim is open), and `Done` refuses it as already
  finalized.
- **Finalize from `Review` carries the reviewed target.** `promoteRun` refuses
  every manual promotion without `reviewedTargetCommit`, so the finalize body is
  `{reviewedTargetCommit?, allowTargetDrift?}`, forwarded to `promoteRun` from
  `Review` and refused with `CONFIG` for any other status. `git-state` exposes
  `targetHead`.
- **One writer includes promotion.** D1's lifecycle slot and the promotion claim
  are distinct locks on the same `workspaces` row. The lifecycle claim refuses a
  live promotion claim and `promoteRun` refuses any live lifecycle claim, so no
  git operation runs inside a worktree a promotion is rebasing. A live
  promotion claim reads `busy` in the policy, and a promoted run's `update` is
  refused (`promoted`); reopen remains the way back.
- **Template placeholders.** `{task_key}` is composed from `projects.task_key` +
  `-` + `tasks.number` (no `tasks.task_key` column exists), else `run-<8hex>`.
  `{attempt}` is the internal branch's `attempt-N` suffix for a flow run and `1`
  otherwise.
- **Open PR is from `origin`.** The provider adapters resolve `--head` in the base
  repository and pull-request promotion pushes to `origin`. A branch published
  to another remote is refused until it is published to `origin`; cross-repository
  PRs are out of scope. The adapter result also reports `reused`, the only honest
  source for "the existing open PR was returned untouched".
- **The ext sync route keeps `Review` eligibility.** It shares the sync core, so
  the core takes an explicit admission mode — the workbench policy for
  `POST /api/runs/{runId}/sync`, the original `status='Review'` arm for
  `POST /api/v1/ext/runs/sync` — as Consequences' "ext API unchanged" requires.
- **Git identity.** Snapshot and rescue commits supply a default identity when
  the host has none (`commitIdentityArgs`), so `workspace_git_identity_invalid`
  remains an archive/drop preservation refusal only.
- **Reattach and reopen share the revival, not the write.** The shared helper
  re-creates the worktree only. Reattach clears `removed_at`, gives a run the
  GC collects a fresh `scheduled_removal_at` (decision 8) and keeps `archived_*`;
  reopen keeps its own writes
  (it clears `archived_*`). A re-attached but unrecorded worktree is repaired by
  the workspace reconciler's `workspace_reattached` arm (not
  `workspace_reconstructed`, which inserts a missing row).
- **The handoff branch stays.** The handoff form (remote + handoff branch name)
  moves from the retired Export dialog into the panel's Publish section,
  unchanged, with the same routes.

As built (2026-09-23), refinements found while implementing:

- **An existing public name outranks the template.** The name resolves from the
  upstream, else the recorded `published_*`, else a pre-ADR-181 PR's head (the
  internal name on `origin`) — each on the pushed remote — before the request
  and the template; otherwise re-promoting a reopened pre-ADR-181 run would open
  a second PR. `nameSource: "upstream"` names every fixed case.
- **An update may land on the run's own publication.** Onto `published`, with
  nothing local past the ref, landing exactly on it is the update, so the
  verify gate's "identical to the target" refusal is waived there only.
- **One PR finalize.** The parked finalize mints the promotion claim like a
  promotion and runs promotion's own PR finalize, attributed `pr_finalize`
  there (not through `promoteRun`'s input). A shared tree's finalized allocator
  settles with its `Review` siblings.
- **Scratch.** A scratch rebase lands by fast-forward and records no merge
  commit; Open PR on a scratch run honours the scratch target lock, so a later
  finalize finds the same PR; the scratch claim fences against live workbench
  operations now that it has writers.

Decided by the owner after implementation (2026-09-23):

- **One writer per worktree covers recover.** Recover used to flip
  `Crashed → Running` without reading the lifecycle slot, and the lifecycle
  claim recorded `expectedRunStatus` without comparing it, so an agent could be
  resumed into a tree a git operation was rewriting — a gap widened by this
  ADR's git actions on `Crashed`. `resumeCrashedRun` and the scratch recover
  now refuse `CONFLICT` `busy` while a live lifecycle or promotion claim holds
  the tree, and the lifecycle claim and the parked finalize decide on the run's
  status under the `runs` row lock, taken after the `workspaces` row lock once
  the slot is known free.
- **A `Failed` worktree expires.** Decision 2 listed `Failed` "without the
  terminal TTL" and the Consequences let the rail grow accordingly — with no
  bound, since `Failed` is never GC-disposable. The worktree GC now collects a
  `Failed` run's worktree like a `Done` one (`WORKTREE_TTL_RUN_STATUSES`:
  `gcAgeDays` after `ended_at`, preserved first to `maister/archive/<runId>`,
  which Reattach restores from), and the rail and run detail show its countdown.
  Its runtime objects are not collected (retention keeps `Done | Abandoned`),
  and a `Failed` reuser of a shared tree still holds the tree. As built, the rail
  no longer labels a `Failed` row "Running" — an unmapped status fell through to
  the live tone.

Decided by the owner after review (2026-09-25):

- **A force replaces exactly the head the operator confirmed.** D4's lease was
  read by `ls-remote` at the forced retry, so newer work that landed on the
  public name after the refusal was overwritten on an unconfirmed checkbox. A
  non-fast-forward refusal now names the remote head it observed and the ref
  (`remoteHead`, `remoteRef`); the panel confirms the force in the shared
  destructive dialog, naming the ref, the head and an open PR on the branch;
  the retry sends `expectedHead` (required with `force`, refused without it, a
  full SHA), and the push's explicit-SHA lease is that head. A remote that moved
  on is refused again with its new head for a fresh confirmation. The handoff
  branch never forces.
- **A template must name the task.** D5 validated a custom template only for
  "at least one placeholder" and one sample render, so `feature/{slug}` passed —
  two tasks with one title, or every task-less run, rendered the same public
  name, and a confirmed force on one would replace the other's branch. A
  template must now contain `{task_key}` (unique per task, `run-<8hex>` without
  one) and render a valid name both with a task and without one. Attempts of
  one task still share their name, as D4 intends.
- **No force-push drops the publication's own commits silently.** ADR-141's
  sync push, which the panel's Update now reaches in every parked status, is a
  force-with-lease on the head read at the time, so commits only the
  publication had (a reviewer's fixup, a suggestion committed on the PR) left
  the branch without a word. Every force-push of a run branch now asks one
  guard first. The guard counts commits reachable from the lease head, from
  neither the update's ref nor any head the run branch has had, and not the
  same patch as the run's own. A merge counts unless it is exactly what git
  makes of its two parents (a provider's "Update branch"): one that resolved a
  conflict, or carries an edit of its own, holds changes nothing else has
  (amended 2026-09-26, Codex review). The branch's reflog is what
  knows those heads: a rebase whose push never landed, or a squash, replaced
  the run's own commits, not the publication's. With the reflog expired or off,
  only the patch match is left and such a push is refused rather than guessed.
  The update refuses `CONFLICT` `publication_diverged` before its claim, and
  the squashing PR promotion refuses before its squash, releasing its claim.
  Only the git panel may confirm the drop, by sending back exactly the refused
  head: its refusal dialog offers the same update onto the publication first,
  or overwriting exactly that head. A refused promotion reads as that on the
  review panel, never as a merge conflict. The ext API, `ai_rebase_merge` and
  the resolver have no confirmation path. The resolver's finalize and the
  recovery sweep push on the lease the admission checked.
