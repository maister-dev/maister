# ADR-197: Explicit fenced agent retry admission

[Back to ADR index](../decisions.md#adr-197-explicit-fenced-agent-retry-admission)

**Date:** 2026-10-30
**Status:** Accepted

**Context:** Frequent operational execution currently exposes session failures as workspaces and per-run attention, while routing confidence does not establish request validity or safe replay.

**Decision:** A human may create one new attempt on a selected runner only after canonical evidence proves no work was dispatched. Freeze the accepted recipe; serialize request identity and successor lineage in a durable fenced intent. Adopt only exact owned allocations after crash. Transfer disposal ownership atomically to the created run; preserve unknown bytes and unknown host outcomes.

The contract is **Implemented**. Existing agent behavior remains explicit legacy until its scoped migration/capability boundary. Canonical state transitions, wire shapes, schema and acceptance belong to [the owning domain](../system-analytics/agent-retry.md), not this rationale.

**Consequences:** Platform/schema/MCP/UI deploy before compatible core and explicit project policy/pin changes. No automatic approval, promotion, blind side-effect replay or remote publication is introduced. Additive evidence survives cleanup and rollback; incompatible old writers stay fenced.

**Alternatives Considered:** Agent-ID exceptions, cosmetic Review filters, empty-diff promotion, prompt-only validation and a parallel workflow engine do not enforce the stated boundaries.

**Checks:** [Acceptance traceability](../system-analytics/agent-activity-traceability.md).
