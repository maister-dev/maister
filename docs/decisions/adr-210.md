# ADR-210: Versioned agent memory vaults in PostgreSQL

> Part of the ADR log — [index and editing rules](../decisions.md). Supersedes the agent memory file contract in [ADR-152](adr-152.md), part C.

**Date:** 2026-11-19
**Status:** Accepted

**Context:** Agent attachments need private cross-run memory with independent note edits, attributable history, recovery and governed review. The previous contract stores one markdown file and uses an attachment-wide content hash.

**Decision:** Store each vault, note, revision, operation and launch injection manifest in the main PostgreSQL lineage. Stable project and installation attachment identities partition the vaults. The current attachment and current source authority govern access. A note mutation compares its base revision and hash and commits the effect and operation receipt together. Retain history across detach, clear and rename. The global administrator may redact an exact revision through an audited, atomic payload removal. Optional vector search uses a rebuildable Brain projection.

An attested agent session receives a bounded protocol, visible index and path listing. It reads and changes notes through the vault API. Launch receipts record the applied manifest. Existing raw-file hashes retain their original interpretation. Review is required for externally sourced executions and for installation agents. Promotion carries an exact revision reference into an existing governed proposal.

**Consequences:** An explicit migration imports and verifies legacy files and historical snapshots before activation and later file cleanup. Legacy index endpoints get a compatibility release. The vault and Project Brain retain separate storage and authority.

**Alternatives Considered:** A Git-backed vault would conflate the agent's private working memory with repository ownership and worktree access. A single replacement document would serialize unrelated edits and make note-level recovery impossible.

The [agent memory contract](../system-analytics/agent-memory.md) describes the Designed behavior and its implementation status.
