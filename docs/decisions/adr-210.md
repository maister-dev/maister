# ADR-210: Sandboxed execution, runner access profiles and host-side credential confinement

[Back to ADR index](../decisions.md#adr-210-sandboxed-execution-runner-access-profiles-and-host-side-credential-confinement)

**Date:** 2026-11-19
**Status:** Proposed

**Context:** The execution host accepts trusted manager requests and launches processes that can evaluate repository-controlled instructions and code. CLI, check and setup execution also has direct web-side launch paths. The command ledger is bound to Run assignments, while preflight probes, diagnostics and package installation need an execution identity before a Run exists.

**Decision:** Separate the web manager, trusted execution supervisor and unprivileged workload. Authenticate all manager traffic. Start each workload in a disposable host-enforced policy with immutable launch evidence and an epoch-fenced execution identity. Use the host as the sole network and credential broker. Preserve existing Run events and route non-Run operations through the same durable stream and acknowledgement ordering. Resolve all editable permissions within the platform ceiling before dispatch. Record an explicitly authorized exception as a weaker execution class.

**Consequences:** Missing or stale enforcement evidence refuses admission. Resumes retain frozen policy and recheck live authority, physical scope and credentials. Non-Run receipt storage requires coordinated Postgres and host SQLite migrations. The platform advertises individual OS, workload and enforcement capabilities after qualification. Checkout writes require a qualified isolation boundary for Git metadata and independent actor attribution. Live provider compatibility and performance targets require measured evidence.

**Alternatives Considered:** Adapter-native permission prompts, administrator-owned Git hooks and direct provider environment variables remain insufficient as enforcement boundaries. Keeping pre-Run commands in the web process would retain a workload execution path outside the host policy.

The designed behavior, boundaries and qualification requirements are in [Execution isolation](../system-analytics/execution-isolation.md). Its activation amends ADR-023 (service identity), ADR-065 (runner administration), ADR-095 (approval), ADR-114 (session policy), ADR-153 (child environments), ADR-166 D12 (placement and command fencing) and ADR-179 (MCP secret handling).
