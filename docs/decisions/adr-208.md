# ADR-208: Run duration and execution time

> Implementation status is maintained in the [current contract](../system-analytics/runs.md#run-timing). The accepted decision below retains its original design-stage wording.

[Back to ADR index](../decisions.md#adr-208-run-duration-and-execution-time)

**Date:** 2026-11-15
**Status:** Accepted

**Context:** The task page showed `ended_at − started_at` (including queue and human waits) and the Run header summed node-attempt durations (double-counting parallel attempts and including waits), so neither answered "how long did the agent work".

**Decision:** Every Run exposes two metrics. **Duration** = `(ended_at ?? now) − started_at`. **Execution** = the measure of the union of execution intervals (non-human node attempts; agent turns for agent and scratch Runs; child Run execution clipped to the parent window) minus the union of wait intervals (open HITL requests, checkpoint idle, admission before the first execution), clipped to the Run window. Each carries a quality `exact | partial | unavailable`; missing evidence is never shown as zero. A pure projection computes both from a batched loader; the task Run history, the Run header and the `/runs` ledger show both columns, and a keyboard/touch-accessible popover shows the wait breakdown.

**Consequences:** Parallel branches and retries never exceed wall clock. Legacy Runs without ledger evidence render `—` with a reason. No schema change.

**Alternatives Considered:** Summing attempt durations (double counts); a status-transition history table (new write path on every transition for a read-only metric); showing only wall clock (hides execution efficiency).
