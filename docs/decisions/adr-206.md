# ADR-206: Provider-neutral task external source binding

> Implementation status is maintained in the [current contract](../system-analytics/tasks.md#external-source-binding). The accepted decision below retains its original design-stage wording.

[Back to ADR index](../decisions.md#adr-206-provider-neutral-task-external-source-binding)

**Date:** 2026-11-15
**Status:** Accepted

**Context:** Tasks imported from an external tracker carried their identity only as prompt text (`Source-GitHub-ID`, `Source-GitHub-Issue`) and comment receipts. Nothing in the database prevented two tasks for one issue, title or prompt edits could erase the marker, and visible numbers (`#7`) collide across repositories and hosts. The code-host provider (`projects.provider`) does not describe where work items come from.

**Decision:** A task may carry at most one structured external source binding in `task_external_sources`, keyed by `(project_id, source_kind, source_instance, external_id)` and unique per task. `source_kind` is an open bounded slug independent of the code host; `source_instance` is a normalized host or connection id; `external_id` is the provider's stable machine identifier; human keys, scope and URL are display and closing-reference inputs, never identity. Create-with-source inserts the binding in the task-creation transaction so a duplicate identity refuses `CONFLICT {reason:"source_already_bound"}` without leaving a task. Bindings are immutable except for a same-identity refresh of key/scope/URL; only an audited human detach frees an identity. Legacy marker-only tasks are bound by an operator-run, dry-run-first backfill that classifies and never guesses.

**Consequences:** Intake agents look up by source before creating and rely on the database for dedup; provider comment receipts stay as a provider-side journal. The external GitHub reconciliation design re-bases its identity on this table instead of a competing one. Bindings cascade with their task (tasks are never hard-deleted in production). Librarian tokens cannot attach sources.

**Alternatives Considered:** Columns on `tasks` (no room for a future lifecycle and no per-identity uniqueness across kinds); identity by visible number or URL (collides across instances and changes on transfer); prompt-text markers only (no transactional uniqueness; erasable by edits); a provider-specific GitHub table (blocks GitLab/Jira/GitVerse sources on non-GitHub code hosts).
