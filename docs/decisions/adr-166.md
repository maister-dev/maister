# ADR-166: Local execution-host contract — durable host identity, epoch-fenced assignments, command ledger, opaque adopted workspaces

> Part of the ADR log — hub, index, and editing rules: [`../decisions.md`](../decisions.md).

**Date:** 2026-09-02
**Status:** Implemented

**Context:** The web tier addresses the supervisor as an anonymous global
endpoint. Verified against the code at main `73fa99915` (Stage A preflight,
2026-09-02):

1. **One URL, no routing model.** `web/lib/supervisor-client.ts` is the only
   place a supervisor URL is built (`MAISTER_SUPERVISOR_URL ??
http://localhost:7777`); 17 exports and ~102 non-test call sites in ~30
   files reach it, with no auth header, no retry, and no timeout on
   `sendPrompt` / `streamSession`.
2. **ADR-023 is the truth.** `docs/architecture.md` claimed the supervisor
   "MAY run on a different host"; the code refutes it. The browser stream
   route tails `run.events.jsonl` via local `node:fs`, `docs/deployment.md`
   requires an identical `MAISTER_RUNTIME_ROOT` on both processes, and
   worktree / diff / promotion are web-side git operations. A shared
   filesystem is REQUIRED today.
3. **The supervisor is fully in-memory and unauthenticated.** The
   `SessionRegistry` is a `Map` rebuilt empty at boot; there is no startup
   reconciliation, no host identity, no state directory. It binds
   `0.0.0.0:7777`. Durable per-run artifacts (`<stepId>.log`,
   `run.events.jsonl`, `cost.jsonl`) live under
   `<MAISTER_RUNTIME_ROOT>/.maister/<projectSlug>/runs/<runId>/` with
   body-controlled path segments. There is no `supervisor/src/checkpoint.ts`;
   checkpoint is an inline handler in `http-api.ts`.
4. **`node:sqlite` is already a production pattern** on both sides
   (`supervisor/src/adapter-smoke-cache-lock.ts`,
   `web/lib/agents/materialization-lock.ts`) with vitest shims in both
   workspaces. CI runs Node 24.
5. **Two session id spaces, asymmetrically persisted.** The supervisor
   `sessionId` is persisted ONLY for scratch
   (`scratch_runs.supervisor_session_id`); flow and agent runs scan
   `listSessions()` by `acpSessionId`, `(runId, stepId)`, or `runId`.
   `run_sessions.acp_session_id` is written only AFTER the prompt returns for
   flow runs, so the id is NULL for the entire mid-prompt window.
6. **Probable identity bug.** `checkpointBudgetLiveSession` in
   `web/lib/services/hitl.ts` passes `run_sessions.acp_session_id` to
   `checkpointSession()`, which is keyed by the supervisor's own session id.
7. **Prompt completion is HTTP-only.** `POST /sessions/:id/prompt` blocks for
   the turn; no turn-completed SSE event exists. Every SSE event is appended
   to `run.events.jsonl`.
8. **Every path is in the wire contract.** `StartSessionRequest` carries
   `worktreePath`, `repoPath`, `confineRoot`, `contextMounts[].path`, and
   `capabilityProfilePath` plus the path-segment ids `projectSlug`, `runId`,
   `stepId`; `GET /sessions` echoes every raw path.

Reserved identifiers: at the preflight (main `73fa99915`) the max ADR was
`ADR-162` and `ADR-163` was squatted by the flow-target-delegation branch, so
this record was drafted as ADR-164 with migration `0128`. Both numbers were
taken on `main` before this branch landed (ADR-164 = the managed-CCR removal,
`0128_remove_router_sidecars`), so the first rebase renumbered it to ADR-165 /
`0129`; those were then taken by the governed recursive agent harness (ADR-165,
`0129_run_results`), so the second rebase renumbered this record to
**ADR-166** and its single additive migration to **`0130_execution_hosts`**
(gaps are allowed — the migration journal already has gaps at 64/69/74/75).
The supervisor OpenAPI and both AsyncAPI files are at `0.7.0` and bump to
`0.8.0`. The flow engine version (`3.6.0`) is untouched.

The owner brief asks for the target execution-host architecture seam — a
durable host identity, a durable per-run placement with a monotonic epoch, an
opaque workspace handle, a unique command id on every host-bound command, and
load-bearing fencing at the execution boundary — WITHOUT changing single-host
behavior, so that later stages (durable event plane, host-owned filesystem and
multi-host placement, trusted remote hosts, cloud hosts) have a seam to land
on. The spec is
[`system-analytics/execution-hosts.md`](../system-analytics/execution-hosts.md).

**Decision:** Introduce a **local execution-host contract** between Web Core
and the supervisor, deployable on one host over loopback HTTP with the
current shared filesystem, preserving every current user-visible behavior.

- **D1 — Host identity is minted by the supervisor and persisted in a
  supervisor-private `node:sqlite` state store.** On first boot the
  supervisor mints `hostKey = "eh_" + <uuid without dashes>` into
  `<MAISTER_EXECUTION_HOST_STATE_DIR>/state.sqlite` (default
  `<MAISTER_RUNTIME_ROOT>/.maister/execution-host/`; WAL,
  `synchronous=NORMAL`; tables `host_identity`, `run_fences`, `workspaces`,
  `command_receipts`). A per-process `bootId` marks restarts. An optional
  pin `MAISTER_EXECUTION_HOST_KEY` applies when no key is stored or when it
  equals the stored key; a pin that CONFLICTS with the stored key **refuses
  boot** (fatal `execution-host-key-conflict`, exit 1) — no silent identity
  change is possible. An unwritable state dir is a fatal boot error. The
  web tier never reads the state dir; it resolves the host from
  `GET /health` (`host.{hostKey, bootId, protocolVersion}`) and registers it
  in `execution_hosts` (`kind='local_direct'`). The supervisor URL stays
  transport configuration read at call time — never stored, never a domain
  concept. The identity-change policy under the active row's lock: same key
  → touch; new key while the old row owns zero `active` assignments of
  non-terminal runs → retire old, insert new; new key while the old row still
  owns non-terminal runs → REFUSE (`readiness='unavailable'`,
  `readiness_reason='identity_changed'`, every command issue fails
  `EXECUTOR_UNAVAILABLE {details.reason:"host_identity_mismatch"}`);
  unreachable or malformed health → `readiness='unavailable'` at most once
  per 30 s, launches keep today's 503.
- **D2 — One run ↔ at most one `active` assignment ↔ one host; the workspace
  handle is run-scoped and lives on the assignment.** `execution_assignments`
  is append-only, one row per `(run, epoch)`; `execution_commands` is the
  delivery ledger; `runs.execution_assignment_id`,
  `run_sessions.execution_assignment_id`, `run_sessions.host_session_id`,
  and `node_attempts.execution_assignment_id` carry attribution. The
  authoritative SQL is the plan's Appendix C, mirrored in
  [`database-schema.md`](../database-schema.md) and
  [`db/execution-hosts-domain.md`](../db/execution-hosts-domain.md).
  `scratch_runs.supervisor_session_id` stays and is mirrored into
  `run_sessions.host_session_id` (the mirror is removed in Stage B).
- **D3 — Epoch authority is Postgres; fencing is enforced by the host.**
  `mintAssignment(tx, {runId, hostId, reason})` runs in the same transaction
  as the existing placement CAS: lock the active row, mark it `superseded`,
  insert `epoch = COALESCE(max, 0) + 1`, update `runs`. The epoch is the
  driver-ownership generation — minted exactly when a driver takes over a run
  with no live driver (`launch`, `resume`, `recover`, `wait_resume`,
  `rework_return`, `gate_chat`, `sync_resolver`, `scratch_recover`,
  `node_interrupt`, `legacy_backfill`), and only on the run-INSERT branch of
  launch. Release is advisory (the next mint supersedes anything); the sweep
  is the backstop. **Command admission by assignment state:** `active` →
  all kinds; `released` → teardown kinds only (`session.checkpoint`,
  `session.delete`, `session.cancel`, `session.input{action:"cancel"}`,
  `workspace.release`); `superseded` → nothing (local `fenced`, no wire
  call). The host keeps `run_fences(run_id, assignment_id, epoch)` in
  sqlite, written BEFORE execution, and rules in order: `hostKey ≠ own` →
  409 `PRECONDITION host_mismatch`; `epoch < stored` → **409 `FENCED`**
  (`details.reason="assignment_fenced"`); `epoch = stored ∧ assignmentId ≠
stored` → 409 `PRECONDITION assignment_mismatch`; `epoch > stored` →
  persist, then EVICT every live session of that run under a lower epoch
  (cancel its deferreds, `session.exited {reason:"fenced"}`, its pending
  prompt answers 409 `FENCED`), then execute. Session routes also require
  `fence.runId === record.runId` (`run_mismatch`).
- **D4 — Every host-bound mutating route takes a command envelope**
  `{command:{id, kind, issuedAt}, fence:{hostKey, assignmentId,
assignmentEpoch, runId}, payload}`; the session id stays in the URL.
  Eight kinds: `workspace.adopt`, `workspace.release`, `session.create`,
  `session.prompt`, `session.input`, `session.cancel`, `session.checkpoint`,
  `session.delete`. The ledger FSM is `queued → delivering → accepted →
succeeded | failed | fenced`; every transition is a CAS on `(id, state IN
expected, attempts)`; a late signal for a terminal row is logged and
  ignored.
- **D5 — Intent before side effect; delivery state only after
  acknowledgement.** Order: `queued` row committed (in the caller's tx where
  one exists) → wire call outside any tx → ack tx AFTER the response together
  with the result-derived domain writes. Unknown-outcome transport failures
  retry the SAME command id up to the kind's budget; a parsed 503 is
  definitive (`failed`, the caller's own retry issues a NEW command); 409
  `FENCED` is terminal (`fenced` → `CONFLICT {details.reason:
"assignment_fenced"}`); a prompt failure after acceptance does ONE receipt
  lookup before classification. **Driver yield rule:** any outcome carrying
  `assignment_fenced` means this driver's assignment is superseded — the
  driver logs `driver-yielded` and returns WITHOUT writing run, node-attempt,
  HITL, or scratch state. Completion of a prompt rides the long-lived HTTP
  response AND the SSE `session.command` event (also in `run.events.jsonl`)
  AND the receipt; `PromptHandle.completion` resolves from whichever durable
  signal arrives first. Terminal `execution_commands` rows are pruned after
  7 days by the `system_sweep` pass; assignments are kept.
- **D6 — Supervisor-side idempotency via receipts.** `command_receipts`
  (phase `accepted | completed | rejected`) make a command id execute at most
  once per host: a duplicate replays the stored response verbatim with
  `X-Maister-Command-Replayed: true`; an in-flight duplicate (any kind) joins
  the running execution; `accepted` without an in-flight promise (restart
  mid-turn) → 409 `PRECONDITION turn_lost`. A receipt write failure → 500
  `ACP_PROTOCOL` (the effect may exist; reconcile catches an orphan session —
  accepted residual X-EH-21). `GET /commands/{commandId}` returns the receipt
  or 404. Receipts prune at boot and hourly (7-day TTL).
- **D7 — Adoption is the only path-bearing operation.** `POST
/workspaces/adopt` registers a path as an opaque host-scoped handle
  `executionWorkspaceId = "ws_" + uuid`, idempotent on `(runId, realpath)`.
  Kinds `git_worktree` (realpath under `MAISTER_WORKSPACE_ROOTS`; `.git` FILE
  whose `gitdir:` resolves under `<repoPath>/.git/worktrees/`; `repoPath` is a
  repo root), `repo_checkout` (a repo root equal to `repoPath`, arbitrary
  location — ADR-023), `directory` (under the roots, no `repoPath`). All:
  absolute, no `..`, realpath exists, no symlink escape, not inside the state
  dir. `MAISTER_WORKSPACE_ROOTS` (colon-separated) defaults to
  `~/.maister/worktrees:~/.maister/local:<MAISTER_RUNTIME_ROOT>/.maister`; a
  moved `MAISTER_WORKTREES_ROOT` / `MAISTER_LOCAL_PACKAGES_ROOT` on the web
  MUST be mirrored here. After the strict flip, `POST /sessions` and every
  `/sessions/{id}/*` route accept only `executionWorkspaceId`; `runId`,
  `projectSlug`, `worktreePath`, `repoPath`, `confineRoot`, and
  `contextMounts` leave the session payload (`legacy_field` /
  `missing_envelope` refusals). The web derives every adopt value from server
  state, never from a request body it received.
- **D8 — Restarts.** Supervisor: identity, fences, receipts, and handles
  reload; a new `bootId`; live sessions are gone (unchanged); the registrar
  sees the bootId change and runs one reconcile sweep. Web:
  `instrumentation.ts` order is migrations check → `ensureLocalExecutionHost()`
  → `recoverExecutionCommands()` → `adoptLegacyActiveRuns()` → the existing
  sweeps; a periodic recovery pass and the retention prune join
  `runSystemSweep()` (no new `job_kind`).
- **D9 — Migration is additive and evidence-based.** Historical runs keep
  `execution_assignment_id = NULL` forever ("pre-Stage-A, never placed").
  At startup, `Running`/`NeedsInput` runs with a live session on the local
  host are backfilled with epoch 1 (`legacy_backfill`); without a live session
  they stay NULL and reconcile classifies them; parked statuses mint on their
  next placement. A command issuer meeting a NULL assignment calls
  `ensureAssignment(runId, "legacy_backfill")` (WARN) — deterministic because
  exactly one non-retired local host can exist. **`ensureAssignment` MUST be
  deleted in Stage C** (the multi-host stage makes the lazy single-host
  assumption false). No registered local host at boot → the backfill is
  skipped, logged once, retried on the next sweep (accepted residual X-EH-22).
- **D10 — Compatibility strategy.** A new module `web/lib/execution-host/`
  (`types`, `transports/local-direct`, `hosts`, `assignments`, `commands`,
  `redact`, `ledger`, `deliverer`, `adoption`, `recovery`, `registrar`,
  `resolver`, `legacy`, `client`, `index`) with a dependency-inverted
  deliverer (it depends on the `CommandLedger` and `ExecutionHostTransport`
  interfaces; neither knows the other) and a per-kind policy table. The six
  DI facade types are deleted in waves and replaced by `BoundClient`; tests
  use ONE shared fake. The wire accepts an optional envelope and
  `executionWorkspaceId` XOR legacy path fields during the migration waves
  (WARN `legacy-unfenced-command`) and flips strict inside the same branch —
  a schema union time-boxed to the branch, not a runtime flag. An ESLint
  `no-restricted-imports` fence forbids `@/lib/supervisor-client` outside
  `web/lib/execution-host/**`.
- **D11 — Ownership.** Web Core owns the run state machine, placement,
  command intent + delivery ledger, worktree creation / git ops / diff /
  promotion (transitional), browser event tailing (transitional shared FS),
  and the legacy backfill. Postgres is the SSOT for hosts, assignments,
  commands, and run state. The local execution host owns adapter processes
  and ACP sessions, its identity, the fence high-water, receipts, the
  workspace registry and path validation, and pipe-to-disk logs/events
  (transitional). It never owns run state, placement, or git.
- **No new `MaisterError` code.** `FENCED` is a supervisor code (HTTP 409)
  mapped to `CONFLICT` with `details.reason="assignment_fenced"`;
  `EXECUTOR_UNAVAILABLE {details.reason:"host_identity_mismatch"}` is
  web-minted; every other refusal reuses `PRECONDITION` with a typed reason
  token. `SupervisorErrorBody` gains typed `details` so tests assert tokens,
  never message text.
- **D12 — Deferred to Stages B–E (seams only).** Stage B: host→web event
  ingestion, artifact reads via host API, retiring the `run.events.jsonl` tail
  and the long-lived prompt HTTP, dropping the `scratch_runs` mirror. Stage C:
  `POST /workspaces/materialize`, git ops on the host, placement over N hosts,
  host UI, deleting `ensureAssignment`, `lease_expires_at` renewal. Stage D:
  host auth/enrollment, relay/WebSocket, secret confinement. Stage E:
  provisioner, ephemeral hosts (`retired_at` lifecycle, readiness model).
  Explicitly out of Stage A: remote transport, multiple simultaneous hosts,
  placement, host UI, object storage, canonical host→web event ingestion,
  moving git/diff/checks/artifacts to the host, cross-host ACP resume, cloud
  provisioning, multi-repo materialization, swarm, long-lived agent identity.

**Consequences:**

- Single-host behavior is byte-for-byte preserved for every current workflow
  (flow runs, scratch/assistant runs, HITL, checkpoint/resume, cancel/abandon,
  reconcile, concurrency accounting, local promotion); the shared filesystem
  and local event coupling stay REQUIRED and are documented as a limitation,
  not removed. No sentence in the docs may claim remote or multi-host support.
- Every new run has a durable assignment with an epoch; every host-bound
  command carries a fence and a unique id; a stale epoch is rejected at the
  boundary with 409 `FENCED` and the evicted driver yields without writing
  state — split-brain between an old and a new driver incarnation becomes
  structurally impossible rather than merely unlikely.
- Duplicate delivery of any command is safe (receipts + in-flight join), and
  every web crash window (before send, before ack, mid-prompt) has a defined,
  tested recovery from the ledger + receipts.
- Session APIs stop carrying raw paths; the host validates the one
  path-bearing operation against configured roots. Three new supervisor env
  vars (`MAISTER_EXECUTION_HOST_STATE_DIR`, `MAISTER_EXECUTION_HOST_KEY`,
  `MAISTER_WORKSPACE_ROOTS`) and a supervisor-private state directory; none
  on the web; compose files unchanged (ADR-023).
- A pinned key that conflicts with the stored key refuses boot — an operator
  who restores a state dir on another machine must either unset the pin or
  deliberately wipe the dir. Accepted residual windows: a receipt write that
  fails after execution (X-EH-21) and a host unreachable at web boot
  (X-EH-22), both caught by the existing reconcile.
- The lazy single-host `ensureAssignment` is a Stage-A-only crutch with a
  recorded deletion obligation (Stage C). The loopback is unauthenticated
  (Stage D adds host auth) — documented limitation.
- The probable `hitl.ts` identity bug (acp id passed where a supervisor id
  is expected) is fixed through the branded `HostSessionId` after reproduction.

**Alternatives Considered:**

- _Per-session assignments_: rejected — a flow run's N sequential sessions
  (ADR-114) and the gate-chat sub-session on a live run share one driver
  incarnation; per-session epochs would fence a driver against itself.
- _Host-side epoch authority_: rejected — Postgres already serializes the
  placement CAS; a second authority would need a consensus protocol between
  two processes that share a disk today.
- _Async-only prompt completion (drop the long-lived HTTP now)_: rejected for
  Stage A — the existing runners are written around the blocking prompt; the
  SSE `session.command` event plus receipts prepare the seam without
  rewriting every driver.
- _`better-sqlite3`_: rejected — `node:sqlite` is already a production
  pattern on both sides with vitest shims; no new dependency.
- _A JSON fence file instead of sqlite_: rejected — receipts and handles need
  the same durability and concurrent-write safety; one store, one lock model.
- _Pin overrides a conflicting stored key with a WARN_: rejected (owner
  decision) — a silent identity change would let a restored state dir adopt
  another host's fences and handles; refusing boot is the honest failure.
- _A new `MaisterError` code (`FENCED`)_: rejected — the UI already branches
  on `CONFLICT`; `details.reason` carries the discriminator (ADR-093 pattern)
  without widening the client-safe union.
- _Storing the supervisor URL on `execution_hosts`_: rejected — the URL is
  transport configuration; storing it would make a domain row depend on the
  deployment layout and break the "transport replaceable behind a typed
  boundary" requirement.
- _Auto-retire the old host row on every identity change_: rejected — an old
  row that still owns non-terminal runs would lose its fences; refusing until
  the operator pins the old key or stops the runs is the safe default.
