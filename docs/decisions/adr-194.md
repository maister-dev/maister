# ADR-194: Explicit reviewed project configuration commits

[Back to ADR index](../decisions.md#adr-194-explicit-reviewed-project-configuration-commits)

**Date:** 2026-10-29
**Status:** Accepted

**Context:** Package write-back and absent-manifest bootstrap dirty project
checkouts, while path-null persistence gating hides repeated export. Existing
limited serialization loses source-owned content; shared-index commits cannot
safely isolate concurrent staging.

**Decision:** Runtime application changes DB configuration only. Extend existing
persist-config with immutable complete diff reviews, exact-state confirmation,
operation-attributed dedicated local commits, semantic status and explicit
recovery. Push has a separate immutable destination/range review and receipt.
The [owning contract](../system-analytics/project-config-persistence.md) defines
the private worktree, prepared HEAD transaction, safe read-tree publication,
unborn scaffolding/amend protocol and every recovery/refusal boundary.

This supersedes ADR-088's implicit manifest write-back consequence and ADR-093's
later generated-file registration override. Manifest pinning, runtime DB authority,
package trust, owner/default registration rules and ambient Git identity/auth stay.
Source-owned YAML is patched at owned leaves, never replaced from lossy DB state.

**Consequences:** Add a main-lineage export revision and immutable commit/push
intent records. Existing untracked bootstrap manifests remain user-owned and
require manual review. Deleted Studio-cut coordinates refuse export; they are
never fabricated or omitted. Drain old web writers at upgrade; no mixed-version
rolling repository mutation guarantee. Implementation remains Designed until
its [acceptance matrix](../system-analytics/project-config-persistence-traceability.md)
is fully qualified. No new manifest schema, runtime configuration source, daemon,
watcher, scheduler or Git upgrade is required.

**Alternatives Considered:** Automatic commits/push, local override YAML,
shared-index commit and whole-manifest replacement violate explicit review,
repository protection or source preservation. Git commit-tree is used only for
private unborn scaffolding; the reviewed commit uses normal hooks/signing.

The final caller-index reservation and its same-operation crash proof are part of the publication protocol: see [the owning contract](../system-analytics/project-config-persistence.md#final-caller-index-reservation). The HEAD transaction alone does not bind concurrent staging; the final index/manifest/authority check occurs while a no-clobber, inode/digest-proven standard Git index lock is held. Unknown Git locks remain operator-owned and are never removed.
