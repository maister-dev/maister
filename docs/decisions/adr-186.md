# ADR-186: Librarian delegated authority: per-turn owner-bound tokens with live RBAC

> Part of the ADR log — hub, index, and editing rules: [`../decisions.md`](../decisions.md).

**Date:** 2026-09-26
**Status:** Accepted

> **Builds on** [ADR-089](../decisions.md#adr-089-platform-agent-catalog-with-per-agent-runner-and-a-five-source-trigger-model)
> (per-launch ephemeral tokens feeding the `maister` MCP facade),
> [ADR-090](../decisions.md#adr-090-agent-workspace-axis-with-three-layer-read-only-enforcement-and-quarantine)
> (L1/L2/L3 layering) and
> [ADR-130](../decisions.md#adr-130-adapter-agnostic-capability-enforcement-at-the-acp-seam)
> (`capability_guard`); it amends none of them. `AGENT_TOKEN_SCOPES` and
> `CROSS_PROJECT_AGENT_SCOPES` are not changed. Owns requirement family `LAU`
> ([librarian-authority.md](../system-analytics/librarian-authority.md)); the
> runtime is [ADR-185](../decisions.md#adr-185-librarian-runtime-a-project-less-run-kind-with-per-turn-acp-sessions).

**Context:** The librarian acts for the current user with that user's current
permissions (LIB-02), reaches the platform only through the MAIster MCP facade
(LIB-05), and must never receive a long-lived, admin or widened agent credential
(LIB-07). Facts verified against the working tree at `8c77218` (2026-09-26):

- Token kinds are `project | user | agent`, with no DB CHECK. A global personal
  token (`user`, `project_id` NULL) is re-checked against its owner's live
  project role on every request inside `handleExt`
  (`web/lib/tokens/ext-handler.ts`); every refusal there answered `404`.
- The shared HITL chokepoint refuses every non-user actor for the human-only
  kinds (`web/lib/services/hitl.ts:6101-6119`); the session respond route
  answers as `HitlActor{kind:"user"}`
  (`web/app/api/runs/[runId]/hitl/[hitlRequestId]/respond/route.ts:146-149`).
- `readOnlySession` arbitrates every permission request first and returns
  (`supervisor/src/acp-client.ts:516-545`), so `capability_guard` (`:744`) never
  runs for such a session, and it auto-allows the kinds `read`, `search`,
  `fetch`, `think` (`:133-138`) — host files and generic HTTP.
- `capability_guard` governs by field presence: `tools` governs every call that
  reaches the seam, `mcps` only MCP calls; `enforcedClasses` is audit-only
  (`supervisor/src/guardrail-hooks.ts:92-120`). An ungoverned call falls through
  to the execution-policy auto-approve (`acp-client.ts:867`).
- A global admin passes `requireProjectAction` for any `projectId`, including
  NULL, before any project comparison (`web/lib/authz.ts:307-314`).

**Decision:** A librarian turn acts with a fresh token of a new kind `librarian`,
bound to the owner and the turn, whose every request is re-checked against the
owner's live RBAC, whose scope list is explicit and excludes human-only
authority, and whose session reaches the platform through the `maister` MCP
server only.

**D1 — One token per turn.** `project_tokens.token_kind='librarian'`,
`owner_user_id` = owner, `project_id` NULL, `agent_id` NULL, `librarian_turn_id`
set, `expires_at` = the turn's `deadline_at`, name `librarian-turn:<turnId>`
(reserved by `RESERVED_TOKEN_NAME_PATTERN` in `web/lib/tokens/lifecycle.ts`, so
no human issuance can produce it). Migration `0183` adds
`project_tokens_kind_check` (four kinds) and `project_tokens_librarian_check`;
`0184` adds `project_tokens_librarian_turn_fk`. `issueLibrarianTurnToken`
(`web/lib/librarian/authority.ts`) runs when the run flips `Running` — a
`Pending` or `admitted` turn holds no token — and the turn-end transaction
revokes it (LAU-02, `IT-LAU-02`). The secret is injected only into that turn's
stdio facade process, one per session, so no credential or ACP state is shared
between users. It is passed as `MAISTER_PROJECT_TOKEN`, which the facade prefers
over `MAISTER_ACCESS_TOKEN` (`mcp/src/auth.ts:13-15`), so no inherited value can
outrank it (agent precedent: `web/lib/agents/launch.ts:2859`). Summary turns
carry no token (ADR-190).

**D2 — Principal.** `TokenKind` and `TokenActor` gain `librarian` and
`librarianTurnId`. `verifyToken` applies the user-kind owner checks (owner exists,
`account_status='active'`, no pending password change) to the librarian kind on
every request; `actorUserIdForToken` and `socialActorForToken` return the owner;
`actor_label` is `librarian:<ownerUserId>` (`web/lib/tokens/verify.ts`).
Deactivation therefore refuses the next request of an in-flight turn (LAU-10,
`IT-LAU-10`; `EDGE-LAU-01` for replay after revocation).

**D3 — Scope policy.** `LIBRARIAN_TOKEN_SCOPES` in `web/types/token-scopes.ts`
is an explicit list, never `*`: `projects:read`, `work:read`, `activity:read`,
`decisions:read`, `tasks:read|create|update|triage`, `comments:read|create`,
`relations:read|create|delete`, `flows:read`, `runners:read`, `memory:read`,
`runs:read|launch|cancel|recover|sync|message`, `readiness:read`, `hitl:read`,
`hitl:inbox:read`, `hitl:request`, `librarian:cards|memory|history`. The new
scopes (`projects:read`, `work:read`, `activity:read`, `runs:message`,
`librarian:*`) are added to `TOKEN_SCOPES`; `runs:cancel` serves the owner's
stop route (ADR-187 D10b), never the coordinator's; every write scope is mapped in
`PROJECT_ACTION_BY_SCOPE`, because an unmapped scope falls back to `readBoard`.
`runs:sync` covers sync and reopen (ADR-141); there is no rework scope — a
rework claim hands the worktree to the clicking human (ADR-160) and is not a
librarian operation. Excluded: `hitl:respond`, `hitl:respond:human`,
`runs:promote`, `runs:delegate`, `runs:collect`, `memory:write`,
`agent_memory:write`, `notifications:subscriptions`, `agents:trigger`, every
evaluation scope, and every token, settings, admin, package or flow-authoring
surface. An Explain turn (ADR-187 D11) receives `LIBRARIAN_READ_SCOPES`, the
read-only subset, so teammate answers and update text never run with effect
authority (LIB-08; LAU-05, `IT-LAU-05`). `AGENT_TOKEN_SCOPES` and
`CROSS_PROJECT_AGENT_SCOPES` are untouched; the existing agent scope tests stay
green.

**D4 — Live admission in `handleExt`.** Admission is opt-in per route: a route
that does not declare `admitLibrarian` refuses the kind before project
resolution with `403 UNAUTHORIZED {details.reason:"librarian_not_admitted"}`.
Human-only and coordinator routes never opt in. On an admitting route the
owner's live role is checked per request in two steps: no `readBoard` on the
project → `404`, answered exactly like a missing project (LAU-06); visible but
the owner's role is below the scope's action minimum → `403 UNAUTHORIZED
{details.requiredAction}`, so the librarian can tell the owner why. Then the
scope must be in the token's scopes, and the token's turn must be `running`
(checked by id; `403` otherwise). The project comes from the slug, or — for a
project-less token on a resource-addressed route — from
`resolveLibrarianProjectId` (the run's project for `runs/[runId]`, `activity`,
`readiness`, `hitl` read, `recover`, `stop`). A route whose target is a body
field (`runs` POST `taskId`; `runs/sync` and `runs/reopen` `runId`) resolves it
after the token is verified and audits a malformed body with `422`, keeping the
audit-first rule those routes were written for. Test: `IT-LAU-03`.

**D5 — Refusals (LAU-04).** Each closed surface names its mechanism:

| Surface | Closed by |
| --- | --- |
| `hitl_respond` (any kind), `run_promote`, `run_delegate`, `run_collect`, `agent_memory_write` | scope not held + route does not opt in |
| `run_discard` (`runs/[runId]/discard`, scope `runs:recover` shared with recover) | route does not opt in |
| `triage_set` (`…/tasks/{taskId}/triage`; the kind holds `tasks:triage` for send-to-triage) | route does not opt in |
| `run_cancel`, `run_rework`, `run_message`, `run_plan` (coordinator routes bound to `actor.boundRunId`, e.g. `web/app/api/v1/ext/runs/cancel/route.ts:59-70`) | route does not opt in |
| `notification-subscriptions` | `requirePersonalOrLibrarianActor(actor, {allowLibrarian:false})` |
| token, settings, admin, package, flow-authoring routes | session-only or not opted in |
| every `/api/v1/ext/librarian/*` route presented an agent, project or user token | the route admits the librarian kind only |

The three inline "global personal token only" checks (`ext/hitl`,
`ext/decisions`, `notification-subscriptions`) share one helper,
`requirePersonalOrLibrarianActor(actor, {allowLibrarian})`
(`web/lib/tokens/personal-actor.ts`); the HITL inbox and the decisions queue
admit the librarian as a read of the owner's own queue, never an answer.
Test: `IT-LAU-04`.

**D6 — Visibility before aggregation.** Every list, search and count admitted
for the kind filters by the owner's visible projects before aggregating
(`getVisibleProjects`), so a foreign project contributes no row, count or
distinct error (LAU-06, `IT-LAU-06`; archived mid-turn: `EDGE-LAU-03`).

**D7 — Audit.** `token_audit_log` gains `on_behalf_of_user_id`,
`librarian_turn_id` and `operation_id` (`0183`). Every librarian-token request,
refused or admitted, writes a row through `recordRequiredTokenAudit`; an audit
failure fails the request. For an effect the row is written inside the route's
own transaction and carries the operation id (ADR-187 D6). The turn's source
project set is `DISTINCT project_id` over its audit rows (reused by ADR-190
masking). LAU-07, `IT-LAU-07`.

**D8 — Human-only boundary and attribution.** The token can never answer a
human-only HITL kind (chokepoint above), promote or discard. Those reach the
owner as confirmation cards (ADR-187 D7) whose click goes through a session route
as `HitlActor{kind:"user", userId}` — which also keeps the budget-breach restart
paths working, since they call the session-bound `requireProjectAction`
unconditionally (`web/lib/services/hitl.ts:3998`, `:4168`). Effects made through
the token record the owner as social actor plus `via_operation_id` (LAU-08,
`IT-LAU-08`).

**D9 — Personal data isolation; no admin inspection in this release.** No role,
including global admin, can read another user's conversation, memory, snapshots
or librarian run through any route. Every `/api/librarian/*` route resolves the
conversation from the session user (`server-state`), never from input. The run
stream admits a project-less run's creator only
(`web/app/api/runs/[runId]/stream/route.ts:337-346`). Because the admin
short-circuit accepts a NULL project, every other `/api/runs/[runId]/*` session
route answers `404` for `run_kind='librarian'` instead of calling
`requireProjectAction(run.projectId, …)` — for example
`web/app/api/runs/[runId]/abandon/route.ts:89-99` loads the run unfiltered today
(ADR-185 D11 fan-out). An administrative inspection capability is out of this
release; adding one needs its own ADR and audit. LAU-09, `IT-LAU-09`,
`EDGE-LAU-02`.

**D10 — MCP-only session (LIB-05).** `readOnlySession` is not used: it would
return before `capability_guard` and auto-allow host reads and fetches (Context).
Each owner-message and Explain session carries:

- **L1** — `enforcementProfile` (`SessionEnforcementProfileSchema`,
  `supervisor/src/types.ts:354-367`): `tools.allow` = the librarian tool names
  (`mcp__maister__<tool>`, generated from the librarian toolset that also feeds
  the instructions and the facade, one drift test), `mcps.allowServers:
  ["maister"]`, `enforcedClasses: ["tools","mcps"]`, `escalationThreshold: 3`.
  An out-of-profile call is answered `cancelled` inline; the third consecutive
  one halts the session and cancels its pending permissions
  (`acp-client.ts:787-818`). The owner adapter sees the halt and fails the turn
  `capability_trip`.
- **L3 policy** — `autoApprovePermissions` (execution policy
  `permissions=auto_approve`), so an L1-admitted MCP call never waits for a
  human.
- **L2** — materialized Claude `settings.local.json` deny rules for Read,
  Glob, Grep, WebFetch, WebSearch, Bash, Edit, Write, and NotebookEdit via
  `web/lib/librarian/session-profile.ts`. Codex has no equivalent deny surface
  and is refused by the runner guard pending isolation and qualification.
  A write executed without reaching the
  seam still halts through the always-ask sentinel (`acp-client.ts:455-500`).
- **Only the `maister` server** is attached, with the turn token; the cwd is the
  empty conversation directory (ADR-185 D3).
- **No HITL row, ever.** The librarian runtime registers no permission-to-HITL
  writer: a permission request that still reaches the manager (an adapter
  offering no allow-shaped option) is answered `cancel` through `BoundClient` and
  fails the turn `capability_trip`, so no `hitl_requests` row exists for a
  librarian run.

Summary turns (ADR-190) attach no server and carry no token. A profile of
`{mcps:{allowServers:[]}, enforcedClasses:["mcps"]}` (the first plan draft) would
leave every built-in call ungoverned and auto-approved (Context), so a summary
turn carries the owner-turn profile with `escalationThreshold: 1`: with no server
attached no allowed tool is callable, the first call halts the session, and any
tool call observed fails the turn (`EDGE-LAU-04`). The runner guard (`readOnlyCapable`, never
`dangerously_skip_permissions`, capability `claude`; Codex remains ineligible)
is ADR-185 D8. An
adapter that executes a built-in without reaching the seam is a blocking defect
and is not selectable as the librarian runner. LAU-11: `IT-LAU-11` (supervisor,
mock adapter) and T7.2 (live adapters).

**D11 — Route identifiers (normative).**

| Route | Identifiers |
| --- | --- |
| `GET /api/librarian/conversation`, `GET /api/librarian/messages` | owner `auth-context`; conversation `server-state` (by owner); `beforeSeq`, `limit` body-controlled (bounded ints) |
| `POST /api/librarian/messages` | owner `auth-context`; `clientMessageId` body-controlled (uuid, scoped to the owner's conversation); `subject.taskIds` body-controlled → visibility-checked, 404 on foreign |
| `DELETE /api/librarian/messages/{messageId}` | `url-param` compared to the owner's conversation (`server-state`); mismatch → 404 |
| `POST /api/librarian/turns/current/stop`, `POST /api/librarian/reset`, `…/history/clear[-preview]`, `POST /api/librarian/read-cursor` | owner only; no ids in body except `previewDigest` / `seq` |
| `POST /api/librarian/cards/{cardId}/decide` | `url-param` checked against owner; `expectedRevision` body-controlled, compared to `server-state` |
| `GET/POST/PATCH/DELETE /api/librarian/memory[/{id}]` | owner only; `id` url-param checked against owner |
| `POST /api/librarian/updates/{updateId}/explain` | url-param checked against owner |
| `GET /api/librarian/stream` | owner only; `lastEventId` body-controlled (int) |
| `POST /api/v1/ext/librarian/*` | owner from token (`auth-context`); no user or conversation id accepted |
| Ext routes admitting librarian tokens | project from slug / `resolveLibrarianProjectId` (`url-param` / `server-state`), always RBAC-checked live |
| `PATCH /api/admin/platform/librarian` | `requireGlobalRole('admin')`; `runnerId` body-controlled → must exist, be enabled and pass the ADR-185 D8 guard |

No route accepts a `userId`, and no `/api/librarian/*` route is reachable with a
token (LAU-01, `IT-LAU-01`).

**Consequences:**

- The librarian's authority can never exceed its owner's, and a membership,
  role or account change takes effect on the next tool call of a running turn.
- The default-deny `admitLibrarian` flag makes a new ext route closed to the
  kind until someone opts it in deliberately; the refusal table is a review
  checklist, not the enforcement.
- The facade toolset filter is presentation only; every refusal is server-side.
- A viewer-level owner gets a useful `403` naming the missing action on a
  project they can see, while a foreign project stays indistinguishable from a
  missing one.
- An admin who needs to inspect a conversation cannot; that is a deliberate
  gap of this release.
- Built-in denial rests on L1 at the permission seam plus L2 settings. An
  adapter that runs a read-class built-in without asking needs its own deny
  mechanism; Codex is ineligible until one is qualified.

**Implementation adversarial review (2026-09-27):**

- **Authority and visibility:** Rechecked the token's explicit scope set,
  deny-by-default route opt-in, per-request owner role check, source-project
  message mask and human-only action exclusion. `IT-LAU-03..10` and
  `E2E-L-05..06` exercise membership changes and foreign-project refusals.
- **Intent:** The first instruction version did not explicitly tell the model
  to treat teammate answers, retrieved records and conversation history as
  untrusted data. `librarian-instructions.v4` now says those sources cannot
  authorize effects. Explain turns also carry only `LIBRARIAN_READ_SCOPES`,
  so an injected answer cannot gain effect authority (`IT-LAU-05`).
- **Duplicate effects:** Rechecked the conversation-row lock, request digest,
  unique operation key, same-key replay and reset settlement barrier.
  `IT-LOP-01..03`, `E2E-L-07` and `IT-LMM-05` cover their race boundaries.
  A replay of a different request with the same key remains a `409` refusal.
- **Reset and forget:** Rechecked the epoch and generation fences, source
  visibility recheck, tombstones and retained task links. `IT-LMM-03..09`
  and `E2E-L-09..10` exercise the stale writer and deletion boundaries.
  Live adapter behavior is recorded separately in the qualification evidence;
  these deterministic checks do not prove a model's instruction following.
- **Host-read boundary:** The first live D5 marker probe reported no disclosure
  for both adapters, but neither direct ACP probe observed a permission request
  for a read. Reviewing installed `codex-acp@1.10.0` showed no settings-level
  built-in denial equivalent to Claude's `settings.local.json`. The Codex
  runner guard now refuses new and previously selected runners with
  `builtin_denial_unverified`; the admin UI names the reason. A focused
  PostgreSQL settings test and Claude on-disk deny-settings test pass. The
  Codex marker result remains an observation, not a D5 qualification.

**Alternatives Considered:**

- **Reuse the user's global personal token:** rejected — the brief forbids
  requiring a long-lived pasted token, and it would carry `*` and outlive the turn.
- **Issue an agent token (`token_kind='agent'`) for a synthetic agent:**
  rejected — agent tokens are project-bound, act as the agent, and widening
  them would touch `AGENT_TOKEN_SCOPES` for every platform agent.
- **`readOnlySession` for the MCP-only guarantee:** rejected — it pre-empts
  `capability_guard` and auto-allows host reads and fetches.
- **Per-conversation token reused across turns:** rejected — a revoked or
  queued turn would still hold authority; per-turn issue and revoke bounds it to
  the running turn.
- **Admin read access to conversations for support:** deferred — it needs an
  explicit, audited capability (LIB-07), not an implied role.
