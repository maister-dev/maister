# ADR-184: An open prompt does not pin the outbox — the span feed reads its ACKed prefix canonically

> Part of the ADR log — hub, index, and editing rules: [`../decisions.md`](../decisions.md).

**Date:** 2026-09-27
**Status:** Accepted

> **Amends [ADR-167](../decisions.md#adr-167-durable-execution-host-event-and-runtime-data-plane)**
> (D5: the host-span settlement feed reads a span's ACKed prefix from
> `execution_events`; the rule "host pruning retains a v2 command's span until
> its terminal is ACKed" is withdrawn) and
> **[ADR-183](../decisions.md#adr-183-outbox-pressure-means-the-manager-is-behind)**
> (D3: the retained-pressure cutoff no longer stops at an open span; its
> "Measured limit (open)" is resolved here). Each record carries a dated
> amendment bullet. [ADR-177](../decisions.md#adr-177-evidence-first-crash-classification)
> needs none: its rule — crash a lost stream's turn only on a recorded host-span
> refusal — is unchanged, and this record states the consequence.

**Context:** The execution host deletes its outbox as a contiguous prefix: the
prune walk takes the oldest rows and stops at the first one it may not delete;
the replay floor is the last deleted row, the boot audit refuses a store whose
rows above the floor are not contiguous, the span store answers
`runtime_storage_unavailable` for an empty page above the floor, and SSE
catch-up has no gap detection. One stop condition had nothing to do with the
manager: the walk also stopped at the smallest `accepted_sequence` of a v2
prompt whose terminal was not yet ACKed (`protectedRuntimeEventSpan`). It was
added with the host-span settlement feed (ADR-167 D5 amendment, 2026-09-23),
whose reader always asked the host for the WHOLE span `(acceptedSequence − 1,
terminalSequence]` — whether the owner's output was read behind the canonical
frontier, or a completed turn was settled from the host (`verifyHostPromptSpan`,
the D-B4 feed that also rescues a turn on a lost stream before ADR-177's
resolver crashes it). Nothing else on the host reads a command span's outbox
rows: receipt retirement, `/commands/{id}`, terminal evidence, the output
manifest, runtime objects and boot recovery all use receipt columns or separate
files.

The price was measured on `cc9cf20c` (ADR-183 plan, note N19). Because the
floor is a prefix, the OLDEST open prompt pinned every later row of the stream,
whatever session wrote it. R20 at the default budgets — nine turns of ~10
minutes at ~390 rows/s, the manager caught up (lag within two batches) —
reached the soft budget at 205 s with the retained-pressure prune stalling at
once on `protectedFromSequence`, and the hard budget at 253 s; frames were then
refused with nothing unacknowledged, and all nine sessions were checkpointed at
the 5-minute pause bound and parked. The limit is the turn's duration × the
host-wide row rate, not the manager.

Two facts make the pin unnecessary:

- **The manager's frontier bounds the host's floor.** The manager ACKs only a
  committed contiguous frontier (`recordConfirmedRuntimeEventAck` refuses
  `through > last_contiguous_sequence`), and the host keeps `floor ≤
  acknowledged_through`. So *host floor ≤ host ACK ≤ manager
  `last_contiguous_sequence`*: every row the host pruned is already in
  `execution_events` (or recorded in `execution_event_skips`), and every row
  above the manager's frontier is still on the host. Rows and the frontier
  commit in one ingest transaction, so a row at or below a frontier a reader
  has seen is visible to it. The one exception is a manager whose database went
  back in time (a restore), which is EDGE-EVT-03 today and stays so.
- **A sequence at or below the frontier can be absent from `execution_events`.**
  The contiguity walk steps over `execution_event_skips` rows (`unknown_run |
  payload_unstorable`). A canonical span read counted rows and failed such a
  span with `event_span_gap`; a host read still served the row. Once the host
  no longer keeps a span's ACKed rows, a skipped row in that prefix can only be
  verified from the skip ledger.

**Decision:** The span stop goes; the reader moves. The host prunes any
confirmed-ACKed row, open span or not, and the manager reads every prompt span
from one pager: canonically up to its own frontier, from the host above it.

**D1 — The floor stays a contiguous prefix; only the span stop goes (host).**
A row is prunable iff it is confirmed-ACKed and, in `grace` mode, older than
the 24 h grace. `protectedRuntimeEventSpan` and its stop are deleted in BOTH
prune modes. The walk still breaks at the first unACKed row, at the grace
cutoff and at the 1 MiB page cap; the floor is still the last DELETED row;
ACK ranges still go `<= last`; the boot audit, the span store's contiguity
check and SSE replay are untouched. The floor may now pass an open prompt's
`accepted_sequence` — never the ACK watermark. `runtimeEventPruneState` drops
`protectedFromSequence`; the stall line `outbox-retained-pressure-prune-stalled`
logs `retainedCount`, `unacknowledgedCount` and `acknowledgedThrough` — a stall
now means only unACKed rows remain above the low budget: the manager is behind.

**D2 — One rule, in both modes.** "Never an unACKed row" is the whole rule.
Keeping the stop in `grace` mode would keep a 24 h pin with no reader. The
premise: the supervisor and the web ship together. A new host beside an old
manager (one without the pager) would lose the host-span rescue for a span
whose ACKed prefix was pruned; that pairing is not a supported deployment.

**D3 — One span pager, two sources (manager).** `promptSpanPages`
(`web/lib/execution-host/prompt-span-pages.ts`) replaces both the canonical
pager and the host pager for every reader of a prompt span — owner output
(`readPromptOutput`) and the settlement feed (`verifyHostPromptSpan`):

1. The cursor starts at `acceptedSequence − 1` and the pager ends when it
   reaches `terminalSequence`.
2. Before each page it re-reads the stream row's `last_contiguous_sequence`
   (`F`).
3. While `cursor < F` it reads the canonical page `(cursor, min(F, terminal)]`
   — `execution_events` rows merged with the stream's `execution_event_skips`
   rows by `host_sequence`, at most 100 rows and 1 MiB. A sequence at or below
   `F` present in neither is `event_span_gap`: the frontier promised it.
4. Otherwise it reads one host page `(cursor, terminal]` through the existing
   host reader (same normalization and disposition classification).
5. A host `replay_floor_lost` re-reads `F`. If `F > cursor` — the manager
   ingested and ACKed past the cursor while the host pruned — the pager
   continues canonically; otherwise it throws `HostSpanUnavailable
   ("replay_floor_lost")` as today (a restore or a foreign store). Every retry
   requires a strict frontier advance, bounded by `terminalSequence`, so the
   loop terminates.
6. `stream_identity_changed`, `beyond_emitted`, `request_failed`, identity and
   cursor faults are thrown unchanged.
7. `settled_from` stays truthful. When the settlement feed starts with `F ≥
   terminalSequence` it reads nothing from the host and answers
   `canonical_available`: the attempt records no verdict and no settlement,
   and the canonical feed (the direct binding or the prompt projector, a
   durable cursor consumer) settles it as `canonical`. A settlement labelled
   `host_span` therefore always read at least its terminal row from the host.

The span verifier (`commandEvents`) keeps every check and gains one row kind:
a *skipped row* `{hostSequence, runId, eventType, reason}`, accepted for
contiguity only when its `runId` differs from the command's run. A skipped row
of the prompt's own run is `event_span_gap` — unverifiable, as before; a
skipped accepted row is own-run by definition, hence a gap. The accepted-row
binding applies to the first row whatever its source.

**D4 — The signal rule covers the whole span.** A read is a *fast feed* when
the span is not wholly behind the frontier at its start (`F <
terminalSequence`), and always when it settles (`verifyHostPromptSpan`). A fast
feed refuses (`HostSpanSignals`) on an own-session consumer-signal event
(`session.hook_trip`, `session.permission_request`, `session.exited`,
`session.crashed`) from EITHER source: the canonical prefix now carries the
obligation the host rows carried alone. A read that starts with `F ≥
terminalSequence` is the canonical path and, as before, does not refuse on
signals — the canonical feed delivers them to their consumers.
`frontierFallback` keeps mapping `HostSpanUnavailable` and `HostSpanSignals` to
`event_frontier` for a fast owner read.

**D5 — What stays the same.** `hostSpanEligible`, the verdict mapping
(`busy | refused`), `settled_from`, ADR-177's resolver rule, the direct binding
(`reconcileStoredPromptEvidence`, canonical-only), `confirmHostSpanSettlement`,
the prelude's runtime-object reads (manifest and response are objects, not
outbox rows), and the span route's wire contract, including its
`replay_floor_lost` answer below the floor. With D1 and D3 a live or lost
stream's span is always readable, so a refusal the resolver sees is a genuine
loss.

**D6 — A producer pause is logged (host).** The frame gate logs INFO
`producer-output-paused {sessionId, runId, outboxRefusesFrames}` on the
`outputPaused` false→true edge and INFO `producer-output-resumed {sessionId,
runId, pausedMs}` on true→false — at most one pair per pause.
`producer-pause-exceeded` is unchanged. There is no health field: the acceptance
counts the lines, and so can an operator.

**D7 — Acceptance at the default budgets.** The retained-pressure trigger is
the soft budget (ADR-183 D3) and a pass prunes only to below low, so "retained
below soft at every sample" is unreachable by construction. R20 at the default
budgets, ten minutes, alone on a quiet host on mains power, gates on the
consequences instead: (a) `pressured` never set; (b) no command refused
`event_outbox_backpressure` and no manager pressure record; (c) zero
`producer-output-paused` and zero `producer-pause-exceeded` lines; (d) retained
never reaches the hard budget; (e) every `outbox-retained-pressure-prune`
episode ends below low and `outbox-retained-pressure-prune-stalled` never logs;
(f) retained stays at or above soft for at most **N** consecutive 1 s samples,
where N is measured, not guessed: twice the longest retained-pressure pass of a
first acceptance run, rounded up to whole seconds and capped at 10, recorded
here and as a named constant in the harness; a second run must pass with it;
(g) at least 360 rows/s and every existing R20 gate (lag within two batches,
ACKs no more than batches, no server close, no host-span settlement, all nine
prompts settled canonically). While retained is at or above soft the host is
*constrained* (ADR-183 D5) and funds completion and teardown evidence from
producer wallets — a funding source only; nothing is refused or paused, and (f)
bounds the windows.

**D8 — No new lock.** "Host floor ≤ host ACK ≤ manager frontier" is enforced
by what already exists: the ACK route's contiguity and beyond-emitted refusals,
the ingest transaction and the boot audit. The pager tolerates the one race the
change opens (D3.5). The prune transaction (`BEGIN IMMEDIATE` per page) is
unchanged.

**Recovery windows (normative).** The pager is read-only and the host prune is
per-page transactional.

| # | Window | What happens |
| --- | --- | --- |
| W1 | The host pruned `(cursor, F′]` between the pager's frontier read and its host request | `replay_floor_lost` → re-read `F` → canonical page (D3.5) |
| W2 | The manager process dies mid-read | nothing was written; the next reader starts from `acceptedSequence − 1` |
| W3 | A manager restored behind the host's ACK | frontier < floor → `replay_floor_lost` without an advance → `refused` → EDGE-EVT-03 (the stream becomes `unrecoverable`; the resolver crashes a lost stream's turn) |
| W4 | The host restarts mid-span | the boot audit passes (the prefix is intact); the span resumes from the manager's frontier |

**Consequences:**

- A busy host with a caught-up manager no longer reaches the hard budget
  because one turn is long: the retained-pressure prune deletes every ACKed
  row, and only the manager falling behind (the unACKed lane, ADR-183 D1) can
  pin the outbox.
- The stream-lost rescue keeps working: a lost stream's frontier is where
  ingest stopped, the host still holds every row above it, and the pager reads
  the prefix canonically and the tail from the host.
- A manager restored behind the host's ACK still gets `replay_floor_lost` and
  a `refused` verdict (W3) — unchanged.
- A skipped row of the prompt's own run is unverifiable, as before; a foreign
  skipped row no longer fails an otherwise caught-up span with
  `event_span_gap`.
- An owner read and a settlement that touched the host log one INFO
  `prompt-span-read {commandId, canonicalRows, hostRows, skippedRows,
  frontierAtStart, floorRetries}`; a floor retry logs DEBUG
  `prompt-span-floor-retry {commandId, cursor, frontier}`.
- No migration, env var, wire field, route, error code or table changes. The
  host-private `RuntimeEventPruneState` type drops `protectedFromSequence`.

**Alternatives Considered:**

- **Holes in the outbox (prune ACKed rows around an open span):** rejected —
  it breaks the prefix contract every host dependent relies on (the prune walk,
  ACK ranges, the boot audit, the span store's 503 guarantee, and SSE catch-up,
  which would skip a gap silently) and changes EDGE-EVT-03.
- **Keep the span stop in `grace` mode only:** rejected — with the reader moved
  it protects nothing and keeps a 24 h pin; one rule is simpler.
- **Raise the default budgets:** rejected — it measures the longest turn, not
  the manager; any budget is crossed by a long enough turn at a high enough
  row rate.
- **Read the whole span canonically once the frontier covers it, and from the
  host otherwise (two paths, as before):** rejected — the host no longer holds
  an open span's ACKed prefix, so the host path alone cannot read it; a
  cursor that switches source at the frontier is the smallest reader that is
  always complete.
