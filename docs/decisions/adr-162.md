# ADR-162: Universal structured node result — transport matrix, open JSON grammar, schema identity

> Part of the ADR log — hub, index, and editing rules: [`../decisions.md`](../decisions.md).


**Date:** 2026-09-01
**Status:** Accepted

**Context:** `output.result` (ADR-063, extended by ADR-103) is the node-level
contract for a schema-validated structured result folded into
`node_attempts.vars`. Three gaps accumulated since it shipped:

1. **The transport is picked by a two-arm ternary, not by a matrix.** The seam
   selects `sentinel` for `ai_coding`/`judge` and `file` for everything else
   after excluding `human`/`form`. `orchestrator` and `consensus` therefore fall
   to the `file` arm — a transport neither of them provisions, because
   `MAISTER_OUTPUT_FILE` is armed only inside `runCliStep`. A declared
   `output.result` on either node type is silently dead: `required: true`
   produces a guaranteed, misleading "MAISTER_OUTPUT_FILE was not written"
   `CONFIG`, `required: false` is a no-op. The Zod DSL accepts the declaration on
   all eight node types with no per-type gate, so nothing refuses it at load.
2. **The schema grammar is narrower than the payloads agents actually emit.**
   `formSchemaSchema` has five scalar-ish types plus `object`; `array` checks
   only `Array.isArray`, there is no escape hatch for an opaque JSON subtree, and
   the validator has no structural bounds — no depth limit, no key-count limit,
   no array-length limit, and no rejection of `__proto__`/`constructor`/
   `prototype` own keys, on a payload whose producer is an LLM.
3. **Nothing records which schema validated an attempt.** `node_attempts` has no
   engine-metadata slot: `vars` is the flow-visible plane, `decision` is
   rework/takeover provenance, `stdout` is truncated diagnostics. A package
   upgrade that edits a schema file leaves no way to tell which contract a past
   attempt was judged against.

**Decision:** Make the transport a **matrix keyed by node type**, widen the
schema grammar with bounded openness, and persist a per-attempt schema identity.

- **One transport SSOT.** `NODE_OUTPUT_TRANSPORT` in
  `web/lib/flows/graph/node-output.ts` maps every node type to exactly one
  transport; the seam, the load-time refusals, and the shipped authoring grammar
  all derive from it. The transport is chosen by the node's **execution
  mechanism**, never author-declared.

  | Node type | Transport | Semantics |
  |---|---|---|
  | `ai_coding`, `judge`, `orchestrator` | `sentinel` | Last properly-fenced ` ```json maister:output ` block in the 1 MiB-capped stdout of the **completing** turn. |
  | `cli`, `check` | `file` | Per-attempt `MAISTER_OUTPUT_FILE`, unchanged. |
  | `consensus` | `engine_vars` | The engine-produced `result.vars` is validated **in place** — no merge, no mutation. |
  | `human`, `form` | none | Declaring `output.result` is refused at load; their vars come from the native HITL input artifact. |

- **An orchestrator is validated only on its completing turn.** A parked turn
  (pending children) breaks out of `runGraph` before the seam, so a coordinator
  that yields is never asked for a payload it has not produced yet. This is
  the existing control flow, now stated as contract rather than left implicit.

- **`consensus` validates engine vars, and validation is all it does.** The only
  `ok && !needsInput` result reaching the seam is synthesis completion carrying
  `vars.consensus`. The seam validates that object against the declared schema
  and never writes into it — the engine owns those keys. Absent ⇔ zero keys.

- **`human`/`form` + `output.result` is refused at load with no engine floor.**
  The combination is dead configuration today, so a hard refusal corrects an
  authoring error rather than breaking working behavior. Every other new
  capability is floored at `3.6.0`.

- **Engine `3.5.0 → 3.6.0`.** `output.result` on `orchestrator`/`consensus`
  requires `compat.engine_min >= 3.6.0`, enforced at manifest load. A schema
  document using `type: "json"` or `items` requires the same floor, enforced
  where manifest and document meet: package install
  (`validatePackageRootSchemaReferences` → `FLOW_INSTALL`) and Studio lifecycle
  validation (`form_schema_invalid`, BLOCK).

- **`type: "json"` is any JSON value, and it is the one type where `null` is
  present.** Every other type keeps `null = absent` byte-identically; a
  `required` `json` field is satisfied by an explicit `null` and violated only
  by a missing key. Diverging here is deliberate: an opaque-JSON field whose
  legitimate value is `null` would otherwise be unrepresentable.

- **`array` gains an optional recursive nameless `items`.** Arrays without
  `items` stay untyped and byte-identically valid; with `items`, each element is
  checked and a violation names `field[i]`.

- **Objects stay open by default and undeclared keys are preserved.** This was
  already the behavior (the validator iterates schema fields, not payload keys);
  it is now formalized, documented, and pinned by test. No
  `additionalProperties` knob — the default is already open and no use-case
  demands closing it.

- **Structural bounds and unsafe-key rejection live in one pre-pass walk**:
  own-keys `__proto__` / `constructor` / `prototype` rejected at any depth
  (naming the JSON path), depth > 64, total object keys > 10 000, array length
  > 10 000. Exported constants, **no new env vars** — `MAISTER_NODE_OUTPUT_MAX_BYTES`
  stays the single tunable and subsumes per-string length.

- **The hardening lands on the shared validator, so it lands on all three of its
  consumers** — node output, HITL form/human responses, and Brain lesson
  distillation. That is intended: all three validate LLM-origin payloads that
  reach the same flow-visible plane, and a bound that holds for one holds for
  all. It is regression-swept, not assumed.

- **Per-attempt schema identity is persisted** in a new nullable
  `node_attempts.output_contract` jsonb (migration `0127`):
  `{ schemaRef, schemaVersion, sha256, transport, engineVersion }`, written on
  the same ledger UPDATE that closes the attempt — success **and** seam failure
  — and never cleared by `markNodeReworked`. `sha256` hashes the raw schema
  bytes at resolution time. `NULL` means "pre-feature or no declaration", never
  "unknown contract". No existing column fits: `vars` is the flow-visible plane
  and a reader would surface engine metadata as a flow variable.

- **No API surface changes.** The only full-row `select().from(nodeAttempts)` in
  non-test code is engine-internal (`ledger.ts`); every UI/ext query enumerates
  columns, so the new column reaches no documented response. Exposing it later
  is a separate decision.

- **The sentinel instruction stays package-owned.** The engine does not inject
  "emit a ` ```json maister:output ` block" into any prompt; the shipped
  authoring grammar teaches the author instead.

**Consequences:**

- A previously-silent misconfiguration becomes a loud one. An
  `orchestrator`/`consensus` node declaring `output.result` at an engine floor
  below `3.6.0`, and any `human`/`form` node declaring it at any floor, now
  refuse at load. A census over the repo and shipped packages found **zero**
  such declarations, so nothing real breaks — but the refusals are intentional
  behavior changes, not compatible extensions.
- `ai_coding`, `judge`, `cli`, and `check` are byte-identical, pinned by their
  existing suites passing without assertion edits.
- Payloads that were previously accepted and are now rejected: those carrying an
  own `__proto__`/`constructor`/`prototype` key, or exceeding the depth/key/
  array bounds. This is the task's documented-unsafe carve-out and applies to
  HITL form responses and Brain lessons as well as node output.
- One additive nullable column; old rows read `NULL`. No backfill, no response
  shape change, no new `MaisterError` code, no new env var, no compose change.

**Alternatives Considered:**

- _Provision `MAISTER_OUTPUT_FILE` for orchestrator/consensus too_: rejected —
  neither runs a shell child, so there is no process to hand a path to; the file
  would have to be written by the engine itself, which is what `engine_vars`
  does directly and without a filesystem round-trip.
- _Inject the sentinel instruction into every agent prompt_: rejected — it would
  mutate `resolved_prompt` for every run of every declaring node, break prompt
  stability that reruns and provenance depend on, and take ownership of prompt
  text away from the package that ships it. Teaching the authoring grammar
  achieves the same outcome at authoring time.
- _Merge validated `consensus` payload keys into `vars` like the other arms_:
  rejected — the engine produced those keys; folding a validated copy back over
  them is either a no-op or a silent overwrite of engine state by agent-shaped
  data.
- _Close objects by default / add an `additionalProperties` knob_: rejected —
  the validator has always been open, closing it would break every existing
  payload carrying extra keys, and no use-case asked for the knob.
- _Make the structural limits env-tunable_: rejected — they are safety bounds on
  an LLM-authored payload, not a capacity dial; `MAISTER_NODE_OUTPUT_MAX_BYTES`
  already covers the capacity axis.
- _Reuse `node_attempts.vars` for the schema identity_: rejected — `vars` is the
  flow-visible plane read by templating, `decide`, and the run-context
  projection; engine metadata placed there would surface as a flow variable.
- _Skip the audit column and derive identity from the pinned revision_: rejected
  — the pinned revision names the package, not the bytes of the schema file the
  attempt was actually judged against, and a fork/sync can change those bytes
  under a stable ref.
- _Refuse `human`/`form` + `output.result` behind the `3.6.0` floor like the
  coordinator arms_: rejected — a floor implies "works above this version". The
  combination is dead at every version, so the honest gate is an unconditional
  refusal.

**Amendments:**

- 2026-09-01 — Implementation precision on the audit column: `output_contract`
  is recorded whenever the declared schema was RESOLVED — the success path and
  any post-resolution seam failure (a schema mismatch). A failure that occurs
  before the schema is read (payload absent while `required`, malformed JSON,
  over the byte cap, unresolvable schema path) leaves it `NULL`, because no
  contract identity exists at that point. Resolving eagerly on every declaring
  attempt was rejected: it would turn a today-passing optional-absent run whose
  schema file is broken into a `CONFIG` failure, which is a behavior change the
  decision never intended.
