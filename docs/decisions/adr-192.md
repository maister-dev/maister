# ADR-192: Durable scratch prompt intent before command admission

> Part of the ADR log — hub, index, and editing rules: [`../decisions.md`](../decisions.md).

**Date:** 2026-09-30
**Status:** Proposed

**Context:** Five scratch paths commit a prompt-ready dialog before they admit
`session.prompt`: project and local-package launch, queued dispatch, direct
message, Recover, and the D-A8 idle resume. A web death between those commits
leaves `runs.status='Running'` under a live host session, but the continuation
worker only re-drives a `WaitingForUser` dialog with a queued row. The stored
`run_messages` row is insufficient to reconstruct the original operation:
`sendLocalPackageAssistantMessage` derives its prompt from request-only
`intent`/`focus`, mints a postprocess action ID after the row commits, and uses
the request's edit-lock generation. Local-package launch has the same
postprocess/lock cut. Recover and D-A8 use a generation-scoped `recovery`
owner, while a queued row uses its message-scoped `message` owner. Choosing the
newest row after restart could therefore send a different prompt or reuse the
wrong command key. The immutable command ledger prevents a second admission
only when the caller presents the **same** owner, operation key and payload.

**Decision:** A prompt-ready scratch status transaction MUST durably freeze its
active prompt intent before returning. Migration 0192 adds a nullable
`scratch_runs.active_prompt_intent` JSONB column and a bounded partial index
on `(updated_at, run_id)` where `dialog_status='Running'`. The nullable shape
allows existing rows and mixed-version writers to remain readable. A versioned
parser admits only an intent containing:

- owner variant (`initial`, `package_initial`, `message`, `package_message`, or
  `recovery`) and its exact message ID/sequence or assignment generation;
- current assignment and host-session identity, the existing
  `scratchPromptOperationKey`, and the source message row where one exists;
- the exact normalized prompt, step ID and ordered content-block references
  that the live path would submit;
- for package owners, local-package ID, the server-minted postprocess action
  ID and the edit-lock generation captured while that lock is held.

The column is a *single active turn* snapshot, not a second command ledger.
It is replaced only by a winning transaction for a later turn and is cleared
or made inert by its terminal status transition. It is never populated from a
timestamp, a latest-row guess, or a receipt that lacks matching identity.
Package context is materialized and its action ID minted **before** the
prompt-ready commit; a materialization failure rolls that transition back.
Queued dispatch freezes the selected oldest row in the same transaction as
`queued → prompted`; Recover's queued-ahead branch remains
`WaitingForUser` and has no recovery prompt intent until a message dispatcher
wins. D-A8 freezes the source row it selected when it claims its generation.

The continuation worker may select a Running dialog older than one eligible
tick, but age is only a *wake condition*. Inside `issueOwnedPrompt`'s
`admitOwner(tx)` transaction the owner takes the existing scheduler → run →
scratch_runs → message lock order, parses and verifies the frozen intent,
current assignment/incarnation and status, and lets the ledger compare the
immutable request under that same run lock. A matching command is joined or
left to its owner; an unresolved, quarantined, retired or terminal-unapplied
command never authorizes a new effect. A missing command plus a valid current
intent may admit the original operation once. Stop, Recover and a successor
assignment fence an old intent before any send. Remote I/O occurs after commit.

**Existing and mixed-version rows:** A null intent on an old Running dialog is
not proof of an unsent prompt. The worker MUST NOT re-drive it, requeue a
`prompted` row, or mark a package turn delivered. It records a bounded,
structured diagnostic; the scratch detail shows an explicit unknown-delivery
notice directing the operator to Stop this run and start a new run.
Stop moves the run to Review, so this is not the Crashed-run Recover API. A known ledger command
continues through its owner. The rollout may overlap an older web writer;
null-intent rows retain this conservative treatment until old writers drain.
There is no fabricated backfill for package `intent`/`focus` or a postprocess
ID that never existed in durable state. This is an explicit pre-upgrade
limitation; only turns written by the new intent contract can meet automatic
two-tick recovery.

**Checks before implementation:** The migration's SQL CHECK must reject a
non-object or unsupported version and bound the stored payload; the TypeScript
parser enforces the full discriminated shape. Test the empty schema and an
upgrade from 0191 with queued, Running and parked rows, preserving the latter
as null. Prove the partial index bounds the worker query with representative
`EXPLAIN` cardinalities. RED controls kill the production web at each commit
cut, restart on the same DB/host and assert one prompt effect per operation,
exact package postprocessing and FIFO. A legacy null-intent row must emit the
visible refusal without a prompt. No endpoint, run status, `MaisterError`
code or session cause enum is added.
