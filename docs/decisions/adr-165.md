## Context

An `orchestrator` node (ADR-098/099/100) can now delegate to a catalog **agent**
and, since ADR-163, to a trusted **flow**. ADR-162 gave every AI-producing
*node* a validated structured `output.result`. Together they get MAIster to the
edge of a recursive harness — a coordinator that fans work out to children,
reads what they produced, and composes a governed result — but four structural
gaps stop it there. Each was established by reading the working tree, not
assumed:

1. **No run-level result entity.** `output.result` is a *node* concept. Its
   payload is merged into `node_attempts.vars` (`result.vars = {...vars,
   ...value}`) and the pure value exists only inside the seam's success path.
   An **agent** run has no result plane at all: `finalizeAgentRun` writes only
   `runs`, and `consumeAgentSession` extracts text solely for consensus drafts.
   A parent therefore cannot ask "what did my child produce?" — only "did it
   exit?".
2. **Node-level delegation bounds are dead config.** `settings.delegation
   .max_fanout` / `.max_depth` parse and are never read; `admitDelegatedChild`
   uses the env ceilings only. With `MAISTER_ORCHESTRATOR_MAX_DEPTH=3` and
   `MAISTER_MAX_ORCHESTRATOR_FANOUT=16` a single root admits up to 4 096 runs.
   There is no child-count budget and no per-orchestrator active-children cap.
3. **`run_collect` scavenges.** It reads an `inline` artifact for `outputText`
   with no `ORDER BY` (non-deterministic under two qualifying artifacts),
   invents a `"unknown"` status for a missing row, and its OpenAPI documents a
   404 where the code returns 409.
4. **No tree-wide roll-up.** Cost and wall-clock are per-run in every UI and in
   the Evaluation Lab; `queryRunTreeTokens` exists but is metered only by the
   root-scoped keep-alive budget sweeper. The Lab has no rework, crash,
   child-count or result-quality measure.

The run-tree substrate that a harness needs is otherwise present and unchanged
by this ADR: `runs.parent_run_id` / `root_run_id`, `WaitingOnChildren` +
`orchestrator_resume`, `cascadeAbandonRunTreeAndStopSessions`, promotion's
`assertEvidenceReady` re-gate, ADR-101 root tree meters, the artifact validity
FSM, and readiness.

---

## Decision

Ship a **run-kind-neutral public result plane**, make node-level recursion
bounds live behind an engine floor, extend `run_collect` to serve validated
results, and let a flow run that produced a result and changed nothing finish
without a human review step.

### D1 — A new table, not the artifact plane or `node_attempts`

`run_results` holds **one row per result revision** (including `invalid` rows),
plus three additive nullable `jsonb` columns: `runs.result_contract`,
`runs.delegation_bounds`, `flow_revisions.result_profiles`. Migration `0129`,
additive, no backfill; `NULL` means "no contract / pre-feature".

A revision has its own lifecycle and there are N per run, which is the DB rule
for a new table. Plane separation (ADR-162 D7) forbids reusing
`artifact_instances`, and `node_attempts.vars` is a merged bag (never the pure
value) and exists only for graph runs.

### D2 — The envelope

The wire shape is `{ schemaRef, value }` and nothing else. The producer supplies
**only** `value`; every other field is engine-owned:

| Field | Owner | Source |
| --- | --- | --- |
| run identity | engine | `run_results.run_id` |
| schema identity | engine | `schema_ref`, `schema_sha256`, `schema_version` from the launch-time contract |
| producer identity | engine | `producer_kind` (`flow_node` \| `agent_session`) + `producer_ref` |
| attempt / revision | engine | `node_attempt_id`, `revision` (1-based, `UNIQUE(run_id, revision)`) |
| validity + supersession | engine | `validity`, `superseded_by_id`, `superseded_at` |
| artifact metadata | engine | `artifact_manifest` — the engine manifest AT PUBLISH, from `artifact_instances` |
| creation / completion | engine | `created_at`; completion is `runs.ended_at`, joined, never duplicated |

`schemaRef = "<flowRefId>@<resolvedRevision[:12]>:<schemaStem>"` — deterministic
from server state, matching the brief's `package@revision:name` shape.

### D3 — Flow result: a top-level `result.export`

```yaml
result:
  export:
    schema: ./schemas/research-result.v1.json
    from: [orchestrate]
    required: true          # default
```

Load-time rules (all `CONFIG`, all in `validateGraphManifest`): every `from[]`
node exists, is not `human`/`form`, declares `output.result`, and its
`output.result.schema` normalizes to the SAME path as the export's. A producer
node's `output.result.required` is forced `true` when the export is required.
At runtime, **latest valid publish wins**.

Enforcing "every permitted producer satisfies the export schema" where it is
declared is the ADR-162 pattern: a statically decidable misconfiguration is a
load-time refusal, not a runtime surprise.

### D4 — Agent result: package-level named `result_profiles`

```yaml
# maister-package.yaml
result_profiles:
  research:
    schema: ./schemas/research-result.v1.json
```

Resolved at **install** into `flow_revisions.result_profiles` for every member
flow, in the same statement that writes the revision. At delegation,
`body.resultProfile` is a **name** resolved against the PARENT run's pinned
revision (`runs.flow_revision_id` → `flow_revisions.result_profiles`); the
allowed set is that map's keys. Package-root `schemas/` is already copied into
every member flow's `installedPath/schemas/` at install, so no new materialization
path is introduced.

Schema documents are **JSON** (`./schemas/<name>.json`) — `ROOT_SCHEMA_PATTERN`
accepts nothing else, and the reader is the existing `readFormSchemaDocWithBytes`.

### D5 — Node bounds go live at engine `3.7.0`, and only there

`settings.delegation` gains `max_active_children?` and, for orchestrator nodes in
a `≥ 3.7.0` manifest, a **required and complete** `budget { max_tokens,
wall_clock_minutes, max_child_runs, consecutive_failures }`.

Effective bounds, computed at node start:

```
depth  = min(MAISTER_ORCHESTRATOR_MAX_DEPTH,   max_depth  ?? 2)
fanout = min(MAISTER_MAX_ORCHESTRATOR_FANOUT,  max_fanout ?? 6)
active = min(poolCap(kind),                    max_active_children ?? 3)
```

`max_depth` is ABSOLUTE from the tree root and admission min-merges it with the
root's snapshot, so a nested flow declares the depth its children occupy in the
whole tree. `budget` is normalized into the internal camelCase shape at this one
seam — the manifest's snake_case keys are unreadable to admission and the
sweeper.

A manifest below the floor keeps **byte-identical** env-only semantics. Floor
gating is the ADR-162 precedent; no shipped manifest changes behaviour, and
"deeper recursion needs Flow author intent" holds because the node default (2)
sits below the env ceiling (3). No new environment variable (D13).

### D6 — Bounds are snapshotted on the orchestrator run

`runs.delegation_bounds` is written at the token-issuance site, keyed by
`nodeAttemptId`, and rewritten only when the active node **attempt** changes.
Admission reads the parent's and the ancestors' snapshots; `NULL` means env-only.
An env change after the snapshot cannot change a running tree's bounds — that is
the point (brief §5 "active node from server state", §7 "record effective bounds
for audit and recovery").

### D7 — Active-children concurrency is a queue, never a refusal

A child whose parent already has `maxActiveChildren` siblings in
`SLOT_HOLDING_RUN_STATUSES` (`Running | NeedsInput | HumanWorking`) stays
`Pending`; `tryStartRun` and `promoteNextPending` skip it exactly the way
`sharedWriterSiblingActive` already does. `run_delegate` reports the outcome
additively as `status: "Pending" | "Running"`.

Cap semantics in MAIster are queue + position (root `CLAUDE.md` §4), and reusing
the scheduler's one skip idiom keeps a single mechanism.

### D8 — Count budgets bind everywhere; spend budgets bind at the root

- **`max_child_runs` binds at EVERY level.** Admission walks the ancestor chain
  (it already visits every ancestor for the depth check) and refuses when any
  ancestor's subtree — all statuses, recursive CTE over `parent_run_id` — plus
  the incoming count exceeds that ancestor's `max_child_runs`. Because that
  invariant is ancestor-scoped while the per-orchestrator lock is keyed on the
  parent, admission ALSO locks the **tree root** before counting — otherwise two
  orchestrators in one tree read the same pre-insert count and both admit.
- **Token / wall-clock / consecutive-failure budgets bind at the tree ROOT**,
  min-merged into the existing ADR-101 sweeper meters. On a nested orchestrator
  they are recorded and not metered.

Count is what prevents a depth × fan-out blow-up and is cheap to evaluate under
the lock already held. The sweeper already meters the root; a per-subtree spend
meter is a separate mechanism and stays out (residual **R-nested**).

Documented contract: *count budgets bind at every level; spend, time and failure
budgets bind at the tree root; a flow launched as a child obeys the root's.*

### D9 — Publish points, and their atomicity

| Producer | Where the result is written | Transaction |
| --- | --- | --- |
| Flow node | `closeSucceededAttemptWithResult` — one helper wrapping `markNodeSucceeded` + the `run_results` INSERT + supersede, at all three `markNodeSucceeded` call sites | one tx |
| Agent run | `finalizeAgentRun` parses, validates, inserts, flips status and emits | its EXISTING tx |
| Flow terminal | the completeness gate and result-only completion | the EXISTING terminal tx |
| Collect marker | `first_collected_at` | a tx before the HTTP response (idempotent) |

Every result write shares the transaction of the state it describes, so a woken
parent can never observe a settle without its row.

### D10 — Missing and invalid semantics

`required` excuses **absence only**.

| Case | Row | Run | Event |
| --- | --- | --- | --- |
| Agent child, required profile, sentinel absent | `invalid` (`result_missing`, no value) | `Failed` | `run.failed{reason:"result_missing"}` |
| Agent child, present but invalid | `invalid` (class reason) | `Failed` | `run.failed{reason:"result_invalid"}` |
| Agent child, optional profile, absent | none (`absent`) | normal | normal |
| Flow producer node fails | ADR-162 semantics unchanged (`on_mismatch` rework, else Failed) | — | — |
| Flow `graph_completed`, required export, no current `valid` row | `invalid` (`result_missing`) | `Failed` | `run.failed{reason:"result_missing"}` |
| Human-resolved Review flip (`operator_stop`, `rework_released`, `sync_returned`) | none | **never failed** | `run.review{cause, resultStatus}` |
| Failure-terminal child | — | — | collect reports `unavailable` + `resultFailure` from the newest `invalid` row |

Fail-closed is the right default because auto-promotion reads these states; the
parent wakes on `run.failed` and either re-delegates within budget or escalates.
The `invalid` row gives `resultFailure` exactly ONE durable source.

### D11 — Supersession and staleness

A publish supersedes every prior `valid | stale` row for the run.
`markDownstreamStale` flips the run's `valid` row to `stale` when its producer
node is among the staled nodes. At most one `valid` row per run, enforced by a
partial unique index — mirroring the artifact FSM without joining the evidence
plane.

### D12 — `run_collect` v2 is additive on the same route

New fields: `settled`, `resultStatus`, `result`, `resultRevision`,
`resultFailure`; artifact items gain `nodeId` and `validity`. `outputText`
becomes deprecated and deterministic (`ORDER BY created_at DESC LIMIT 1`). The
`"unknown"` status fallback is removed — a missing row is a mismatch → `409`.
The OpenAPI 404-vs-409 drift is fixed **to the code**. Every existing caller
keeps working on the fields it already reads, so no versioned `/collect/v2`
route is needed.

### D13 — No new environment variable

Nothing new to wire: no `compose*.yml`, no Dockerfile, no `.env.example` value.
Description text only in `docs/configuration.md` and `.env.example` comments.

### D14 — Numbering

ADR-165, migration `0129`, engine `3.7.0`. A renumber pass runs after the rebase
onto `main`; 164/0128 are taken only if the owner drops the Stage A branch.

### D15 — Hidden subagents are structurally excluded

The reference workflow's orchestrator node carries `enforcement.tools: strict`
with a `tools` allow-list that omits the adapter's subagent tool (`Task`/`Agent`
on claude; codex has none), enforced at the supervisor ACP seam by
`capability_guard` (ADR-130). Delegation happens only through `run_delegate` /
`run_plan`. An adapter-internal hidden subagent does not satisfy this contract
because nothing it does is governed, budgeted, or collectable.

### D16 — The reference RAH graph: one flow run, one worktree

```
orchestrate (orchestrator)  →  writer (ai_coding)  →  verify (judge)  →  review (human)  →  done
```

- `orchestrate` fans out **read-only** researchers: agent children at depth 1, or
  `rah-research` flow children at depth 2. Its completing turn publishes the
  REDUCED result, including `consumedChildRunIds`.
- `writer` is the **only** worktree writer, by construction — no shared-workspace
  child writers.
- `verify` is a judge on an independent runner behind a blocking `ai_judgment`
  gate; `review` is a human node; readiness and `promoteRun` are unchanged.
- `orchestrate.output.result.on_mismatch: retry`, bounded by `rework.maxLoops`;
  `decide` on `outcome` routes `blocked → escalate` (human).
- Research flow children carry `result.export` and finish `Done` by result-only
  completion (D17) — the coordinator only collects.

### D17 — Result-only completion

In `runGraph`'s success branch, when **all three** hold:

1. `runs.result_contract.kind === "flow_export"`,
2. a `valid` current result exists, and
3. the workspace is clean — `diffNameStatus(base_commit..branch)` empty AND
   `diffWorkingTree(HEAD)` empty; a NULL `base_commit` is **not** clean —

the run flips `Running → Done` inside the terminal transaction:

- `runs { status: "Done", endedAt, currentStepId: null, diffStat: {files:0, additions:0, deletions:0} }`; `promotedHeadSha` and `mergeCommitSha` stay NULL.
- `workspaces { scheduledRemovalAt = now + gcAgeDays }`; `promotion_state` stays `none`.
- `systemCloseActiveAssignmentsForRun`.
- webhook `run.done{}` + domain `run.done{ …, completion:"result_only", resultStatus:"valid", parentRunId }`.
- **No** `run.review`; `deliverRunIfAutoReady` is skipped; mounts released, token
  revoked, `promoteNextPending` via the existing exit.

Any other success exit — a committed diff, a dirty tree, an optional-absent
result, or no export at all — behaves **byte-identically to today**.
`assertEvidenceReady(runId, "review")` still gates it (it runs before the
branch). `promotion_hold` is deliberately **not** consulted: nothing is promoted,
there is no git side effect, and the hold column is untouched.

A research flow has nothing to promote. This gives it parity with a
`workspace: none` agent child reaching `Done`, removes the coordinator-discipline
residual for research flows, and keeps `Review` meaning exactly "a diff awaits a
human".

### D18 — `ralph_loop` never relaunches a delegated child

`ralphLoopConsumer` relaunches a task-backed flow run on `run.failed` when the
policy says `ralph_loop` and it is the task's latest run — without checking
`parent_run_id`. A delegated flow child would therefore be relaunched
lineage-less: an orphan the parent never collects. Runs with `parent_run_id` are
now skipped (and logged). The orchestrator owns retries of its children; that is
what brief §6's "route child failures through bounded rework or human escalation"
means.

## The envelope, by run kind

| Run kind | Public result | Contract source |
| --- | --- | --- |
| **flow** | opt-in via `result.export` | the PINNED `flow_revisions` manifest at launch |
| **agent** | opt-in via `resultProfile` at delegation | the PARENT run's pinned `flow_revisions.result_profiles` |
| **scratch** | optional; no contract today | — (`result_contract` NULL) |
| manual / board launches | optional; a flow declaring `result.export` gets one | as flow |

A **nested orchestrator publishes its OWN result** — it is a flow run like any
other, and its export is independent of what its children published.

## Wake invariant

A parent in `WaitingOnChildren` is woken by `orchestrator_resume` on exactly
these `domain_events` kinds, routed by `payload.parentRunId`:

`run.review` (cause-tagged) · `run.done` (including `completion:"result_only"`) ·
`run.failed` · `run.crashed` · `run.abandoned`.

Failure kinds wake unconditionally; success-side kinds wake at
`pendingChildCount === 0`.

> **Invariant.** The child's `run_results` row — valid or invalid — is committed
> in the SAME transaction as the settle flip that emits the event. A woken
> parent's `run_collect` therefore never observes a half-published result.

Payload widening is additive, with no new kinds and no CHECK change:
`run.review | run.done | run.failed` gain `resultStatus`; `run.done` gains
`completion ∈ {promoted, result_only}`; `run.failed.reason` gains
`result_missing | result_invalid`.

## Consequences

**Positive**

- One engine-owned result plane serves every run kind; a coordinator reads
  `result.value`, not scavenged text.
- Recursion is bounded by author intent within instance ceilings, recorded on the
  run for audit and recovery, and enforced under the lock that already serializes
  admission.
- A research child that changes nothing finishes by itself; `Review` keeps a
  single meaning.
- Tree-wide cost and wall-clock become first-class, and the Evaluation Lab can
  compare a recursive harness against flat arms over recorded facts.

**Negative / accepted**

- One more table and three more `jsonb` columns to keep in the four-legged
  migration discipline.
- `Running → Done` is a new flow-run edge. It is reachable only for flows
  declaring `result.export`, of which none exist today.
- `run_collect`'s `"unknown"` status fallback disappears; a caller relying on it
  now sees a `409`. It was never a truthful state.
- `ralph_loop` no longer relaunches delegated children. That is the fix, but it
  is a behaviour change to a shipped path.

**Blast radius.** Shipped processes ship no `orchestrator` node and no
`result.export`. Bounds change only behind `engine_min ≥ 3.7.0`. The residual
surface is `run_collect`'s three field-level changes, `run_delegate`'s additive
`status`, the OpenAPI 404 → 409 drift fix, and D18.

## Residuals

- **R-nested** — subtree token / wall-clock / failure budgets below the root are
  recorded but not metered. Only `max_child_runs` binds per ancestor.
- **W12 narrowed** — the "a delegated flow child parks in `Review` forever"
  residual from ADR-163 now applies only to flows that do NOT declare
  `result.export`. Result-bearing research flows finish themselves (D17).
- **W4** — a child that dies after `session.exited` is observed but before the
  finalize transaction reconciles to `Crashed` with **no result row**. The parent
  wakes on `run.crashed` and collects `unavailable`.
- `workspaceMode: shared` for flow children stays an ADR-163 follow-up; the
  reference workflow has exactly one writer by construction.

## Alternatives considered

- _Model the result as an `artifact_instances` kind._ Rejected — ADR-162 D7 set
  the plane separation deliberately: artifacts are evidence with a currency FSM
  tied to nodes, results are a run-level public contract with revisions and a
  supersession chain. Overloading the artifact plane would give every result a
  node identity an agent run does not have.
- _Put the result on `runs` columns._ Rejected — there are N revisions per run
  and an `invalid` row must persist a reason with no value. A single column
  cannot hold a supersession chain, and widening `runs` with five nullable
  columns per revision concept is the shape the "new table" DB rule exists to
  prevent.
- _Refuse rather than queue at the active-children cap._ Rejected — every other
  concurrency cap in MAIster queues with a position badge; a refusal would make
  a coordinator's fan-out non-deterministic in the size of the pool.
- _Make node bounds live for all manifests._ Rejected — `settings.delegation` has
  parsed since ADR-098 and been ignored since. Turning it on retroactively would
  silently change the behaviour of any shipped manifest that set it decoratively.
  The floor is the ADR-162 precedent for exactly this.
- _A versioned `/collect/v2` route._ Rejected — every change is additive except
  removing an untruthful fallback; a second route would double the surface the
  MCP facade mirrors for no compatibility gain.
- _Park an invalid agent result in `Review` for `run_rework` (Q4-B)._ Rejected
  for now — it presumes a human is watching a delegated child, which inverts the
  harness contract. Revisit if writer-children packages appear.
- _Auto-archive Review children instead of result-only completion (Q5-B)._
  Rejected — superseded by D17, which is honest about what happened (the run
  completed) instead of hiding a state the run never should have entered.
- _Let the delegation body carry a schema path instead of a profile name._
  Rejected — a path is a filesystem locator on a body-controlled field. A name
  resolved through an allow-list keyed on the parent's PINNED revision has no
  path component anywhere.

## As-built (2026-09-02)

Implemented as designed. Every decision D1–D18 stands; what follows is what the
implementation learned that the design did not say.

### Reconciled with the design

- **`max_depth` is ABSOLUTE from the tree root.** D5's formula is
  `min(env, max_depth ?? 2)` and admission additionally min-merges the ROOT's
  and PARENT's snapshots (R5). Together those mean a nested flow's `max_depth`
  is compared against its depth counted from the WHOLE tree's root, not from
  itself — so a flow authored to run as a child must declare the depth its own
  children will occupy in the whole tree, not the levels it adds. The reference
  fixture's research flow originally declared the relative number and would have
  refused its own researchers. Documented in `flow-dsl.md` and
  `orchestrator.md`; the fixture declares 2.
- **The declared `budget` is normalized, not copied.** A manifest writes
  snake_case; admission reads `budget.maxChildRuns` and the ADR-101 sweeper reads
  `budget.maxTokens`. Publishing the declaration verbatim published a budget
  nothing could read — every lookup `undefined`, every count budget silently
  unbound, no error anywhere. `DeclaredDelegationBudget` is now a distinct type
  from the effective `DelegationBudget`, and `computeEffectiveDelegationBounds`
  translates at that one seam.
- **A tree ROOT has `root_run_id = NULL`.** The launchers write
  `parent.rootRunId ?? parent.id`, so descendants carry the root's id and
  nothing self-stamps a root. The tree cost roll-up therefore tests PARENTAGE
  for rootness and scopes on `id = root OR root_run_id = root`; a
  `root_run_id`-only predicate never fires on a real root and drops the root's
  own spend.

### Residuals unchanged

**R-nested** (spend meters are root-only), **W12-narrowed**, **W4**
(no result on crash) stand as designed.

### Known gap, pre-existing and NOT introduced here

`queryRunTreeTokens` — the ADR-101 tree-budget meter that D8 min-merges the node
budget INTO — has the same `root_run_id`-only scope described above, so the tree
token budget excludes the root coordinator's own spend and a tree breach fires
later than the policy intends. It predates this ADR; aligning it changes shipped
budget behaviour for every existing tree and is deliberately left to its own
decision.
