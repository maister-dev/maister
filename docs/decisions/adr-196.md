# ADR-196: Agent activity history and grouped incidents

[Back to ADR index](../decisions.md#adr-196-agent-activity-history-and-grouped-incidents)

**Date:** 2026-10-30
**Status:** Accepted

**Context:** Frequent operational execution currently exposes session failures as workspaces and per-run attention, while routing confidence does not establish request validity or safe replay.

**Decision:** Separate active execution from physical workspace retention. Freeze source identity and launch ordering. Represent recurring failures as scoped cause episodes, immutable occurrences and independent per-reader acknowledgement/publication receipts. Reuse terminal/cleanup/outbox ownership, SSE, result evidence and existing notification delivery. Never group HITL or infer business outcome from workspace/prose.

The contract is **Implemented**. Existing agent behavior remains explicit legacy until its scoped migration/capability boundary. Canonical state transitions, wire shapes, schema and acceptance belong to [the owning domain](../system-analytics/agent-incidents.md), not this rationale.

**Consequences:** Platform/schema/MCP/UI deploy before compatible core and explicit project policy/pin changes. No automatic approval, promotion, blind side-effect replay or remote publication is introduced. Additive evidence survives cleanup and rollback; incompatible old writers stay fenced.

**Alternatives Considered:** Agent-ID exceptions, cosmetic Review filters, empty-diff promotion, prompt-only validation and a parallel workflow engine do not enforce the stated boundaries.

**Checks:** [Acceptance traceability](../system-analytics/agent-activity-traceability.md).
