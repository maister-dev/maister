# ADR-167: Durable execution-host event and runtime-data plane

> Part of the ADR log — hub, index, and editing rules: [`../decisions.md`](../decisions.md).

**Date:** 2026-09-04
**Status:** Implemented; amended 2026-09-23 (retirement tombstone guards; host-evidence settlement); amended 2026-09-25 (steer inside a prompt span; batched ingest and ACK, pausing subscriber)

**Qualification:** A/B correctness qualification is in progress.

The decision remains accepted. The [stabilization requirements](../system-analytics/execution-hosts.md#ab-stabilization-requirements) identify incomplete enforcement and required acceptance; this status does not certify those scenarios.

**Context:** Stage A established a local execution-host boundary with durable
host identity, assignment epochs, command receipts, and opaque workspace
handles. The web control plane still reads runtime files owned by the local
supervisor, so it cannot yet be the durable owner of event and runtime-data
metadata. ADR-023 and the current code establish that the shared filesystem is
an implementation limitation, not a remote-host feature.

**Decision:** Stage B makes Postgres the durable canonical owner of execution
events and runtime-data metadata while the execution host retains its ACP
processes, private SQLite state, and private runtime files. The decision is
implemented in independently deployable B0–B4 increments described by the
four bounded system specifications:

- [`execution-event-plane.md`](../system-analytics/execution-event-plane.md)
  owns durable host event ingestion, ordering, replay, acknowledgements,
  redaction, and reconciliation.
- [`execution-prompt-lifecycle.md`](../system-analytics/execution-prompt-lifecycle.md)
  owns asynchronous prompt continuation through the existing Stage A command
  ledger and receipt identity.
- [`execution-runtime-objects.md`](../system-analytics/execution-runtime-objects.md)
  owns opaque runtime-object metadata and bounded path-free transfer.
- [`execution-data-cutover.md`](../system-analytics/execution-data-cutover.md)
  owns the versioned per-run compatibility cutover and legacy-data import.

**D1 — Canonical event ownership.** An execution host writes each externally
observable event to a durable host outbox before live publication. A
transport-neutral v1 envelope has a closed deterministic spine
`{envelopeVersion,eventId,hostKey,hostBootId,streamId,sequence,runId,assignmentId,assignmentEpoch,hostSessionId,eventType,occurredAt,payloadSchema,payload}`;
`sequence` is a signed-BIGINT-safe decimal string and `payload` is open JSON
only for a negotiated type/schema pair. The manager resolves the host from the
selected transport and health identity, inserts at-least-once delivery exactly
once by event ID and `(host,stream,sequence)`, and allocates per-run canonical
sequence only for a contiguous accepted prefix. It is therefore the manager,
not a runtime event file, that feeds projections and browser replay.

**D2 — Ordering, replay, and acknowledgement.** Host order is total within a
durable `streamId`; a boot ID describes process incarnation and never resets
that stream's sequence. Gaps retain later events as pending, stop ACK at the
last contiguous sequence, and are replayed from that exact exclusive cursor.
Duplicate and lost-ACK delivery is harmless. An unrecoverable replay floor,
conflicting identity, malformed input, or receipt/event disagreement is a
typed degraded/quarantined condition, never inferred completion. ACKs are
stream-bound absolute monotonic watermarks and do not wait for downstream
projectors. Canonical events retain for the run in Stage B; the host prunes only
confirmed-ACKed outbox rows after a fixed replay grace.

**D3 — Initial transport.** The initial adapter is manager-consumed,
host-global SSE plus explicit acknowledgement over the existing local-direct
HTTP connection. It is an implementation of transport-neutral event-source,
acknowledgement, and runtime-object interfaces. Stage B adds neither a public
listener nor remote enrollment, mutual authentication, relay, WebSocket, or
object-storage deployment. A future trusted relay adapter must preserve these
wire semantics without changing the domain contracts.

**D4 — Epoch fencing and safety.** Every host event is associated with the
Stage A assignment ID and epoch. A stale event is retained as audit evidence
and can advance a host watermark but ordinarily receives no current run
sequence and cannot mutate lifecycle, cost, artifact, or prompt-owner state.
The narrow exception is a late terminal `session.command` event whose command
ID, kind, run, host, assignment, and epoch exactly match an accepted durable
command. It may settle only that historical command ledger entry; its receipt
cannot settle the command by itself, and it cannot mutate current run/session,
cost, artifact, HITL, or prompt-owner state. Host restart preserves its
stream/outbox and receipt ledger; manager restart resumes from durable
watermarks. Backpressure rejects new mutating admissions before data is
dropped, reserves terminal capacity, and surfaces typed reconciliation work.

**D5 — Prompt lifecycle.** `session.prompt` remains the existing Stage A
command and receipt identity. Canonical-mode admission returns an accepted
command/serializable `{commandId}` handle only after the host persists its
accepted receipt and event. Terminal outcomes are asynchronous events plus a
queryable receipt; the only prompt route is short-lived admission. Prompt
owners are typed, server-derived, and uniquely keyed. The
request digest binds a retry to identical canonical request bytes. Terminal
application is idempotent and reconciles only agreeing receipt/event evidence;
`turn_lost`, cancellation, checkpoint, session exit, duplicate delivery, and
acknowledgement loss all have explicit safe outcomes.

**D6 — Runtime objects.** Raw logs, transcripts, output/evidence bytes,
attachments, capability profiles/instructions, and agent-memory snapshots remain host files
when they are ACP runtime content. The manager owns only an opaque catalog and
metadata including association, kind, MIME, size, SHA-256, generation, state,
retention, and tombstone. Reserve/upload/read/range/delete contracts are
fenced, idempotent, bounded, and path-free. Manager-owned evaluation evidence,
inline/gate/HITL artifacts, and Flow-only state are not converted into host
objects. Git ranges, repository materialization, worktrees, checks, and
promotion stay Stage C.

**D7 — Compatibility and cutover.** B4 has one bounded historical-import
procedure. `execution-data-plane:import-legacy` is a phased operator CLI: its
`rows` phase imports events and cost facts under deterministic source identities
taken from the frozen manifest, and its `finalize-proof` phase writes all five
preservation-lane records. It does not flip a run mode. Migration `0135` first proves that every
legacy run has complete preservation lanes, then atomically flips every run to
`canonical_events_v1` and drops the legacy artifact cursor. Migration `0136`
allows only that mode. Migration `0169` (S4.7) is the writer floor the cut-over
leaves behind: the five-lane proof 0135 checked once becomes a permanent CHECK,
a proven lane is final, and the lane table accepts writes only from a session
that declares the `execution-ab-1` writer capability — every binary carrying
0169 declares it on connect, an older one is refused by class — while the web
boot and `db:check` refuse a database whose ledger is ahead of the binary's
journal. A missing source, malformed line, unproven association,
or changed fingerprint fails loudly; no reader/writer fallback remains.

**D8 — Trust and observability.** URL-selected run and artifact IDs are
authorized before server-derived assignment, host, session, object, and owner
IDs are used. Request body values are limited to their own object/command
boundary; raw paths, prompts, payload bodies, attachments, secrets,
environment values, and credentials never enter logs or browser events.
Structured metrics/logs report ingest lag, watermark, duplicates, gaps,
replay, reconnect, completion latency, stale fencing, object transfer,
storage, and reconciliation outcome.

**2026-09-22 amendment — Implemented (P0-6/P0-7).** The first as-built slice of
D8 exposes scheduler-clock truth and event-plane ingest/projection lag.
The host negotiates a cheap stream head/backlog block on `/health`; the manager
computes sequence distances from existing watermarks/cursors and persists a
bounded versioned observation in the existing `system_sweep` attempt summary.
Lag remains read-only observability and cannot degrade a stream or satisfy the
ADR-177 lost predicate. `/admin/scheduler` receives a first-class clock card and
`/admin/execution-host` composes host/stream/consumer/poison/worker/command
evidence. This amendment does not claim the remaining D8 duplicate, reconnect,
completion-latency, object-transfer or storage metrics are implemented.

**2026-09-23 amendment — Implemented (retirement tombstone guards).** The S2.11
tombstone could not be written for a settled prompt: the `0140` request trigger
and `request_v2_check`, and the `0141` evidence trigger and
`terminal_evidence_check`, predate retirement and forbade the compaction, so
the manager half threw after the host half had already retired and the pass
stopped behind that row. Migration `0176` exempts exactly one transition —
`retired_at` NULL → set, with `request_canonical_json`, `receipt_evidence`,
`result` and `last_error` becoming NULL — while identity, both digests, the
terminal event, state and `completed_at` stay frozen; a settled tombstone is
final afterwards. The tombstone contract is unchanged: identity, digests and
outcome disposition, never a replayable request. A manager compaction failure
is now contained to its row (`manager_compaction_failed`); the host half is
idempotent, so the next pass completes it.

**2026-09-23 amendment — D5: host evidence is an admissible settlement
authority (D4 flow-progression decoupling).** The host stream is one per host
and totally ordered, so a finished turn's terminal event queues behind other
runs' transcript chunks. Progression no longer waits for that queue:

- *Admission.* `applyCreateAck` (the single writer behind the live ACK, the
  owned-create replay, the W2 receipt fold and the lifecycle projector) inserts
  the exact incarnation as `created` in the ACK transaction under the
  assignment lock, and first retires every other open incarnation of the same
  logical session — lower epoch, or the same epoch with a different host
  session (`session_superseded`), because consecutive flow nodes reuse one
  session name on one assignment. The lifecycle projector transitions
  `created → active` (or `lost` for a current-assignment stale create), and
  `projectTerminal` refuses to move a `lost` row into `checkpointed`. Applying
  an acknowledgement asks whether the session the host made is still the
  owner's, not whether the owner may create one now (`lockCreateOwner`'s
  required `create | ack` check): a run or attempt paused for input still owns
  its session, so the pause never marks an admitted session `lost`. An unowned
  create's acknowledgement applies only while it is the newest unowned create of
  its session name on the assignment, so a late fold of an older create cannot
  retire the live successor. Prompt
  admission accepts `created | active` at every admission site; a timeout of
  the remaining fence wait is a typed yield on every path, never a run failure.
  A queued agent message deferred because its session was not yet admissible
  (`session_not_admissible`) is re-driven after the launch turn parks, by the
  existing parked-run arm of the agent continuation worker.
- *Settlement.* `reducePromptEvidence` stays the only terminal writer but
  takes two evidence feeds: the canonical event, and — for a `completed` v2
  receipt with an output manifest only — the turn's event span
  `[acceptedSequence, terminalSequence]` read from the host through the
  read-only `GET /runtime-events/span` and verified by the same checks as
  ingested rows. The route returns every retained envelope of the range and
  takes no `sourceCommandId` filter, because contiguity and source binding can
  only be proven over the whole range. A fast feed (direct binding of the
  receipt-named terminal event, or the host span) settles only a span with no
  `session.hook_trip`, `session.permission_request`, `session.exited` or
  `session.crashed` event, so the flow runner never loses a guardrail or
  permission signal it would have observed canonically. Settlement uses the
  host's terminal *event bytes* plus the receipt — never the receipt by itself
  (D4 holds). `execution_commands.settled_from` (`canonical | host_span`,
  immutable once written, migration `0177`) records the feed — a column, not a
  marker derived from timestamps, because ingest captures `now` before its
  transaction and a settlement committing inside it would read as canonical,
  and not a field of `receipt_evidence`, `result` or `application_error`, each of
  which an agreement check compares whole. A host-span row may hold a digest
  without `terminal_event_id` until the canonical event confirms it, so `0177`
  relaxes the `0141` CHECK for `settled_from = 'host_span'` and carries the
  evidence trigger forward with `settled_from` frozen once written. A command
  whose assignment was released settles its historical ledger entry only,
  exactly like a late canonical event; owner application follows the existing
  supersession rule. `execution_commands.host_span_verdict` (`busy | refused`,
  migration `0178`) records the answer of the latest host-span read that did not
  settle, cleared when a read claims the command; the ADR-177 stream-lost
  resolver crashes only on a recorded refusal. Owner application treats output
  still behind the canonical frontier with an unreadable span as late, not
  failed, while the stream is not lost, and counts it toward poisoning once the
  stream is lost.
- *Confirmation.* The canonical event later binds `terminal_event_id` and
  recomputes the same digest. A disagreement is recorded as the existing
  `prompt_terminal_conflict` quarantine: after application the applied outcome
  stands (post-hoc audit), before application the command is poisoned as
  today. The canonical log remains the observation authority; once the
  confirming event AGREES, dispatched prompts anchored before it are re-anchored
  to it so the transcript keeps host order — a disagreeing event moves nothing,
  and the comparison uses the database clock on both sides. Adapter checks that
  need the terminal event row defer instead of reading its absence as proof.
- *Watchdog.* `maxDurationMinutes` never kills an attempt whose newest owned
  prompt (any `flow_node_attempt` variant) finished on the host and still has a
  writer: settled with its owner able to apply it (`pending_application` /
  `applying`), or a `completed` receipt probe while the host's stream is alive.
  A poisoned, quarantined or lost turn, or a completed receipt on a lost stream,
  has no writer left and is killed — deferring it would leave a live-session or
  judge node with no bound, because the ADR-177 evidence arm covers only
  sessionless `ai_coding` / `orchestrator` nodes. The deferral is bounded by the
  owner, which applies or poisons, and by canonical ingest while the stream
  lives. It performs no settlement and no host call beyond that probe.

Scope limits: failed and fenced receipts settle canonically (no manifest, no
bounded span); scratch and agent owners still apply after their transcript /
lifecycle projectors by design (they defer, they do not fail). Implemented
2026-09-23 on `claude/flow-progression-host-decoupling-216849`.

**2026-09-25 amendment — D5: another command kind inside a prompt's span
(Implemented — [ADR-182](../decisions.md#adr-182-steering-a-running-agent-turn-as-a-durable-fenced-command)).**
`session.steer` joins the command kinds (a permission answer, a cancel) that
may appear inside a prompt's
`[acceptedSequence, terminalSequence]` span. Its rows are `session.command`
rows, which the span verifier already steps over; the output the steered agent
produces rides the parent's `sourceCommandId`, because the host stamps the
session's active prompt and a steer never changes it; and its evidence is its
own receipt and its own `session.command{kind: "session.steer"}` pair — the
parent's request digest, receipt and span are untouched. The parent link is the
steer's own payload (`parentCommandId`), echoed in its result or refusal
details, never a field of the parent's evidence.

**2026-09-25 amendment — Implemented 2026-09-26 (D2/D3 throughput: batched
ingest and ACK, a subscriber that pauses instead of closing).** D2's semantics are
unchanged — total order per `streamId`, contiguous-only ACK, harmless
duplicates and lost ACKs, ACK independent of projectors, and the order
commit → ACK → confirm. What moves is the granularity on both sides of the
wire.

- *Manager reader.* One pass still holds one claim per host stream. It reads
  the stream continuously into a buffer bounded by `4 × N` rows and 16 MiB of
  payload; when the buffer is full it stops reading the socket, which is how
  backpressure reaches the host. It never grows a second buffer.
- *Batches.* A batch is cut at the first of `N` rows
  (`MAISTER_EVENT_INGEST_BATCH_ROWS`, default 200, range 1–1000), 4 MiB of
  payload, 100 ms after the batch's first row was buffered, a `streamId`
  change (cut before the differing envelope), the end of the stream, or an
  abort. Each batch is one PostgreSQL transaction: one stream-row lock, the
  runs of the batch and of the first pending page locked once in ascending id
  order before any insert — `FOR NO KEY UPDATE`, the allocator's own lock, so a
  projector's foreign-key check on a run (`KEY SHARE`) never makes a batch
  wait — one multi-row insert, one contiguity walk that reads
  pending rows one 500-sequence window at a time (≤ 500 rows whatever plan the
  database picks), and exactly one stream-row write and one
  host-row write. Per-event ingest is a batch of one, so there is one write path
  and every per-row disposition equals what the per-event path gave the same
  input. A batch commits whole or not at all. A payload PostgreSQL refuses
  aborts the batch, which is re-run as single-envelope batches so the existing
  `payload_unstorable` quarantine skips only that envelope; a deadlock,
  serialization failure or connection reset is retried in place once and then
  handed to the reconnect path. An aborted pass discards its buffer; replay
  re-serves it.
- *ACK.* At most one ACK per committed batch, and only when the batch moved the
  contiguous watermark above the pass's last ACK. A trickling tail is
  acknowledged within 100 ms of arrival because a batch is cut at least that
  often; there is no second timer.
- *Lease and liveness.* The claim lease is renewed inside every batch
  transaction under the stream lock when the locked row still names this
  consumer. A miss still commits the batch — ingest is idempotent under the
  stream lock — and ends the pass as `claim_lost`. The consumer loop's liveness
  advances per committed batch and per confirmed ACK, so a pass that stays open
  under continuous load is never replaced as stalled; every batch commit also
  advances `last_seen_at`.
- *Reconnect cursor.* The cursor stays `last_contiguous_sequence`, exactly as
  D2 states ("replayed from that exact exclusive cursor"). The request that
  prompted this amendment proposed `last_received_sequence`; that cursor sits
  above any hole and would never re-fetch it. Frames still buffered at a cut are
  above the cursor, so they are re-served and deduplicated.
- *Host subscriber.* `GET /runtime-events` serves each connection from a pump:
  it pages the durable outbox after the cursor until an empty page, then goes
  live. A `write()` that returns `false` pauses the subscriber until `drain`
  and resumes from the last sequence written to the socket; the publisher never
  blocks on a subscriber and keeps no per-subscriber queue. The host no longer
  closes a connection on backpressure (`slow_client`) or at a page boundary
  (`replay_page`), and the 500-event pending cap is removed. A connection closes
  only for `disconnect` (the client went away), `floor` (a catch-up read fell
  below the replay floor), `protocol` (the stream was replaced or is corrupt, or
  a live event names another stream) or `shutdown`.
- *Operator evidence.* `GET /health?includeStream=true` adds
  `subscriberPauses` and `closes` by reason, counted since boot. The admin
  execution-host page and the `system_sweep` observation carry them. They are
  transport telemetry: no lag verdict, stall rule or lifecycle decision reads
  them.
- *Load gate (R20).* An opt-in harness runs the concurrency caps' worth of
  sessions (6 flow + 3 agent) on a real supervisor with no proxy in the path,
  at ~394 host rows/s (22 frames/s per session: one mock frame commits ~2
  rows, so the 10 frames/s floor alone carried only ~180 rows/s). It requires
  a flat host-to-manager lag no higher than `2N`, no more ACKs than batches, no
  server-ended stream close, and no host-span settlement. Measured on
  2026-09-26: before this amendment (`master`, per-event) the lag grew
  29 345 → 67 083 rows in three minutes with 203 server-ended closes, one ACK
  per event and no prompt finishing; with it, at the chosen defaults
  `N = 200, T = 100 ms`, the lag stayed 46–60 rows, one connection served the
  whole run with no close and no pause, 3 153 ACKs covered 129 943 events, and
  all nine prompts settled canonically. The sweep chose the defaults: the
  smallest `N` at 250 ms whose maximum lag stayed at or below `N` (50: 66,
  100: 110, 200: 122), then the smallest `T` at `N = 200` that did (100: 60,
  250: 122, 500: 214).
- *Run lock mode, found by R20.* The runs are locked `FOR NO KEY UPDATE`, not
  `FOR UPDATE`: with `FOR UPDATE` every batch waited for each projection
  transaction that had inserted a child row of one of its runs (its FK check
  holds `KEY SHARE`), and the first branch run's lag climbed to 1 165 rows
  while the projection backlog grew to ~2 400. `NO KEY UPDATE` still
  serializes the owner apply and the idle-resume CAS, so the lock-order control
  stays deadlock-free.

No table, column, index or migration changes on either store, and no error
code is added; the close reasons are health and log vocabulary. Normative
detail: [`execution-event-plane.md`](../system-analytics/execution-event-plane.md).

**Consequences:**

- The one-host compose deployment remains the default and gains no relay,
  enrollment, or operator dependency. The web tier can stop mounting the host
  runtime-data directory once B4 completes.
- Runtime event/cost files, file-tail browser SSE, path-bearing artifact reads,
  and `scratch_runs.supervisor_session_id` are removed manager authority; host
  files remain private implementation details only.
- Database migrations are additive for B0/B3 and destructive only after the
  B4 import/drain proof. Historical completed runs remain viewable from
  imported/canonical records.
- Stage C owns host-owned repositories/workspaces, multiple-host placement,
  Git/worktree/check/promotion movement, and cross-host recovery only at new
  attempt boundaries. Stage D owns remote-host enrollment/authentication,
  public relay, secret confinement, cloud, and object storage. Neither stage
  is implemented by this decision.

**Alternatives considered:**

- **Continue file polling and mount the runtime root in web:** rejected because
  it makes control-plane correctness depend on an execution-host filesystem.
- **Put execution events in `domain_events`:** rejected because its business
  trigger retention and project-scoped consumers are incompatible with stream
  ordering and host acknowledgement.
- **Use a remote relay in Stage B:** rejected because trusted enrollment and
  public-network authentication are a separate Stage D trust boundary.
- **Use a long-lived prompt HTTP response as durable completion:** rejected
  because it cannot survive web/network restarts or prove terminal ownership.
