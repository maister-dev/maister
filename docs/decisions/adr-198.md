# ADR-198: Incoming request qualification before delivery

[Back to ADR index](../decisions.md#adr-198-incoming-request-qualification-before-delivery)

**Date:** 2026-10-30
**Status:** Accepted

**Context:** Frequent operational execution currently exposes session failures as workspaces and per-run attention, while routing confidence does not establish request validity or safe replay.

**Decision:** Reuse task rows as Incoming carriers with a separate required qualification axis. Read current source at an immutable authorized commit. Assess clarity, consistency, evidence and relevance; unknown is not rejection. Stage agent candidates and publish only alongside clean validated operational success. Human decisions use explicit revisioned authority. Gate every independent delivery admission; preserve governed parent execution decomposition through server-owned provenance.

The contract is **Implemented**. Existing agent behavior remains explicit legacy until its scoped migration/capability boundary. Canonical state transitions, wire shapes, schema and acceptance belong to [the owning domain](../system-analytics/task-qualification.md), not this rationale.

**Consequences:** Platform/schema/MCP/UI deploy before compatible core and explicit project policy/pin changes. No automatic approval, promotion, blind side-effect replay or remote publication is introduced. Additive evidence survives cleanup and rollback; incompatible old writers stay fenced.

**Alternatives Considered:** Agent-ID exceptions, cosmetic Review filters, empty-diff promotion, prompt-only validation and a parallel workflow engine do not enforce the stated boundaries.

**Checks:** [Acceptance traceability](../system-analytics/agent-activity-traceability.md).
