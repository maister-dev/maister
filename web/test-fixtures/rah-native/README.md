# Governed evidence research / Исследование с проверяемыми источниками

This package supplies `rah-root-d1`, `rah-root-d2`, `rah-research` and the single-role `rah-control`. All export the native `evidence_findings_v1` contract. Engine 3.11.1 or newer is required. Company-owned knowledge needs no repository; these CB0 Flows use the existing project execution entry. Project-less company assignments require the separate company execution capability.

Install an immutable package revision through MAIster Settings → Packages, then review trust, attach it to the intended project and enable its agents/Flows. These are distinct operations: downloading or installing does not grant trust, enable execution or grant source access. Bind the `research` session to an installed Ready runner matching the `core-claude` intent (the standard `claude-code` platform runner); another supported runtime requires an explicit session binding. Research agents also need a Ready read-only-capable runner. This package contains no executable setup hooks and no credentials.

Grant only the required current company/project knowledge access to each receiving role. Enable the project attachment's Brain read permission for all three roles. Keep personal agent memory disabled. Pass the explicit company/project owner and exact record references in the request. A revoked grant or unknown source capture is a refusal; restoring an explicit grant is a new authorization decision, never a prompt instruction. Repository work follows normal project admission; physical shared workspaces are unsupported for native evidence runs.

Start with `rah-control`, then `rah-root-d1`, then `rah-root-d2`. Inspect exact result revisions and their evidence in the run view. Depth two uses intermediate `rah-research` Flow children and their researcher agents; the root only collects direct children. Budgets are absolute tree bounds, with at most two concurrent children. Child completion alone does not prove the requested conclusion. Missing, stale or conflicting evidence stays explicit, repeated use of one witness is not independent confirmation, and work acceptance never confirms a fact. Review proposed knowledge separately under the configured confirmation policy.

Root Flows can submit one evidence-linked proposal when the request explicitly asks for it and the coordinator has a current `knowledge:propose` grant. Reuse one stable idempotency key across uncertain responses or interruption. The control and intermediate research Flows cannot invoke proposal writes. Review and confirmation remain separate authorized actions. A pending child causes the coordinator to end its turn without a final result; the harness parks and resumes the same run. Keep existing child IDs after resumption and use no shell timers or polling loops.

Tool enforcement is strict and lists the required Brain/delegation calls explicitly. The Claude session uses the ask permission mode. Workspace read access is an instruction under the current platform contract; this package does not claim a filesystem sandbox. Shell and repository write tools are excluded from the strict Claude tool list. Engine 3.11.1 includes host-owned native tool arbitration; strict launch needs fresh capability smoke contract v2, including benign shell and read-only MCP probes.

For interrupted work, inspect retained run/attempt history and current source grants before continuing through existing recovery controls. An uncertain steering command requires receipt reconciliation. Do not create a replacement run to bypass a source refusal or blindly resend an unknown operation. This package has no restart/upgrade capability. Installing and parsing it does not establish live ACP or stand-pilot readiness; qualification records must identify the actual resolved package commit, schema hashes, runner and resulting run IDs.

## По-русски

Пакет содержит `rah-root-d1`, `rah-root-d2`, `rah-research` и контрольный процесс без делегирования `rah-control`. Все публикуют нативный контракт `evidence_findings_v1`; требуется движок 3.11.1 или новее. Знания компании не требуют репозитория. Процессы CB0 запускаются через существующий проектный контекст; назначения компании без проекта требуют отдельной возможности исполнения.

Установите неизменяемую ревизию через Настройки → Пакеты, отдельно проверьте доверие, подключите пакет к нужному проекту и включите агентов и процессы. Загрузка и установка не предоставляют доверие, разрешения или право исполнения. Привяжите сессию `research` к установленному готовому исполнителю, соответствующему `core-claude` (стандартный `claude-code`); другой поддерживаемый runtime требует явной привязки сессии. Исследователям также нужен готовый исполнитель с поддержкой режима только для чтения. Пакет не содержит исполняемых установочных хуков или учётных данных.

Предоставьте каждой принимающей роли только необходимые текущие права на знания компании или проекта. Включите чтение Brain у проектного подключения всех трёх ролей. Личную память агентов оставьте отключённой. Передавайте явного владельца и точные ссылки на записи. Отзыв прав или неизвестная классификация источников приводят к отказу; новые права предоставляются явным решением, а не инструкцией в запросе. Работа с репозиторием проходит обычный проектный допуск. Общие физические рабочие каталоги для нативных результатов не поддерживаются.

Проверьте сначала `rah-control`, затем `rah-root-d1` и `rah-root-d2`. В истории запуска просмотрите точные ревизии результатов и источники. На второй глубине промежуточные процессы `rah-research` делегируют исследователям, а корневой координатор собирает только непосредственных детей. Бюджеты действуют на дерево; одновременно разрешены не более двух детей. Завершение ребёнка не доказывает требуемый вывод. Недостающие, устаревшие и противоречащие свидетельства остаются явными. Повтор одной ссылки не создаёт независимого подтверждения. Приёмка работы не подтверждает факт; предложения знаний рассматриваются отдельно по действующей политике.

Корневые процессы могут отправить предложение со ссылками на свидетельства, если это явно запрошено и у координатора есть действующее право `knowledge:propose`. После прерывания или неопределённого ответа повторно используйте тот же ключ идемпотентности и то же содержимое. Контрольный и промежуточный исследовательский процессы не могут вызывать запись предложений. Рассмотрение и подтверждение фактов остаются отдельными действиями с собственными правами. Если дочерняя работа ещё не завершена, координатор заканчивает ход без итогового результата: harness приостанавливает и возобновляет тот же запуск. После возобновления используйте сохранённые идентификаторы детей, без shell-таймеров и циклов опроса.

Строгий контроль инструментов явно разрешает необходимые обращения к Brain и делегирование. Сессия Claude использует режим разрешений ask. Доступ к рабочей области на чтение является инструкцией в текущем контракте платформы; пакет не заявляет файловую изоляцию. Shell и инструменты записи в репозиторий исключены из строгого списка инструментов Claude. Движок 3.11.1 включает принудительную передачу нативных инструментов на проверку платформе. Строгий запуск требует свежей проверки capability smoke v2, включая безопасную shell-команду и MCP-вызов на чтение.

После прерывания проверьте историю попыток и текущие права перед продолжением через существующие средства восстановления. Неопределённая доставка управляющего сообщения требует сверки квитанции. Не создавайте новый запуск для обхода отказа и не повторяйте вслепую неизвестную операцию. Пакет не выполняет перезапуски или обновления. Установка и разбор пакета не доказывают готовность реального ACP или пилота обслуживания: свидетельства квалификации должны содержать точный commit пакета, хэши схем, исполнителя и идентификаторы запусков.
