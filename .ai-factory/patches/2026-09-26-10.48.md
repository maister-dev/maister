# ADR-182 steering review fixes: exactly-once was overclaimed, gates lived in the UI

**Date:** 2026-09-26 10:48
**Files:** web/lib/execution-host/{recovery,deliverer,steer-settlement,create-ack,client,owned-session-create}.ts, web/lib/scratch-runs/{service,state,dialog}.ts, web/app/api/scratch-runs/[runId]/{route,recover/route}.ts, web/components/scratch/{scratch-composer,scratch-conversation}.tsx, web/lib/agents/{turns,turn-claim,prompt-owner}.ts, web/lib/db/migrations/0180_agent_turn_steering.sql, supervisor/src/{http-api,acp-client}.ts, docs (ADR-166/167/182, execution-prompt-lifecycle, execution-hosts, scratch-runs, agents, supervisor, web/supervisor/operations OpenAPI, database-schema, scratch-run screen), CLAUDE.md
**Severity:** high

## Problem

A whole-branch review (seven reviewers, one of them a Codex adversarial pass) found that the steering feature broke its own central invariant and let some gates through:

1. After a manager death during the retry backoff, the recovery pass orphaned an already-attempted `session.steer` (ledger `queued`, `attempts > 0`) without reading its receipt. An injected message was then converted into a queued prompt and delivered twice.
2. The docs claimed "delivered exactly once" and "the only double delivery is a late adapter". The code converts a message after a definitive answer that follows an injection into a turn that then died: a fence after the adapter answered, `turn_lost`, a dead adapter, or a 503 before receipt replay.
3. The local-package assistant's idle-only gate existed only in the UI (`sendWhileBusy`). The generic scratch message route steered or queued into a busy assistant turn, and its dispatch skipped the ADR-097 teardown.
4. An unknown scratch steer outcome answered 503 after the row was committed. The operator resent, and scratch has no idempotency key.
5. A steer conversion folded by recovery never woke the scratch queue, which stranded a row in `WaitingForUser` with no crash involved.
6. Queued rows on an ended dialog kept a "Queued" badge forever. Recover sent its own message before older queued rows. `Starting` offered Send, but the server refused it with `PRECONDITION`. A stale delivery notice came back on the next dispatched turn.
7. The migration trigger's comment claimed it enforced parent binding, and it did not. The detail route leaked `steer_command_id`. `applyCreateAck` took `steeringSupported` as optional.

## Root Cause

- **Retry-state conflation.** The recovery pass treats `queued` as "never sent" (ADR-166 W1). The deliverer reuses `queued` for "attempted, retry pending" after an unknown outcome. That was harmless for kinds whose orphan is a plain failure, and wrong for the one kind whose orphan converts: it acts on the message.
- **Invariant stated at the wrong scope.** Exactly-once holds between the manager and a live host. It cannot hold across host or turn death without adapter-side dedupe. The ADR asserted the stronger property, and no reviewer enumerated the post-effect windows until an adversarial pass did.
- **Gate at the edge instead of the choke point.** D-D5 was implemented as a composer prop, but two routes reach `appendScratchUserMessage`.
- **An error returned after a durable commit.** The busy arm rethrew the unknown outcome, although its intent was already persisted.
- **Wake owned by the live wrapper only.** Settlement returned the fact "requeued", but only the live caller acted on it. The recovery caller discarded the settlement result.

## Solution

- Recovery claims an attempted `queued` steer back to `delivering` and folds its receipt; only a missing receipt orphans it. `settleInLedgerTx` returns the settlement, gates it on the ledger CAS having written, and wakes the scratch dispatcher after commit through a dynamic import, as in the precedent in `adoption.ts`. The live ack and refusal paths skip settlement when their CAS changed nothing.
- The owner chose at-least-once across a dead turn, recorded as EDGE-STR-09, together with an ADR-166 E-EH-11 amendment for the fenced conversion and a CLAUDE.md §1 note.
- `appendScratchUserMessage` refuses a busy project-less run on every route, and the dispatcher derives the assistant flag from the run. An unsettled busy steer answers `steered`.
- `Starting` left the busy set. `queuedMessageUnsendable()` drives a "Not sent" badge. Recover queues its own text behind rows left from before the crash (`queueScratchRecoverMessageBehind`). The notice resets when the dialog leaves `Running`.
- A closed agent run supersedes the successor (`CLOSES_MESSAGE_TURNS`, an exhaustive map shared with turn-claim).
- The supervisor serializes the steers of one session within one 30 s budget and re-checks after each wait. `steerTimeoutMs` is injectable for tests.
- The trigger binds a steer to its parent's assignment, incarnation and command. The migration was unmerged and never applied outside test containers; the dev DB was verified at 0178.
- The detail route projects the documented `ScratchMessage`. `applyCreateAck` requires `steeringSupported`, and the compiler then surfaced 8 call sites.

## Prevention

- When a kind's orphan path acts on the domain (converts, re-sends, supersedes), audit every producer of the state the orphan reads. `queued` meant two things here.
- State an exactly-once invariant with its scope: which process deaths it survives. Run the adversarial pass over the post-effect windows, and prefer "at most once converted, at least once across a dead turn" when there is no adapter-side dedupe.
- A gate a spec calls "idle-only" belongs in the service choke point every route funnels through. A UI prop is presentation only.
- After a durable intent commit, answer the accepted state. Do not return a transport error that invites a resend.
- When a settlement returns a "do this next" fact (requeued), every caller acts on it, not only the live one.
- A proxy barrier in a test must be scoped to its own run's session and released in `finally`. A second release of a disposed barrier throws: track handles, never release blindly in `afterEach`.
- A test that raises the run count needs the concurrency cap raised for its file. The scratch file silently hit the default cap of 6.
