# Prevent unresolved runner previews from becoming launch overrides

**Date:** 2026-07-07 11:08
**Scope:** `/aif-fix` review finding for graded runner resolution launch preview
**Files:**
- `web/app/api/runs/launch-options/route.ts`
- `web/app/api/runs/launch-options/__tests__/route.test.ts`
- `web/components/board/launch-popover.tsx`
- `web/components/board/__tests__/launch-popover.test.ts`

## Problem

The launch-options route treated any single-session preview failure as if it
were an implicit default-session resolution and replaced the unresolved session
with the platform default runner. For a declared runner slot whose required
`capability_agent` was absent, this could preselect a runner with the wrong
capability and cause the client to submit it as an ephemeral launch override.

## Fix

The preview resolution now records whether each logical session declared a
runner. A resolved declared session still selects its runner normally, including
soft mismatch warnings. An unresolved declared single session remains
`selectedRunnerId: null` so the launch POST does not hide the resolver failure
behind an override. Only an implicit default session may use the project/platform
default-chain fallback.

The client launch body builder now returns a sparse object and omits empty
runner/base/target branch fields instead of preserving keys with `undefined`
values.

The non-fatal preview catch logs structured task/project/flow/session context
plus the normalized error code/message so unresolved slot previews are visible
without exposing provider credentials.

## Regression Coverage

- Route regression: a single declared Claude session with only a Codex platform
  default returns `selectedRunnerId: null`, `selectedRunnerWarning: null`, and no
  synthetic session selector entry.
- Client regression: an empty runner selection does not create a `runnerId`
  property in the launch body.

## Lesson

Preview DTOs that catch domain resolver errors must carry enough provenance to
distinguish a resolvable implicit default from an unresolved declared contract.
Otherwise a display fallback can cross the request boundary and become a real
launch override.
