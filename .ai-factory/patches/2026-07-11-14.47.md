# ADR-129 capability enforcement: three seam-vs-adapter blockers found only by adversarial review

**Date:** 2026-07-11 14:47
**Files:** supervisor/src/{acp-client,types,spawn}.ts, supervisor/test/fixtures/mock-acp-guardrail.mjs, supervisor/src/__tests__/guardrail-interceptor.integration.test.ts, web/lib/flows/{enforcement-profile,enforcement-evidence}.ts, web/lib/flows/graph/runner-graph.ts, web/lib/services/runs.ts, web/lib/runs/{hook-trip,hook-trip-rule}.ts, web/lib/{agents/launch,flows/runner-agent,db/schema}.ts, web/lib/flows/__tests__/enforcement-profile.test.ts, web/lib/flows/__tests__/enforcement-evidence.test.ts
**Severity:** critical

## Problem

`/aif-review` on the ADR-129 branch found THREE blocking defects the implementation's own green test suite (web 6123 + supervisor 356/88 + e2e 3) was blind to — all three at the seam between the interceptor's assumptions and the REAL claude adapter / launch wiring:

1. **C1 — D5 always-ask sentinel halted every enforced session on its first write.** The sentinel matched `session/update` `sessionUpdate:"tool_call"` and halted if the id wasn't yet in `capabilityArbitratedToolCallIds` (populated only inside `requestPermission`). But `claude-agent-acp` (dist, `includePartialMessages:true`) STREAMS the pending `tool_call{kind:"edit",status:"pending"}` on `content_block_start` BEFORE it calls `requestPermission` from `canUseTool`. FIFO stream processing → the pending write is always seen un-arbitrated → halt, before capability_guard ever evaluated. Broke acceptance #1/#3 on the primary adapter.
2. **C2 — the skip-permissions evidence refusal was dead code.** Both production callers (`runner-graph.ts`, `services/runs.ts`) called `assertEnforcementEvidence({settings, agent})` WITHOUT `permissionPolicy`, so the `dangerously_skip_permissions` refusal branch never fired. A strict node on a skip-perms runner passed the gate, spawned, and ran with capability_guard inert (no `requestPermission` under skip-perms) → silent false-enforce (ADR-032 violation).
3. **C3 — an `enforcement.mcps:strict` orchestrator denied its own delegation.** The `maister` MCP facade is appended to `mcpServers` AFTER `deriveSessionEnforcementProfile` computed `mcps.allowServers`, so `mcp__maister__*` calls were denied → halt after N, with no author remedy.

## Root Cause

All three share ONE root cause class: **the interceptor/gate encoded an assumption about ordering or wiring that the mock never exercised, so the tests passed while production broke.**

- C1: the mock's `requestTool` emitted ONLY a `requestPermission` (never the real pending-`tool_call`→`requestPermission`→execution-`tool_call_update` triple). The sentinel's premise ("a write's id is arbitrated before its `tool_call` notification") is the inverse of the real adapter's streaming order. Nothing forced the mock to model the real order.
- C2: the unit test passed `permissionPolicy` explicitly (green), which MASKED that no caller did. A green test on the pure function is not evidence the callers wire it.
- C3: a system-injected value (the facade) was added to one delivered field (`mcpServers`) but not its dependent derived field (`enforcementProfile.mcps.allowServers`) — a derive-then-mutate-the-input ordering bug.

## Solution

- **C1:** the sentinel now tracks pending WRITE ids from the streamed `tool_call` (`capabilityPendingWriteIds`), REMOVES an id when it reaches `requestPermission` (arbitrated), and halts only when an EXECUTION `tool_call_update` (`status` completed|failed — the post-permission event) arrives for an id STILL pending. Replaced the write-only `capabilityArbitratedToolCallIds` with the single bounded `capabilityPendingWriteIds` set (also fixes the unbounded-set smell). The mock now models the real triple (`arbitratedWrite` = pending→permission→execution → no halt; `unarbitratedWrite` = pending→execution → halt), with a new `capability_arbitrated_write` scenario + a regression test asserting a legit write does NOT false-halt.
- **C2:** threaded the resolved runner's `permissionPolicy` into both callers, and made `permissionPolicy` a **required** param of `assertEnforcementEvidence` — a dropped caller is now a compile error, not a runtime hole (the strongest possible regression guard). Updated the 5 unit cases to pass `"default"`.
- **C3:** extracted `admitFacadeServer(profile, name)` and call it when appending the facade — the facade joins `allowServers` iff mcps is governed. 3 unit tests (admit / no-op-when-tools-only / idempotent).

Folded-in review suggestions: `haltRuleFromEvent` exhaustive mapper extracted to a PURE module `lib/runs/hook-trip-rule.ts` (kills the duplicated ternary in runner-agent + launch AND makes a future 4th halt-rule a compile error; the pure module also keeps working when tests mock the DB-heavy `hook-trip.ts`); documented the intentional tools-vs-mcps empty-allow asymmetry + a locking test; corrected the false "resume path reads the persisted profile" comments (it re-derives); clarified the deny-counter reset semantics (in-profile allow resets; ungoverned pass_through does not — anti-evasion).

## Prevention

- **A mock that doesn't model the real wire order proves nothing.** For any interceptor keyed on ACP event ordering, the fixture MUST emit the real adapter's event sequence (grep the bundled adapter `dist` for the emit order — `sessionUpdate:"tool_call"` `status:"pending"` streams BEFORE `requestPermission`; the execution signal is `tool_call_update` `status:"completed"`). Replay the real order, not the author's mental model.
- **A green unit test on a pure guard is not evidence its callers wire it.** When a guard takes a policy/param that gates a security refusal, make the param REQUIRED so a dropped caller fails typecheck; a test that passes the param explicitly masks the caller gap.
- **Derive-then-inject is an ordering bug generator.** When a value is appended to a delivered list AFTER a dependent field was derived from that list, update the dependent field in the same step (or derive after the append).
- **Adversarial multi-agent review earns its cost on seam/ordering bugs.** A single solo review pass (mine) rated all three SAFE/minor; independent reviewers blind to the implementation reasoning caught each. Run adversarial review on interceptor / launch-wiring / state-machine diffs specifically.
