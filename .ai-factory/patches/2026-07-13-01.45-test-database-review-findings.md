# Test database lifecycle review remediation

**Date:** 2026-07-13 01:45
**Scope:** Unified Testcontainers database helper review follow-up

## Problem

The helper could leave a disposable PostgreSQL container running when
`Pool.end()` failed. A Docker failure during container startup after a
successful runtime probe was also not converted to the documented typed error.
The analytics attributed E2E migration and seed work to the helper rather than
the E2E preparation command path.

## Root cause

Teardown awaited pool shutdown and container shutdown sequentially without a
failure-safe cleanup path. The Docker-boundary error mapping covered only the
preflight probe. The original analytics model did not distinguish wrapper,
helper, and preparation responsibilities.

## Solution

Added a shared cleanup routine that always attempts container shutdown after
pool shutdown and aggregates dual failures without hiding the operation error.
Container-start failures now use the same safe typed Docker error as probe
failures, and the probe timeout is cleared on every race outcome. Added a real
Docker regression that proves an already-closed pool cannot leave the
container reachable, plus a focused post-probe startup-error contract test.
Corrected the specification, plan, and analytics sequence/state model.

## Prevention

For lifecycle code, test a cleanup failure as well as the normal teardown path
and state explicitly which component performs each migration or seed action.
When a readiness probe precedes a resource operation, ensure later
runtime-bound failures preserve the same public error contract.
