# Fence coordinator rework before changing Git

**Date:** 2026-11-04 10:15
**Files:** `web/lib/flows/graph/runner-graph.ts`, its existing orchestrator-park integration suite, task-launch and orchestrator analytics
**Severity:** high

## Problem

A late accepted child kept its parent waiting at the final ledger boundary,
but non-keep rework had already rewound the checkout. The existing keep-policy
race could not detect lost commits, staged files or working-tree changes.

## Root Cause

The final parent-row fence protected node completion after Git effects. Both
reachable orchestrator workspace-policy paths performed those effects earlier.
A final database decision cannot compensate for an already changed workspace.

## Solution

Reuse one parent-serialized obligation check and credential-retirement operation
in a short committed transaction before either non-keep policy. Accepted work
parks without touching Git. After retirement, the old credential cannot accept
new child work. Git remains outside database transactions; all five node-closing
branches retain the same final fence. Existing failure and recovery policy stays
in force. The auto-retry workspace path is limited to ai_coding and CLI nodes.

## Validation

The actual Git RED in `/private/tmp/maister-parent-pre-git-fence-git-red.log`
lost HEAD, index and file changes before parking. Its corrected counterpart
preserves committed, staged, unstaged and untracked state. The opposite ordering
refuses the actual retired credential with 401 and no accepted intent, proves
an independent parent row lock succeeds while Git is paused, then completes
the real rewind and a valid next turn.

All three owning integration suites pass 51/51 with normal database cleanup:
`/private/tmp/maister-parent-pre-git-owners-qualified.log`. These use real
PostgreSQL/Git and controlled provider responses. Final rebased browser and full
integration qualification remain pending.

## Prevention

Trace every workspace effect before its final status write. A late guard must
also precede destructive effects. Test observable Git state with a non-keep
policy and both transaction orderings; a keep-policy race proves less.
