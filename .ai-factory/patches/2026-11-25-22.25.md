**Severity:** high

## Problem

An independent second review of the branch caught three blocking defects and several DRY/contract gaps introduced during the first review-remediation commit (`28464e9a2`):

1. **Red unit test in `run-diff.test.ts:734`:** `prepareDiff` was updated to downgrade single files exceeding `maxLineToIgnoreSyntax` (`2,000` lines) individually without consuming the shared `8,000`-line budget, and `prepare.test.ts` was updated, but `run-diff.test.ts` still used a single `8,000`-line file to exhaust the budget and therefore failed expecting `"plaintext"`.
2. **Two ESLint React Compiler errors:** `use-run-stream.ts` added synchronous `setState` resets inside `useEffect` (dropping `master`'s `eslint-disable` without replacing the pattern), and `use-run-stream-visibility.dom.test.ts` mutated a module-level `let latest` variable during render.
3. **Spec drift & duplicated classifiers/producers:** `workbench.md` and the plan omitted the per-file `2,000`-line rule and rewrote unrelated `## Expectations` bullets; governed-run SQL was hand-copied in `/stream` and `/peek/stream` instead of exported from `knowledge-run-disclosure.ts`; diff-cache entry assembly was copied across 3 producers with no cross-producer parity test; trailing debounces remained in `git-panel.tsx` and `study-lab.tsx`; and `TaskLaunchIntentStatus` duplicated the live pill beside `StatusBar`.

## Root Cause

1. **Scoped test re-runs missed a sibling consumer of a behavior change:** After changing `prepareDiff`'s per-file cap semantics in Track F2, only `lib/diff/__tests__/` was re-run instead of grepping all callers of `MAX_TOTAL_SYNTAX_LINES` (which would have immediately caught `components/workbench/__tests__/run-diff.test.ts`).
2. **Hook rewrite used imperative effect resets instead of render-derived keyed state:** Resetting 5 state atoms synchronously in `useEffect` violated `react-hooks/set-state-in-effect`, and assigning an outer variable in a test harness component violated `react-hooks/globals`.
3. **Copy-paste across adjacent boundaries:** Re-implementing SQL predicates (`runGovernedSql`), cache entry builders, `visibilitychange` handlers, and `createCoalescedRefresher` boilerplate instead of exporting a single source of truth created drift hazards.
4. **Blanket verification claims without full-lane execution:** Marking Task 4.1 complete without running the full `test:unit` lane and recording exact measurements masked the red test and left benchmark claims unverifiable.

## Solution

- **Fixed red test & aligned specs:** Rebuilt `run-diff.test.ts`'s fixture with `4 × 2,000`-line files plus `src/trailing.ts`, split `prepare.ts`'s info log into per-file cap vs shared budget messages, and aligned `workbench.md`, `web.openapi.yaml`, and the plan (restoring `master`'s 12 untouched `workbench.md` expectations verbatim).
- **Eliminated React Compiler violations cleanly:** Refactored `use-run-stream.ts` to keyed `RunStreamState` derived during render (zero synchronous `setState` in `useEffect`, zero `eslint-disable`), and reported snapshots via `useEffect` in `use-run-stream-visibility.dom.test.ts`.
- **Unified shared abstractions & swept siblings:**
  - Exported `runHasPrivateMemorySql`, `runKnowledgeEnrolledSql`, and `runDisclosureGovernedSql` from `knowledge-run-disclosure.ts` and adopted them in `/stream` and `/peek/stream`.
  - Exported `enrichCachedDiffFiles` and `buildPreparedDiffCacheEntry` from `lib/diff/cache.ts`, replaced all 3 producers (`diff/route.ts` ×2 + `runs/[runId]/layout.tsx`), and added cross-producer parity tests.
  - Removed the dead `DiffPrepResult` compat branch from `review-comments/anchor.ts`.
  - Extracted `lib/sse-visibility.ts` (adopted in 4 visibility-pausing SSE hooks/providers) and `lib/runs/use-coalesced-refresh.ts` (adopted in all 7 SSE-driven refresh components including the remaining `git-panel.tsx` and `study-lab.tsx` siblings); renamed `CHANGE_SUMMARY_REFRESH_DEBOUNCE_MS` → `CHANGE_SUMMARY_REFRESH_COALESCE_MS`.
  - Exposed `isShared` from `useSharedAttentionStream` so `TaskLaunchIntentStatus` suppresses the duplicate live pill when shared while keeping inline reconnect UI on disconnect.
  - Added direct `getEventListeners(..., "abort")` assertions on abort and `reader.cancel()` in `attention/stream/route.integration.test.ts`.
  - Refined OpenAPI/AsyncAPI/analytics wording (`at least once every 2,500 ms`, `active-user account status`, `replay` schema, `0369` semantics, `32 MiB` serialized-JSON budget, `retain: false` visibility scope), stripped plan IDs from code/test comments, and recorded real full-suite + benchmark numbers in Task 4.1.

## Prevention

- Whenever modifying a constant's or algorithm's semantics (`MAX_TOTAL_SYNTAX_LINES`, governed-run classification, cache entry format), grep EVERY consumer across the entire workspace and run the **full** `test:unit` lane before declaring a fix batch done.
- Prefer render-derived keyed state (`state.key === currentKey ? state : initial(currentKey)`) over synchronous `setState` in `useEffect`, and report test harness values inside `useEffect` rather than mutating module variables during render.
- Export security predicates and cache-entry builders from their owning module rather than duplicating them in route/layout callers, and add a cross-producer test whenever two entry points share a cache key.
- Keep `docs/system-analytics/` edits strictly surgical (never rewrite unrelated `## Expectations` bullets) and record exact command outputs and measured benchmark numbers before checking off verification tasks.
