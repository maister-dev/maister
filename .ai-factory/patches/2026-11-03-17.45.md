# Consume accepted consensus roles and migrate fixtures through real admission

**Date:** 2026-11-03 17:45
**Files:** web/lib/flows/graph/consensus/{roles,drafts,admission,runtime}.ts; web/lib/flows/graph/consensus/**tests**/{task-admission.integration,runtime,drafts,roles}.test.ts; web/lib/flows/graph/**tests**/consensus-prompt-owners.integration.test.ts; supervisor/test/fixtures/mock-acp-lifecycle.mjs
**Severity:** high

## Problem

A parent accepted runner A, but a later consensus role lookup selected B after
the live binding changed. The original 23-case command-owner suite also seeded
task-bound Running parents without an admission/input witness, so the stricter
child admission correctly refused them.

## Root Cause

Acceptance already stored `consensus:<node>:<role>` runner snapshots, but draft,
proof, verifier and synthesizer readers resolved live bindings/defaults again.
The old integration seed assumed task association implied authority. Recovery
faults were injected by changing a pinned Flow prompt between traversals, which
contradicted the newly enforced immutable launch contract.

## Solution

Use one parent-bound reader of the original immutable intent (or guarded child
parent proof), requiring the exact frozen slot and resolution tier. Check the
selected runner's current enablement, readiness and complete configuration
digest; refuse drift without choosing another runner. Keep explicit no-intent
legacy resolution separate.

All 23 command-owner cases now accept and bind real intents. Ordinary cases use
the opaque session principal; scheduled cases claim an actual cron occurrence
and use the package-pinned agent producer with current accepted qualification.
Recover receives current opaque user authority. Incomplete/empty synthesis
faults come from a bounded, strictly parsed response file inside the controlled
ACP fixture root, leaving accepted inputs and Flow definitions unchanged.

The real scheduled fixture exposed the identical package/scheduled revision
conflict; the shared engine's equality-only correction is covered by all three
scheduled propagation cases. No historical run or assessment was rewritten.

## Prevention

- Consume frozen selections at every execution reader, not merely acceptance.
- Require the parent identity in each reader so omitted call sites fail typing.
- Correct shared-function consumers to satisfy real admission; do not weaken
  the gate or invent a fixture admission snapshot.
- Inject provider failures at the controlled provider boundary. Mutating an
  accepted definition tests a different contract.
- Preserve complete consumer scenarios and their original behavioral checks.
