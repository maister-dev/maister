# Keep browser fixtures compatible with current admission guards

**Date:** 2026-11-03 Europe/Moscow
**Files:** `web/e2e/_seed/db.ts`, standalone seed/global setup and direct-pool browser consumers, `web/e2e/workbench-git.spec.ts`
**Severity:** medium

## Problem and established cause

The first frozen browser wrapper stopped before any browser assertion: its standalone PostgreSQL seeder had no current writer declaration (`task_launch_writer_capability`, SQLSTATE 23514). Its activity-feed fixture then exposed missing explicit flag provenance under `tasks_triage_flag_origin_check`. These are fixture incompatibilities with the new schema, not reproduced production failures or a reason to relax either guard.

The existing Git workflow also matched hidden and visible Run surfaces through a global test ID. The original journey passed only on retry; the retries-disabled run reproduced a strict-locator failure, including the Git-panel control.

## Solution

Every direct E2E pool now uses one constructor with startup options derived from the actual writer-capability constants. The activity fixture records its genuine explicit hold instead of fabricating qualification or omitting provenance. The Git workflow scopes status and controls to the visible Run shell, following the existing child-peek test convention; all delivery assertions remain intact.

## Verification and prevention

The actual wrapper now migrates and seeds its disposable database, opens the real browser, commits/publishes through a temporary bare repository, opens one controlled fake-GitHub PR and finalizes the Run. Both auth and the Git journey pass with `--retries=0` (`/tmp/maister-e2e-workbench-visible-shell-qualified.log`). Scope lint and Web types pass. No live GitHub or paid model was used; the wrapper retired its owned processes/database with zero leaks.

Class sweep:

```text
rg -n 'new Pool\(' web/e2e --glob '*.ts'

```

Use the current capability declaration at every connection boundary, not a hardcoded historic floor. Keep new fixture holds explicit. A browser assertion must select the actual visible product surface without relying on a retry, arbitrary first match or a longer timeout.
