# Preserve finite delegated grants across internal token rotation

**Date:** 2026-11-04 09:50
**Files:** machine token issuance/revocation/verification, managed-token classifiers and list projections, accepted delegated-source validation, token/service integration tests and direct minter fixtures
**Severity:** high

## Problem

An orchestrator can accept a finite child request before its next turn replaces
the private credential. Treating that internal replacement as repudiation loses
the accepted decision. Treating every old credential as live instead would let
an in-flight principal create fresh requests after rotation or cancellation.
Mutable display names cannot distinguish those authorities safely.

## Root Cause

Machine Run binding came from reserved display names, and the token store only
recorded a revocation timestamp. Fresh acceptance and accepted-source dispatch
used the same live-credential validator. Managed-token edit/list boundaries also
classified orchestrator credentials by display name alone.

The real PostgreSQL minter RED observed no immutable binding on the issued row:
`/tmp/maister-delegation-token-binding-red.log`. A second behavioral RED renamed
a real stamped credential and demonstrated that the old managed-token predicate
allowed editing it: `/tmp/maister-stamped-token-management-red.log`.

## Solution

Machine INSERTs stamp an immutable Run/project origin. Internal orchestrator
replacement records `rotation`; explicit revocation retires every existing
generation of the exact stored family while preserving first retirement times.
Legacy rows receive no inferred origin or rotation grant. The known legacy
private credential is conservatively retired during replacement using its exact
private identity tuple; unrelated same-name peers remain unchanged.

Presented revoked secrets always fail live verification. An accepted-only
validator reloads one exact stored intent and frozen source, then rechecks its
original token, current grants, expiry, parent and child proof. Its rotation
exception returns no reusable launch principal. New keys and source constructors
remain live-only, including a stale pre-rotation principal after cancellation.

Managed-token editability and SQL list filters exclude positive machine origins
independently of display name. No origin or revocation metadata enters token DTOs.
The additive PostgreSQL migration and its guards are owned by the combined
queued-child-obligation phase; historical rows and receipts remain unchanged.

## Prevention

Model fresh authorization separately from a finite accepted obligation. Bind a
dispatch exception to its exact stored decision rather than an optional flag or
a search for another matching intent. Sweep issuance, verification, revocation,
management classifiers and SQL projections together when adding private identity.
Minter tests must create the actual matching live Run; negative terminal-state
tests should mint first and then terminalize, preserving the original assertion.
