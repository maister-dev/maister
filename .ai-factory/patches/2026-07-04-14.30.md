# Allow disabling removed Brain sources

**Date:** 2026-07-04 14:30
**Files:** web/lib/brain/sources.ts, web/lib/brain/__tests__/sources.integration.test.ts
**Severity:** medium

## Problem

A Project Brain source could not be soft-disabled after its tracked file was
removed from the project's main branch. `updateBrainSource(..., { enabled:
false })` still attempted to read the current source contents and failed with
`PRECONDITION` before updating the `enabled` flag.

## Root Cause

`updateBrainSource` treated every patch as an indexable source edit. The
readability check was correct for enabled sources and source-shape edits, but
it was too broad for a metadata-only disable operation. That made the recovery
control depend on the broken file still being readable.

## Solution

Added a focused predicate that keeps readability validation for enabled sources
and for path/kind/chunker edits, while allowing pure `enabled: false` updates
to skip the content read. The skipped-read path logs structured context through
the existing `brain:sources` logger. Added an integration regression test that
registers a source, removes it from the tracked Git ref, and then disables it
successfully.

## Prevention

- Review soft-disable and kill-switch operations as recovery paths; they should
  not require the broken dependency they are disabling.
- Keep tests for broken-resource recovery separate from happy-path disable
  tests against still-valid resources.
- When changing validation predicates, cover the branch where validation is
  intentionally skipped and the branch where it remains required.
