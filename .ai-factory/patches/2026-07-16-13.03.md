# Stable next-intl test fixture prevents render-loop OOM

**Date:** 2026-07-16 13:03 MSK
**Files:** web/components/studio/__tests__/upstream-divergence-drawer.dom.test.ts
**Severity:** high

## Problem

The four-test `UpstreamDivergenceDrawer` DOM file never completed. Its Vitest
worker reached roughly 4 GB heap and exited OOM before any test body recorded
runtime, which also prevented the full unit suite from completing.

## Root Cause

The test's `next-intl` mock returned a fresh translator function on every
render. The drawer includes the API-error translator in a `useCallback`
dependency array and invokes that callback from an effect. Each state update
therefore produced a new translator, a new callback, and another effect run,
creating an unbounded render/fetch loop.

The real `use-intl` implementation memoizes the translator while its context
inputs remain stable. The production component was correct; the mounted test
fixture did not model the dependency's identity contract.

## Solution

Changed the test-only mock to cache one translator per namespace inside the
hoisted mock factory. Existing mounted tests now also assert one initial fetch
and exactly one additional fetch after selecting a cut.

The focused file completes all four tests in about 30 ms, the Studio slice
passes 71 tests, and the full web unit suite passes 6601 tests without heap,
pool, skip, or unhandled-error overrides.

## Prevention

- Mocks for hook-returned functions used in effect or callback dependencies
  must preserve the real hook's stable identity contract.
- Mounted React tests that load on effect should assert exact side-effect
  counts, not only that an expected call occurred.
- When a worker OOMs before test runtime begins, inspect render/effect identity
  feedback loops before changing worker or heap settings.
