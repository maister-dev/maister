# Scheduler-clock / event-lag review remediation: readiness coupling, lag verdict, per-panel degradation

**Date:** 2026-09-22 20:56
**Files:** `supervisor/src/{http-api,types}.ts`, `supervisor/src/__tests__/runtime-event-outbox.integration.test.ts`, `web/lib/supervisor-client.ts`, `web/lib/execution-host/{admin-status.ts,transports/local-direct.ts,events/{lag,lag-observation,lag-read-model}.ts}`, `web/lib/scheduler/{tick-service,timer,clock-health,jobs}.ts`, `web/lib/queries/scheduler.ts`, `web/lib/instance-config.ts`, `web/instrumentation-node.ts`, `web/components/{admin/*,chrome/*}`, `web/messages/{en,ru}.json`, `web/lib/db/{schema.ts,migrations/0174_poisoned_consumer_lookup.sql}`, docs (`adr-060`, `scheduler.md`, `execution-event-plane.md`, `execution-hosts.md`, `error-taxonomy.md`, `supervisor.openapi.yaml`, screens)
**Severity:** high

## Problem

A whole-branch review of `codex/scheduler-clock-ingest-lag` found seven
merge-blocking defects. The two that mattered most were availability lies:

1. A **telemetry** fault refused **launches**. `checkSupervisorHealth` always
   asked for `/health?includeStream=true`; the supervisor turned any
   `runtimeEventHealthSnapshot()` throw into `503 EXECUTOR_UNAVAILABLE` with
   `details.reason: runtime_storage_unavailable`; the web mapped every non-2xx
   to `kind: "unavailable"`, and the registrar called `markUnavailable`. A
   corrupt event-stream COUNTER therefore stopped every launch, while the
   daemon and SQLite were both fine.
2. The healthy steady state reported `unknown`. `lag.status` was `unknown`
   whenever `oldestUnacknowledgedAgeMs === null`, and the schema forces null
   exactly at zero backlog — so a fully-acknowledged host could never read
   `clear`. No test covered count 0 (the suite used 3 and 101).

Plus: the admin page parsed search params before authorizing; `Promise.all`
made a collector timeout fail the entire diagnostics page (the condition the
page exists to diagnose); the rail pill's role gating disagreed with itself
across rail states; ADR-060 still documented the pre-change timer default; and
several plan acceptance items were marked done with no executed evidence.

## Root Cause

The recurring cause is **one signal serving two audiences**. `/health` answers
both "can this host accept work?" and "how far behind is its event stream?",
and the code never separated them: one request, one status code, one failure
mode. Once the two were fused, an optional telemetry block could veto
admission, and the only honest value for "nothing outstanding" (a null age)
collided with the value used for "the host told us nothing".

Two secondary causes:

- **Fail-closed applied to a diagnostic surface.** `Promise.all` and the
  `diagnosticCount > 0 -> unavailable` projection rule both treat partial
  evidence as no evidence. On a page whose purpose is to show a degraded
  plane, that erases exactly the data an operator came for — and the
  projection rule made an open lag incident permanently unrecoverable, since
  the lane it needed to clear was blanked by one inconsistent cursor.
- **Tests written to pass rather than to discriminate.** `lagAgeMs: 0`
  disabled the age predicate in the only real-store sequence; the migration
  EXPLAINed a hand-written lookalike instead of the production CTE; the
  "reconcile failed" case asserted a null impasse that was really a TypeError
  on an undefined model; and a hand-copied "baseline parser" omitted the
  `host` field, so the backward-compatibility claim was never tested.

## Solution

- **Readiness decoupled structurally, not by retry.** `includeStream` is now a
  parameter and defaults OFF. `transport.health()` (registrar, prompt output,
  stream identity) never requests the block, so a telemetry fault cannot reach
  admission; only `platformStatus()` (pill, lag collector) opts in. The
  supervisor keeps its typed 503 — plan D5 forbids omitting the block to
  impersonate an older host — but no longer claims storage needs repair for a
  telemetry fault: the new `stream_health_unavailable` reason separates them.
- `lag.status` is `unknown` only when the host reported no block at all.
- The admin read authorizes BEFORE parsing input (it now takes raw
  `searchParams`), and composes its three panels with independent settlement,
  so a collector timeout degrades one panel.
- The projection lane is measured over the consumers that report cleanly; only
  a host whose consumers are ALL diagnostic reports `unavailable`.
- `loadPreviousSchedulerAttempt` is wrapped: a telemetry read on the recovery
  path can no longer fail the attempt and count toward `disabled_at`.
- The overlap-settled INFO reports the invocation the timer itself ran
  (`runSchedulerTick` hands the caller its own completion) instead of the
  process-wide last completion, which a concurrent cron tick can own.
- `MAISTER_SCHEDULER_TIMER_ENABLED` is validated at boot beside the lag
  threshold, before the durable workers start.
- Performance: the `node_attempts` probe moved AFTER the ranking cut (2025
  loops -> 21, measured), and migration 0174 adds the missing partial index for
  the poisoned-consumer count/page.

## Prevention

- **A readiness probe must not request optional telemetry.** When one endpoint
  serves both admission and diagnostics, split the REQUEST, not just the
  response handling — a shared request means a shared failure mode no amount
  of downstream classification can undo.
- **Never let one value mean both "zero" and "unknown".** If a field is null
  both when a thing is absent and when it is empty, the verdict derived from
  it is wrong in one of those cases; the test suite must contain the empty
  case explicitly.
- **Diagnostic surfaces degrade per panel.** Any page whose job is to show a
  broken subsystem composes its reads with independent settlement.
- **Falsify every regression guard.** Each guard added here was run against
  the unfixed code and observed to fail: zero-backlog -> `clear`; the readiness
  split; the D1 core-row predicate; the node_attempts loop bound (2025 vs 21);
  the RU English-copy check; the real age gate; and the degenerate
  system-sweeps fixture. A guard that was not observed failing is a claim.
- **`next dev` is not production for authorization.** `forbidden()` +
  `experimental.authInterrupts` renders the boundary but answers **200** on a
  production build; the literal 403 comes from the proxy rewrite. A "remove
  the duplicate 403 mechanism" simplification was attempted, caught by the new
  production case, and reverted — the two mechanisms are not redundant. Any
  403/401 contract needs at least one case on a real build.
- **EXPLAIN the query production runs.** The builder is now exported and used
  by both, so the index proof cannot drift from the caller.
