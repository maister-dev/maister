# Plan-review capture, recovery, and parent-surface corrections

**Date:** 2026-07-14 22:10
**Files:** `web/lib/flows/graph/runner-graph.ts`, `web/lib/services/hitl.ts`, `web/lib/queries/run.ts`, Plan-review tests and release-contract documentation
**Severity:** critical

## Problem

The Plan-review graph captured output from the review node's rework target
instead of from the node that transitions into the review. In the released AIF
topology, `improve` produces the artifacts while the review reworks to `plan`,
so a run could fail before opening the human gate. Recovery also scanned the
oldest answered human rows before filtering for live Plan-review parents, which
allowed historical rows to consume its limit. Run detail could place a decision
child ahead of its parent and consequently hide the parent's gate chat.

## Root Cause

The capture helper traversed the reverse transition relation from the review
node, assuming the requested producer id was the rework target. The recovery
query relied on later per-row validation after applying a global limit. The run
detail query sorted every open request by creation time without applying the
parent/child ownership rule needed by the response surface.

## Solution

The capture helper now looks up the requested producer and verifies its direct
transition to the configured review. Recovery joins the run and source artifact
and filters for a pending, current-step, current-artifact, typed Plan-review
parent before deterministic batching. Run detail promotes Plan-review parents
ahead of their children. Release
documentation and dogfood configuration name the verified package tags and
commits. Targeted unit, Docker-backed integration, and authenticated browser
coverage exercise the producer topology, historical-row starvation, Inbox
response, gate chat, and final rework handoff.

## Prevention

- For transition-derived behavior, test a topology where the forward producer
  and rework target differ.
- Apply eligibility predicates before a bounded recovery query, not only in a
  post-query validator.
- Preserve parent-first ordering wherever a parent owns the only full HITL
  surface.
- Record external package tag and commit evidence when marking a release task
  complete.
