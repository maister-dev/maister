# Confirm Git retirement and retain the first cleanup limit

**Date:** 2026-11-21 19:04 MSK
**Files:** `web/lib/project-config-persistence/git-process.ts`, `web/lib/gc/operational-disposition.ts`, `web/lib/agents/operational-diagnostics.ts`, `web/components/runs/run-peek-content.tsx` and their tests and contracts
**Severity:** high

## Problem

The direct Git timeout could reject while its child was still active. A cleanup limit could be replaced by a later archive scan or disappear after a separate preservation failure. Run Peek hid integrity guidance on its default Conversation tab.

## Root Cause

`execFile` reports an abort when it sends SIGTERM. Workbench callers rely on the Git promise settling after the child is finished. Cleanup wrote only the last thrown error, even though verification had already returned a measured limit. Peek rendered authorized guidance inside its Execution tab.

## Solution

Wait for direct Git child closure before returning the typed timeout and escalate if the child remains active after the grace period. Retain the first observed limit in the cleanup attempt and the final preservation error on the same receipt. Clear the measurement on a new attempt or successful release. Reuse the same notices above the Peek tabs.

## Prevention

Use process exit as the assertion in timeout tests. Force a secondary failure after a real measured limit and reload the authorized receipt. Test the initial UI tab and a tab switch to catch duplicated or hidden guidance.
