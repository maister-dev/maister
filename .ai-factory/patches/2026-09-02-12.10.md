**Severity:** critical

## Problem

`/codex:adversarial-review` on `claude/flow-target-delegation-178968` returned four
findings; all four were verified in source before any edit (four Explore agents +
own reads of the decisive lines):

1. **Stop became delivery.** An operator stop of an as-plan flow child emitted a
   `run.review` byte-identical to graph completion; `auto_launch_run_plan` then
   `local_merge`d the half-done diff. The ADR-126 lane evaluator excludes every
   delegated child and the readiness gate is vacuous for an early stop, so
   nothing else stood in the way.
2. **Nested cancel leaked sessions.** `cascadeAbandonRunTree` flips rows only, and
   FOUR callers (operator stop, drop, the delegated `run_cancel`, the abandon
   route) discarded its `cascadedRunIds`; a grandchild kept spending and mutating
   its worktree under an `Abandoned` row that no `Running`-only sweep revisits.
3. **A dead DAG reported as accepted.** `run_plan`'s post-commit source launch
   swallowed every refusal into a 202 whose row was indistinguishable from a
   blocked dependent; nothing retried a sole failed source, and — worse than the
   reviewer said — the parent, counting zero child RUNS, completed its node over
   the dead DAG instead of parking.
4. **Provenance drift.** The flow snapshot's revision fields came from the route's
   resolve while `runs.flow_revision_id` came from the launcher's later resolve;
   a repoint of `flows.enabled_revision_id` in between (an admin enable, or a
   concurrent launch's package-version choice) split the two.

## Root Cause

- (1) The emit helper had exactly one job — wake the parent — and every Review
  flip was routed through it (a previous review fix), so the consumer inherited a
  population it could not distinguish: the payload carried no *cause*. Adding
  emitters to a shared helper widened the consumer's semantics silently.
- (2) A result field (`cascadedRunIds`) that only ONE of seven callers consumed.
  The composition "cascade + tear down sessions" lived in the two callers that
  needed it first (budget path, delegate compensation) as copy-paste; the four
  later callers took the rows and forgot the sessions. There was also no recovery
  path for the crash window between the cascade commit and the teardown.
- (3) A "must not roll back the committed DAG" comment written for the partial
  case was applied to the total case, and the park decision counts run rows, so
  the failure was invisible to the one mechanism that would have caught it.
- (4) D7 had already made the launcher own the branch pair for exactly this
  reason ("the snapshot and `workspaces` can never disagree") — the same
  reasoning was not applied to the revision triple three lines above it.

## Solution

- (1) `RUN_REVIEW_CAUSES` (`graph_completed | agent_exit | operator_stop |
  rework_released | sync_returned`) and a **required** `cause` on
  `ReviewFlipRow` (compile-time coverage of every writer; the agent finalizer's
  literal stamps `agent_exit`); `auto_launch_run_plan` auto-promotes only the two
  completion causes and is fail-closed for a missing one. The wake path is
  untouched (Q1-A holds).
- (2) One composition, `cascadeAbandonRunTreeAndStopSessions` (cascade.ts), used by
  ALL seven tree-cancelling callers; `teardownLiveSessionsForRuns` stops EVERY live
  session of a run and tolerates a `listSessions` failure; the reconcile tick
  reaps a live session under an `Abandoned` row (`orphanSessionsReaped`,
  allow-listed to that one status) as the crash-window recovery path.
- (3) A partial refusal carries `launchError` on its result row plus the
  release-time system comment (`noteAsPlanRefusal`, moved to
  `lib/orchestrator/as-plan-refusal.ts`); when EVERY source is refused the
  committed DAG is abandoned (`abandonUnlaunchedTasks`, parity with
  `run_delegate`) and the call answers the refusal's code, `PRECONDITION` when the
  codes mix. OpenAPI (`ExtRunPlanResultItem.launchError`, truthful 202/503 text)
  and the MCP description follow.
- (4) `launchRunStaged` overrides `flowRevisionId` / `resolvedRevision` /
  `engineMin` / `engineMax` from the revision it selected, exactly like the branch
  pair; `FlowDelegationSnapshotInput` and the builder no longer carry them.

## Prevention

- A payload consumed by a decision-making consumer needs a **discriminant for
  the cause**, not just the fact; when a shared emit helper gains writers, ask what
  every consumer will now DO with the new population.
- A function whose result carries "what you must do next" (`cascadedRunIds`)
  must not leave that next step to the caller — ship the composition, grep every
  caller of the primitive, convert all of them in one pass, and give the crash
  window between the two halves a sweep.
- A "best-effort, keep going" comment must state the case it covers; the
  degenerate case (ALL attempts failed) usually needs the opposite policy.
- When a later stage re-derives a value an earlier stage already wrote into an
  "immutable" record, the later stage owns the record — D7 was the precedent;
  check for siblings of a precedent before closing a review finding.
- Test seams: the launcher reads the `flows` row BEFORE `checkSupervisorHealth`,
  so a mid-launch race must be injected through the caller's `authorize` hook; a
  second `vi.mock` of the same module in one file silently shadows the first.
