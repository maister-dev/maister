# Preserve typed driver fences while integrating scheduled input

**Date:** 2026-11-02 09:30 UTC
**Files:** web/lib/db/pg-error.ts; web/lib/flows/runner-agent.ts; web/lib/flows/graph/**tests**/driver-claim.integration.test.ts; retry and launch integration owners; migration 0213 metadata; scheduled-request analytics
**Severity:** high

## Problem

The privacy fix initially classified Drizzle-wrapped ownership loss as a database crash. Integration also had to preserve current master's version-2 retry strategies and its migration allocations, rather than overwriting them with the branch's original version-1 assumptions.

## Root Cause

Drizzle wraps errors from guarded query adapters as well as errors from Postgres. The existing Flow fence classifier deliberately searches causes. Removing a wrapped typed fence's cause without preserving its identity changes a required yield into CRASH. A newly accepted retry is now version 2, so accepting a fresh recipe is no longer a valid legacy version-1 fixture. Child-run peek owns two migrations, 0211 and 0212, after retry strategies at 0210.

## Solution

Unwrap causeless typed domain failures before replacing ordinary query errors; retain no SQL wrapper or nested database cause. Keep normal ownership yields out of persistence-error logging. The driver regression uses a real claimed/aborted guarded database and verifies recognizable fencing, no query exposure, unchanged Running ownership and no prompt effect. Preserve the shared retry snapshot field across both recipe versions and include it conditionally in the common context digest input. Consolidate legacy coverage into actual persisted version-1 recipes with absent/captured input, exact retained bytes and successor snapshots; keep the current version-2 concurrency test distinct. Allocate scheduled input to 0213 and preserve preceding migrations and the merged snapshot chain. Replace the old rollback test's raw-cause oracle with the same trigger's explicit safe constraint and SQLSTATE; retain all rollback assertions.

## Prevention

- Treat error classification as control flow. Test typed fencing and continuation errors whenever removing exception causes.
- Re-derive migration SQL/journal/snapshot/schema together against the integration parent; verify populated upgrade and generation without drift.
- Inspect actual recipe versions, never infer legacy input from a test title.
- Keep every test and timeout when reducing worker contention; an isolated pass alone is not a complete regression run.
- Sibling sweep command: `rg -n 'queryErrorDiagnostics|redactQueryError' web/lib/db/pg-error.ts web/lib/agents/launch.ts web/lib/services/runs.ts web/lib/flows/runner-agent.ts web/lib/flows/graph/prompt-record.ts`.
- Sweep output at integration: `pg-error.ts` defines diagnostics/redaction; `agents/launch.ts` uses redaction at standalone insert and diagnostics at consensus failure; `services/runs.ts` uses both at Flow insert; `runner-agent.ts` uses both at dispatch and diagnostics for resolved-prompt projection; `prompt-record.ts` uses diagnostics at transcript projection. All six exposed paths have a boundary owner; worktree-only compensation remains separate.
