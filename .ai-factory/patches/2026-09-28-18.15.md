**Severity:** high

## Problem

A whole-branch `/aif-review` of the outbox-pressure branch confirmed four majors and a set of minors (commits `e7840f264..b9e949ac9`).

- **M2 — the admission fence followed the wrong bit.** `recordHostPressureSample` cleared the manager's pressure record whenever `stream.pressured` (unACKed rows only) was false. A host refusing new work at the retained, physical or control limit was read as admitting. Each `system_sweep` tick then:
  - cleared the fence;
  - auto-resumed host-paused interrupts;
  - drained the queue into fresh refusals.
  A health sample fetched before a refusal also deleted the fresher refusal record.
- **M1 — a prompt whose terminal row is a skip hung silently.** Ingest records an unstorable terminal (a NUL, 22P05) in `execution_event_skips`, and the frontier walks past it. ADR-184 D3.7 answered `canonical_available`, but no canonical event could ever exist, so the command waited forever on a healthy stream.
- **M3 — the HITL card mistreated a stored answer.** A `503 event_outbox_backpressure` stores the answer, but the card entered the stored view only for `delivery_unavailable`. The operator saw live buttons plus a red error, and after a refresh two contradictory lines.
- **M4 — a host-paused interrupt defaulted to a destructive action.** For a node the host paused, the one-click default was *Restart node*. It discards the ACP context the park preserved and spends an operator restart.
- **Found while writing a RED, not in the review:** `createOwnedSession` rethrew a refused create's STORED failure (`PRECONDITION event_outbox_backpressure`). The driver never saw `host_pressured` and FAILED the node instead of parking it.
- **Found by the adversarial re-review:** without a session, a `judge` node and an AI gate on a `check` node gate-redispatched into the same quarantined command every tick.

## Root Cause

- **One wire token hid five causes.** Every outbox refusal travelled as `event_outbox_backpressure`. The manager could not tell a host that refuses new work from a per-command wallet refusal, so it keyed on the only host-wide bit it had (`pressured`), which means something narrower.
- **"canonical_available" was trusted as "will settle".** D3.7 was right that the host must not settle a row at or below the frontier. It assumed the canonical feed would then settle it. A skip-ledger row satisfies the frontier and never becomes an event.
- **Owners treated "no verdict yet" and "no verdict ever" the same.** Agent, scratch and the watchdog all mapped a failed wait to `ContinuationPending`, which is correct only while some feed can still settle the command. An unsettled quarantine (accepted, no terminal evidence) has no writer left, so every owner yielded forever. A live session hid it for flows: reconcile reattached, and the reattached driver yielded again.
- **A gate re-dispatch re-enters the same attempt.** `runFlow`'s durable continuation reuses the open attempt, the same logical key returns the same command, and the driver yields. Reconcile read evidence only for agent node kinds. That was a fine gate for "a turn the host lost", but not for "a turn nothing will ever settle", which any node with a prompt can hold (`pre_finish.gates` run on every node).
- **The stored refusal is re-read, not the live one.** `createOwnedSession`'s retained-create path rethrew what the ledger stored. The typed `host_pressured` conversion lived only on the live refusal path.
- **A UI predicate was spelled at each site.** The stored-view check was a string compare in three places, so the new refusal reason reached none of them.

## Solution

- **The refusal names its cause, and the host publishes the signal the fence follows.**
  - The wire carries `details.outboxLimit` (unacknowledged | retained | physical | control | wallet), with an exhaustive reason→limit map.
  - `/health` publishes `stream.newWorkRefusedBy`, checked in admission order.
  - The manager's record follows `newWorkRefusedBy`, with the `pressured` fallback for an older host. A `sampledAt` guard (`pressured_since <= sampledAt`) keeps a fresher refusal record. A `wallet` refusal parks without closing the fence.
- **The queue is a backstop.** `applyHostPressureSample` drains both pools on every admitting sample, each step isolated.
- **Host parks survive.** Keep-alive Pass 2 excludes host-parked runs. Auto-resume backs off exponentially (cap 16 ticks) with an ERROR line and never gives up.
- **The create choke point converts a stored refusal too** (`owned-session-create.ts`), so every create owner parks.
- **The skipped terminal is quarantined at the one reducer every feed reaches:** `reducePromptEvidence`'s no-evidence branch, under the prompt row lock, with `causeCode: terminal_unstorable` for v1 and v2.
- **An unsettled quarantine ends its owner.** Owners read the command state (`isUnsettledPromptQuarantine`), not the conflict details:
  - flow: the reconcile sweep reads every node kind the host-evidence path does not cover, DB-only, live or not. It crashes `owner-poisoned` through the turn-lost boundary, stopping live sessions first.
  - agent: one wrapper around `startAgentSession` stops the session, finalizes `Crashed owner_poisoned` and closes the turn. This holds for the issuing and the re-driving driver, and for consensus drafts.
  - scratch: one choke point in `sendScratchPromptAndProjectEvents` returns the dialog to `WaitingForUser` with `CONFLICT` and `error_metadata {reason, causeCode}`. The send answers the typed conflict.
  - the watchdog does not defer a quarantined command.
- **Post-hoc was descoped, and ADR-184 says why.** Quarantining a host-span-settled command at the canonical skip would take the prompt lock inside the ingest transaction, inverting the run→command order.
- **UI fixes:**
  - one `isStoredAnswerDeliveryReason` predicate at the three sites, with honest backpressure copy;
  - `deriveNodeInterruptOptions({cause})` is REQUIRED and defaults to Resume for `host_pressure`, and the default option is painted as the primary button;
  - an admin "Refusing new work: {limit}" badge;
  - a scratch quarantine notice.

## Prevention

- **A token that aggregates causes must carry the cause.** When a manager-side policy branches on a refusal, check that the wire says WHICH limit refused. A policy keyed on a coarser bit (`pressured`) looks right on the one path it was designed for and wrong on every other.
- **"Defer to the other feed" needs proof that the other feed CAN deliver.** When a rule hands evidence to another reader, enumerate what that reader can never see. Here that was skip-ledger rows, which satisfy contiguity and never become events.
- **Every "pending" branch needs a "never" twin.** Where an owner maps a failed wait to pending, ask what makes it final: quarantined with no evidence, stream lost, owner poisoned. Read that from the durable state at the choke point, not from the error's details. The details are only as complete as the one raise site that built them.
- **Re-dispatch is not recovery when the attempt is reused.** Before trusting "retry-safe re-dispatch" to heal a stuck turn, check whether re-entry mints a new command or meets the old one (`isDurableContinuation` reuses the open attempt). Evidence gates keyed on node kind must cover every node that can own a prompt, gates included.
- **Convert a refusal where BOTH paths pass.** A typed conversion on the live path is skipped by a replay that rethrows the stored failure. Put it at the choke point both reach (`createOwnedSession`).
- **A UI predicate for a server reason lives in the shared contract module** (`hitl-response-contract.ts`), never as a string compare at each site.
- **A REQUIRED parameter beats a default** when a new input changes a server-owned default (`cause` → `defaultOptionId`): the compiler finds every caller.
- **Use a different model for the adversarial pass, and verify every finding in source.** It found the judge/check gap the original review, the plan and my own falsification all missed, because each of those reasoned from the node kinds the plan named.
- **A gate over samples must say what an ABSENT sample means.** The first R20 run failed the new-work gate on its first sample (t = 28 ms, before the stream opened: no telemetry, so the field was `undefined` and dropped from the logged JSON). Count "refused" (a string) and "telemetry present but the signal missing" separately; never let absence read as a refusal, or as admitting.
- **A detached driver in a test must be settled by the case that started it.** `permission-crash-boundary`'s Recover case `void`-ed the resumed `runFlow` (Recover awaits its dispatcher). The driver lived through six more cases and settled only because the last case restarts the host, 377 ms before `afterAll`. Under load it ran into `testDatabase.stop` → five unhandled 57P01. Record every detached promise, settle it in its case, and let `afterAll` await the list after killing the host, then fail naming any straggler (`cf7931090`). Probe it deterministically by running the case alone (`-t`): the promise was `PENDING` at teardown every time.
- **zsh aborts a `$(...)` whose glob does not match** (`--include=*.integration.test.ts`). The file list came back empty and `vitest run` silently ran the WHOLE lane. Build file lists with `grep -rl ... | grep integration.test.ts`, and print the count before running.
