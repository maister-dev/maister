# Keep preparation copy and delegated fixture evidence truthful

**Date:** 2026-11-04 13:36
**Files:** web/messages/en.json; web/messages/ru.json; web/components/runs/**tests**/operational-run-result.test.ts; web/e2e/_seed/seed-e2e.ts; web/e2e/flow-target-delegation.spec.ts
**Severity:** medium

## Problem

A Run infrastructure-preparation failure always claimed the model never
started, although the same projection can describe preparation for a later
continuation after earlier model execution. Separately, the delegated Flow
browser case returned an empty HTTP 500 before canonical launch acceptance.

## Root Cause

`OperationalOutcome.infrastructureFailure` identifies preparation failure but
contains no global proof of absent model execution. Its localized description
made that unsupported inference. Historical Runs also need not expose a Retry
action, so remediation must not promise one.

The Flow fixture declared an Installed revision whose directory did not exist.
The actual server exception was `ENOENT / scandir` while computing its frozen
asset digest, through `captureTaskLaunchFlowAssets` and
`serverTaskLaunchRequest`, before `acceptServerTaskLaunch` could be called.
This is a missing fixture asset, not evidence of a model refusal or import cycle.
The frozen browser evidence is retained in
`/private/tmp/maister-e2e-final-11-10d255160.log` and its trace directory.

## Solution

Use neutral Run preparation-failure copy in EN/RU, preserve the infrastructure
versus assessment distinction, and direct users to the reported technical cause
before another attempt. Do not add a DTO field or guess model history in the
client. The separate task failure notice retains its explicit
`modelStarted === false` rule and proven pre-model remediation.

The existing real-locale component regression now renders a later preparation
epoch, asserts literal neutral/actionable copy and retained safe diagnostics,
rejects the old global model claim, and proves the task notice still honors
positive pre-model evidence. Both locales failed before the copy change; the
three coupled component suites then passed 23/23. Evidence is retained in
`/private/tmp/maister-r10-operational-copy-{red,green}.log`.

The delegated Flow seeder creates the declared directory and writes `flow.yaml`
from the same manifest object persisted in its revision. The browser case waits
for exactly two selected Flow Runs joined to their exact canonical intent
bindings and parent-derived admission proof. Only then does it release the
existing child gate and inspect the unchanged kind, carrier, relation and state
assertions. Accepted child intent is not mistaken for an already-bound Run.
Actual browser GREEN for these fixture corrections remains pending the next
coordinated frozen lane; source inspection and lint are not equivalent evidence.

## Prevention

Localized product copy is part of the evidence contract. Make definitive
claims only when the read model carries their proof, and distinguish one
generation's preparation from the complete Run history. An Installed test
revision must carry real asset bytes before launch; never disable capture to
accommodate an invented fixture. Observe canonical child bindings before
asserting physical child execution, while retaining exact effect counts.
