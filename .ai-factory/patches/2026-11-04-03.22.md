# Preserve the interactive Origin boundary in browser fixture HTTP calls

**Date:** 2026-11-04 03:22
**Files:** web/e2e/platform-agents-activity.spec.ts; web/e2e/platform-agents-operational.spec.ts; web/e2e/task-launch-gating.spec.ts
**Severity:** medium

## Problem

The frozen 29-case browser lane failed four canonical journeys before their
intended execution boundary: activity retry preparation, operational Stop,
Triager infrastructure failure and the RU manual-admission sequence. Each
project-agent launch answered HTTP 403 with
`UNAUTHORIZED / launch_interactive_origin_required`.

## Root Cause

These setup calls used Playwright's `page.request.post` API rather than a
browser fetch. They retained the authenticated session but supplied no Origin
header. The shared interactive launch guard correctly refused them. Other
same-class setup calls in serial downstream cases had the same omission but
were not reached after the first failure.

## Solution

Add the configured Playwright `baseURL`'s exact public origin to all six
direct project-agent launch call sites in the three canonical specs. Thread
that explicit base URL through the task qualifier helper, since the page can
still be `about:blank` when setup launches the qualifier. Existing browser
interactions, authorization, assertions, stable request identities and the
runtime Origin guard remain unchanged. No bind address, forwarded header or
client admission flag is substituted for the configured public origin.

## Prevention

When a mutation's CSRF policy changes, inspect direct APIRequestContext setup
and cleanup producers as well as browser click handlers. Do not assume the
request context synthesizes browser Origin headers. Derive fixture authority
from the actual configured base URL and keep negative-origin API controls
unchanged. Re-run serial downstream cases after fixing their earliest setup
failure; a filtered or not-run case is not qualified.

RED evidence is retained in
`/private/tmp/maister-e2e-final-11-94381c8fc-api-refusals.json`, the corresponding
trace directory and full wrapper log. That lane finished naturally with 19
passed, eight failed and two not run; its exact invocation reported zero leaks,
an independent native snapshot found no owned survivors and its owned database
container was removed. This correction has scoped ESLint and formatting checks;
the next frozen browser repeat owns runtime GREEN evidence.
