# Prepare the production Web build before isolation cases

**Date** 2026-11-23 00:38 MSK

**Files** `scripts/run-stage-ab-tests.mjs`, `web/vitest.workspace.ts`, `web/test-support/vitest-production-web.setup.ts`

**Severity** medium

## Problem

In GitHub Actions run `45066484628`, the macOS Intel isolation part 1 case `O-build-lock` exhausted its 600-second Vitest timeout. The other 19 cases passed. The aggregate isolation job reported the matrix failure.

## Root cause

The test reclaimed the injected dead owner before starting the shared cold production build. The build completed successfully in 674.451 seconds and subsequent calls verified reuse of its build ID. The case had already timed out. The setup cost belonged to the serial isolation lane, while whichever case or hook first requested the artifact paid it from its own timeout.

## Solution

The isolation lane prepares one production artifact in Vitest global setup using its existing invocation and build helper. `rg -n 'buildProductionWeb' web/test-support/__tests__ web/lib/scratch-runs/__tests__/dispatch-window.integration.test.ts` shows the other consumers in process cleanup, process death, partitions, filesystem isolation, durable workers, and dispatch-window. All production isolation parts get the shared setup. Preflight and nested reporter and reaper controls retain their existing paths. Cases still validate the build witnesses, and the ownership checks, exact inventory, lane deadline, and job budget apply as before. Existing structured build events record the revision, ID and elapsed time.

## Prevention

Put cold artifact preparation under the lane that owns its lifetime. Keep per-case budgets for verification and use the existing build receipt to confirm that cases reused the artifact prepared by their invocation.
