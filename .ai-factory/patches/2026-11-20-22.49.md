# Preserve context binding, transcript, and replay evidence

**Date:** 2026-11-20 22:49

**Files:** `runtime/acp-context.ts`, `web/lib/execution-host/events/`, `web/lib/projector/artifact-projector.ts`, `web/lib/runs/`, `web/lib/use-run-stream.ts`, shared transcript and scratch components, `web/e2e/scratch-detail.spec.ts`, migration 0359, run API contracts and analytics

**Severity:** high

## Problem

A late context snapshot could restore usage from a previous process after a
bind or resume. Transcript freshness was inferred from a canonical maximum,
which can stay fixed when an earlier marker changes. Reading that maximum and
counting compactions also made each periodic snapshot depend on retained
history size. During replay, pruned context references could hold back later
valid events. Some summary text could fail PostgreSQL JSONB ingestion.
The existing full-record action for large previews lacked a compaction
marker regression witness.

## Root Cause

- Run sequence, selected physical binding, processed numeric state, and
  committed transcript state advance independently. A canonical maximum
  cannot identify a late mutation below that maximum.
- A valid optional update can refer to runtime content the object ledger has
  already confirmed deleted. Treating that exact tombstone like a missing
  object waits for bytes that cannot return.
- Transcript byte admission, summary storage and summary rendering apply
  different boundaries. An authorized preview needs a test that exercises
  the affordance through the marker renderer.

## Solution

Preserve the canonical cursor and carry a separate scoped transcript revision
updated in the same transaction as its marker. Store compaction counts on the
numeric scope row and read them independently of transcript history. Rank
physical binding observations separately from in-binding context sequences.
Keep upgrades forward-only and initialize the new read model from migration
0358 data. Distinguish exact deletion from retryable absence and integrity
failure at the projection boundary. Record partial coverage for lost numeric
evidence. Preserve Unicode code points at clipping boundaries and use the
shared JSONB-safe transcript codec. Verify the authorized full-record action
through the existing shared renderer.

## Regression witnesses

| Boundary | Reproduce and check |
| --- | --- |
| Binding and live revision | Delay an older hydration or stream snapshot until after a fresh binding without creation evidence. Apply a lower-sequence marker mutation after a newer marker revision and require the reader to observe the change. |
| Retention and migration | Migrate populated 0358 state and check its existing IDs and counters. Replay an accepted object reference after confirmed deletion, distinguish transient and corrupt references, and observe later usage and coverage. |
| Transcript storage and preview | Project text with a Unicode boundary or storage control character. Exercise the authorized oversized-record affordance against the exact attempt. |
| Browser replay privacy | Wait for the exact canonical marker sequence and assert that its private summary stays out of the stream while an authorized transcript read can display it. |
