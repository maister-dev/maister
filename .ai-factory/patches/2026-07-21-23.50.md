# Error `details` stripped at one route family's serializer, silently voiding a documented 409 discriminator

**Date:** 2026-07-21 23:50
**Files:** `web/lib/catalog/route-errors.ts`, `web/lib/catalog/authored-lock.ts`,
`web/lib/catalog/authored-service.ts`, 4 caps route handlers, 2 local-packages
lock routes, `web/components/flows/authored-cap-lock-shell.tsx`,
`web/components/flows/use-editor-lock.ts` (tests), `web/components/studio/{local-package-editor,local-packages-list}.tsx`,
`docs/api/web.openapi.yaml`, `docs/system-analytics/{capability-catalog,flow-studio}.md`,
`docs/configuration.md`, `docs/screens/studio/{README,editor}.md`
**Severity:** high

## Problem

`/aif-review` of the ADR-149 authored-capability edit-lock branch surfaced 24
findings. The most consequential: `details.reason = "edit_lock_not_held"` — an
explicit spec requirement (ACL-07), documented in ADR-149, two analytics files,
and the OpenAPI `sessionId` description — **never reached any HTTP client**.

A stale-draft refusal and a lock refusal are both `409 CONFLICT`. `details.reason`
was the only structured discriminator between them. Without it a client must
match on message text, which `CLAUDE.md` §3 forbids outright.

Secondary: the same branch shipped a sequence diagram whose branch ordering was
inverted relative to the code, two stale-on-arrival `(Designed)` status tags for
implemented routes, a keep-alive test that could not observe the write it named,
and an editor that enabled Save/Publish before its lock was confirmed.

## Root Cause

**Two sibling error serializers, only one of which forwarded `details`.**
`lib/api/project-route-helpers.ts#errorResponse` forwards `err.details` (with an
ADR-093 comment explaining why). Its twin `lib/catalog/route-errors.ts#catalogErrorResponse`
— serving all five caps routes — constructed `{ code, message }` and dropped it.

The author never saw the gap because **every test asserted at the wrong layer**.
Ten assertions checked `err.details.reason`, all against the *thrown MaisterError
object* in service/helper tests. The single route-level test put
`details: { reason: "edit_lock_not_held" }` into the **mock's rejection value**
and then asserted only `status` and `body.code`. Writing the field into a mock
reads as coverage; it is the opposite — it encodes the author's belief that the
field survives, while asserting nothing about whether it does.

The deeper pattern: a value crossing N boundaries needs an assertion at the
**outermost** boundary. Service-layer assertions on a field whose whole purpose
is to reach a client prove nothing about the contract.

The H4 defect has the same shape: `useEditorLock` exported `confirmed` with a
doc-comment saying "gate anything that must not run on an unconfirmed lock on
this", the studio twin consumed it, and the new consumer did not — so the
optimistic RSC snapshot (`heldByMe: !held`) left save/publish live during the
acquire round-trip, where a submit crashes to the root error boundary and takes
the editor buffer with it.

## Solution

- `catalogErrorResponse` now forwards `err.details`, mirroring its twin. Verified
  no leak first: enumerated every `details` payload reachable from those routes
  (reasons, booleans, caller-supplied ids — no paths, session ids, or argv).
- Regression test asserts `body.details` on the **response**, not the mock.
  Proved RED against the pre-fix serializer (`expected undefined to deeply equal
  { reason: 'edit_lock_not_held' }`), GREEN after.
- 404 alignment: added `capabilityExistsInProject` (no lifecycle filter, so
  ARCHIVED still reaches its `CONFLICT`) and probed it in the four caps routes
  that answered 422. Sweep found `graph`/`diff` **already** returned 404 — the
  422 was the pre-existing outlier, not something the branch introduced.
- H4: `effectiveCanManage = canManage && heldByMe && confirmed`.
- Orphaned-lock coherence: the FK is `ON DELETE SET NULL`, so deleting a holder
  left `locked_by_session` + TTL intact. `readLockState` called it held and no
  acquire disjunct matched it, while `assertNoForeignLiveLock` called it free —
  they disagreed for a full TTL. Now `locked_by_user_id IS NOT NULL` is part of
  liveness in all predicates: orphaned lock == free lock.
- H2: the keep-alive test now re-reads `lock_expires_at` from the DB. Proved by
  re-applying the mutation that survived the original suite (`SET lock_expires_at
  = lock_expires_at`) — it now fails the test.
- Transport coverage: `createHttpEditorLockTransport` had zero tests; both URLs
  could be replaced with `/BROKEN-*` and stay green. Now 3 tests fail on that
  mutation.
- Docs: sequence diagram reordered to the real code path (lock assert → stale
  check → validation → CAS); `publish-local`'s response documented as the FLAT
  spread it actually is; ADR-096 tags corrected on the lock pair;
  `configuration.md`'s contradictory Designed/Implemented cell fixed.

## Prevention

- **Assert a wire field on the wire.** When a `details`/`code`/header value
  exists to inform a client, at least one test must read it off a real
  `Response`. Grep for `details` in mock *setup* with no matching assertion on
  `(await res.json()).details` — that pairing is the tell.
- **Two serializers for one error type will diverge.** When a module gets its
  own `*ErrorResponse`, diff it field-by-field against the canonical one. A
  missing field is invisible until a contract depends on it.
- **A test that puts a value into a mock is not testing that value.** Review
  question: "if I deleted this field from the mock, would any assertion fail?"
- **A hook that exports a guard must be checked at every consumer.** `confirmed`
  existed and was documented; only one of two consumers used it. When adding a
  second consumer of a shared hook, diff the destructuring against the first.
- **Mutation-test the assertions that matter.** Three separate defects here
  (TTL write, transport URLs, `details`) were all invisible to green suites and
  all caught by a one-line source mutation.
- Verify a reviewer's finding before acting: this batch **rejected** one reported
  finding (bare `#adr-NNN` anchors "broken") after reading the validator, which
  explicitly sanctions that shorthand — and **reversed** another (the `(c2)`
  coverage-boundary breach) after concluding the test was legitimate and the
  spec's wording was too literal; the spec was amended instead of deleting a
  useful test.

## Deliberately NOT changed (recorded per sweep rule)

- **20 remaining `(ADR-096 — Designed)` tags** in `web.openapi.yaml` on
  local-packages surfaces (import/diff/commit/fork/files) this branch never
  touched. Pre-existing R6 staleness; deserves its own pass.
- **`graph`/`diff` caps routes lack documented 409/422.** Real gap, but a
  different class (project-not-found / invalid-manifest) than the 404 alignment.
- **`project_id` not re-asserted in the authored lock UPDATEs.** Verified
  unexploitable — `authored_capabilities.project_id` is never updated anywhere
  in the codebase. Documented as a stated invariant on the module instead of
  threading the scope through four signatures.
- **`markLost` unused by the authored editor.** Structurally unreachable there:
  its saves are server actions, so there is no fetch response to inspect. Left
  for the studio consumer.
- **Refresh never falls back to acquire** after a suspend-induced expiry (editor
  stays read-only until reload). Changing it would alter the shared hook's
  behavior for the studio editor too, which ACL-08 pins as unchanged.
