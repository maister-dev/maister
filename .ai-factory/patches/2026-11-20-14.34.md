# Retain disclosure-specific authority before using governed context

**Date** 2026-11-20 14:34

**Files** `web/lib/agent-memory-vault/`, `web/lib/agents/`, `web/lib/librarian/`, main migration 0355, and the Web and external API contracts

**Severity** High

## Problem

Ordinary project runs had no durable provenance for governed vault text, while Librarian context could carry historical project-only text without its project restriction. Installation activity required member access at the initial read but its continuation retained only the board visibility floor. Directory views could account for unreturned descendants. Librarian confirmation cards could offer a truncated effect for acceptance, and redaction could contend with card decisions in the opposite lock order.

## Root cause

The permission used to construct a response and the permission recorded for subsequent use were resolved separately. Directory generation and the evidence for a directory entry served different purposes but shared an unbounded descendant set. An advisory transaction fence was missing between the two operations that lock both the immutable note payload and its dependent cards. The installation credential trigger protected the binding by comparing whole rows and rejected the existing terminal revocation write.

## Solution

Require durable capture before serving governed revisions to project executions. Carry older project-only provenance and selected history, summary and memory restrictions into the next Librarian prompt. Persist typed member-level installation sources for activity and Brain recall. A replacement inherits the exact predecessor capture and its source ledger. Migration 0355 permits the existing terminal revocation while protecting the credential's scope, recorded reason and inactive state.

Use one visible descendant revision to witness a returned directory while keeping its generation for CAS. Admit confirmations only when the complete effect fits the existing preview cap. Hide older incomplete previews and require the exact current effect before acceptance. Take the shared or exclusive source fence before card and vault row locks. Publish the browser's real projection in Web OpenAPI and the card-creation receipt in external OpenAPI.

## Prevention

Treat a response, its authorization receipt, and its replay path as one contract. Keep content and labels outside diagnostics. Verify both sides of a lock order with independent database connections and use the real prior migration when exercising an authority guard.
