# Keep regression fixtures aligned with admitted state and dependency ownership

**Date:** 2026-11-09 12:24 UTC
**Files:** web/lib/db/__tests__/migration-task-launch-admission.integration.test.ts; web/lib/domain-events/__tests__/dispatch.integration.test.ts; web/lib/flows/graph/__tests__/orchestrator-park.integration.test.ts
**Severity:** medium

## Problem

The complete regression reported three assertion failures and one suite collection failure. The real pinned-package qualification had passed, so these receipts required separate investigation rather than treating them as new product behavior failures.

## Root Cause

- Migration 0265 added a nullable specialist_assignment receipt column. The historical v1 row comparison predated it and omitted the required null expectation; the original fields were unchanged.
- Two registered event consumers now use the runtime database singleton. The dispatcher fixture had only created its own database handle and never bound DB_URL for those consumers.
- A late-delegation test released its advisory barrier after observing any Run writer. An unrelated writer could satisfy that poll before the intended acceptance waiter appeared, making the test invalidate its own ordering.
- The collection error was a transient missing drizzle-orm package. An isolated checkout shared node_modules with the primary checkout; pnpm's automatic dependency repair relinked the primary dependency graph to the temporary checkout while the full run was importing it. The unchanged delegated-launch suite passed in isolation.

## Solution

Keep strict historical equality and explicitly expect the newly added receipt to remain null. Bind the dispatcher consumers to the owned database, then close the singleton and restore environment/container ownership in finally. Tie the delegation barrier to the exact database, advisory key and acceptance backend; observe a Run writer blocked by that backend and reuse the session's admitted credential. Multiple legitimate blocked writers need not make that barrier fail. Preserve pending-work, rewind-byte and same-credential assertions.

Restore primary dependencies with a noninteractive frozen offline install and verify manifests/lockfile unchanged. Disable automatic dependency repair for isolated test processes and their children with pnpm_config_verify_deps_before_run=false. Never install through shared dependency symlinks while another qualification uses them. No product runtime or applied migration changes are needed for these corrections.

## Prevention

Reconcile strict migration oracles when nullable columns are introduced; proving null is stronger than discarding unknown fields. Exercise actual registered consumers with the runtime connection they use. A concurrency barrier must identify the precise resource and waiter, not a SQL-text category. Keep the dependency graph stable alongside source and HEAD; a symlinked worktree is not isolated from a package manager that repairs it.
