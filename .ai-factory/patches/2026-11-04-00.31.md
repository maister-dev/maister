# Preserve hold provenance in manual launch preview

**Date:** 2026-11-04 00:31
**Files:** web/app/api/runs/launch-options/route.ts; web/app/api/__tests__/task-launch-admission.integration.test.ts; web/e2e/task-launch-gating.spec.ts
**Severity:** medium

## Problem

The RU browser journey passed failed-Triager manual admission and cancellation,
then disabled Launch for a task with a current negative assessment. The accepted
assessment was advisory to the manual decision under the existing contract.

## Root Cause

The launch-options route called the correct shared manual and concurrent
classifiers, but constructed their task input without `triageFlagOrigin` or
`queuePaused`. Missing flag origin correctly means an unknown independent hold,
so a qualification-origin flag was misclassified. Omitting pause could also
advertise launchability that the authoritative admission engine would refuse.

## Solution

Pass both stored fields into the existing classifiers. The shared helper,
independent hold policy and automatic classification remain unchanged. The real
route regression uses an actual accepted `needs_review` assessment and checks
manual and concurrent previews: qualification-origin advice permits launch;
explicit, dispatch-failure and unknown origins refuse; a paused qualification
flag still refuses. Assessment contents remain unchanged.

The browser scenario also preserves the valid state-CAS conflict: delayed real
GET observation leaves an old receipt while owned repository contention advances
the queue version. It requires the localized 409 guidance, visible Refresh, a
fresh cancellation key and observed newer version, then a successful cancellation
without a Run. Finally blocks release both the observation barrier and physical
repository fence even when route setup or removal fails.

## Prevention

Audit all callers when a policy helper is correct but a product surface differs.
An incomplete DTO can change the effective policy without changing the helper.

The separate raw-flag automatic classifier is intentional in
`scheduler/c2-eligibility.ts` and `run-schedules/dispatch.ts`; qualification advice
does not authorize automatic execution. Visual status badges also retain their
existing qualification findings.

Evidence: focused real-route RED
`/private/tmp/maister-manual-preview-hold-red.log`; complete API suite GREEN 12/12
`/private/tmp/maister-manual-preview-hold-green.log`. The original browser trace
shows stale cancellation version 1 while the real queue was version 3 with
`operation_busy`; its later cleanup cancellation was a separate request, not a
successful UI retry. No historical run/assessment, admission authority, schema,
migration or production state is changed.
