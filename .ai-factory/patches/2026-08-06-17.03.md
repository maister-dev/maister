# Auth-first ordering on the relations route + cross-project `relations:delete` narrowed to self-authored edges

**Date:** 2026-08-06 17:03
**Files:** `web/app/api/projects/[slug]/tasks/[number]/relations/route.ts`,
`web/lib/social/relations.ts`,
`web/app/api/v1/ext/projects/[slug]/tasks/[taskId]/relations/route.ts`,
`web/types/token-scopes.ts`, `docs/decisions.md`,
`docs/system-analytics/identity-access.md`,
`docs/system-analytics/external-operations.md`,
`docs/api/external/operations.openapi.yaml`
**Severity:** medium

## Problem

Two findings from an `/aif-review` of the ADR-155/156/157 branch.

1. `handleRelationMutation` parsed the body (`bodySchema.parse(await req.json())`)
   at line 102 and only called `requireActiveSession()` at line 111. An
   unauthenticated caller sending a malformed body got `CONFIG`/400 carrying the
   Zod message — which after ADR-155 describes the `toTaskKey` shape and the
   exactly-one-of refine — where it was owed a 401.

2. `CROSS_PROJECT_AGENT_SCOPES` admitted `relations:delete`, so a reach-granted
   agent token could delete **any** relation in the target project. A dropped
   `blocks`/`requires` edge silently un-gates that project's launches.

## Root Cause

1. Not a regression — the ordering predates the branch (`main:89` parse vs
   `main:98` auth). The branch widened what leaks by adding `toTaskKey` and the
   `.refine()` into the pre-auth schema. The route's own ext siblings already do
   it correctly (`v1/ext/.../tasks/route.ts` even comments "Authenticate first").

2. A scope-versus-justification gap. ADR-156 excluded `tasks:update` because it
   would mutate "a sibling's **existing** task content from outside", and
   justified `relations:delete` with "an agent … cannot later remove the edge it
   created" — i.e. the intent was **self-authored** removal. Nothing in the
   allow-list expressed "self-authored", and an allow-list grants per-scope, not
   per-row, so the written justification and the shipped capability diverged.

## Solution

1. Moved the parse inside the authenticated `try`, below `requireActiveSession()`.
   The authenticated CONFIG contract is unchanged.

2. Added an optional `onlyAuthoredBy` to `removeTaskRelation`, applied as extra
   AND-terms on the DELETE's **own** `WHERE` (`actor_type='agent'` AND
   `actor_id=<caller>`) rather than a preceding SELECT — a check-then-act would
   race a concurrent re-author, and 0 rows deleted already means "no such
   relation" to every caller, so the refusal keeps the existence-hidden
   `200 {removed:false}` shape. The ext route passes it only when the token is an
   agent whose own project differs from the one it is acting in, so same-project
   agent tokens (which already hold `manageTaskRelations`) are untouched.

## Prevention

- **Verify the premise before fixing an "ordering violation".** A crude
  whole-file grep flagged 44 routes; a per-function scan cut it to 18; spot
  checks showed most of those were `parseJson` **helpers** whose call sites auth
  first. Only an in-function, call-site-aware scan is evidence. Record the
  classification (fixed / already-safe / out-of-scope) — parse-before-auth is
  still real in ~17 other handlers and is a repo-wide pattern, not a one-off, so
  fixing one route does NOT fix the class.
- **Prove a regression test red.** Both fixes were re-run with the fix stashed:
  3 auth-first and 2 narrowing cases fail without it. The no-over-restriction
  guards (same-project delete still works; authenticated CONFIG preserved)
  correctly pass both ways — a test that passes either way is a guard, not
  evidence, and must be labelled as such.
- **When an allow-list entry's justification is narrower than the entry,
  the code is the defect.** Read each scope's stated reason and ask whether the
  grant is per-scope or per-row; if the reason says "the edge it created", the
  enforcement belongs in the operation's predicate, not the scope list.
- **Sweep the callers of a shared function before adding a precondition.**
  `removeTaskRelation` had exactly 2 callers; the session route was correctly
  excluded (humans authorized on both ends). Full consumer suites re-run: 76
  integration + 73 unit green.
