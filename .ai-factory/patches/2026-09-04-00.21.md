**Date:** 2026-09-04 00:21

**Severity:** critical

## Problem

`/aif-review` of the Stage A branch (ADR-166, 12 commits, 318 files) gated FAIL:

- After ANY supervisor restart with in-flight runs, the first `localHost()` caller
  hung forever and every later host resolution (launch, sweeper, mint) hung with
  it — a process-wide outage with no error.
- A run reopened after its worktree was garbage-collected could never spawn an
  agent session again (`workspace_released` on every create).
- Cap-queued (`Pending`) launches lost their assignment to the sweep after 60 s and
  were re-placed on promotion with `placement_reason='legacy_backfill'` plus a
  spurious legacy WARN; the same lazy mint would break outright once
  `ensureAssignment` is deleted in Stage C.
- The assistant launch minted two epochs at birth; gates, consensus, scratch
  recover/stop/discard, agent idle claims, and several catch sites either ignored
  a fenced (`assignment_fenced`) outcome or folded it into a generic failure that
  wrote run state — the exact split-brain E-EH-11 forbids.
- `ensureAssignment` was check-then-act; driverless `delivering` rows with no host
  receipt were unrecoverable and could starve recovery at 500 rows; a ledger write
  failure mid-turn left a prompt's `completion` pending forever; payload redaction
  was key-based and let `args`/`url` secrets through.
- The vitest fake host was more permissive than the real supervisor, so ~90
  fake-backed suites proved the fake's contract; the only end-to-end fencing test
  (E1) flaked 2/6.
- Docs drifted from code on the fence rule order, the stale-checkpoint path, the
  command FSM, `details.field`, `readiness_reason`, and an agent-facing file still
  claimed the supervisor may run on another host.

## Root Cause

- **Deadlock:** the registrar awaited a DOMAIN sweep (`runReconcileSweep`) inside
  the resolver's single-flight promise. The sweep re-dispatches `runFlow`, whose
  first agent node binds the host through the same resolver, which returned the
  very promise that was waiting on the sweep. A lookup owning domain work is the
  defect class, not the particular await.
- **Released handles:** the host keyed handles `UNIQUE (run_id, real_path)` without
  a `released_at` filter while the web copied handles forward blindly and
  re-adopted only on `unknown_workspace`. Two halves each assumed the other never
  produced a released-but-reused path; `reopen` re-creates exactly that.
- **Sweep:** the stale-assignment predicate was a DENY-list of a coarse property
  (`NOT IN (Running, NeedsInput)`), which silently admitted `Pending` — a queued
  run whose claim had already minted an assignment for the driver that will pick
  it up.
- **Double mint / missing mints / fenced folds:** two rebases duplicated a line;
  the placement rule ("every re-entry mints inside its own claim") was applied to
  the paths the author had in mind, not enumerated over every claim site; the
  yield rule was enforced at the main runner but the callers of `runAgentStep`
  (gates, consensus) and the teardown catch blocks were never walked as a
  checklist.
- **Lazy bind:** drivers bound `forRun(runId)` (whatever assignment is active at
  bind time) instead of the row their own claim minted, so the fence's structural
  guarantee depended on status-CAS ordering.
- **E1 flake:** `transitionBackToRunning` flipped `NeedsInput → Running` on ANY
  session update after a permission request; a keep-alive checkpoint cancels the
  deferred and the adapter still emits one update, which won against both
  NeedsInput-guarded checkpoint transitions and stranded the run `Running`
  (pre-existing on main, surfaced by the new regression test).
- **Fake drift:** the fake was written from the plan's intent, never diffed
  rule-by-rule against the real host, so it stayed permissive exactly where the
  host refuses (`host_mismatch`, `run_mismatch`, `assignment_mismatch`, unknown
  session, released handle).

## Solution

- Registrar: no reconcile at all — `restarted:true` + log; the periodic
  `system_sweep` reconcile classifies the runs (≤ 60 s). Resolver stays a pure
  single-flight lookup. `refuse` throttled like `unavailable`.
- Sweep backstop: exhaustive `satisfies Record<RunStatus, boolean>` map →
  `STALE_ASSIGNMENT_RUN_STATUSES` (allow-list) and `DRIVER_OWNED_RUN_STATUSES`
  (Pending included) shared by the sweep and the registrar's ownership count.
- `ensureAssignment`: re-check under the run row lock; a placed run with no active
  assignment is refused (`PRECONDITION assignment_missing`); only never-placed
  rows mint lazily.
- Handles: host partial unique `workspaces_active_uq WHERE released_at IS NULL`
  (+ `PRAGMA user_version` 0→1 rebuild for existing stores), lookup filters
  released; the client re-adopts once on `workspace_released` as on
  `unknown_workspace`.
- Drivers bind by assignment id (`executionFor(runId, {assignmentId})`); claim
  transitions return the minted row; the graph runner binds the id it read at
  entry. One agent idle-claim helper (`claimAgentIdleResumeInTransaction`) mints
  `resume` for all three agent resumes. Scratch recover is a CAS + mint with a
  rollback release; stop/discard, gates, consensus, park, consume, gate-chat,
  agent-question, sync-target/resolver, evaluations reaper yield on fenced
  outcomes. Release calls added to every terminal writer that lacked one, inside
  the CAS tx.
- Recovery: `delivering`-without-receipt → `queued` then re-delivered/orphaned;
  `(created_at, id)` cursor paging; shared `applyCreateAck` for client and fold.
  Deliverer: every ledger write guarded; `completion` always settles
  (`ledger_write_failed`). Redaction: per-kind allow-list projection. Transport
  timeouts flow from the one policy table.
- Runner: `NeedsInput → Running` flips only when the permission row carries a
  `response` (written in the respond route's Phase-1 tx, before delivery), retried
  per update; a checkpoint-cancel update never flips.
- Supervisor: eviction inside the receipt-guarded in-flight execution; replay
  before liveness/handle guards; realpath'd state dir; `.git` directory for repo
  roots; context mounts validated; `SAFE_PATH_SEGMENT` rejects `.`/`..`;
  post-close event appends serialized; transitional dead code removed;
  `engines.node >= 22.13`.
- Fake host rebuilt rule-by-rule to the host's semantics plus a parity suite that
  runs one scenario table against BOTH the fake and a real supervisor child; the
  real-supervisor harness kills the process group (no orphaned adapters) and
  scrubs `MAISTER_EXECUTION_HOST_*`.
- Docs: ADR-166 Amendments (8), analytics diagrams/tables/expectations to the
  as-built contract, error taxonomy "web-minted reasons" table, OpenAPI headers/
  fields/status codes, DESCRIPTION.md topology truth.

## Prevention

- A resolver/registrar/lookup MUST NOT await domain sweeps; schedule them
  out-of-band. Review checklist: "does anything inside a single-flight promise
  call back into the same resolver?"
- Status guards over `runs.status` are allow-lists derived from an exhaustive
  `satisfies Record<RunStatus, …>` map — never `NOT IN (...)`.
- When a contract is split across two processes (handle registry vs. client
  re-adopt policy), write the parity test that runs the same scenario table
  against the fake AND the real peer; a fake that is not diffed rule-by-rule
  against its peer proves nothing.
- Enumerate every claim site and every catch site as a checklist when a rule
  says "every re-entry mints" / "every fenced outcome yields" — grep
  `forRun(`, `mintPlacement(`, `isFencedError(` and classify each hit.
- After a rebase, grep for consecutive duplicate statements
  (`awk 'prev==$0 && $0!=""{print FILENAME": "FNR": "$0}{prev=$0}'`).
- A flaky end-to-end test is a defect to root-cause, not to quarantine: make its
  timeout dump the run row, transitions, ledger and host log first.
