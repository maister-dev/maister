# Operational integrity, cleanup ownership and continuation contracts

**Date:** 2026-10-30 11:40
**Severity:** high
**Files:** `web/lib/agents/{launch,operational-context}.ts`,
`web/lib/context-mounts/{launch,service,terminal,operational-lock}.ts`,
`web/lib/gc/operational-disposition.ts`,
`web/lib/run-results/operational-types.ts`, `web/lib/services/hitl.ts`,
`web/lib/workbench-lifecycle/service.ts`, operational workbench components,
`web/lib/reconcile.ts`, their integration/browser tests, and operational
API/domain documentation.

## Problem

An operational run could report success before validating its sibling context
repositories. Ignored files and committed changes escaped the legacy porcelain
check. A failed Git worktree removal was swallowed while the operational cleanup
owner recorded release. The operational layout also removed Stop, and a business
question's actual HTTP 202 body omitted the `state` required by both API schemas.
Current documentation still described implemented contracts as Designed.
The sibling sweep also reproduced an orphaned queued continuation bypassing the
agent finalizer and failing its database terminal-receipt constraint.

## Root Cause

- Integrity was scoped to primary cwd even though execution also exposed detached
  sibling repositories. Resume reused a remove-first materializer designed for
  legacy agents rather than immutable operational execution evidence.
- Legacy context cleanup was intentionally best effort, backed by a separate GC.
  Operational cleanup reused it as a success proof while that GC excludes
  operational owners. A Git no-op is not proof that filesystem bytes disappeared.
  Legacy preparation also wrote its snapshot after all Git effects, leaving
  partially created operational mounts outside their cleanup owner's inventory.
- The layout replaced the entire action set instead of applying the existing
  kind-aware policy. Stop's legacy post-finalization cleanup also overlapped the
  operational disposal owner.
- Service and declarative API changes were tested separately; neither validated
  the actual operational answer response against the published accepted schema.
- Domain indexes and adjacent HITL prose retained pre-implementation assumptions.

## Solution

Freeze context descriptors and full integrity witnesses inside the existing
immutable baseline before dispatch. Validate them on continuation and terminal
completion, use sibling-project reference evidence, and preserve changed or
indeterminate bytes before deletion. Missing witnesses fail closed. Keep
code-delivery materialization timing and best-effort cleanup semantics intact.
Operational disposal owns strict cleanup and verifies removal, including retries
after partial removal. Existing baseline immutability protects the extension;
no additional database migration is required.
Generic context release refuses operational ownership. Reconciliation routes
orphaned pending operational children through the existing agent finalizer.
Operational preparation records context descriptors before filesystem effects
and refuses existing checkout paths, preserving an interrupted preparation for
diagnosis instead of applying the legacy remove-first materializer to it.
Preparation and context disposal share the existing OS-backed materialization
mutex mechanism, keyed by run outside source checkouts. Revalidate the running
owner after acquiring it: cancellation may already have won. Without this
fence, cancellation could finish cleanup before an in-flight create landed.
Git effects stay outside Postgres transactions, per the database convention.

Restore Stop through the shared action policy and retain one operational cleanup
owner. Return `state: resume-queued` on accepted operational human answers and
describe same-answer replay separately. Use HeroUI and shared localized feedback,
with one feedback identity per mutation attempt. Reconcile the current API,
persistence and lifecycle descriptions without rewriting historical ADR status.

## Prevention

- Enumerate every mounted repository when defining an integrity boundary. Test
  ignored and committed changes, continuation, immutable ownership and retained
  diagnostic bytes against real Git and PostgreSQL.
- A cleanup consumer must distinguish best effort from durable completion. Assert
  actual path absence and preserve failure ownership; test partial removal and
  no-op Git responses rather than only injected exceptions.
- Persisting an intent before effects solves crash discovery, but does not by
  itself serialize cancellation with in-flight effects. Test both ownership
  and the actual effect/disposal race. Compare JSONB snapshots canonically,
  since PostgreSQL does not preserve object property insertion order.
- Test actual HTTP response bodies against both published contracts and exercise
  browser action wiring, state transitions and localized feedback.
- Reuse kind-aware action policies; suppressing an entire toolbar can remove
  cancellation together with forbidden delivery actions.
- Keep recurring-automation UX separate from workspace disposal: terminal
  visibility does not deduplicate recurring operational failures.

## Sibling sweep

`rg -n 'releaseContextMounts|releaseRunContextMounts|inspectOperationalRun'
web/lib --glob '*.ts' --glob '!**/__tests__/**'` identified context terminal
cleanup, agent launch/finalization, operational disposition, Flow runner,
promotion and generic abandonment. Operational disposition must be the strict
preserve-before-delete owner; ordinary Flow/code-delivery callers retain their
existing behavior. Reconciliation abandonment requires explicit agent handling.

`rg -n -i -U 'operational[^\n]{0,90}(designed|accepted)|designed[^\n]{0,90}operational'
docs site-docs .ai-factory/ARCHITECTURE.md CLAUDE.md` leaves only
`docs/decisions.md:238`, ADR-195 **Accepted**. This is the decision's lifecycle
status, not an unimplemented-feature claim, and is intentionally retained.

`rg -n 'operationalActiveWorkspacePredicate|listOperationalAttention' web`
confirms terminal visibility is shared by project/portfolio projections, while
attention acknowledgements remain per run/reason/revision. Per-automation history
and incident aggregation are a separate proposed product contract, not delivered
by these fixes.

## Qualification

The regressions reproduce before the fixes: four real Git/PostgreSQL context
integrity/removal cases, the external HITL response missing `state`, and the
browser's missing Stop action. Post-fix receipts and the final gate battery are
recorded in the active operational implementation plan; historical broad-suite
receipts are not represented as executions of these fixes.
