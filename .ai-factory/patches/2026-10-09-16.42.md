## Root Cause

Completed cases pass while setup and repeated real process boots consume the
fixed budget. The prior database correction reduces the same completed-owner
sum by 168.846s; its actual fresh main/Brain transport remains 6/6 and database
clones already reuse migrated templates. The one production build takes
244.737s; verified subsequent reuse takes 30–134ms. Deduplicated physical and
embedded logs show 43 real web boots with median kernel-start-to-listening
12.833s and total 590.843s. These times overlap suite durations.
The hosted artifacts have no native-reader latency/count measurements, so
changing exact kernel ownership checks on an assumed CPU cost is unjustified.
The full missing duration is unknown; the measured portion does not prove
that any single optimization will satisfy the Intel budget.

## Solution

Add one macOS-job step after `runtime:check` and before Colima provisioning.
The selected Node creates a fresh 0700 cache inside canonical `RUNNER_TEMP`,
outside report uploads. A real same-executable child must observe an initial
cache directory within that fresh root, ALREADY_ENABLED status, exact Node
and imported runtime module, and actual persisted file-module entries after
normal exit. Only then publish `NODE_COMPILE_CACHE` in `GITHUB_ENV` and a
bounded structured ready receipt. Preserve inherited disablement and fail
explicitly if activation/persistence is unavailable; reject CR/LF paths.
No dependency or cross-job cache/production artifact restoration is added.
The ephemeral runner owns its lifetime. Build, preflight and real fixtures
inherit the cache through their existing environment paths.
Node owns exact source/path/version invalidation; SIGKILL cannot be assumed
to persist newly compiled entries. This lane does not collect V8 coverage.
These semantics follow the [pinned Node contract](https://nodejs.org/download/release/v24.19.0/docs/api/module.html#module-compile-cache).

APIs, HTTP/SSE/object contracts, Postgres schema/SQL/journals, product
configuration, deployment, Linux capabilities and native ownership/signal
contracts are unchanged. No migration or ADR allocation is needed. Kernel
private-root denial and fail-closed driver selection remain required.
Both exact Nodes and two web shards each remain on push; isolation stays
serial/unsharded with seven owners/50 cases, separate preflight, a 60-minute
job and the original min(2340,3240-elapsed) slice. No case is removed or skipped.
