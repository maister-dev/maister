# Keep integration fixtures consistent with admission and writer contracts

**Date:** 2026-11-04 01:51 (Europe/Moscow)
**Files:** `web/test-support/pg-container.ts`; historical migration, Brain,
notification and flag-provenance integration fixtures; project-Brain analytics.
**Severity:** medium

## Problem and root cause

The full frozen suite reached the current writer-v3 floor through Brain and
post-upgrade connections that still declared no current binary capability.
Independent notification clients had the same omission. Several read-model
fixtures also inserted flagged tasks without the now-required origin. These
failures occurred before the assertions those tests intended to exercise.

The old Brain projection assertion expected Flow configuration and a routing
verdict to authorize automatic execution without qualification. That expectation
conflicts with the explicit launch contract; the scheduler correctly refused it.

## Solution

Reuse the existing current-binary declaration on the initial quiescent connection
and future connections of current-schema fixture pools. Require at most one
existing idle connection before installing the declaration. Historical rows are
still inserted at their historical migration boundary; current declarations are
applied after upgrading. Independent clients declare their own capability.
No migration SQL, writer floor, admission guard or historical row is rewritten.

Use unknown provenance for legacy flagged read-model fixtures and explicit
provenance for the social hold test. The Brain projection case retains configured
routing, but now requires zero fabricated assessments, intents and Runs. Current
analytics distinguish this configuration from automatic/manual authorization.

## Verification and prevention

The original failures and exact constraints are retained in
`/private/tmp/maister-web-full-integration-final-failures.json`. Initial fixture
repair passed 124 cases and exposed the remaining obsolete Brain expectation.
The final affected cohort passes **11 files / 125 tests**, with owned database
teardown, in `/tmp/maister-current-writer-fixtures-final.log`.

Keep capability declaration separate from authorization: a current binary must
still satisfy every intent, assessment, identity and ownership guard. Do not
disable guards or manufacture accepted qualification to preserve an obsolete
automatic-launch assertion.
