# Project Run routing catalogs match credential scopes

**Date** 2026-11-22 23:21 MSK

**Files** `mcp/src/toolsets.ts`, `mcp/src/tools.ts`, `mcp/src/__tests__/stdio.integration.test.ts`, `web/lib/agents/launch.ts`, `web/lib/flows/graph/runner-graph.ts`, `web/lib/flows/runner-agent.ts`

**Severity** medium

## Problem

A project qualifier called `project_get` after a Human answer and ended with `INSUFFICIENT_SCOPE` before submitting an assessment candidate.

## Root cause

Commit `f8863413f` introduced a project directory for the Librarian. The unnamed facade also advertised it to project Runs. The directory requires `projects:read`, while project Run tokens carry the narrower `flows:read` and `runners:read` scopes used by the Core qualifier's routing instructions.

## Solution

The stdio catalog and dispatch guard both use the `project-run` profile for project agents and native project Flow nodes. Qualifier prompts use `flow_list` and `runner_list` with the bound project slug. Existing route scope checks enforce access and built-in structured MCP logs carry tool and refusal context.

`rg -n 'scopeLabel: "projects:read"' web/app/api/v1/ext` found the project collection, directory, and members routes. The profile excludes their three corresponding tools. `rg -n 'agentFacadeMcpServer\(|MAISTER_MCP_TOOLSET' web/lib/agents/launch.ts web/lib/flows/graph/runner-graph.ts web/lib/flows/runner-agent.ts web/lib/librarian/session-profile.ts` found project agent and native Flow injection, the vault profile, installation injection, and the Librarian profile. The project callers select `project-run`. The other callers keep their credential-specific selections.

## Prevention

Verify discovery and dispatch against the compiled facade for each Run credential profile when adding a routing tool. The project Run stdio test checks both authorized catalog requests and local refusal of the directory tools before REST.
