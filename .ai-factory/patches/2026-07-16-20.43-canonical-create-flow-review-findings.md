# Harden canonical Create Flow review findings

**Date:** 2026-07-16 20:43
**Files:** local-package creation, version-cut service, Studio create routes,
OpenAPI, system analytics, roadmap, and focused tests
**Severity:** high

## Problem

Canonical initial-Flow creation could compensate a filesystem failure by
recursively deleting a path it did not create. Separately, callers could run a
cut precondition before acquiring the mutation lease, leaving a stale window
before export. Malformed JSON on the two create routes escaped validation as a
500 response, and the documented Create Flow request schemas were looser than
the Zod boundary.

## Root Cause

The database row was treated as implicit ownership of the derived working
directory. Cut validation lived at route/caller level rather than at the
irreversible service boundary. JSON decoding was not modeled as a validation
result, and OpenAPI omitted strict object constraints and the collection
create's forbidden response.

## Solution

New package, fork, and default-package creation now claim the working directory
with exclusive `mkdir` before writing. Cleanup removes a directory only after
that claim; a pre-existing path is preserved while the newly inserted row is
rolled back. `cutLocalPackageVersion` now acquires the lease, reloads the
package, and validates the clean committed tree before export. Create routes
return localized-safe 422 JSON validation errors, and OpenAPI mirrors the
strict request contract. Tests cover the preserved path, internal cut gate,
malformed JSON, committed test cuts, and read-only mutation controls.

## Prevention

Filesystem cleanup must be conditioned on explicit operation-local ownership,
not a derived path or database identity. Preconditions protecting irreversible
work must run inside the same exclusive lease as the work. Treat request-body
parsing as an explicit validation step and update the external contract with
the runtime schema.
