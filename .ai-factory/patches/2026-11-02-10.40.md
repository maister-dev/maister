# Explain failed GitHub intake results without losing frozen contracts

**Date:** 2026-11-02 10:40
**Files:** operational result schema/decision/terminal/projection/UI, launch contract and snapshot integration, core intake skill and fixture, OpenAPI and owning documentation.
**Severity:** high

## Problem

Production gh-intake history showed Failed beside “No delivery workspace”, which
looked like the failure cause. Latest run `01b96b00-c6d7-4539-a7e6-2b96fff180a4`
reported partial with counts 18/4/0/4/14/0. Its actual JSON contained confirmed
old task/issue references but only unresolved operation receipts. Validation
correctly rejected it, while the UI retained only `schema_mismatch`.

## Root cause

- Guidance did not make the precise progress predicate and held-source case
  concrete enough. Verification of skipped old imports was mistaken for progress.
- The result decision produced a validation message, but the immutable receipt
  persisted only its generic reason; the shared projection could not recover it.
- “No delivery workspace” conflated normal operational cleanup with failure.
- Frozen-contract reading required today's appendix digest, so an instruction-only
  repair would invalidate old queued/checkpointed runs.

## Solution

Clarify both platform guidance and the core skill shared by gh/MCP transports.
Partial needs completed/created work or a confirmed operation receipt; held
reconciliation without progress is blocked. Preserve counters and effect identity;
do not manufacture progress or weaken result acceptance. Verify the shipped
held-source example through real package installation.

Keep exact original/revised supported v1 digests, self-digest and provenance
checks; retain old instructions on continuation. Store at most 20 safe validator
rule codes and schema-known paths on existing terminal JSON, expose them through
the shared DTO and localize rule/remediation in EN/RU. Rejected values, unknown
keys and raw validator messages never enter the receipt. Invalid output remains
Failed with no usable public result; old receipts remain readable. No migration.
Use neutral “No retained workspace” in history and active execution rows.

## Remaining product boundary

A blocked outcome is not a recovery workflow. The current ask_human operation
requires an existing task; taskless intake cannot use it to resolve a failed
pre-task import. A future grouped Inbox recovery decision must show the affected
sources, recheck all-status task provenance, bind repair approval to exact marker
identities and revalidate before effects. Do not fabricate a task just to ask a
question, auto-delete uncertain markers, or describe this workflow as implemented.
No production markers, tasks or settings were changed during this repair.
