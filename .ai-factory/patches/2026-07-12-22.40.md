**Severity:** medium

## Problem

`/aif-review` of the MCP-management-v2 UI half (T6.2/T7.x) plus an independent
adversarial reviewer surfaced: analytics/screen docs that still tagged the
shipped board dialogs / shared MCP-select / hub e2e as "Designed/Follow-up"
(a contract lie under docs/CLAUDE.md R6); a dead `!res.ok && res.status !== 204`
branch; a "Test connection" button that fired the probe but showed the user
nothing; a ~50-line focus-trap duplicated between `ProjectMcpModal` and the new
`ModalFrame`; and three logic gaps the first pass missed — a `connectable`
filter that hid a legitimate platform candidate, a `recommendedTargetId` that
ignored `platform.enabled`, and a `SOURCE_ORDER` that ranked by the hub's
`package` token while the scratch caller feeds the raw `flow-package`
capability source.

## Root Cause

1. **Doc drift:** the plan's "docs reconcile" step (T8.2) ran during the
   *backend* merge, BEFORE the UI half landed — so the UI-half status tags were
   never flipped. Re-running the as-built reconcile was not treated as part of
   the UI change.
2. **Dead branch / silent probe:** first-implementation gaps — `res.ok` already
   excludes 204, and a fire-and-forget `router.refresh()` discarded the probe's
   `{ok, reason}` body (probe route returns HTTP 200 even on a failed handshake;
   `last_probe_status` is cached but the panel rendered neither it nor
   `readiness_status`, which the probe never updates).
3. **DRY:** a `// kept local — surgical, not a refactor` comment was the author
   confessing duplication that would drift (the exact must-fix the skill-context
   flags).
4. **Two-vocabulary miss:** the shared `McpSelect` consumes `source` from BOTH
   the hub (`platform|project|package`) and raw `capability_records`
   (`platform|project|flow-package`); `SOURCE_ORDER` only listed the former, so
   a `flow-package` group sorted after the free-add `custom` group.
5. **`connectable` / `recommendedTargetId`:** an any-source `servers.some(refId===)`
   and an `enabled`-blind platform lookup — both diverged from the sibling
   `candidatesFor`, which already had the correct predicates.

## Solution

- Docs: flipped the UI-half tags to Implemented in `mcp-management.md`,
  `project-mcps-hub.md` (+ corrected source path `board/mcp-panel.tsx` →
  `board/panels/mcp-panel.tsx`, the drifted servers-column list, and the phantom
  `mcpHub` i18n namespace claim), `screens/README.md`, and the SDD header.
- `act()`: `if (!res.ok)`. Swept the 204 pattern — `mcp-modal.tsx:287`'s
  `res.status === 204` is a *correct* check (its DELETE genuinely returns 204),
  left as-is.
- `testConnection`: now reads the probe body regardless of status, branches on
  `res.ok && payload.ok`, and renders an inline "Testing…" → ✓ latency / ✗ reason
  per ref (`probing` i18n key EN+RU).
- Extracted `useModalFocusTrap(dialogRef, onClose)`; both `ProjectMcpModal` and
  `ModalFrame` call it.
- `SOURCE_ORDER` gained `flow-package`; `connectable` excludes only a
  platform-source projection OR an enabled platform binding (not any-source);
  `recommendedTargetId` gates the platform id on `enabled`; `McpSelect` restores
  type-to-filter (query narrows unselected chips, selected always visible).
- Tests: behavioral `MatchDialog.bind`/`OverlayDialog.save` (fetch-mock DOM),
  `McpSelect` flow-package ordering + query-filter.

## Prevention

- **Phased-feature docs:** when the UI phase of a feature whose backend already
  merged lands, RE-RUN the as-built docs reconcile in the SAME change — a prior
  phase's reconcile does not cover surfaces that did not exist yet. Grep the
  docs tree for the feature's `Designed`/`Follow-up` tags before declaring done.
- **Two-vocabulary components:** when one component consumes an enum from two
  producers (hub DTO vs raw DB source), enumerate BOTH token sets in any
  ordering/lookup table; a standalone repro (`sourceRank("flow-package")`) is
  cheap.
- **Sibling parity:** a new predicate (`connectable`, `recommendedTargetId`)
  built next to an existing one (`candidatesFor`) must apply the SAME guards
  (`enabled`, source-scoped match) — diff them.
- **Every fire-and-forget action shows its result:** a button that POSTs and
  only `router.refresh()`es is silent when the route returns 200-with-a-failure
  body; surface `{ok, reason}` inline.
- **Out-of-scope siblings (recorded, not silently omitted):** the SDD §4.1–4.6,
  `docs/database-schema.md:51`, and `docs/db/projects-domain.md:261` still tag
  already-merged *backend* pieces as "Designed" (pre-existing from the backend
  merge, not this diff). Left for a separate backend-docs sweep per the review's
  own class-A scoping; noted here so a future reader fixes the class, not the line.
