**Date:** 2026-07-27 20:55
**Files:** `web/lib/agents/memory-store.ts`, `web/lib/agents/launch.ts`,

`mcp/src/tools.ts`, `docs/{decisions,system-analytics/agent-memory,system-analytics/assistant-activity,screens/projects/project-settings-agents,api/web.openapi}.*`
**Severity:** critical

## Problem

`/aif-review` of `feature/pulse-agent-memory-files` (ADR-152) surfaced 19 findings.
The load-bearing one: `writeAgentMemoryCas` promised a content-hash
compare-and-swap — the contract the OpenAPI, the domain doc, the ADR **and the
maintenance instruction injected into every agent prompt** all advertise ("if the
write loses the CAS you get the current content back to merge and retry"). It was
a bare `read → compare → write` with nothing holding the interval. Two writers
holding the same `ifHash` both passed the comparison and both wrote; one agent's
memory was silently discarded with a `200`. Measured directly: two concurrent
first-writer calls each returned `ok`, and the surviving bytes varied run to run.

Two further must-fixes: (1) memory was re-injected, re-snapshotted and
`runs.agent_memory_hash` re-stamped on every agent-session **resume**, though
REQ-C4 AC4 / D14 / the domain doc all say "initial spawn only" — so the
provenance column described the last resume instead of what the agent started
from; (2) the provenance write sat inside the spawn `try` whose `catch` finalizes
the run `Failed`, so a full disk could kill a launch that REQ-C5 says memory must
never block.

## Root Cause

**The CAS.** A filesystem has no compare-and-swap. `atomicWriteText` (tmp +
rename) guarantees the file is never *partially* written, and that guarantee was
mistaken for the *serialization* a CAS needs. They are different properties: one
is about torn reads, the other about lost updates. The author reasoned "atomic
write ⇒ atomic CAS".

**Why the test missed it.** The plan explicitly demanded real concurrency
(§6.5) and the route test did launch two genuinely parallel writes — but at the
ROUTE layer both handlers execute an identical sequence of DB round-trips, which
staggers them just enough that one read lands after the other's write. It passed
6/6 runs. The test proved a scheduling accident, not the invariant. It also
asserted only `[200, 409]` and byte-integrity — both of which an unsynchronized
implementation can satisfy by luck.

**The resume.** `startAgentSession` is both the spawn and the resume entry point
(it passes `resumeSessionId` when the run has an `acp_session_id`). The author
read it as the launch path only. No test covered AC4 — the one clause the code
violated was the one clause with no test.

## Solution

- `writeAgentMemoryCas` now takes a db handle and holds a per-`(project, agent)`
  `pg_advisory_xact_lock` across read → compare → atomic write, mirroring
  `social/relations.ts`. Rejected alternatives, both recorded in ADR-152 D26: a
  DB hash column + SQL CAS (splits truth across row and file; a crash between
  them leaves a hash describing bytes never written), and an in-process mutex
  (closes the window only within one Node worker).
- The regression test lives at the **store** layer
  (`memory-store.db.integration.test.ts`), because the route layer structurally
  cannot prove it. Four cases; the decisive ones are "two updates holding the
  SAME hash" and "ten racers", which fail deterministically without the lock.
- `applyAgentMemoryForLaunch` returns early when `run.acpSessionId` is set;
  snapshot + stamp moved into their own WARN-only `catch`.
- The post-write state is captured INSIDE the lock and returned, so no route
  re-reads the file afterwards (a re-read can report the next writer's bytes as
  the outcome of this call).
- 16 further findings: flow-bound agents refused at both `attachAgent` and
  `updateAgentLink`; `nullable: true` → `type: ["string","null"]` in the MCP
  inputSchema (an OpenAPI keyword is meaningless in JSON Schema and a validating
  client would reject the documented first-writer form); batched
  `launchedLineageRunIds` replacing an N-query on a polling endpoint; shared
  `ConfirmDialog` + `useModalFocusTrap` replacing `window.confirm` and a
  hand-rolled trap; typed 404 lookup replacing `err.message.includes(...)`;
  unrelated prettier reflow reverted out of the diff.

## Prevention

- **A "CAS" over a filesystem is a check-then-act until something serializes it.**
  When reviewing any read-compare-write over a non-transactional store, ask what
  holds the interval. `atomicWrite*` answers "is the file torn?", never "can two
  writers both win?".
- **A two-racer test at the wrong layer proves nothing.** Put the concurrency
  test at the layer that owns the invariant. If the racers traverse identical
  I/O, they self-serialize and the test passes for a reason unrelated to the
  code. Always mutation-check a concurrency test by disabling the guard — here
  that flipped 2 of 4 cases red, and revealed the 3rd case (two first-writers)
  passes even unlocked, which is precisely why the original route test survived.
- **An entry point that serves two lifecycles needs an explicit gate per
  lifecycle.** Grep the callers of any `start*` function before assuming it means
  "first time". `resumeSessionId` in the same function body was the tell.
- **Evidence must never be able to kill the thing it describes.** A provenance
  write inside a try/catch whose catch is terminal inverts the priority; it gets
  its own WARN-only catch (the `#try-scope` rule, re-found).
- **Adding a precondition to a shared function breaks fixtures seeded for the
  looser contract.** The `updateAgentLink` guard broke an owner-route test whose
  agent had no resolvable package. Correct the SEED, or — as here — pick a signal
  that needs no new dependency (`agents.flow_ref`, the same column the UI reads,
  one flat read, and it keeps the disable path working when a pin is broken).
- **Integration-suite regression must be judged on NAME sets, never counts.**
  This suite flips ±2 tests run-to-run: the baseline run had 2 failures mine
  didn't, and a worktree test appeared in 2 of 3 of my runs while passing in
  isolation. Only the name-set diff isolated the one real regression.
