# Keep native execution evidence aligned with its owning cases

**Date:** 2026-11-06 16:56
**Files:** `scripts/run-stage-ab-tests.mjs`, `scripts/isolation-ci-evidence.mjs` and their existing tests
**Severity:** medium

## Problem and cause

The production-worker boot owner declares nine controls after adding durable task-launch restart coverage and changing lifecycle composition to four handles. Its native report manifest still required eight cases and the obsolete three-handle title. Even after correcting that manifest, the hosted evidence combiner rejected the new exact total because it independently hardcoded 50 cases.

## Solution

Require the exact nine declared boot controls, preserving every existing required case and strict missing/duplicate/skipped/unexpected-case rejection. The evidence combiner derives its exact total from the existing canonical isolation suite/case manifest. Darwin now requires 51 cases in disjoint parts of 19 and 32; Linux additionally retains its five platform-specific controls for 56. Platform, identity, cleanup, report hash and per-case validation remain unchanged.

The existing script-test owner now constructs a report from the actual boot file's parameterized owner kinds and literal test declarations. It requires all nine and checks that removing each one is rejected, so a successful report assembled only from stale manifest entries cannot hide another declaration mismatch.

## Reproduction and validation

- `/private/tmp/maister-r18-native-manifest-red.log`: the report built from the actual nine declarations fails the unchanged validator because the required three-handle title is absent. Existing inventory totals also expose the missing ninth case.
- `/private/tmp/maister-r18-native-evidence-red.log`: after correcting the case manifest, the existing combined-evidence test fails with actual 51 versus hardcoded 50; seven other evidence checks pass.
- `/private/tmp/maister-r18-native-manifest-green.log`: the complete existing three-file script group passes 35/35 after both fixes. Temporary Unix socket fixtures require OS access; the initial sandboxed invocation failed with `listen EPERM` and is not counted as a product regression.
- `/private/tmp/maister-r18-native-manifest-lint.log`: scoped JavaScript ESLint syntax, unused-variable and unreachable-code checks pass with zero warnings. Root scripts have no project ESLint configuration. `git diff --check` passes.

No production build or native execution lane ran for this correction. A declaration/report validation pass does not establish the native restart behavior; its frozen native qualification remains owned by the coordinator.

## Prevention

When a native owning suite adds or renames a case, update its strict report manifest in the same change. Derive aggregate evidence totals from that canonical manifest rather than maintaining another independent literal count.
