**Severity:** medium

## Problem

An `/aif-review` of the capability-enforcement branch (ADR-129) surfaced a set of
consistency/quality findings that the green suite did not catch. None was a runtime
correctness bug (the 3 real blockers had already been fixed in an earlier pass), but
several were exactly the drift classes this project treats as must-fix:

- **D5 sentinel doc drift (must-fix).** Three docs (a `guardrail-hooks.md`
  Expectations *acceptance bullet*, its mechanics paragraph, and the ADR) still
  described the always-ask halt as keyed off the un-arbitrated `tool_call`
  *notification* — the exact pre-fix behavior a prior blocker (C1) had corrected in
  code. The code halts on the **execution** `tool_call_update` (`completed`/`failed`)
  for a still-pending write. A test written from the stale acceptance bullet would
  re-assert the C1 false-halt.
- **Half-fanned-out enum.** `ScratchHookTripRule` (type) and `scratch-runs/events.ts`
  (encoder) were widened for `capability_guard`, but the *decoder*
  (`parseScratchMessageContent`) still allow-listed only the three older rules, so a
  `capability_guard` scratch payload would decode as raw legacy text.
- **Re-implemented SSOT predicate.** `deriveSessionEnforcementProfile` decided "is
  this class strict-enforced" with an inline `enforcement===strict && table===enforced`
  predicate, duplicating the verdict the launch evidence gate reads from
  `evaluateNodeEnforcement`.
- **Undocumented enforcement boundaries.** The seam only governs permission-gated
  calls (adapter-auto-allowed reads bypass), the D5 backstop is WRITE_KINDS-only
  (excludes `execute`/bash), and the smoke probe's automated `ok` for a *plain* tool
  proves identity is *surfaced*, not *stable* — none stated where a reader would look.
- Minor: audit-snapshot comment claimed it stored the "delivered" profile (it stores
  the pre-facade one); the shared `hookTripNotice` deny label said "write denied"
  (path_guard-centric); two low test-gaps (anti-evasion counter, negative smoke).

## Root Cause

- **Docs drift is invisible to a green suite.** The C1 code fix changed the sentinel's
  trigger event but the reviewed *acceptance contract* prose was never reconciled — a
  documented invariant steers the next implementer back to the old shape, and nothing
  fails a test.
- **A new enum value must be fanned to ALL consumers, encode AND decode.** Widening a
  type + producer without the matching parser is a latent half-fan-out; here it was
  unreachable (scratch carries no `enforcementProfile`), which is exactly why no test
  caught it.
- **Two implementations of one predicate silently agree until one changes.** The inline
  predicate was byte-equivalent to the `evaluateNodeEnforcement` verdict *today*; the
  risk is future divergence between the derivation and the gate that both key on it.

## Solution

- **D5 drift:** rewrote all three spots to state the trigger is the execution
  `tool_call_update` (status completed/failed) for an id still un-arbitrated, with the
  "keys off execution, not the pending notification, so a legit write never false-halts"
  rationale — aligning them to the one edge bullet that was already correct.
- **Enum fan-out:** added `capability_guard` to `parseScratchMessageContent`'s
  allow-list (the parse-result type already permitted it).
- **SSOT:** `deriveSessionEnforcementProfile` now derives the enforced-class set from
  `evaluateNodeEnforcement(...).filter(verdict==="enforced")` — the same function the
  evidence gate consults — and dropped the now-unused `enforcement` field from the
  local `EnforcementBearing` type. Behavior-preserving (enforcement-profile tests
  unchanged and green).
- **Boundary docs:** added an edge bullet + code comments (`acp-client.ts` D5 check,
  `smoke-acp-adapter.ts` summarizer) documenting the permission-gated-only scope, the
  WRITE_KINDS-only D5 backstop (bash covered by the primary path + smoke, not D5), and
  that plain-tool name *stability* is operator-verified. Deliberately documentation-only
  (owner chose document-and-defer over hardening the probe / extending D5 to `execute`).
- **Minor:** corrected the audit-snapshot comment; changed the deny label to "call
  denied, continuing" (EN+RU); added an anti-evasion integration test (mcps-strict
  pass_through interleaved between denies must not reset the breaker) and a negative
  smoke-summary unit test (no stable identity → `error`).

## Prevention

- **When a code fix changes an event/trigger an interceptor keys on, grep the
  Expectations/acceptance bullets for the OLD trigger in the same change** — a stale
  acceptance bullet is more dangerous than stale narrative, because it reads as a
  reviewed invariant. (`git grep` the old phrase — here `"never arbitrated"` /
  `` `tool_call` `` — across `docs/` before exit.)
- **Fan a new enum value to encode AND decode.** After widening a type + producer,
  grep every `=== "<sibling-value>"` allow-list for the sibling and confirm the new
  value joins it; an unreachable miss today becomes a silent drop when the value later
  reaches that path.
- **A capability flag derives from the ONE function that computes it.** Prefer
  `evaluateNodeEnforcement(...).some(verdict==="enforced")` over a re-implemented
  `strict && enforced` predicate — even when they are provably equal today.
- **Document an enforcement boundary where the reader stands.** The "seam sees only
  permission-gated calls / D5 is WRITE_KINDS-only / smoke proves surfaced-not-stable"
  limits belong as comments at the exact check + an Edge-cases bullet, not implied.
