# Terminal agent prompt application must own safe finalization

**Date:** 2026-11-02 18:40
**Files:** web/lib/execution-host/{runtime-object-content,prompt-owner-application,prompt-owner-errors,prompt-application-recovery}.ts; web/lib/agents/{prompt-owner,execution-quiescence,permission-result,finalization}.ts; web/lib/workbench-lifecycle/service.ts; web/lib/scheduler.ts; supervisor/src/http-api.ts
**Severity:** critical

## Problem

Completed agent prompts retained dispatched turns and Running Runs, exhausting
the agent scheduler pool. One command poisoned after five prepare failures;
another renewed application claims and repeatedly deleted its ended session.

## Root Cause

Runtime-object GET capacity and concurrent legacy verification report
`PRECONDITION command_in_progress`. Exhausted inner read retries incorrectly
consumed the outer application failure budget. Supplied deployment logs prove
that path; poisoning was its outcome, not its cause.

Agent application sent a fresh DELETE whenever retained incarnation state was
active, then deferred while canonical lifecycle lagged. Preparation repeated
integrity work and had no deadline. The specific deployment event preventing
Case 2's incarnation closure was not established from the available evidence.
Old DELETE success also did not await observed exit after SIGKILL. Application
diagnostics discarded the original reason/details and stage.

## Solution

Treat read contention as retryable service pressure. Bound preparation and
repeated teardown/finalization deferrals. Reuse exact-fenced DELETE evidence,
project canonical lifecycle before integrity work, and require terminal binding
proof plus fresh host quiescence. Failed application uses existing atomic domain
finalization, turn acknowledgement and command marker, then scheduler promotion.
Unprovable recovery remains visibly poisoned with separate recovery diagnostics.

Validated historical permission-result grants retain their checkpoint proof.
Never-dispatched cancellation has a separate admission-locked proof, authorizing
Abandoned only. Stop refuses a false success after deferred finalization.

Exact-observation CLI rearm retains original terminal evidence and failure
provenance. The persistent web worker applies it; the CLI must not close its pool
under a scheduler launcher dispatched during local finalization. The supported
procedure lives in docs/system-analytics/execution-prompt-lifecycle.md.

## Prevention

Classify errors at their owning boundary before consuming domain retry budgets.
Preserve diagnostics and durable wait deadlines across every retry writer.
Never infer process exit from session absence, successful prompt or old DELETE.
Test claim expiry, duplicate/competing workers, delayed canonical exit, failed
teardown, changed permission grants, pre-dispatch cancellation and actual next
Pending admission with the concurrency cap. Distinguish integrity refusals from
application failures; a valid retained result does not imply a successful Run.

Sibling sweep: `rg -l 'prepareAgentRunFinalization|finalizeAgentRun|stopAgentPromptSession' web -g '*test.ts'`
identified the finalization consumer suites. `createAgentPromptOwners` forwards
ordinary-agent failure recovery through the production consensus registry;
consensus drafts retain their separate round contract. Settled execution fixtures
now establish real canonical teardown; unstarted fixtures exercise cancellation.
