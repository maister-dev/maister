# UI completion batch review findings

**Date:** 2026-07-13 11:21
**Files:** UI-completion SDD/docs; package read model; run stream and promotion components; launch/onboarding, feedback, Studio, navigation, and regression tests
**Severity:** high

## Problem

The UI-completion batch was based on stale `main` and left several review
findings unresolved: a package attachment count could reveal cross-project
membership to non-admin readers; Flow-run detail consumers could open duplicate
SSE subscriptions; header promotion could diverge from the inspector operation;
and several action surfaces could expose raw server details or leave a failed
confirmation busy. The SDD still described the delivered contract as Designed.

## Root Cause

Cross-surface presentation work had independently-owned action and subscription
paths without one narrow shared choke point. The package projection treated an
admin-only advisory aggregation as a generic DTO field, and docs had no final
as-built evidence pass. That made local correctness insufficient: callers with
different visibility and lifecycle constraints were not all held to the same
invariant.

## Solution

Rebased the branch onto current `main`, then applied the review fixes at shared
boundaries. The package affected-project aggregation is opt-in and is requested
only for authorized trust operators. `RunStreamProvider` gives Flow-run child
surfaces one subscription owner, while promotion request construction and
refusal checks live in one shared operation used by both header and inspector.
Launchability, shared confirmation recovery, generic localized error feedback,
and the role-projected mobile rail were reconciled with their existing server
contracts.

Added focused regression coverage for the exact-install count, promotion
payload/refusal parity, stream ownership, first-run launchability, mobile rail
interaction, and localized error rendering. The SDD and screen/domain docs now
record the implemented contract and final validation matrix. No browser logging
was added: existing typed failures and server diagnostics remain the debugging
boundary.

The final real-Postgres run also exposed an incidental over-specified assertion
for an existing upgrade DTO: compatibility metadata is part of that DTO, while
the test's contract is the selected upgrade identity. The assertion now checks
that identity without rejecting legitimate additive metadata.

## Prevention

- For a read-model field with different visibility requirements, make the
  sensitive aggregation explicit at the query boundary and test both the
  default omission and authorized opt-in.
- When two UI surfaces invoke the same irreversible operation, share its
  eligibility and payload builder and cover refusal parity before adding a new
  entry point.
- Treat each screen's EventSource as a single-owner resource; child consumers
  receive context rather than creating their own stream.
- Close SDD work only after source sentinels, lint/type checks, behavior suites,
  docs/contracts validation, and the full browser baseline have been rerun.
