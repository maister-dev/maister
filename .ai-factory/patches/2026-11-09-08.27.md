**Date:** 2026-11-09 08:27 UTC

**Severity:** medium

## Problem

The retained real-package test first received403 launch_interactive_origin_required before model execution. After current admission was used, the actual root Flow failed without a published result; its retained artifact contained only Failed and could not explain the node/command failure after disposable-resource cleanup.

## Root Cause

The live consumer still used the retired one-shot request shape, omitting same-origin authority, immutable task/settings witnesses and a delivery key. Nullable accepted intents were also treated as immediate Run creation. Failure evidence stopped at the result ledger, which is absent when execution fails before publication.

## Solution

Read current authorized launch options, submit one explicit same-origin keyed decision to the canonical intent endpoint, and wait for its exact existing intent/Run association. Reuse the shared Run-binding observer. Retain bounded node/action, normalized terminal-event and command/application metadata before cleanup. Only the exact isolated synthetic database/project/repository may expose failed-node text; strip controls, mask known credential values, reuse the shared evidence redactor, then capture a UTF-8-safe4096-byte tail with truncation and redaction counts. Do not retain raw prompts, vars, request bodies or original output objects. The next capture adds exact UTC lifecycle timestamps, run-bound credential retirement metadata and a restricted token audit projection in one read-only repeatable-read snapshot; it excludes credentials, hashes, prefixes, names, actor labels and endpoint text. Retirement state establishes ordering, not the identity of its caller. Refresh actual adapter arbitration rather than treating an old cache as proof of the current binary.

## Prevention

Treat every installable-package test as a client of current authoritative admission. A successful intent is not a Run or model-start receipt. A failure manifest must include the ledger which can fail before result publication, and it must be captured before owned database/process cleanup. Verify diagnostic scope and secret/path/control canaries against a real database, preserve failed attempts, and distinguish harness repair from successful package qualification.
