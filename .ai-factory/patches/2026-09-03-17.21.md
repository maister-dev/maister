**Severity:** critical

## Problem

A third adversarial review of the tree-budget branch returned five valid
findings. **Two were regressions introduced by my own fix in the previous
commit** (`5aba45dc`), one was a gap left by my partial fix after that
(`bdb18864`), and two were pre-existing defects the original gate fix made
reachable.

1. **(critical, mine)** On a lost root CAS I stamped `notified.tree="terminate"`
   to stop a re-entry re-cascading a gutted tree. `alreadyActioned` compares
   `RUNG_ORDER[prior] >= RUNG_ORDER[rung]` and nothing outranks `terminate`, so
   the stamp **permanently disabled tree enforcement** for a root that is
   non-terminal by definition on that path. I traded a benign harm (the cascade
   is idempotent) for unbounded subsequent spend.
2. **(high, mine)** My singleton skip checked only that run and tree token
   ceilings both *exist*. A stricter tree ceiling (`tree=1000` under
   `run=10000`) was silently ignored.
3. **(high)** The tree-terminate arm had **no run-kind branch at all** while the
   run-scope arm has three. A scratch/agent singleton reaching it via a tree
   wall-clock ceiling got `runs.status='Failed'` with `scratch_runs` still live,
   no `finalizeAgentRun`, and the **flow** pool promoted for an agent slot. The
   arm's header comment asserted "the scratch finalizer is never a tree root" —
   an invariant nothing enforced.
4. **(high)** My abandon pre-check read the status from the route's single
   initial SELECT; five awaits later the cascade ran against a stale value.
5. **(medium)** I edited a frozen 2026-06 spec three times as if it were
   current guidance while its §5 still described behaviour ADR-106/125 replaced.

Plus a self-inflicted 500 during the fix: I wired `expandExecutionPolicy` into
the HITL raise path, which dereferences `policy.preset` on a run with no
snapshot, when the fail-open `budgetFromSnapshot` already existed for exactly
that case.

## Root Cause

**(1) A monotonic idempotency marker was written for an action that did not
complete.** `notified[scope]` is a high-water mark consulted with `>=`. Writing
the top rung means "nothing further can ever be needed here". That is only true
when the terminal transition actually landed; on the lost-CAS branch it had not.

**(2) Redundant measurement ≠ redundant limits.** "A tree of one spends exactly
its own tokens" is a fact about the *meter*. Two different ceilings over the
same meter are two different constraints; the stricter one binds. I generalised
a true statement about the measurement into a false one about the limits.

**(3) A dispatcher grew one arm at a time and the newest never got the
run-kind branch** — and a comment "asserted" the gap away instead of a guard.

**(4) Validate-before-mutate was done, but against stale data.** The check was
in the right place and read the wrong value.

**(5) A frozen planning artifact was treated as a living contract.**

**(6, the 500)** I reached for the general-purpose expander instead of grepping
for the helper the neighbouring code already used for the same input.

**Meta-cause:** each fix cycle was reviewed only *before* it, never *after*.
The fix for finding N in review K was finding 1 in review K+1. Two of five
findings here would not have existed if `5aba45dc` had been adversarially
re-reviewed before commit.

## Solution

- **(1)** Removed the unconditional stamp; the WARN carries the operator signal.
  Test: lost CAS → root resumes → new child breaches → tree still acts.
- **(2)** Skip only when the tree ceilings are **not stricter** than the run's
  (`tree.escalate >= run.escalate && tree.hard >= run.hard`). **Landed together
  with a coupled raise** — `coupledRaiseOverride` in `budget-breach-fork.ts`
  lifts `tree.maxTokens` alongside a raised `run.maxTokens` when tree was not
  already stricter — because fixing (2) alone reintroduces the raise-then-kill
  regression: after a raise the unraised tree ceiling *becomes* the stricter
  one. A deliberately tighter tree ceiling is preserved (no tree override is
  written, so the snapshot's stricter value stays effective).
- **(3)** The tree arm now mirrors the run-scope arm's three arms after the
  cascade: agent → `finalizeAgentRun` (which also promotes the agent pool),
  scratch → `markScratchCrashed`, flow → `markNodeFailed(BUDGET_EXCEEDED, tx)`
  inside the existing root-CAS transaction. The false "never a tree root" claim
  is gone.
- **(4)** Re-read the status immediately before the cascade. **Codex's remedy —
  CAS the root first — was rejected on evidence:** it would make abandon the only
  inverted caller of six; today's partial state has a tested reconcile backstop
  (M-2, `reconcile-sweep.integration.test.ts:979`) while the inverted one is
  recovered only for a `Running` child; `reapAbandonedRunSessions` never flips
  rows; and `auto_launch_run_plan` could launch a fresh child into an abandoned
  tree mid-window. The doc now states the achievable guarantee, not an absolute.
- **(5)** A supersession banner naming ADR-106 (`onBudgetBreach`) and ADR-125
  (four-option fork) and pointing to `execution-policy.md` as canonical. The
  frozen body is amended, not rewritten.
- **(6)** `budgetFromSnapshot` — the same helper the watchdog uses.

## Prevention

- **Never write a terminal idempotency marker for a transition that did not
  land.** If the CAS lost, the marker belongs to the winner, not to you.
- **Before skipping a meter as "redundant", ask whether the *limit* is
  redundant, not just the measurement.** Compare the ceilings.
- **A coupled default needs a coupled raise.** Anything that seeds two ceilings
  from one value must lift both, or one becomes a trap after the first raise.
- **A comment that asserts an invariant is a missing guard.** "X is never Y
  here" — grep the candidate query; if nothing filters Y, add the branch.
- **A pre-check must read the value it checks at the moment it matters** — a
  status fetched five awaits earlier is a hint, not a guard.
- **Before inverting an ordering to close a race, enumerate the recovery for
  the *new* partial state.** A window with a tested backstop beats a window
  with none, even if the second looks narrower.
- **Grep for the helper the neighbouring code uses on the same input before
  introducing a stricter one.** `budgetFromSnapshot` was one grep away.
- **Adversarially re-review every fix cycle, not just the original change.**
  The fix is a change too.
- **Cross-reference the canonical contract before editing a frozen spec** —
  or add a supersession banner instead of editing at all.
