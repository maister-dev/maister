# Revalidate automatic agent intent and serialize interrupt decisions

**Date:** 2026-11-04 12:30
**Files:** `web/lib/tasks/launch-agent-execution.ts`, `web/lib/services/hitl.ts`, their owning integration suites and task-launch/HITL analytics
**Severity:** medium

## Problem

A queued bearer-created standalone agent could bind a Run after its task's
automatic arm was withdrawn. Separately, real session-create ACK projection
and node-interrupt restart could deadlock while locking the same Run and attempt
in opposite orders. The full integration incident's later stale-handler 409 is
a separate valid refusal; this fix does not reinterpret it as success.

## Root Cause

Agent dispatch treated a bearer origin like a server-owned scheduled decision,
skipping the independent automatic-arm check required at acceptance. Its semantic
and settings digests deliberately exclude that mutable arm, so they could not
close the gap. Flow dispatch already used the correct distinction.

Create ACKs lock Run before attempt. The interrupt restart instead changed the
parked attempt before updating Run. Production graph traversal already acquires
Run first through its driver database, so its finish-continuation helper was not
the inverse owner. The actual inverse transaction was the HITL restart claim.

Changing restart alone also exposes stop/resume siblings: those claims hold HITL
while inserting assignment events whose Run foreign key takes a row lock. All
same-card decision claims therefore need the same Run-first order.

Independent review also found that a full initial `FOR UPDATE` blocks public
assignment-event foreign keys while the public claim holds its assignment row.
The HITL close then waits for that row, producing another real deadlock. The
owner-order fence needs `NO KEY UPDATE`, not a stronger early lock.

## Solution

Only server-owned execution sources retain the standalone-agent arm exception.
Bearer roots repeat the current automatic-arm check before preparation and first
dispatch. No accepted assessment, snapshot or server-source policy is rewritten.

A private SQL-only helper locks Run `FOR NO KEY UPDATE` before every
node-interrupt Phase1 claim: restart-node, restart-from, stop and resume. This
still serializes ACKs and other owners while allowing public assignment-event
`KEY SHARE` locks to complete. Restart closes and holds all active human
assignments before placement upgrades Run to `FOR UPDATE`. Existing decision,
current-attempt,
forward-skip, authorization and replay checks remain. Filesystem/host effects
remain outside these transactions. The graph finish-continuation path is unchanged.

## Prevention

Reconcile all target kinds against the same admission basis instead of treating
credential provenance as a separate authorization policy. Include foreign-key
row locks when auditing lock order, and inspect every competing decision on the
same resource before changing one transaction's acquisition order.
