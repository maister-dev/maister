# Completed-work no_progress accounting and checkpoint causality

**Date:** 2026-11-03 11:52 Europe/Moscow
**Files:** supervisor/src/{guardrail-progress,guardrail-hooks,acp-client,http-api,registry,heartbeat,types}.ts; web/lib/{flows,execution-host,runs,run-transcript,scratch-runs}; existing HITL controls; wire contracts and regression fixtures
**Severity:** high

## Problem

Ordinary investigation exhausted no_progress at 15 pending tool starts. Intentional guardrail checkpoint termination rejected an in-flight prompt as ACP_PROTOCOL and obscured the pause in command application and UI. Deployment reports identify run 5813d455-7b4f-4557-9520-ece04131048e and command e1e423d7-7192-4c8c-a7c3-51497a7fe503; the short elapsed interval is not evidence of a network timeout.

## Root Cause

The watchdog counted notification starts rather than settled tool IDs and recognized only mutation kinds as progress. A separate denial tick could double count. The prompt catch translated only pressure checkpoints; generic route checkpoints lost their intentional cause. Cancellation flags and pending tools also needed explicit prompt-boundary cleanup.

## Solution

A pure ledger merges metadata by ID, counts terminal work once, credits novel successful mutation requests or novel investigation request/result pairs, and retains hashes rather than content. Failures, definitive denials, unsolicited cancellations and unproven completions consume the budget. Starts and duplicate updates do not. Unknown IDs are diagnosed and skipped because they cannot be deduplicated safely. At threshold the current parallel cohort receives at most one additional threshold of settled work; new calls cannot prolong grace. Novelty is bounded to 4096 hashes and recent summaries to ten; pending-only hangs remain owned by duration/resource guards.

Default no_progress is 150, configurable through MAISTER_HOOK_NO_PROGRESS_TURNS and per-node/agent settings.hooks.noProgress.maxTurns. Repetition remains independently bounded at 5. Human Resume is unchanged.

Checkpoint attribution requires prior registry intent while the ACP transport was open and the SDK's exact transport-abort identity. Explicit adapter errors, output failures and unexpected disconnects retain their errors. CHECKPOINT/session_checkpointed plus the original stop reason flows through durable terminal/receipt order and STEP_CHECKPOINTED application; pressure compatibility stays intact. Intentional teardown drains are excluded from watchdog accounting. Prompt admission clears stale cancellation intent, and completion retires pending IDs without inventing work.

Threshold, operation counts, resets, pending/ignored updates and bounded safe summaries reach the existing EN/RU NeedsInput card.

## Regression Evidence

Before implementation, both pending and useful investigation protocol cases failed (expected zero trips, received one), and intentional in-flight checkpoint failed (expected CHECKPOINT, received ACP_PROTOCOL); unexpected-disconnect control passed. Additional adversarial regressions reproduced idle-cancel disabling the next watchdog and checkpoint-drain tool failures replacing checkpoint with no_progress before their fixes.

Validated: full supervisor unit suite; full supervisor integration suite with two workers; final directly affected checkpoint/lifecycle/guardrail integration suite; web decoder/UI/config unit tests and real PostgreSQL escalation tests; web/supervisor/MCP typechecks, MCP build, scoped lint, docs/contracts validation and diff whitespace. Initial unrestricted integration concurrency produced one 50ms TERM-resistant teardown failure; isolated and bounded-concurrency runs passed without weakening the lifecycle assertion.

## Prevention

Protocol fixtures must emit realistic pending/completed updates. Test terminal-ID deduplication, sparse metadata, read-only investigation, unchanged/volatile results, rolling parallel work, real cancellation followed by another turn, intentional teardown drain, unexpected transport loss, and explicit unrelated errors racing a checkpoint. Never infer intentional cause from connection-error text or elapsed time.
