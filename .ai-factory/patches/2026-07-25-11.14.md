# /aif-review fix batch: controlled-launch fidelity trio + idempotency + contract/test/doc drift (ADR-150)

**Date:** 2026-07-25 11:14
**Files:** web/lib/evaluations/{slot-threading.ts (new),launch-seam.ts,preflight.ts,launch-batch.ts,recipes.ts}, web/app/api/projects/[slug]/evaluations/studies/[studyId]/launch-batches/route.ts, web/lib/runs/auto-delivery.ts, web/lib/services/hitl.ts, web/messages/{en,ru}.json, docs/{api/web.openapi.yaml,database-schema.md,db/erd.md,db/evaluations-domain.md,system-analytics/evaluations.md}, +4 test files
**Severity:** medium

## Problem

A comprehensive `/aif-review` of the merged Experiments→Evaluation Lab cut-over (ADR-150) surfaced, in the NEW controlled-launch feature, one HIGH + six MEDIUM + LOWs that all shared one theme — a launch surface that was wired but under-enforced:

- **H1** a `mode:"runner"` hard-pin on a non-`session:` slot (e.g. a `consensus:` participant, the archetypal model comparison) was **silently dropped** by the seam AND passed preflight clean — green preflight, wrong runners, invalid comparison evidence.
- **M1** preflight was advisory-only: the launch route/seam never invoked it, so a caller who skipped the preview could launch an un-vetted recipe (only `launchRun`'s flow-launchability re-check gated anything).
- **M2** inline recipes were keyed by `inline-${Date.now()}-${index}`, so an idempotent retry minted new recipeIds → different request digest → `409` + orphan recipes (or a double-launch on reopen) — the key did the opposite of its purpose on the primary UI path.
- **M4** the launched participant's `runIdentity.flowRevisionId` recorded the recipe's DECLARED pin, but the run resolved its flow from the task's LIVE revision → provenance attributed results to a revision that didn't produce them.
- **M3** the `EvaluationPinOption` OpenAPI schema (re-authored during the pin-options port) diverged from the handler (`label`/`isLocalCut` vs the real `packageName`/`kind`) — a regression from the correct legacy schema.
- **M5** the launch-precondition gating (kill-switch / decided / archived / no-flow) had no test.
- **M6/L7/L8** `database-schema.md` still listed the dropped `experiments`/`experiment_runs` as current cascade participants + Implemented indexes; a test-proof cited `0000→0119` instead of `0120`; the ERDs omitted the additive columns. **L9** two lineage comments described the removed two-leg union as current.

## Root Cause

- **H1/M1 (the deepest):** the F2 hard-warn principle ("if the seam can't honor a declared input, preflight must WARN, never silently pass") had been applied to `mode:"intent"` slots but NOT to `mode:"runner"` pins the seam also can't thread, and preflight itself was **never on the launch path** — it was a separate advisory route the UI *optionally* called. Two half-measures (warn-only-intent + advisory-only-preflight) left a hole that either alone would have closed.
- **M2:** non-determinism (`Date.now()`) was injected UPSTREAM of a digest-based dedup keyed on the downstream ids — the idempotency contract can only hold if every input to the digest is reproducible from the idempotency key.
- **M4:** a documented co-evolve deferral (pinned flow-revision not threaded) was allowed to also govern the PROVENANCE record — a fidelity gap silently became a data-integrity lie because the record copied the intent, not the outcome.
- **M3:** a schema re-authored from memory during a namespace port, not derived from the handler; `validate:contracts` checks YAML/`$ref` validity, never response-shape-vs-code, so the drift passed the gate.
- **M6:** a table-drop's doc reconciliation swept the top-level catalog + entity blocks but missed the later cascade-tree + index-catalog sections — a retirement is a contract-WIDE sweep, and two sections drift independently of the primary prose.

## Solution

Owner chose "fix all, trio minimal (make-it-loud, no big threading)". Every finding verified against source before editing (all confirmed real).

- **H1:** new pure SSOT predicate `isSeamThreadableSlot(slotKey)` (`session:` only), consumed by BOTH the seam (which pins it threads) and preflight (which pins it must warn) so they can't drift; `checkSlotTarget` now emits a `slot_runner_pin_not_threaded` WARNING for an available runner pinned to a non-`session:` slot. RED-first preflight unit test (consensus pin → warning, session pin → none).
- **M1:** the launch route now runs `preflightStudyRecipe` on every inline recipe and BLOCKS on any hard refusal before any write (scoped to the inline path — the primary UI concern; recipeId reuse references already-vetted recipes; keeps route-test blast radius to zero since no route test posts inline). Route integration test: inline recipe with an unresolvable flow → blocked 4xx, never 201.
- **M2:** deterministic inline key `inline-${idempotencyKey}-${index}` + an opt-in `returnExistingOnKeyConflict` on `createControlledRecipe` (off by default, so an explicit create still 409s) — an idempotent retry now resolves to the same recipeId → same digest → `deduped:true`. RED-first lib test.
- **M4:** the drive reads the run's ACTUAL `runs.flowRevisionId` post-seam and records that (keeping `flowRefId`, which is stable); falls back to the declared pin only if the run row is absent.
- **L1 (bonus, same file):** `finalizeBatchStatus` now recomputes under a `FOR UPDATE` batch-row lock so two concurrent fire-and-forget drives (create + retry) can't clobber a terminal status into a permanent `launching`.
- **M3:** rewrote `EvaluationPinOption` to the handler's real shape; `validate:contracts` green.
- **M5:** 4 `renderToStaticMarkup(ControlledLaunch)` gating tests (each disabled reason + the enabled case).
- **M6/L7/L8/L9:** removed the stale cascade/index rows, fixed `0119→0120`, added the additive columns to both ERDs, reworded the two lineage comments to drop the removed leg.

**Consciously deferred (recorded, not silently omitted):** L2 (rewire new components to the shared `useFeedback` provider) and L4 (icon-affordance on a few text-only buttons) are house-style polish with test-context/regression risk disproportionate to a LOW — flagged for a dedicated UI pass. L5 (`item.errorReason` in a chip tooltip) is a **non-issue**: `launch-batch.ts` persists a bounded typed `errorCode` there, not raw error text.

## Prevention

- **A "co-evolve deferral" that claims a safety net is a claim to VERIFY, not documentation** — apply the F2 hard-warn rule to EVERY un-honorable declared-input class (intent AND runner pins), and enforce the validation layer ON the action path, not merely as an optional preview. A warn-only-on-one-variant + advisory-only-gate leaves a hole either alone closes.
- **Idempotency dies if any digest input is non-deterministic** — when a key feeds a digest, every upstream value must be reproducible from the idempotency key; never inject `Date.now()`/random above a dedup.
- **A provenance record must capture the OUTCOME, not the intent** — when the seam can't honor a pin, record what actually ran (query the row), don't copy the declared value.
- **Response-shape-vs-code drift is invisible to `validate:contracts`** — after porting/re-authoring a schema, diff it field-by-field against the handler's return (and against the pre-port version, which may have been correct).
- **A table drop is a contract-WIDE doc sweep** — grep the whole `database-schema.md` for the token across the cascade tree, the index catalog, AND the narrative; each drifts independently, and a self-contradicting file (drop narrative + "Implemented" index rows) is the tell.
- **Route-preflight blast radius is bounded by scoping to the inline path** — lib tests that call the batch API directly bypass route enforcement; check whether any route test posts the enforced shape before assuming churn.
