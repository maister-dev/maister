# A denied read is not a verdict, and a pre-transaction read is not evidence

**Date:** 2026-09-23 16:55
**Files:** web/lib/execution-host/prompt-reconciliation.ts, web/lib/reconcile-evidence-db.ts, web/lib/runs/turn-lost-boundary.ts, web/lib/__tests__/reconcile-host-evidence.integration.test.ts, web/lib/runs/__tests__/turn-lost-boundary.integration.test.ts, docs/decisions/adr-177.md, docs/decisions.md, docs/system-analytics/{reconciliation-gc,execution-prompt-lifecycle,runs}.md, .ai-factory/plans/claude-flow-progression-host-decoupling-216849.md
**Severity:** high

## Problem

Codex adversarial review of the ADR-177 / host-evidence branch, both findings reproduced on real Postgres before any edit:

1. On a lost stream the reconcile sweep offers a `completed` turn to host-span settlement, then crashes it `stream-lost` if the offer did not settle it. When another reader held the settlement claim (or its 5 s retry delay was pending, or the host stayed busy), `reconcilePromptCommand` returned without reading anything, and the sweep crashed the run while that reader was settling a readable result.
2. `applyTurnLostBoundary` read the command's `application_state` BEFORE its transaction. A gate the owner applied after classification read as "already discharged", and a gate's attempt close admits the action's completion, so a passed gate crashed its run. A command a host-span reader settled after classification still had `completion_applied_at IS NULL`, so the CAS stamped it applied and discarded the result.

## Root Cause

Both are the same wrong belief: that the absence of a result at decision time means no result is coming. In (1) "not settled after the offer" conflated "the span was read and refused" with "the read never happened"; the return type carried no way to tell them apart (`receiptRead: "not_due"` was returned on both the held-claim and the backoff paths). In (2) the boundary's guards each protected ONE writer — `action_completion IS NULL` the action owner, `completion_applied_at IS NULL` a second discharge — and the gate refinement removed the first while "already applied ⇒ discharged" removed the second, leaving the gate path with no guard at all. The existing test for "already discharged" seeded `applied` WITHOUT the quarantine the only legitimate writer (`quarantine()`) always stores — a lenient seed that certified the hole.

## Solution

1. `reconcilePromptCommand` reports `hostReadDeferred` (claim not acquired on either claim path, or `attemptHostSpan` answering `"busy"` after its bounded re-reads). The resolver returns the stream bound as not holding for that tick, so the classifier SKIPs `evidence-pending`. Transport failures stay refusals (they cannot be told from a host gone for good; a version mismatch would otherwise defer forever). Bounded without a timer: claim 30 s, backoff 5 s, and a prompt wait exits on the lost stream.
2. The boundary locks the command row LAST in its transaction (the owner application's own order, so no new cycle) and re-classifies it with the pure D1 derivation, no probe. `CRASH_EVIDENCE` maps each reason to the classes that still justify it; anything else throws `TurnLostCasLost("command", observed)` and rolls back. Only `quarantined` may already be applied.

Falsified: 4 mutations, each red for its named reason; restored and marker-grepped after each.

## Prevention

- A result type that feeds a terminal decision must distinguish "answered no" from "did not ask". Grep every caller for the decision it makes on the negative branch.
- A crash/discard boundary re-reads the evidence it acts on under a row lock inside its own transaction. A pre-transaction read is a hint, not a guard.
- When a refinement removes one guard for a legitimate case (admitting a completed action for gates), list which writer that guard was protecting against and name the guard that now covers it.
- A fixture for an "already X" state must carry every column the real writer of X stores; seed from the writer, not from the column you check.
- Barrier tests: park the concurrent reader with the fake's `onCall` hook, and release it in `finally`.
