# Fix: Experiment Comparison Studio review follow-up

## Problem

Review follow-up identified remaining Experiment Comparison Studio defects after
the first repair pass:

- Experiment member launch could still create a worktree before observing a
  concurrently terminal experiment.
- Diff snapshot capture treated file-metadata failures as total evidence loss.
- External experiment advisory attribution was body-claimed, and all agent
  tokens with experiment scopes could use the judge surface.
- The comparison UI pair selector did not constrain rendered diff panes, and
  the Files "Different" count did not match displayed single-sided rows.
- The experiment lab page hid all comparison read failures as not-found and
  eagerly prepared every diff snapshot.

## Root Cause

The affected code paths each had a missing boundary alignment:

- The member launch row-lock check existed only inside the run insert
  transaction, after worktree creation.
- Snapshot text and git file metadata were fetched as one all-or-nothing
  `Promise.all`.
- The external advisory schema mixed untrusted request input with server-owned
  token identity.
- UI tab state and server-side diff preparation had duplicated selection logic.

## Fix

- Added pre-worktree experiment membership launchability validation while
  preserving the transaction-time re-check.
- Made metadata capture best-effort after text diff success, with structured
  fallback logging and patch-derived file summaries.
- Moved the experiment judge id into a lightweight constant, restricted
  experiment agent-token callers to the package-sourced judge, removed
  `agentRunId` from the external request body/MCP facade, and derive advisory
  attribution from `TokenActor.boundRunId`.
- Added a pure comparison selection helper and reused it in the tabs and page.
- Let non-not-found comparison read failures propagate from the page.
- Updated OpenAPI, MCP descriptions, screen docs, and analytics expectations.

## Tests

- Added/updated focused tests for member-launch side-effect ordering,
  diff-metadata fallback, advisory attribution/authorization, comparison
  selection, pair rendering, and Files filter counts.
- Verified focused web tests, MCP facade tests, typecheck, docs validation, and
  the full web unit suite.

## Prevention

- Keep experiment route schemas free of server-owned identity fields.
- Keep comparison selection in `web/lib/experiments/comparison-selection.ts`
  so rendered diff panes and server-side preparation cannot drift.
- When a best-effort metadata source fails after primary evidence is available,
  preserve the primary evidence and log the fallback instead of dropping the
  whole artifact.
