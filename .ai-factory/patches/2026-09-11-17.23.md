# M51 review remediation: an unscoped queue source, two contract drifts, a committed VAPID key, and twelve follow-ups

**Date:** 2026-09-11 17:30
**Files:** web/lib/queries/portfolio.ts, web/lib/queries/decisions.ts, web/lib/queries/__tests__/decisions.integration.test.ts, docs/api/external/operations.openapi.yaml, docs/api/web.openapi.yaml, web/playwright.config.ts, web/e2e/push-notifications.spec.ts
**Severity:** high

## Problem

Four blockers from `/aif-review` of `feature/m51-see-everything`:

1. The project page's "needs you" count reported every visible project's HITL.
   `computeDecisionsQueue` scoped three of its four sources with `projectIds`
   and called the fourth, `getCrossProjectHitlInbox(userId, globalRole)`, with
   no scope at all. Proven on a live database: with the fix reverted the new
   assertions fail with `expected [ …(5) ] to not include '<secondProject>'`.
2. Ten OpenAPI entries across two contract files were tagged `(Designed ADR-168/172)`
   for routes that ship and are tested in the same branch. `master` had zero
   `(Designed` tags in that file.
3. `GET /api/attention/stream` had an AsyncAPI channel but no OpenAPI path entry,
   so its auth surface, resume parameters and close semantics were undocumented.
4. A real generated VAPID private key was committed in `playwright.config.ts`.

## Root Cause

1. **An asymmetric source signature.** Three of the four decision sources take
   `projectIds` as their first argument; the fourth resolves its own visibility
   internally and had no parameter to narrow it. The shape of the call site made
   the omission invisible — four entries in one `Promise.all`, three carrying an
   argument the fourth structurally could not accept. The covering test could not
   catch it because the fixture had exactly ONE visible project, which makes
   "scoped to that project" and "not scoped" the same query; its assertion
   (`scoped.count === all.count`) passed in both worlds.
2. **A spec-first milestone that never re-ran the reconcile over the contract
   form.** The tags were written in Phase 1 when the routes genuinely did not
   exist. The Phase-8 as-built pass updated analytics prose and ADR amendments
   and touched no `*.openapi.yaml` / `*.asyncapi.yaml` file, so the status flip
   covered one FORM of the claim and missed the other.
3. **The SSE convention lives in two files and only one was written.** Both SSE
   precedents carry an OpenAPI entry for the handshake plus an AsyncAPI channel
   for the frames. Adding the second half looked complete because the dedicated
   contract validator for the new channel passed. No gate enumerates
   `app/api/**/route.ts` against OpenAPI paths.
4. **A justification that outran the test.** The key was added to make
   `pushManager.subscribe` work in a real browser; the suite then discovered that
   call can never resolve headless and switched to POSTing synthetic endpoints —
   but the config comment (and the spec's own file header) kept the original
   rationale, so the key looked load-bearing. `isPushConfigured()` tests presence,
   never validity, so any non-empty string always sufficed.

## Solution

1. `getCrossProjectHitlInbox` gained an optional `scope` that is INTERSECTED
   with visibility (`allVisibleIds.filter(...)`), never widening it; the queue
   passes its own `scope` through. `DecisionsScope` is now a type alias of
   `CrossProjectHitlScope` so the two cannot drift. The fixture gained a second
   VISIBLE project holding its own respondable HITL — the discriminant — plus a
   test that scopes to the project holding only a HITL and asserts one item of
   one kind.
2. Flipped all ten to the per-file house form (`(ADR-NNN, Implemented)` in the
   ext contract, `(Implemented, ADR-NNN)` in web), then grepped to zero.
3. Added the `/api/attention/stream` path entry modelled on
   `/api/runs/{runId}/stream`: auth-first note, `Last-Event-ID` header and
   `lastEventId` query fallback with the canonical decimal pattern, the three
   event names, the five-minute quiet cap, the SSE headers, 401/403, and a
   pointer to the AsyncAPI.
4. Replaced both values with shape-valid base64url placeholders and corrected
   the config comment AND the spec's file header, which contradicted the note
   200 lines below it in the same file.

## Prevention

- **A read model whose sources take the scope differently will lose one of
  them.** When one source of an aggregate resolves its own authorization or
  visibility set, give it the same narrowing parameter as its siblings rather
  than trusting the call site — a source that structurally cannot accept a
  scope will silently ignore it.
- **A scope test needs two members on the wide side.** `scoped.count ===
  all.count` over a one-project fixture asserts nothing. Ask of every filter
  test: is there a row the filter must REMOVE, and does the test name it?
- **An as-built reconcile enumerates FORMS, not documents.** A status claim
  lives as analytics prose, as an ADR line, as an OpenAPI `summary`, and as a
  schema `description`. Grep the label (`(Designed`), not the feature.
- **A new route is two contract surfaces when it streams.** Diff a new SSE route
  against an existing one in BOTH `docs/api/*.openapi.yaml` and
  `docs/api/async/*.asyncapi.yaml`; no gate enumerates routes against paths.
- **When a comment justifies a secret, verify the justification still holds.**
  Here the code the rationale described had already been replaced. Before
  committing any key material, ask what would break if the value were the string
  `"placeholder"` — if nothing, it must be a placeholder.

## Second pass — the twelve non-blocking findings

Fixed in the same session, grouped by the pattern each belongs to.

**A union member with no behaviour (S1).** `PushOutcome` declared `terminal`
and documented it as "dead, never retried", but the caller collapsed it into the
same argument shape as every other outcome, so `classifyResult` — which sees only
a status — scheduled a retry. A `403` was re-sent across the whole 24-hour curve.
`FinishInput` gained an explicit `terminal` flag (the one verdict a status code
cannot yield), and `408`/`429` were carved out of the terminal arm by name: they
are the two 4xx that mean "later", and collapsing the range would have dropped a
notification under rate limiting. Both arms now have tests; the terminal one was
falsified (`expected 'pending' to be 'dead'`).

**Writes a transaction deletes (S2).** The `410` path inserted an attempt row and
stamped the delivery `dead` before deleting the endpoint, under a comment saying
this preserved the audit trail. Both cascades — `push_subscription_id` and
`delivery_id` — remove those rows in the same transaction; the suite already
asserted it (`expect(await pushRow(eventId)).toBeUndefined()`). The delete is now
the whole operation.

**Claims louder than their mechanism (S11).** "Idempotent across two sweeps
racing" was true only because `system_sweep` is a scheduler singleton, and
`ORDER BY … id DESC` over a random uuid is a stable tiebreak that says nothing
about recency. Both comments now name what actually holds them.

**Surface nobody consumes (S5).** `useAttentionStream` returned `decisions`,
`updates`, `projectIds`, `lastEventId` and took an `enabled` option; its single
consumer reads four fields and passes nothing. The wire shape is ADR-locked, so
the HOOK shrank — re-exposing the counters client-side would have been a second
source for a number ADR-168 D8 says has exactly one.

**Three spellings of one format (S6).** The route's cursor regex, the client's,
and the AsyncAPI `pattern` were written independently, and the client's rejected
`0` where the route accepts it. One exported constant in `lib/sse/frame.ts`.

**Other:** `NOT_FOUND` replaces a stray `CONFLICT` on the ext 404s, matching
every sibling route (S4); `readersOf` resolves once per distinct project instead
of once per event (S8); the three unread classifier inputs say so and say why
(S7); `attention.md` and `work-stages.md` gained the R6 status tag and an
As-built section their milestone siblings already had (S9); the opt-in pair got
icons and a danger tone per `rules/frontend.md` (S10); the service worker
restricts its navigation target to a same-origin path and compares resolved URLs
instead of `endsWith` (S12).

**One self-inflicted bug, caught by typecheck:** a comment added inside the
service worker's TEMPLATE LITERAL contained backticks and terminated the string.
Anything written into `app/sw.js/route.ts`'s worker source must avoid backticks
and `${`.
