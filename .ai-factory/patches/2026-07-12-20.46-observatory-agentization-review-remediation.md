# Observatory agentization review remediation

**Date:** 2026-07-12 20:46
**Files:** promotion evidence, managed-worktree provenance, repository scanner, Observatory queries/components, migration `0098`, contracts, and tests
**Severity:** high

## Problem

The initial feature branch left review-blocking gaps: no end-to-end repository
denominator scanner or project Agentization panel, ambiguous shared-worktree
evidence ownership, scheduler contract/runtime drift, and delivery statistics
that could diverge from target-branch history after rebase or squash.

## Root Cause

The work had been implemented as disconnected feature slices. Its original
read-only analytics contract depended on three coupled facts—provenance that
survives Git sync, exact final target evidence, and a background-only
denominator—but the initial code and tests did not close those seams together.
Run-kind scoping also had no explicit contract for flow-ledger panels versus
cost, budget, and delivery output.

The subsequent full unit sweep also exposed two incomplete closed-set edges:
the new scheduler kind was absent from the admin locale map, and the existing
promotion-route fixture did not provide the new provenance/history seams.

## Solution

Implemented the complete SDD: strict worktree-scoped provenance hook/template
installation and repair; root-owned final evidence with crash recovery;
path-cleaned first-parent delivery history; a poison-isolated cached scanner
with provider-backed PR finalization; kind-aware, cache-only project
Agentization/funnel queries and UI; and matching schema, API, analytics, ADR,
and bilingual contracts. The repair uses existing typed failures and service
boundary logging rather than adding `console` output to pure/read modules.
The final pass adds the scheduler labels and makes the route fixture assert the
provenance argument while supplying the new recovery/stat dependencies.

## Prevention

- Treat provenance, final evidence, scanner cache, and Observatory rollup as
  one contract and test each boundary at its owning layer.
- For shared worktrees, persist delivery evidence only on the immutable root
  allocator row; never infer a child split.
- Keep page reads cache-only and verify no Git or scheduler call enters the
  Observatory query path.
- When a scheduler kind is added, audit every closed-set registration,
  lifecycle, claim, dispatch, admin, OpenAPI, and localized-label fanout.
- When a promotion service gains a required dependency, sweep every route-level
  module mock and assert the new production argument rather than relying on a
  permissive old stub.
- Keep flow-ledger metrics explicitly flow-scoped; use run-kind joins for
  cost/budget rather than denormalized historical columns.

## Verification

- Focused real-Git, promotion, scheduler, parser, rollup, component, and page
  contract suites pass; typecheck, docs/contracts validation, ESLint, and
  whitespace gates are rerun in the fix close-out.
- The full web unit suite has 6,411 passing tests. Its only two failures need a
  loopback listener, which this sandbox rejects with `EPERM`.
- Testcontainers suites cover scanner/job/query integration and are listed;
  their execution requires a working container runtime.
