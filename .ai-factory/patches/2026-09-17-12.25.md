# Conditional unmount discarded an unsent HITL answer; a requirement read unconditional but was implemented conditionally

**Date:** 2026-09-17 12:25
**Files:** web/components/work/work-rows-table.tsx, web/app/(app)/page.tsx, web/messages/{en,ru}.json, docs/system-analytics/home-navigation.md, web/app/api/runs/__tests__/takeover.test.ts
**Severity:** high

## Problem

Eleven findings from `/aif-review` on the ADR-174 Desk rebuild. Two were
materially worse than their first classification:

1. **Unsent-answer loss.** The Desk's expanded row rendered its panel with
   `{canExpand && open ? <tr>…</tr> : null}`. The panel carries `RunHitlResponse`
   — the HITL answer form — so collapsing a row unmounted the form and silently
   threw away a half-typed response. Re-expanding also re-fetched
   `inbox-context`, contradicting `REQ-D16`'s "first expand only".
2. **A MUST that only held sometimes.** `REQ-D14` says `Executing`/`Queued` rows
   expand to "that run's recent events". The code filtered `feed.rows` — the
   cross-project activity feed, capped at `ACTIVITY_FEED_DEFAULT_LIMIT = 100` —
   and returned `null` when nothing matched, so the row lost its expand
   affordance entirely. Which rows were expandable therefore depended on *other
   projects'* activity.

Plus: a drag-select ending on a row expanded it; the owning analytics doc still
listed the removed regions; `aria-controls` and a focus ring were missing on a
row that had become a keyboard control; and the `$stage` placeholder had no
guard.

## Root Cause

**1 — the default React idiom is wrong for stateful panels.** Conditional
rendering is the reflex for "show when open", and it is correct for presentational
content. It is wrong the moment the hidden subtree owns state a user created.
Nothing in the type system distinguishes the two, and the panel had been
*extracted from a card* whose own expansion used the same conditional idiom
safely — because on `/inbox` the card never unmounts. The idiom was copied across
a boundary where its precondition no longer held.

**2 — "the data the page already loads" quietly became "the data that happens to
be there".** `REQ-D2`/`REQ-D15` correctly push the Desk to reuse loaded read
models instead of adding queries. Applying that to the events arm looked like the
same move, but the activity feed is a *bounded global* list while the decision
queue is *complete for the reader*. One is a legitimate join source; the other is
a sample. The requirement's wording ("that run's recent events") never signalled
a dependence on global volume, so the gap was invisible in review of the diff and
only appeared when asking "what makes this affordance appear?".

**3 — an adversarial pass over the FIX found a regression in the fix.**
`aria-controls` was advertised from first render while the panel row only exists
after first expand — a dangling reference introduced by the accessibility fix
itself.

## Solution

- **Mount-once, then `hidden`.** `hasOpened` gates rendering; `hidden={!open}`
  gates visibility. No panel exists on page load (so `REQ-D16`'s no-fan-out
  property is untouched), and once opened it survives collapse with its form
  state and never re-requests.
- **Stable affordance.** The events arm always returns a panel and renders an
  explicit "no recent activity" line when the loaded feed holds nothing for that
  run. No new query, so `AC-D2`'s query allow-list assertion stays green.
- **Selection guard.** `activate()` returns early when
  `getSelection()?.toString()` is non-empty.
- `aria-controls` gated on `hasOpened`; `focus-visible` ring; `$stage`
  placeholder guard beside the existing `$count` one; analytics Domain-entities
  and ADR citations corrected.
- The earlier `takeover.test.ts` hoist got an explicit 60s hook budget: moving a
  module-graph load out of the 5s per-test budget put it in the 10s *hook*
  default, where exceeding it fails the whole file.

## Prevention

- **Ask of every conditionally-rendered subtree: does anything in here hold state
  the user authored?** If yes, mount-once + `hidden` is the rule, not
  conditional rendering. The give-away is a form, a live session, or an unsent
  draft anywhere in the subtree — including transitively, via an extracted
  component whose original parent never unmounted.
- **When reusing already-loaded data as a join source, classify it first:**
  *complete for this reader* (the decision queue) or *a bounded sample* (the
  activity feed). A sample makes any affordance derived from it non-deterministic
  under load. Prefer rendering an explicit empty state over returning `null`, so
  the affordance is stable even when the sample misses.
- **A requirement whose wording is unconditional must be implemented
  unconditionally, or the requirement must be amended.** "Expands to that run's
  recent events" and "expands when that run's events happen to be in the last 100
  global events" are different contracts.
- **Any row/cell made clickable needs a text-selection guard** — copying values
  out of a table is an everyday action.
- **Re-review the fix as a change of its own.** The accessibility fix here
  introduced a dangling `aria-controls`; the earlier test fix moved a timeout
  from one budget to another. Both were found only by an adversarial pass *after*
  the fix compiled and its tests passed.
- **Classify timeouts by host load before chasing them.** Every suite failure in
  this batch was a 5s/10s timeout at load average 335 on 16 cores, green in
  isolation and green again at load 100. `uptime` before `git bisect`.
