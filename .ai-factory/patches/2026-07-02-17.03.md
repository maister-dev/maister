# SDD plan shipped a supply-chain hole + untested dispatch seam + self-contradicting API gate

**Date:** 2026-07-02 17:03
**Files:** .ai-factory/plans/auto-promotion-lanes.md
**Severity:** high

## Problem

A codex adversarial review of the auto-promotion-lanes SDD plan (the deps
lane for hands-free promotion) surfaced three defects the plan's own four
self-check passes had missed:

1. **(high) Supply-chain hole in the highest-risk lane.** §4.3 deps content
   check said "Lockfile-only diffs are eligible" and allowed *any* value
   change on an existing dependency key. So an unattended lane could
   auto-promote (a) a lockfile-only diff — a changed dependency graph with
   NO manifest evidence — and (b) a manifest key swapped to a non-registry
   specifier (`file:`, `git`, `github:`, `http(s):`, `workspace:`, path).
   This contradicted the plan's own "no-blind-ship" intent.
2. **(medium) Untested dispatch seam.** §4.6 listed the `tick-service`
   dispatch switch as a registration point, but every planned test invoked
   the handler *directly* (catalog/claim/direct-handler). A missing
   `case "auto_promote"` in `runClaimedJob` would leave every test green
   while production ticks never promoted anything.
3. **(medium) Self-contradicting API-contract gate.** §4.8/INV-13 claimed
   "redocly validator-clean" while T3/MO-2 only required "zero NEW errors vs
   a branch-point *count* baseline" — a weaker gate that can ship an invalid
   spec, and one disconnected from `validate:docs` (which does not run
   redocly at all).

## Root Cause

- **F1:** the classifier was designed around *path* classification; the
  content gate was bolted on for `package.json` only and never reasoned
  about the lockfile as an independently-executable artifact. "Deep-compare
  the manifest" felt sufficient, so the lockfile — the thing that actually
  pins resolved versions and sources — was waved through. The specifier
  *shape* (registry range vs protocol/path) was never in the allow-list
  because the mental model was "version bump = value change," which is a
  necessary-but-not-sufficient condition.
- **F2:** tests were written against the unit of *logic* (the handler), not
  the unit of *wiring* (kind → claim → dispatch → handler). A registration
  checklist enumerated the seam but nothing *executed* it end-to-end, so the
  checklist could be silently incomplete.
- **F3:** two people-pleasing phrasings ("validator-clean" as the aspiration,
  "zero new errors vs baseline" as the pragmatic escape hatch for 2 known
  pre-existing errors) were both written and never reconciled; a count-delta
  masks a new error whenever a pre-existing one is coincidentally resolved.

## Solution

Amended the plan (SDD spec + TDD tasks + invariants + traceability +
decisions/risks), owner picking the KISS depth for F1:

- **F1:** §4.3 now requires both-sided `isRegistryVersionSpecifier` on every
  changed dep key (rejects protocol/path specifiers — protocol-swap
  defense); **lockfile-only diffs disqualify**; a lockfile riding a validated
  manifest passes a best-effort non-registry-resolution scan. Residual
  (transitive smuggle) is fail-to-manual-bounded + documented (D-11, R4,
  ADR-126); full per-format consequence-proof is Phase-2. T6 gains one RED
  case per rejected-specifier family + lockfile-only + lockfile-tamper.
- **F2:** T13 gains a RED through-`runSchedulerTick({jobKind:'auto_promote'})`
  integration test (mirrors run-schedules/tick.integration) that fails if
  the dispatch arm / kind registration is absent.
- **F3:** T3/INV-13/MO-2/§4.8/T21 now gate on the *touched* artifacts being
  redocly-clean against an **enumerated** baseline (2 known errors by
  `{ruleId, pointer}`), any touched-location error blocking; recorded that
  `validate:docs` != redocly.

## Prevention

- **A dependency/lockfile is executable input, not text.** When a plan
  auto-actions a `package.json`/lockfile diff, gate the *specifier shape*
  (registry range allow-list, reject protocol/path) AND require manifest
  evidence for any lockfile change — never treat "value changed" as "safe
  bump."
- **Test the wiring seam, not just the handler.** For any new scheduler
  `jobKind` / dispatch switch / consumer registry, add ONE end-to-end test
  that drives the real claim→dispatch path; a registration checklist that
  nothing executes is an unverified claim.
- **A validation gate must be stated once, and be achievable.** "Validator-
  clean" and "zero-new-vs-count-baseline" cannot both be the gate. Pin the
  baseline by enumerated `{ruleId, pointer}`, make any touched-location error
  blocking, and name which command actually runs the validator.
- **Self-review passes miss adversarial classes.** Four "completeness /
  consistency / no-holes" passes still shipped a supply-chain hole — an
  adversarial (refute-the-design) pass is a distinct, required lens for
  security-sensitive autopilot features.
