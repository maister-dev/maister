# A dead guard: measuring "did anything change" from the wrong baseline

**Date:** 2026-09-01 05:40
**Files:** web/lib/db/schema.ts, web/lib/db/migrations/0126_claim_head_sha.sql, web/lib/runs/claim-head.ts, web/lib/flows/graph/ledger.ts, web/app/api/runs/[runId]/{rework-claim,takeover}/{claim,return}/route.ts
**Severity:** high

## Problem

Both human-claim return routes refused with "no commits to return — release
instead" when `git log <merge-base>..<branch>` was empty. In production that
condition is unreachable: a run only reaches `Review` (or a `human_review` node)
after its flow has committed work, so the branch always has commits. An operator
could claim a run, change nothing, and Return — re-entering validation instead
of being told to Release — and `returnedCommitCount` reported the flow's commits
as the operator's.

The existing test passed because it initialized the worktree branch exactly at
`main`. It tested the only shape where the guard fires, not the shape that
occurs.

## Root Cause

**One range was made to answer two different questions.** `merge-base..branch`
is the right range for the REVIEW evidence — the reviewer wants the whole branch
diff — and it was reused, unexamined, for "did the operator commit anything".
Those questions have different baselines: one is anchored at the branch point,
the other at the moment the claim was taken. Nothing recorded the second anchor,
so the only available range was silently substituted.

The test encoded the same confusion. It was written to make the guard fire, and
the simplest way to do that was to start the branch at `main` — which quietly
removed the very condition (pre-existing branch commits) that makes the guard
fail in production. A test that constructs the one state where a check works is
not evidence that the check works.

A second defect surfaced while generating the migration: migration `0125`
hand-authored a widened `domain_events` CHECK (13 kinds) but `schema.ts` still
declared 11. `drizzle-kit generate` therefore emitted a migration REVERTING the
constraint — the DB and the schema module had diverged, and the next person to
regenerate anything would have silently broken the ADR-160 emits.

## Solution

Migration `0126` adds `node_attempts.claim_head_sha`, written by `claimTakeover`
— the single insert point for both the ADR-030 takeover and the ADR-160 rework
claim, so both returns are fixed at the shared writer rather than per-route. The
returns now compute `claim_head_sha..branch` for the decision and the reported
count, keeping `merge-base..branch` for the review artifacts. A null head (a
pre-column row, or a SHA git could not resolve) falls back to the old count,
because a wrong zero would refuse a return that really did carry work.

`schema.ts` was corrected to the 13-kind CHECK before regenerating, so `0126` is
a single `ADD COLUMN`.

## Prevention

- **A range is an answer to a question, not a reusable value.** Before reusing a
  git range (or any derived baseline), state the question it answers out loud.
  "What did the reviewer see" and "what did the operator add" are different
  questions with different anchors.
- **Ask whether a guard's failing state is reachable in production.** A refusal
  whose condition requires a state the system never produces is dead code that
  reads as protection. Write the test in the production shape FIRST, then the
  degenerate one.
- **Test setup that makes a check fire may be removing the condition that breaks
  it.** If a test has to construct an unusual precondition to exercise a guard,
  that unusual precondition deserves a second test in the ordinary shape.
- **After hand-authoring a migration, run `drizzle-kit generate` and read the
  diff.** If it proposes to undo your migration, `schema.ts` was never updated —
  the migration triple (SQL + journal + snapshot) is not the whole contract;
  `schema.ts` is the fourth leg, and drizzle regenerates against it.
- When a defect lives in a helper shared by two features, fix it at the shared
  writer and say so — `claimTakeover` writes both claim shapes, so one column
  and one helper closed both routes.
