# A question asked at the wrong moment, a bound nobody checked, and a timestamp that could not round-trip

**Date:** 2026-09-23 23:01
**Files:** web/lib/execution-host/{create-intent,owned-session-create,prompt-owners,prompt-reconciliation,prompt-evidence,types}.ts, web/lib/execution-host/events/lifecycle-projector.ts, web/lib/{reconcile-evidence,reconcile-evidence-db,reconcile}.ts, web/lib/runs/{keepalive-sweeper,turn-lost-boundary}.ts, web/lib/flows/{runner-agent,graph/prompt-owner}.ts, web/lib/db/{schema.ts,migrations/0178_host_span_verdict.sql}, tests and docs (ADR-167, ADR-177, lifecycle, reconciliation, flow-settings, event-plane, schema docs, web OpenAPI, SDD)
**Severity:** high

## Problem

The whole-branch `/aif-review` found five blockers after round 1's fixes:
1. A permission pause under projector lag turned a live, admitted session `lost` (agent results dropped, cleanup and the ADR-180 park witness broken).
2. Owner application counted an unreadable host span as a failure; five in a row poisoned a completed turn.
3. The duration watchdog deferred a poisoned turn forever on live-session and judge nodes.
4. Round 1's own stream-lost deferral bound was false: a flow continuation re-drives the wait every ~5 s, so "a later tick finds the claim free" held only by chance.
5. A PRM Expectation still described the boundary's pre-round-1 rule.

While fixing, a sixth appeared: switching `completed_at` to `clock_timestamp()` broke the canonical prompt projector (`projection_failure`) — the confirming re-reduce wrote back a millisecond JS Date over a microsecond value and the 0177 immutability trigger refused it.

## Root Cause

- (1) One predicate (`lockCreateOwner`) answered two questions: "may this owner open a session NOW" (creation) and "is this session still the owner's" (acknowledgement). The branch started asking the second question later (at projection time), where transient run states make the first question's answer wrong.
- (2) A refusal typed for "the evidence is incomplete" was indistinguishable, to the failure counter, from "the application is broken". Late evidence became failed evidence the moment host-span settlement made the frontier path reachable.
- (3) and (4) Bounds were ASSERTED in docs and comments ("bounded by ADR-177 stream-lost"; "the only 4 Hz claimant exits") without checking which runs the bounding mechanism actually reaches (the evidence arm skips live sessions and judge nodes) or who re-enters the contended resource (the continuation worker).
- (6) A value written from the database clock is not the value the ORM reads back; any write-back of an immutable column must be omitted, not "rewritten with the same value".

## Solution

- `lockCreateOwner(tx, input, check: "create" | "ack")`, required; ack admits paused runs/attempts. Unowned creates apply only when newest.
- `preparePromptOwner` maps `event_frontier` to `PromptOwnerDeferred` while `commandStreamLost` is false; the lost stream is the bound.
- Watchdog witness = ADR-177 class `pending_application | applying`, or a completed receipt on a live stream.
- Migration 0178 `host_span_verdict (busy | refused)`: cleared at every read claim, written at release; the resolver crashes only on a recorded refusal (or an ineligible command) and waits on the next answer otherwise — no timer, no luck.
- `completed_at` = `date_trunc('milliseconds', clock_timestamp())`, set once, omitted on confirmation; re-anchor only after an agreeing reduce and a fresh bind.

Every guard falsified; the table is in the SDD round-2 record.

## Prevention

- When a predicate gains a second caller at a different lifecycle moment, ask whether it answers the same question there; make the question a required parameter.
- For every "bounded by X" claim, list who can re-enter the contended resource and which runs X actually reaches; write the bound as the NEXT DURABLE ANSWER, never "a later tick will get lucky".
- A failure counter must only count failures that no future evidence can repair; late evidence is a deferral with an explicit terminal bound.
- Any column protected by an immutability trigger: never include it in an UPDATE after the first write; values from `clock_timestamp()`/`now()` do not survive a JS Date round trip.
- Parallel subagents in one tree: a shared-infrastructure regression (a projector failure) shows up in THEIR suites first — ask them to report "fails with my files reverted" (they did), and bisect your own in-flight change before theirs.
