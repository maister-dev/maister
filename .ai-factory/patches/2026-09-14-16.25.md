# Inspect and assign every Flow runner before launch

**Date:** 2026-09-14 16:25
**Files:** `web/lib/acp-runners/flow-preflight.ts`, launch service, launch-options,
task launch config, launch dialog, safe error frames, associated tests and contracts.
**Severity:** high

## Problem

MAI-4 still failed with a generic CONFIG after all three consensus roles had
been assigned. The live preview reported both launch verdicts as allowed while
the ordinary `cross` session had no resolved runner. The Flow's Codex profile
matched three ready host runners without a `session:cross` project binding.

## Root Cause

The previous fix added remediation for consensus roles, but preview caught
ordinary session failures without including them in the launchability verdict.
Admission rejected those sessions without the safe slot identifiers used by the
dialog. Preview and admission assembled their session inputs separately.
Refreshing after saving a primary-session binding also sent an untouched,
inferred main selection as an override, masking the newly saved binding.

## Solution

Share the complete ordinary-session and consensus inspection across admission,
launch-options, and task configuration, preserving task, recipe, explicit
launch, binding, and default precedence. Block both launch modes on every
unresolved slot before run/workspace creation. Return safe slot identifiers
through JSON and SSE for ordinary sessions as well as consensus roles.

Expose declared sessions and consensus roles together as `runnerSlots`, keeping
the legacy consensus subset. Existing project binding controls assign or clear
each declared slot. Refresh uses the same override semantics as submission;
untouched inferred selections follow the refreshed server resolution.

## Prevention

A preview that catches a resolution failure must include it in its launch
verdict. Derive remediation from the entire admission slot set, including
ordinary sessions. Verify assigned consensus plus unassigned ordinary roles,
not only each subsystem in isolation. Keep preview and POST override semantics
aligned and exercise selection equality as well as changes.
