# Russian docs drift from English source of truth

**Date:** 2026-07-07 11:40
**Files:** docs/ru/overview.md, docs/ru/getting-started.md, docs/ru/workflow.md, docs/ru/concepts.md, docs/ru/operators-guide.md
**Severity:** medium

## Problem

The Russian product/operator documentation simplified several English source-of-truth details:

- run statuses omitted `HumanWorking` and `Failed`;
- package trust sounded like broad runtime capability expansion;
- readiness-gated runners did not explicitly mention diagnostics and smoke evidence;
- PR promotion prerequisites were less explicit than the English documentation.

## Root Cause

The Russian documentation was written as a concise user-facing layer, but the compression step collapsed some operational constraints that are important for safe use. The English docs are canonical for run lifecycle, package trust, runner readiness, and promotion prerequisites, so translated/operator guides must preserve those constraints even when they stay shorter.

## Solution

Updated the Russian docs to align with the English source of truth:

- added `HumanWorking` and `Failed` run statuses and clarified `Review`;
- clarified that package trust enables setup/enablement lifecycle, not arbitrary runtime rights;
- added readiness diagnostics and ACP smoke evidence wording for Gemini/OpenCode/MiMo;
- clarified that `local_merge` needs no provider prerequisites while `pull_request` promotion does.

## Prevention

- When creating translated docs, compare lifecycle tables against the canonical Mermaid state machine, not just README summaries.
- Preserve operational gates and prerequisites even in short user-facing translations.
- Ask a docs-auditor sidecar to check EN -> RU drift after adding or compressing translated docs.
