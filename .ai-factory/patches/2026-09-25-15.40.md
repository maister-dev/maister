# ADR-181 review fixes: a force that re-read its lease, an ABA the status lock could not see, degraded facts that hid actions

**Date:** 2026-09-25 15:40
**Files:** web/lib/workbench-lifecycle/service.ts, web/lib/workbench-git/{facts,service,public-branch-name}.ts, web/lib/runs/{lifecycle-claim,rework-claim,sync-target,promote}.ts, web/lib/worktree.ts, web/app/api/runs/[runId]/{export-branch,sync,promote}/route.ts, web/app/api/runs/[runId]/workbench-lifecycle/route-utils.ts, web/components/workbench/git-panel{,-kit,-tree,-publish,-update,-pr,-commands,-reattach}.tsx, web/components/runs/run-inspector.tsx, web/test-support/workbench-git-seed.ts, web/messages/{en,ru}.json, docs (ADR-181 amendments, workbench-git.md, workbench-lifecycle.md, screens/runs/git-panel.md, error-taxonomy.md, configuration.md, web.openapi.yaml, ru/manual/07-review.md), .ai-factory/rules/backend.md
**Severity:** high

## Problem

`/aif-review` of the whole ADR-181 branch (run git panel) found five MAJOR and
eleven MINOR defects while every lane was green. The ones that mattered:

1. **An unconfirmed force overwrote work nobody saw.** A non-fast-forward
   publish revealed a bare "overwrite" checkbox, and the forced retry leased
   whatever `ls-remote` read at retry time. Commits pushed to the public name
   after the refusal were replaced on a click that never showed them.
2. **A HumanWorking operation could run for the wrong operator.** The policy
   admits the rework-claim owner; both claims re-checked only the run status
   under the run lock. A return and a re-claim in between keep the status
   `HumanWorking` and change the owner (ABA), so the former owner's discard or
   update still ran.
3. **A failed probe hid Re-attach.** The facts loader degraded a failed git read
   to null but folded "no source resolved" into `false` even when a probe had
   thrown, so one git hiccup read as "nothing to re-attach from".
4. **A viewer saw an error, not their role.** `git-state` answers 403 below
   `recoverRun`; the panel read every non-OK answer as a load failure although
   the screen doc promised a members-only state.
5. **A template could collide across tasks.** `feature/{slug}` passed validation,
   so two tasks with one title — or every task-less run — rendered one public
   name, and a confirmed force on one would replace the other.

Smaller ones: the publish pushed without re-proving its lease; the facts
loader duplicated the "who holds the tree" rule; the sync and promote routes
carried copies of the D24 error body; the git service mixed injected deps and
bare `getDb()`; `git-state` warnings were never rendered; disabled inspector
links were `aria-disabled` yet navigated; the Handoff toggle was text-only; a
1300-line panel component; a scratch PR target that the panel let the operator
edit into a guaranteed refusal.

## Root Cause

- **A lease read at retry time protects the push, not the operator.** The
  explicit-SHA lease closed the race between the read and the push, and the
  design stopped there. What the operator confirmed was never part of the
  contract, so "force" meant "replace whatever is there now".
- **A lock re-check covers exactly the columns it reads.** The run-status
  re-check under the row lock was written for the recover race
  (`Crashed → Running`); ownership lives in `node_attempts`, which the lock
  does not name, so the status alone certified an owner that changed.
- **"Unknown" and "none" were one value.** The policy's contract (C32: a
  not-probed fact never hides an action) held for `hasRemote` because it was
  mapped straight from the probe's null, but the re-attach flag was computed
  from the sources with `.some(...)`, which turns every null into `false`.
- **Tests and fixtures never produced the failing shapes.** No test named a
  confirmed head; no test re-claimed between admission and claim; every probe
  test used a healthy repo; the DOM stub always answered git-state 200; the
  template tests accepted a slug-only template as valid.

## Solution

- Force publish: the non-fast-forward refusal carries the observed `remoteHead`
  and `remoteRef` (serialized top-level beside `pushRejected`). The panel
  confirms in the shared destructive dialog, naming the ref, the short head and
  an open PR. The retry sends `expectedHead`: the route requires it with
  `force` and refuses it without, and it must be a full SHA. The push leases
  exactly it. A moved remote is refused again with its new head, and the
  dialog asks again. Falsified: leasing the re-read head turns the "remote
  moved past the confirmed head" case red.
- `requireReworkClaimOwner` re-reads the owner inside both claim transactions.
  The lifecycle claim gets the actor from every workbench call site. A former
  owner gets `PRECONDITION human_owned`, with no slot, rescue ref or sync
  attempt written. Both race controls were red before the fix.
- The facts loader: "no source" needs every probe to have answered, otherwise
  the flag is null. The git-state suite fails the loader's reads through a
  delegating `@/lib/worktree` mock. Removing the probe's catch turns both
  degrade cases red.
- The publish renews its lease between the remote read and the push; a lost
  lease refuses with nothing pushed.
- A 403 renders the members-only note; the `warnings` render as a localized
  status line.
- `validatePublicBranchTemplate` requires `{task_key}` and a valid render both
  with and without a task.
- Refactors, each passing its suites before and after:
  - `workbenchClaimHolder` is the one "who holds the tree" rule;
  - `maisterErrorBody` is the one D24 body;
  - the git deps carry `db`;
  - the panel is one component per section, with typed input owned by the
    section.

## Prevention

- **A destructive confirmation must bind the server to what the dialog
  showed.** The dialog names the thing being replaced, the request carries its
  identity back, and the server compares or leases exactly it. Re-reading at
  action time throws the confirmation away.
- **For every "re-check under the lock", list the facts the admission used and
  re-check each one.** Admission here read status AND owner; the claim
  re-checked status only. A status that can round-trip (A → B → A) certifies
  nothing about the other facts.
- **Keep unknown distinct from none all the way to the policy.** A boolean
  derived from probes (`.some`, `.every`, `length > 0`) must go null when any
  probe failed. Add one degrade test per derived flag, not only per probe.
- **A template that names a shared resource must contain the unique key.**
  Validate against every render shape production takes (with and without a
  task), not one sample.
- **Do not chain `git commit` behind a grep of test output.** `vitest … | grep`
  exits 0 whenever the grep matched, so a red suite was committed once in this
  batch (`c6553c97`, fixed by `d4b3774c`). Capture vitest's own exit code
  (`> log; RC=$?`) and commit only on `RC=0`.
- **Moving state into child components:** seed it from the read the child
  mounts with, and check that no conditional unmount sits between the read and
  the typed input.
