# Preserve failed qualifier visibility without inventing model-start evidence

**Date:** 2026-11-04 00:16
**Files:** web/lib/tasks/{qualification-queries,qualification-types}.ts; web/lib/agents/launch.ts; web/components/{board/launch-popover,agents/task-agent-launch-control}.tsx; owning qualification producer/projection and browser interaction tests
**Severity:** medium

## Problem

The real RU browser journey created a qualifier whose runner refused session
creation. The Run failed without publishing an assessment, but manual Launch
showed the generic missing-assessment explanation instead of the failed-Triager
explanation.

## Root Cause

The source-failure projection required zero session-create/prompt commands and a
recognized preparation failure. A real rejected create is still a durable
command, so this stricter before-model proof excluded the failed qualifier
entirely. The old immutable qualifier snapshot also lacked an input revision and
digest; task association alone could incorrectly label an edited request with an
older failure.

## Solution

Select the latest operational qualifier before checking its outcome. Expose its
failure only while the new frozen revision and digest both match the current
server-owned input and no current accepted assessment supersedes it. Keep the
existing strict preparation proof for `modelStarted:false`. Other failed
qualifiers use null model-start, stage and cause fields; their UI shows the Run
link and specific failure explanation without claiming the model never started.

New producers add both input witness fields to the existing immutable JSONB
snapshot. Existing readers and the current CHECK accept these optional additive
keys; the existing immutability trigger protects them. No column, migration,
generated schema/ERD change or historical backfill is needed. Old snapshots
without this proof remain historical evidence rather than a current-input claim.

## Prevention

- Separate a failed assessment producer from proof of a pre-model failure.
- Match both semantic revision and digest before presenting a source failure as
  current; never infer this binding from the task ID alone.
- Keep accepted decisions, latest non-failed qualifier attempts and stale input
  precedence intact. Unrelated operational Runs do not replace the qualifier.
- Exercise the actual producer and finalizer as well as direct projection
  controls; a hand-authored snapshot alone cannot prove producer compatibility.
