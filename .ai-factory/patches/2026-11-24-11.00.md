# Resolve the built-in MCP facade from its execution assignment

**Date:** 2026-11-24 11:00 MSK
**Files:** `web/lib/agents/facade-launch.ts`, its agent, Flow and librarian callers, Studio catalog preview, and operator contracts
**Severity:** high

## Problem

Registering one remote supervisor changed the facade command for local Run
assignments. A local supervisor without a workload Web origin refused
dispatch. The catalog preview also omitted runner transport compatibility.
The operator contract and architecture still described parts of the remote
path as design only. The parallel browser run exposed an additional race
when an agent called `ask_human` while Web was persisting the prompt ACK.

## Root Cause

The facade resolver inspected a Web-wide route table. The existence of
another host's route says nothing about the owner of a session. The local
and relocated-host tests supplied facade configuration independently and
missed the real selection across both host kinds. The catalog description
also stopped at transport and distribution requirements before consulting the
canonical adapter transport table. The question handler required final
manager acceptance on its first read, although the host can already be
executing that exact prompt.

## Solution

A required host kind obtained from the bound client now selects the facade
on each agent, Flow and librarian session path. Server diagnostics record the
host kind. Studio's preview projects compatible adapter types from the same
transport rules used by launch. The operator references cover environment,
ingress, executable, scripts and readiness.

The scoped question request can wait briefly for its exact owned prompt
and session incarnation. It releases database locks while waiting,
revalidates the token and owner on reread, and writes an Inbox question
only after acceptance and activation are durable. The same public
Microsoft Learn call was independently verified in each of the two
assigned test containers before their supervisors started.

## Prevention

Exercise the session payload producer with both local and remote routing
configured. Use the production facade factory in a real assigned-host
qualification test. Pair catalog preview examples with the wire schema and
test that a skill preview carries no MCP compatibility record.
Hold the host ACK and lifecycle projection in the real Postgres test.
Observe successful continuation, rejected stale authority, bounded
timeout, and waiter cleanup without a persisted question.

Find all facade send sites with
`rg -n 'resolveFacadeLaunch\(|agentFacadeMcpServer\(|librarianFacadeServer\(' web/lib -g '*.ts' -g '!**/__tests__/**'`.
The sweep covered standalone/installation agents, Flow orchestrator and
knowledge nodes, Flow question and vault nodes, and fresh and resumed
librarian sessions.
