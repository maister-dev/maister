# Missing Drizzle snapshot for newest migration

**Date:** 2026-07-07 13:51
**Files:** web/lib/db/migrations/meta/0092_snapshot.json, web/lib/db/__tests__/migration-journal-integrity.test.ts
**Severity:** high

## Problem

Migration `0092_graded_runner_resolution` was present in `_journal.json` and
had a matching SQL file, but the generated Drizzle snapshot
`meta/0092_snapshot.json` was missing. The existing journal integrity guard
passed because it checked only journal-to-SQL consistency.

## Root Cause

The migration review surface treated SQL and journal registration as complete
migration metadata. Drizzle's snapshot lineage is a separate generated artifact,
and the integrity test did not assert that the newest main migration has the
snapshot needed by future schema generation.

## Solution

Added `meta/0092_snapshot.json` by advancing the `0091` snapshot id lineage and
adding the nullable `run_sessions.resolution_warning` `jsonb` column. Extended
the main migration integrity test to require the newest journal entry to have a
matching Drizzle snapshot.

## Prevention

Review every new main migration as a triple: SQL file, `_journal.json` entry,
and `meta/<NNNN>_snapshot.json`. Keep the integrity test focused on the newest
entry so legacy snapshot gaps remain tolerated while new missing snapshots fail
immediately with an actionable message.
