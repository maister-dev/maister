# Adversarial review of ADR-168: a stale read, a silent default, and two UI axes

**Date:** 2026-09-13
**Files:** web/lib/tokens/update.ts, web/lib/tokens/revoke.ts, web/lib/tokens/scopes.ts,
web/types/token-scopes.ts, web/components/board/token-actions.tsx,
web/components/account/personal-tokens-panel.tsx, web/components/use-modal-a11y.ts,
web/app/api/{account,projects/[slug]}/tokens/[tokenId]/route.ts
**Severity:** high

## Problem

Five findings, all verified in source before any edit; none rejected.

1. A PATCH naming only `name` restored scopes a concurrent narrowing had just
   committed, and recorded only `renamed` — the reversal had no ledger row.
2. Every revocation made through the UI was attributed to `system`.
3. The scope picker could not express `["*", "hitl:respond:human"]`: granting
   the human scope dropped the wildcard, granting the wildcard dropped the human
   scope, and removing either from the valid pair emptied the selection.
4. Both personal-token dialogs left the row's destructive Revoke button in the
   tab order behind them.
5. The personal scope picker had drifted 8 scopes behind the vocabulary,
   including `flows:read` and `runners:read` — the exact grants ADR-168 exists
   to let an operator add after issuance.

## Root Cause

Four different shapes of the same mistake: **a boundary was drawn where it was
convenient rather than where the invariant lives.**

1. The read-modify-write spanned a transaction boundary. I had seen this window
   during my own adversarial pass and dismissed it, because ADR-168 D4 accepts
   last-write-wins. That reasoning checked the FIELD VALUES and never checked
   the LEDGER — and D4's acceptance rests entirely on "both edits write ledger
   rows, so the sequence is reconstructible". A restore nobody recorded voids
   the premise the residual was granted under.
2. The actor parameter was added as optional "so the existing call shape stays
   valid". That is exactly what made the omission silent: both DELETE routes
   kept compiling. The service test passed an actor explicitly and so could
   never see it — a test that supplies what production forgets proves nothing.
3. `*` and the exact-only scopes are two independent axes on the server
   (`normalizeTokenScopes` keeps them side by side deliberately). The UI folded
   them into one list, so every toggle had to destroy one axis to change the
   other.
4. `aria-modal="true"` announces modality; it does not implement it. Copying a
   neighbouring dialog's markup copied the attribute and none of the behaviour.
5. A hand-maintained mirror of a vocabulary drifts. It had, by 8 entries.

## Solution

- Read the row `FOR UPDATE` inside the writing transaction, so the diff, the
  write and the ledger see one version. The CAS stays as a backstop.
- Made the revoke actor a REQUIRED parameter and reordered to `(input, actor,
  db?)`; the compiler then named all 12 call sites. Both routes pass the session
  user.
- Rebuilt both toggles on split axes (`broad` / `exact`), each mode keeping its
  own empty-selection rule; moved the exact-only set into the client-safe
  vocabulary so server and UI read ONE definition.
- Extracted the modal behaviour from `AccessibleModal` into `useModalA11y` and
  applied it to both personal dialogs — the pre-existing create one too.
- Derived the personal picker and its label keys from `USER_TOKEN_SCOPE_VALUES`
  mechanically, deleting the hand-written list and its parallel switch.

Every fix carries a test proven to fail without it: the concurrency regression
uses a second connection holding the row, because `Promise.all` did NOT
reproduce the interleaving and passed against the unfixed code.

## Prevention

- A concurrency residual an ADR "accepts" is scoped by the ARGUMENT it was
  accepted under. Re-read that argument before invoking the acceptance; here it
  covered contested values, never omitted ones.
- When adding an argument to N call sites, make it REQUIRED. A default turns a
  missed call site into silent wrong data, and a service test that passes the
  argument explicitly cannot detect it. Assert at the seam where the real value
  originates.
- A test written to prove a concurrency fix must be shown to FAIL without the
  fix. Timing-based interleaving (`Promise.all`) is not a test; force the order
  with a second connection.
- Mirroring a server constant or vocabulary in the UI is a drift generator —
  export it from the client-safe module instead.
- `aria-modal` is not a focus trap. Reuse the behaviour, not the markup.
