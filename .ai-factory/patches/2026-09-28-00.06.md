# Ownership-residuals review fixes: closed-but-undelivered answers, stored-answer fit, and the queue invariant's missing writers

**Date:** 2026-09-28 00:06
**Files:** web/lib/hitl-closed-answer.ts (new), web/lib/services/hitl.ts, web/lib/scratch-runs/{events,idle-resume,respawn,service,authorization,open-permissions,turn-completion,attachments}.ts, web/lib/scheduler.ts, web/lib/agents/{turns,turn-variants,finalization,stranded-turns,continuation-worker}.ts, web/lib/orchestrator/cascade.ts, web/lib/execution-host/steer-settlement.ts, web/lib/execution-host/events/{lag-read-model,lag-observation}.ts, web/lib/domain-events/{outbox,taxonomy}.ts, web/lib/runs/{state-transitions,keepalive-sweeper,resume-driver,terminal-cause,flow-result-dto}.ts, web/lib/flows/{runner-agent,graph/permission-rejection}.ts, web/lib/agents/permission-rejection.ts, web/lib/reconcile.ts, web/app/api/scratch-runs/[runId]/{recover,discard}/route.ts, web/components/{runs/terminal-cause-notice,scratch/scratch-conversation,admin/execution-host-status}.tsx, web/test-support/fake-execution-host.ts, supervisor/src/http-api.ts (comment), web/messages/{en,ru}.json, the matching tests and docs.
**Severity:** critical

## Problem

A whole-branch review found six criticals and a tail of majors in the branch's own new code:

- A permission answer stored for one tool was auto-delivered to whatever tool a respawned scratch session asked for first. Option ids (`allow-once`, `allow-with-updates`) are the same for every tool, so the fit check always passed; the rebind also overwrote the row's `toolCall`, so the audit said the operator approved the new tool.
- `responded_at` was read as "delivered", but the branch added three writers that set it without delivering. An identical retry then answered 200 "already delivered", and `markScratchPermissionDelivered` flipped a finished dialog back to `Running`. A boundary closing the row mid-delivery made the in-flight answer 200 as well.
- Idle resume re-sent the newest user row, which could be a queued message (sent twice) instead of the interrupted turn's prompt (never re-sent).
- A failed freed-slot respawn rolled back without restoring `resume_requested_at`, so the gate never re-selected the run and its answer waited for the TTL.
- The project-less assistant idle resume skipped the ADR-097 launching-user + edit-lock gate that Recover enforces.
- The orchestrator cascade abandoned agent runs without the queued-turn supersede, so their messages stayed `queued` forever and the stranded alarm fired every sweep.
- Terminal causes carried prose (`prompt-failed:<message>`), and about 25 emitted reason tokens had no copy.

## Root Cause

- **One column, two meanings.** `responded_at` meant "delivered" to the respond route but "no longer pending" to every closer. Nothing distinguished the two, and new closers joined without anyone re-reading the readers.
- **Identity by a weak proxy.** The rebind compared the option id — generic across tools — instead of the request's identity. The flow precedent (`permission_reissue_source`) compares the full `toolCall`, but a re-prompted scratch turn mints a fresh `toolCallId`, so neither the proxy nor the precedent fits as-is; the existing "does not fit" branch had never run (it supersedes, which the 0155 trigger forbids for permission rows).
- **An invariant enforced at one writer of the status.** D-M1 lived in finalization only; the cascade flips agent runs terminal with a bulk UPDATE and never passes through it.
- **A claim that clears state its rollback does not restore.** The claim cleared the queue key; the rollback restored status and step only.
- **A second entry point that inherited none of the first's authz.** Idle resume reached the same respawn as Recover without Recover's gate.
- **A MUST with no enforcement point.** "cause carries tokens only" was a convention at each emitter; one emitter built reasons from messages.

## Solution

- **`_closed` marker.** `web/lib/hitl-closed-answer.ts` marks an answered permission row closed without delivery (`response._closed {reason, at}`; only a jsonb object is merged, since `||` on a scalar builds an array). All ten non-delivery closers write it. Phase 1 reads it BEFORE the terminal-run refusal (most closers end the run in the same transaction, so a later check made the `delivery_rejected` and crash `session_ended` refusals unreachable), and the HITL_TIMEOUT arm reads it too; both answer the reason's own refusal. The scratch self-heal flips only a `NeedsInput` dialog with nothing else open.
- **Rebind identity.** It is the canonical `toolCall` minus `toolCallId`/`status`/`_meta`, plus each option's `optionId` + `kind`. The adapter mints a subagent call's `_meta` parent id per call, and ExitPlanMode option names embed context usage. A request that cannot be canonicalized counts as a mismatch, instead of throwing into the handler's cancel path. On a mismatch the stored answer is closed (`request_changed`) and a fresh request is recorded. Tests cover both a same tool under a new id (with a new `_meta` and relabelled options) and a different tool, driven through the mock's replay journal.
- **Idle resume.** It re-prompts the newest `prompted` or NULL-delivery row. The claim returns its observed state, and every rollback restores it (including a pre-respawn load failure). The gate passes its claim through instead of re-reading after commit.
- **Assistant gate.** Phase 1 enforces launching-user + lock before storing. The shared claim re-checks the lock (the gate has no actor); a queued run passed over there moves its `resume_requested_at` to `now()`, so runs only their owner can unblock never hold the gate's `limit(cap)` window. `edit_lock_not_held` joined the closed respond enum.
- **Queue invariant.** `supersedeUndispatchedMessageTurns` (queued + claimed message turns, `MESSAGE_TURN_VARIANTS`, keyed on `CLOSES_MESSAGE_TURNS` including Done) is shared by finalization and the cascade. The steer settlement locks the run before inserting.
- **Terminal cause.** `emitDomainEvent` normalizes the cause reason (token before `:`, grammar and length bound) as the choke point. The reader drops only a bad reason. A registry test pins EN/RU copy for every token and code, and the notice leads with the reason copy.
- **Also fixed:**
  - Recover is auth-first, and answers 202 on a continuation-pending yield.
  - A launch yield returns the launch response.
  - Scratch stop/discard re-check under locks (proved with a lock-barrier two-racer test that the unguarded code fails).
  - The budget sweeper honours `{applied}`.
  - The stranded report leaves the persisted blob, reads outside the lag snapshot, and reports `null` on failure.
  - The fake host mirrors `session_checkpointed`, with a parity scenario.

## Prevention

- **A shared column's meaning is a contract.** When a diff adds a writer to a marker column, grep every READER of that column and ask whether the new write means what the reader assumes: `rg 'respondedAt' | grep -v set` for readers, `rg 'respondedAt:'` for writers.
- **Match identity on the request, not an id that is shared across requests.** When "the same request" is decided by a field, check whether the producer reuses that field across different requests (adapter option ids) or mints it fresh per call (`toolCallId`). A re-prompt changes the second kind, so neither works alone.
- **Enforce an invariant at every writer.** An invariant stated for "every run that ends" must be enforced at every writer of the terminal status. `rg 'status: "Abandoned"'` found the cascade's bulk UPDATE, which never calls finalization.
- **A rollback restores everything its claim cleared.** Diff the claim's SET list against the rollback's.
- **A refusal is ordered after nothing that dominates it.** A new, more specific refusal (the `_closed` reason) placed after a generic one (terminal run) is dead whenever the generic condition is written in the same transaction as the specific one. For each writer of the specific marker, check what else that transaction writes.
- **A skip that keeps its queue key needs a way out of the window.** A `limit(n)` FIFO scan plus a `continue` on a durable, actor-only condition is starvation. The skipped row must yield its place or leave the scan.
- **Identity excludes producer-minted and display fields.** Read the producer (here the adapter's `buildClaudePermissionPresentation` / `buildClaudePermissionOptions`) for per-call ids and labels built from session state before hashing a request.
- **A second path into a privileged effect inherits the first path's gate,** and a gate with no actor (a scheduler) re-checks the resource precondition itself.
- **A MUST names its enforcement point.** Put it at the choke point every writer uses (here `emitDomainEvent`), not at each emitter.
- **Race tests need the window open.** Falsifying the stop guard first "passed" because the second stop's unlocked pre-check saw the first finish. Only a second connection holding the run row until both racers were parked (checked via `pg_stat_activity`) produced two events without the guard. Also check a falsification's operator precedence (`false && a || b` is still `b`).
- **Classified, not fixed:**
  - Gate permission parks share the node crash gap. It is pre-existing on master; recorded in the decisions.md TODO, and a follow-up task was offered.
  - The stranded query's open-prompt exclusion has no seedable fixture (the 0140 owner_ref constraint).
  - `resumeCount` scoping is unreachable for scratch.
  - The C4 retry has no backoff: while a host is down but still `ready` (readiness drops only on an ingest failure), each freed-slot pass claims and rolls back once. This is bounded per pass and better than the stranded `Running` run it replaced. A backoff would need a new column.
  - A claimed agent message that a `Done` finalization supersedes still fails its claimer's admission (the run is closed, the assignment released). This is pre-existing on master; the helper comment now says so instead of implying a graceful `superseded` answer.
  - Swapping the inline withdraw for `withdrawRefusedPermissionDelivery` was rejected, because the two differ in semantics (the helper keeps an intent it cannot prove refused).
  - D-A8(2), "the idle-resume claim requires a `checkpointed` incarnation on the current assignment", was implemented and then reverted. The scratch consumer parks from the session stream's exit event before the lifecycle projection writes that incarnation, so the witness is often absent at claim time (seven real-supervisor cases went red). Every writer of `NeedsInput → NeedsInputIdle` already parks only the current generation. A requirement copied from a writer's guard (Pass 1b parks FROM the witness) is not a reader's guard.
