# Retire E2E process owners before linked Git and root cleanup

**Date:** 2026-11-06 17:30
**Files:** web/e2e/run.ts; web/test-support/process-invocation.ts; four Playwright configs; removed e2e/global-teardown.ts; existing wrapper and worktree-root tests
**Severity:** medium

## Problem

The focused binding browser body passed, but global teardown failed with
`ENOTEMPTY` in the fixture repository's `.git/info`. The wrapper subsequently
found a linked worktree whose parent repository's Git metadata had been deleted.
A passing test body with failed teardown was correctly an unsuccessful lane.

## Root Cause

Installed Playwright 1.64.1 registers Web-server plugin setup before global setup
and custom global teardown, then unwinds in reverse. The custom teardown removed
test repositories before the Web plugin stopped, permitting overlap with active
Git work. The retained focused invocation contained no registered fixture roots:
its second error followed the partially completed early filesystem deletion.

The full lane also has a separate ordering hazard: dynamic fixtures register
temporary parent repositories as invocation roots. The wrapper's old sequence
removed those roots before calling linked-worktree cleanup, which still needs
their Git registries. Merely removing the early hook would leave this hazard.

## Solution

The wrapper owns destructive E2E cleanup. The shared root remover accepts a
precise pre-removal operation, verifies physical invocation quiescence before
calling it, and rechecks before deleting registered roots. E2E supplies linked
worktree cleanup through this existing invocation-reclaimer boundary, while
parent repositories still exist. Callback failure preserves the registered roots
and remains an error. Database shutdown stays in the wrapper's unconditional
cleanup aggregation, including when process ownership cannot be proven. The
four Playwright configs no longer install filesystem deletion as global teardown.

Two new controls in the existing real-Git owner failed before the fix and passed
after it: the parent repository remains usable while its linked worktree is
retired, and a callback that introduces an actual tagged child is refused before
root deletion; another attempt while that child is alive never calls preparation.
After confirmed child exit the same cleanup succeeds. This owner passes 4/4.
The existing wrapper/release composition suites pass 24/24, preserving original
failure aggregation and DB shutdown. An earlier test expecting filesystem
cleanup despite an unproven release now explicitly requires root retention.
Logs: `/private/tmp/maister-r23-root-order-{red,green}.log` and
`/private/tmp/maister-r23-wrapper-green.log`. Focused browser cleanup and the
complete frozen browser lane remain separate required qualification.

## Prevention

Assign cleanup to the layer that can establish process quiescence. Git worktrees
and their parent repositories are dependent resources, not interchangeable paths
to delete in any order. Keep pre-removal operations behind the physical-owner
guard, preserve errors and diagnostic roots when it cannot be established, and
keep database teardown reachable. Do not hide removal races with retries, sleeps,
or weakened browser assertions.
