# Fence sessionless Flow traversal against terminalization

**Scope:** Flow traversal ownership, the existing graph/driver consumers, and the terminalization contract in `docs/system-analytics/execution-prompt-lifecycle.md`.

## Root cause

`runFlow` bypassed its durable claim and guarded database for graphs without owned prompts or CLI nodes. A human/form traversal could load Running, lose to a successful authorized abandon, then append an attempt and commit a HITL plus its notification through the unguarded database. Current accepted-launch SQL guards refused the later NeedsInput update, but could not roll back those earlier transactions. A retained live legacy Run could also return to NeedsInput. The final crash CAS already preserved Abandoned; the unconditional `ended Crashed` log falsely suggested a committed rewrite.

The defect also existed on the reviewed master baseline. The R18 worker fixture exposed it; waiting for a parked Run improves that fixture's teardown but does not provide a product fence.

## Fix and boundaries

Every active traversal now uses the existing durable token/lease and guarded database. Placed claims retain their exact active assignment and epoch. A separate server-only operation admits a never-placed sessionless Run only from its actual stored graph, a null assignment pointer, and absent assignment history. It freezes and rechecks the parsed manifest digest alongside the pointer/history and existing lease. It neither fabricates a placement nor contacts Supervisor. A missing pointer with placement history refuses instead of receiving this compatibility grant.

Run locks use `NO KEY UPDATE` before assignment locks. This preserves status/pointer serialization while remaining compatible with the `KEY SHARE` foreign-key check emitted by public human-assignment transitions. Separate placed/unplaced authority checks and proof constructors share one private token/30-second lease acquisition CAS. The stored-graph check reuses the extracted traversal requirement classifier. Its CLI classification follows actual dispatch: `cli`, `check`, and `command_check` gates use `runCliStep`. Model nodes and owned-prompt gates retain their existing classification. Failed terminal CAS branches preserve the winning state and report the observed status without claiming a terminal outcome or closing another owner's assignments.

Production caller audit: `rg 'runGraph\(|runReviewHuman\(|runFormCollect\(' web -g '*.ts' -g '!**/__tests__/**'` finds `runGraph` only through `flows/runner.ts`; human/form dispatch and rework escalation remain inside `runner-graph.ts` and receive the same guarded database. Resume/continuation callbacks enter `runFlow`. Direct handler tests remain handler tests; they do not create a new public execution path. No schema, migration, historical Run/qualification rewrite, model call, deployment, or archived package-pinning change is included.

## Prevention

Execution ownership applies to every reachable writer, including human/form work before any model command exists. Classify actual effects once and reuse that classification in compatibility admission. Do not use a log label, a cached status, scheduler shutdown, or a missing assignment pointer as proof that an old traversal has stopped. Keep short ownership-lock queries observable, and inspect a consumer's fixture imports before treating its integration label as permission to boot another runtime.
