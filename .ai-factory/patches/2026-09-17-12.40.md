# A responsive column was declared twice and hidden once; the invariant that mattered was only proved in a lane CI does not run

**Date:** 2026-09-17 12:40
**Files:** web/components/work/work-rows-table.tsx, web/components/work/\_\_tests\_\_/work-rows-table.test.ts, web/app/(app)/page.tsx, web/app/(app)/\_\_tests\_\_/desk-contract.test.ts, web/components/inbox/hitl-panel.tsx, web/lib/runs/run-query-state.ts, web/app/(app)/runs/[runId]/layout.tsx, docs/screens/{desk,work}.md, .ai-factory/specs/desk-one-object-per-work-item.spec.md, .ai-factory/ROADMAP.md
**Severity:** high

## Problem

Seven findings from `/aif-review` on the ADR-174 Desk rebuild. One was a shipped
visual defect, one was a coverage hole in the change's central invariant:

1. **The header row outran its body by one column below 1024px.** `REQ-D11`
   introduced CSS-driven responsive column dropping — a brand-new mechanism on
   this branch, master had none. The `waitingOn` `<td>` got `DROP_SM`; its
   `<th>`, ~170 lines away, got nothing. Measured on rendered markup:

   ```
   width 390:  header=5 body=4  *** MISMATCH ***
   width 800:  header=6 body=5  *** MISMATCH ***
   width 1100: header=8 body=8  OK
   ```

   Below `lg` the `<thead>` kept a "Waiting on" column with no cells under it,
   so every header from that point rightward — "Next action" included — labelled
   the wrong column, on BOTH `/` and `/work`, at exactly the phone and tablet
   widths the feature exists to serve.

2. **`NAV-08` was proved only in Playwright, which CI does not run.** "One
   object per work item" is the reason ADR-174 exists, and `REQ-D24` says so
   ("MUST be asserted, not assumed"). Its mechanism is one predicate —
   `queue.items.filter((item) => item.kind === "flagged")`. Nothing asserted it
   at any layer. `DecisionSections` buckets by kind internally and renders a
   section per populated bucket, so widening that filter to `queue.items`
   restores the exact `hitl`/`crashed`/`promotable` duplication the ADR deletes,
   with every CI test still green. Verified by doing it: the suite stayed green.

Plus: the documented drop priority was the reverse of the implemented one in
three places; the project column's "when and only when" rule ignored the new
`<md` CSS hide; `?wb=review&scope=review` reached a third hand-spelled copy; the
activity labels were rebuilt once per row; `DeskRegion` carried a `className` no
caller passed; and the extracted `HitlPanel` kept `window.location.reload()` on
one arm and `router.refresh()` on the other.

## Root Cause

**1 — a one-column invariant with two spellings and no single enforcement
point.** Hiding a table column in CSS necessarily touches two elements, and
nothing in the type system, the linter, or the existing tests relates them. The
three test layers each had a structural blind spot that made the defect
invisible rather than merely untested:

- `renderToStaticMarkup` tests assert label presence — no stylesheet, so
  "visible" is not a concept they have;
- the jsdom `colSpan` test counts `thead th` nodes, and jsdom applies no CSS, so
  it counts 10 either way and passes;
- the e2e at 390px asserts the page does not scroll horizontally — which stays
  true when the header is one column wider, because the extra column just
  squeezes.

The author's own comment stated the invariant ("Every `colSpan` below must be
the FULL column count") for the `colSpan` half and never for the `<th>`/`<td>`
half, which is the half that had two writers.

**2 — "it has a test" was true and irrelevant.** The spec itself records that
CI runs lint, typecheck, `test:unit`, `test:integration`, `validate:docs:all`
and `validate:contracts` — and that `test:e2e` is a manual gate. It even states
the principle: "a guard in the lane CI runs is worth more than the same guard in
a lane that is green because nobody ran it." Then it routed its most important
requirement to e2e anyway, because the *rendered consequence* genuinely needs a
browser. The missed move is that a requirement has two halves — a consequence
and a mechanism — and they do not have to be proved at the same layer.

**3 — prose written before the constants, never re-derived.** "`tokens`,
`readiness` first" was a design intention. The breakpoints that shipped drop
`blockers`/`lastActivity` first (below `xl`) and `tokens`/`readiness` second
(below `lg`). The sentence was then copied into `REQ-D11`, `docs/screens/work.md`
and the code comment, so one stale intention became three stale claims — and the
code comment contradicted itself between its first and second clause.

## Solution

1. `DROP_SM` on the `waitingOn` `<th>`, so the column drops as one unit. The
   column is an em dash on every row without a pending request and the widest
   text column when it is not, and the person is still named by the Desk's
   expanded panel and by the run surface.
2. A `T-D11` **pairing** test: reduce every `<th>` and `<td>` class to its
   breakpoint token and assert the two lists are equal, under both groupings,
   plus a readable per-width consequence check at 390/800/1100/1300. Asserted as
   the pairing rather than as a column count so the failure names the column and
   an eleventh column cannot satisfy it by accident. Falsified: reverting the
   one-line fix turns 3 cases red with exact messages.
3. A `NAV-08` source-contract case in `desk-contract.test.ts` pinning the
   `flagged` filter and that `DecisionSections` is fed `heldItems`. Falsified:
   widening the filter turns it red while the other 15 stay green. `E2E-NAV-08`
   keeps the rendered half.
4. Drop order re-derived from the constants and rewritten in all three places;
   the two project-column rules (DOM-level grouping, CSS-level `<md`) described
   as independent and composing.
5. `runReviewHref()` in `lib/runs/run-query-state.ts` — the module that already
   owns the `wb`/`scope` vocabulary and its sibling `buildRun*Href` helpers —
   adopted at all three call sites. Verified byte-identical to the literal it
   replaces before adoption.
6. `router.refresh()` on both `HitlPanel` arms. This was pre-existing drift, but
   the extraction made it a Desk bug: a full reload resets every row's `useState`
   and collapses the page. No test asserted `location.reload`.
7. Labels hoisted above the row loop; dead `className` prop and the `clsx` import
   it orphaned removed.
8. `REQ-D14` amended for the join's scope asymmetry — `getWorkTable` reads
   *visible* projects, `getDecisionsQueue` reads *actionable* ones — so a
   project-`viewer`'s `WaitingOnHuman`/`Crashed` rows render inert by design.
   Behaviour unchanged: it is already the correct degradation under ADR-169 D7,
   and it was only ever missing from the spec.

No runtime logging. Per the project's logger-boundary rule this batch is markup,
docs, tests and a pure href helper; behaviour is locked by the two falsified
guards instead.

## Prevention

- **When a rule requires the same class at two DOM sites, assert the PAIRING,
  not the instance.** "Is `waitingOn` hidden at 390px?" would have passed for a
  broken table. "Does every `<th>` carry its `<td>`'s drop class?" cannot.
- **Before accepting a test layer, ask what that layer is blind to.** Three
  suites covered this feature and all three were structurally incapable of
  seeing the defect. A layer that cannot fail for reason X is not coverage of X.
- **Split an acceptance criterion into consequence and mechanism, and prove each
  at the cheapest layer that can see it.** A requirement whose only guard lives
  outside CI is unguarded in practice; the mechanism is usually a predicate or a
  constant that the CI lane can pin even when the rendering cannot.
- **Re-derive ordering prose from the constants after the constants are
  chosen**, and grep for the sentence — a design intention repeated in a spec, a
  screen doc and a comment decays in three places at once.
- **A comment that states an invariant for one half of a two-sided rule is a
  review signal.** The `colSpan` half was spelled out; the `th`/`td` half, which
  had two independent writers, was not.
