# Normalize unavailable Flow bytes at both asset digest boundaries

**Date:** 2026-11-04 13:54
**Files:** web/lib/tasks/launch-flow-assets.ts; web/lib/tasks/__tests__/launch-flow-assets.integration.test.ts
**Severity:** medium

## Problem

A stored installed Flow revision could point to a missing directory. Preview or acceptance then exposed a raw filesystem ENOENT as a generic server failure. A missing private accepted-flow directory on reconstructed execution followed the same unclassified path.

## Root Cause

The shared module normalized copy, witness and path-validation failures to PRECONDITION/launch_flow_assets_changed, but the initial installed-directory digest and the reconstructed captured-directory digest ran outside that error boundary. Tests covered changed bytes and valid capture recovery, but not unavailable directories at those reads.

## Solution

One domain-local digest reader retains the original cause and throws the existing typed asset refusal for either digest. It does not substitute mutable installation bytes for a missing accepted capture, create a qualification, or admit a request. Its message applies to selected assets before and after acceptance.

## Prevention

- Audit filesystem reads before the main copy block as well as inside its catch.
- Use actual absent directories with real persisted revisions. Cover preview and acceptance independently, and assert no intent, Run or execution command is created.
- Verify the safe public 409 projection while retaining native ENOENT only in the internal cause. Never include filesystem paths in the public response.
- Extend the existing frozen-capture runtime case: captured A remains A after the installation changes to B; deleting capture A must refuse instead of falling back to B.

## Evidence

The existing real PostgreSQL/Git integration file reproduced three failures before the change: native ENOENT at preview, acceptance and reconstructed capture reading. The complete seven-case file passes after the fix, with zero invocation leaks. Scoped ESLint and Web no-emit types pass. This is local fixture evidence; no production state or historical assessment was changed.
