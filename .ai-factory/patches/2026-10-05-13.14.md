# Preserve bounded Linux policies and the selected Docker transport

**Date:** 2026-10-05 13:14 UTC
**Files:** web/test-support/linux-isolation-protocol.ts; web/test-support/linux-isolation-launcher.mjs; web/test-support/__tests__/linux-isolation-protocol.test.ts; web/test-support/__tests__/linux-isolation-driver.integration.test.ts; docs/system-analytics/test-infrastructure.md
**Severity:** medium

## Problem

Production Linux isolation refused a144827byte policy at its112KiB argument
bound in a long worktree. The Docker TCP refusal integration control also failed
when the local daemon used a rootless Unix socket.

## Root Cause

Every same-path mount serialized its long absolute path twice. The namespace
child hop serialized the expanded policy again. The Docker control independently
assumed a conventional socket instead of using the endpoint selected by the
same Testcontainers client that provisions the database.

## Solution

Represent an identical destination with an explicit null wire marker and decode
it to the validated source. Use the bounded serializer on both hops; reject
missing destinations and retain all byte limits. Connect the refusal proxy to
the selected runtime client's absolute host Unix socket, failing explicitly if
that transport is unavailable.

## Prevention

Exercise serialization using realistic long worktrees and many mounts, including
a distinct destination, exact roundtrip, input immutability and oversized-policy
refusal. Qualify real boundary controls on rootless Docker as well as conventional
host layouts. Reuse resolved transport authority rather than rediscovering it
with a different default. Validate every serialization hop against the same
argument bound.
