# Preserve Git sync progress and addressable Flow checks

**Date** 2026-11-23 22:01 MSK

**Files** Run detail layout, Flow check links, Run query state, Flow center and the M15, M22 and child-peek browser journeys

**Severity** medium

## Problem

Moving Stop run into the header conflicted with the Git panel's new progress display on master. Copying an inspector check link lost the selected evaluation. Direct fullscreen entry with an empty child selection activated two modal focus handlers.

## Root cause

The layout used the number of remaining actions to decide whether to mount a panel that also owns progress. Inspector links kept the evaluation in the initiating click handler. Fullscreen and the child controller interpreted the same empty query value differently.

## Solution

Mount the detail panel for remaining actions or an authorized sync attempt. Include the inspector destination in native links and resolve it against the reasons already rendered for that Run. Let the shared child-query reader normalize empty selections for both surfaces.

## Prevention

Run `pnpm --filter maister-web test:e2e:flow` to exercise these boundaries in Chromium and Firefox. The tests use a running Flow whose sole lifecycle action is Stop, two failed evaluations with distinct destinations, and fullscreen entry with both a selected child and an empty selection.

Sibling inspection covered `syncAttempt`, `FlowChecksLink` and direct reads of the `peek` parameter. The Git panel and timeline retain their existing attempt projections. Workbench check links retain their existing result selection. The child controller and fullscreen graph share the selection reader.
