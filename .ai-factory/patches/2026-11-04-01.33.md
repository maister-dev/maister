# Keep scripted consumers and native fault targets tied to current ownership

**Date:** 2026-11-04 01:33
**Files:** web/lib/agents/__tests__/agent-run-result.integration.test.ts; web/lib/agents/__tests__/persistent-park.integration.test.ts; web/lib/scratch-runs/__tests__/dispatch-window.integration.test.ts
**Severity:** medium

## Problem

The full integration run at `801c8f1b1` reached stricter ownership checks with
older test fixtures. Seventeen result-consumer cases and one nonpersistent park
case supplied an unrelated in-memory assignment. Two scratch restart controls
treated the native adapter as a direct Supervisor child, so their signal helper
failed before the intended process-death window.

## Root Cause

The scripted consumer omitted its Run selector and never persisted an ACTIVE
assignment. Result publication correctly rejected that generation. Operational
finalization also requires the host's persisted terminal lifecycle observation;
the legacy scripted stream alone does not supply that independent evidence.

The Supervisor now runs a managed gate as its child and the native adapter as the
gate's child. A positive native process identity with that ancestry cannot meet
the old direct-parent assertion. In the FIFO control, the rejected dispatch was
hidden behind the later database-barrier timeout.

## Solution

Bind each scripted execution through the existing DB-backed fake host helper to
the actual Run's ACTIVE assignment. Keep the original event stream and result,
integrity, buffer, crash and park assertions. Represent the provider's already
observed terminal session through the actual create-ACK, canonical event ingest
and lifecycle reducers. Do not admit a prompt command that would select another
consumer branch, mock finalization or weaken the assignment/quiescence checks.
This proves the provider boundary and database reducers, not OS process death.

For native signals, resolve the exact current DB Run, ACTIVE assignment, epoch
and ACP handle. Pass those witnesses to the shared owned-adapter capture helper,
require its actual adapter PID to match the prompt invocation record, then
signal that PID. The helper checks the scoped inventory attestation, native
adapter/gate ancestry and captured owned process group. There is no gate-PID
fallback. Existing FIFO/recovery keys, payload, target session and application
counts remain the acceptance criteria.

## Prevention

When an ownership boundary tightens, make its fixture carry the actual durable
owner before interpreting a failure as a domain regression. Keep terminal event
evidence separate from absence of live sessions. Signal targets must follow the
current Supervisor process architecture; never infer a native PID from the
manager PID or an old direct-parent assumption.

The consumer inventory found the two changed DB-less scripted helpers.
`agent-hook-trip.integration.test.ts` already persists its matching assignment;
`agent-session-replay.integration.test.ts` already binds through the shared host
helper. They were not changed. Native proof is centralized in
`capture-supervisor-process-groups.ts`, owned by a separate fixture maintainer.

Evidence: original full-run failures are retained in
`/private/tmp/maister-web-full-integration-final-failures.json`; the first scoped
run reached 19/24 with five operational quiescence refusals in
`/tmp/maister-scripted-active-assignment-green.log`. A diagnostic with direct
terminal fixture rows reached 24/24 in
`/tmp/maister-scripted-active-lifecycle-green.log`; that row setup was replaced
with the real canonical reducers before final acceptance. An intermediate
separate host stream passed but caused `event_stream_mismatch` during artifact
cleanup. Reusing the fake provider's existing `publishCanonical` stream removed
that fixture fault. Final reducer-based validation is **24/24 GREEN** across both
files in `/tmp/maister-scripted-provider-stream-green.log`; both test databases
stopped. Native restart validation remains pending the coordinated Web build
window. Scoped ESLint and `git diff --check` pass. No production fence was
changed and no OS process-death claim comes from the scripted suites.
