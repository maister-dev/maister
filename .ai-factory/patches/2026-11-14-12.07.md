# Keep preview and work controls tied to their current source

**Date** 2026-11-14 12:07 Europe/Moscow

**Files** Launch preview, project configuration receipt, Run workbench, artifact readers and Librarian history

**Severity** high

## Problem

A package selection preserved a runner from the preceding preview. A stale
HITL question or memory suggestion continued to show confirm controls.
Refreshing project configuration could leave the same push receipt stuck.
A newer check hid an earlier live blocker from Results, and the browser's
preview limit still allowed the original artifact to be read by the server.
A subsequent browser run exposed a Run Git panel that could close after a
successful PR mutation.

## Root Cause

The form had two runner states, the Git dialog had two receipt authorities,
and the Librarian counted pending rows without verifying their frozen targets.
Results collapsed display rows before applying readiness policy. Artifact
preview used the download response and trimmed it in the browser. The Run Git
panel kept its disclosure only in a component that could remount on refresh.

## Solution

Derive launch runner state from the draft and acknowledged preview, and apply
no-store to all interactive preview outcomes. Refresh both checkout and current
receipt by GET, keeping the receipt ID and active reviews. Scope eligible
confirmation IDs to the owner and use them for history controls, attention
and indicator. Apply canonical blockers before grouping Results. Terminal
receipt observations and Run refreshes preserve the selected UI state.

Use a dedicated `view=preview` request with server-owned limits and an explicit
truncation header. The original download remains separately addressable.
Filesystem and Git readers use bounded reads. Execution-object previews carry
a verified byte range, with full representation verification at the host.

## Prevention

- Exercise the second Flow or cut choice before allowing submit. Assert which token and runner selection reaches the handler.
- Change HITL and memory independently while keeping the SSE cursor fixed. Check the count, controls and historical receipt in the same regression.
- Exercise a receipt's pending, unknown and terminal transitions under one ID. Require focus before sending Escape to a docked panel.
- Compare Results against merge readiness and exercise exact-limit, overflow and multibyte payloads at the HTTP boundary.
- Audit consumer seams with `rg 'liveBlockingGates\(|readEligibleConfirmationIds|/artifacts/.*/payload|refreshObservation|workspace_branch_delivery|librarian_history' web docs .ai-factory/plans/feature-ux-dogfooding-package-2.md`. Direct and batch readiness already use the full gate set. The consensus HITL artifact link remains a download. The migration journal and ERD remain on the existing lineage.
