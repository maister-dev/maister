# Preserve authority and identity across vault disclosures and retries

**Date:** 2026-11-20 13:07
**Files:** `web/lib/agent-memory-vault/`, `web/lib/agents/installation-facade.ts`, `web/lib/brain/knowledge-execution-access.ts`, `web/lib/librarian/`, `web/lib/queries/inbox-review-actions.ts`, `web/components/{agents,inbox}/`, `mcp/src/tools.ts`, main migration 0354
**Severity:** high

## Problem

Launch and resume could present retained memory after a source grant changed, and a vault within its note quota could exceed the native provenance budget. Librarian history search returned governed excerpts without capturing their restrictions on the receiving turn. Legacy import could reuse a receipt after a project slug changed owners. Installation readers and Inbox or Memory users could encounter a mismatched response shape, an unusable continuation, or an ambiguous write outcome after a lost response.

## Root Cause

- Several disclosures treated a separately authorized read, historical capture, or response lookahead as equivalent to the data actually returned in the current transaction.
- File paths, descendant directory generations, and the currently visible Inbox selection were used as identities across operations. Each can change independently of the original owner, selected subtree, or committed request.
- Review previews truncated content at a display limit. Their HTTP surface offered no way to continue inspection.

## Solution

Use current source authority for both on-demand and prompt delivery. Bound prompt paths against the packet and provenance budgets before capture. Retain sources when a Librarian tool returns guarded excerpts, and fence personal-memory writes when its storage cannot preserve those restrictions. Bind note import receipts to the original project and agent in migration 0354. Keep installation response schemas and filters specific to the credential, expose consumable continuation cursors, and capture only returned contributors plus explicitly addressed authorized targets. Keep the selected subtree generation and replay the exact serialized command or batch after uncertain delivery. Page full vault and Brain previews using a cursor bound to the reviewer, proposal version, and content.

## Prevention

- Check `rg -l 'stageProjectAgentMemory|stageProjectFlowMemory|stageInstallationAgentMemory|assertMemorySessionSources' web/lib` after changing launch authority. The sweep includes standalone launch and prompt ownership, the Flow runner, the node prompt and consensus prompt owners, and protected-findings tests.
- Check `rg -l 'installationReadAdapter' web/app/api` against the OpenAPI credential and response variants. It resolves six shared project, task, and Run handlers. The installation-only Observatory handler needs its own contract assertion.
- Check `rg -n 'assertMemoryTurnFence|lockLegacySource|assertReceiptOwner' web/lib/librarian web/lib/agent-memory-vault/import-legacy.ts` when a rule changes. The fence serves direct writes and proposed personal-memory cards. The source lock and receipt owner check serve each import checkpoint, activation, and cleanup.
- Exercise response loss after the server changes the visible list, authority changes after staging or before a later page, and migration from the actual prior schema. Keep these cases in the boundary that owns the invariant.

## Regression witnesses

| --- | --- | --- |
| PostgreSQL vault launch and resume | A staged project prompt was restored after source revocation. A default-size native vault failed capture validation. | Resume refuses the revoked reference. Fresh launch retains the authorized index and only paths it can record. |

| Memory and Inbox DOM | Descendant generations conflicted with their parent. Retrying recomputed a mutation or generated new keys after commit removed rows. | The request keeps the selected subtree generation. An unchanged retry sends the original request bytes. |
