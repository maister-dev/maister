# Patch: Brain review follow-up exact-failure coverage

## Trigger

A second review pass found two residual issues after the Project Brain B/C
review-fix sweep:

- Glob source validation enforced `BRAIN_SOURCE_MAX_GLOB_MATCHES` only after the
  full tracked tree had already been walked.
- Implemented Brain web routes returned `MaisterErrorBody` with
  `PRECONDITION` on 404, while the web OpenAPI contract still advertised the
  generic `NotFound` response.

## Root Causes

- The broad-glob regression test only asserted `PRECONDITION`; it did not track
  the fixture files or assert the match-limit message, so the test could pass on
  the wrong precondition path.
- The API docs fix needed operation-level anchoring. Replacing repeated response
  refs without enough route context can touch unrelated OpenAPI operations.

## Rule

When fixing review findings after a large docs/code parity sweep:

1. Turn each valid finding into a focused regression that proves the exact
   failure mode, not only the shared error code.
2. For resource caps, assert the boundary value in the error evidence so a test
   distinguishes early rejection from post-hoc counting.
3. For OpenAPI response-body parity, patch by `operationId` or route block and
   run `git --no-pager diff -- docs/api/*.yaml` before validation.
4. Run focused route tests, the affected integration test, `pnpm
   validate:contracts`, typecheck, lint, and `git --no-pager diff --check`.
