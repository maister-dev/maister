# Keep stream ownership and original failure evidence through teardown

**Date:** 2026-11-04 12:35
**Files:** supervisor/src/bounded-acp-stream.ts; supervisor/src/acp-client.ts; web/lib/agents/{operational-integrity,preparation-ownership,preparation-workspace,preparation-trace,create-failure,finalization,launch}.ts; web/lib/tasks/launch-agent-definition.ts; existing owning tests and mock ACP fixture
**Severity:** high

## Problem

A native child could exit while its frame spool was opening and lose every stdout frame without an output failure. Preparation diagnostics could replace the first I/O failure with a secondary close, lease-journal, or release error. Private capture cleanup could also erase the exact pending or fencing error type. After rebasing the checkpoint guardrail change, genuine adapter responses completed during graceful checkpoint teardown became rejected CHECKPOINT commands.

## Root Cause

The readable preservation listener was owned by a lazy generator reached only after asynchronous spool creation. Node automatically resumes child stdio on exit, so bytes had no reader during that gap. Failure cleanup used throwing finally blocks or AggregateError wrappers before the primary error was durably projected or classified. The new checkpoint marker was checked unconditionally after a successful ACP response, treating explicit completion as interruption.

## Solution

The capture owner installs the existing readable listener synchronously and releases it after drain or output close. Probe handles and preparation/capture owners retain the exact first exception, attempt their owned cleanup, and record safe bounded secondary cause chains with operation and owner context. Cleanup without an earlier failure still throws.

Error preservation must not swallow ownership loss. A real same-assignment successor could claim after the failed driver's physical release, and the old assignment-only finalizer then marked that successor Failed. The preparation owner now stays physically held through terminal DB commit. Shared apply validates its exact operation/resource/incarnation/assignment/epoch and current phase/lease; a released owner cannot supply this proof. Failure publication reporting assignment_fenced yields after logging the original failure. A generic pre-dispatch finalizer cannot omit a known preparation owner. Release precedes cleanup afterCommit, avoiding a self-busy cleanup cycle. Actual historical dispatch chooses the existing regular finalizer with its unchanged canonical and scoped process-quiescence requirements; it is not treated as a never-started execution. A real non-cancelled ACP response retains its existing stop reason; only a cancelled response or exact SDK transport abort can become a proven intentional checkpoint interruption.

## Prevention

- Hold real child exit behind the actual spool-open barrier; verify all frames and listener release, not merely an error count.
- Test first failure plus cleanup failure and cleanup-only failure separately. Close real resources before injecting secondary faults; never close raw FileHandle descriptors in a shared test process.
- Assert pending/fenced identity survives cleanup. Real PostgreSQL failure-publication refusal must not erase the original pre-model diagnostic or issue model commands.
- Test terminal settlement versus a same-assignment preparation claim, in both accepted-successor-first and terminal-commit-first orders. Retain physical ownership through the exact fenced DB write; logging the primary error does not authorize a stale finalizer. Distinguish historical diagnostic/object commands from model create/prompt commands.
- Sweep real finalizer consumers, including a continuation whose old session is canonically exited. Its preparation refusal must preserve the existing integrity/evidence outcome through the full quiescence path.
- Check the complete installed ACP StopReason union. Exercise real responses on SIGTERM, including cancellation and explicit adapter errors, without converting completed work into a new turn.
- A native gate PID is not the adapter PID. Inject ACP loss into the positively recorded adapter, and qualify fixture cleanup with an invocation ledger.

## Evidence

R1 actual native-child RED received zero frames instead of three; its owning tests are green. A real PostgreSQL release barrier accepted a same-assignment preparation successor before the old failure terminalized it; that takeover RED is now closed with exact-owner and lease/cleanup controls. R5 real-file controlled read/close RED lost read/EIO, and real PostgreSQL journal/refused-release RED lost native diagnostics or fencing; owning preparation cases pass. R8 actual adapter response-on-SIGTERM RED rejected all four non-cancelled stop reasons; the nine-case checkpoint owner now passes with zero fixture leaks. These are local scripted-provider findings, not reconstructed production MAI-27 history or paid-provider evidence. Full combined acceptance remains the coordinator's gate.
