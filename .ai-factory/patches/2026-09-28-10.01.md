# Late HTTP acknowledgements overwrote run state, a race skipped the assistant gate, and a re-stamped turn rolled back a finalization

**Date:** 2026-09-28 10:01
**Files:** web/lib/scratch-runs/events.ts, web/lib/services/hitl.ts, web/lib/agents/create-failure.ts, web/lib/scratch-runs/__tests__/scratch-idle-resume.integration.test.ts, web/lib/scratch-runs/__tests__/scratch-idle-resume-assistant.integration.test.ts, docs/system-analytics/{scratch-runs,hitl}.md, docs/api/web.openapi.yaml, docs/error-taxonomy.md, docs/decisions.md
**Severity:** high

## Problem

A Codex adversarial review of the ownership-residuals branch raised three findings. The full integration lane of the previous fix round was also red.

- **A late acknowledgement overwrote newer state.** The stored-answer delivery's `onAck` set the dialog and run `Running` unconditionally. Holding the input response in the fault proxy showed it concretely:
  - The agent got the answer and finished the turn (`WaitingForUser`); the late ack flipped the dialog back to `Running`, a busy dialog with no turn.
  - A run stopped meanwhile (`Review`) was resurrected to `Running`.
  - The failure branch did the same with `NeedsInput`: a stopped run was re-opened.
- **A race skipped the assistant gate.** The ADR-097 launching-user + lock gate ran only when Phase 1 read `NeedsInputIdle`. If the host had parked the session but the projection still read `NeedsInput`, another user's answer was stored through the live path. The host answered 410 `session_checkpointed`; the route parked and resumed. The resume claim checked only the lock, so another user's answer respawned a session into the launching user's working dir.
- **A restart window between a dispatch's commit and its prompt admission.** Classified as pre-existing and systemic, not fixed (see below).
- **Two prompt-owners reds.** "owner-agent-message settles a failed retained create" stayed `Running` for 30 s. It reproduced idle, and passed at `HEAD`, so the previous round's uncommitted change caused it.

## Root Cause

- **An HTTP acknowledgement is outside the event stream's order.** The ack's transaction runs whenever the HTTP answer lands. The turn completion and the stop are applied from other paths meanwhile. A status written from an ack therefore has no ordering guarantee. The write was also redundant: the idle resume had set `Running` before prompting, and this path never parks the dialog.
- **A gate placed at one observation of the state, not at the transition it protects.** The gate keyed on what Phase 1 read (`NeedsInputIdle`). The privileged effect is the resume itself, which two entries reach: the parked path and the checkpointed-session arm.
- **A widened writer met an immutable column.** The previous round made finalization supersede `claimed` message turns and stamp `completed_at`. `settleAgentCreateFailure` supersedes its own source turn again after `prepared.apply()`, with a fresh `new Date()`. Trigger `agent_turns_binding_immutable` (0180) refuses a change to a set `completed_at`, so the whole settle rolled back. The previous round's sweep checked the readers of the new supersede, not the writers after it in the same transaction.

## Solution

- **The ack writes no status.** It stamps only `responded_at` and `_audit`. The failure branch surfaces `NeedsInput` only inside a transaction that locks runs, then the HITL row, and only if all of these still hold:
  - the run and the dialog are `Running`;
  - the row is unanswered;
  - the row is still bound to this session and request.
- **The gate runs at the resume.** `runScratchIdleResume`, which both entries pass, runs `assertParkedAssistantAnswerable` for a project-less run under the scheduler lock and the run lock. A refusal withdraws the stored answer (`response = NULL`), so nothing can resume on it and its owner can answer afresh. The Phase-1 gate stays, so a parked answer is still refused before anything is stored.
- **The create-failure supersede is guarded** on `state = 'claimed'`. It is a no-op when finalization already superseded the turn, and still supersedes a non-message source turn.
- **Tests.**
  - The idle-resume suite now runs through the fault proxy. Three new real-supervisor cases hold the input: the response while the turn completes, the response while the run is stopped, and the request while the run is stopped, then cut.
  - The assistant suite covers the checkpointed race with a fake host (an exited session with `intentionalReason: "checkpoint"`).
  - Each test was falsified against the old code: an ack flip, a catch without a guard, and a removed gate each turned it red.
- **The adversarial re-review of this cycle (no BLOCKER) led to these fixes:**
  - The idle resume closes every request of the parked session that nobody answered. The host keeps parallel requests pending, and such a row pinned the dialog `NeedsInput` through the delivered-flip guard.
  - An answer to a row closed before anyone answered it gets 409 `not_awaiting_input`, not "already delivered". The unit fixture that seeded `respondedAt` without a response was corrected to a delivered row.
  - The resume gate runs only while the run is still parked, and withdraws only an answer that request itself stored (an identical answer already stored belongs to whoever gave it).
  - The rebind picks the stored row whose identity matches, else the newest.
  - A closed row answers its reason before the assignment claim, whose cancelled-assignment refusal hid it for flow and agent rows.
  - A failure of the surfacing transaction no longer escapes into the handler's cancel path.
- **A third, narrow re-review (MINORs only, parallel-request edges) led to these fixes:**
  - A no-match retires the stored answer only in a single-request park. With several requests parked, the re-raised one may be another of them, so the answers wait for their own re-raise or for the turn's completion.
  - The delivered-flip guard counts only the delivered request's own host session. An earlier session's open row no longer pins the dialog.
  - A failed surfacing transaction is retried once, then escapes to the cancel path rather than hanging the turn.
  - The pre-assignment refusal also covers rows closed unanswered (409 `not_awaiting_input`).
  - One real-supervisor case (a parallel request re-raised first, then answered live) falsifies the first two. A flow case with a cancelled assignment falsifies the last. The retry-once has no test: it would need injecting a transaction failure.
- **Recorded, not fixed:** a parked session's late exit event overwriting its successor's dialog (unmeasured reachability; `decisions.md`), and Stop/Discard never closing open permission rows (pre-existing; `decisions.md`). The failure branch's positive case (a live session refusing a pending request outright) has no test: the host never produces that refusal for a valid held request, and the proxy never invents host evidence. The key-left-set concern is moot once a withdrawal is limited to an answer stored by the refused request.
- **The restart window is recorded, not fixed (owner decision).** Every scratch dispatch commits `Running` before admitting its prompt: the launch, the queued dispatch and Recover on master, and the idle resume. Rerouting the idle resume through the queue would not close the dispatcher's own window. The TODO is in `docs/decisions.md`, with a follow-up task to design a sweep that proves from the command ledger that no prompt is in flight.

## Prevention

- **Never write run or dialog status from an HTTP ack.** Status belongs to the ordered paths (the event projection and the locked transitions). An ack may stamp only facts about its own command and row. When an ack must move state, fence it on the state it expects under the run lock.
- **Put a gate at the privileged transition, not at the observation that usually precedes it.** List every entry into the effect: `rg "runIdleResumeForKind|runScratchIdleResume"` found the checkpointed arm.
- **When a writer is widened, sweep the writers after it in the same transaction, not only its readers.** `git grep -n "\.apply(tx)"` plus `git grep -n "update(agentTurns)"`. Any later update of the same row must tolerate the earlier write, especially for columns an immutability trigger guards (`completed_at`, `command_id`, the binding).
- **A withdrawal names its owner.** Before undoing stored state on a refusal, check that the refused request is the one that wrote it (here `claim.kind === "claimed"`), and that the state has not moved on (the run is still parked).
- **Scope a "nothing else is open" guard to the resource that holds it.** A NOT EXISTS over the whole run counts rows no live session can ever release (an earlier session's), so one leftover row pins the dialog for good. Scope it to the host session the delivered request belongs to.
- **Swallowing a failure is also a policy.** A best-effort write that swallows its error can hang the caller as surely as escaping can cancel it. Pick the outcome deliberately: here, retry once, then fail closed (cancel the request) rather than leave it waiting.
- **A pre-lock read is fine for final markers.** A refusal that depends only on a value that never reverts (`response._closed`) can run before the side-effecting claim (the assignment), so the claim's own refusal cannot mask it.
- **Race tests hold the wire, not the database.** `supervisor-fault-proxy` `hold-response` reproduces the late ack naturally (the host acts, only the answer is late), and `hold-request` + `cut()` reproduces the failed delivery.
- **Classify a red by baseline before fixing it.** The prompt-owners reds reproduced idle but not at `HEAD`, which pointed at this round's diff. A one-line revert experiment then confirmed the cause before any fix. The two tests `HEAD`'s own run failed (`owner-agent-initial recovers after SIGKILL…`, and a 28-minute `…cannot finalize a successor assignment…`) passed in both working-tree runs, so they were not this round's.
