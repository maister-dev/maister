# Recover failed agent work after changing its runner

**Date:** 2026-11-02 00:43
**Files:** `web/lib/agents/{retry*,launch,finalization,activity-types}.ts`, scoped retry routes, migration 0210, agent retry/history/settings components, EN/RU messages, integration/DOM/E2E tests and owning contracts.
**Severity:** high

## Problem

Old triager failures refused retry after a runner change with
`reconciliation_required`. The dialog hid runner selection behind eligibility,
refresh produced no visible feedback, and a failed backlog had no batch recovery.
Saving a new agent runner did not offer recovery of pending work.

## Root Cause

- Generic replay correctly required positive pre-work evidence, but offered no
  distinct explicit current-task reassessment for historical triager sessions.
- Operational finalization could replace the diagnostic cause and lose the
  undispatched-failure producer's proof.
- Retry previews did not identify the current effective runner. Request/cleanup
  state conflated a definitive refusal with an unknown delivery outcome.
- Source-only deduplication did not serialize fresh assessments of one task
  across several failed sources.
- Snapshot validation alone did not guarantee consumption of the accepted SHA,
  configuration, policy and branch inputs at launch.

## Solution

Keep generic pre-work replay strict. Add explicitly confirmed fresh qualification
for the current pinned operational qualifier, with current task/repository inputs,
task-level locking, current-assessment/active-work guards and atomic legacy opt-in.
Retain source history and preserve explicit user launch intent. Version-two recipes
freeze the strategy and launch inputs; version one retains its original semantics.
Migration 0210 expands the existing CHECK without deleting receipts.

Batch preview/acceptance delegates to the single retry owner, scopes every source
before accepting a prefix, keeps per-item keys and reports refusal/unknown states.
After a successful runner change, offer the batch without automatic acceptance.
Always show runner/remediation, announce refresh, recover stale cleanup revisions,
and label pending unknown batches explicitly. Bounded preview windows must remain
navigable beyond 100 retained failures, including blocked windows, with a return
to the newest failures.

## Prevention and verification

- Test business safety separately from transport/process completion. Never infer
  absent effects from prose, zero tokens or a missing result file.
- Assert the actual successor snapshot and selected runner, including a target-ref
  race and legacy recipe compatibility. Exercise independent old sources sharing
  one task concurrently.
- Test batch response loss, foreign-source rejection before a prefix, pagination,
  stale cleanup revisions, unknown-request selection changes and failed previews.
- Browser acceptance covers settings save → offer → explicit confirmation → two
  completed successors, and proves save alone creates none.
- Focused retry integrations: 17 passed. Shared real-launch consumers: all 18
  suites / 147 tests passed. Additional finalization, integrity, attention and
  qualification regression set: 36 passed. Browser suite: 8 passed with clean
  owned-process/database cleanup. Type, contract, documentation and schema gates
  pass; DOM interaction regressions cover the UI recovery state machine.
