# Repeated production-fault database setup exhausts hosted isolation time

**Date:** 2026-10-02
**Severity:** high
**Status:** Locally qualified; hosted Intel acceptance remains open.
**Files:** `web/test-support/pg-container.ts`, `production-fault-fixture.ts`,
its three owning integration suites, `pg-template.integration.test.ts`,
`docs/system-analytics/test-infrastructure.md`.

## Problem

Hosted run 36877828238 stops the Intel isolation slice with exit 124 after the
production build succeeds. The complete reporter is absent; preflight is not
proof of the full lane.

## Root Cause

Nineteen fresh container/main/Brain setups consume 926.013 seconds of the slice,
including 621.18 seconds replaying main migrations. Every production fault case
repeated the same schema preparation. This is a measured removable cost, not
proof that this fix alone will satisfy the Intel budget.

## Solution

Run unchanged main then Brain migrators once in a suite-owned disposable
Testcontainers container. Disable connections to the template; clone a unique
writable database before each case's seeds. End case pools and drop their DBs
only after production clients stop. Suite cleanup awaits pending allocations,
rejects late allocations, reports unclosed cases, and still reclaims the
container. No truncation, handwritten schema, durability change or skipped
fault controls. Historical migration tests retain their original path.

Sibling sweep: `rg -n 'startProductionFaultFixture' web` before modification
found the implementation and only these consumers:
- `web/test-support/__tests__/execution-ab-partitions.integration.test.ts`: fixed.
- `web/test-support/__tests__/execution-ab-process-death.integration.test.ts`: fixed.
- `web/lib/scratch-runs/__tests__/dispatch-window.integration.test.ts`: fixed.

Other isolation consumers of `startMainAndBrainPostgresTestDb` use beforeAll,
already migrating once per suite; they are intentionally unchanged. Preflight
retains its own independent runtime/migration proof.

## Validation and prevention

The real RED control fails when allocation delegates to the former per-case
container/migration path. Clone controls check real container identity, schema
and application-write isolation, both migration ledgers and requested pool size.
Negative controls cover frozen templates, pool cleanup failure, unclosed cases
and an allocation racing with suite shutdown. Review identified and corrected
the latter race and guaranteed cleanup after assertion/allocation failure.

Static checks pass. After the owner woke the host, the fresh helper aggregate
passes 8/8; existing unit controls pass 2/2. The unchanged full isolation CLI
passes 7 suites / 50 cases in 813.192 seconds including cleanup, with no skips
or leaks. Its exact suite and mandatory-title validation passes. The 22 clones
cost 572 ms combined locally. Evidence is linked in the CI/R9 plan.

Earlier local aggregates remain failed sleep-interrupted evidence, confirmed
by pmset timestamps. Local ARM64 results do not prove Intel budget recovery.
Owner push and exact hosted artifact validation remain required. Platform,
60-minute job and slice limits stay unchanged.
