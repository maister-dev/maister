# Run transcript reads cannot starve behind live updates

**Date:** 2026-11-02 14:45
**Files:** web/components/runs/{agent-run-transcript,node-transcript-panel,run-transcript-panel,run-transcript-history,run-peek-transcript}.tsx; web/app/api/runs/[runId]/transcript/route.ts; web/e2e/run-transcript-history.spec.ts
**Severity:** high

## Problem

An active Run displayed empty agent activity despite successful transcript
responses. Firefox reproduced fifteen reads in twenty-two seconds while no
history was visible. Each read downloaded the whole conversation.

## Root Cause

The main Run and Flow-node panels independently implemented latest-request-wins
loading. Live ticks issued a newer read before the preceding response arrived,
so repeated events invalidated every completed response. Pending reads and
failures also used the true-empty label. The child peek already had bounded
pages, request coalescing, cancellation and explicit loading/error states.

## Solution

Share that existing reader across all three surfaces. One refresh owns its
response; notifications received during the read request one subsequent refresh.
Load 100 messages per page and retain no more than five windows. Preserve the
visible content while prepending history in either the document or peek scroller.
Keep execution activity separate from connection liveness when rendering terminal
Run tools. Paged API debug logs record read duration, message count and projection
state without message bodies.

## Prevention

Hold a real initial transcript response while committed message changes arrive
over the workbench stream; verify it is displayed before the coalesced refresh.
Exercise both agent and Flow-node panels, failed-read retry and bounded parent
history with scroll retention. Reuse the canonical paged reader instead of
introducing another client concurrency policy.

Sibling sweep: `rg -n 'reqIdRef|transcript\\?node|CHANGE_SUMMARY_REFRESH_DEBOUNCE_MS' web/components/runs/{agent-run-transcript,node-transcript-panel,run-transcript-panel,run-transcript-history,run-peek-transcript}.tsx`
returned no matches. Both duplicate latest-wins readers were removed; peek uses
the same shared implementation. The legacy full-transcript API remains available
for existing non-panel consumers.
