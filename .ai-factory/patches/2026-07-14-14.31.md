# Bootstrap missing `maister.yaml` at project registration

**Date:** 2026-07-14 14:31
**Files:** `web/app/api/projects/route.ts`, `web/app/api/__tests__/projects-register.integration.test.ts`, `web/app/api/__tests__/projects-register-clone.integration.test.ts`, `web/e2e/project-onboarding.spec.ts`, `docs/api/web.openapi.yaml`, `docs/system-analytics/projects.md`
**Severity:** medium

## Problem

Adding a repository without `maister.yaml` did not establish the project configuration file required for normal project lifecycle operations.

## Root Cause

The registration route accepted the missing-manifest case through a database-only default configuration path. It did not create the source-of-truth manifest in the repository, leaving the registration contract inconsistent with the expected onboarding behavior.

## Solution

Atomically create a minimal, schema-valid `maister.yaml` before re-entering the normal registration path. The generated file records the requested project name (or directory basename) and an empty `flows` list. If registration fails afterwards, remove only the byte-for-byte unchanged generated file. Existing invalid manifests still fail validation and are never replaced.

## Prevention

Integration coverage now verifies both local-directory registration and cloned-repository registration without a manifest, including the persisted manifest path and generated file contents. The API and operator documentation define the bootstrap contract and retain nullable manifest paths only for legacy database rows.
