# Fence review rework from lease-expired gate chat

**Date:** 2026-07-14 23:40
**Files:** `web/lib/services/gate-chat.ts`, `web/lib/services/hitl.ts`, review-feedback preview route and integration coverage, ADR-138 contracts
**Severity:** high

## Problem

Expiring a pending gate-chat lease inside response admission allowed rework to
start while the original ACP request could still execute its L3 workspace
restore. Preview also advertised a pending-chat refusal without enforcing it,
and equivalent retry objects could conflict solely because their keys arrived in
a different order.

## Root Cause

The lease was treated as a terminal coordinator outcome rather than as a
cancellation deadline owned by the running chat handler. The response and
preview paths therefore had different fencing rules, while idempotency compared
raw JSON serialization.

## Solution

Lease expiry now asks the supervisor to cancel but leaves the coordinator
pending until the owner has awaited the prompt, performed L3 restore, and
written its terminal abort. Preview performs a read-only pending-turn check, and
response equality uses recursively sorted object keys while preserving array
order. Tests cover no-mutation preview rejection, lease cancellation with L3
restore, and reordered review retry idempotency.

## Prevention

ADR-138, API, analytics, database, ERD, Flow DSL/graph, roadmap, and the
implementation plan now state the same fail-closed lifecycle and
scope-selected review source. Any future coordinator change must preserve the
rule that a lease cannot release the rework fence before L3 settles.
