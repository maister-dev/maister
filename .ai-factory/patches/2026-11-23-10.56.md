# Handle ACP auth status during resume and retain unsupported message diagnostics

**Date** 2026-11-23 10:56 MSK

**Files** `supervisor/src/bounded-acp-stream.ts`, `supervisor/src/spawn.ts`, shared runtime diagnostic parser, Agent Run terminal projection and notice, contracts and focused tests

**Severity** high

## Problem

MAI-33 could not resume after human input. Supervisor reported `ACP_PROTOCOL`, `required_output_incomplete` and `producer_method_unsupported`. The command failed at 09:50:03 MSK. The Run finalized at 09:51:14 MSK. Its diagnostic record omitted the method and JSON-RPC kind.

## Root Cause

`codex-acp` 2.9.0 emits standard `auth/status_update` alongside its legacy extension. Both are notifications. The bounded stream forwarded legacy extension traffic to the SDK and rejected the new standard method. The real pinned adapter reproduced the same refusal locally against a synthetic app-server thread.

## Solution

Recognize `auth/status_update` as an informational notification. Keep existing capture and refuse unsupported messages with a typed diagnostic limited to the method identifier and envelope kind. Correlate the supervisor log with the exact command. Pass only diagnostics from the authoritative create or prompt failure through Agent Run finalization and show them in the shared terminal notice.

## Prevention

Exercise the real pinned adapter across the bounded stream at resume. Assert that the same session accepts its next prompt. Check that unsupported request and notification frames still fail with safe metadata and that the accepted command failure reaches the Run and the localized notice.

The sibling sweep used `rg -n 'boundedAcpStream\(|producer_method_unsupported|settleAgentCreateFailure\(|readUnsupportedAcpMessage\(' supervisor/src web/lib runtime`. The protocol rule covers the shared supervisor stream. Agent create and prompt use their exact receipts for terminal projection. Flow and Scratch retain the shared supervisor journal and receipt diagnostics.
