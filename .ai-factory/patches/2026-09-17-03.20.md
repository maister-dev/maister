# One NUL in an agent payload stopped the whole event plane for 15 hours

**Date:** 2026-09-17 03:20
**Files:** `web/lib/execution-host/events/{jsonb-safe,ingest,consumer,stream-health,transcript-projector}.ts`, `web/lib/execution-host/{ledger,recovery,deliverer,commands}.ts`, `web/lib/run-transcript/transcript.ts`, `web/lib/scheduler/system-sweeps.ts`, `web/lib/instance-config.ts`, `web/lib/db/schema.ts`, `web/app/api/v1/ext/runs/[runId]/recover/route.ts`, `supervisor/src/host-state.ts`, docs
**Severity:** critical

## Problem

Run `0a74a6aa` hung in `Running` then `Failed`. `max(received_at)` on
`execution_events` was 15 h stale — host-wide, every run — while
`execution_event_streams.state` read `active` and `execution_hosts.readiness`
read `ready`. A second fix attempt died with `EXECUTOR_UNAVAILABLE` / "session
incarnation projection is not ready for prompt admission".

## Root Cause

`execution_events.payload` is a **`jsonb`** column, and PostgreSQL cannot
represent `U+0000` there (`22P05`). Host sequence 181545 carried a NUL escape —
emitted, with some irony, by an agent editing a NUL-escaping bug. The insert
threw, the consumer recorded `last_error` and retried, and because the
contiguity walk stops at the first missing sequence, every later event of every
run was held behind it. 3748 warn lines were emitted and nothing consumed them.

Three further defects turned a bad event into a 15-hour outage:

1. **Nothing read the liveness columns.** `last_seen_at`, the gap columns,
   `last_error` and `next_retry_at` were write-only repo-wide; the `lost` and
   `closed` stream states were unreachable enum members.
2. **A prompt cannot terminalize without an ingested terminal event**
   (`prompt-evidence.ts:288`), so the stuck `accepted` command and the empty
   `run_session_incarnations` projection were both *consequences*, not
   independent defects.
3. **The supervisor conflated an absent replay cursor with a lost one**
   (`host-state.ts:1733`), so a cursor-less consumer was refused forever by any
   host that had ever pruned — a second, independent way to wedge the plane.

## Solution

Escape the characters `jsonb` cannot hold, reversibly, once at the ingest parse
site so payload/digest/bytes agree — and decode at the transcript read boundary,
because an escape without a matching decode trades an outage for silent
corruption. Add the doctrine backstop the repo already states but had not
implemented for this case: an event PostgreSQL still refuses goes to the skip
ledger as `payload_unstorable` and the walk advances.

Then make the plane observable: a `system_sweep` pass that restarts the consumer
first and degrades to `lost` only when a restarted one still cannot advance; a
command-impasse counter; a classified (permanent) projector failure; poisoned
consumers reported.

## Prevention

- **A column type is a contract.** Before writing untrusted text into `jsonb`,
  ask what that type cannot represent. `text` would have stored this fine — the
  transcript's `run_messages.content` did.
- **"Could this ever become ingestable?" must be asked of every ingest-time
  throw.** `CLAUDE.md` already legislated this for unknown runs; nobody applied
  it to write failures. The rule is the class, not the cited case.
- **Write-only telemetry is not telemetry.** Grep for a READER before trusting a
  column, a health method, or an enum value. `ProjectionWorker.health()`,
  `last_seen_at` and `state='lost'` all existed and none had a caller.
- **A liveness predicate needs a positive expectation of activity.** There is no
  heartbeat event and one stream serves a whole host, so "silent for N seconds"
  would have flagged every idle stand. The stall is *open work producing no
  events*.
- **Three "independent" defects in a report are a hypothesis.** Two of these
  were consequences of the first, and fixing them as filed (a blind `accepted`
  timeout) would have violated the retirement doctrine.

## Findings that changed the plan mid-flight

- **Live-state admission broke a documented invariant.** Re-reading the
  assignment state at admission looked obviously right; test D3 states that a
  superseded assignment's original owner may still delete its own immutable
  runtime objects. The snapshot's looseness was load-bearing. Reverted to a log.
- **Clearing `runs.execution_assignment_id` on release would have regressed
  `legacy.ts`**, which reads NULL there as "legacy run never placed". ~25
  readers; the grep was the whole answer.
- **`forAssignment` must NOT assert `state === 'active'`** — `isAdmissible`
  deliberately permits teardown kinds on a released assignment.
- **The operator's `curl` never reached the comparison it accused.** The
  supervisor parses no query string, so `?afterSequence=` was discarded on every
  attempt; the refusal came from the null-cursor branch, not an inverted one.
- **A neuter that breaks syntax is not a falsification.** The first floor
  falsification produced "no tests" and was discarded and redone.
- **Two failures were baseline-proved, not fixed**: `projection-worker`
  AT-03 and `deliverer` D3 fail identically on the unmodified tree under full-lane
  contention and pass standalone.
