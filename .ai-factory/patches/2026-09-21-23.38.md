# A tab whose href was written before the reader's last click

**Severity:** medium

## Problem

An earlier round made the filter bar compose each commit onto the edits still in
flight, which closed half a class. The other half stayed open and ADR-178
recorded it as intended: a view tab is a `<Link>` whose href the SERVER built
from a `current` that predates anything just committed, so clicking one dropped
that commit. The not-applied hint was the whole mitigation.

Two ordinary gestures hit it. A period preset and then a tab are two clicks in
one motion, and the tab's href predates the preset by construction. Worse,
clicking a tab BLURS a focused text field, which COMMITS — so the commit the
click itself causes was exactly the one the click discarded. The reader landed
on the new view filtered by nothing, holding text the page was not using.

Separately, `m23-observatory.spec.ts:239` flaked at ~25%, and the previous round
had filed it as this race's symptom. It was not.

## Root Cause

**The race.** Ownership of the pending patch was scoped to the bar. Any other
surface that builds a URL from the same filters — a tab, and tomorrow a reset
link or a breadcrumb — reads the server's copy, which is stale the moment a
commit is in flight. Scoping the fix to the component that happened to surface
the bug left every sibling consumer exactly as wrong as before.

**The flake, which was a different thing entirely.** A probe over six runs
showed `hintAfterFill` (the hint renders from component state alone) correlating
perfectly with the outcome: `true` → the draft survived; `false` → it did not,
and one run took a full page navigation (two `load` events). `page.goto`
resolves on load, which in Next dev is well before hydration, so `fill()` set
the DOM value and nothing else. The "draft" was never in React state to survive.
A test-synchronisation defect wearing the costume of a product race — and the
previous round's patch note asserted the product explanation without probing it.

## Solution

The patch moved ABOVE both consumers, into `ObservatoryFilterState`. The bar
commits through it; the tabs build their hrefs from `current` PLUS whatever it
holds, so the two surfaces cannot disagree about what the filters are.

It is held as STATE, not only as a ref: a ref keeps the bar correct and leaves
the tabs stale, because nothing re-renders them. The ref mirror stays for the
other half — two commits inside one tick must compose, and `useState` has not
applied the first when the second runs. Both halves are falsified separately.

`observatoryViewHref` takes the pending patch and applies it BEFORE the
unowned-key drop, so a committed artifact filter still cannot ride into Harness.

The provider has no default value and throws when missing. A permissive default
would let a surface that forgot it keep working while silently dropping every
composed edit — the same invisible degradation the whole change removes.

`Tabs` needed no change: it takes no hooks and adopts its importer's
environment, so the tabs render from a Client Component and stay real `<Link>`s
that push.

The flake was fixed as what it is — the tests now retry the interaction until
React demonstrably holds it, and the preset test proves hydration on a preset it
is NOT racing, so the gate does not close the window the test exists to open.

## Prevention

- **Ask who else builds this URL.** A pending-state fix scoped to one component
  is a fix for one component. The question is not "does the bar compose its
  edits" but "does everything that navigates from these filters read the same
  source of truth".
- **State vs ref is a contract, not a style choice.** If another component's
  RENDER has to reflect the value, a ref is silently insufficient. Falsify that
  specifically: the ref-only variant fails five tests here.
- **Never give a shared-state context a permissive default.** It converts a
  wiring mistake into a silent behavioural regression at the exact moment
  someone adds the next surface.
- **A flake in your feature's area is not evidence about your feature.** Probe
  the mechanism before naming it. Here a four-value probe line separated
  "hydration had not happened" from "the commit was dropped" in one run, after a
  previous round had already written the wrong explanation down as fact.
- **`goto` resolving is not the page being interactive.** In Next dev, an early
  `fill`/`click` lands in the DOM with no React behind it. Retry the interaction
  until an artefact that can only come from component state appears.
