# Fence preparation publication and driver failure settlement

**Date:** 2026-11-03 12:12 Europe/Moscow
**Files:** `web/lib/agents/{launch,preparation-ownership,preparation-workspace,create-failure,finalization,operational-diagnostics}.ts`, preparation ownership integration tests
**Severity:** high

## Problem

An expired preparer could publish baseline bytes before the later preparation
phase update rejected its lease. Workspace resolution/acquisition failures
occurred outside the structured diagnostic boundary. A stale driver could
settle a successor assignment through a generic failure handler.

## Root Cause

Run baseline publication and preparation phase advancement used separate
transactions. The acquisition boundary preceded the diagnostic try/catch.
Driver failure finalization did not carry the observed assignment generation.
The safe error-code filter also discarded numeric-leading SQLSTATE strings.

## Solution

Publish baseline/generation and phase receipt together under current run,
assignment, preparation token and DB-time lease predicates. Capture acquisition
failures inside the diagnostic boundary while yielding busy/fenced owners.
Snapshot each driver's assignment and recheck that exact nullable pointer under
run/assignment locks before terminal writes. Preserve bounded SQLSTATE codes.

Existing structured phase logs, typed fencing errors and persisted safe cause
chains cover diagnosis; no console logging or filesystem content is added.

## Prevention

Treat publication bytes and their durable ownership receipt as one commit.
Carry the original owner through failure paths; rereading a newer pointer is
not authority to terminate it. Exercise lease loss during real capture and
failure-handler races, rather than checking only successful owner acquisition.
