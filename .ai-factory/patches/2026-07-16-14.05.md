## Problem

`/aif-review` on ADR-139/140 produced 10 merge-blocking findings + ~25 more,
after two prior adversarial rounds had missed them. Phase 1 landed two criticals
with no tests. This session executed the remaining plan.

## Root Cause

Two causes explain nearly every code defect:

1. **The sync claim hand-rolled the shared lifecycle claim** instead of behaving
   like one. It inherited neither the staleness contract nor a fenced release,
   so a 300s reclaim window silently stole a 30-minute sync's slot and the
   promotion fence evaporated.
2. **Docs described an intended design the code diverged from.** In every case
   verified, the CODE was right and the DOC was wrong.

A third, cutting across the tests: **assertions that cannot fail.** A test named
"names both SHAs" asserted a SHA looked like hex; the gh reader asserted the PR
number it passed in; a sweep composition never mocked the sweep it added, so it
threw into a swallowed `errors[]` nothing asserted.

## Solution

### The design corrections that mattered more than the plan's text

- **#3**: the plan offered "route through `claimLifecycleOperation`". That cannot
  work — that function IS the thief (archive/drop call it), so routing the victim
  through it changes nothing, and it would split the claim's ONE `FOR UPDATE` tx
  and drop the injected db seam. A sync-aware timeout fails too: HITL resume
  re-stamps `agent_running_since`, so no finite window is both long enough for a
  live resolver and short enough to self-heal. The defect was narrower:
  `claimed_at` means "claim start" while the reclaim window READS it as "last
  known alive". Beating it fixes the mismatch, leaves `canReclaimLifecycle`
  untouched, and dissolves the plan's stated testability blocker.
- **#12**: re-run the pure gate under `FOR UPDATE` rather than re-encode its
  predicate in a WHERE — `pr_state` is nullable and the conflicted-only case has
  it NULL, where `eq()` never matches.
- **run-header runId**: the plan pointed at `promotionOperation.runId`, but that
  is only built for a promotable Review run while reopen exists for a DONE one.
- **#C1**: the plan called the indeterminate-remote refusal "the ONLY guard
  against an unleased force-push". Git's empty-lease refusal is a second one — so
  a bare `code: CONFLICT` assertion passes with the guard deleted. The test had
  to assert the REASON.
- **22b**: REFUTED. `migration-journal-integrity` asserts a snapshot only for the
  NEWEST journal entry, so the "duplicate" is the only thing covering 0103.
  Deleting it would cut real coverage. Kept, with evidence.

### Verification method

Every fix was **mutation-proven**: neuter the fix, watch the new test fail,
restore. This caught a test of mine that passed with its own guard removed.

## Prevention

- **A plan's prescribed fix is a hypothesis, not a spec.** Three of this plan's
  fixes were wrong or insufficient *as written*, and the plan was itself written
  from a verified review. Re-derive the defect from source before applying the
  remedy; when they disagree, the source wins and the divergence gets recorded.
- **A new test proves nothing until you break the code and watch it fail.**
  `expect(code).toBe("CONFLICT")` passed with the guard deleted because a second
  mechanism produced the same code. Mutation-test every fix, every time.
- **Assert the discriminant, not the outcome.** When two paths reach the same
  status, only the message/field that distinguishes them is a real assertion.
- **A composition test must assert its summary is clean** (`errors: []`), or an
  arm that silently throws is invisible. That assertion immediately exposed two
  more pre-existing broken arms.
- **Grep the class, not the line.** `published` was re-implemented 3× and
  diverged; the terminal-phase trio was re-listed 5× with a dead type sitting
  unused next to it; `EXEC_TIMEOUT_MS` was hand-mirrored with a comment claiming
  "drift is safe" while it reserved lease headroom. A "mirrors X" comment is a
  confession.
- **An inverted rationale is worse than a missing one.** "target-scoped fetch"
  was documented in 8 places as the REASON the lease is safe; the code is safe
  for the opposite reason. A reader trusting it would optimize away the very
  `ls-remote` that makes it work.
- **Frozen history stays.** ADR-077's "12 types" records what that ADR decided;
  it gets a supersession pointer, not a rewrite.
