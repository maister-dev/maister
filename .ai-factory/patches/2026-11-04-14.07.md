# Preserve typed refusals at selected package asset boundaries

**Date:** 2026-11-04 14:07
**Files:** `web/lib/tasks/launch-capabilities.ts`, `launch-capability-materialization.ts`, `launch-agent-resolution.ts`, `launch-agent-definition.ts`, and their existing capability-materialization/agent-admission integration suites
**Severity:** medium

## Problem

The finite sibling audit after the Flow installed-directory fix found native filesystem errors escaping capability preflight, accepted capability capture, pinned agent package hashing, agent package copy, and agent definition reads. A selected but missing directory could produce HTTP 500 or a generic transient preparation failure instead of the existing actionable asset-change refusal. This is local reproduced behavior; it does not establish the historical MAI-27 filesystem cause.

## Root Cause

Digest mismatch branches produced typed domain refusals, but rejected digest/copy/read promises bypassed those branches. Outer capture cleanup deliberately preserved the primary error and therefore correctly retained the native error; it did not supply the missing domain classification. Earlier definition resolution could read a file successfully without guaranteeing the later package digest/read would succeed.

## Solution

Use the existing capability-change reason for both preflight and accepted capture, retaining the original error as `MaisterError.cause`. Share one precise agent package digest wrapper between initial selection and pinned reads. Wrap only the package copy operation and share one source reader between pinned and privately captured definitions. Existing typed validation/ownership errors and capability materialization callback failures retain their exact identity. Existing preparation/dispatch logs and HTTP projection remain authoritative; no duplicate path-bearing log or new public error fields are introduced. Cleanup ownership, immutable asset verification, admission, and model dispatch gates remain unchanged.

## Prevention

Review both digest mismatch and digest rejection at every selected immutable input boundary. Place the domain wrapper at the narrow I/O operation, preserve original causes, and leave downstream effect/owner errors outside that wrapper. Use real filesystem disappearance at a deterministic boundary plus actual PostgreSQL acceptance/materialization; a fabricated rejected promise does not establish caller composition.
