# Admission-claim double launch: guard the class, not the racer pair the flake showed

**Date:** 2026-09-26 12:55
**Files:** web/lib/scheduler/c2-eligibility.ts, web/lib/scheduler.ts, web/lib/__tests__/admission-gate.integration.test.ts, web/lib/scheduler/handlers/__tests__/auto-launch-triaged.integration.test.ts, web/test-support/process-invocation.ts, scripts/run-stage-ab-tests.mjs, web/e2e/run.ts, web/e2e/__tests__/run.test.ts, web/test-support/__tests__/invocation-release.test.ts, docs/system-analytics/task-queue.md, docs/system-analytics/test-infrastructure.md, docs/database-schema.md
**Severity:** medium

## Problem

Review of `claude/admission-claim-live-run-cas` found the fix for the
`AC-F1-claim` double launch correct but incomplete as a class: the claim CAS
re-typed the eligibility read's "live flow run" query inline behind a
"re-assert the check the eligibility read made" comment; the poll backstop,
which takes neither the scheduler lock nor a claim, could still hit the same
symptom (PRECONDITION on the claimer's worktree → task flagged, auto-launch
cleared) during a gate claimer's worktree window; a run that turned terminal
inside the straddled window still admitted one retry ahead of its backoff; and
`task-queue.md` described the old mechanism. On the e2e side the wrapper's
terminal cleanup duplicated the A/B runner's composition and diverged from it
(no container reclaim), and the Playwright child was never registered.

## Root Cause

The fix was written against the racer pair the flake exposed (two gate
admissions) instead of the invariant ("one flow run per task, counted by the
verdict that admits it"). Guarding the pair at the CAS left every other
admitter — the 60 s poll, a manual Launch, a crash recover — outside the guard,
and duplicating the predicate meant the two copies could later disagree on
what "live" means. Rewriting the straddle test then showed the second lesson:
once a claimed task is excluded from the candidate query, two gate admissions
cannot straddle each other at all (the scheduler lock orders their
transactions), so the CAS re-check's real job is the claimless admitters. The
test harness had encoded the author's mental model of the race, and only a
deterministic failure of the rewritten harness revealed which mechanism covers
which edge.

## Solution

- One definition of the predicate in `c2-eligibility.ts`: `taskFlowRuns` +
  `liveFlowRunCondition` serve `hasLiveFlowRun` and the exported
  `unseenOrLiveFlowRunExists(db, taskId, latestFlowRunStartedAt)`, whose second
  arm refuses any flow run started after the latest one the verdict saw.
  `evaluateC2Candidate` returns that fingerprint on `eligible`.
- `loadC2CandidateRows` excludes tasks with an outstanding claim, closing the
  poll edge and, with the lock, the gate-vs-gate edge at selection time.
- The straddle harness parks a gate admission on a `domain_events` ACCESS
  EXCLUSIVE lock and lands a claimless launch while parked; two cases (live and
  already-terminal landed run) each fail with their arm removed. Racer
  settlement moved into `finally`.
- `releaseInvocation(invocation, subject, reclaimers?)` in
  `process-invocation.ts` is the single terminal-cleanup composition; the A/B
  runner and the e2e wrapper call it, the wrapper registers its Playwright
  child via `registerSpawnedProcess`, and a unit test pins the composition.

## Prevention

- When a race fix names a racer PAIR, enumerate every writer of the resource
  (here: every caller of `launchRun`) and ask which of them the guard covers;
  file the rest as fixed / already-safe / out of scope in the same pass.
- A test that reproduces a race is a claim about WHERE the window is; after
  any change to the guard's position (a filter moved earlier, a lock widened),
  re-derive whether the harness still opens the window — a poll timeout on the
  parking probe is the tell that it does not.
- "Re-assert the check X made" in a comment is a duplicated predicate: extract
  the composition before the second copy is written, never after.
- Two runners with "the same" cleanup order are one helper with a label; the
  first divergence (a skipped reclaimer) is the bug the helper prevents.
