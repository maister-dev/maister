# Failed session creation must prove process retirement

**Date:** 2026-11-03 18:46
**Files:** supervisor/src/http-api.ts, supervisor/src/execution-fence.ts, supervisor/src/command-receipts.ts, supervisor/src/session-create-outcome.ts, supervisor/src/session-process-ownership.ts, supervisor/src/session-process-gate.mjs, supervisor/src/session-process-context.ts, supervisor/src/spawn.ts, supervisor/src/types.ts, supervisor/src/host-state.ts, supervisor/src/__tests__/lifecycle.integration.test.ts, runtime/process-group.ts, runtime/safe-error-cause.ts, docs/api/supervisor.openapi.yaml
**Severity:** high

## Problem

A rejected ACP handshake could remove a still-running child from supervisor
inventory. A manager treating that rejected create and empty inventory as
quiescence could then release capacity or clean its workspace prematurely.

## Root Cause

The handshake failure path waited after SIGTERM, escalated to SIGKILL, and
removed the registry entry without confirming exit after escalation. The
ordinary DELETE path already required both exit and durable terminal output.
Receipt rejection alone did not distinguish a pre-spawn refusal, confirmed
retirement, and an unresolved process lifetime.

## Solution

Handshake cleanup and DELETE share bounded TERM/wait/KILL/wait termination.
Unconfirmed cleanup retains its session and returns an actionable error while
leaving the create receipt accepted. A safe rejected create carries the
versioned `sessionCreateQuiescence` host witness, minted only before invoking
spawn or after confirming exit and terminal output. Unstamped historical or
internal-spawn failure receipts remain unproven; consumers must not infer
retirement from their rejected phase.

The accepted receipt durably retains its actionable unresolved outcome. Replay
returns that outcome without spawning or rewriting it to `turn_lost`. The
retained child's terminal callback and an owned DELETE can both close the same
original receipt after actual retirement. This is event-driven and idempotent;
it adds no polling, timer job, replacement command, or unbounded retry. Host
restart preserves unresolved producer ownership instead of fabricating a
`turn_lost` or crashed-process proof from a missing in-memory registry.

Host SQLite schema 16 adds immutable process obligations. A detached gate
cannot spawn the adapter before its exact command, Run, assignment, epoch and
group are durably registered. Its bootstrap environment excludes adapter Node
startup hooks. The wrapper reports actual native spawn errno through private
IPC, retains its live group anchor while the adapter resists TERM, and exposes
the adapter PID separately. A Supervisor SIGKILL cannot erase that group's
ownership. Recovered groups authorize observation only; a surviving descendant
prevents a retirement witness and cleanup.

Scoped inventory attests physical ownership with a required version header;
aggregate inventory remains a projection. Unknown legacy ownership stays scoped
to its Run. Positive OS boot identity and PID namespace prevent confusing
Supervisor/container restart with physical retirement. An actual verified OS
reboot after upgrade resolves legacy unknown ownership; neither a client flag
nor historical receipt rewriting can do so.

## Evidence

The integration reproducer uses a real TERM-resistant process and intercepts
only SIGKILL delivery to force the notification boundary. RED observed a live
PID whose registry entry had been removed. GREEN retains that PID in inventory
with an unresolved receipt. The confirmed-exit case uses actual SIGKILL,
verifies the PID is absent and terminal output published, then checks the
stamped rejected receipt and registry removal.
Both late exit and owned DELETE are exercised through the original create's
receipt endpoint, including replay while unresolved.

Sibling sweep: `rg -n 'registry.remove|SIGKILL|waitForChildExit'
supervisor/src/{shutdown,checkpoint-teardown,http-api,execution-fence}.ts`.
The handshake's removal was fixed. DELETE reuses its established barrier.
Fence eviction now refuses dispatch when the common retirement barrier fails,
including a second request at the already-advanced high-water. The gate runs
before new receipt admission, so the original command may retry unchanged after
retirement; terminal historical replay is preserved. Checkpoint timeout refuses success;
shutdown awaits process exit, drain, and terminal publication. These siblings
do not remove an unconfirmed child and were preserved.

Two further real-process interleavings held the old create before native spawn
and withheld its spawn notification after native creation. Both failed before
the fix. Hosted spawn now checks the durable epoch after asynchronous staging,
then creates and registers a successful child without yielding between them.
An actual failed native spawn with no PID has a dedicated typed `not_started`
outcome. Generic spawn errors remain conservative. The existing safe cause
serializer is shared with the host; the original bounded failure code/stage/
cause chain survives late receipt settlement without messages or credentials.
Actual missing environment references and EACCES log preparation failures prove
zero native processes. Their no-child receipt commits before a synchronous
storage-unavailable latch; the technical storage protection remains active.

The native Supervisor-SIGKILL regression proved an initialized adapter survives
its parent, then previously authorized a duplicate. The corrected path retains
the original accepted receipt while its group lives, converges that same
receipt after actual whole-group retirement, and permits exactly one successor.
The inherited-descendant and held-GO preload controls independently exercise the
physical group and trusted bootstrap contracts. These are local native tests,
not hosted deployment evidence.

## Prevention

Separate command refusal from physical effect retirement. Every cleanup proof
must identify the current command/owner/epoch and positively establish process
lifetime; absence from a registry is insufficient. When introducing a stronger
proof, keep historical receipts conservative rather than rewriting them.
