# Verify historical identity and wait for settled fault witnesses

**Date:** 2026-11-11 17:44 Europe/Moscow
**Files:** `web/lib/queries/flow-packages.ts`, Studio package routes, Evidence and transcript components, `web/test-support/__tests__/execution-ab-partitions.integration.test.ts`, `web/lib/db/__tests__/migration-task-launch-admission.integration.test.ts`
**Severity:** medium

## Problem

A real project attachment upgrade left its previous, Run-pinned Flow revision unreachable from the project viewer. Same-status verification gates also opened the same set of Evidence nodes. The partition tests could fail after observing the expected recovery because P1 allowed only one receipt probe and P2 sampled an in-progress retry claim.

## Root Cause

The current Flow source is mutable after attachment adoption, while the Run's revision binding is durable. Gate state is shared by many records. In the fault fixture, the command counter advances at claim time and readers can issue more than one receipt request before the old Web process exits. The counter and a single socket therefore cannot prove a settled retry window.

## Solution

Authorize the project before resolving a historical revision. Require a retained Run that pins that revision for the same project and Flow row, and select the Studio install only when its source and member provenance are proven. Use the persisted gate row ID for an exact Evidence link. Hold all P1 receipt probes for the selected command through process death. For P2 observe the exhausted probe budget and durable reconciliation state together. The migration fixture preserves a queued pre-upgrade row with no dispatch authority.

## Prevention

- Exercise an actual attachment upgrade across different source paths. Keep the selected project, Flow row, revision and user grant in the witness.
- Seed a second gate with the same state when testing a record-level link. Clear the filter and confirm the other gate remains reachable.
- Match a crash barrier to the scope of its producers. Await the joint database and transport witness while retaining exactly-once application and adapter-effect assertions.
- Construct old migration fixtures under the old schema's row invariants before asserting new columns and replay behavior.
