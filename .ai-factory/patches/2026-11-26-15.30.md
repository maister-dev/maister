## Problem

Review of `feature/recoverable-project-package-installation` surfaced three blocking defects and several quality/spec/UX gaps:
1. **Outer-`db` write inside `db.transaction(tx)` (`#getDb-bypass`):** `executor.ts` called `await progress("projection")` (which writes via outer pooled `db`) inside `db.transaction(async (tx) => ...)` in both `executePackage` and the `capability_import` branch, risking connection-pool deadlock while holding `projects FOR UPDATE` and committing `stage = "projection"` outside `tx` even on rollback.
2. **Permanent cross-project `setup_owner_live` DoS:** `hasReservedOwner` in `setup.ts` only checked whether the original attempt was in the declaration's current generation. If the queued recovery attempt failed before reaching `runMaterialSetup` (e.g., `authority_revoked`) or the owning project was archived, the `recovery:<attemptId>` receipt permanently blocked other projects sharing the physical setup target with `409 setup_owner_live`.
3. **Silent stripping of dotted `memberRef` diagnostics:** `worker.ts` sanitized `memberRef` with `/^[a-zA-Z0-9:_-]{1,200}$/`, stripping valid dotted capability/Flow/package identifiers (allowed by `manifest-path-segments.ts`).
4. **Auth-first ordering on global-admin-only routes:** `dependency-declarations/[declarationId]/_lib.ts`, `flow-packages/install/route.ts`, and `flow-packages/[flowRefId]/upgrade/route.ts` called `authorizeManagePackages(slug)` (resolving slug -> `409`) before `requireGlobalRole("admin")`, letting non-admins probe slug existence.
5. **Process/setup edge cases, read-model SQL, typing, UI/i18n, and spec/OpenAPI parity:** `groupExists` did not treat `EPERM` as an existing process group; `spawn` errors rejected `exited` twice (masking `MaisterError("EXECUTOR_UNAVAILABLE")`); `read.ts` joined `setup_pending` on `enabled_revision_id` instead of `(flow_ref_id, resolved_revision)` and omitted `package_install_id IS NULL` on standalone joins; `import.ts` and `attach.ts` used untagged `: any` transaction callbacks; `dependency-declarations.tsx` exposed raw `row.stage` fallback, used bare `response.json()` on 409/422, omitted `encodeURIComponent(slug)` on the Git settings link, and lacked success status feedback and icons; `en.json`/`ru.json` missed 5 reason keys and mixed `runner`/`исполнитель`/`раннер` in Russian; `project-dependency-installation.md` omitted two transitions in `stateDiagram-v2`; and `web.openapi.yaml` omitted the `503` response on `postProject`.

## Root Cause

- Helper callbacks (`progress`) captured the outer `db` pool handle and were invoked inside `db.transaction` blocks alongside `recordCommittedApplication(tx, claim)` which already updated `stage: "projection"` transactionally.
- `hasReservedOwner` checked only declaration generation liveness and did not inspect whether the owning project was archived or whether the reserved recovery attempt had already terminated without dispatching.
- Diagnostic allowlist regexes were authored independently from `manifest-path-segments.ts`.
- Global-admin-only routes layered `requireGlobalRole("admin")` after `authorizeManagePackages(slug)` instead of reusing `authorizePackageTrust(slug)`.

## Solution

- Removed both nested `await progress("projection")` calls inside `db.transaction` in `executor.ts` (`recordCommittedApplication(tx, claim)` atomically writes `stage: "projection"` inside `tx`).
- Hardened `hasReservedOwner` in `setup.ts` to join `projects` with `archived_at IS NULL` and exclude attempts whose `retry_of_attempt_id` successor has reached a terminal status (`NOT IN ('pending', 'running')`), while preserving `inheritSetupRecovery` for same-project admin takeover when no other project has claimed the slot.
- Updated `groupExists` (`EPERM` -> `true`), resolved spawn errors without double-rejection in `finally`, and added module-local `pino` logging (`log.debug` / `log.warn`) in `setup.ts`.
- Updated the `memberRef` sanitizer in `worker.ts` to `/^(?!.*\.\.)[a-zA-Z0-9.:_-]{1,200}$/`.
- Switched `dependency-declarations/[declarationId]/_lib.ts`, `flow-packages/install/route.ts`, and `flow-packages/[flowRefId]/upgrade/route.ts` to `authorizePackageTrust(slug)`.
- Aligned `read.ts` `setup_pending` join with `setup_failed` and constrained standalone `flows`/`capability_imports` joins with `package_install_id IS NULL`.
- Replaced untagged `: any` transaction callback annotations in `import.ts` and `attach.ts` with `Db` / `Tx` and typed `tx.execute<{ id: string }>`.
- Added `field?: string` to `ApiErrorBody["details"]` in `web/lib/api-error.ts`, updated `dependency-declarations.tsx` to use `readApiErrorBody`, hide unknown raw `row.stage`, encode `slug`, render `role="status"` success feedback, and display `@heroicons/react/24/outline` icons.
- Added the missing `dependencies` and `dependencies.reasons` keys in `en.json` and `ru.json`, unified Russian `раннер` terminology, completed `stateDiagram-v2` in `docs/system-analytics/project-dependency-installation.md`, and documented `503` on `postProject` in `docs/api/web.openapi.yaml`.
- Added regression tests across `worker.integration.test.ts`, `auth-order.test.ts`, `projects-packages-routes.integration.test.ts`, and `project-packages-section.dom.test.ts`.

## Prevention

- Never pass an outer-`db` progress callback into code executed inside `db.transaction(tx)`; state updates inside a transaction must take `tx` directly (or be folded into the transaction's own checkpoint update).
- When reserving a shared physical resource on behalf of a queued job (`recovery:<attemptId>`), define liveness in terms of an active (non-terminal) consumer in an unarchived tenant so pre-dispatch failures cannot wedge other tenants.
- For every global-admin-only project route, use `authorizePackageTrust(slug)` (which enforces `requireGlobalRole("admin")` before `resolveProjectBySlug(slug)`).
- Keep diagnostic identifier allowlist regexes consistent with `manifest-path-segments.ts` (including single `.` with negative lookahead `(?!.*\.\.)`).
