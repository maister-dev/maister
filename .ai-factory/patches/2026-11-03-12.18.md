# Share the delivery reservation with historical launch writers

**Date:** 2026-11-03 12:18 Europe/Moscow
**Files:** migration 0221 and its journal/snapshot, `launch-shared-reservation.integration.test.ts`
**Severity:** high

## Problem

An accepted ordinary task launch intent and a legacy v1 delivery run could both
commit for the same task. The intent partial unique index covered only intents;
the v1 run guard verified qualification without competing for that reservation.

## Root Cause

The two writer generations had disjoint decisive guards. An early application
read of existing runs could not prevent an uncommitted competing insertion.

## Solution

Migration 0221 adds symmetric trigger checks under the existing task row fence.
Both insertion orders serialize, then observe the committed competitor. The
intent trigger sorts before the older shared-lock guard to avoid lock upgrades.
No trigger acquires a run or intent row lock after the task lock. Modern service
advisory locking remains unchanged. Operational agents keep their separate lane.

Active historical continuations retain their immutable v1 receipt; a terminal
run re-entering active execution must compete again. No historical run or
qualification is rewritten. The named SQL constraint provides a safe diagnostic
identity; the shared engine integration owns its public conflict projection.

## Tests and prevention

Node 24, fresh PostgreSQL and temporary Git: all five new regressions failed
before the guard. They cover both committed arrival orders, both uncommitted
arrival orders, active historical continuation and conflicting recovery.
The guard passes those five plus the related qualification/intent controls
(25 tests). Final trigger-order run: 5/5; typecheck, lint and diff checks pass.
Logs: `/private/tmp/maister-launch-shared-reservation-{red,green,final}.log`.

Executed source sweep:

```text
guard_task_launch_shared_reservation
runs: INSERT or entry into an active root delivery state
task_launch_intents: INSERT or entry into an active ordinary reservation
same-run active continuation: retained historical owner
operational agent: excluded from ordinary delivery reservation
```

When adding a new durable reservation, enumerate every old and new writer at
the database boundary. Test an uncommitted winner in both directions; two
sequential happy paths cannot establish cross-generation exclusion.
