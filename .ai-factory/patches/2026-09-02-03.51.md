**Severity:** critical

## Problem

`/aif-review` of the ADR-163 flow-target delegation branch returned `fail`:

1. A delegated flow child stopped by a human (UI stop, ADR-161 node-interrupt
   stop) or returned to `Review` by the ADR-160 rework-claim release / ADR-141
   sync resolver flipped to `Review` with a WEBHOOK only. Its parent parked in
   `WaitingOnChildren` never woke; `reconcile.ts` then classified the parent
   `orchestrator-stuck` and `cascadeAbandonRunTree` abandoned every child,
   diffs included. The branch's own MUST ("a delegated child reaching Review
   MUST emit run.review … or a parked parent deadlocks") was met on one edge.
2. `run_plan` folded every flow-arm refusal into `PRECONDITION 409` while
   OpenAPI/MCP promised `CONFIG 422` for `workspace` on a flow entry — and the
   new test pinned the wrong side.
3. The failed-launch compensation HARD-DELETED the carrier task via
   SELECT-then-DELETE; `runs.task_id` and `domain_events.task_id` cascade, so a
   concurrently inserted run could vanish and the committed `task.created`
   fact always did. It was the only `.delete(tasks)` in production code.
4. The seven-check launchability sequence lived three times (launcher, delegation
   resolver with a literal "mirrors" comment, board projection) and the copies
   had already diverged: the board also required a Ready runner + an executable
   stored manifest, so a board-unlaunchable flow passed delegation trust and
   failed after its carrier task existed (a missing runner surfaced as a 503).
5. `run_cancel` parked a flow child in `Review`, which still counted as LIVE for
   the shared fan-out cap while `run_rework`/`run_message` were refused for flow
   children — the coordinator could not reclaim capacity except by promoting.
6. Docs described a per-arm `.strict()` union the code never used, a pre-flight
   order and "pre-tx" bounds that no longer held, and a per-node
   `settings.delegation` knob as enforced (nothing reads it).
7. The new `kind: "flow"` discriminant reached no read model: the run-tree
   rendered a flow child as a bare row, board cards carried no provenance, and a
   relaunch after the orchestrator was abandoned silently produced a
   lineage-less run.

## Root Cause

- **A gate rule inlined at one edge.** The `run.review` domain emit was written
  inside the graph runner's Review branch instead of at the ONE place every
  Review flip passes. Every other Review flip (operator stop, sync returns,
  rework-claim release) predates the flow child that made the rule matter, so
  none carried it. Class: "a guard on one of N edges is a guard on none".
- **A tool contract inherited from a shape that no longer applies.** The
  cancel path reused the operator's stop-to-Review transition for a child that
  has no rework loop of its own; "cancel" stopped meaning "end".
- **Mechanism described from the plan, not from the code.** REQ-01 said
  "discriminated Zod union"; the implementer deliberately chose a strict object
  + refinement for better messages, and every spec surface kept the plan's
  wording. The refusal table's "Where checked" column was written before the
  code and never re-derived.
- **Compensation designed for "no orphan card" without checking FK cascades.**
  The model's terminal exit is `Abandoned`; deletion was chosen for tidiness.
- **Partial SSOT extraction.** The enablement SET was hoisted; the SEQUENCE and
  its messages were copied, and the copy declared itself a mirror.
- **Discriminant widening without the consumer grep.** `delegation_snapshot`
  and `delegation_spec` gained `kind: "flow"`; readers that narrowed on
  `agentDefinitionId` / `agentId` (run-tree DTO, C2 predicate) silently
  returned null / admitted the new shape.

## Solution

- `emitDelegatedReviewIfChild(tx, row)` owns the gate rule; the graph runner,
  `markRunStoppedAndCloseAssignments`, and the three `state-transitions` Review
  re-entries call it (the latter through one `casToReviewAndEmit`). Tests: a
  child of a PARKED parent stopped via the real UI-stop path wakes it; each
  transition flip emits for a child and not for a top-level run.
- `stopWorkbenchRunForToken` routes a flow child with `parent_run_id` through
  `cancelDelegatedFlowChild` → `markAbandoned` (emits `run.abandoned`, GC
  deadline, assignments closed in the same tx, pool slot released); human stop
  paths keep `Review`. Owner decision Q1-A.
- `abandonUnlaunchedTasks(db, ids, at)` in the tasks service carries the
  no-run guard INSIDE the UPDATE (`NOT EXISTS runs`) and serves both the
  cascade and the compensation; the `parent_of` relation stays as provenance.
- `run_plan`: per-kind allow-list before resolution via the shared
  `refuseUnsupportedDelegationOption` (CONFIG 422, all entries at once);
  resolution failures keep one shared code, mixed → PRECONDITION with `[CODE]`
  per line. Owner decision Q2-A.
- Budget-breach `restart` for delegated children: VERIFIED ALREADY-SAFE
  (`isRestartAvailable` excludes `parentRunId !== null`, pinned by
  `budget-breach-options.test.ts`) — the review finding read `hitl.ts` alone.
- `evaluateFlowLaunchability` / `describeFlowLaunchabilityRefusal` /
  `assertFlowLaunchable` (pure) shared by the launcher, the resolver and the
  board projection; `hasReadyPlatformRunner` replaces two inline queries and
  joins the resolver together with `classifyStoredFlowManifest`; the remaining
  four private enablement sets import the constant; `flowDelegationSnapshot`
  builds the snapshot for all three creation edges.
- As-plan release-time typed refusals are posted as a deduped system comment
  (`addTaskComment`); `launch_mode` stays `auto`. A new `task_activity` kind
  would have been a migration.
- C2 predicate: `delegation_spec IS NULL` instead of `-> 'agentId' IS NULL`.
- Read models: `ChildRunRef.delegationTarget {kind, ref}` with a kind-aware
  eyebrow; `parentTask` on both board card DTOs rendered as a chip linking to
  the orchestrator's task, plus an amber relaunch warning; EN/RU strings.
- `teardownLiveSessionsForRuns` shared by the delegate route's W6 path and the
  keepalive sweeper's tree-terminate.
- MCP descriptions (cancel/rework/message/flowId), three stale comments, the
  launcher's snapshot type narrowed to the flow arm, and a full docs sweep
  (ADR-163 amendment, ADR-126 amendment, orchestrator/runs/domain-events/
  flow-dsl/configuration/error-taxonomy/OpenAPI/tasks/scheduler/social-board/
  README, Studio advisory hint for `settings.delegation`).
- Deterministic tests for the earlier repair-pass fixes (git config lock retry,
  tree-owner adoption + mismatch, lifecycle-claim release shape) and prefix
  checks in the resolver isolation test.

## Prevention

- When a status flip has a "MUST emit" invariant, put the emit in a helper
  called from EVERY writer of that status and grep `status: "Review"` (or the
  equivalent) for writers before closing the review — not only the path the
  feature author had in mind.
- A refusal-table "Where checked" column and any "mechanism" sentence in an
  ADR are re-derived from the code at review exit, line by line; a plan
  requirement that names a mechanism (REQ-01 "discriminated union") is either
  met literally or amended when the implementer chooses otherwise.
- Before a hard delete of any row, list its inbound `ON DELETE CASCADE` FKs;
  in this schema `tasks` has cascades from `runs` and `domain_events`, so the
  terminal exit is `Abandoned`.
- A `// mirrors X` comment is a defect: extract the composition (the whole
  check sequence with its messages), not only the constant it reads.
- Widening a jsonb discriminated union: grep every reader of the column for
  field sniffing (`"agentDefinitionId" in`, `-> 'agentId'`) and every DTO that
  projects it; UI read models are consumers too.
- A cancel/stop tool on a child must free whatever the admission counter
  counts; check the cap predicate against the tool's resulting status.
- Verify a review finding in source before fixing: one of nine "MAJOR"
  findings (budget restart) was already handled and already pinned.
- Shell hygiene for long sessions: every Bash call `cd`s to the package
  directory explicitly; a bare `pnpm exec vitest` from the wrong cwd prints only
  "Command not found", which a summary grep hides.
