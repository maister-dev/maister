# Pairwise judging + controlled-launch recipe fidelity (Codex-1/2/4)

**Date:** 2026-07-26 12:32
**Files:** web/lib/evaluations/judges/facade.ts · web/lib/evaluations/frozen-participants.ts (new) · web/lib/evaluations/aggregation/{pairwise-aggregate,worker}.ts · web/lib/evaluations/judges/launch.ts · web/lib/evaluations/dispatcher/tick.ts · web/lib/evaluations/{launch-seam,preflight,standardization,launch-batch}.ts · web/lib/services/runs.ts · docs/api/external/operations.openapi.yaml · docs/api/web.openapi.yaml · docs/system-analytics/evaluations.md · mcp/src/tools.ts · web/messages/{en,ru}.json
**Severity:** high

## Problem

Three HIGH adversarial-review findings on the Evaluation-Lab cut-over, all of
the same species — *the system recorded an intent it did not enforce*:

1. **Codex-2** — a pairwise judge attempt carried `match_a`/`match_b`
   internally, but the evaluator context never told the judge which blinded
   candidate is which side, and served the WHOLE snapshot's evidence. A valid
   `winner: a|b|tie` pick could systematically record the opposite or an
   unrelated result.
2. **Codex-4** — pairwise provisioning, tournament aggregation, and objective
   checks read LIVE Study membership, not the execution's sealed evidence
   snapshot. A mid-flight add produced phantom standings; a tombstone made
   completed matches vanish; a lost pair let an execution reach `completed`
   with expected matches missing.
3. **Codex-1** — a "controlled launch of an immutable recipe" forwarded almost
   none of the recipe: `launchRun` executed the task's live enabled flow
   revision with live inputs, so a variant ran the current configuration, not
   its frozen passport.

## Root Cause

Each subsystem exposed a *declared* contract (match columns, sealed snapshot,
immutable recipe) whose *enforcement point* was never wired: the columns and
snapshots were written for provenance, but every read path that mattered
(judge context, pair fan-out, tournament matrix, launch resolution) kept
reading the older, live source it predated. The pattern survived review
because each individual read was locally correct — only comparing what was
*promised at freeze time* with what was *read at use time* exposed the gap.
Prior mitigations (preflight WARN on unthreaded pins, M4 record-the-actual
provenance) surfaced the gap without closing it, which made it look handled.

## Solution

- **Codex-2:** `EvaluatorContext.match {a,b}` maps the attempt's match sides
  through the SAME per-execution blinding as `candidates`; all four judge
  surfaces (context, evidence list, bounded read, objective results) are
  scoped to the pair plus shared null-participant items; a match side with no
  captured evidence refuses `PRECONDITION` (never served half-blind). The
  seal path already bound picks to the row's own `match_a`/`match_b` —
  verified, no change.
- **Codex-4:** new `frozenExecutionParticipants()` derives the participant
  universe from the sealed snapshot's `participant_watermarks` keys
  (tombstone-inclusive, `(displayOrder, id)`-ordered, fail-closed without a
  snapshot). Provisioning, the tournament, and `runChecksForExecution` all
  read it; the live `orderedStudyParticipantIds` helper is deleted. The
  tournament walks the frozen expected matrix and synthesizes empty verdicts
  for missing pairs, so a lost pair keeps the execution `partial`. Membership
  mutations become inert to a sealed execution (plan step 7's "version"
  branch — no route gate needed).
- **Codex-1 (owner-locked option C):** `launchRun` accepts seam-only
  `evaluationFlowRevisionId` (resolved through the ADR-132 pin guard matrix,
  snapshotted to `runs.flow_revision_id`, which the runner executes) and
  `evaluationFormInputs` (pre-written per form node as `input-<nodeId>.json`
  inside the worktree-compensation window; the runner's existing-file-wins
  branch consumes them). The seam re-runs full live preflight fail-closed
  before its first side effect. The four still-unthreaded axes
  (capabilityOverlay, packagePins, nodeAgentBindings, budgets) warn at
  preflight (`recipe_axis_not_threaded`) and refuse standardization
  (`axis_not_threaded_*`, plus `winner_revision_mismatch` when the recorded
  revision differs from the pin).

## Prevention

- For any freeze/snapshot/pin feature, enumerate every read path and assert
  it reads the frozen source — "recorded for provenance" without a switched
  read path is the exact shape of all three findings. A grep for the LIVE
  source's accessor (here `orderedStudyParticipantIds`,
  `isNull(removedAt)` in the execution pipeline, `flow.enabledRevisionId`
  after a pin exists) is the review check.
- A WARN or a provenance record over a known gap is a surfacing measure, not
  a fix — track it as an open defect until the enforcement lands, or an
  adversarial pass will (correctly) re-file it as no-ship.
- When a fan-out (pairs, checks) and its aggregation live in different
  modules, they MUST share one participant-set function; two derivations of
  "the same" set is how provisioning/aggregation desync.
- Contract fixtures in integration tests should derive digests from the real
  projection (`buildFlowContractProjection` + digest fns), never literals —
  fake digests silently exempt the suite from every drift gate, and turning
  on real enforcement then breaks the suite (predicted by the plan here).
- Package form-schema docs are JSON at package-root `schemas/<name>.json`
  (the cut validator hard-blocks YAML and non-root refs); field `type` is
  `string|number|boolean|enum|array|object`.
