# Freeze the Flow installation consumed by execution

**Date:** 2026-11-03 Europe/Moscow
**Files:** `web/lib/tasks/launch-flow-assets.ts`, launch resolution/acceptance/execution hooks, `web/lib/flows/graph/runner-core.ts`, preparation cleanup, `launch-flow-assets.integration.test.ts`
**Severity:** high

## Problem

A pinned Flow database revision did not pin the script, form and schema bytes read from its mutable installed directory. Real runtime loading executed B after accepting A. Private captures also needed a lifecycle owner when binding failed before a Run existed.

## Root Cause

The manifest/revision identity and capability-import materialization did not cover `flowInstallPath` itself. The graph runtime reconstructed that path from the global revision on each load. Checkout cleanup had no knowledge of new private Flow asset captures.

## Solution

Include the Flow directory identity in the preview token and immutable settings. Separate the database metadata token from filesystem preflight so acceptance transactions perform no asset reads. Validate copied private bytes against the accepted identity, retain an intent/run/incarnation/settings witness, and use the captured directory for launch-time forms and every runtime/recovery load.

The existing physical preparation fence owns capture. Partial captures are preserved and refused rather than overwritten. Never-bound closed intent cleanup verifies the private witness and content before deleting only that capture. A bound Run is excluded. If asset removal committed but witness removal did not, cleanup finishes forward using the matching witness. The shared `assertManagedCapturePath` primitive resolves the configured root alias, rejects child symlinks and returns the canonical contained path before capture, consumption or release; Flow, agent and imported capability captures use it.

## Tests and prevention

Three real PostgreSQL/Git regressions first failed: preview-to-acceptance mutation was accepted, acceptance-to-preparation mutation bound a Run, and runtime executed changed B instead of accepted A (`/private/tmp/maister-flow-assets-red.log`). The fourth real binding-fault/cancel/cleanup test reproduced private bytes left after cleanup reported removed (`/private/tmp/maister-flow-assets-cleanup-red.log`). The fifth redirected a project capture through a child symlink outside the configured runtime root. Current five asset cases and eleven existing cleanup checks pass together after the shared containment refactor, 16/16 (`/tmp/maister-flow-assets-shared-path-green.log`). They include reconstructed runtime readers, unchanged outside files and a bound-capture retention control. No model or remote service was used.

An immutable manifest pointer does not establish the identity of files loaded beside it. Follow actual runtime script/schema/form reads, and keep any captured files under the same durable lifecycle authority as the request that created them.
