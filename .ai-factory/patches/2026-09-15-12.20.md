# Stop poisoning the artifact projector over adapter telemetry

**Date:** 2026-09-15 12:20 (Europe/Moscow)
**Files:** `web/lib/projector/artifact-projector.ts`,
`web/lib/projector/__tests__/artifact-projector-shapes.test.ts`,
`docs/system-analytics/execution-event-plane.md`.
**Severity:** high

## Problem

`canonical-artifact-projector-v1` was poisoned on every run that reached it —
15 consumers on the stand, all of them this one projector, while the other 99
consumers were `ready`. The poison positions are at the very start of each run:
`run_sequence` 4 of 6824, 5 of 61, 8 of 10913. A poisoned consumer's cursor
never advances, so from the fourth event onward NOTHING in the run is projected.
One of those runs is formally `Done` with no artifacts projected at all.

## Root Cause

`deriveFromLine` throws on an unrecognised `sessionUpdate` discriminant, and its
own comment promises "the caller can WARN + skip while still advancing". The
caller did the opposite: every non-`ExecutionEventProjectionError` was rewrapped
as `permanentCanonicalProjectionError(...)`, and `permanent = true` poisons the
consumer immediately with no retry and `next_retry_at = null`.

Two frames tripped it, both harmless telemetry that derives no artifact at all:

- `model_advisory` (claude adapter) — `{channel: "settings_local",
  configuredModel: "claude-fable-5-1[1m]", observedModelId: "default"}`
- `session_info_update` (codex adapter) — `{_meta: {codex: {threadStatus: …}}}`

They belong beside `agent_message_chunk` and `plan` in the known-non-deriving
allow-list and were simply missing from it. The deeper defect is the caller's
classification: adapters keep adding telemetry frames, so every future one would
poison the projector at its fourth event.

## Solution

- Allow-list both frames, so an ordinary run logs nothing for them.
- Give the classifier a typed `UnknownSessionUpdateShape`. The caller WARNs with
  the discriminant — the only thing needed to allow-list the next one — and
  advances, honouring the contract its comment already stated. Everything else
  keeps poisoning: a malformed event (missing `update` payload) and any
  unexpected error from the derivation itself are unchanged.

## Verification

- RED: three new unit cases failed with the stand's exact error,
  `ExecutionEventProjectionError: canonical artifact event has an invalid shape:
  unknown sessionUpdate shape: model_advisory`, `permanent: true`. The fourth
  case (malformed event stays permanent) passed before and after.
- GREEN: 4/4, and the WARN fires only for the genuinely unknown shape.
- `lib/projector` + `lib/execution-host` unit suites 49/49; the artifact
  projector integration suite 1/1; `tsc --noEmit` clean.

## Operations

The code fix does not un-poison existing consumers. After deploying, rearm each
one (the mechanism is documented in `execution-event-plane.md`):

```
pnpm --dir web execution:projection:rearm --consumer canonical-artifact-projector-v1 \
  --run <run-id> --event <last_error.eventId> --cursor <last_run_sequence> \
  --error-generation <last_error.errorGeneration>
```

Rearming before the code is deployed re-poisons on the same event.

## Prevention

A comment that states a failure policy is not the policy. When one function
throws for a caller to classify, the classification belongs to a TYPE, not to a
convention — the caller here rewrapped everything as permanent while its own
source of truth promised warn-and-skip. And a projector's poison stops an entire
run's projection: reserve it for what can never succeed, never for input a newer
peer is allowed to invent.
