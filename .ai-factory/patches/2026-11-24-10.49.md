# Dependency eligibility, installation and recovery across entry points

**Date:** 2026-11-24 10:49

**Files:** `web/lib/project-dependencies/`, `web/lib/packages/`, `web/lib/tasks/`, `web/lib/capabilities/`, `web/lib/db/`, `web/lib/project-config-persistence/`, project management routes and panels

**Severity:** high

## Problem

A Run could receive files from an import awaiting trust. A manual or CLI upgrade could replace a working package after its replacement's setup failed. A trust decision could survive an interrupted setup while the project lost the operation needed to repair it. Migration and configuration publication also disagreed with runtime handling of supported sources.

## Root cause

Admission, bundle capture and worktree materialization queried eligibility independently. Native upgrades and worker upgrades interpreted the same Flow setup result differently. A setup receipt identified mutable script bytes, and some trust entry points dispatched outside the durable attempt lifecycle. The worker checked authority on either side of fetch without fencing the first global write. Git confirmation reused a reviewed local pin's former unresolved state even when it had since become effective.

## Solution

Use the effective native revision and its supplier's trust and setup state for new launches. Prepare replacements before switching the effective attachment. Resolve a local revision and its contents from the same staged directory and verify the cache before reuse. Fence publication, renewal and settlement with the live claim. Record trusted setup work before dispatch and address recovery by a stable physical identity. Validate both reviewed and currently effective local material before accepting Git publication. Keep migration acceptance and management diagnostics consistent with the supported input and account contracts.

## Prevention

Verify each decision at its last consumer. Inspect the Run's actual files, the old enabled Flow after a failed upgrade, the global installation after revocation, the shell invocation count after recovery, and the Git ref after a stale confirmation. Upgrade a populated database through each intermediate migration and boot with each previously shipped ledger receipt.

The sibling sweep `rg -l 'eligibleProjectImport' web/lib` identified the catalog, worktree materializer, scratch service and task/agent launch consumers. `rg -l 'settlePreparedPackageSetups' web/lib` identified the shared stage and its package and worker callers. Tests exercise the native attachment and CLI entry points as well as deferred registration.

Two checks from neighboring suites caught failures outside the initial regression set. Native RAH members require an explicit enable decision and keep their initial `Installed` state when a runner is missing. In the production shutdown test, group-wide SIGTERM could interrupt the fixture's ownership inspector during a legitimate drain. Graceful signaling now targets the verified service process. Deadline escalation and orphan cleanup still address its verified process group.
