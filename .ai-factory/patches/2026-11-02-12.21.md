# Contiguous peek history and explicit UI resource ownership

**Date:** 2026-11-02 12:21 Europe/Moscow
**Files:** `web/components/runs/run-peek-transcript.tsx`, `web/components/runs/run-children-provider.tsx`, `web/components/use-modal-a11y.ts`, `web/e2e/child-run-peek.spec.ts`, EN/RU messages and the peek navigation/data contracts
**Severity:** medium

## Problem

Live transcript refresh could render messages 1–100 immediately followed by
201–300 without identifying the missing middle. Loading a sixth history page
created the same discontinuity through eviction. Shift+Tab from the initial
peek heading escaped the modal, and closing or switching peek left its
unowned child-list request active. The modal E2E also used an ambiguous global
main-region locator during parent refresh.

## Root Cause

- The live tail moved independently of cached earlier windows; eviction removed
  a middle window. A page-level scroll bookmark could not compensate for a
  growing message earlier inside that page.
- Earlier-page adoption only checked the transport signal, allowing a response
  from before Latest or an attempt change to restore superseded history.
- The focus trap assumed initial focus was one of its tab stops. Peek deliberately
  focuses a heading with `tabIndex=-1`.
- Slice release removed only the owner count. Pending-controller ownership and
  identity were not part of response/error/finalizer adoption.

## Solution

Retain one contiguous five-page displayed segment while reading history.
Revalidate its stable final window and the visible older window, read the live
end separately, and expose Latest messages when newer content exists. Evict
the newest displayed page when loading farther back. Bookmark the visible
renderer block, retain fresh copies by message ID, and fence reads with window
revisions and an explicitly canceled Earlier controller. Latest, attempt reset,
denial and unmount release their owned reads.

The shared modal hook routes forward/reverse Tab from programmatic focus into
its first/last stop, following the already-safe feedback-modal pattern. Child
slice cleanup aborts and removes the last owner's controller immediately;
every adoption and finalizer checks controller identity. Shared owners keep
their own request active. The modal E2E captures the peek's direct retained
main element and verifies its identity after Close.

Client logging policy stays unchanged. Existing structured peek request/stream
boundary logs cover the requests; browser regressions verify DOM and signal
ownership directly instead of introducing client console logging.

## Prevention

Extend existing browser journeys with advancing live windows, sixth-page
eviction, growth above the reader, reverse Tab from the actual initial focus,
and request cancellation/reacquisition. Hold actual HTTP responses across both
Latest and a new Flow attempt. Assert the real signal and displayed content,
not a fixed request count: development remounts can legitimately issue another
request after owned cancellation. No implementation-mirroring units are needed.
