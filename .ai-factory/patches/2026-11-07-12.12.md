# Canonical physical preparation identity across ancestor aliases

**Date:** 2026-11-07 12:12 Europe/Moscow
**Files:** web/lib/agents/preparation-resource.ts; preparation-workspace.ts; preparation-ownership.ts; launch.ts; web/lib/tasks/launch-first-dispatch.ts; owning integration/process fixtures; filesystem ownership inventory; preparation/persistence contracts
**Severity:** medium

## Problem

Equivalent ancestor aliases acquired independent plain-directory preparation
mutexes. Real terminal disposal through the other alias removed an in-use tree.
Two regression controls failed before the fix; the original MAI-27 exception
remains unknown and is not reconstructed by this later reproduction.

## Root Cause

`path.resolve` normalizes syntax but does not identify the physical directory.
Both the mutex key and durable preparation hash retained the alias spelling.
Task-agent dispatch also equated the immutable allocation hash with physical
operation identity, while actual preparation recomputed paths from live roots.

## Solution

Resolve existing ancestor aliases before hashing and append missing suffixes
without creating them. Reject leaf symlinks/non-directories and propagate other
filesystem errors. Share that canonical path between plain mutex and operation
identity; execute preparation at its frozen descriptor. Derive first-dispatch
physical identity from that descriptor outside SQL, leaving allocation hashes
and Flow V1 cleanup unchanged. No migration or historical rewrite is needed.

A same-Run journal with an unknown different resource hash refuses explicitly.
Both driver error boundaries preserve that actionable primary diagnosis instead
of attempting proofless finalization. Structured existing lifecycle logging and
the safe `[FIX:preparation-identity]` refusal identify the retained Run. Upgrade
requires stopping and quiescing old managers; this is not rolling compatibility.

## Prevention

- Canonicalize physical ownership independently from immutable allocation
  witnesses. Test identity before creation and after creation, across aliases,
  epochs and process death.
- Exercise real cleanup and the real driver, not only lock acquisition. Expected
  refusal tests must release an unexpectedly returned owner in `finally`.
- Audit sibling hash/path consumers with:
  `rg -n 'claimAgentPreparation\(|openAgentPreparation\(|acquirePreparationWorkspace\(|commitTaskAgentLaunchFirstDispatch\(' web --glob '*.ts' --glob '!**/__tests__/**'`.
  Production callers: `agents/launch.ts`, `agents/accepted-cleanup.ts`,
  `gc/operational-disposition.ts`, `tasks/launch-first-dispatch.ts` and
  `agents/preparation-workspace.ts`. All use the shared physical derivation.
  `tasks/launch-dispatch-claim.ts` allocation hashes and
  `tasks/launch-preparation-cleanup.ts` Flow V1 checks intentionally remain
  unchanged; they are immutable allocation witnesses, not physical mutex keys.
- Keep extracted filesystem readers classified in the operation inventory.
