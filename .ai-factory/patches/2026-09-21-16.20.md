# Four ways ADR-177 inferred a lost turn from the absence of a signal

**Date:** 2026-09-21 16:20
**Files:** web/lib/reconcile-evidence-db.ts, web/lib/reconcile-evidence.ts, web/lib/reconcile.ts, web/lib/runs/turn-lost-boundary.ts, web/lib/runs/crash-recover.ts, web/lib/flows/graph/prompt-owner.ts (+3 test files)
**Severity:** critical

## Problem

An adversarial Codex review of the ADR-177 branch found four high-severity
defects that a full green lane, a self-review, and a round of review fixes had
all missed:

1. The receipt probe treated "not `completed` and not `inflight`" as PROOF of a
   lost turn. `normalizeCommandReceiptV2` hardcodes `inflight: false` (the v2
   wire shape has no liveness field) and v2's phase enum includes `accepted`, so
   an accepted v2 receipt for a RUNNING turn was indistinguishable from a lost
   one. The same branch mapped every `rejected` receipt to `turn_lost`, but the
   supervisor's `completeAsync` catch writes `rejected` for ordinary failures
   too. Both crashed healthy runs.
2. The gate turn-lost branch called a close whose CAS required
   `action_completion IS NULL`. Gates run AFTER the action persists its
   completion on the SAME attempt, so EVERY real lost gate turn matched zero
   rows, threw, and the owner-application layer retried until the command
   poisoned — a permanent stall, not a crash.
3. The `owner-poisoned` boundary closes the attempt. `applyCrashedTurnEvidence`
   only inspects OPEN `Running` attempts, so a later Recover answered `absent`
   and dispatched a fresh prompt — silently undoing ADR-175's refusal to
   re-prompt a turn whose receipt and terminal event disagree.
4. The boundary re-derived "the attempt" instead of using the one the sweep had
   classified. A Recover landing between classification and write could open
   attempt B at the same node, and the boundary would then close B and mark B's
   healthy in-flight command applied using A's diagnosis.

## Root Cause

**One mistake in four places: a terminal decision was allowed to rest on the
ABSENCE of a signal rather than the presence of proof.** `inflight === false`,
`phase !== "completed"`, "no open attempt", "the open attempt at this node" —
each is a hole where something else is true, and each was read as evidence.
Crashing a run is irreversible for the operator, so the predicate behind it
needs a positive witness; every one of these had a negative one.

Two aggravating factors made them invisible:

**The fixtures encoded the author's mental model, not production.** The gate
tests seeded an attempt with no `action_completion` because that is what the
boundary's other caller produces — but gates only ever run when a completion
EXISTS. A suite written from the same assumption as the code cannot falsify it.
This is the "replay the real artifact before trusting a shape assumption" rule,
applied to a DB row instead of a wire payload.

**Two of the four were mine to catch and I did not.** A prior self-review found
the probe/boundary attempt MISMATCH and fixed the predicate — but re-running the
same query is not the same as pinning the same row, so finding 4 survived the
fix that was supposed to address it. And the quarantine bypass is the exact
reachability argument the plan itself made for `turn_lost` (closing the attempt
makes Recover answer `absent`); it was written down as SAFE for one reason and
never re-checked for the other.

## Solution

- The probe returns `turn_lost` only on affirmative proof: a v1 `accepted`
  receipt with `inflight:false`, or a `rejected` receipt whose body satisfies
  `isTurnLostError`. Everything else — v2 accepted, ordinary rejections, 404s,
  transport errors — is `pending_ingest`, which SKIPS.
- `closeTurnLostAttempt` takes an explicit `admitCompletedAction`; the gate path
  sets it and preserves the action's result, and a lost CAS inside an owner
  apply returns `superseded` rather than throwing into a poison loop.
- `applyCrashedTurnEvidence` checks the node's most recent CLOSED attempt for a
  `prompt_terminal_conflict` command before allowing a dispatch.
- The sweep carries its classified `nodeAttemptId` + `commandId` into the
  boundary, which refuses a moved target.

## Prevention

- **For any predicate that can terminalize a run, write down the POSITIVE
  witness.** If the answer can be produced by a missing field, a normalizer
  default, or an empty result set, it is not evidence. Grep the producers of
  every field the predicate reads — `normalizeCommandReceiptV2` hardcoding
  `inflight: false` was one `rg` away.
- **Derive fixtures from the caller's real state, not from a sibling caller's.**
  Before asserting a branch works, ask what the row looks like at the moment
  that branch runs — for a gate, `action_completion` is non-null by definition.
- **A fix for "these two disagree" must pin the IDENTITY, not just unify the
  QUERY.** Two callers running the same predicate at different times still
  disagree.
- **When a plan argues a consequence is safe, re-derive it for every arm that
  reaches it.** "Closing the attempt makes Recover fall through" was analysed for
  `turn_lost` and correct there; nobody re-asked it for `owner-poisoned`, where
  falling through destroys a refusal.
