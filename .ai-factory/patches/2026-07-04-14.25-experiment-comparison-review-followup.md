**Severity:** high

## Problem

The second review pass found that the experiment comparison branch still had a few contract gaps after the larger critical fixes: the abandon route documented optional bodies but rejected an empty request, launch analytics promised a locked admission path that the implementation did not make explicit, status recomputation could rewrite the original `launchedAt`, and the acceptance evidence still lacked a create-then-launch route-level proof.

## Root Cause

The earlier fixes focused on the broken primary flow and DTO drift, but a few cross-surface invariants were left as doc claims instead of executable checks. The tests also asserted old raw diff text instead of the current DiffView surface, so one UI contract check was coupled to a stale rendering detail.

## Solution

The abandon route now treats an empty request body as the default `{ stopLiveRuns: true }` payload and keeps explicit JSON validation for non-empty bodies. Launch now loads experiment admission data through a transaction-backed row-lock helper before fan-out, while docs and analytics describe the precise lock boundary and the remaining unique-index conflict mapping. Experiment status timestamp updates now share one helper so transitions back to `running` do not rewrite the first launch timestamp. The e2e suite now covers create -> launch -> member Review -> comparable through the real web routes and asserts the current DiffView surface.

## Prevention

When analytics or OpenAPI describe concurrency, timestamp, or optional-body guarantees, add one focused route/integration assertion that exercises the real route shape rather than only the service mock. UI e2e assertions should target stable user-visible structure and labels, not implementation text that disappears when a component moves to a richer renderer.
