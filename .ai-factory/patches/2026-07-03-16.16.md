# Codex round-2 fixes: sweep-crash regression, false give-up race, dead external-check verdict

**Date:** 2026-07-03 16.16
**Files:** web/lib/scheduler/handlers/auto-promote.ts,
web/lib/auto-promotion/readers.ts,
web/lib/scheduler/handlers/__tests__/auto-promote.integration.test.ts,
web/lib/auto-promotion/__tests__/readers.integration.test.ts
**Severity:** high

## Problem

A second Codex adversarial review of the auto-promotion branch found three defects:

1. **[high, a regression from my OWN round-1 fix]** The round-1 F1 prefilter
   `(auto_promotion->>'enabled')::boolean IS TRUE` throws a Postgres cast error on
   a stored `{"enabled":"x"}` (a value `resolveAutoPromotionConfig` is designed to
   tolerate as `config_invalid`). Because the throw is in the candidate `SELECT`,
   ONE malformed project row fails the `auto_promote.default` singleton every tick
   → after `max_failures` the job is disabled → auto-promotion dies platform-wide.
2. **[high]** `promoteCandidate` wrapped the irreversible `promote()` AND the
   post-success `addTaskComment` in one `try`, and `holdAndComment`'s CAS guarded
   only `promotion_hold IS NULL`. So (a) a comment failure after a successful merge
   and (b) a sweep-vs-human race loser (real `CONFLICT` after the human moved the
   run to `Done`) both wrote a false "auto-promotion gave up" system hold + comment
   on an already-`Done` run.
3. **[medium]** `readers.ts` `externalCheck` never returned `not_declared`, so the
   `external_check_missing` verdict that evaluate/i18n/docs/tests treat as real was
   production-dead — a typo'd lane `requireExternalCheckId` mis-reported
   `declared_not_passed`.

## Root Cause

1. **A type cast in SQL is fail-OPEN; the TS parser is fail-CLOSED.** The round-1
   fix pushed the enabled-toggle into SQL as a `::boolean` cast, assuming stored
   configs are well-typed — but the whole point of `resolveAutoPromotionConfig` is
   that they are NOT (it fail-closes malformed configs). A cast throws where the
   parser tolerates; the two disagreed, and the throwing one ran first, in a
   singleton the whole platform depends on.
2. **A `try` that spans an irreversible side-effect plus a best-effort follow-up
   misclassifies the follow-up's failure**, and a give-up write that doesn't
   re-assert the run is still in the state it's giving up ON races a concurrent
   winner. The give-up hold is only meaningful while the run is still `Review`.
3. **A verdict whose reader can never emit it is a lying contract.** The reader
   short-cut `not_declared` with a code comment ("needs the compiled FlowGraph")
   instead of implementing it, leaving evaluate/i18n/tests asserting a dead state.

## Solution

1. **R2-F1:** replaced the cast with non-throwing JSONB containment
   `auto_promotion @> '{"enabled": true}'::jsonb` — excludes disabled/malformed/
   null configs without a cast error; `resolveAutoPromotionConfig` stays the
   in-code authority for the enabled-but-otherwise-malformed case.
2. **R2-F2:** moved the success `addTaskComment` OUT of the promote `try` into a
   best-effort `try/catch` (WARN-only); added `status='Review'` to the
   `holdAndComment` CAS and made it return whether it actually held.
   `promoteCandidate` now counts `gaveUp` only when the hold landed, else treats
   the failure as a benign `skipped` race loss.
3. **R2-F3 (graph implementation, no heuristic):** a run's flow manifest lives in
   the DB (`flow_revisions.manifest` when pinned, else `flows.manifest` — the same
   precedence runner-core uses). A new fail-closed
   `declaredExternalCheckGateIds(db, runId)` loads it, `compileManifest`s it, and
   collects every `gate.id` with `kind === "external_check"` across `graph.nodes`.
   `externalCheck` returns `not_declared` when the lane's id is absent from that
   set, else the existing passed/declared_not_passed check. Any load/compile error
   fails closed to an empty set + WARN (never a throw into the sweep — the R2-F1
   lesson applied prospectively).

## Prevention

- **Never push a value that a TS parser deliberately fail-closes into an SQL
  type cast.** A cast is fail-open (throws); prefer a non-throwing predicate
  (`@>`, `->> = 'literal'`) and keep the tolerant parser as the authority. Any
  per-row work in a shared singleton job MUST be crash-proof or it disables the
  feature for everyone.
- **A `try` must wrap exactly the operation whose failure you're classifying.**
  Never span an irreversible side-effect and a best-effort follow-up in one
  `try` whose `catch` means "the side-effect failed."
- **A give-up / compensating write must re-assert the state it compensates FOR**
  (here `status='Review'`) under its CAS, or it races a concurrent winner and
  corrupts a terminal record. Count the metric only when the write lands.
- **Don't ship a verdict/enum value the producer can't emit.** If a reader returns
  a strict subset of a declared state space, either implement the missing states
  or remove them from the contract — a dead branch in evaluate + a passing test
  that drives it via a mock hides the gap.
- **Graph gate declarations are materialized in the in-DB manifest** — reach them
  via `compileManifest(flows/flow_revisions.manifest)`, not a bundle re-read.
