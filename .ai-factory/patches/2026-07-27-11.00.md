# Assistant activity as-built sync and cross-project route proof

**Date:** 2026-07-27 11:00
**Files:** docs/system-analytics/assistant-activity.md, web/app/api/v1/ext/runs/[runId]/activity/__tests__/route.db.integration.test.ts
**Severity:** medium

## Problem

The assistant-activity branch passed most focused checks, but two verification
findings remained:

- the canonical analytics doc still described the feature as only "Designed"
  and referred to the implementation surface as planned, even though the
  branch shipped the routes, substrate, MCP facade, and tests;
- the per-run ext activity route had no real regression test proving that a
  token bound to project A receives a 404 for a run that belongs to project B
  on the real token/service/DB path.

## Root Cause

The implementation and the docs/tests drifted at the finish line:

- the analytics doc was treated as a frozen design artifact instead of being
  promoted to as-built state during the final sync pass;
- the existing route test file optimized for fast route-module coverage by
  mocking auth, audit, and the service boundary, which preserved serialization
  checks but left the project-isolation guarantee unproven against the real
  database path.

## Solution

- Updated `docs/system-analytics/assistant-activity.md` to reflect the
  implemented state and changed the implementation reference from "planned" to
  "implemented", plus added the focused verification surfaces that now back the
  domain contract.
- Added a new DB-backed integration test for
  `GET /api/v1/ext/runs/{runId}/activity` that:
  - seeds two projects and a real run in the second project;
  - issues a real project token for the first project;
  - calls the real route without mocking the service/auth path;
  - asserts `404 NOT_FOUND` plus the expected audit row.

## Prevention

- When a feature has a canonical `docs/system-analytics/*` artifact, treat it
  as an as-built contract surface, not as a design-only note, in the final
  verification sweep.
- Keep fast mocked route tests for DTO/error-shape coverage, but add at least
  one DB-backed integration regression whenever the feature relies on
  server-derived project/run ownership.
- For ext routes, verify the trust-boundary behavior on the real `handleExt` +
  token + DB path before closing a review finding.
