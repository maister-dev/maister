# CI memory, framing and recovery test boundaries

**Date:** 2026-09-08 20:11
**Files:** `.github/workflows/ci.yml`, `Dockerfile`, `supervisor/src/bounded-acp-stream.ts`, `supervisor/src/__tests__/lifecycle.integration.test.ts`, `supervisor/src/__tests__/runtime-file-budget.integration.test.ts`, `supervisor/src/__tests__/_fixtures/boot-host.ts`, `supervisor/src/__tests__/_fixtures/output-memory-profile.ts`, `supervisor/src/__tests__/adapter-compatibility.integration.test.ts`, `web/lib/agents/__tests__/prompt-owners.integration.test.ts`
**Severity:** high

## Problem

CI stopped at web TypeScript heap exhaustion and supervisor integration
failures. The production image compiled JavaScript, then exhausted the
TypeScript worker heap. Supervisor tests also exhausted a 2 GiB heap, and
child output could lose its final frame during asynchronous consumption.
The mandatory A/B job also had a 30-minute deadline despite healthy serial
execution exceeding 40 minutes.
Hook and budget recovery cases could also stop a responder before its resumed
prompt was delivered, despite intending to test accepted work before completion.

## Root Cause

- The web TypeScript program outgrew Node's effective default heap in CI.
- Deep equality on 8 MiB Buffers enumerated millions of numeric properties.
- The memory profiler deliberately runs full GC across twenty producers;
  a shared five-second receipt deadline measured GC overhead as latency.
- Node resumes child stdio on exit. Removing every readable listener while
  awaiting disk writes lets that resume discard unread bytes.
- Compatibility tests passed raw pipe chunks to a connection that expects
  complete frames. Adjacent JSON-RPC writes can share one pipe chunk.
- The process budget admits one suite on runners with two or four cores.
  Successful runs of the identical suite sources measured over 41 minutes
  in aggregate, including real lease-expiry waits needed for recovery proof.
- An agent turn becomes `dispatched` during database admission, before HTTP
  delivery. Killing at that state can leave no supervisor prompt receipt.
  The continuation-only fixture did not run startup command recovery, which
  production uses to redeliver such unsent commands.

## Solution

Scope a 4 GiB heap to web typechecking and the image build command. Compare
large Buffers with native byte equality. Give only profiler receipt waits a
60-second deadline, retaining the overall subprocess deadline and reporting
receipt state on failure. Keep readable mode active throughout bounded
capture and explicitly drive the final EOF. Exercise the same framing
boundary in adapter tests as production.
Allow 60 minutes for the mandatory A/B job, preserving its worker budget,
individual test deadlines and real recovery timing.
For the accepted-prompt fault window, wait for command acknowledgement and
assert an accepted v2 receipt with no terminal result after killing the responder.
Keep the separate real startup recovery cases for unsent commands.

## Prevention

Distinguish compilation from worker-memory failures in image logs. Verify
large-payload tests at CI's actual heap limit. Qualify memory separately from
instrumented throughput. Test child exit with a real subprocess while the
consumer holds a frame, checking both exact bytes and eventual EOF. Never
assume operating-system pipe chunks correspond to protocol messages.
Size job deadlines from aggregate successful suite durations at the minimum
supported worker count, including installation and prerequisite checks.
Place fault barriers at the durable boundary named by the scenario; a local
admission state does not prove remote acceptance.
