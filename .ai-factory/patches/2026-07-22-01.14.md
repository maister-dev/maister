# Authored edit-lock review-fix batch: leak, crash containment, session-user binding, and 5 stale baseline tests

**Date:** 2026-07-22 01.14
**Files:** web/lib/catalog/authored-lock.ts, authored-service.ts; web/app/(app)/flows/[projectSlug]/[capId]/{page.tsx,error.tsx}; web/components/flows/{use-editor-lock.ts,authored-cap-lock-shell.tsx}; web/components/studio/local-package-editor.tsx; web/app/api/projects/[slug]/catalog/caps/[capId]/lock-{refresh,release}/route.ts; web/lib/services/__tests__/runs-launch-branch.test.ts; web/app/api/runs/[runId]/hitl/[hitlRequestId]/respond/__tests__/route.test.ts; docs/{decisions.md,system-analytics/{capability-catalog,flow-studio}.md,api/web.openapi.yaml}
**Severity:** high

## Problem

An `/aif-review` of the ADR-149 authored-capability edit-lock branch surfaced
three blockers plus several suggestions, and the suite carried 5 red unit tests.

1. `readLockState(capId, "")` ran unconditionally in the editor RSC page and
   passed the holder's `users.name ?? users.email` into a client component's
   props — so a project `viewer`/`member` received the editing owner's email in
   the Flight payload, though only a manager ever sees the banner.
2. A save/publish that lost the edit-lock threw `CONFLICT` from a server action
   with no `error.tsx` under `app/(app)/flows/`, so it unwound to the ROOT
   boundary and tore down the whole app shell + unsaved buffer. The trigger was
   common: a second same-user tab steals the lock (`acquireLock` allows
   `locked_by_user_id = userId`), leaving the first tab believing it held the
   lock for up to 60s.
3. `assertHoldsLock`/`refreshLock`/`releaseLock` matched on `locked_by_session`
   only. The session id is a client-minted bearer token, so a leaked session
   could be replayed by a different user to write through / refresh / drop the
   lock — worsened by a `Date.now()`/`Math.random()` session-id fallback on
   non-secure-context (LAN HTTP) self-hosts.
4. 5 unit tests were red on `main`: 4 in `runs-launch-branch.test.ts`
   (`db.select(...).from(...).innerJoin is not a function`) and 1 in the HITL
   `respond` budget_breach test (`500` instead of `202`, "unknown table").

## Root Cause

- **Leak (1):** an authorization boundary was enforced on the *display* surface
  (`canManage && !heldByMe` on the banner) but not on the *data read* that fed
  it. RSC reads that produce client props must be gated by the SAME authority as
  the surface that renders them — "rendered only under X" is not "transmitted
  only under X".
- **Crash (2):** server-action errors unwind to the nearest `error.tsx`; the
  editor route had none, so the blast radius was the whole app. The "only true
  races" framing missed that same-user multi-tab is a steady-state trigger, not
  a race, because acquire deliberately allows same-user takeover.
- **Binding (3):** a per-mount client secret was treated as sufficient proof of
  identity. A bearer token minted by the client must be paired with a
  server-authoritative principal (the authenticated `userId`) at every write, and
  its generation must not silently degrade to a predictable source.
- **Stale tests (4):** ADR-146 (evaluation participation, D15) added two new
  DB-touching calls into shared paths — `deriveEvaluationParticipationFromSource`
  in `launchRun` and `isLaunchedEvaluationRun` in the budget_breach restart — but
  the pre-existing tests' hand-rolled fake DBs modeled neither. The tests went
  red the moment ADR-146 landed and stayed an "accepted baseline" instead of
  being fixed. A shared orchestrator (`launchRun`) gaining a dependency silently
  breaks every hand-mocked caller test.

## Solution

- Gate the `readLockState` call on `canManage`; hand non-managers a free-lock
  snapshot (also removes a dead query).
- Add `app/(app)/flows/[projectSlug]/[capId]/error.tsx` (mirrors the studio
  boundary) to contain the crash to the editor segment; add an in-place `retry`
  affordance on the read-only banner (thrash-free, buffer-preserving — chosen
  over auto-reacquire, which ping-pongs between two same-user tabs).
- Add `locked_by_user_id = ${userId}` to `assertHoldsLock`/`refreshLock`/
  `releaseLock`; add `lifecycle <> 'ARCHIVED'` to `acquireLock`; prefer
  `crypto.getRandomValues` for the session-id fallback. Move the ARCHIVED
  immutability check BEFORE the lock assert in update/publish so a
  concurrent-archive race returns "immutable", not `edit_lock_not_held`.
- Fix the 5 tests by modeling the new ADR-146 dependency: mock
  `@/lib/evaluations/membership` `deriveEvaluationParticipationFromSource → null`
  (experiment-focused tests want neutral evaluation inheritance); register
  `evaluation_participants: []` in the respond test's fake DB so the real
  lineage check runs and returns false.
- Reconcile docs (publish flowchart, flow-studio sequence + Expectation 11,
  capability-catalog seam table, ADR-149 Consequences, OpenAPI 409 note) with the
  reordered, hardened code.

## Prevention

- When a shared service (especially `launchRun` / a HITL composite) gains a new
  DB-touching dependency, grep its existing `__tests__` for the fake-db / mock
  pattern and update EVERY caller test in the same change — a hand-rolled fake
  DB that throws "unknown table" / "innerJoin is not a function" is the tell.
- A "red on main / accepted baseline" test is debt, not a constant: diagnose the
  root cause before treating it as immovable.
- Any RSC read that feeds client props MUST be gated by the same authorization
  as the surface that displays the value (grep the read, not just the render).
- A client-minted session/bearer token must be bound to a server-authoritative
  principal at every privileged write, and its generation must never degrade to
  `Date.now()`/`Math.random()` (use `crypto.getRandomValues`).
- A server action that can throw a domain `CONFLICT` needs a segment-level
  `error.tsx`, or the whole app unwinds to the root boundary.
- When two service methods gate on the same row, order the checks so the
  DOMINANT invariant (immutability) is reported before the weaker one (lock),
  and give each a distinct, testable discriminator.
