# Bound fault observation to the causal operation

**Date:** 2026-10-02 14:40
**Files:** `web/lib/scratch-runs/__tests__/dispatch-window.integration.test.ts`, `web/test-support/__tests__/execution-ab-partitions.integration.test.ts`, `docs/system-analytics/test-infrastructure.md`
**Severity:** medium

## Problem

Hosted run 36990724261 failed P4 with an aborted checkpoint response and S3
with no permission observed within ten seconds. The isolation slice later
exhausted its budget without a complete reporter.

## Root Cause

S3 charged worktree and session preparation to the permission observation
budget. P4 kept an original HTTP request open while creating and projecting a
successor session, then installed audit DDL; Intel timing left only 143 ms
before the unchanged transport deadline. Retry matches were consequences of
the expired request, not evidence that the ownership guard failed.

## Solution

S3 witnesses the initial prompt at a held proxy request, forwards it, then
starts its unchanged permission wait, scoped to that command's run. P4 installs
its audit before checkpoint and holds successor creation after the new
assignment and Running attempt commit. It drains the old prompt application,
clears setup audit entries, snapshots authority, and releases the real old ACK.
The original callback must return 409 without current writes. Successor session
activation and exactly-once completion are then verified outside that wire
window. Existing structured proxy witnesses cover the changed controls; no
product logging or API/schema change is needed.

A trial barrier on the checkpoint ACK ledger write deadlocked with restart and
was removed. Holding a command row is not automatically safe merely because
the ACK path does not explicitly acquire the run lock.

## Regression controls

Hosted logs provide the original failure evidence. Focused repaired controls
pass. Withholding S3's initial prompt reproduces the missing-permission
assertion (a dispatch dependency control, not a slow-launch simulation).
Removing only P4's stale-attempt CAS causes its successor snapshot assertion
to fail. Both mutations are restored; the final-tree full lane is tracked in
the CI/R9 plan. The original 50 case names and all ownership expectations stay.

## Prevention

Start an observation deadline at the event it measures. Move independent setup
outside a deliberately delayed network response; do not extend the production
transport deadline to fit a fault fixture. A changed fault seam must retain a
real handler and mutation-sensitive assertions, and document precisely which
successor state exists at the audit boundary. Read-only sibling search:
`rg -n 'P4: delayed checkpoint|P4.*ACK|original HTTP|30.second|30-second' docs/system-analytics/test-infrastructure.md .ai-factory/plans/codex-stage-ab-ci-r9.md scripts/run-stage-ab-tests.mjs web/test-support/__tests__/execution-ab-partitions.integration.test.ts`.
The canonical contract and the older S5.2 closeout plan now share one current
amendment; prior phase results remain historical. Host budget acceptance stays
open until a complete Intel reporter and clean teardown prove it.

Final validation: 50/50 isolation cases in seven suites, 797.973 seconds,
zero leaks; independent preflight 1/1, 4.056 seconds, zero leaks. Types, scoped
