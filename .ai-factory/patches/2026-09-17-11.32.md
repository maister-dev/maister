# Excerpt derivation stripped markup the renderer shows literally, and a spec amendment left its own section stale

**Date:** 2026-09-17 11:32
**Files:** `web/lib/markdown-excerpt.ts`,
`web/lib/__tests__/markdown-excerpt.test.ts`,
`web/lib/__tests__/markdown-excerpt-renderer-parity.test.ts` (new),
`web/components/board/task-card-description.tsx`,
`web/components/social/markdown-body.tsx`,
`docs/screens/projects/project-board.md`,
`docs/system-analytics/tasks.md`,
`.ai-factory/plans/claude-task-card-description-truncate-bfefb1.md`
**Severity:** medium

## Problem

Two defects found by `/aif-review` on the branch that shipped the Backlog
task-card description excerpt.

**C1 — the excerpt silently deleted user text.** `markdownExcerpt` carried
`const HTML_TAG = /<[^>]*>/g`, applied as `.replace(HTML_TAG, "")`. That is not
an HTML-tag matcher; it deletes everything between any `<` and the next `>`:

| input | excerpt showed | expanded body showed |
| --- | --- | --- |
| `Replace <TaskInlineEditableField /> with a plain link` | `Replace with a plain link` | unchanged |
| `Use Array<string> for the list` | `Use Array for the list` | unchanged |
| `Fail if x < 5 and y > 3 in the loop` | `Fail if x 3 in the loop` | unchanged |
| `See <https://example.com> now` | `See now` | `See https://example.com now` |

The last row is the one that matters most: the blanket strip was wrong in BOTH
directions at once. No test covered any of it — the S1.2 acceptance table pinned
18 derivation rules, one per rule, and the only transform absent from it was the
broken one.

**C2 — a spec amendment corrected its own narrative and left its normative text
standing.** When in-place editing was removed from the card, an amendment banner
was added to S2 saying "S2 has three states, not four". The table six lines below
it still read "exactly four observable states" and still listed the removed
`editing` row; expectation E5 still cited test S2-d, which had been deleted; and
all of S3 — under the heading "load-bearing, do not collapse" — still specified
the three-level component chain that had just been collapsed, including a `MUST`
(a `WHY` comment at the `renderView` call site) that no code path could satisfy.
A later sweep found the same drift in S7, which still asserted "the predicted
breakage does not occur, and no mock was added" after both mocks had landed.

## Root Cause

**C1 is a spec defect first, a regex defect second.** S1.1 had already derived
and stated the governing principle — for intra-word underscores:

> otherwise the collapsed excerpt reads `snakecase` while the expanded Markdown
> directly below it reads `snake_case`

It even reasoned explicitly about why `*` does NOT get the same exemption. But
the neighbouring bullet, "HTML tags → removed, text content kept", was written
from the generic idea of "strip markup" and was never re-derived against the
renderer. `MarkdownBody` mounts remark-only with no `rehype-raw` (ADR-078 D10),
so raw HTML renders as literal text — making HTML the CLEAREST case for the rule
the spec had just applied to `_`. The principle was stated once and then not
carried across the list. The regex was then written to match the wrong bullet,
and overshot even that.

The deeper cause is that the rule had no enforcement mechanism. Every other S1.1
bullet was sampled by one row in S1.2, and rows sample instances — they cannot
express "the excerpt must agree with the renderer". The one bullet nobody
sampled was free to be wrong.

**C2 is the amendment pattern applied to prose only.** Each amendment on this
plan was written as a dated banner narrating what changed. That reads well and
is honest, but a banner does not retract the text below it. The project's review
rules already name this as the highest-risk drift class — "a documented
edge-case bullet reads as a reviewed invariant and steers future implementers
back to the old shape" — and the section literally headed "do not collapse"
described a structure that had already been collapsed.

## Solution

**C1.** The review prescribed "drop the HTML strip entirely". That prescription
was WRONG, and re-deriving from source caught it: CommonMark autolinks are also
`<…>`, and the renderer UNWRAPS those (`<https://example.com>` renders as a link
whose text has no brackets). Dropping the strip would have fixed raw HTML and
broken autolinks. The rule that actually matches the renderer is asymmetric:

- raw HTML → KEPT verbatim (renderer shows it literally);
- autolinks → brackets removed, inner text kept (renderer consumes them).

`HTML_TAG` was replaced by
`AUTOLINK = /<([A-Za-z][A-Za-z0-9+.-]{1,31}:[^\s<>]*|[^\s<>@]+@[^\s<>@]+)>/g`
applied as `.replace(AUTOLINK, "$1")`, with the scheme bound matching
CommonMark's 2-32 characters. S1.1's bullet was rewritten to state both
directions and why; S1.2 gained rows 19 and 20 as a deliberate PAIR, because a
single row would let the wrong blanket rule pass.

The missing enforcement was added as
`markdown-excerpt-renderer-parity.test.ts`: it asserts each case against
`MarkdownBody`'s own rendered output rather than a hand-written string, so it
cannot encode the same assumption the bug did. Recorded in the plan as
expectation E6.

**C2.** S2's table was cut to three states and the `editing` row removed; E5 was
kept as an explicitly struck entry (not silently deleted) since it was the
expectation the plan was originally written to protect; S3's body was replaced
with an as-built diagram plus a note that the hook-order constraint remains true
for `TaskInlineEditableField`'s other callers — the task detail page still uses
that seam; S7's paragraph now carries both amendments in order, because the pair
(prediction dropped, then prediction becoming true) is the lesson. T4's task body
was left intact as an execution record with a superseding note.

**Doc sweep.** C1 changed observable behavior, so the shipped docs were
re-derived too: `project-board.md` said the excerpt has "markup stripped", which
is now false for raw HTML, and `tasks.md` gained the parity test in its
enforcement list.

No runtime logging was added. `markdown-excerpt.ts` is a pure client-safe module
and the rest is tests and docs — the skill-context rule "`[FIX]` logging yields
to the project's logger boundary" resolves this case to "behavior locked by
tests instead", and the repo lints `no-console`.

## Prevention

- **A derivation rule that says "strip markup" must name the renderer it is
  previewing.** Stripping is only correct for markup that renderer consumes.
  Whenever a preview and its expanded form sit on the same screen, the preview's
  contract is "reads the same", and the test for it asserts against the
  renderer's output — never against a hand-written expected string, which just
  re-encodes the author's assumption.
- **When a spec states a principle in one bullet, walk the whole list with it.**
  S1.1 reasoned carefully about `_` and `*` and left `HTML` untouched three lines
  away. A principle introduced mid-list is a signal to re-derive every sibling.
- **An amendment must edit the normative text, not just prepend a banner.** If
  the amendment says "three states, not four", the table saying four is now the
  defect. Grep the artifact for the retired token (`four`, `S2-d`, the deleted
  component name) and drive it to zero — a retirement is a document-wide sweep,
  and this one reached three sections that the first pass missed.
- **A review's prescribed remedy is a hypothesis.** "Drop the strip" came from a
  verified review and was still wrong, because the reviewer had not enumerated
  the other `<…>` form. Re-derive the fix from source, then record the
  divergence.
- **Review checklist item:** for any regex that deletes a span between two
  delimiters, ask what ordinary prose contains those delimiters. `<[^>]*>` reads
  as "an HTML tag" and behaves as "delete to the next `>`".
