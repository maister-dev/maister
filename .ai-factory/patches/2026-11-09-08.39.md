# Apply migration safety limits before ledger access

**Date:** 2026-11-09 08:39 UTC
**Files:** web/lib/db/migrate.ts; web/lib/db/migrate-brain.ts; web/lib/db/migration-session.ts; web/lib/db/__tests__/migration-session-cli.integration.test.ts
**Severity:** high

## Problem

The qualification contract promised bounded database migration waits, but upgrades beginning after main 0230 had no guaranteed timeout. Brain ledger access happened before pending SQL could apply its own local settings. A blocking lock could therefore stall either CLI indefinitely.

## Root Cause

`SET LOCAL` belongs to the transaction containing its migration and cannot configure later upgrade sessions or preceding ledger queries. An asynchronous pool connection listener also did not establish an awaited writer-capability boundary before migration work.

## Solution

Each CLI acquires one dedicated client and awaits shared session setup before Drizzle ledger access or DDL. Setup applies a five-second lock timeout, a 120-second statement timeout and the existing writer capability. All staged migration calls and backfills use that client; finalization releases it and ends the pool even if temporary-directory cleanup fails. Existing SQL, journals and snapshots remain unchanged. Structured debug logging records the configured limits without connection credentials.

## Prevention

Qualify the real CLI at an upgrade boundary beyond the migration that introduced a local setting. Start with connection timeouts explicitly disabled, hold an existing-table or ledger lock, observe the actual wait, verify bounded refusal and unchanged pending ledger/content, then release and retry. Assert both session settings at DDL execution. Distinguish per-lock and per-statement limits from a total upgrade deadline, and pending-batch rollback from earlier committed stages.

## Verification

Both new real-Postgres CLI regressions fail against the original entry points and pass with the dedicated-client setup. Four existing CLI-consumer suites pass all 16 tests. Independent review, type checking and scoped lint pass. The final primary-checkout qualification is recorded separately with the exact source revision.
