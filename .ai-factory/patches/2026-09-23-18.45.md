# P0-5 review remediation: overloaded wake marker, replay identity, and recovery parity

**Date:** 2026-09-23 18:45
**Files:** `web/lib/db/schema.ts`, `web/lib/db/migrations/0175_failed_child_wake.sql`, `web/lib/domain-events/{coordinator-wake-intent,outbox}.ts`, `web/lib/flows/graph/{coordinator-wake,continuation-worker,runner-graph,prompt-owner}.ts`, `web/lib/flows/runner.ts`, `web/lib/flows/runner-agent.ts`, `web/lib/runs/recover-classify.ts`, `web/lib/queries/{run,decisions}.ts`, `web/lib/runs/recover.ts`, `web/lib/reconcile-evidence-db.ts`, `web/lib/flows/graph/consensus/*` (runtime, ledger, critique, text, prompt-owner, draft-prompt-owner, drafts, human-decision, input-evidence, recovery-evidence, bounded-log, locator-meta, digest, artifact-defs), `web/lib/flows/{consensus-resolution,hitl-validate}.ts`, `web/app/api/runs/[runId]/artifacts/[artifactId]/payload/route.ts`, inbox UI + messages, tests, docs
**Severity:** high

## Problem

A whole-branch review of P0-5 found seven code defects the branch's own green gates had missed:

- **C1:** consensus nodes with `retry_safe: true` silently lost crash-recover redispatch.
- **C2:** the HITL round-debate artifact was `requiredFor: ["review"]`, so a rework that later agreed without a HITL left readiness permanently blocked.
- **C3:** replaying HITL creation after its commit threw "consensus round debate changed on replay", and would have opened a second request.
- **C4:** HITL disagreement summaries grew unbounded once the verifier parsed its whole 1 MiB output.
- **C5:** the failed-child wake marker reused `runs.resume_requested_at`. Reproduced: C3 admission dispatched `resumeRun` for an unanswered `NeedsInputIdle` coordinator.
- **C6:** that marker was armed only for a `Running` or `WaitingOnChildren` parent.
- **C7:** the consensus poison scan filtered on an `application_state` value the CHECK forbids, so it missed a quarantine found after application.
- **C8:** an unrelated e2e-loop wire assertion had been deleted.

## Root Cause

- **C5/C6:** a column with an existing reader (C3's "HITL answered" key) was given a second meaning without grepping its readers. Only the WRITER side was reviewed. Arming was keyed on the parent statuses the author had in mind, not on every status an orchestrator attempt can be open in.
- **C3:** the first pass and the replay serialized DIFFERENT object shapes of one cell. The runtime's fail-closed write returned its in-memory object (manifest key order), while the replay read jsonb (storage key order). The HITL id was random, so a replay could not recognise its own request.
- **C1:** a new special case for consensus returned early and replaced the general `retry_safe` rule instead of adding to it. The test edit then pinned the regression.
- **C7:** the new scan re-implemented the canonical `classifyPromptEvidence` quarantine rule from memory. The `FIXME(any)` schema cast hid the impossible enum literal from `tsc`.
- **C2:** HITL evidence was modelled like a synthesis deliverable.

## Solution

- **C5/C6:** added a dedicated `runs.failed_child_wake_at` (migration 0175).
  - It is armed in the child's terminal-event transaction for `Running`, `NeedsInput`, `NeedsInputIdle` and `WaitingOnChildren` orchestrator parents.
  - It is cleared when the coordinator's turn actually starts, not at the CAS. A retryable rollback therefore keeps it.
  - `resume_requested_at` keeps only its old meaning.
- **C3:**
  - `recordConsensusVerdict` returns the cell as stored.
  - `writeConsensusVerdict` inserts the raw artifact and then the cell, both insert-if-absent. The FK needs the artifact first, and a loser never overwrites the winner.
  - The HITL id is deterministic from (attempt, round, answered-count) and created with `createHitlRequestIfAbsent`. A replay adopts an open request; an answered one is re-asked, which is master's behaviour.
- **C1:** quarantine, then witness, then fall through to `retry_safe`. `consensusEvidence` is now a required parameter.
- **C7:** the scan is classified by `classifyPromptEvidence`.
- **C2:** dropped `requiredFor`.
- **C4:** the summary is bounded at 1,024 bytes.
- **C8:** restored the assertion and pinned `MAISTER_MCP_FACADE_COMMAND` in the test.
- **Also fixed:**
  - a shared budget for the addressed verdict, union and technical notes;
  - a shared client-safe HITL decoder used by the writer, validator, resolver and card, which closes the pickability parity gap;
  - `readRepoFiles` for inline consensus agent output on the payload route;
  - superseded commands treated as settled;
  - pick and provide decisions no longer resolve the request;
  - input-evidence spans located by a slot sentinel;
  - unified stop reasons;
  - DRY helpers.

## Prevention

- Before giving an existing column a new writer, grep EVERY reader of the column (`rg "resumeRequestedAt|resume_requested_at"`) and ask what each reader will do with the new population. When in doubt, add a column; the owner accepted a migration for exactly this.
- When a first pass and a replay must produce byte-identical evidence, both must read it from the SAME source (the DB). Never compare an in-memory object with its jsonb round-trip.
- A new special case for one kind in a shared classifier must fall through to the general rule. A test edit that removes a kind from a shared table is itself a review item.
- Re-implementing a canonical classifier inline is a DRY/safety finding. Reuse it, especially where a `FIXME(any)` cast disables type checking.
- Adversarially review your OWN fix cycle. This session's pass found two regressions in its own fixes:
  - an FK violation from reordering an insert;
  - a deterministic HITL id that would have adopted an already-answered request.

  Falsify every new guard, and check that the mutation run actually executed tests: `--maxWorkers=1` without `--minWorkers=1` starts nothing.
