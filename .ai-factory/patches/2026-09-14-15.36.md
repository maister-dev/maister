# Run status and input-form freshness

**Date:** 2026-09-14 15:36
**Files:** `web/components/runs/run-live-refresh.tsx`, `web/components/attention/attention-live-refresh.tsx`, app shell and launch consumers, `web/app/api/attention/stream/route.ts`, migration `0168`, focused DOM/integration tests
**Severity:** medium

## Problem

A running Flow can retain a NeedsInput sidebar label. An initial form can remain
absent from Inbox after the run becomes ready for input; launch leaves the user
on the task board.

## Root Cause

Trailing debounce postpones run-status checks indefinitely during continuous
SSE output. Shared layouts also survive navigation with older data. Attention
subscriptions exist only on selected pages and ignore their initial snapshot.
The form's decision event precedes its run-status commit, so a scan can consume
the event before the Inbox query considers the form actionable.

## Solution

Run checks coalesce ticks without moving the deadline, serialize requests,
retain changes during a request, and cancel work on navigation/termination.
Connection-time refresh reconciles retained layout data. The authenticated app
owns one attention subscription in its footer. Immediate launch opens the run.
The attention scan also reads the existing parked-state webhook outbox fact;
the project/time partial index bounds that lookup without external deliveries.

## Prevention

Test continuous event bursts and connect-time state gaps through mounted React
components. Use decimal SSE cursors in reconnect tests. Exercise decision
creation before run parking with real PostgreSQL and assert subsequent
invalidation, queue count, and project visibility. Shared chrome must keep
authenticated subscriptions out of login pages.
