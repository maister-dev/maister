# Verify-driven fix batch: as-built doc drift, silent co-evolve misroute, unasserted Test-Matrix arms

**Date:** 2026-07-24 15:19
**Files:** docs/decisions.md, docs/system-analytics/evaluations.md, docs/api/web.openapi.yaml, docs/api/external/operations.openapi.yaml, docs/CLAUDE.md, docs/screens/README.md, web/lib/evaluations/preflight.ts, web/lib/evaluations/launch-seam.ts, web/messages/{en,ru}.json, web/lib/scheduler/handlers/auto-promote.ts, web/lib/gc/workspace-gc.ts, 5 evaluations/db test files (+2 new: launch-batch-cap-saturation, ext/evaluations/result route)
**Severity:** medium

## Problem

An `/aif-verify` pass over the merged Experiments→Evaluation Lab cut-over (ADR-150) found three non-blocking classes: **F1** three canonical spec files (evaluations.md, both OpenAPI, the ADR-150 body) still carried Phase-0 `Designed` status labels and PRE-renumber migration numbers `0118`/`0119` (the ADR body even contradicted its own Consequences which correctly said `0119`/`0120`), plus ~6 stale numbers in code comments and two `ADR-142..147/149` refs; **F2** an intent-mode recipe slot silently passed preflight (`preflight.ts` exact-intent branch `return {}`) yet the launch seam threads only `mode:"runner"` hard-pins, so the variant launched on the WRONG runner — and the seam comment justified it as "Preflight already refuses… fidelity not safety," which was FALSE; **F3** four Test-Matrix rows the matrix claimed were covered had no real test (live-loader flow-facet refusals incl. the security-relevant `flow_not_launchable`, cap-saturation→Pending, packagePin create↔launch parity, ext result-route pairwise pick).

## Root Cause

- **F1:** a provenance renumber (twin took ADR-149+migr 0118 first, so this cut-over became ADR-150 + migr 0119/0120) renamed the FILES/journal/snapshots correctly but the PROSE lagged — status labels frozen at spec-time never flipped to `Implemented`, and migration numbers embedded in narrative sentences and code comments were missed because a file-rename pass does not touch prose. The as-built sync commit closed the DB-doc/glossary/ROADMAP half but not the ADR-body / system-analytics / OpenAPI-summary half.
- **F2:** a documented "co-evolve deferral" (intent-mode slot resolution needs the live catalog) was annotated with an UNVERIFIED safety claim. The author assumed preflight refused what the seam couldn't honor; in fact preflight's exact-intent path returned a silent pass, so the deferral degraded to a silent misroute, not a caught refusal.
- **F3:** the Test Matrix was authored as intent ("each behavior at exactly one level") but never audited row-by-row against real assertions; several rows had only lib-level or pure-core coverage, and the live-loader security surface (a loader mis-reading `trustStatus`/`enablementState`) had no end-to-end guard.

## Solution

- **F1:** grep-to-zero sweep, classifying every hit by feature (the twin's ADR-149/`0118` refs left INTACT; only this cut-over's own refs changed): `Designed→Implemented`, additive `0118→0119` / drop `0119→0120` inside the ADR-150 body with uniquely-anchored edits, `Accepted→Implemented` status + index, `/149→/150`, and 6 code-comment numbers. Verified with grep-to-zero + `validate:docs:all` + `validate:contracts` green.
- **F2 (owner chose hard-warn over refuse):** folded the exact-intent branch into the warning path so EVERY satisfiable intent slot emits `slot_intent_soft_mismatch` (never a silent pass), rewrote the warning message + EN/RU i18n + the false seam comment + evaluations.md to state the real behavior (falls back to the default runner chain). RED-first: the exact-intent test failed on the old code, passed after.
- **F3:** added non-trivial integration arms (real Testcontainers, no vacuous mocks), each RED-verified. Two subagents reported honest gaps instead of faking green: the ext result route has no participant-id membership check (winner is a positional `a|b|tie` enum — unenforceable by design; the real match-identity contract is `isPairwise ⟺ winner-present`, 422 both ways), and `artifact_contract_drift` is a digest-mismatch not reachable via the method loader (used `artifact_requirement_uncovered` instead).

## Prevention

- After ANY provenance renumber, the grep-to-zero surface includes PROSE number forms and STATUS LABELS, not just `NNNN_name.sql` filenames — sweep ADR bodies, `system-analytics/*`, OpenAPI `summary`/`description`, and code comments; verify each migration number against `migrations/meta/_journal.json`, and an ADR's own Consequences paragraph is a cross-check against its body.
- A "co-evolve deferral" comment that claims a safety net ("preflight already refuses X") is a CLAIM to verify against the actual gate, not documentation — if a seam cannot honor a declared input, the preflight/validation layer must WARN or refuse it, never silently pass (a silent pass turns a fidelity gap into a correctness bug).
- A Test Matrix is a checklist to AUDIT row-by-row against real assertions, not a coverage claim — especially the security-relevant live-loader boundary; prefer an integration test that asserts the loader's cross-row computation directly (`enablementLaunchable === false`) over end-to-end-only coverage.
