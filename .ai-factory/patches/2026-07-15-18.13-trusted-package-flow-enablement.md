# Trusted package Flow enablement repair

## Symptom

Previously trusted package Flow revisions could remain in `Installed`, which
made the launchability filter omit them from both task creation and Flow
selection.

## Root cause

`trustPackageRevision` propagated executable trust and ran deferred setup, but
did not transition ready attached Flow rows to `Enabled`.

## Repair

- Promote only still-`Installed`, trusted member rows whose revision completed
  setup and remains installed.
- Run migration `0103_repair_trusted_package_flow_enablement` once for existing
  eligible graph package Flows.
- Preserve disabled, untrusted, failed, pending, legacy, and detached rows.

## Validation

- `pnpm --filter maister-web typecheck`
- `vitest` migration journal integrity test
- Local `db:migrate` and `db:check`
