# ADR-129 fork-loop: apply-site guard, ext:: RCE hardening, sync mutex

**Date:** 2026-07-12 11:12
**Files:** web/lib/runs/promote.ts, web/lib/runs/auto-delivery.ts, web/lib/experiments/membership.ts, web/lib/auto-promotion/readers.ts, web/lib/services/hitl.ts, web/lib/packages/catalog.ts, web/lib/local-packages/git.ts, web/lib/local-packages/{sync,lock,versions}.ts, web/lib/packages/pin.ts, web/components/experiments/variant-editor.tsx, docs/api/web.openapi.yaml, docs/system-analytics/local-packages.md
**Severity:** critical

## Problem

An adversarial review of the ADR-129 branch (green suite: 6194 unit / 2244 integration / e2e) surfaced defects the per-phase gates missed:

1. **Blocker — experiment-member runs auto-promoted.** ADR-124's "experiment runs never auto-promote" was implemented at TWO seams — the ADR-126 sweep SQL prefilter and an `evaluateAutoPromotion` `not_applicable` term — but BOTH sit on the sweep path. A THIRD path (`deliverRunIfAutoReady` → `promoteRun(autoOnReady:true)`, fired at every flow run's Review transition) had no membership check, so on an `auto_on_ready` project/variant both the winning AND losing variant branches were silently `git merge --no-ff`'d before a human opened the comparison lab. The ADR even named the risk ("promoteRun evaluation can be reached OUTSIDE the sweep") and still guarded the sweep predicate, not the apply site.
2. **Critical (pre-existing) — `ext::` transport RCE.** `packageSourceCreateBodySchema.url` is `z.string()` with no scheme allow-list; `createPackageSource` validated the path only for `kind:'local'`, never calling `validateUrl` for `kind:'git'`. An admin-registered `ext::sh -c '…'` url reached `git remote add` at publish and executed on the host.
3. **High — sync/resolve/abort had no mutex.** The editor lock (`assertHoldsLock`) passes twice for one session, so a double-submit ran two 3-way merges over one working dir. The sibling **publish** path already had a strict CAS mutex (`acquirePublishLock`) — the lesson was not carried over.
4. **High — divergence OpenAPI lied.** Documented `ours`/`theirs`/`element`; the handler returns `base`/`compared`/`perFile`.

## Root Cause

- **Guard at the predicate, not the apply site.** A membership predicate consumed only by the sweep reads like enforcement but is not; the authoritative guard must sit at the ONE irreversible choke point (`promoteWorkspaceRun`) every caller funnels through, keyed on the actor/intent (`autoOnReady || attribution.source==='auto_promotion'`), so the human winner-promote stays allowed.
- **Sibling-field validation gap.** The branch authored the source-registration schema and added `kind:'local'` path validation but left the sibling `kind:'git'` url (a subprocess-argv sink) unguarded.
- **A hard-won concurrency primitive wasn't reused.** `acquirePublishLock` existed with an explicit "NO same-session escape" comment; sync was written against the weaker edit-lock.
- **Specs-first drift.** The OpenAPI reflected an earlier divergence design the code moved past; the "SDD review gate" (re-derive contract surfaces from the diff) didn't catch it.

## Solution

- One canonical `isExperimentMemberRun(db,runId)` in `membership.ts`; guard `promoteWorkspaceRun` (throws `PRECONDITION {experimentMember:true}` for unattended promotes), plus an ordering short-circuit in `deliverRunIfAutoReady` (avoids a spurious degrade-to-manual); converged two pre-existing duplicate membership queries onto it. Regression tests: short-circuit-without-degrade, apply-site refusal, human-promote-not-blocked.
- `validateUrl(opts.url)` for `kind:'git'`; `--` in `gitSetRemote`; `branchNameSchema` on `baseBranch`; `..`-segment refusal on local paths. Regression tests: `ext::` and option-shaped urls refused pre-persistence.
- Generalized `acquirePublishLock`→ a working-dir mutex (aliases, zero publish blast radius); each of sync/resolve/abort acquires it and re-reads state UNDER the lock (TOCTOU-safe); made abort idempotent (no-pending → no-op `200`, not `409`). Deterministic concurrency test: lock-held → sync refuses.
- Rewrote `LocalPackageDivergence` to `base`/`compared`/`perFile`; fixed pin-options `422→400` (code wins); added abort `422`; deterministic `orderBy(asc(pi.id))` on the provenance reverse-join; trust deny-list → allow-list in `pin.ts`; threaded a hardcoded `"local cut"/"upstream"` string through EN+RU i18n.

## Prevention

- When a review says a guard is "at the irreversible apply site," verify the guard's callers ARE that site — grep the funnel (`rg 'promoteWorkspaceRun|promoteRun'`) and confirm every automatic caller passes through the guarded seam, not just the one the author had in mind.
- When adding a validator to one field of a boundary schema, sweep EVERY sibling whose value reaches the same class of sink (fs / subprocess argv / SQL) in the same pass.
- A `// NO same-session escape` mutex is a signal that the SAME hazard exists on every sibling that mutates the same resource — grep for other writers of that working dir before assuming the edit-lock suffices.
- A green multi-agent review does not clear the apply-site/actor-authority class; run an explicit adversarial pass on promotion / trust-boundary / concurrency diffs.

## Re-review addendum (2026-07-12, independent 4-agent adversarial pass over the fix diff)

The fix pass was itself adversarially re-reviewed. C1 (choke-point guard) and C3 (sync mutex) held up — verified no bypass, no deadlock/release-leak, no legitimate path broken, no acceptance-criterion regression. But the C2 hardening had a **real hole that its own tests masked**:

- `validateUrl`'s scp branch `/^[^/@]+@[^/:]+:/` admits `ext::sh -c …@h:` (the `::` and spaces live in the `[^/@]+` user segment) and `-oProxyCommand=…@host:` (option injection). So a scp-shaped `ext::` payload was still **stored**; git's own default `protocol.ext.allow` was the only backstop, which the code never pins. The new tests only asserted the *non-scp* forms (`ext::sh -c 'id'`, `--upload-pack=…`) — exactly the shapes already rejected — so they were **false green**.
- Fix: harden `validateUrl` to reject `::` smart-transport and `-`-leading scp user/host; test the actual bypass shapes; route `ensureDefaultPackageSources` through `validateUrl` too.

**Lesson: a security-control test must assert the BYPASS the control exists to stop, not a payload the control already rejects for an unrelated reason.** When adding a validator, enumerate the evasion shapes (transport prefixes, option-leading, encoding) and pin each as a negative test — a green "malicious input rejected" test proves nothing if the input was malformed in a way orthogonal to the threat. Re-derive the regex's actual accept-set (run it on the evasion strings) rather than trusting the intent.
