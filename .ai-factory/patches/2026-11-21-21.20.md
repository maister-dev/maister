# Bind durable wait evidence to each decision

**Date:** 2026-11-21 21:20
**Files:** `web/lib/waits/`, `web/lib/auto-promotion/`, `runtime/pull-request.ts`, `supervisor/src/workspace-publication.ts`, `docs/api/`, `web/e2e/flow-waits.spec.ts`
**Severity:** high

## Problem

A pre-callback observation could leave the exact callback pending, and an old
Review event could settle a new related-run wait as Review after Done. An
interrupted park preparation could occupy capacity indefinitely. A PR merged
into a different base could qualify for delivery, and the platform switch
could still allow an autonomous failure.

## Root Cause

Observations mixed facts with different lifetimes. A ref reading lacked the
receipt it covered, and historical events lacked the registration snapshot that
separates existing state from subsequent transitions. Publication trusted the
intended base and fenced the caller before lookup, leaving the provider write
outside the last host authorization check. Terminal paths evaluated different
subsets of the same live authority.

## Solution

Bind facts to the exact delivery or snapshot and bound the park preparation
from the attempt start. Read the provider's base and route the PR effect through
the host receipt with a fence immediately before the write. Share platform
authority across promotion, finalization, classified failure and conflict
recovery. Resolve external prompt bytes through the typed data path after
instruction rendering. Keep route schemas, agent and operator read models, and
Studio transitions in sync with the graph lifecycle.

## Prevention

Replay a callback arriving after a same-SHA observation. Test retargeting and
epoch changes between provider lookup and write across all three adapters.
When moving a subprocess across the host seam, update the operation-scoped
filesystem inventory and run its mutation checks. Validate an actual parked
Run response against each generic status contract and check operator controls
against the server-owned action set.
