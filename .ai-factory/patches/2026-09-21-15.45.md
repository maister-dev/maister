# Review fixes for ADR-177: a non-deterministic crash predicate, a split attempt identity, and two untested owner branches

**Date:** 2026-09-21 15:45
**Files:** web/lib/execution-host/events/stream-health.ts, web/lib/reconcile-evidence-db.ts, web/lib/reconcile.ts, web/lib/runs/turn-lost-boundary.ts, web/lib/flows/graph/prompt-owner.ts, web/lib/agents/prompt-owner.ts, web/lib/agents/finalization.ts, web/test-support/turn-lost-seed.ts, docs/decisions/adr-177.md, docs/system-analytics/execution-prompt-lifecycle.md (+3 test files)
**Severity:** high

## Problem

A self-review of the ADR-177 branch found six defects that the branch's own
green lanes did not surface:

1. `commandStreamLost()` selected ONE arbitrary stream row (`.limit(1)`, no
   `ORDER BY`, no state filter) and answered from it. ADR-177 promoted that
   answer from a yield-and-retry diagnostic into a run-terminalizing crash
   (`crash / stream-lost`), so on a host holding both a `lost` and an `active`
   stream it could crash a run whose evidence was arriving normally.
2. The evidence probe resolved the run's newest `node_attempts` row (any node,
   any status) while `applyTurnLostBoundary` resolved the open `Running`
   attempt at `current_step_id`. A run could be CLASSIFIED from attempt A and
   ACTED on at attempt B; when B had no owned command the boundary answered
   `not-claimed`, the sweep logged a lost CAS, and the run stayed `Running`
   with nothing bounding the next tick.
3. The flow GATE owner's turn-lost branch (~25 lines writing three tables) and
   the agent owner's `turnLost ? "Crashed" : "Failed"` ternary had NO test.
   Inverting the ternary left the entire suite green.
4. Choosing `Crashed` over `Failed` silently widens `TERMINAL_CAS_SOURCE` from
   `{Running, NeedsInput}` to four statuses — intended, but unasserted.
5. The gate branch returned `"applied"` leaving `gate_results.status='running'`,
   the exact stuck shape `runGateStepGuarded` exists to prevent.
6. That branch's precondition subset omitted `currentStepId === nodeId`, making
   it strictly weaker than the sibling verdict path beside it.

## Root Cause

Three distinct causes, worth separating:

**A shared helper's contract was assumed rather than read.** `commandStreamLost`
was correct enough for its original caller, which yields and retries — an
arbitrary answer costs one wasted wait. Reusing it for a decision that
TERMINALIZES a run changed the required precision without changing the helper.
The lesson is not "the helper was buggy"; it is that promoting a predicate from
advisory to terminal is a contract change that must re-derive the predicate.

**DRY applied to two questions that only looked like one.** The probe and the
grace anchor were merged into one `latestAttemptRow` read on the reasoning that
both wanted "the attempt". They do not: the grace anchor asks *how long since
this run did anything* (run-scoped, any node, any status) and the probe asks
*which attempt owns the turn in flight* (node-scoped, open). Merging them made
the classifier and the writer disagree about what they were talking about.

**The "assert through the consumer" rule was applied unevenly.** The plan banned
constant-restating tests and required every acceptance to go through a consumer
— and that rule was enforced for the accounting work (T4.1) while the owner-side
wiring (T3.3/T3.4) shipped with its decision inlined in an adapter whose `apply`
is unreachable without a live launcher. An untestable shape is how an untested
branch gets rationalised.

## Solution

- `commandStreamLost` now means *a stream was given up AND none is live*: it
  reads every stream of the host and returns `lost ∧ ¬active`. Strictly better
  for the original caller too (it stops yielding on a recovered host).
- One exported predicate, `resolveEvidenceAttemptId`, used by BOTH the probe and
  the boundary, so a decision and its write cannot target different attempts.
  The grace anchor is restored to its own run-scoped read.
- The agent decision is extracted to `agentTerminalOutcomeFor`, a pure function
  with 8 unit cases covering both production error shapes, the negatives, and
  the CAS widening (`TERMINAL_CAS_SOURCE` exported to make that assertable).
- The gate branch marks the evaluation `stale` (not `failed` — a host restart is
  not a judge's verdict; not `running` — that is the stuck shape) and its guard
  now matches its sibling's. Three integration cases drive the REAL adapter.

## Prevention

- **Falsify every regression guard, and believe the result.** The first guard
  written for defect 1 went through the sweep and PASSED against the unfixed
  code, because the old implementation's answer was arbitrary and happened to
  land benign. It was replaced with a five-shape contract test plus an explicit
  note that this class cannot be falsified against non-deterministic code. A
  guard that cannot fail is not coverage.
- **When a predicate is promoted from advisory to terminal, re-derive it.** Grep
  the helper's other callers and ask what each does with a WRONG answer: yield
  and retry is survivable, crash is not.
- **Before merging two reads for DRY, state each question in words.** If the
  sentences differ, the reads are not duplicates.
- **A decision inlined in an unreachable adapter is untestable by construction.**
  Extract it to a named function in the same pass that writes it, or accept that
  no test covers it. "Covered by the integration suite" is a claim to verify —
  here the suite exercised the two halves separately and would have passed with
  the decision inverted.
