# Codex review #3: crash arms must honour their transition's result; coordinator death is any terminal parent

**Date:** 2026-09-03 23:46
**Files:** web/lib/reconcile.ts, web/lib/runs/keepalive-sweeper.ts, web/lib/runs/budget-breach-fork.ts, web/lib/services/hitl.ts, web/lib/__tests__/reconcile-sweep.integration.test.ts, web/lib/__tests__/reconcile-classify.test.ts, web/lib/runs/__tests__/budget-watchdog.integration.test.ts, web/lib/runs/__tests__/budget-breach-options.test.ts, web/lib/services/__tests__/hitl-budget-breach.integration.test.ts, docs/system-analytics/orchestrator.md, docs/system-analytics/execution-policy.md, .ai-factory/specs/cost-budget-governance.md
**Severity:** high

## Problem

Third adversarial review of the tree-budget / orphan-recovery branch. Seven
findings accepted (F1 F2 F3 F4 F6 F7 F9), two held (F5 F8 — see below).

- **F1** The reconcile flow crash arm called `crashRunningRun` and ignored its
  `{ok:false}`: a run that a concurrent transition moved between candidate
  load and the status-guarded CAS (e.g. paused into `NeedsInput` with a fresh
  assignment) lost the CAS — and then had its materializations cleaned, its
  assignments closed, a slot promoted and `crashed` incremented anyway.
- **F2** `orphaned-orchestrator` is the one crash reason that can carry a LIVE
  session (coordinator death is checked before liveness). The cascade tears
  down DESCENDANT sessions only and nothing reaps a live session under a
  `Crashed` row, so the coordinator's own adapter kept spending under a
  terminal row.
- **F3** `coordinatorGone` and the orphan loader's SQL treated only
  `Crashed | Abandoned` as coordinator death. A `Running` orchestrator that
  trips its own run-scope budget or fails at a node goes `Failed` WITHOUT a
  cascade; a `Done` coordinator can leave a child too. Both stranded children
  were invisible to the per-status recovery that the previous round added.
- **F4** The agent crash arm ignored `finalizeAgentRun`'s `{finalized:false}`
  (lost CAS, or finalize deferred to a pending human-ask activation) and never
  asked the choke point to close open HITL rows — an orphan paused on a
  permission request kept counting toward "Needs you" under a Crashed row.
- **F6** The budget tree-terminate arm resolved the root's active attempt
  BEFORE its transaction and CASed on status alone. A root that advanced from
  node A to node B while staying `Running` still won the CAS, and the stale
  (already Succeeded) attempt A was failed while B kept running under a
  `Failed` run. The run-scope arm already guarded on `current_step_id`.
- **F7** `coupledRaiseOverride` lifted ANY tree ceiling that was not stricter
  than run — including an operator's deliberately LOOSER aggregate cap — and
  the `budget_raised` audit named only the breached scope.
- **F9** Two doc sentences still described the pre-fix behaviour (lost tree CAS
  "recorded"; coordinator death as Crashed/Abandoned).

## Root Cause

- F1/F4: a status-guarded CAS is the ONLY thing that says "this transition
  landed", yet both arms treated the call as fire-and-forget. The orchestrator
  arm next to them already branched on its result — the pattern existed, the
  two siblings just never adopted it.
- F2: the cascade helper's contract is "descendants" and the E5 kill-first
  discipline lived only in the budget tree arm; the new orphaned-orchestrator
  route reused the stuck path, whose classifier guarantees `!liveSession`, so
  nobody had ever needed to stop the coordinator's own session there.
- F3: the set was written from the cascade's point of view (the two statuses a
  cascade WRITES), not from the child's ("can my parent still drive me?"). The
  loader's SQL duplicated the literal list, so the classifier and loader could
  only drift together.
- F6: fetching the attempt outside the CAS transaction with no guard tying the
  CAS to the node the attempt belongs to. Same class as F1/F4: state read
  before the CAS, acted on after it, without the CAS covering it.
- F7: ordering (`tree < run` ⇒ stricter, else couple) was taken as proof the
  two ceilings were seeded together. Only exact equality is that proof — it is
  the shape `applyDefaultBudgetForUnattended` writes.

## Solution

- reconcile.ts: flow arm branches on `crashResult.ok`; agent arm passes
  `closeOpenHitl: true` and branches on `result.finalized`; both count a
  lost CAS as `skipped` at WARN and touch nothing downstream. The
  orphaned-orchestrator route stops every live session of the coordinator
  itself BEFORE the cascade with the budget arm's E5 semantics
  (`EXECUTOR_UNAVAILABLE` → leave the whole sub-tree for the next tick;
  terminal failure → proceed). `coordinatorGone` keys on
  `isTerminalRunStatus`, and the loader's `NOT IN` is built with
  `sql.join` over `TERMINAL_RUN_STATUSES` — one set, two consumers.
- keepalive-sweeper.ts: the tree-root CAS gains the same `current_step_id`
  guard as the run-scope arm.
- budget-breach-fork.ts / hitl.ts: couple only on exact equality; the helper
  returns `{ override, coupledScopes }` and the audit carries
  `coupledScopes`.
- Tests, all red-first: F1 and F4 racers use the sweep's `listWorktrees` hook
  (it runs after candidate load, before classification) instead of module
  mocks; F2 has a happy path and a 5xx path; F3 covers Failed/Done parents in
  the classifier and the sweep; F6 injects the node advance at the root's
  session kill; F7 has the looser-tree unit case plus two breach integration
  cases asserting the audit through a pass-through spy on
  `logExecPolicyAction`.
- Held on the record: **F5** (tree budget for `Review` roots) — E6/E11
  locked, the owner's call; **F8** (abandon route cascade-first) — rejected
  with evidence in round 3 and re-affirmed (all cascade callers are
  cascade-first; inverted order has an unrecovered window and an auto-launch
  hazard).

## Prevention

- Every call to a status-guarded transition MUST branch on its result before
  any dependent effect. Grep the choke points (`crashRunningRun`,
  `finalizeAgentRun`, `markAbandoned`, `crashWaitingOnChildren`) for
  callers that discard the return value.
- State read before a CAS and acted on after it must be covered BY the CAS
  (guard on the row fields the read depended on), or re-read inside the tx.
- Derive SQL literal lists from the TS constant (`sql.join`); never duplicate
  a status set as string literals.
- A new route into an existing arm inherits that arm's PRECONDITIONS — check
  what the classifier guaranteed for the old route (here `!liveSession`)
  before reusing its action.
- DB CHECK constraints shape fixtures: `hitl_requests` forbids a task binding
  on non-agent-question rows and requires one on agent questions — read the
  constraint before seeding, and note that a "task-less pending question"
  cannot exist (the recovery pass's `if (!row.taskId) continue` is dead).
- An audit line must name everything the action changed, not the scope that
  triggered it.
