# HITL review remediation: replaceable budget claims and request-scoped scratch feedback

**Date:** 2026-09-23 12:34
**Files:** `web/components/board/{run-hitl-response.tsx,__tests__/run-hitl-operator.dom.test.ts}`, `web/components/inbox/hitl-panel.tsx`, `web/components/scratch/{scratch-conversation.tsx,scratch-permission-panel.tsx,__tests__/scratch-hitl-operator.dom.test.ts}`, `docs/{screens/inbox.md,screens/runs/flow-run.md,screens/runs/scratch-run.md,system-analytics/hitl.md}`
**Severity:** high

## Problem

Four branch-review findings contradicted the P0-4 operator contract. A budget claim whose stage was `failed` returned as `answer_stored` and lost its still-valid recovery controls. A stored permission option missing from the current option set was treated as retryable because `Array.find` returns `undefined` but the check rejected only `null`. Scratch rendered a localized prompt-owner reason but omitted its `causeCode` diagnostic. Its refusal and busy state were keyed only by run, so a late refusal for request A could appear beside request B on the same run.

## Root Cause

`answerState` describes whether a response is present, while budget-claim `stage` describes whether that response remains the active choice. Treating the first as a universal lock ignored the existing server rule that `stage: failed` permits a replacement decision. The option check mixed the `null` fallback used for absent payloads with `undefined` from `Array.find`. Scratch accepted a shared error descriptor but rendered only its translation key; its asynchronous POST guard compared run ids and had no request identity to reject old completions.

## Solution

The board and inbox keep `budget_breach` with `claimStage: failed` actionable, matching the server's reclaim path. Both stored-permission cards require an option actually present in the current choices before offering Retry. Scratch now renders the shared descriptor's `causeCode` in a `<code>` detail and scopes pending, refusal, and late POST completion to `runId:hitlRequestId`. A terminal 410 remains visible after its card disappears only while that request is the latest one observed. EN/RU copy continues to come from the existing shared reason map; no new runtime logging was added to client components.

## Prevention

- Check derived read states against domain sub-states before making controls read-only; test the replaceable and terminal stages separately.
- When validating a `find` result, use its actual absence value, `undefined`, and include an obsolete-option regression case.
- Treat asynchronous feedback as belonging to a request identity. Test an old completion both while the next request is open and after it disappears.
- Render the complete shared error descriptor on every surface, including its optional diagnostic field, without exposing raw server messages.
