# ADR-129: close the D-1/D-4 delivery + resume test-coverage gaps + correct REQ-17 wording

**Date:** 2026-07-11 21:30
**Files:** web/lib/flows/__tests__/runner-agent-hooks.test.ts, .ai-factory/plans/claude-capability-enforcement-acp-seam-7f6053.md
**Severity:** low

## Problem

The adversarial /aif-review of the ADR-129 branch flagged two test-coverage gaps left open by the blocker-fix pass (patch 2026-07-11-14.47):

- **D-1 (REQ-20):** the derivation of `enforcementProfile` was unit-tested and the supervisor acceptance was schema-tested, but the GLUE that actually DELIVERS the profile on the outgoing `createSession` body (`runAgentStep` → `createInput.enforcementProfile`) had NO test. A regression dropping `ctx.enforcementProfile` from the session body would ship green.
- **D-4 (REQ-17):** no test exercised the resume path's enforcement behavior, and REQ-17's wording ("on resume READ the persisted `enforcement_snapshot`") described behavior that does not exist.

## Root Cause

- D-1: the delivery seam sits between two tested layers (derive / accept) with nothing asserting the wire in between — a classic "each end tested, the join untested" gap.
- D-4: REQ-17 was authored against an assumed design (read-the-snapshot on resume). The as-built flow forces new-session per attempt and RE-DERIVES the profile deterministically; the persisted `plan.enforcementProfile` is an audit snapshot, never read back (confirmed while fixing the false "resume reads the profile" comments in the blocker pass). The requirement text was never reconciled to the code.

## Solution

Added three wiring tests to `runner-agent-hooks.test.ts` (reusing its no-DB `makeApi`/`makeCtx` harness — the createSession spy already captures the body):
- REQ-20: `ctx.enforcementProfile` is delivered on the new-session `createSession` body.
- REQ-17: a resume (`ctx.resumeSessionId` set) re-delivers the (re-derived) profile alongside `resumeSessionId` — the same createInput is reused on the resume path.
- Inert: a non-enforced node omits the field (byte-identical to pre-ADR-129), asserted with `not.toHaveBeenCalledWith(objectContaining({ enforcementProfile: expect.anything() }))`.

Corrected REQ-17 in the plan matrix to the as-built truth (re-derive + re-deliver; snapshot is audit-only), pointed its test cell at the determinism test + the new resume test, and updated REQ-11 (D5 sentinel now keyed off EXECUTION, not the pending notification) and REQ-20's test cell to the real files.

## Prevention

- **A value that crosses a process boundary needs a test at the SEND site, not only at the derive + receive sites.** When a field is derived in module A and consumed in service B, assert the caller PUTS it on the wire — the two-ended coverage (derive-unit + accept-schema) leaves the delivery unguarded.
- **A requirement that describes a mechanism ("reads the snapshot") must be reconciled to the code at as-built.** When the implementation chose a different mechanism (re-derive), correct the REQ text in the same pass — a stale requirement steers the next implementer to the wrong design.
- Prefer `toHaveBeenCalledWith(expect.objectContaining(...))` over `mock.calls[0][0]` on a no-param `vi.fn` — the latter types the call args as an empty tuple and fails `tsc`.
