# Dispatch consensus draft children outside the parent's traversal claim

**Date:** 2026-09-14 18:45 (Europe/Moscow)
**Files:** `web/lib/flows/graph/consensus/{drafts,runtime,ledger}.ts`,
`web/lib/flows/graph/runner-graph.ts`, `web/lib/flows/runner.ts`,
`web/lib/runs/{flow-result-dto,node-status-visual}.ts`,
`web/components/runs/node-status-icon.tsx`, EN/RU messages, associated tests,
`docs/system-analytics/{consensus,execution-prompt-lifecycle}.md`,
`docs/screens/runs/flow-run.md`, `web/CLAUDE.md`, `consensus-output.integration.test.ts` (fake host seam).
**Severity:** high

## Problem

The first live `aif-dev` run (MAI-4, attempt-3) parked its `plan_consensus`
node as "Нужен ввод" with an empty inbox, then produced a consensus HITL asking
the operator to pick between two "Draft unavailable." drafts. All four draft
children (two rounds × claude-fable / codex-astra) ended `Crashed` with
`reconcile: agent-session-gone`; no `POST /sessions` ever reached the
supervisor, `execution_commands` held no row for them, and the only web-side
error was `Flow traversal no longer owns its continuation`. The board showed no
reason anywhere.

## Root Cause

- `launchConsensusDraftRuns` dispatched each runner-kind child with
  `startAgentSession(runId, { db: input.db })`, where `input.db` is the
  parent's traversal-scoped handle (`flowDriverDatabase`): every statement on it
  asserts the PARENT's active execution assignment. The consensus park releases
  that assignment (`waiting_on_children`) within ~200 ms of fan-out, so the
  child's session create, prompt — and even the catch-path
  `finalizeAgentRun(Failed)` — threw `FlowDriverClaimLost`. The child stayed
  `Running` without a session until the 60 s reconcile sweep crashed it.
- The real-supervisor consensus suite never caught this because `runFlow`
  only takes the fenced driver path for graphs with `ai_coding`/`judge`/
  `orchestrator` nodes; a consensus-only test graph ran unfenced. `aif-dev`
  carries `ai_coding` nodes, so production was fenced.
- With every draft unavailable the runtime still verified fail-closed
  (`draft_unavailable`), spent round 2 on nothing, and escalated to a human.
  The children's terminal reason lives only on their `run.crashed` domain
  event and in journald; the run DTO labelled the parked coordinator node with
  the ledger's `NeedsInput` mark although the run was `WaitingOnChildren`.

## Solution

- Thread the graph driver's root handle (`opts.driver.rootDb`) through
  `executeNodeAction` → `runConsensusNode` → `launchConsensusDraftRuns` as
  `rootDb`; the child dispatch rides it, the fan-out's own rows stay on the
  traversal handle.
- Count `consensus` nodes as owned-prompt graphs in `runFlow`, so consensus-only
  graphs (and the suite) take the same fenced path as production.
- Fail a settled round with no available draft as `MaisterError("CRASH")`
  (`details.reason = consensus_no_draft_available`, each child's status and
  terminal reason from `domain_events`) before verifying, iterating or
  escalating; `loadConsensusDraftFailureReasons` reads those reasons.
- Present the current coordinator node of a `WaitingOnChildren` run as
  `WaitingOnChildren` (pause glyph, "Ждёт подзадач" / "Waiting on children")
  instead of `NeedsInput`, in the node list, the selected-node field and the
  canvas chip.

  pass unchanged (30 tests).

  finds the single dispatch (root handle); `rg -n 'rootDb' web/lib/flows`
  shows the driver, graph ctx and consensus inputs only.

## Prevention

Any work a coordinator starts that outlives its own traversal (child dispatch,
consumers, owner application) must take the root handle; the traversal handle
is only for statements that should die with the claim. A regression suite for
a fenced feature must run on the fenced path — mirror `runFlow`'s owned-prompt
rule, do not rely on a shortcut. An infrastructure failure of every participant
must fail the node with its evidence, never masquerade as "no consensus".
