# Qualify launch consumers and replace obsolete synchronous route tests

**Date:** 2026-11-03 15:00 Europe/Moscow
**Files:** scheduled automatic source adapters and validators; `web/test-support/{accepted-qualification,automatic-qualification,repository-qualification}.ts`; launch engine/API/execution-host/recurring-schedule consumer fixtures; `web/app/api/runs/__tests__/launch-intent-adapter.integration.test.ts`; removed `web/app/api/runs/__tests__/post-branch.test.ts`
**Severity:** high

## Problem

Strict admission for new task execution roots exposed old consumers that treated legacy `triage_status=triaged` as sufficient qualification. Engine tests then failed at admission before reaching their intended branch, package, capability, concurrency or host checks. The old compatibility-route unit suite also required synchronous mocked Run creation and launch SSE frames after the route had changed to durable JSON launch-intent acceptance.

## Root Cause

Legacy task flags were being used as a substitute for a current accepted assessment, and scheduled roots called the engine directly rather than recording their own automatic authority. The fixtures encoded those older assumptions. Several engine fixtures also used nonexistent `/repos/...` repositories and fabricated commit IDs; those cannot demonstrate the repository evidence required by real admission.

The 17 mocked route tests asserted forwarding to obsolete `launchRun`/`launchRunStaged` entry points. Mocking the new admission constructor to preserve them would bypass the authority behavior that the change is intended to protect.

## Solution

Scheduled jobs, recurring logical fires and one-time reservations now use DB-scoped opaque server-source constructors and the canonical automatic acceptance contract. Stable source IDs survive waiting/replay; mutable lease timestamps do not alter logical fire identity. A queued accepted fire reports Dispatching without inventing a Run. One-time recovery adopts its existing fixed Run/attempt/branch/path allocation and does not spend another attempt or remove its owned checkout.

Consumer fixtures now seed a well-formed current accepted qualification using the actual task digest and revision under real SQL guards. Actual engine/dispatch cases use owned temporary Git repositories and reachable evidence SHAs. Synthetic evidence remains confined to selector tests whose existing injected launch seam deliberately stops before engine dispatch. Legacy/unarmed/source-child negative cases remain negative. Existing engine effect and host boundaries were retained; no canonical authority was mocked.

Two real PostgreSQL/temp-Git compatibility-route cases replace the unique selection/parser assertions. The 17 obsolete mocked tests were removed only after their replacements passed. Root/evaluation/agent/recovery consumers owned by other workers were excluded from this bounded slice and require their separate gates. ## Prevention

When tightening shared admission, enumerate consumer test names and classify which fixtures are allowed to stop at a selector seam. Use real Git evidence for tests that enter the engine. Preserve negative fixtures and technical assertions rather than weakening the admission predicate. Replace old route contract tests by proving the new real handler behavior first, and map every removed assertion to its primary owner so duplicate removal does not silently remove unique coverage. Keep queued-source recovery tests separate from selector fixtures: they must prove the durable decision, original allocation and truthful acknowledgment under actual restart/lease recovery.
