# Seed execution placement for the packaged-script integration fixture

## Root cause

The complete frozen Web integration gate at `e38ed6d14` reproduced the existing
packaged-script fixture entering `runFlow` without an execution assignment. R20
correctly includes `check` actions in CLI traversal ownership because both
`check` and `cli` dispatch real `runCliStep`. Lazy legacy placement therefore
reached the explicit test-runner refusal for an unset `MAISTER_SUPERVISOR_URL`,
before any attempt or shell command ran. The previous fixture had relied on
check-only traversal bypassing that ownership requirement.

This is a fixture correction, not a production-host bypass. Canonical Flow
launch resolves `localHost` and creates its assignment atomically with the Run
for every manifest. The production ownership and test-runner host guards remain
unchanged.

## Fix and scope

`web/lib/flows/graph/__tests__/flow-install-dir.integration.test.ts` now imports
existing `seedPlacedGraphRun` under its existing local alias. That helper creates
real SQL host/assignment rows through the established fake execution-host
boundary; this check-only graph sends no ACP command. The actual bash command,
pinned installed Flow directory, `MAISTER_FLOW_DIR` shell guard, Review and
Succeeded assertions, and literal `flow-dir-script-ran` stdout assertion are
unchanged. No product, migration, timeout, provider, or historical data change
is included.

The fixture also removes its exact returned runtime/worktree paths in `finally`
after the real command and assertions. Both removals are attempted and errors
propagate; no broad prefix cleanup or silent `force` removal is used. This
closes the raw-directory lifecycle gap identified during independent review.

Source-class audit: `services/runs.ts` resolves the placement host before launch
and calls `mintPlacement` in the Run-insert transaction without a node-type
filter. `runner-graph.ts` dispatches both `cli` and `check` through `runCliStep`;
`runner-core.ts` uses the pinned revision's actual manifest and installation
path. The existing main graph integration fixture already creates placement,
and the real-Supervisor CLI owner does so through `localHost`/`mintPlacement`.
No equivalent runtime relaxation is appropriate.

## Prevention

When execution ownership becomes stricter, seed the actual launch preconditions
for command fixtures instead of weakening the guard or manufacturing command
output. Classify effects using actual dispatch, including check nodes and gates;
test names alone do not establish that a graph is sessionless and effect-free.
