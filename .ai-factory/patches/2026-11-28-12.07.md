# Plan gates named `validate:docs` while CI runs `validate:docs:all`; as-built flip and static guards left gaps

**Date:** 2026-11-28 12:07
**Files:** docs/system-analytics/m51-traceability.md, docs/CLAUDE.md, docs/decisions/adr-225.md, docs/error-taxonomy.md, docs/supervisor.md, docs/system-analytics/{README,attention,client-messages,host-diagnostics,identity-access}.md, web/CLAUDE.md, docs/configuration.md, docs/database-schema.md, supervisor/src/{diagnostics-cache,http-api,host-state}.ts, supervisor/src/__tests__/{diagnostics-cache,diagnostics-route.integration,host-state-v23.integration}.test.ts, web/lib/queries/decisions.ts, web/test-support/client-namespace-scanner.ts, web/lib/__tests__/i18n-client-namespaces.test.ts, web/lib/execution-host/__tests__/diagnostics-freshness.test.ts, web/lib/db/__tests__/hot-path-indexes.integration.test.ts
**Severity:** medium

## Problem

A perf branch passed every gate its plan listed, yet CI's docs gate was red
(`validate:docs:all`: `EDGE-ATN-09: matrix row names no enforcing task`). The
"Designed → Implemented" close-out left six stale surfaces, including a dead
heading anchor and two agent-facing docs still describing the pre-change
behavior. Four guards had holes a one-line change could walk through:

- reverting the root layout to the raw i18n catalog kept every test green;
- the one real call site in `lib/execution-host/client.ts` was exempted as
  "infrastructure" from the freshness test;
- `export { useTranslations as useT } from "next-intl"` hid every `useT` call
  from the namespace scanner;
- two plan-check tests synchronized on fixed 300 ms sleeps (one with a promise
  nothing ever resolved), and one hand-copied the SQL it claimed to check.

## Root Cause

- **Gate name copied from a stale doc.** `docs/CLAUDE.md` still said wiring
  `validate:docs` into CI was an open follow-up and that a Stop hook ran it.
  Neither was true: CI runs `validate:docs:all`, which adds the
  requirement-coverage groups. The plan's "Full gates" line inherited the
  narrower name, so Task 17 was ticked with a red CI gate.
- **Two validators with incompatible assumptions.** `validate-docs-indexes`
  demands a traceability row for every declared `EDGE-ATN-*` id; the M51
  coverage check demands each row cite a task defined in the M51 plan. A later
  branch that declares an M51-prefixed edge id fails one or the other.
- **Status flip done by editing, not by grep.** The flip touched the files the
  plan named; it missed the README index rows, one `(Designed)` bullet, the
  "currently 22" sentence, and the anchor of the heading it renamed
  (`#per-render-memoization-designed`). Doctrine text in two other files ("the
  `users` row is re-read on every call") was made false by the code change and
  not revisited. A new `details.reason` token reached the OpenAPI, the prose and
  the ADR but not the canonical table in `error-taxonomy.md`.
- **Metrics recorded before a rebase.** ADR-225's validation figures described
  the pre-rebase catalogs (83 namespaces, −16.1%) and were replayed by the
  rebase without recomputation (HEAD: 84, −15.5%).
- **File-wide exemption hid a call site.** `client.ts` holds both an options
  forwarder and a real `diagnostics({ refresh: true })` call; exempting the file
  exempted both.
- **Name-based recognition.** The scanner recognizes hooks by identifier name,
  so a same-name re-export is handled, but a renamed re-export is invisible and
  raises no violation.
- **Clocks instead of signals.** The hot-path test had a `tickSeen` promise
  resolved only in `finally` (so the race always waited the timer) and a bare
  sleep; IDX-12c asserted a hand-copied statement, so a reader change would not
  fail it.

## Solution

- Cited the owning M51 tasks with a parenthetical, as the file's own
  `EDGE-ATN-08` row does: `T4.3, T4.4, T5.7 (memo key: … Task 12)`. Corrected
  `docs/CLAUDE.md` to name the CI command and the difference.
- Completed the flip and reconciled the behavior-change doctrine: status labels,
  the renamed anchor, the `on every call/check` sentences, the
  `diagnostics_query_invalid` row, and recomputed ADR-225 at HEAD with the
  measurement method stated (decision text untouched; a dated amendment records
  the delta).
- CMSG-01 now has a guard: the scanner reports where the root provider's picker
  and list were imported from, following one local `const` binding.
- The freshness test classifies `client.ts` as fresh and exempts only the exact
  forwarding call (`FORWARDING_CALLS`), and also sees direct
  `checkSupervisorDiagnostics(` calls.
- The scanner flags any re-export of the hooks or the provider
  (`intl_reexport`) and any import of them from another module
  (`indirect_intl_import`), reads `.js/.jsx` sources, and the repo walker
  rethrows every error except an absent optional root.
- The hot-path test waits for the worker's candidate statement through
  `onCapture`; IDX-12c captures the reader's own statement with
  `vi.spyOn(DatabaseSync.prototype, "prepare")`.
- Small production fixes under test: the discarded-older-generation log moved
  from WARN to DEBUG (routine race); a smoke-cache `stat` failure other than
  ENOENT is logged at WARN instead of swallowed; the misleading per-step
  host-state log was removed (the summary line already reports the real
  version); `decisionsCacheKey` encodes fields through a
  `satisfies Record<keyof DecisionsScope, …>` codec map.

## Prevention

- **Gate on the command CI runs.** Before ticking a "full gates" task, compare
  the plan's list with `.github/workflows/ci.yml`. For docs that is
  `validate:docs:all`, which includes the M51 coverage check.
- **After a status flip, grep, don't recall.** Grep every status form
  (`Designed`, `currently N`, `(Designed — ADR-x)`), every anchor of a renamed
  heading, and every sentence of the form "on every call/check/request" that
  the change made untrue. A new `details.reason` needs a row in
  `error-taxonomy.md`.
- **A declared M51-prefixed id needs an M51 task in the matrix.** Cite the
  owning tasks with a parenthetical note, or keep the requirement under an id
  outside that matrix.
- **Recompute recorded metrics at HEAD after a rebase** and state how they were
  measured.
- **Exempt calls, not files.** A static guard may skip a specific forwarding
  expression; a file-wide "infrastructure" exemption hides every future call
  site in that file.
- **Prove a guard by mutation before trusting it.** Revert the wiring, drop the
  `refresh`, rename the import: the test must go red. Three facts learned the
  hard way in this pass: a mutation pattern that never matches the real string
  yields a false GREEN (`/schema (upgraded|-migrated)/` did not match
  `host-state-schema-migrated`); `mockRestore()` clears `mock.calls`, so read
  the calls first; `run() { "$@" }` with `CI=true pnpm …` exits 127 and the
  gate silently never ran — read every step's rc.
- **Wait for a signal, not a clock**, in tests that drive a worker or a stream:
  `onCapture`, a deferred resolved by the code under test, or a spy on the
  method that issues the statement.
- **Re-derive a review finding in source before fixing it.** Three findings of
  the review that led here were wrong until re-derived: the attention-scan
  sentinel does fire for either table filter (the scan is one `UNION`
  statement naming both tables); TODO bullets were inside the `## TODO`
  section, not under an ADR stub (a `### ADR`-only heading scan missed the
  `##` heading); a same-name re-export is recognized by the scanner (only a
  renamed one escapes).
- **Session environment is not a regression.** In this review shell a listener
  bound to `0.0.0.0` is unreachable over loopback, so every real-supervisor
  fixture fails with "did not answer /health"; judge those lanes by failing
  NAME SETS against the pre-fix baseline.
