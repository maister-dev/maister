# Supervise the agent session observer instead of losing it silently

**Date:** 2026-09-14 22:39 (Europe/Moscow)
**Files:** `web/lib/agents/launch.ts`,
`web/lib/execution-host/{deliverer,index}.ts`,
`web/lib/agents/__tests__/agent-session-supervisor.test.ts`,
`docs/system-analytics/execution-prompt-lifecycle.md`.
**Severity:** high

## Problem

The second live `aif-dev` run (stand, `e5e5a8e2`) lost its `plan_consensus`
node again — this time AFTER both drafters had written their plans. The
`claude-fable` draft child's receipt was clean (`phase=completed`,
`status=succeeded`, `stopReason=end_turn`, `httpStatus=200`, 548 transcript
objects / 2.08 MB), yet the run ended `Crashed` and its coordinator was killed
twelve minutes later as `orchestrator-stuck`, cascading the sibling to
`Abandoned`.

The only trace of the real failure was one line:

```
22:02:04  agent-owned-session-observing        observer started
22:02:31  agent session consumer failed        errorType=MaisterError   ← 27 s in
22:04/07/09/11  reconcile: refusing reattach for non-flow run — skipping
22:12:51  session.prompt → superseded
22:13:22  agent-finalization outcome=Crashed
22:13:25  consensus runner draft session started   ← 3 s AFTER its own crash
```

`errorType` was the whole diagnosis: no code, no message, no details, nothing in
`execution_commands.application_error`, no `node_attempts` row for the child, and
no error column on `runs`. The cause was unknowable by construction.

## Root Cause

- `observeOwnedAgentSession` dispatched the observer as a fire-and-forget
  microtask whose catch logged `error.name` and nothing else, with no retry and
  no effect on run state. The canonical session stream is a DURABLE, replayable
  log, and every failure on its path is a transient `MaisterError`:
  `prepareSessionContent` raises `EXECUTOR_UNAVAILABLE`
  (`runtime_object_missing`) when a content-referenced event's runtime object is
  not yet available, and `projectionTransaction` raises `EXECUTOR_UNAVAILABLE`
  (`projection_connection_timeout`) or `ACP_PROTOCOL`
  (`projection_transaction_deadline`) under pool pressure — two draft children
  hydrate every content-referenced event through it. Every OTHER consumer of the
  same events retries: the projector framework allows `MAX_TRANSIENT_ATTEMPTS`
  and then records a poison with reason, type, message and fingerprint. The
  agent observer was the one that died on the first error and said nothing.
- Nothing can replace it. `reconcile` classifies a live-session run as
  `reattach` and then refuses: `refusing reattach for non-flow run — skipping`
  (four times here). So the run held a live session no one read for ten minutes,
  and both terminal statuses it eventually got — the child's
  `agent-session-gone`, the coordinator's `orchestrator-stuck` — named the
  symptom, not the cause.
- `"consensus runner draft session started"` was logged AFTER
  `dispatchStoredAgentTurn`, which awaits the whole turn's application, so the
  marker timestamped the settle and read as a session that began after its own
  run had ended.

## Solution

- `superviseAgentSession` keeps ONE observer on the session for as long as the
  stream can be re-entered: up to `AGENT_CONSUMER_MAX_ATTEMPTS` (10) attempts
  with capped exponential backoff (1 s → 15 s), a window sized to outlast the
  90 s reconcile grace, since nothing else looks at a run whose session is live.
  A fenced stream or the run's abort signal stops it without retry.
- A retry is a RECONNECT, not a restart. `AgentSessionConsumerState` carries
  `lastEventId`, `sawPermissionRequest` and the ADR-165 turn text across
  attempts, and `consumeAgentSession` resumes the stream after the last event it
  finished handling — so no permission HITL row and no input delivery is
  replayed, and the sentinel contract still sees the completing turn's text.
- Every attempt's failure is logged through the house `errorRecord` shape
  (`code`, `message`, `details`) plus attempt number and resume point;
  exhaustion is an ERROR line stating the run has no observer. Both observer
  call sites (owned turn and plain agent session) go through the same path.
- The observer still never terminalizes the run: an owned prompt's outcome
  belongs to its prompt owner and its own retry/poison ledger.
- The draft marker is emitted BEFORE the awaiting dispatch, with a separate
  `consensus runner draft turn settled` line after it.

## Prevention

A fire-and-forget consumer of a durable, replayable stream must be supervised
like every other consumer of those events, and its failure must be reported with
the typed code, message and details — an `error.name` is not a diagnosis. When a
component can be lost with no replacement, the status the system finally writes
names the sweep that noticed, not the failure that happened; check what recovers
a component before accepting that its death is survivable.

## Follow-up (not in this patch)

`reconcile` still has no recovery for a non-flow run whose observer is gone
while its session is live (`refusing reattach for non-flow run`). In-process
retry does not cover web-process death. Closing it needs an in-proc observer
registry (the `hasSyncDriver` precedent) plus a re-observe arm in the sweep's
`reattach` branch — a change to the reconcile decision table, not a bug fix.
