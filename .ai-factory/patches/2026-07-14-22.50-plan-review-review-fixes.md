# Plan-review review safety fixes

**Date:** 2026-07-14 22:50
**Files:** `web/lib/services/hitl.ts`, Plan-review integration and route tests,
`docs/decisions.md`, `docs/system-analytics/social-board.md`
**Severity:** critical

## Problem

The Plan-review response path lacked regressions for approval while a blocking
child was open and for transactional child-card creation/re-entry. A non-final
child response committed its answer before its delivery marker, assignment
completion, audit, and webhook row, which left a crash window and emitted
duplicate events on same-payload retries. Several boundary checks and docs also
lacked coverage or used stale wording.

## Root Cause

The non-final path completed its durable response in one transaction and did
the remaining durable side effects in a second transaction. Creation was only
covered indirectly by schema constraints; service tests seeded already-created
children instead of exercising the creator.

## Solution

The non-final branch now stamps the child, completes its assignment, records
the audit, and writes the redacted webhook outbox event in its response
transaction. The event is conditional on a newly stamped child, so a same
payload retry cannot emit again. Docker-backed tests now cover the parent
approval guard, redacted replay-safe event, rollback and re-entry of parent
plus child creation, the reverse migration constraint, exact envelope
validation, UI assumptions, and the graph-only resume path. ADR-137 wording
now accurately limits optional metadata to outbound webhooks, and the Inbox
projection is marked implemented.

## Prevention

- Keep all durable non-final response effects in the same transaction as the
  response marker.
- Test control-plane safety invariants through the real service and Postgres,
  not only the schema constraint that supports them.
- Assert retry idempotency at the observable outbox boundary.
