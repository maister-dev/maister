# Workspace reconciliation review fixes

## Finding

The lifecycle-state database constraints made a valid claim an atomic tuple:
state, attempt id, operation name, expected run status, and an unexpired lease.
The branch-sync path still wrote only the legacy subset, so its successful and
failure paths could leave a constraint violation rather than a fenced claim.

## Resolution

- Make sync claim acquisition persist the expected `Review` status and expiry.
- Renew the expiry, not only the observability timestamp, from the sync driver
  heartbeat.
- Clear both fields when the fenced claim is released.
- Make lifecycle integration fixtures construct the same complete shape and
  prove recovery of expired sync leases.

## Prevention

When a migration strengthens a multi-column state invariant, enumerate every
writer and every fixture for that state before considering the migration
complete. Run the owning real-Postgres integration suites after the migration;
typechecking alone cannot reveal database check-constraint violations.
