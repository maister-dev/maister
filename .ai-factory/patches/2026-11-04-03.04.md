# Validate strict Flow enforcement before accepting a launch

**Date:** 2026-11-04 03:04
**Files:** `web/lib/flows/enforcement-refusal.ts`, `web/lib/flows/enforcement.ts`, `web/lib/acp-runners/enforcement-preflight.ts`, task launch resolution/options/HTTP, launch controls, EN/RU messages, Web/external OpenAPI contracts and affected browser fixtures
**Severity:** medium

## Problem

Eight browser launch observers still expected the legacy run-creation endpoint,
SSE response or a task's latest Run. Migration exposed a real diagnostic gap:
canonical admission accepted an impossible strict-enforcement request, then
dispatch retained only a generic preparation hold. The request did not execute,
but the user lost the actionable node and capability-class explanation.

## Root Cause

The existing static enforcement authority ran during Run preparation, after
canonical intent acceptance. Preview and acceptance resolved session runners
without invoking that authority. The HTTP safety projection correctly refused
raw error text but lacked a typed alternative carrying safe diagnostic fields.

The actual PostgreSQL/Git HTTP regression returned 202 instead of the expected
400 before implementation: `/private/tmp/maister-enforcement-preflight-red.log`.
Its primary session uses Codex while the refused node's named session resolves
to Claude, so a primary-runner-only check cannot satisfy the assertion.

## Solution

Reuse the existing static check for each compiled node's actual session runner
in preview and acceptance; keep the full dispatch checks. A bounded shared
diagnostic carries node identity, capability class, actual capability agent,
strict intent and available support. HTTP exposes only validated fields; unsafe
identities produce a generic configuration refusal rather than raw content.
Web and external contracts distinguish this strict shape from other errors.
Both launch controls translate the explanation and actionable next step.

Browser observers follow the accepted intent and its exact eventual Run binding.
Capacity tests retain a valid queued receipt with no Run. They never substitute
the latest task Run or manufacture a Run to satisfy an old response assumption.

## Prevention

Check deterministic technical admission before durable acceptance and repeat it
at dispatch. Resolve named and compiler-generated solo sessions individually.
Keep diagnostic projections bounded and typed, with contract validation for
missing fields, controls, oversized IDs, unknown enums and extra source data.
Clear an earlier preview diagnostic when a later generic request fails, and
fence asynchronous preview results by selection and cancellation.

## Validation

Behavioral RED is captured above. The complete coupled real PostgreSQL/Git HTTP
suite passes 15/15 in 4.62 seconds, exit 0, with normal database teardown and no
unhandled errors: `/private/tmp/maister-enforcement-preflight-final-green.log`.
The existing external API suite passes 8/8 in
`/tmp/maister-enforcement-external-green.log`. Named-session diagnostics,
zero-effect rejection, the stronger invalid-manifest boundary, extra-field
redaction and malformed external diagnostic normalization are covered.

Scoped producer/helper/browser-fixture lint, formatting and diff checks pass.
The full Web unit suite passes 885 files / 9233 tests; types, documentation and
Web/external contract checks, including strict-error negative controls, pass.
The eight migrated browser specs and full frozen integration qualification
remain pending; no production, live model or live GitHub operation is claimed.
