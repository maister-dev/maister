# Recheck transient fixture membership without weakening signal authority

**Date:** 2026-11-09 13:16 UTC
**Files:** web/test-support/process-invocation.ts; web/test-support/__tests__/execution-ab-process-cleanup.integration.test.ts; web/test-support/fixtures/process-helper-retirement.c
**Severity:** medium

## Problem

The frozen full integration run passed 6,266 checks but reported one webhook test failure during supervisor shutdown: an invocation group contained a readable but untagged child and the strict signal guard refused. The refusal stack identifies cleanup; it cannot independently establish every preceding business assertion because a finally error can mask an earlier failure.

## Root Cause

A single process snapshot remained authoritative for the shutdown decision even after a short-lived member retired. Actual tagged sysctl children reproduce readable-but-untagged identities on Darwin; a controlled real kernel snapshot reproduces the refusal. The executable of historical child 87207 was not retained, so the controlled reproduction establishes the failure class without identifying that historical command. An unverified member is never permission to signal by ancestry, process group or age.

## Solution

Allow at most three fresh full-group snapshots with ten-millisecond gaps inside a 100-millisecond scheduling window. Every reread must retain the exact original verified leader lifetime, and every actual signal still passes the unchanged strict all-members ownership guard. Persistent foreign members, unavailable reads and changed identities refuse. The existing per-reader ten-second transport timeout is separate; the scheduling window is not a hard wall-clock deadline.

The real-process regression preserves kernel ownership reads and schedules only the exact spawned helper's retirement after its captured PID, parent, group, UID and kernel start are revalidated. Fixture failure cleanup asks the trusted parent to reap its original child handle, attempts independent bounded cleanup stages, retains original failures, and preserves the ledger/root unless quiescence is positively established.

## Prevention

Treat a complete ownership snapshot as a short-lived observation. Retry observation within a documented bound, never broaden authorization or omit an unverified member. Keep positive retirement and persistent foreign/inspection-denial controls together. Failure injection must also verify that its own stopped children and ownership evidence remain recoverable.

The failed full receipt and zero-process/container/root cleanup are retained. A new frozen full integration run remains required; no production runtime or migration changes are made.
