**Severity:** high

## Problem

The Testcontainers consolidation left the E2E wrapper unable to guarantee
pool/container teardown when its parent receives `SIGINT` or `SIGTERM`: the
wrapper had no signal boundary, and a parent termination bypassed its
`finally`. The shared helper also advertised a typed Drizzle client without a
runtime schema, so `db.query` was not available to callers. Its specification,
execution plan, and analytics did not describe cancellation or trace the
implemented acceptance checks. During end-to-end verification, the authenticated
Observatory cost spec was also found routed to the anonymous Playwright project.

## Root cause

The initial implementation concentrated lifecycle ownership inside the normal
return/error path. It did not model the process boundary or require a test that
proved child exit happens before resource teardown. Type-level compatibility
with existing schema-agnostic fixtures was mistaken for runtime schema
configuration. Documentation followed the implementation outline rather than
the full operational state machine.

## Solution

- Install wrapper-owned `SIGINT`/`SIGTERM` handlers before database startup,
  forward the signal to the detached Playwright process group, wait for its
  observed exit, and escalate to `SIGKILL` after a bounded grace period before
  the database `finally` runs.
- Add focused regressions for both signals, interruption during startup,
  preparation failure, teardown ordering, and a real SIGTERM-resistant child.
- Compose a runtime-schema Drizzle client with the legacy schema-agnostic
  handle, then prove `db.query.users` works after real migrations.
- Complete the SDD traceability matrix and test-infrastructure analytics,
  including cancellation states, expected failures, and documentation indexes.
- Route `observatory-cost-breakdown.spec.ts` through the seeded-auth Playwright
  project.

## Prevention

- A wrapper that owns an ephemeral external resource must have a process-signal
  contract, not only a promise `finally`; test that the child has exited before
  resource teardown and include a signal-resistant fixture for escalation.
- When a helper exposes a typed ORM client, prove both compile-time and runtime
  schema access with a real query; a generic-only client is insufficient.
- Treat state/process analytics, acceptance criteria, and execution-plan
  traceability as delivery contracts. Capture failure and cancellation paths,
  not only the happy path.
- Any Playwright spec that requires a session must be explicitly included in
  the authenticated project selector; a successful auth setup alone does not
  authenticate unclassified specs.

## Verification

- `pnpm --filter maister-web typecheck`
- Focused wrapper unit and lifecycle tests
- Shared helper and representative Brain Docker integrations
- Documentation and API-contract validation
- Static ownership scans and `git diff --check`

The focused E2E regression passes through a fresh disposable database. The
complete E2E invocation also released its database and port, but retains
unrelated legacy UI-spec failures; those failures are not evidence against the
test-database lifecycle contract.
