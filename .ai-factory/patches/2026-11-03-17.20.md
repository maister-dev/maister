# Replace unproven engine fixtures with canonical admission

**Date:** 2026-11-03 Europe/Moscow
**Files:** `web/test-support/{launch-engine-response,evaluation-engine-launch,repository-qualification}.ts`; owned launch engine/API/host integration consumers; `web/lib/services/__tests__/runs-launch-branch.test.ts`; removed generic gate/materialize/pin mock suites
**Severity:** high

## Problem

Closing the public generic Flow allocator correctly refuses a new task root without its durable accepted decision. Old technical fixtures still called that allocator with context actor fields and positional fake database results. Keeping those tests green through a mocked admission principal would conceal the authority contract instead of checking it.

## Root Cause

The fixtures treated engine configuration, an authorization callback or internal provenance fields as enough to create a Run. Those are not an opaque admission proof. Their mocks also did not execute SQL predicates: the mocked history tests reported that Done/Abandoned Run-again worked while the actual final task transition rejected both states.

Frozen runner slots initially lost their original resolution tier by being re-resolved as launch overrides, and the earlier preview runner guard dropped actionable slot details. Actual canonical consumer tests exposed those source issues; the source owner restored the accepted tier and shared typed diagnostics. A separate accepted-task-status fence now permits the exact human Run-again decision through binding while continuing to refuse automated terminal-task admission and a later terminalization race.

## Solution

Ordinary technical roots issue and verify actual local project/user tokens, satisfy the current real-Git qualification and explicit auto arm, record acceptance with a fresh task revision/settings token, acquire the durable preparation claim and physical repository fence, and enter the accepted engine. Existing context denials run before effects. Human concurrent controls obtain the real session principal through the existing authentication boundary and SQL grants. Concurrent requests/claims overlap under real Postgres; physical Git effects serialize under their actual repository owner.

Delegated children issue a real orchestrator token, establish the durable execution-child proof and use the delegated source-family constructor. The same operation key binds the proof, constructor and acceptance. Evaluation pin/form/session controls persist actual studies, controlled recipes and batch items, drive the real batch transition and normal evaluation preflight/source acceptance, then bind through the real engine. No generic production bypass or test source kind was added. Temporary repositories, checkouts and captures have owned cleanup roots.

Host pressure now keeps an accepted intent queued without inventing a Pending Run. The actual pressure-clear sweep binds/starts it and exposes the assignment. The old audit callback fault was replaced by a scoped actual PostgreSQL assignment-insert failure, proving that Run/placement rows roll back together. Actual token-audit atomicity remains owned by the dedicated admission/external primary tests.

The approved setup contract differs from the obsolete rollback mock: a completed shared adoption is retained if a later admission gate refuses. A real scheduled-adoption control advances the project to cut2, pauses the task in that adoption transaction, then observes the later refusal with zero Run/intent/worktree and the adopted cut still present. Unknown evaluation form fields are refused by the real preflight before acceptance; declared valid values are then checked in the actual form artifact.

## Prevention

Test a shared admission precondition through the actual source constructor. A typed context actor and a configured Flow are not authority. Preserve real SQL predicates when migrating engine tests: fake databases can miss exactly the commit-time guard being changed. Map each removed assertion by its primary behavior and test name before removing duplicate mock scaffolding. Keep source-specific pins, child proofs, concurrent human decisions, audit atomicity and queued-source acknowledgments on their own real authority paths. Treat an outdated expected contract and a product regression as different outcomes; prove the latter with a valid current fixture before changing runtime code.
