# Scheduled automation lease and aggregate contract hardening

**Date:** 2026-07-16 13:06
**Files:** `web/lib/scheduled-launches/{service,dispatch,queries}.ts`, `web/lib/services/runs.ts`, `web/components/automations/*`, API/docs contracts and focused tests
**Severity:** high

## Problem

An active scheduled launch retained a fixed five-minute claim lease while
`launchRun` could spend longer fetching, creating a worktree, or materializing
capabilities. The stale-dispatch recovery could then reclaim the same intent
and remove its verified clean worktree. The aggregate Automations endpoint also
advertised cursor pagination while the UI discarded its cursor and the server
loaded every source row before slicing.

## Root Cause

The reservation/fence protected individual state updates but did not carry a
liveness signal across the long external launch handoff or fence the Run insert.
The aggregate reader implemented cursor comparison after merging all three
sources, so its bounded API response did not bound query results. Documentation
and OpenAPI were not reconciled with the durable retry outcome returned by the
Run-now route.

## Solution

Added a fenced, non-overlapping one-minute claim heartbeat and a locked
ownership assertion before worktree creation and inside the Run transaction.
The aggregate reader now applies the cursor predicate and `limit + 1` candidate
window to each ordered source before the merge; the panel receives, advances,
and resets the opaque cursor. Cancellation uses the shared portaled confirmation
dialog. Contracts, system analytics, screen documentation, translations, and
focused regression tests now describe and cover the actual behavior.

## Prevention

- A lease around a long external operation needs both renewal and a durable
  fence at the irreversible persistence boundary.
- A cursor contract is incomplete until database predicates, source limits,
  server response, and client continuation are all present.
- Review route-level error behavior against the durable state returned after
  dispatch; do not document an upstream status that the route absorbs.
- Run typecheck, focused interaction tests, contract validation, docs
  validation, and the real-Postgres integration suite when Docker is available.
