# Size-bounded Run transcript navigation and scroll preservation

**Date:** 2026-11-02 18:14 Europe/Moscow
**Severity:** high
**Files:** `web/lib/runs/transcript-page.ts`, `web/lib/runs/transcript-message-content.ts`, transcript page and message attachment routes, canonical transcript projector, Drizzle schema and generated migration `0214`, `web/components/runs/run-transcript-history.tsx`, `web/components/run-transcript/transcript-view.tsx`, EN/RU catalogs, existing peek/migration integration and transcript/child-peek E2E suites, scratch renderer smoke fixture, OpenAPI and existing Run/schema contracts and ERD.

## Problem

Agent activity on full Run pages and child Run peeks could end in dozens of empty “Limited preview” cards. Tool payload fragments appeared as raw JSON. The latest conversation was not initially scrolled into view, and history navigation did not follow actual reading position.

## Root Cause

The shared reader selected up to 100 records, reversed them into chronological order, and spent an estimated 380 KiB budget oldest-first. It emitted every candidate even after its body allocation reached zero. Cursors described candidates rather than size-admitted records. A separate 64 KiB cutoff previewed records that fit the portion. PostgreSQL `left` counted characters while the estimate used bytes. Commit `971bce871` introduced this mechanism; `136212fad` exposed it on full agent and Flow-node panels by routing them through the shared reader.

Each window and preview used a separate renderer, splitting consecutive tool groups. The history flag tracked button clicks instead of scroll position. Keeping only earlier portions evicted later history without a forward pagination path.

Flow-node cursor order also reused `supervisor_event_id`, which is last-mutation evidence. Coalescing a tool result could move an existing record across a loaded boundary. Prompt horizons can legitimately change after late canonical ingest, including an initial `-1` horizon that the old cursor validator rejected. Body-only refresh merging discarded newly ingested records and corrected boundary metadata when the final message ID stayed unchanged.

## Solution

- Admit a contiguous portion in traversal order using serialized UTF-8 content and response-envelope bytes, then present it chronologically. Stop at the budget boundary; only individually oversized records receive valid role-specific previews.
- Bind before/after/window cursors and availability to returned records. Keep nonempty boundary cursors usable for future live rows, including timestamp ties. Resolve memory-pressure anchors inside the current authorized scope.
- Add `first_supervisor_event_id` for stable canonical creation order through additive migration `0214`; preserve last-mutation IDs, external activity semantics and latest-usage selection. Retain the old index and add a creation-order paging index. Resolve cursor record IDs inside the authorized repeatable-read scope so corrected prompt horizons rebase without losing reachable history. Merge late records and fresh boundary metadata across retained windows, with the freshest response winning.
- Download complete oversized records through the same transcript authorization policy, with backpressured database chunks of at most 64 KiB, current-attempt checks, row-version fencing, abort handling and safe attachment headers.
- Use one renderer for retained records and preserve message identity, tool grouping, usage, thoughts and explicit expansion choices. Restore scroll by stable message ID in both document and nested scrollers.
- Share automatic and button navigation, guard concurrent boundaries, preserve displayed content on failures and require explicit retry. Bound retained history in both directions; resume tail following through Jump to latest or actual arrival at the current bottom. Live appending and contiguous catch-up continue while reading earlier messages; only automatic scrolling pauses. Merge small live portions within the existing count/byte bounds, preserving the original first-record cursor, and deduplicate by stable message ID.
- Keep diagnostics at the existing pino route boundary: counts, bytes, scope, timing, availability and typed failure context; no message bodies.

## Prevention

Assert complete forward/backward traversal of seeded IDs, not just one page's count. Measure actual JSON UTF-8 response bytes and include escaped controls, multibyte text, moderate tool results followed by small replies, individual oversized records and timestamp ties. Browser checks must assert the visible message's offset, both scroll owners, failed-load retry, live following and history-reading updates. Re-review size bounds after mutable-row refreshes and preserve the fresher snapshot when overlapping reads return at different times.
