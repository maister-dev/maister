# Preserve intentional UI drafts and batch choices

**Date:** 2026-11-04 14:26
**Files:** web/components/agents/human-assessment-form.tsx; web/components/agents/task-qualification-control.tsx; web/components/agents/agent-retry-batch-control.tsx; their existing DOM tests; owning task qualification and agent activity analytics
**Severity:** medium

## Problem

Closing the optional human assessment discarded unsaved fields and an uncertain
submission. Reopening could create a different body/key while the original write
had possibly committed. Changing the retry runner silently selected previously
deselected and newly eligible rows. Invalid assessment Save left keyboard focus
at the bottom while actionable errors appeared above it.

## Root Cause

The assessment component owned the draft and held request but was unmounted on
close. The opener always fetched a new context. Runner refresh reused the initial
batch-window loader's default-all selection policy. Assessment validation rendered
issues without moving focus to an associated invalid control.

## Solution

Keep the form component mounted across dialog closure and reuse its existing
context on reopen. Confirmed save removes the retained draft; the existing explicit
context reload and uncertain-write guards remain unchanged. Validation focuses
the first marked invalid control within this form, or the form's issue summary.
No draft, evidence, context token or request body is logged in the client.

Runner refresh carries an immutable selection snapshot and intersects it with
fresh eligibility. An empty snapshot stays empty. Initial and new-window previews
still select their eligible rows. The POST uses fresh fingerprints and canonical
launch requests while unresolved keyed writes retain their existing freeze.

Three regression cases failed before the state/selection fix; the added focus
assertion also failed before the focus effect. The two existing DOM suites now
pass 18/18. They cover dirty fields and evidence across Escape/reopen, exact
body/key replay after a lost response and reopen without a new context GET,
invalid-control focus, and an actual accepted batch POST after empty/subset
selection and runner-specific fingerprint refresh. Evidence is retained in
`/private/tmp/maister-ui-draft-selection-{red,green}.log` and
`/private/tmp/maister-assessment-focus-red.log`. Browser qualification remains a
separate frozen lane; these component results do not claim browser execution.
The four coupled authoring, retry, board-launch and task-agent interaction suites
pass 37/37. Web types and scoped ESLint pass without diagnostics; changed files
are formatted and `git diff --check` is clean.

## Prevention

Review dialog lifetime together with the lifetime of dirty and uncertain state.
Closing presentation must not erase an unresolved operation's identity. A refresh
updates available options without expanding the user's explicit choice. Distinguish
an absent selection snapshot from an explicitly empty one, and verify outgoing
requests use the refreshed preview rather than testing checkbox appearance alone.
Validation needs both associated messages and a keyboard path to the first issue.
