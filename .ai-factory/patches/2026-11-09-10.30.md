# Preserve the admitted session credential across graph continuation

**Date:** 2026-11-09 10:30 UTC
**Files:** web/lib/flows/graph/runner-graph.ts; web/lib/flows/runner-agent.ts; web/lib/flows/graph/driver-lifetime.ts; owning graph/orchestrator integration tests
**Severity:** high

## Problem

The real pinned RAH package completed depth-one research, but depth-two execution lost knowledge and delegation access after its graph driver yielded. Safe server logs and token metadata show a replacement credential issued for the same active node attempt, followed by 401 responses from the existing session. The final unconfirmed-session-delete failure obscured this earlier loss of authority.

## Root Cause

Graph materialization issued and rotated a credential before checking for durable prompt reattachment or completed-action replay. The owned-session mechanism correctly reused its canonical create descriptor; the active adapter therefore kept the original secret while the graph retired it. Driver renewal logging also omitted the exception classification, so renewal failure could not be distinguished from lease expiry or a database deadline.

## Solution

Retain current role, capability and source checks on every traversal, but defer credential issuance and MCP injection to the existing new-owned-create payload callback. Canonical create replay and active-prompt reattachment retain their admitted credential. New owned-session identities can rotate normally. Terminal cleanup is required independently of whether the current traversal minted a token. Renewal diagnostics record typed code, reason and safe query diagnostics without SQL parameters or raw exception bodies.

The recursive-loop fixture also used a one-shot direct-launch substitute which converted an explicit no-effect execution-writer refusal into ACP_PROTOCOL. Its bounded retry retains identical input, admits only the existing exact delegation_execution_busy classification, warns safely and propagates all other or exhausted errors. Existing child-count, result and ownership assertions remain the oracle.

## Prevention

Exercise genuine canonical-create replay while a controlled ACP prompt remains active, then verify the original secret still authenticates and terminal cleanup revokes it. A complementary two-node case must demonstrate distinct credentials for genuinely new sessions. Keep historical capability checks separate from current action authority, and avoid introducing another secret store or execution ledger. Record the original failure before disposable resources are cleaned up.

## Verification

The actual PostgreSQL/supervisor replay test is RED with TokenAuthError revoked on the original descriptor secret. The replay suite is GREEN 2/2; the new-session case is GREEN 1/1. Full loop and park consumers pass 27/27 and the loop passes an independent repeat. Two independent adversarial reviews find no actionable defect. Current primary-checkout and complete-regression receipts remain separate from these isolated results. The earlier independently reproduced SQLSTATE `40P01` hazard does not establish the cause of this live driver's renewal failure.
