**Severity:** critical

## Problem

`/aif-review` of the ADR-180 branch (one owner for the permission deadline)
rated it FAIL with every suite green. Six blockers:

1. An answer after the 30 s registry grace got a retryable 503, the sweeper's
   checkpointed arm parked the run — and every retry then answered 503
   "Original permission delivery evidence is not yet complete" until the 24 h
   TTL abandoned it. Reproduced by a throwaway control that extended RED 4b by
   one operator step.
2. Pass 1b selected any `NeedsInput` run with a `checkpointed` incarnation, so a
   sweep tick landing between `markResumed` and the create ack re-parked the
   resume and released its fresh assignment.
3. The race-window arm called the flow resume for every run kind; an agent run
   would fail on the missing `workspaces` row or skip its own claim.
4. The host's parked 410 required `status === "exited"`, which the heartbeat
   sets only after the child exits and drains; an answer inside the
   cancel→exit window got the terminal 410 and failed the run.
5. RED 7 accepted either checkpoint order, and three docs claimed the terminal
   event proves the flow handoff.
6. Contract prose drift (`MAISTER_KEEPALIVE_MINUTES` in the event-plane
   contract, `/respond` arms, the scratch-runs row, the architecture tree) and a
   documented WARN that could never fire (the registry singleton has no logger).

Fixing 3 and choosing to widen the agent path exposed two more: a host park
mints no `session.checkpoint` command, so the agent idle claim waited for one
forever (`checkpoint_not_confirmed`), and the LIVE agent driver applied the
interrupted prompt's terminal before any resume — superseding the turn the
resume needed `dispatched`.

## Root Cause

Each control asserted the state the plan's scenario ended in — "503, then the
next tick parks", "202 resume-in-progress", "boundary: terminal" — and stopped.
The transitions one step past those states were never driven: the operator's
retry, the sweep tick during a resume, the answer during a park's teardown, the
agent kind. Two mechanisms hid it:

- The delivery-intent rule ("a definitive 503 voids the intent, mint a fresh
  input") existed on the live retry only; the idle preflight read the same
  intent and asked for a receipt the host would never write.
- "The session was parked" was proved by a `session.checkpoint` command row in
  three places (agent readiness, the agent completion guard, Pass 1b's
  candidate set), and a host-initiated park has no row. The terminal event was
  accepted as a witness in ONE place (`permissionCheckpointOrder`) and nowhere
  else.

The review's own C5 ("the terminal witness inverts the order") was WRONG: a
probe showed the host commits an interrupted prompt's rejection after the
session's terminal (`after_checkpoint`). Verifying the finding before fixing it
turned a deletion into an assertion.

## Solution

- `isRefusedPermissionDelivery` + `withdrawRefusedPermissionDelivery`
  (`execution-host/permission-delivery.ts`) at the choke point; the live retry,
  the node and gate resume claims, `prepareFlowPermissionResult`, the agent live
  retry and the agent readiness all use it. RED 4b retries after the park and
  waits for `respondedAt`.
- Pass 1b: `incarnation.execution_assignment_id = runs.execution_assignment_id`,
  `ORDER BY runs.id`. RED 12 seeds the in-flight window.
- `hitl.ts`: the agent idle branch became `runAgentIdleResume`; both resume
  sites call `runIdleResumeForKind`. RED 13 drives an agent through the window.
- Agent widening: `readCheckpointSource` takes the terminal witness when no
  checkpoint command exists; an `alreadyCheckpointed: true` acknowledgement
  yields to the session's checkpoint terminal in `permissionCheckpointOrder`
  (the first cut treated it as no witness at all and broke the agent
  completed-original handoff for a session that ended on its own — the second
  cut keeps it as the fallback position); `checkpointCommandId` is nullable;
  `requireAgentPermissionCompletion` defers on a `checkpointed` incarnation so
  the live driver does not supersede the turn. RED 14 parks an agent through the
  host cap and resumes it.
- `/input`: wait for the exit (kill grace) when the entry is parking, then the
  checkpointed 410; a park that outlasts the grace answers a retryable 503. Two
  in-process controls use a parkable fake child and poll `listenerCount("exit")`
  to prove the route was blocked inside the window before releasing it. Both
  fail against the unfixed route.
- RED 7 asserts `after_checkpoint` with the real signature; RED 4a/8 wait for
  `respondedAt`; RED 5 dropped; RED 1/3 add a positive over the whole log
  (polled — the log line lands after the terminal reaches the stream); RED 11
  pins the boot WARN. `bootHost` installs one cap handler over every booted
  registry. Docs and contracts say what the code does. A first draft recorded a
  "delivered-but-unstamped input under a host park" residual as a follow-up;
  re-derivation showed it unreachable for a single-permission prompt (an
  acknowledged input has no open deferred for the cap to fire on), so ADR-180
  states that instead of deferring work.

## Prevention

- For every control whose final assertion is a parked / queued / retryable
  state, drive the operator's next step in a throwaway control before rating
  the branch. Green suites certify the story, not the state after it.
- When a proof is widened ("the terminal event is also a witness"), grep every
  OTHER place that proves the same fact by the old evidence
  (`rg "session.checkpoint"` found the agent readiness, the completion guard and
  the sweeper) — a witness accepted in one reader and refused in three is a
  dead end, not a widening.
- A rule that names a failure class ("a definitive 503 voids the intent") lives
  at the choke point every reader funnels through, never inline in one caller.
- Verify a review finding's DIRECTION before fixing it; a 20 s probe refuted the
  inversion claim and kept a correct branch.
- A live driver is part of the system under test: a control that kills the
  driver before the park (as the existing agent checkpoint control does) cannot
  see what the driver does to the turn when it survives.
