# Preserve accepted child work before a Run is bound

**Date:** 2026-11-04 04:03
**Files:** web/lib/orchestrator/child-obligations.ts; web/lib/orchestrator/child-launch-context.ts; web/lib/flows/graph/{runner-graph,coordinator-wake,continuation-worker}.ts; web/lib/flows/runner-agent.ts; web/lib/runs/{recover,state-transitions}.ts; web/lib/reconcile.ts; web/lib/domain-events/orchestrator-resume.ts; web/lib/tasks/launch-dispatch.ts; web/lib/execution-host/ledger.ts; web/lib/db/migrations/0227_queued_child_obligations.sql
**Severity:** high

## Problem

A successful delegated request can durably exist before it has a Run. Counting
only child Runs let a clean orchestrator turn finish in Review and invalidate
the accepted child's parent authority. A refused expired preparation also stayed
in preparing because the pre-claim refusal helper only held queued rows.

## Root Cause

The asynchronous admission contract changed the first durable execution object
from a Run to an intent, while parent completion, wake, recovery and reconcile
still used Run-only counters. The preliminary completion count also did not
serialize with a later accepted delegation. Unbound failure has no child Run
settlement event, and live fanout accounting answers a different question from
parent completion. Expired preparation was absent from the refusal transition.

## Solution

Use one indexed completion-obligation predicate for accepted never-bound child
requests and actual Runs, without changing live fanout limits. Serialize every
orchestrator node-closing transaction with acceptance on the parent Run; retire
delegation credentials only after the final zero-obligation check. Keep queued,
preparing and held requests visible to wait/recovery readers. Discover unobserved
failed/cancelled receipts through existing launch events and continuation work.

Freeze bounded typed child receipts with the actual owned prompt and its request
digest. A successful applied owner can acknowledge only that original structured
witness, never newly read context or marker-like prose. Observation is metadata:
it neither advances the outcome version nor emits another launch event. Preserve
active preparation leases; a rejected expired never-bound preparation becomes
held with its original reason, identity and pending cleanup disposition.

## Prevention

Trace accepted work through all completion and recovery readers whenever the
admission object changes. Do not equate queued obligations with live capacity or
weaken parent authority to rescue work after premature completion. Check every
node-closing branch, not just ordinary success. Test real parent row contention,
the original owned prompt across driver restart, terminal outcomes while siblings
remain queued, and valid versus expired leases. Test fixtures must canonicalize
temporary paths and clean managed checkouts before their parent repositories.
