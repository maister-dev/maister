# Auto-promotion external-check reader used any-ever-passed instead of latest-live gate status

**Date:** 2026-07-03 16.40
**Files:** web/lib/auto-promotion/readers.ts,
web/lib/auto-promotion/__tests__/readers.integration.test.ts
**Severity:** high

## Problem

The ADR-126 auto-promotion `externalCheck` reader decided a lane's
`requireExternalCheckId` by selecting EVERY historical `gate_results` row for the
run/gate and returning `passed` if ANY row was ever `passed`/`overridden`. So a
stale `passed` from a superseded node attempt could satisfy the lane's CI gate
even after a newer `pending`/`failed`/`stale` report on the LIVE attempt — and
because a lane can require an ADVISORY external check (which `readinessGreen()`
doesn't gate), the sweep could auto-promote over failing required evidence.
Surfaced by a Codex adversarial review; the existing reader tests only covered
no-row / one-passed-row / absent-declaration / malformed-manifest, so the
stale-pass regression was uncovered.

## Root Cause

The reader reimplemented external-check evaluation with `rows.some(passed)`
instead of the live/latest-per-gate semantics that the rest of the readiness
subsystem (`evidence-readiness.ts` via `readiness-core.ts`) already uses. The
`gate_results` ledger is append-only across attempts (rework appends fresh rows;
supersede-on-new-commit re-stales prior `passed` rows), so "any row ever passed"
is the wrong reduction — only the newest report on the LIVE (latest-attempt)
lineage governs. This was a known residual flagged (and deliberately deferred as
"out of scope, mention don't fix") during the previous fix round; the review
escalated it, confirming that a known correctness gap on an auto-merge path
should not be deferred.

## Solution

Rewrote `externalCheck` to share `readiness-core`'s single-source-of-truth
classifier instead of a bespoke reduction:
- `getNodeAttemptsForRun` + `latestAttemptIdsByNode` → the set of live
  (latest-attempt-per-node) attempt ids;
- select the run's external_check rows for the gate, keep only those on a live
  attempt, then `collapseLatestExternalPerGate` → the single newest report;
- `isExternalGateReady(latest.status)` (the passed/overridden allow-list) → the
  verdict; no live row ⇒ `declared_not_passed`.

The `not_declared` compiled-manifest declaration lookup (prior round) is
unchanged. Added a regression test: an older `passed` attempt + a newer LIVE
`pending` attempt ⇒ `declared_not_passed` (was wrongly `passed`).

## Prevention

- **When a subsystem already owns a classifier, reuse it — don't reimplement a
  reduction over the same append-only ledger.** `gate_results` is append-only
  across attempts; any consumer that reduces it MUST apply the shared
  live-attempt filter + latest-per-gate collapse (`readiness-core`), or it will
  read stale/superseded evidence. Grep for `gate_results` consumers when adding a
  new one and route them through the SSOT helpers.
- **`some(passed)` / any-ever-true over a temporal, append-only table is almost
  always wrong** — the latest live record governs, not the historical max.
- **Don't defer a known correctness gap on an auto-merge / promotion path.** A
  residual noted as "out of scope, mention don't fix" in one round is still a
  shippable defect; if it gates an irreversible action, fix it in the same pass.
- **Test the temporal dimension:** a gate/evidence reader needs a case with an
  old-good + newer-bad record on a fresh attempt, not just single-row presence.
