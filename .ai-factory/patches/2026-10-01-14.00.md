# Match the isolation fixture to the production build

**Date:** 2026-10-01
**Files:** `web/test-support/real-web.ts`, native process inspection and its existing O-identity control
**Severity:** high

## Problem and cause

Hosted run 36858618377 at `1ef389077` exhausted the V8 heap repeatedly
during the isolation fixture's production builds and timed out without a
complete isolation reporter. The fixture forced Webpack even though the
package and Docker production build use Next's default Turbopack bundler and
configured aliases. A cold local Webpack build with a 2048 MiB V8 heap
reproduced the OOM (exit 134). Enabling Webpack workers, its memory optimization,
or mirroring the lowlight alias did not resolve it; those experiments were
removed.

## Solution

Remove only the forced bundler argument. Build registration, detached group,
watchdog, invocation stamp, verified artifact handle and reuse checks remain
unchanged. Installed Next uses a worker thread for Turbopack compilation,
within the registered process, and awaits its shutdown.

The hosted logs independently contain failures to inspect still-live fixture
processes. The native reader now records fixed PID/stage/result/expected/errno
fields. The TypeScript reader retains bounded stderr on successful omissions
and failed invocations. No argv/environment bytes are logged. Ownership and
cleanup refusal rules are unchanged. This is diagnostic coverage, not proof
that the hosted inspection failure is fixed.

## Verification and limits

- Cold build RED: `/private/tmp/s52-build-2048-baseline.log`, exit 134,
  30.44 seconds. Same 2048 MiB V8 cap with the production bundler GREEN:
  `/private/tmp/s52-build-2048-production.log`, exit 0, 14.38 seconds.
- Peak successful-build RSS is 4,701,356,032 bytes (about 4.38 GiB), including
  native allocations outside V8. This is not a 2 GiB total-memory claim.
  The build emitted 75 NFT tracing warnings; compilation alone does not
  establish production boot or isolation acceptance.
- The real sandbox-denial O-identity case fails its diagnostic assertion
  with the old C reader (`/private/tmp/s52-inspection-red.json`) and passes
  with the new one (`/private/tmp/s52-inspection-green.json`). Existing
  ownership, argv-decoy, foreign-invocation and child-survival assertions
  remain intact. These focused reports do not qualify the complete slice.
- Full production isolation GREEN on local Darwin ARM64 / Node 24.15.0:
  50/50 in seven suites, no skips, accepted by the unchanged
  `validateLaneReport` including every required case name. Report:
  `/private/tmp/s52-fix-isolation-evidence/maister-ab-isolation-ithU4W/vitest.json`.
  Fresh owned build: 59.292 seconds; Vitest: 905.87 seconds; complete lane:
  907.263 seconds including 0.703 seconds cleanup, zero leaks. This run used
  the same explicit 2048 MiB V8 cap. Separate preflight passes 1/1 in 7.478
  seconds including cleanup (`maister-ab-isolation-IVZZlV/vitest.json` in the
  same evidence directory). The production isolation and restart controls
  therefore cover the built server despite the NFT warnings.

## Prevention

Keep the production fixture's bundler aligned with the shipped build. Measure
V8 and native memory separately. Retain syscall evidence without weakening
process identity checks. Only the complete hosted report and timing qualify
S5.2; local ARM build success cannot establish the Intel job budget.
