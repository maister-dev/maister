# Elapsed application wait must not authorize failure finalization

**Date:** 2026-11-02 17:15
**Files:** web/lib/execution-host/{prompt-owner-application,prompt-owner-errors}.ts; web/lib/execution-host/__tests__/prompt-application-recovery.integration.test.ts; web/lib/agents/__tests__/application-quiescence.integration.test.ts
**Severity:** high

## Problem

A retry deadline introduced while fixing agent slot starvation treated an aged
teardown/finalization deferral as exhausted result application. New incident
evidence showed Case 2 settling without intervention after approximately 6m33s,
with zero application failures. The historical lifecycle-projection time is
unknown; event time and accepted ingest do not establish it.

## Root Cause

The engine used elapsed time as failure evidence. An aged Deferred could invoke
safe-failure preparation and poison a healthy transient wait. If canonical
readiness returned inside that preparation, it could instead commit Failed even
though the original result remained valid. Preparation timeouts had the same
incorrect failure-budget classification. Transient blockers during genuine
failure recovery also went directly to poison.

## Solution

Keep the bounded per-claim preparation deadline, but release the claim and record
stalled/retry diagnostics without counting Deferred or timeout as a result
failure. Retry the original adapter. Only genuine invariant/exhausted
nontransient failures may select failure finalization. Transient recovery
blockers retain original and recovery diagnostics and retry without holding the
claim indefinitely. Nontransient contract violations retain explicit operator
recovery.

## Prevention

Treat a timeout as a liveness observation, not proof of irrecoverability. Test
readiness arriving inside recovery as well as before the next attempt. The
real-PostgreSQL/fake-host regression persists a 6m33s deferral, releases canonical
exit as original preparation defers, then verifies original Done/result, one
DELETE, one publication, no prompt replay and no Failed event. Genuine failure
and queue/cap regressions remain separate.

Do not attribute a delay to projector failure from a backdated ended_at or a
later healthy cursor. Non-exhausted busy reads and repeated DELETEs establish
observations, not the delay's cause. Already-applied commands need no rearm.
