# Evaluation Lab remediation delta: interrupted-agent work audit + 0111 rebase enum regression

**Severity:** critical

## Problem

Two intertwined problems closed in one pass:
1. A background agent executing the Evaluation Lab review-remediation FIX_PLAN was killed by the owner mid-task, leaving an 82-file uncommitted delta of unknown state on `feature/evaluation-lab`.
2. Buried in that branch, committed migration `0111_evaluation_verdict_activity.sql` re-created the `task_activity` event-kind CHECK **without `run_pr_merged`** — the value main's `0105_pr_state_tracking.sql` had added. A fresh `db:migrate` would produce a DB that rejects every `pr_state_scan` merge-activity insert (23514), and drizzle-kit would never generate a repair because schema.ts and the snapshot already carried the correct 12-value set.

## Root Cause

1. **Interrupted ≠ incomplete.** The kill signal said nothing about progress. A dedicated audit (full-diff read, interruption markers, `tsc` on both packages, 92 integration tests on real PG) proved the delta was substantively COMPLETE — only cosmetics remained (2 prettier warnings, stale `mcp/dist`, one redundant cast). Discarding or "finishing" it blind would have destroyed or duplicated verified work.
2. **The 0111 regression is the renumber-onto-main enum class:** the migration was authored against a base where 0105 didn't exist; the rebase/renumber pass bumped numbers but never re-merged main's additions into a re-created CHECK constraint. A DROP+re-CREATE of a shared constraint silently reverts sibling-branch additions, and snapshot/schema correctness *masks* it from every drizzle tool.

## Solution

Audited the delta (verdict: keep all slices), finished the cosmetics (scoped `eslint --fix` on 2 files, `pnpm --filter @maister/mcp build`, typed `createStudy` return `{ id: string } & Record<string, unknown>` and dropped both `as string` casts), ran the close-out battery (typecheck, validate:docs, validate:contracts, `git diff --check` — all green), committed as ONE commit `87dd58c7d`, deleted FIX_PLAN.md. The delta itself already restored `run_pr_merged` in 0111 and amended unapplied 0109/0112 in place (owner-approved premise: migrations 0107–0114 applied nowhere durable — any dev DB that ran the originals must be reset).

## Prevention

- Before discarding or redoing a killed agent's work, run a structured audit: full diff read → interruption markers (half-migrated call sites, unused imports) → typecheck → the real test suite. Verdict per slice (keep / finish / discard), never whole-hog.
- Any migration that DROP+re-CREATEs a CHECK/enum on a **shared** table must be re-derived from schema.ts at rebase time, not carried verbatim. Grep every re-created constraint's value list against main's newest migration touching the same constraint.
- `mcp/src` edits are inert until `pnpm --filter @maister/mcp build` — the facade runs `mcp/dist/main.js`. Check dist mtime vs src mtime.
- In-place amendment of migration SQL is safe ONLY under a recorded "applied nowhere durable" premise; record it in the plan and re-confirm with the owner before merge.
