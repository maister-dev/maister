# Protect scheduled input at database failure boundaries and wrap history text

**Date:** 2026-11-02 09:13 UTC
**Files:** web/lib/db/pg-error.ts; web/lib/services/runs.ts; web/lib/agents/launch.ts; web/lib/flows/runner-agent.ts; web/lib/flows/graph/prompt-record.ts; web/components/agents/scheduled-request-evidence.tsx; owning integration/E2E tests; docs/api/web.openapi.yaml
**Severity:** high

## Problem

Request-bearing Flow INSERT failures logged Drizzle query parameters. Standalone failures could propagate the same text into HTTP/HITL diagnostics. Best-effort Flow prompt projections and consensus draft failure logging shared the exposure. Opening a valid 8000-code-point request containing a long token expanded the history table to approximately 67 thousand pixels. API status descriptions still called the shipped contracts Designed.

## Root Cause

DrizzleQueryError embeds query parameters in its message and retains the driver cause. Sanitizing only the outer cron/settings logger misses inner loggers and downstream persistence of error messages. The previous privacy test substituted the launcher instead of failing its actual database write. CSS break-word wrapping does not reduce a table cell's intrinsic minimum width; the browser journey exercised only short accepted requests.

## Solution

Project safe error type, SQLSTATE and constraint through the existing Postgres error helper. At standalone/Flow insert and Flow dispatch boundaries replace Drizzle query errors with content-free CRASH errors, without retaining a raw cause. Preserve non-query error identity and existing cleanup, fencing and best-effort semantics. Use safe diagnostics for both Flow prompt projections and consensus draft failures. Apply overflow-wrap:anywhere to the shared history/details disclosure and reconcile the API status labels.

## Prevention

- Inject real Postgres failures into both launchers, transcript/resolved-prompt projections and owned-command persistence; assert safe diagnostics and unchanged rollback/dispatch behavior.
- Keep the single EN/RU browser journey and use a valid maximum-length request with an unbroken token; assert the opened table fits its container.
- Mutation-check the owned-command redaction so a status-only assertion cannot hide disclosure.
- Sweep command: `rg -n 'catch|\.message|log\.(warn|error)' web/lib/agents/launch.ts web/lib/services/runs.ts web/lib/flows/runner-agent.ts web/lib/flows/graph/prompt-record.ts`.
- Reachable classification: fixed run INSERT propagation (both launchers), Flow dispatch propagation, transcript/resolved-prompt loggers and consensus draft logger. Already safe: cron/admin/retry diagnostics and the main standalone spawn/prompt catch. Excluded: worktree-only cleanup failures whose inputs contain no request text. API/HITL callers receive the sanitized launch failure through the shared boundary.
