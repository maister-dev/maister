# Adversarial pass on agent memory: an asymmetric CAS, a read gate below its own data class, and an unframed self-authored prompt

**Severity:** high

## Problem

A Codex adversarial pass — run AFTER a full `/aif-review` + fix cycle had already
closed 19 findings — returned four more, three of them real:

1. The owner memory `GET` authorized with `readBoard` (viewer), while ADR-053
   deliberately keeps git-tracked file browsing at `readRepoFiles` (member). The
   agent writes this file *with repo access*, so it can hold copied or
   summarized source: the route was a side channel around a boundary the product
   maintains everywhere else. The previous round had not merely missed it — it
   had **pinned the weaker gate in a test**, with a comment explaining that a
   viewer still sees it.
2. `DELETE` was a blind unlink while `PUT` was a CAS. An agent write landing
   while the operator had the drawer open would be destroyed by a `204` with no
   conflict signal.
3. `memoryBlock` trimmed the injected text while the snapshot and hash used the
   untrimmed file bytes, so for any file ending in a newline —
   i.e. normal markdown — `runs.agent_memory_hash` described bytes the agent
   never saw.
4. (Design challenge, not a defect) memory is agent-authored free text replayed
   as prompt context on every later run: a durable self-influence channel.

## Root Cause

**The read gate.** The write side got all the attention because it is the
side that mutates. `readBoard` was picked as "the read bar" without asking what
CLASS of data the file holds — and the answer is "whatever an agent with repo
access chose to write there", which is the same class ADR-053 gates at member.
The test then froze the wrong answer, which is worse than not testing it: a
reviewer reading that comment sees a decision, not an oversight.

**The delete.** I had explicitly considered CAS-on-delete in the prior round and
recorded it as a deliberate non-goal, reasoning "explicit, confirmed, admin-only
action, and the documented contract is idempotency". That reasoning was wrong on
its own terms: D18 exists precisely because a *blind human Save* must not clobber
a concurrent agent write, and a blind human Clear destroys strictly more. I had
also assumed CAS and idempotency were in tension; they are not —
`ifHash: null` matching an absent file IS the idempotent case.

**The trim.** Cosmetic normalization applied at one of three points that were
supposed to describe the same bytes. Nobody trims "the thing being hashed"; the
trim lived in the prompt builder, far from the hashing, and each looked correct
alone.

## Solution

- `GET` now requires `readRepoFiles`; the test that pinned viewer→200 is
  inverted, and a companion case proves a member reads and a viewer cannot. The
  viewer mock was ALSO wrong (it refused only `editSettings`, which is not a
  viewer) and now refuses both bars.
- `clearAgentMemoryCas` mirrors `writeAgentMemoryCas`: same advisory lock, same
  required `ifHash`, `409` with the current content on mismatch. `DELETE` takes a
  JSON body, following the existing `studio/local-packages/[id]/files`
  precedent. The drawer sends the hash it loaded.
- `memoryBlock` no longer trims; the stored bytes are injected verbatim so
  prompt, snapshot and hash describe one thing.
- For (4), the design stands — the alternatives remove the unattended cross-run
  loop the feature exists for — but the block is now framed explicitly as
  untrusted self-authored DATA between `BEGIN/END AGENT MEMORY` markers, and
  ADR-152 D29 records the accepted residual risk instead of leaving it implicit.

## Prevention

- **Pick a read gate from the data's class, not the route's neighbourhood.** Ask
  "what is the most sensitive thing that can end up in this response, and who
  else can already see that?" A file an agent writes inherits the sensitivity of
  everything the agent can read.
- **A test that pins a questionable behavior is worse than no test.** When
  writing an assertion whose comment has to *explain why the weak thing is
  fine*, that is the moment to question the behavior instead of freezing it.
- **Symmetry check on every mutating pair.** If save is guarded and delete is
  not, articulate why deleting is safer than overwriting. It usually isn't.
- **"Deliberate non-goal" from a prior round is not evidence.** Re-derive it
  when challenged; mine survived one review and collapsed on the first sentence
  of scrutiny.
- **When N artifacts claim to describe the same bytes, normalize once at the
  source or not at all.** Any per-consumer tidying breaks the equality silently.
- **Assert invariants for BOTH orderings of a race.** My own new clear-vs-write
  test asserted the ordering that wins on an idle machine and failed under
  full-suite load — the same class of accidental-scheduling test the previous
  patch warned about, reproduced by the person who wrote that warning.
