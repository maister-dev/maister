# Native completion examples must use the actual output transport

**Date:** 2026-11-10
**Files:** `web/lib/run-results/findings-prompt.ts`, `web/lib/agents/__tests__/launch.test.ts`
**Severity:** medium

## Problem

Actual GLM-5.3 depth-two researchers returned schema-valid findings using ordinary JSON fences or placing `maister:output` on a separate body line. Their successful prompt commands therefore correctly produced `result_missing`, failing required-child qualification.

## Root Cause

The shared completion instructions described the transport in prose but demonstrated only bare JSON. Copying the example did not produce an executable native completion. Diagnostic parsing of model text is separate from canonical result acceptance.

## Solution

Show the existing safe example inside the literal canonical fence and specify that its opening marker belongs on the same line. Strengthen the existing launch case to pass the delivered example through the production sentinel extractor and native schema. Keep the extractor, evidence schema, permissions, budgets and acceptance checks unchanged. Existing structured result diagnostics retain the failure cause.

## Prevention

Validate examples through the actual receiving transport and schema, including their surrounding syntax. A shape-valid JSON object alone does not prove that the execution owner can publish it. Keep prompt bytes separate from assistant output so an example cannot become an execution receipt.

The existing case reproduced RED (`absent`), then all ten launch checks passed. The complete web unit suite passed 9,312 checks across 891 files; types, lint and independent review passed.
