# A/B CI pre-push review corrections

**Date:** 2026-09-29 11:57
**Files:** `.github/workflows/ci.yml`, `scripts/run-stage-ab-tests.mjs`, `scripts/run-stage-ab-tests.test.mjs`, `scripts/isolation-ci-workflow.test.mjs`, CI plan and operator docs
**Severity:** medium

## Problem

The isolation suite's 2370-second TERM budget plus 30-second forced termination could consume its entire 40-minute step, leaving no time for shell cleanup. The final cleanup step wrote timing before installing its exit trap, so a timing-file failure could skip deletion of the job-owned Colima profile. A shard-validation test also hard-coded an invalid denominator that would become valid as the manifest grew.

## Root Cause

The deadline accounted for process termination but not the shell's completion, and cleanup treated diagnostic timing as a prerequisite for deleting the runtime. The test assumed today's suite count was permanent. Rebase provenance and CI ownership descriptions had not been updated after the branch moved to a newer master.

## Solution

Reserved 30 seconds each for forced termination and shell completion, installed the cleanup trap before fallible work, and preserved deletion failures even when the timing write also fails. A smoke test executes the workflow's cleanup shell for timing-write and deletion failures. The invalid shard denominator now derives from the manifest length. The plan records the old-to-new commit mapping while preserving the original test SHA, and the docs describe the actual hosted jobs and shard CLI.

## Prevention

- Account for termination, shell completion, cleanup and artifact upload separately when setting hosted deadlines.
- Register cleanup before diagnostic writes and test the actual workflow shell's failure paths.
- Derive invalid boundary cases from the current manifest, and keep evidence tied to the exact tested commit.
