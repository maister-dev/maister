# M43 review remediation: typed graph boundaries, terminal cut-over, and retry closure

**Date:** 2026-07-11 22:35
**Severity:** critical

## Problem

The graph-only/Postgres cut-over left several stored JSONB read paths able to
cast a legacy `steps[]` manifest to `FlowYamlV1` and call `compileManifest`.
That caused an untyped `TypeError` before the D2 run-detail failure banner could
render, and could abort background work. The graph-only boundary also conflated
valid graph shape with host-engine executability, which incorrectly refused
future-engine graph drafts at intake.

The D2 migration terminalized legacy runs but did not close stale C2 queue
claims. Scheduler paths could then either keep a task permanently claimed or
relaunch a known cut-over failure; schedules would repeatedly fire an
incompatible Flow. The UI and OpenAPI contract did not consistently expose the
typed incompatibility reason or disable actions that could not succeed.

## Root Cause

1. **Stored JSON was trusted at compilation sites.** TypeScript casts erased
   the distinction between an authored/in-memory manifest and historical JSONB.
   Several consumers duplicated partial parser logic instead of using one
   stored-manifest authority.
2. **Shape validation and execution validation were coupled.** A graph with a
   future engine range is structurally valid to author or display, but cannot be
   executed by the current host. Treating both cases as one parser result made
   the contract inconsistent.
3. **D2 was modeled as an ordinary failed run by automatic admission.** The
   queue did not recognize its own terminal migration event and therefore had no
   explicit retry boundary or event-bounded claim cleanup.
4. **API/UI/docs were maintained as parallel interpretations.** The locked
   OpenAPI schemas, interactive controls, and documented migration semantics
   lagged the implementation.

## Solution

- Added a single typed manifest boundary with separate shape-only and
  executable-stored classifiers. Every stored runtime/read surface now enters
  through it; pinned revisions remain authoritative over the mutable Flow cache.
- Made incompatible historical run reads degrade to typed states, not crashes;
  D2 history remains visible while resume/promotion stays unavailable.
- Added migration 0094 for the exact stale C2-claim predicate, D2 terminal hold
  plus fresh re-triage semantics, and an `incompatible_disabled` schedule
  outcome that disables a non-executable recurring Flow.
- Restored completed-resume graph finish semantics (gates, artifacts, and
  decide routing) while avoiding a second ACP action.
- Brought response schemas, errors, board/Studio affordances, accessibility
  focus behavior, analytics, ADRs, deployment guidance, and current docs into
  the same contract; added focused unit/integration/E2E coverage at the behavior
  boundaries.

## Prevention

- **No stored manifest may reach `compileManifest` through a type cast.** Use
  the shared classifier and return a typed `MaisterError` or read-model branch.
- **Preserve authority order.** A pinned `flow_revisions.manifest` is immutable
  run evidence; never pre-parse or fall back to the mutable Flow cache first.
- **Keep shape and execution compatibility separate.** Intake/UI validation may
  accept a well-formed future-engine graph; only execution requires the host
  compatibility check.
- **Treat irreversible migration failures as a distinct state machine event.**
  Retry code must inspect the typed event and use a CAS over the current enqueue
  intent; cleanup SQL must be idempotent and bounded by the event timestamp.
- **Make contract evidence executable.** Semantic OpenAPI checks, migration
  idempotency/pinned-authority tests, consumer suppression tests, DOM disabled
  and focus tests, and the D2 E2E fixture own the regression cases.
