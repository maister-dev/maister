## Root cause

1. Draft preparation performs immutable object-content GETs without the admission retry already used by session hydration. Under the real two-read cap, S2.8 sees HTTP 409 `command_in_progress` before its expected `agent_variant_not_implemented` decision. Whole-span wrapping also multiplies a nested read budget.
2. Closed ACP transport can reject the prompt before session terminal publication purges pending permissions. Their asynchronous continuations have not yet recorded `required_output_incomplete` / `producer_permission_failed`, so G0iii-b observes a null reason. A timed delay would not establish the ordering.
3. Turbopack worker threads inherit the watchdog preload and share PID/kernel birth. Their independent cumulative counters can conflict when grouped only by process. Older ambiguous rows do not establish per-stream totals or removable lane cost.

## Solution and contract audit

The shared immutable content opener retries only typed `command_in_progress`: five attempts and abortable 100/200/300/400ms backoff inside the existing deadline, with structured object/event-or-command warnings and the last typed error. Session hydration and command-output reads use it; redundant whole-span retries are removed. The exhausted host-span busy verdict remains. POST prompt admission, public binary/range downloads, authentication, metadata, size, SHA, UTF-8 and shape verification retain their existing paths. The log family is now `runtime-object-content-read-busy` under `runtime-object-content`; eventId/objectId remain, and commandId provides prompt context.

The bounded stream tracks its existing maximum 32 permission continuations. After real output drain and synchronous terminal purge, heartbeat awaits those continuations before releasing `outputTerminal`. Prompt failure then rederives fence→pressure→producer precedence from that causal barrier, preserving original cause, intentional shutdown guards, kill grace and crash-before-prompt-terminal order. No new timer or deadline is introduced.

Watchdog records add only `threadId`/`isMainThread`; all watchers, fresh authority checks, 500ms cadence, signals and refusal behavior remain. The real module Worker control proves same process/kernel identity with distinct thread streams. Classic eval does not execute the import preload and is not used as worker proof.

Existing [GET409 contract](../../docs/api/supervisor.openapi.yaml), [ADR-177](../../docs/decisions/adr-177.md) and [event-plane contract](../../docs/system-analytics/execution-event-plane.md) govern these corrections.
