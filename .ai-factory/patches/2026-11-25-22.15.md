## Problem

Adversarial branch review of `fix_supervisor_fsync_amplification` surfaced three merge-blocking runtime/parity defects plus three high-value hardening gaps:

1. **Supervisor non-text slice exhaustion & mid-slice UTF-8 error strand**: `scanCompleteLineSlice` batched up to 16 arbitrary lines from one `<= 64 KiB` stdout chunk while `producerPressure.beforeFrame` reserved only `frameCount * 2 + 2` rows (capped at 34). A single chunk containing >= 10 non-text frames (up to `FRAME_EVENT_ROWS = 4` events each) exhausted `active_runtime_event_frames.remaining_rows` in `spendEventCapacity`, crashing the live ACP session with `HostRuntimeEventError("event_outbox_wallet_exhausted")`. Additionally, a mid-slice UTF-8 error skipped `frameSliceEnd` and released the frame reservation while valid prior frames stayed unflushed in `pendingTextFrames`.
2. **Transcript batch timeout/deadlock swallowing**: `canonicalTranscriptProjector.projectBatch` only rethrew `MaisterError` with `code === "EXECUTOR_UNAVAILABLE"`, missing `deadlineError()` (whose code is `"ACP_PROTOCOL"` with `details.reason = "projection_transaction_deadline"`) and PostgreSQL `57014`/`55P03`/`40P01`/`40001`/`25P02` errors. Lock/statement timeouts rolled back the savepoint and entered a 100-event sequential replay; deadlocks/aborted transactions were masked as `25P02`.
3. **Librarian expired/prior-segment pending governed card divergence**: `getLinkedWork` reused `readEligibleConfirmationIds` for *all* `card.status === "pending"` governed cards, even though `readEligibleConfirmationIds` filters out expired cards, prior-segment cards, context-epoch mismatches, and reset-state cards. That blanked `available`/`effectPreview`/`target`/`payload` in `getLibrarianConversationView` while direct `getLinkedWork` callers still returned `available: true` + `effectPreview`.
4. **Hardening gaps**: `createSqliteStorage`'s `deltaBytes` parameter on `measure()` was never passed by `storage.write()`, leaving 16 consecutive 1 MiB writes able to overshoot the 8 MiB amortization margin; `transcript-projector.ts` duplicated ~95 lines of compaction update logic across single-event and batch paths; `MAISTER_DB_POOL_MAX` accepted `""`/`0`/`-5`/`"abc"` without fallback to `25`.

## Root Cause

- **Optimistic per-frame row assumption**: Multi-frame chunk slicing assumed every line in a chunk would be an ordinary 2-event text frame without funding the worst-case `FRAME_EVENT_ROWS = 4` events per yielded frame.
- **Wrong error-code assumption in batch catch**: `transcript-projector.ts` assumed `projection-transaction.ts` signaled deadlines via `EXECUTOR_UNAVAILABLE` rather than consulting `isProjectionTransactionUnavailable(error)` and PostgreSQL SQLSTATE classes.
- **Subset-as-superset cache reuse**: Treating the *eligible-for-confirmation* ID set (which applies expiry/segment/epoch/reset filters) as equivalent to *prepareKnowledgeCard-evaluated* for all `status === "pending"` rows conflated two distinct universes.

## Solution

1. Funded every multi-frame slice for worst-case `frameCount * FRAME_EVENT_ROWS` (raising `MAX_FRAME_SLICE_EVENT_ROWS` to `64` and scaling `HostState.maxReservableFrameCount()` by `Math.floor(availableRows / FRAME_EVENT_ROWS)`), updated `docs/system-analytics/execution-event-plane.md`, and guarded `frameSliceStart`/`frameSliceEnd` with `sliceOpen` in `finally` before releasing `admission`.
2. Wired zero-allocation `estimateRuntimeEventBytes(inputs)` into `storage.write(op, estimatedBytes)` so `createSqliteStorage`'s `512 KiB` byte budget tracks real write sizes and forces fresh `physicalSnapshot()` measurement on large writes.
3. Added `isNonReplayableBatchError` (checking `isProjectionTransactionUnavailable(error)`, `EXECUTOR_UNAVAILABLE`, `57014`/`55P03`/`40P01`/`40001`/`25P02`, and `08*`/`57*` classes) in `projectTranscriptBatch` and extracted shared `applyCompactionUpdate` used by both `projectTranscriptEvent` and `applyPlannedTranscriptOps`.
4. Added `readEligibleConfirmations` returning `{ eligibleIds, evaluatedGovernedPendingIds }`, threaded `evaluatedPendingCardIds` from `getLibrarianConversationView` into `getLinkedWork`, and restricted O(1) eligibility reuse strictly to cards in `evaluatedPendingCardIds`.
5. Validated `MAISTER_DB_POOL_MAX` as a positive integer with fallback to `25` in `web/lib/db/client.ts`.
6. Added targeted regression tests covering 12-frame non-text slices + mid-slice invalid UTF-8 flush, >512 KiB `storage.write` fresh measurement, `55P03` non-replayable rethrow in `projectBatch`, expired pending governed card parity across `getLibrarianConversationView` and direct `getLinkedWork`, and invalid `MAISTER_DB_POOL_MAX` fallback.

## Prevention

- Whenever batching heterogeneous items under a single resource reservation, fund the **worst-case** per-item bound (or filter the batch strictly to homogeneous items before reserving).
- Never catch broad errors around a subtransaction/savepoint without rethrowing the canonical transaction-unavailability predicate (`isProjectionTransactionUnavailable`) and PG cancellation/contention SQLSTATEs (`57014`, `55P03`, `40P01`, `40001`, `25P02`).
- Whenever reusing a filtered ID set from helper A inside reader B, also return the exact **evaluated universe** set from A so items excluded by A's pre-filters never get falsely treated as negative results in B.
