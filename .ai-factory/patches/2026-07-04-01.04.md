# Patch: Project Brain B/C review-fix drift gate

## Trigger

Code review found Project Brain B/C docs-contract drift after implementation:
canonical analytics, OpenAPI, DB docs, screen references, SDD, and plan artifacts
still described shipped B/C behavior as designed/future in several places.

## Root Causes

- Status labels were flipped in primary docs but not in index/glossary/screen/API
  surfaces.
- The implementation introduced `0005_brain_proposal_decision_stats.sql` after
  the plan/preflight had frozen only `0003`/`0004`.
- The source-indexing plan claimed glob/default-source behavior that had not been
  exercised through production call sites.
- Test rows asserted a Project Brain Playwright spec even after the branch used
  SSR component, route, and integration coverage for the server-rendered UI.
- Source indexing treated source jobs as if owned-item resumability also bounded
  glob/chunk fanout; broad globs and high-fragmentation files needed explicit
  source budgets.
- The Brain proposal UI used one coarse review capability even though backend
  acceptance actions differ by proposal kind.

## Rule

For `$aif-fix` review follow-up on docs-heavy features, validate code and docs in
both directions before editing:

1. Check the shipped code path for every review finding; fix real behavior gaps
   with focused integration tests instead of only editing docs.
2. Sweep canonical docs, OpenAPI, DB docs, screen docs, SDD, preflight, and plan
   artifacts for stale status labels and DTO shapes.
3. When a required test strategy changes, amend the traceability matrix and task
   acceptance rows instead of leaving a checked task that promises absent tests.
4. Run `CI=true pnpm validate:docs`, `CI=true pnpm validate:contracts`,
   `CI=true pnpm --filter maister-web typecheck`, focused behavior tests, and
   `git --no-pager diff --check`.
5. For indexed-source work, test both registration-time validation and
   worker-time behavior: glob breadth, aggregate bytes, chunk/segment budgets,
   source overlap with exact peers, deterministic `last_error`, and transient
   embedding retry.
6. UI permission props must mirror backend action gates at the same granularity;
   do not collapse kind-specific route authorization into one screen-level
   boolean.
