# Five adversarial-review findings on multi-repo enablement: deny-only tests, a leaked allocation, and an impossible consent

**Date:** 2026-08-06 19:10
**Files:** `web/app/api/v1/ext/projects/[slug]/tasks/[taskId]/relations/route.ts`,
`web/lib/social/relations.ts`, `web/lib/agents/launch.ts`,
`web/lib/context-mounts/launch.ts`, `web/lib/flows/graph/runner-graph.ts`,
`mcp/src/tools.ts`, `docs/api/external/operations.openapi.yaml`,
`docs/decisions.md`
**Severity:** high

## Problem

An adversarial review over the whole branch raised five findings. All five were
verified in source before any edit; all five were real.

1. A reach-granted agent could **never** create or remove a cross-project
   relation — `refuseCrossProjectTarget` returned an unconditional 404 for every
   agent token, so `relations:create` / `relations:delete` in
   `CROSS_PROJECT_AGENT_SCOPES` were unreachable.
2. The relations `GET` authorized only the URL project, then returned a foreign
   task's `title` and `status` to any caller who could read the near end.
3. An at-cap chain-depth refusal threw between `addWorktree` (`:1204`) and the
   compensating cleanup (`:1344`), stranding a directory and a branch ref with no
   `runs`/`workspaces` row for GC to key on.
4. An agent-driven flow run whose node declared `context_repos` could never
   start: `launchAgentDrivenFlowRun` passes `actorUserId: null`, the graph runner
   passed `consent: {kind: "launching-user"}`, and `authorizeLaunchingUser`
   rejects a missing user.
5. The ADR index table still read `Designed` while the ADR bodies read
   `Implemented`, and `T36` was ticked while its phase sibling `T35` is unwritten.

## Root Cause

Findings 1 and 2 share one cause with three defects already recorded on this
branch: **an assertion that never executes the thing it describes.**

Finding 1 is the sharpest instance yet, because it was self-inflicted by an
earlier fix in the same session. Closing a project-enumeration oracle, I made
every agent token receive a 404. That closed the oracle and *also* made the
granted path unreachable. The test written alongside it asserted only that an
agent gets a 404 — which is exactly what a totally broken feature also produces.
**A deny-only test cannot distinguish "correctly refused" from "does not work",
and a security fix is precisely where that confusion is most likely**, because the
denial is the behavior you are focused on proving.

Finding 2 is the same shape at the read boundary: the route's authorization
answered "may this caller read the near end?" while the response body answered a
second, unasked question — "what is at the far end?" Adding a cross-project
capability turned an existing single-project read into a two-project read, and
nothing re-derived the authorization question from the new response shape.

Finding 3 is an ordering error against a rule the repo already states: *gates run
before irreversible side-effects.* The chain-depth gate is a pure DB read with no
dependency on the worktree, so it had no reason to sit after the allocation — it
landed there because it was added last, appended where the surrounding code
happened to end.

Finding 4 is a contract gap disguised as a bug. ADR-157 D11 defines exactly two
consent forms — a launching user's `readRepoFiles`, or an admin's attach-time
grant. An agent-driven flow run structurally has neither, and that third case was
never enumerated, so it fell into the `launching-user` branch and failed there.

Finding 5: the 121-tag `Designed → Implemented` sweep used regexes matched to
prose forms (`(Designed — ADR-157)`) and silently missed the index table's
`| Designed |` cell form. A sweep that reports a count is not a sweep that
covered every form.

## Solution

- **1:** the agent arm now consults `canAgentReachProject` with the operation's
  own scope, so `relations:create` and `relations:delete` are checked
  independently. Every **denial** still returns the existence-hidden 404, so the
  oracle stays closed; only the allow branch changed. Added the positive
  create-and-remove case plus a disabled-link denial.
- **2:** foreign counterpart content is redacted (`title`/`status` → `null`)
  behind an explicit `redacted` boolean, while the **address**
  (`taskKey` + `number`) is always returned — ADR-155 makes the `blocked` chip's
  `KEY-N` the only mitigation for a wedged success-gated `requires` edge, so
  hiding the row would break a stated contract. Decisions memoize per project so
  N relations into one sibling cost one authorization. `TaskRelationView.other`
  gained `projectId` (both sibling query functions swept) because the check is
  impossible without it. Specced in the external OpenAPI; `relation_list`'s
  description now explains a null title so a model does not read it as missing
  data and retry.
- **3:** the gate moved to `:1059`, before every git mutation. One in-class
  sibling that genuinely cannot be hoisted (`ensureWorktreeProvenance` verifies
  provenance *on* the created tree) got nested compensation guarded by
  `allocatedWorktree`, which keeps ADR-102 shared-tree reuse intact.
- **4:** `ContextMountConsent` gained a third member,
  `{kind: "agent-driven-flow"}`, so the type states out loud that neither D11
  form applies. `prepareContextMounts` refuses it **after** the no-declarations
  and kill-switch short-circuits, with a message naming both remedies.
- **5:** index rows flipped; `T36` un-ticked with the reason recorded.

## Prevention

- **Every allow-list or grant needs a positive test, not only denials.** When a
  change adds a capability behind a permission check, the suite must contain at
  least one case that *exercises the granted path end-to-end*. Grep the new
  scope constant: if every test naming it asserts a refusal, the feature is
  unproven. This would have caught finding 1 the day it shipped.
- **When a read starts spanning two authorization domains, re-derive the
  authorization question from the response shape, not from the route's
  parameters.** Ask "which rows in this body belong to something the caller was
  never authorized for?" — the URL says nothing about the far end of a relation.
- **A tag/number sweep reports the forms it covered, not just a count.** After a
  bulk status flip, grep the *old* value and classify every remaining hit;
  `| Designed |` in a table is a different form from `(Designed — ADR-x)` in prose.
- **A new discriminated-union case beats an `else` fallthrough.** Finding 4's
  failure mode was a real third state silently entering a branch written for a
  different one. Adding the member makes the compiler enumerate it.
- Sibling classification for finding 2 is recorded in the plan (ext = fixed;
  `task-detail.ts` and `board.ts` = intentionally excluded, because ADR-155 needs
  the human chip actionable) with the residual human-surface disclosure flagged
  for an owner decision rather than silently kept or silently changed.
