# Activating a dead safety gate exposes the semantics nobody had to define

**Date:** 2026-09-03 15:06
**Files:** web/lib/runs/keepalive-sweeper.ts, web/lib/runs/budget-default.ts,
web/lib/supervisor-client.ts, web/lib/runs/__tests__/budget-watchdog.integration.test.ts,
web/lib/__tests__/supervisor-client.test.ts
**Severity:** high

## Problem

`f58a8895` fixed a tree-root detection gate (`rootRunId === id`, false for every
production row) that had made ADR-101's **tree-scope budgets never evaluate at
all** since `cec7ec632`. Turning that enforcement on for the first time exposed
three defects in code the commit never touched:

1. A tree breach in the **escalate band** at a `Running` root was silently
   swallowed by a same-tick run escalate — `pickHigher` keeps the FIRST verdict at
   an equal rung and run is folded before tree. The root paused to `NeedsInput`,
   left the candidate scan (which admits only `Running`/`WaitingOnChildren`), and
   the tree was never re-checked while descendants kept spending.
2. **A live regression:** with `MAISTER_DEFAULT_UNATTENDED_BUDGET_TOKENS` seeding
   `run` and `tree` at one value, an operator raise lifted only the breached scope
   (`hitl.ts:4097-4099`), so the unraised tree ceiling killed the run one tick
   after it was funded — violating `execution-policy.md:294` ("the resumed run
   MUST NOT immediately re-escalate").
3. On a lost root CAS the descendants were already irreversibly `Abandoned` while
   `notified.tree` was dropped (computed, but written only inside the CAS `.set()`),
   so a re-entry would re-run the cascade against an already-gutted tree.

Separately: `deleteSession` mapped ANY non-ok response without a recognized body
code to the terminal `ACP_PROTOCOL` — and the supervisor's own unhandled-error
handler emits `500 {code:"ACP_PROTOCOL"}` — so a supervisor-internal 500 took the
"terminal failure — proceeding" branch and abandoned a tree with its root agent
possibly still alive, defeating the E5 retryable guard.

## Root Cause

**Dead code does not fail; it defers.** The gate had been false for every row
since introduction, so every downstream semantic question went unasked: what
should happen when a *Running* root's tree breaches (the spec only ever addressed
a **parked** `WaitingOnChildren` root, whose lack of a `→ NeedsInput` transition
is the stated reason tree scope has no escalate rung), and what a "tree" even
means for a root with no descendants. The tests could not catch any of it because
their fixtures self-stamped roots (`root_run_id = <own id>`) — a shape production
never builds — so they exercised a predicate unreachable in the field.

The regression (2) has a sharper cause: a compensating workaround outlived its
defect. `budget-default.ts` seeded BOTH ceilings *because* tree scope never fired;
its comment said so explicitly. Fixing the gate turned that dead-weight seed into
an active killer, and the raise path — which lifts one scope — could not undo it.

For the classification bug: two functions, `deleteSession` and
`deleteSessionIfPresent`, answered the same question ("is this failure
retryable?") and only one answered it correctly. The correct one was unused on
every path that depended on the answer.

## Solution

- **Promote tree verdicts at classification, not after arbitration**
  (`promoteTreeVerdict`). A real tree breach now competes as rung 3 and wins on
  merit. Promoting afterwards could never work: the trailing check tested the
  *winning* verdict's scope, so a losing tree verdict was already discarded.
- **Skip the redundant tree TOKENS meter for a root with no descendants**, and
  only when run-scope tokens are set. Narrowed to tokens deliberately: `wallclock`
  is a **tree-scope-only** meter, so dropping the whole scope would have silently
  disabled every lone run's duration bound; tree failures are always 0 for a tree
  of one. Existence probe is a `LIMIT 1` on `runs_root_run_id_idx`, not
  `getRunSubtreeIds` (a per-level BFS).
- **Persist `notified.tree` on the lost-CAS path** so the gutted tree is never
  re-cascaded.
- **Share one deletion-failure classifier** between `deleteSession` and
  `deleteSessionIfPresent` (5xx → `EXECUTOR_UNAVAILABLE`).
- Corrected the two `f58a8895` artifacts whose stated mechanism no longer holds.

**Not built, deliberately:** the planned fenced lifecycle claim. Implementation-time
verification showed it cannot prevent the race it exists to close —
`runner-graph.ts:4911` advances a run to `Review` on the normal execution path and
`runner-graph.ts` holds **zero** `claimLifecycleOperation` references, so the claim
would exclude a concurrent archive/sync but not the runner. Shipping it would have
bought a false sense of safety.

## Prevention

- **When a guard turns out to be dead, the fix is two tasks, not one:** re-enable
  it, then re-derive every semantic that was never exercised. Grep the spec for
  the enabled feature and check whether its clauses actually cover the states now
  reachable — here the spec addressed only a parked root.
- **Search for compensating workarounds before enabling a dormant feature.** A
  comment saying "X never fires, so we also do Y" is a load-bearing dependency on
  the bug; enabling X makes Y active. `rg` the feature name in comments first.
- **A fixture that seeds a shape production never builds proves nothing.** Seed
  what the writers actually write, and confirm the test fails before the fix.
- **Two functions answering the same classification question will diverge.**
  Extract the answer once; when you find the correct implementation unused on the
  paths that need it, that is the bug.
- **Verify a proposed mechanism can actually block the thing it fences against**
  before building it — check who takes the lock on the *racing* path, not just on
  the path you are changing.
- Review-tool findings against a newly-activated feature need provenance triage:
  separate "this commit caused it" from "this commit made it reachable", and check
  each against the spec — one of three findings here asked to reverse a decision
  the spec had explicitly locked and deferred ("not v1").
