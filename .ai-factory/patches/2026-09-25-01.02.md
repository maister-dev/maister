# ADR-181 verify fixes: a gate id that became live, a stale renumber target, a fixture that masked a product fix

**Date:** 2026-09-25 01:02
**Files:** web/lib/workbench-lifecycle/service.ts, web/lib/workbench-lifecycle/__tests__/commit-without-remote.integration.test.ts (new), web/lib/db/migrations/0176_workbench_git_publication.sql (renumbered from 0173), web/lib/db/migrations/meta/{_journal.json,0176_snapshot.json}, web/lib/db/__tests__/migration-0176-workbench-git.integration.test.ts (renamed), web/lib/db/schema.ts (comments), docs/database-schema.md, docs/db/{projects,runs}-domain.md, docs/system-analytics/workbench-git.md, supervisor/test/fixtures/mock-acp-adapter-resumable.mjs, web/lib/__tests__/permission-deadline.integration.test.ts, web/CLAUDE.md, the branch plan; the master merge's eight conflict files
**Severity:** high

## Problem

`/aif-verify` on the ADR-181 branch (run git panel) failed with three blockers
while every lane was green:

1. **Commit refused on a repo without a git remote.** The panel enabled
   Commit, but `POST /snapshot-commit` answered 409
   `PRECONDITION details.reason: no_remote`. On master the commit works, and
   `workbench-git.md` promised it.
2. **The merge step's migration target was stale.** The plan said "renumber
   0173 → 0175 at merge", but master (46 commits ahead) already had 0173-0175.
   The trial merge conflicted in 8 files.
3. **T5.5 contradicted master.** The branch had made `permission-deadline`
   RED 13/14 deterministic with an opt-in mock setting
   (`MOCK_ACP_HOLD_AFTER_CANCELLED`). Master had fixed the same race in the
   product (`04a3a39a`), and the setting would have hidden that fix from the
   suite.

## Root Cause

1. `snapshotWorkbenchCommit` gated on `requireActionAllowed(ctx, "exportBranch")`.
   That was a deliberate pre-ADR-181 choice (the ADR-160 rework-claim hole
   shared one id) and harmless while the route's context carried no facts.
   ADR-181 added a `no-remote` fact refusal to `exportBranch` AND made
   `loadContext` attach real facts (`hasRemote`), which turned the old id into
   a live refusal for a purely local operation. Nothing caught it:
   - every real-git test adds `origin`;
   - `real-git.integration.test.ts` injects a hand-built `loadContext` with no
     `facts`, so `hasRemote` was undefined there;
   - the policy unit test proved `snapshotCommit` stays enabled without a remote,
     but nothing tied the route's gate to that id.
2. A migration number chosen at plan time is a claim about master's future. The
   plan recorded the number instead of the rule "next free number at merge".
3. The T5.5 diagnosis accepted the `result` grant as "correct by the product's
   rule" without asking what it told the operator. It told them their stored
   answer was delivered although no `session.input` ever carried it — a product
   bug, which master found and fixed the same day.

## Solution

1. Commit gates on its own id, `snapshotCommit`. In the policy the two ids
   differ only in the `no-remote` fact, so nothing else is admitted.
   - Sweep of every `requireActionAllowed` site: handoff metadata and branch push
     to a validated remote (refusal correct); discard has no fact refusal;
     update onto base/target skips the fetch without an origin; so Commit was
     the only wrong gate.
   - New default-deps integration test on a repo with origin removed: Commit
     succeeds, the panel offers Commit and disables publish, publish is still
     refused. Falsified by restoring the old id (red, `no-remote`).
2. Merged master into the branch (a merge commit, no rebase):
   - the branch's migration regenerated by `drizzle-kit generate --name` as
     `0176_workbench_git_publication` on master's 0175: the same five statements,
     a newer journal `when`, the snapshot chained to 0175, then the
     hand-written SQL restored and "No schema changes" confirmed;
   - the migration test's predecessor moved to `0175_failed_child_wake`;
   - ADR-181's own `0173` mentions swept by feature (master's
     `0173_scheduler_observation_lookup` references left alone);
   - the table-row doc conflicts resolved per row against the merge base, which
     side changed which row, and row 52 merged word-level.
3. Took master's suite and fixture (the setting gone); corrected `web/CLAUDE.md`
   and plan T5.5. Re-measured on the merged tree without the setting:
   - RED 13/14 6/6 under 16 CPU burners;
   - master alone 12/12 twice at load 75-278, with the succeeded-prompt race
     firing in 7 of 12 cases.

## Prevention

- **When a policy action gains a fact refusal, grep every gate that uses that
  id** (`rg 'requireActionAllowed\('`) and ask whether each guarded operation
  needs the fact. An old gate reusing a neighbour's id becomes wrong the moment
  the neighbour learns something.
- **A route that shows a panel action should gate on that same action id.**
  Test the parity with the default deps: the panel's `enabled` and the route's
  outcome must agree.
- **A test that injects the context the production loader builds is not
  coverage of the loader's facts.** Drive at least one case through the default
  deps in a shape the lenient double would never produce (no remote).
- **Record the renumber RULE, not the number**: "the next free number at
  merge, with a `when` newer than master's newest".
  - A table-row conflict is resolved per row by asking which side changed that
    row against the merge base.
  - Key rows by position, not by first cell: the same code appears in several
    tables of `error-taxonomy.md`, and a dict keyed by it compared the wrong
    rows.
  - Grep master's test names before renaming (`migration-0173-*` existed on
    both sides).
  - The number is only final at the moment of the merge: master took
    `0176`-`0178` (33 commits) while this batch's post-merge lanes ran. Re-run
    `git merge-tree --write-tree master HEAD` and read master's journal
    immediately before the final merge, not once per session.
- **A new red after a merge may be master's own**: the supervisor mirror test
  (`stream_health_unavailable` missing from `ReasonToken`) was red on master
  itself. Diff the failing area against master before attributing it to the
  branch.
- **Before fixing a shared suite on a branch, check master for a parallel
  fix**, and before calling an outcome "correct by rule", ask whether it tells
  the operator the truth.
