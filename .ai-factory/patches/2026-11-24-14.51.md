# Close unanswered Flow node questions through the Run lifecycle

**Date:** 2026-11-24 14:51
**Files:** `web/lib/runs/flow-question-lifecycle.ts`, `web/lib/db/flow-node-answer-delivery.ts`, `web/lib/execution-host/prompt-evidence.ts`, `web/lib/db/migrations/0374_flow_node_question_closure.sql`
**Severity:** critical

## Problem

Crash and idle expiry used the generic HITL closure stamp. PostgreSQL rejected that mutation on an unanswered Flow node question, leaving its Run and Inbox work open. Stop and manual abandonment could finish without closing the question. A separate delivery projection failure rolled back already accepted successor command evidence.

## Root cause

`responded_at` means delivery for a Flow node answer. Legacy task-question supersession also requires a successor row, which a terminal Flow visit does not have. The answer observer depended on mutable action-resume state and wrote into the canonical command transaction.

## Solution

Use timestamp-only supersession for an undelivered Flow node question and close its assignments under the lifecycle transaction. Preserve accepted answers and use the same immutable successor predicate to protect proven delivery during terminal closure. Commit canonical command evidence first. A bounded reconciliation page retries delivery using the retained command and original ACP incarnation.

## Prevention

Exercise Stop, manual and TTL abandonment, and crash through their real owners with populated PostgreSQL. Inject failure into the delivery write after an accepted successor and verify that recovery still publishes exactly one receipt. Verify 0374 over populated 0373 and retain the legacy task-question check.

`rg -n 'closeFlowNodeQuestions\(' web/lib/{runs,reconcile.ts,workbench-lifecycle,flows/graph} --glob '!**/__tests__/**'` found the shared owner in keepalive, state transitions, Workbench stop/removal, graph failure/crash and the recovery backstop. `rg -n 'isNull\(hitlRequests.flowNodeAttemptId\)' web/lib/runs/{keepalive-sweeper,state-transitions}.ts` found both generic response-time writers fenced away from Flow node questions.
