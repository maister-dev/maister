# Keep INSERT-only token ownership queries out of audit updates

**Date:** 2026-11-04 10:10
**Files:** migration 0227 token-origin guard; migration-task-launch-admission integration control; delegation fixtures and token-audit-quiescence helper
**Severity:** high

## Confirmed cause

The broad token-consumer run failed two fixture resets with PostgreSQL deadlocks.
An actual `bumpTokenLastUsed` UPDATE held `project_tokens` RowExclusive while
requesting `runs` AccessShare. Reset held `runs` AccessExclusive and requested
`project_tokens` AccessExclusive. PostgreSQL reported SQLSTATE `40P01`, with
`guard_project_token_run_origin() line 3 at IF` as the context. The IF combined
`TG_OP='INSERT'` with the owner SELECT, so planning that expression still locked
the Run relation on an audit-only UPDATE.

A temporary table-lock barrier reproduced the exact cycle using the real audit
function and reset SQL. The retained safe PID/relation evidence is
`/tmp/maister-delegation-detached-audit-lock-detail.json`; its run is
`/tmp/maister-delegation-detached-audit-lock-proof-final.log`. The temporary
diagnostic test was removed. This cause does not require a competing model
driver or a workspace race.

## Correction and acceptance

Nest the owner SELECT lexically inside an INSERT-only IF. Keep all actual owner,
project, immutable-origin and monotonic-revocation checks. The existing DB guard
case now holds the Run table AccessExclusive on one connection while another
updates a real stamped token's `last_used_at` with a bounded lock timeout. The
UPDATE must finish before releasing the Run lock. Both transactions roll back
and both clients release even if rollback fails.

Separately, fixtures now own the detached last-used writes they cause. The
test-only wrapper calls the original function and returns its original promise;
reset and teardown await captured writes. Unexpected failures are retained in
an AggregateError after all captured writes settle. Production best-effort audit
behavior remains unchanged. No delays, retries, guard relaxation or capacity
changes are used.

The two whole API files and full migration file pass **43/43** in
`/tmp/maister-token-audit-quiescence-and-migration-green.log`, including fresh and
populated upgrade controls and the locked-Run UPDATE assertion. All five test
databases stopped naturally. Scoped ESLint and `git diff --check` pass. Broader
consumer validation remains owned by the coordinator.
