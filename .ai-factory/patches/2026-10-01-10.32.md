# Keep persistence maturity aligned with the implemented runtime

**Date:** 2026-10-01 10:32 UTC
**Files:** `docs/database-schema.md`, `docs/db/runs-domain.md`
**Severity:** medium

## Problem

The schema reference and domain index still described ADR-192 transactional
writers and replay as Designed, although its implementation amendment and
production dispatch/recovery code already implement those contracts.

## Root Cause

Schema documentation was updated when migration 0192 landed but its separate
runtime maturity labels were not reconciled after the dependent phase.

## Solution

Mark the implemented runtime contract consistently, retaining ADR-192 as the
single source for ownership and legacy ambiguity semantics. No schema, API,
migration or historical decision text changes are needed.

## Prevention

After a dependent runtime phase lands, search every reference to the migration
and ADR for maturity labels, including comments, wrapped prose and table cells.
Check labels against code and the implementation amendment before editing them.
