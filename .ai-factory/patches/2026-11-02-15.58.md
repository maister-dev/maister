# Human-ask choices and internal MCP schemas must match their contracts

**Date:** 2026-11-02 15:58
**Files:** web/lib/services/{agent-question-response,agent-question-contract,hitl}.ts; web/components/board/hitl-decision-controls.tsx; web/app/api/v1/ext/projects/[slug]/tasks/[taskId]/human-asks/route.ts; runtime/ask-human-input.schema.json; mcp/src/{tools,rest,main}.ts; .github/workflows/ci.yml
**Severity:** high

## Problem

A task-bound agent clarification offered custom text beneath suggested choices,
then rejected that answer as incomplete. In the same Run, agents attempted
`ask_human` twice with JSON Schema before discovering the MAIster form grammar
in repository source.

## Root Cause

The UI always allowed custom input, including enum fields. Agent questions used
the strict Flow/output validator, which correctly rejects values outside an
enum but does not model human clarification suggestions. MCP independently
advertised only `schema: {type: object}` and concealed the required schemaVersion
and field grammar. Generic MCP error rendering discarded structured validation
details. Existing API contract checks did not compare this nested grammar, and
the Docker-free CI lane omitted the internal MCP test/build suite.

## Solution

Agent-question validation interprets enum choices as string suggestions without
mutating the stored schema or answer; required text is nonblank, including nested
array/object fields. Flow/output enums stay closed. Their UI offers only valid
choices and lets an optional selection be cleared. Both run and Inbox copy now
match that distinction.

The MCP input schema is generated from the canonical versioned HTTP body.
Actionable, value-free validation paths survive MCP stdio errors. The generation
check is part of validate:contracts; CI also typechecks, builds and tests MCP.

## Prevention

Treat a proposed choice and an authorization/transition allow-list as distinct
contracts. Verify both UI submission and domain answer/replay behavior. Check
nested schemas, accepted and rejected HTTP payloads, and actual MCP stdio rather
than only top-level field names. Generated artifact checks and tests must run in
CI. Do not accept an undocumented legacy schema as a fallback.

Sibling sweep: `rg -l 'HitlDecisionControls|RunHitlResponse|formFieldsFromSchema' web/components -g '*test.ts'`
covered the run, Inbox, review, progress and form-builder consumers. Flow
`hitl-validate` and structured-output suites retain closed enums. Both run and
Inbox `formInstructions` translations were corrected in EN/RU.
