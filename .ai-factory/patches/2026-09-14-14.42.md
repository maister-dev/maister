# Launch inheritance, durable prompt ownership, checkpoint and removal diagnostics

**Date:** 2026-09-14 14:42 (Europe/Moscow)
**Severity:** high
**Files:** MCP server/tool registry; runner resolver, launch service/preview/popover;
reconcile and resumed-session driver; workspace checkpoint and gate-chat sensor;
run query/result DTOs and failure components; preserve/lifecycle service and routes;
EN/RU messages; corresponding tests and contracts.

## Problem

MAI-4 could be triaged but not auto-enqueued, and manual launch refused an
unbound session even though the project inherited a platform runner. AID-1
failed during Survey, rewind retry failed on `.gitignore`, and Drop returned an
unexplained conflict. Failed node UI omitted the recorded error code and could
show a successful readiness summary.

## Root Cause

- MCP `registerTool` received a generic Zod record instead of the canonical
  tool JSON Schema. The SDK advertised empty properties, losing boolean/null
  types needed by `triage_set.enqueue` and sibling fields.
- Named session intent matching ignored configured project/platform defaults.
  Saved task runner selection was not applied consistently at launch. The
  dialog also submitted an unchanged preview runner as an explicit run-wide
  override, changing secondary-session selection after preview.
- Reconcile treated session liveness as authority to run the permission resume
  driver. The driver attempted a different prompt with an existing durable
  operation key, then deleted the original session after admission refused it.
  The original prompt persisted the resulting `ACP_PROTOCOL` connection close;
  that secondary error obscured the cause. Host traces showed intentional
  exit code zero following the admission conflict in both supplied runs.
- Checkpoint capture populated an empty alternate Git index with `git add -A`.
  Materialized `.gitignore`/config overrides ignore their own tracked paths and
  use skip-worktree. Starting from an empty index omitted the original tracked
  blobs; rewind then tried to delete modified protected files. Gate-chat's
  content sensor duplicated the same incorrect capture semantics.
- Preserve requires a Git commit for dirty/staged content. The web user had no
  usable author/committer identity. Host `git var` failed, and configuring
  identity made Drop succeed. A failed lifecycle claim is already reclaimable
  (`none`/`failed`); its retained attempt ID is not a lock. Dirty worktrees and
  skip-worktree alone did not reproduce the preserve refusal with valid identity.

## Solution

- Publish every canonical `TOOL_SPECS` JSON Schema through the SDK request
  handlers; retain authentication, dispatch, cancellation and route validation.
- Apply compatible configured defaults to unbound sessions, after explicit
  overrides, bindings and concrete runner references. Preserve adapter
  capability and surface model-intent mismatch warnings. Task/launch choices
  apply to the primary session and compatible unbound sessions. Explicit
  per-session recipe assignments beat a saved task choice, including a disabled
  saved runner. Validate a default when used, not before explicit overrides.
  Immediate and scheduled launch builders omit unchanged preview selections.
- Route live Flow reattachment through the durable graph driver/lease.
  Guard direct resume and its top-level catch against existing durable Flow
  prompt ownership. Admission conflicts yield without terminal writes, HITL
  mutation, event consumption or session deletion. Start event consumption only
  after prompt admission; canonical replay retains early permission events.
- Share `captureWorkspaceTree` between checkpoint capture and gate-chat. Seed
  its private index from the actual linked-worktree index, preserving tracked
  ignored blobs and skip-worktree flags without changing the caller's index.
  Do not clear overlays or weaken workspace-preservation checks.
- Read and serialize allow-listed attempt error codes and exit codes into all
  run result/timeline surfaces. Show EN/RU explanations and labeled diagnostic
  fields, never raw server/agent output. Suppress success readiness for failures.
- Check Git author/committer identity before staging preservation content.
  Return typed `workspace_git_identity_invalid` through lifecycle/API to a
  localized user action; other refusal uses `workspace_preservation_failed`.
  Keep full cause/context in structured server logs and retain the worktree.

## Prevention

- Verify `tools/list` and typed `tools/call` using an actual SDK transport, not
  only the handwritten registry. Test boolean false as well as true and nulls.
- Test the complete preview/form/launch contract; a displayed default is not
  an explicit override. Exercise saved runner, project/platform inheritance,
  concrete/bound heterogeneous sessions and explicit recipe choices.
- Test accepted + acknowledged live prompts with real PostgreSQL/supervisor,
  plus owner death before terminal, before application, after application and
  after failure. Assert immutable command identity, original error, owner lease
  and absence of additional session deletion.
- Materialize a real capability bundle before checkpoint/rewind tests. Compare
  both tracked ignored blobs and caller-index bytes, and check the gate-chat
  sensor against exactly the same content-tree semantics.
- A preserve refusal must name the failed prerequisite, leave content/index
  intact where possible and allow retry after configuration is corrected.

## Operational boundary

These are local code changes, not a production deployment. Update web and MCP
before starting a new AID-1 run. Previously malformed checkpoint refs and failed
historical attempts are not rewritten. The user confirmed production Drop works
once Git identity is configured. Actual week-one content generation remains a
post-deployment check. The adjacent poisoned artifact projection and embedding
HTTP 429 jobs are separate findings; this patch does not claim to repair them.

## Executed sibling sweep

Classification:

1. MCP schema publication: fixed at the shared server factory for stdio and HTTP;
   all tool schemas are transport-tested, not just `triage_set`.
2. Runner resolution: launch, launch-options and task-launch-config updated;
   consensus roles intentionally retain their own role binding/intent contract.
3. Resume: reconcile fixed; both HITL callers pass through the guarded shared
   driver. Durable permission resumes already route through the graph owner.
4. Alternate Git indexes: checkpoint and gate-chat fixed together. The existing
   worktree diff helper already copies the real index and does not restore files.
5. Preservation: manual archive/drop/discard share the lifecycle choke point;
   automatic GC uses the same preserve function and already skips removal on failure.
6. Failure readers: required DTO fields and labels cover Flow, agent and timeline;
   unknown error strings are excluded at query and rendering boundaries.
7. Launch body builders: both immediate and scheduled callers now supply the
   initial selection; unchanged preview values are not serialized as overrides.
