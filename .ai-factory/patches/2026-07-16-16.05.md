# ADR-139/140 branch-sync — round-2 review fixes (4 Critical + 6 High + specs)

**Date:** 2026-07-16 16:05
**Files:** `web/lib/runs/{promote,sync-target,sync-recovery,state-transitions,pr-adapter}.ts`,
`web/lib/scheduler/handlers/pr-state-scan.ts`, `web/lib/{worktree,reconcile}.ts`,
`web/lib/db/schema.ts` + migration `0103` + 2 snapshots, 4 routes, 6 components,
`docs/decisions.md`, 8 `docs/system-analytics/*`, 2 OpenAPI specs, 9 test files
**Severity:** critical

## Problem

`/aif-review main` found 4 Critical + 6 High defects on `claude/pr-merge-workflows-4d0e7e`.
The three that mattered most:

- **A rejected target push spawned an AI resolver.** `GitPushRejectedError extends
  MaisterError` with `super("CONFLICT")`, and the push sat INSIDE the merge's catch,
  which routes any `CONFLICT` into the `ai_rebase_merge` resolver delegation. With
  `push=on_success`, a non-fast-forward push of an ALREADY-LANDED merge burned a slot +
  tokens resolving a conflict that did not exist, and returned `ok: true` for a
  landed-but-unpushed merge. (On non-AI modes the same path opened a bogus
  `merge_conflict` HITL assignment.)
- **A permission-denied PR read was written as `pr_state='closed'`.** Providers answer
  permission-denied with the same 404/"could not resolve" they use for a deleted PR.
  That was classified terminal → `closeTerminal`. Since `loadCandidates` selects only
  `NULL|'open'` and nothing else writes `pr_state`, ONE rotated `GH_TOKEN` would
  permanently mark every live PR closed, silently, and block reopen — recoverable only
  by hand-written SQL.
- **The resolver's own parking spot had no recovery arm.** `(NeedsInput, agent_running)`
  is where the resolver waits BY DESIGN (ACP `requestPermission`), yet reconcile is
  `Running`-only, W5 requires `Running`, and W1/W4 requires `mechanical`. Post-restart
  the run held a pool slot AND the sync claim forever.

## Root Cause

Three causes explain nearly all of it:

1. **`CONFLICT` is overloaded.** It means both "the rebase conflicted" and "the push was
   rejected". Any catch that reads the code alone cannot tell a *conflict* from a
   *rejection* — so the fix is structural (scope the try), not a smarter predicate.
2. **The spec stopped short of the code.** ADR-140 claimed W1–W6 "each have a recovery
   predicate" but shipped NO table; the table existed only in an ephemeral plan file, and
   only ever contemplated `status ∈ {Review, Running}`. With no spec table, code
   docstrings became the checklist — so *the implementation defined the windows it
   satisfied*, and every uncovered cell (`NeedsInput`, `Abandoned`, `Crashed`) is one the
   taxonomy never named. This is why H1 is a spec defect, not a coding slip.
3. **Near-duplicate helpers diverged on their safety property.** `releaseSyncClaim` was
   fixed to fence on the claim's own attempt id; its copy `releaseClaim` kept the
   `name='sync'` guard the twin's comment calls a shipped bug. Same for
   `failResolver`/`failAgentAttemptToReview` (CAS-before-restore).

## Solution

- **C1**: moved `maybePushTargetBranch` OUTSIDE the merge's catch (it already owns its
  degrade-to-manual handling). Only `agent_launched` now returns `ok: true`; `noop`/
  `synced` rethrow, since no resolver is coming and the merge never landed.
- **C2**: no failed read may write `pr_state` — 404/not-found is reclassified retryable,
  `closeTerminal` deleted. **Dropped `pr_state_checked_at`** (zero production readers):
  ADR-139's "so one bad row cannot stall the job" rationale was vacuous — the KEYSET
  CURSOR already guarantees that. Owner chose this over the planned attempt-counter,
  which would have re-created C2's own bug class (a token outage permanently abandoning a
  live PR, just via a counter instead of `closed`).
- **C3**: auth-first on 4 routes. **Deviated from the plan** — see below.
- **H1**: added W7 (`NeedsInput|NeedsInputIdle` + `agent_running` + no driver → abort to
  `Review`) + `markSyncReviewFromNeedsInput`. Rather than the planned reconcile
  re-ordering, all four terminal paths (`crashRunningRun`/`crashResumedRun`/
  `crashWaitingOnChildren`/`markAbandoned`) now release a live sync claim in the SAME tx
  as the terminal flip — closing the cell at its source.
- **H2**: `settleAttempt`/`abortAttempt`/`failAttempt`/`failAttemptIfActive` each write
  the terminal phase + release the claim in ONE tx; promote's reverse fence gained the
  same staleness carve-out `canReclaimLifecycle` uses.
- **H3/H4**: `ffUpdateLocalBranch` now takes `withRepoPromotionLock` (the mutation is on
  the SHARED parent repo; every claim upstream is per-workspace) and PROVES divergence
  with `isAncestor` before claiming it — a dirty parent checkout also fails
  `merge --ff-only`, and was being reported as a false divergence naming two SHAs in a
  perfect fast-forward relationship.
- **H5**: both twins fixed and the fence token threaded onto `AttemptRow` (it is a
  SEPARATE uuid from the sync attempt id, readable only off the workspace row).
- **S1**: promoted the W-table into ADR-140 as normative, with W7 named.

## Prevention

- **A finding's observation outlives its prescription.** Round 1 taught this; round 2
  proved it twice more. C3's plan step rested on "every sibling ext route uses a path
  param" — FALSE: 7 of 9 run-action ext routes put `runId` in the body and achieve
  auth-first by NOT using `resolveProjectId`. Following the prescription would have been a
  breaking API change *away* from the convention. **Verify the premise, not just the
  file:line.**
- **Mutation-test every fix.** C1 and H4 were each neutered and watched to fail
  (C1: `promise resolved "{ ok: true, …}" instead of rejecting` — the defect verbatim).
  A test that passes both with and without the fix is not evidence.
- **A test seed that cannot occur in production is a hole, not a fixture.** Six
  sync-recovery tests seeded a claim with NO `lifecycle_operation_attempt_id`
  (`syncRunTarget` always mints one) — they passed only because the un-fenced predicate
  ignored the token. The W5 "paused in NeedsInput" test seeded no in-process driver, which
  IS a post-restart orphan. `flight-card.test.ts` hardcoded `canAct: false` while
  asserting a "LIVE reopen action" — i.e. it asserted the viewer-403 bug. Correct the
  seed to the realistic precondition; never weaken the gate.
- **When a doc's rationale names a mechanism, check that the mechanism is read.**
  `pr_state_checked_at` was written in 6 places and read in 0, while two docs elevated it
  to a MUST. A column nothing reads cannot influence candidate selection.
- Guard the guards: an ADR gate that `Set`-collapses duplicate numbers, and a migration
  test that prefix-matches `0103`, both pass while broken. The migration tests now match
  by NAME and assert the snapshot `prevId` chain + `when` monotonicity — which is what
  makes the owner's renumber safe.
