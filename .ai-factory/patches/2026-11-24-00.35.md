# Reconcile crashes skipped during Web cutover

**Date** 2026-11-24 00:35 MSK

**Files** `web/instrumentation-node.ts`, lifecycle projector and tests, `docs/deployment.md`

**Severity** high

## Problem

A Flow could lose its Recover action after a released session crashed while
an old Web projector was still running during deployment.

## Root Cause

Migration 0369 repairs only accepted events whose lifecycle cursor already
passed them. The legacy projector could skip and advance the cursor after
that migration committed. The upgraded projector would start beyond the
unbound crash.

## Solution

Stop the old Web writers at cutover. The new Web repeats the unchanged exact
repair once before workers start. PostgreSQL commits the repair with its
unique completion marker. A concurrent boot waits for the transaction, and
failure rolls the marker back so the next boot can retry.

## Prevention

Test the sequence through the real cursor: migrate, let the old projector
skip an accepted event, then start the repair without new ingest. Check the
event binding and original session state, the untouched successor, and one
successful repair across two boot claimants.

The writer sweep used `rg -n 'executionProjectionBackfills|projectCanonicalSessionLifecycle|0369_reconcile_skipped_session_crashes' web`.
The lifecycle projector handles new events. The boot repair handles the
released historical sessions. Existing projection backfill consumers retain
their own named row and cursor.
