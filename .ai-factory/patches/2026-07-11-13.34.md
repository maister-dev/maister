# Agent materialization and package lifecycle hardening

Date: 2026-07-11 13:34 MSK
Files: agent materialization ownership/GC, supervisor diagnostics, Studio package validation, API/spec/docs
Severity: critical

## Problem

Terminal agent cleanup could roll back a terminal DB transition, and several
crash windows could leave run-owned materialization, capability settings, or
package artifacts in an ambiguous state. Studio and package lifecycle gates also
needed to enforce the same capability-profile, agent-definition, and schema
contracts as runtime.

## Root Cause

Filesystem ownership work was coupled to transactional finalization and did not
consistently distinguish intent from active leases. Adapter smoke evidence and
package artifacts had independently evolving representations at UI, runtime,
and contract boundaries.

## Solution

- Move terminal filesystem release behind the committed run transition and retain
  records for guarded retry.
- Use a per-cwd SQLite mutex, path-confinement checks, state-aware leases, and
  settings ownership records to make recovery fail closed.
- Validate package agent/profile/schema artifacts through their lifecycle gates
  and expose logical rather than host-local artifact context in admin summaries.
- Add typed smoke freshness/probe diagnostics and synchronize web, supervisor,
  OpenAPI, analytics, ADR, screen, spec, and plan contracts.
