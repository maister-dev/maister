## Problem

Review found terminal and recovery paths that could retain unrecoverable
materialization, delete a recoverable scratch profile, hide an unauthorized
repo-read mutation, orphan a smoke adapter process, or project an inaccurate
package artifact path. Direct flow installation also bypassed the root-schema
contract.

## Root Cause

Ownership state, recovery cleanup, and package schema checks were not applied
uniformly across every terminal/install entry point. Some user-visible contracts
were looser than their typed runtime schemas.

## Solution

- Roll back only zero-owner `preparing` intents after path prevalidation; keep
  foreign leases and corrupt/releasing state fail-closed.
- Journal capability settings through explicit backup/write/restore phases,
  distinguish local from foreign L2 leases, and preserve recoverable crashed
  scratch/worktree materialization.
- Filter L3 porcelain only for every explicitly owned path, including both
  sides of a rename; unknown metadata and user-owned settings stay dirty.
- Enforce package-root schema references on direct and package installs, repair
  reused package schema caches from fresh source bytes, and keep OpenAPI/API
  DTOs aligned with runtime contracts.
- Reap timed-out smoke children with bounded SIGTERM then SIGKILL escalation.
