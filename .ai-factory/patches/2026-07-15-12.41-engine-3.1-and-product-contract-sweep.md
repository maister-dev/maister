# Align engine 3.1 tests and the current product contract

**Date:** 2026-07-15 12:41
**Files:** engine compatibility and Plan-review fixtures under `web/lib/`, the
HITL response route test harness, Flow DSL grammar, README, Vision, Product
View, Roadmap, and current engine documentation
**Severity:** medium

## Problem

The intentional engine `3.1.0` release left tests and current documentation
asserting host engine `3.0.0`. Plan-review compiler invariants also exposed
stale fixtures: the rework target did not render its feedback variable, the
seed expectation omitted `plan_review_answers`, and the HITL route harness
lacked new gate-chat and supervisor dependencies. One diff test ignored the
old path of a rename and therefore tested a different predicate than runtime.

Product documents still described pre-dogfood validation and several shipped
features as future work. They also used the older generic control-plane
positioning.

## Root Cause

The `3.1.0` feature commit updated the engine constant and runtime contracts
without a sibling sweep across version assertions, agent-facing grammar,
fixtures, and current-state documentation. Later review-workspace changes
expanded the HITL service dependencies without updating its isolated route
test harness. The roadmap mixed frozen implementation history with current
product status, so stale planning language looked authoritative.

## Solution

Tests now derive the `3.1.0` host behavior, exercise valid Plan-review rework
wiring, seed both Plan-review variables, and mirror the production rename
predicate. The HITL route harness includes gate-chat storage, feedback preview,
and the current supervisor-client surface. The agent-facing DSL grammar now
documents `settings.plan_review` and its engine floor.

Current docs distinguish the historical `3.0.0` graph-only cut-over from host
engine `3.1.0`. They record dogfood and external installations as an
owner-confirmed adoption signal, move the next validation gate to repeatable
core-package processes on private projects, and use the execution-and-
governance positioning across the product entry points.

## Prevention

- Treat an engine bump as a cross-surface contract change: update the constant,
  compatibility tests, fixtures, agent grammar, and current host-version docs
  in the same change.
- Keep reusable manifest fixtures compiler-valid, including rework feedback
  rendering and every runner-seeded variable.
- Make route-test harnesses fail when a newly imported dependency is absent;
  update table maps and module mocks in the same change as the service import.
- Keep shipped history intact, but put current sequencing and validation gates
  in one authoritative roadmap section.
