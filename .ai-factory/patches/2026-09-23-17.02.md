# Consensus draft selection and coordinator wake review fixes

**Date:** 2026-09-23 17:02
**Files:** `web/lib/flows/hitl-validate.ts`, `web/lib/domain-events/{outbox,coordinator-wake-intent}.ts`, `web/lib/flows/graph/{coordinator-wake,continuation-worker,runner-graph}.ts`, related tests and analytics
**Severity:** high

## Problem

The consensus HITL API accepted an allow-listed `pick-draft-N` even when the stored choice was unavailable, then the runner failed on resume. An orchestrator whose child failed before its park could remain parked behind a pending sibling. A child settling after park but before the one-shot catch-up could also strand either coordinator when the web process died. The P0-5 plan marked full qualification complete despite recording that its aggregate integration command never passed.

## Root Cause

Stable HITL slot numbering was mistaken for pickability in the response validator. The child event consumer discarded events while a parent was Running, while the post-park catch-up had no durable failed-child signal and ran only in the original process. The continuation worker selected deferred wakes but not an ordinary parked coordinator with zero pending children. The plan's checkbox status did not enforce its own release-gate wording. The claimed capacity wait for partial drafts was not reachable: `verifyConsensusRound` records the unpaid cell before the only call to `runVerifier`.

## Solution

Server validation rejects an explicitly unavailable stored draft choice before any HITL mutation, preserving partial and legacy choices. The child terminal-event writer arms an existing parent wake timestamp for a current orchestrator in the same transaction as the event. Post-park and the production continuation worker call the shared CAS wake; the worker selects a parked coordinator with zero pending children or a durable failure intent. A new node attempt clears an unconsumed marker, and a successful wake clears it through the existing state transition. Integration tests cover the early failure with a pending sibling, event replay, missed last-child wakes for both coordinator kinds, worker recovery with pending siblings, and the concurrent single-winner race. The capacity regression is asserted at the round seam without changing reachable production behavior. An ADR-177 fixture's global sweep count failed identically on detached master while the target row remained live, so its test now asserts only the target-row contract; the complete file passed afterward. Contracts and qualification status are reconciled to actual gates.

## Prevention

For decision lists, validate pickability from server-stored choice state separately from stable display slots. For parent/child races, hold the parent inside the park barrier and test both event delivery and process-independent continuation; an in-memory catch-up alone is not a recovery owner. Record a full-suite gate as complete only with a green command or an explicit, justified revised gate. Sibling sweep command: `rg -l 'kind: "run\.(failed|crashed|abandoned)"' web/lib -g '!**/__tests__/**' | sort`; its nine production files (`flows/graph/permission-rejection`, `flows/graph/runner-graph`, `flows/runner-agent`, `orchestrator/cascade`, `runs/keepalive-sweeper`, `runs/state-transitions`, `scratch-runs/events`, `services/hitl`, `workbench-lifecycle/service`) all feed `emitDomainEvent`, so the outbox choke point covers the class. `agents/finalization.ts` also emits a dynamically selected settled kind through the same writer.
