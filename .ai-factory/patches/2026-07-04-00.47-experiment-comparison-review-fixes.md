# Experiment Comparison Studio Review Fixes

**Date:** 2026-07-04 00:47
**Files:** experiment comparison service/routes/components, OpenAPI/docs, run-status writers, worktree diff helpers, targeted tests
**Severity:** critical

## Problem

Code review for `feature/experiment-comparison-studio` found the primary
experiment flow incomplete across backend, UI, contracts, and evidence capture.
Critical symptoms included broken multi-member launch, missing UI route callers,
budget restart refusal for active sibling members, unpinned restart worktrees,
comparison DTO/OpenAPI drift, inconsistent not-found semantics, incomplete
status-sync choke points, unsafe read-heal writes, raw replicate unique
violations, base-ref validation mismatch, missing judge contract, and incomplete
acceptance evidence.

A follow-up review found additional readiness gaps: truncated diff snapshots
produced incomplete file matrices, post-commit loser stop failures turned a
successful terminal transition into a 500, inherited/default runner overlays
skipped compatibility validation, comparison queue positions were always null,
the create/launch UI did not expose the documented variant/replicate range,
diff tabs rendered raw `<pre>` blocks instead of the ADR-066 diff stack, files
filters were static, and `abandon.reason` was accepted but silently dropped.

## Root Cause

- The implementation split core experiment behavior across route handlers,
  run launch, HITL, runner status writers, and read-time comparison projection,
  but the plan's cross-surface invariants were not wired at every writer/reader.
- Tests overused mocks and seeded SQL snapshots, so they proved DTO shapes and
  happy-path UI render states without exercising real launch gates, stop
  dispatch semantics, snapshot capture, or queue projection.
- UI work lagged behind the API contract: the server accepted 2..12 variants
  and 1..10 replicates, but the screen exposed only fixed A/B creation and
  hardcoded launch-all-once actions.
- Snapshot file summaries were derived from bounded diff text, conflating the
  display safety cap with the complete evidence needed for comparison.
- Contracts documented intent that was not backed by typed errors, route tests,
  or concrete OpenAPI/schema parity checks.

## Solution

- Fixed member launch and restart semantics: experiment membership can fan out
  under the intended force gate, budget restart preflight allows active sibling
  members, inherited relaunch/restart worktrees use the stored experiment base
  commit, replicate conflicts map to typed `CONFLICT`, and local/remote base-ref
  validation no longer disagrees for valid pinned bases.
- Added typed experiment not-found errors and consistent 404 mappings across
  comparison/detail/conclude/abandon/launch/judge/external read surfaces.
- Wired status recompute and snapshot capture through additional run-status
  writers, guarded read-heal updates with observed-status CAS, and kept terminal
  status writes from being overwritten by stale reads.
- Added `git diff --raw/--numstat -z` metadata capture so file summaries remain
  complete even when stored diff text is capped/truncated.
- Changed post-commit member-stop dispatch to continue through all runs, log
  per-run failures, and preserve the already-committed conclude/abandon result.
- Validated variant overlays against the inherited project/platform default
  runner before launch side effects, not only explicit per-variant runners.
- Projected scheduler queue positions into the comparison DTO for pending
  member runs.
- Reworked experiment UI actions: create supports dynamic 2..12 variants,
  launch supports variant subset plus 1..10 replicates, abandon/launch/judge
  actions call real routes with refresh/error handling, diff tabs use prepared
  ADR-066 diff data when available, and files filters/drilldown are interactive.
- Removed the unused `abandon.reason` body field from schema/OpenAPI instead of
  continuing to accept and drop it.
- Updated OpenAPI, analytics/docs, ERD/schema docs, screen docs, and i18n labels
  to match the implemented behavior.

## Prevention

- Keep experiment status recompute at every run-status writer that can put a
  member run into Review or a terminal state.
- Keep experiment status writes guarded by observed-status CAS unless the row is
  already locked and freshly read.
- Never derive durable comparison evidence from capped display text; capture
  complete metadata separately from bounded UI payloads.
- Treat post-commit best-effort side effects as reported/logged outcomes, not
  as reasons to fail a committed terminal transition.
- Validate capability overlays against the effective inherited runner before
  any launch side effect.
- For new external/web experiment DTO fields, update code, OpenAPI, screen docs,
  analytics docs, and tests in the same patch.
- Avoid route branching on error strings; add typed domain errors when a known
  experiment failure needs consistent API semantics.
