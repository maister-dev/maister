# Close every allocation and mutable-definition path behind durable admission

**Date:** 2026-11-03 17:38
**Files:** web/lib/tasks/launch-intent.ts, web/lib/tasks/launch-dispatch-claim.ts, web/lib/tasks/launch-first-dispatch.ts, web/lib/services/runs.ts, web/lib/db/migrations/0225_task_launch_agent_preparation.sql
**Severity:** high

## Problem

Legacy Flow allocation could create a qualified Run without a durable launch
intent. Child preparation could allocate a checkout before discovering exhausted
parent capacity. Accepted runner identities could acquire a misleading override
provenance, and runtime readers could parse a revision manifest changed after the
user previewed it. A queued trigger acknowledgement also could not later bind its
reserved Run under the older immutable-settlement rule.

## Root Cause

Qualification, a mechanical trigger and an interactive decision were treated as
interchangeable entrypoint metadata. Freezing IDs did not freeze mutable definition
content or original runner resolution provenance. Shared child workspaces were
incorrectly treated like private pristine checkouts. Historical queued receipts
assumed their Run already existed, while the new admission boundary deliberately
persists authority before allocation.

The command guard initially acquired the parent hierarchy after an UPDATE had
already locked the command row, reversing owned-prompt replay's order. A real SQL
barrier reproduced PostgreSQL `40P01`. Separately, removing early batch Run locks
for the new intent order also removed legacy continuation `SKIP LOCKED`; an
existing sweep barrier then waited on the very row it was meant to skip.

## Solution

The common private engine accepts branded durable execution authority; old public
allocators refuse explicitly. Child admission rechecks the exact current parent
proof, reserves live fanout during preparation and excludes that reservation while
binding. Queued children wait without spending a preparation attempt. Shared
children bind the actual root resource and immutable seed while baselining its
current contents. Runner slots retain their original resolution tier.

Preview tokens cover actual manifest content. Acceptance holds a revision share
lock through intent insertion, and SQL prevents changing a referenced manifest or
digest. A narrowly scoped trigger-receipt transition can link only the reserved
Run belonging to the exact accepted source, preserving settlement and history.
Fresh and populated migration checks retain old receipts and reject forged links.

Outbound V3 command transitions and rearm now lock parent, node attempt and child
before the command row. Terminal receipt recording and non-V3 transaction
boundaries retain their prior semantics. Legacy/already-committed C1/C3 candidates
claim one Run with `SKIP LOCKED` at their own admission edge; first-dispatch intents
retain task-reservation-first ordering.

## Prevention

- Inventory concrete allocation callers, including aliases, retries, internal
  children and taskless procedures; an enabled UI action is not admission proof.
- Separate authenticated service authority from database writer compatibility.
- Freeze resolved content and provenance, then consume those outputs at the
  actual model/command boundary; immutable IDs alone are insufficient.
- Test real reservation, binding and mutation races using owned PostgreSQL/Git
  fixtures, including the losing request and zero-effect refusal paths.
- Keep queued capacity separate from spent tree budget and from source failure;
  never turn capacity waits into permanent failures or invented qualification.
