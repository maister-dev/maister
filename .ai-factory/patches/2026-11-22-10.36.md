# Verify review outcomes at their destination

- **Date** 2026-11-22 10:36
- **Files** `web/lib/queries/inbox-review-actions.ts`, `web/lib/queries/knowledge-memory-reviews.ts`, `web/lib/tasks/launch-capability-materialization.ts`
- **Severity** high

## Problem

An outcome could link an authored rule to a Flow writer. The queue could offer
actions that the domain refused or apply an operation for a disabled binding.
Preview continuations could cross personal credentials, and a multi-note
receipt exposed only its first 20 result links. A package companion could pass
capture validation and disappear from the delivered tree.

## Root cause

The tests checked each projection in isolation. A route prefix passed without
opening the stored draft. Owner grants passed without checking the restricted
record action. A final symlink destination passed without checking its
intermediate directories. Review invalidation tracked pending queue state,
which could remain unchanged while an open history item became inaccessible.

## Solution

Check stored capability kind at the Flow write boundary. Reuse domain
availability and record-grant predicates across review readers and writers.
Bind continuations to the issued credential and exact operation or proposal
snapshot. Revalidate the selected review through the existing attention
stream. Verify every link hop against the actual trees that will be delivered.

## Prevention

Follow a retained reference to its destination in a browser or through the
real API. Test direct and replay callers under changed authority. Use a
multi-page result where the final item has a distinct persisted identity.
Verify companion readability in the projection after capture cleanup.

The call-site sweep used these searches.

```sh
rg -n 'assertCapturedProjectionSymlinks|captureAcceptedDirectory\(' web/lib/tasks --glob '!**/__tests__/**'
rg -n 'parseReviewContinuations\(|projectVaultOutcome\(|readBrainProposalDraftContent\(' web/lib web/app --glob '!**/__tests__/**'
```

The first search found the task bundle and task agent package subset consumers.
Both validate projected links. The Flow asset capture keeps the complete tree.
The second found both authenticated review GET adapters, the receipt and
detail outcome projections, and the separate task and preview consumers of
draft text. Task projection trims as before, while review preserves the stored
text.
