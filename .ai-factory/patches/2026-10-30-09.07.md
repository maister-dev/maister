# Resolve stale integration-branch conflicts without duplicating review UI

**Date:** 2026-10-30 09:07
**Files:** web/app/(app)/runs/[runId]/layout.tsx, web/components/board/__tests__/project-tabs.test.ts, web/components/board/hitl-decision-controls.tsx, web/components/board/run-hitl-response.tsx, web/components/runs/review-panel.tsx, web/components/social/__tests__/task-complete-action.dom.test.ts, web/messages/en.json, web/messages/ru.json
**Severity:** medium

## Problem

The published `integration/dogfood-sdlc` branch no longer merged cleanly with `master`. Git reported eight conflicted files after already-merged split commits and later formatting and runtime work changed the same review, HITL, and translation regions.

## Root Cause

The integration branch retained the original dogfood commit series while equivalent split commits landed independently on `master`. Git could not identify all semantic equivalences across the rewritten histories. Conflict-free portions also combined both the older `primaryResult` rendering path and the branch's newer `flowContent` path, so removing markers alone would have left duplicate controls and an undefined reference.

## Solution

Merged current `master` without rewriting the published integration history. Preserved the branch's review-mode hierarchy, durable conflict-resolver state, manual-takeover labels, and final Russian terminology while accepting current formatting where semantics matched. Removed the auto-merged duplicate result and promotion-control blocks, then verified the merged tree with TypeScript, focused review/HITL/i18n tests, contract validation, supervisor and MCP typechecks, and the MCP build.

## Prevention

- After a stacked or extracted commit series lands, refresh long-lived integration branches promptly.
- During conflict resolution, search for both conflict markers and duplicated semantic identifiers; an automatic merge can be syntactically clean while retaining both implementations.
- Validate published branch merges with focused behavior tests plus typechecking before pushing.
