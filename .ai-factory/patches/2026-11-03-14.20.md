# Verify copied capability bytes before using them

**Date:** 2026-11-03 Europe/Moscow
**Files:** `web/lib/tasks/launch-capability-materialization.ts`, `launch-execution.ts`, `web/lib/capabilities/materialize-bundle.ts`, accepted-engine and real-filesystem copy regressions
**Severity:** high

## Problem

Before and after hashes of an installed capability bundle did not prove which bytes were copied into an accepted task checkout. A deterministic temporary mutation could restore the original source while the checkout contained different material; first-dispatch admission accepted that checkout.

## Root Cause

The accepted identity described the mutable source, while materialization consumed that source independently. The final checkout receipt recorded the resulting bytes without comparing them with the accepted bundle identity. Source equality around an effect does not establish output equality.

## Solution

Capture each complete bundle into a private preparation-owned directory and verify that capture against the accepted content digest before using it. The accepted effect receives only verified capture paths, never re-resolves live project imports. Preserve internal relative symlink text, reject escaping or unmaterialized targets without dereferencing their contents, and remove only the owned capture before sealing the receipt. Keep historical copier semantics through explicit copier composition rather than changing legacy behavior globally.

## Tests and prevention

The real PostgreSQL/Git/native-copy reproducer paused the exact copy boundary, changed A to B, copied B, restored A, then successfully bound and committed the incorrect checkout on the old path. The regression subsequently expected refusal and failed (`/private/tmp/maister-launch-capability-ABA-red.log`). With verified capture it refuses `launch_capabilities_changed` before Run/session/dispatch creation. Valid capture, repository-local precedence, internal-link survival after capture cleanup and invalid target links pass alongside existing materialization tests: 7 integration checks and 9 real-filesystem unit checks (`/private/tmp/maister-launch-capability-ABA-final.log`, `/private/tmp/maister-launch-capability-legacy-unit.log`). No model or remote repository was used.

When freezing a content identity, trace the exact bytes consumed by the effect. A source hash immediately before and after copying is insufficient against change-copy-restore. Verification must cover the immutable captured input or expected copied output. Final full feature qualification remains tracked in the active plan.
