# Align vault disclosures, review lock order, and witness relations

- **Date** 2026-11-22 17:21
- **Severity** high

## Problem and root cause

- The legacy native knowledge reads resolved global personal tokens without the
  source policy used by the personal revision endpoint. Direct REST and
  installed MCP could expose vault-dependent data under `knowledge:read` or
  a wildcard. Collection continuations could also reveal a concealed result.
- History could hold a share lock on a source payload while redaction held a
  dependent proposal row and attempted to delete that payload. History then
  waited for the same proposal. The PostgreSQL barrier regression recorded
  `40P01` while the transactions waited on each other.
- A correction keyed retained and added evidence by witness ID alone. Firefox
  showed that submitting an inspected witness as `supports` lost the selected
  relation when the same exact witness was already linked as `derived_from`.

## Resolution

- The common external read adapter now selects the source-scoped principal for
  global personal credentials. Proposal inspection checks reviewer or proposer
  authority with the current credential and uses the source-scoped principal
  for disclosure and pagination. OpenAPI, MCP tool descriptions and system
  analytics record the same conditional `agent_memory:read` requirement.
- Vault review detail and settlement acquire the shared redaction fence before
  reading source authority or touching dependent rows. The redactor acquires
  the exclusive form of the same advisory lock. The regression confirms that
  redaction completes and a waiting History request conceals the withdrawn
  proposal content. The advisory key stays compatible with existing workers.
- One serializer preserves witness ID, version, digest and relation across
  retained, inspected and captured evidence. Firefox checks the HTTP request and
  stored proposal for both distinct links and for an identical relation kept
  once. Both links use the existing draft evidence schema.

## Prevention

Exercise complete source graphs with the same credential across existing and
new reads. Verify both exact lookups and collection membership before
pagination. For shared payload/proposal transactions, park the exclusive
operation between acquiring the dependent row and removing its source, then
assert the production lock order with real PostgreSQL. Assert the retained
relation and exact reference after a correction reaches storage.
