# Agent runner parity review blockers

**Date:** 2026-07-07 18:04
**Files:** `web/app/api/projects/[slug]/agents/[agentId]/launch/route.ts`, `web/app/api/projects/[slug]/agents/[agentId]/launch/__tests__/route.test.ts`, `web/lib/agents/dirty-watchdog.ts`, `web/lib/agents/__tests__/dirty-watchdog.test.ts`, `supervisor/scripts/smoke-acp-adapter.ts`, `supervisor/src/adapter-smoke-cache.ts`, `supervisor/src/__tests__/adapter-smoke-cache.test.ts`, `docs/supervisor.md`, `docs/system-analytics/acp-runners.md`, `docs/api/supervisor.openapi.yaml`
**Severity:** high

## Problem

Review found three blockers in the agent runner parity branch:

- The manual agent launch OpenAPI/screen contract documented `workspace?`, but the route schema rejected it and never forwarded it to `launchAgentRun`.
- The dirty-watchdog trusted repo-local `.maister/agent-package-skills.json` paths for deletion and porcelain filtering, allowing traversal strings or empty paths to bypass or damage the cleanup boundary.
- Read-only-session smoke diagnostics claimed adapter permission-wire proof even though the generic smoke CLI only ran initialize/newSession plus local supervisor arbitration.

## Root Cause

The defects shared one pattern: contract wording moved faster than the executable boundary checks. The route contract was updated without a route-level test. The manifest cleanup path treated a MAIster-written file as trusted after it lived inside the checkout being policed. The smoke cache treated a local arbitration check as equivalent to adapter-specific prompt/permission evidence.

## Solution

The route body schema now accepts `workspace: "none" | "repo_read" | "worktree"` and forwards it to `launchAgentRun`. Dirty-watchdog manifest restore now accepts only normalized relative package-skill paths under `.claude/skills` or `.gemini/skills`, removes the manifest without touching user settings unless the MAIster marker exists, and filters porcelain by parsed path boundaries instead of substring matching. The smoke CLI now reports read-only-session evidence as `skipped` until a dedicated adapter prompt/permission probe exists, and diagnostics ignore `ok` read-only evidence when the generic adapter smoke itself was skipped or failed.

## Prevention

- For route contract changes, add route-level tests that assert the documented body fields are accepted and forwarded.
- Treat repo-local restore manifests as untrusted input even if MAIster wrote them earlier in the same lifecycle.
- Do not cache `ok` operational evidence unless the code path actually exercised the behavior described by the contract.
- During review fixes, grep sibling contract surfaces and update code, tests, OpenAPI, and analytics together.
