# Close scheduler-clock and event-lag review gaps

**Date:** 2026-09-22 19:03 (Europe/Moscow)
**Scope:** P0-6 scheduler clock and P0-7 execution-event lag observability
**Severity:** high

## Problem

The first implementation exposed the requested operator surfaces, but review
found three correctness gaps and several contract inconsistencies:

- a lag incident disappeared when its active stream became `lost` or `closed`,
  so the documented `inactive` / `reset` transition and its log were
  unreachable;
- `MAISTER_EVENT_STREAM_LAG_SECONDS` was parsed in the supervisor health path
  instead of at web boot, turning invalid process configuration into repeated
  request failures;
- authoritative lag transition logs were published after the scheduler CAS but
  had no scheduler-level proof that a fenced owner remains silent.

The read model also clamped a consumer cursor ahead of its run horizon to zero,
the performance qualification was smaller than the plan claimed, malformed
poison cursors were treated as the first page, and several UI, documentation,
and single-source-of-truth details had drifted.

## Root causes

- The collector returned only the newest 20 streams, and the selection step
  considered active streams only. Once the previously observed identity left
  `active`, the reducer received no sample to close its open incident.
- The lag threshold accessor still read `process.env` from a frequently called
  client path. No boot entry point initialized and retained the validated value.
- Tests stopped at the pure observation builder and did not drive
  `runSchedulerTick` through the durable attempt-result CAS.
- Consumer backlog SQL used `GREATEST(distance, 0)`, which made corrupted or
  inconsistent cursor ordering indistinguishable from a healthy zero backlog.
- The plan's intended production and test boundaries were not consistently
  carried into docs, fixtures, and shared predicates.

## Fix

- The lag collector accepts the previous stream identity and fetches that exact
  row inside the same read-only repeatable-read transaction when it is outside
  the bounded normal page. The reducer now emits `inactive` with `reset` for a
  lost or closed prior stream, preserves an open incident on incomplete samples,
  and resets identity only from a complete replacement sample.
- Observation freshness is at least two scheduler cadences, with a 120-second
  floor, so an operator-edited cadence does not silently invalidate every
  comparison.
- The consumer query returns `backlog = null` plus
  `cursor_ahead_of_horizon`; aggregate diagnostics and bounded diagnostic rows
  are exposed in the admin model. An inconsistent projection cannot report a
  recovered incident.
- The read-only analytics transaction has a two-second PostgreSQL statement
  timeout. The populated qualification uses 50,000 runs, 1,000 active runs,
  2,000 consumers, warm samples, and `EXPLAIN (ANALYZE, BUFFERS)`.
- Web instrumentation validates `MAISTER_EVENT_STREAM_LAG_SECONDS` before
  recoverable boot work and stores milliseconds once. Transports receive that
  number; supervisor health no longer parses process configuration.
- Scheduler integration coverage now proves exactly one lagging WARN and one
  recovered INFO after a successful attempt CAS, and no transition log when the
  attempt loses its lease.
- Admin authorization shares the global-role predicate, poison pagination
  rejects repeated, partial, empty, or oversized cursors, and the E2E fixture
  uses a unique cursor plus `try/finally` cleanup.
- Scheduler and execution-host dates use the requested locale with an explicit
  UTC timezone. The clock card has an overdue state; lag and watermark
  abbreviations have legends; durations are decomposed into hours, minutes, and
  seconds.
- Dead clock DTO data, retired Brain-card messages, a dead consumer-backlog
  helper, duplicated terminal-attempt literals, and the separate admin-access
  module were removed. The timer state-key and numeric SQL cast now state their
  non-obvious reasons.
- Architecture, roadmap, contracts, analytics, screen references, retired-env
  guidance, and ADR-033 were aligned. The OpenAPI and database-schema changes
  are surgical relative to the feature base instead of reformatting unrelated
  content.

## Defect-class audit

- Every production caller of the lag threshold now receives the boot-cached
  value or the explicit protocol default used by isolated client tests.
- Every lag transition log call remains downstream of
  `recordJobAttemptResult`; both success and system-sweep failure paths return
  before publication when their CAS is fenced.
- Lost/closed, replacement, incomplete, stale, advancing, clear, and
  cursor-inconsistent samples have explicit reducer or integration coverage.
- No stall/lost transition function changed. Lagging remains a computed
  observation and never writes a stream state.
- The scheduler observation index remains physically ascending; PostgreSQL
  serves the descending prior-attempt lookup with a backward index scan, now
  described consistently in the plan and analytics docs.

## Prevention

Any derived incident state must test how it closes when its source row leaves
the query's normal eligibility set. Configuration promised as a boot contract
must be parsed at the boot boundary and passed as data through request paths.
Logs that claim scheduler authority require a test on both sides of the durable
attempt CAS. Arithmetic inconsistencies must remain observable instead of being
coerced into healthy values.
