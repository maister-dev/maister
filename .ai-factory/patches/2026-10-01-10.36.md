# Classify child crashes independently of permission delivery timing

**Date:** 2026-10-01 10:36 UTC
**Files:** `web/lib/flows/graph/node-prompt-owner.ts`, owning prompt/permission-resume integration tests, ADR-177 and prompt lifecycle G0
**Severity:** high

## Problem

A real adapter child death could leave its Flow in `NeedsInput` forever when a
permission notification arrived between prompt-owner preparation and application.
The command became `superseded`, no action completion existed, and reattachment
could not settle the park.

## Root Cause

Preparation classified crash evidence only for a snapshot of `Running`.
Application accepted the same current owner in `NeedsInput`, but then rejected
the previously proved crash solely because the run had become parked. An
immutable causal fact was incorrectly conditional on mutable delivery timing.

## Solution

Read exact accepted crash evidence independently of the pre-lock status, then
recheck ownership, current state and evidence under the run/attempt locks.
The existing lost-turn boundary closes either current state and its permissions
atomically. Host-pressure and turn-lost precedence, genuine action failures and
successor/attempt fences remain intact. The structured crash log includes the
locked source status. No new status, error, migration or API is introduced.

## Verification

Real Postgres/supervisor RED controls killed the actual adapter and scheduled
production permission projection between prepare and apply. Both owner variants
failed with `NeedsInput` instead of `Crashed`: `/private/tmp/r1-red.json` and
`/private/tmp/r1-resume-red.json`. Parameterized existing recovery controls cover
the unparked turn, a park before preparation, and a park after preparation,
asserting closed permissions, no action completion and one replacement prompt.
All three new schedules pass on the final typed fixtures in
`/private/tmp/r1-final-controls.json`. The five complete sibling suites pass
39/39 without skips in `/private/tmp/r1-siblings-green.json`. Final full-family
qualification passes 63/63 in `/private/tmp/r1-owner-full-final.json`, giving
102 distinct integration cases in six files with no skips. The initial combined invocation
was interrupted without a final reporter: a lingering fixture dominated its
log tail while later cases were still progressing. It is not treated as a
failed test verdict or a successful qualification; the complete prompt-owner
file was rerun successfully with per-case progress before closure. All owned
test processes and containers were stopped.

The first GREEN attempt exposed an overstrict assertion: unanswered Flow
permissions close with `responded_at` while `response` remains NULL. The test
now asserts that existing contract without changing production closure semantics.

## Prevention

Prepare immutable evidence outside a transaction, but evaluate mutable owner
state inside its lock. A valid state transition of the same owner must not
discard its evidence. Exercise permission scheduling around both prepare and
apply, and settle every detached driver/recovery promise in each case.
