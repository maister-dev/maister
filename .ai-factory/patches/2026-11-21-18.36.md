# Retain workspace integrity evidence across lifecycle transitions

**Date:** 2026-11-21 18:36 MSK
**Files:** `web/lib/agents/continuation-episode.ts`, `web/lib/tasks/launch-dispatch.ts`, `web/lib/gc/operational-disposition.ts`, `web/lib/specialist-assignments/workspace-view.ts`, `web/components/runs/run-peek-content.tsx` and their readers and tests
**Severity:** high

## Problem

An integrity stop could leave a run without the measurements that explained it. A later verification could succeed after the limit changed. A cleanup retry could display the prior attempt's threshold while the new check was still running. Company Flow cleanup and compact Run Peek also missed parts of the operator guidance.

## Root cause

The check wrote precise evidence into its error, but downstream state owners reconstructed the failure from reason codes. The bound task writer was attached to a sibling transition. Cleanup spread old diagnostic fields into a new attempt. Assignment and Peek readers omitted the state and viewer context they needed.

## Solution

Retain the bounded evidence on the continuation episode, current held intent revision, terminal cause, or failed cleanup attempt. The existing ownership transition and its diagnostic now commit together. Read authorized Company Flow causes and cleanup outcomes in one query. Supply the selected Run ID and the current global administrator capability to Peek.

## Prevention

Trace each writer to the state it actually commits and each reader to the matching attempt. Use the same fixture to exercise a limit refusal, independent settings reset, and a later read. Pause a retry before it completes to verify that current advice changes at the start boundary. When a filesystem barrier matches a path, use the canonical path and assert that the barrier won the race with completion. Otherwise an ancestor alias can silently turn a concurrency test into a sequential test.

The sibling sweep used `rg -n 'inspectOperationalWorkspace\(|<OperationalOutcomeDetails|readAssignmentRunSummaries\(|loadTaskLaunchIntegrityLimit\(' web/lib web/components web/app`. Production workspace inspection flows through `operational-context.ts`, `company-flow-workspace.ts` and `operational-disposition.ts`. All supply an explicit stage. Full Run and Peek both supply the role and Run ID. Assignment details and pending Run details use their authorized summary and held-intent readers. The Running delivery path uses its terminal cause once the Pending intent reader ceases to apply.
