# Keep package API descriptions aligned with attachment lifecycle

**Date:** 2026-11-10 09:57 UTC
**Files:** docs/api/web.openapi.yaml, docs/system-analytics/packages.md
**Severity:** medium

## Problem

The package DELETE API description still promised the retired non-terminal-run
guard after implementation and domain documentation adopted attachment-pinning
lifecycle checks. The adjacent upgrade description omitted evidence retention
and legacy-run refusal, and both descriptions still claimed configuration
write-back despite routes requiring separate reviewed persistence.

## Root Cause

The guard sweep covered execution and domain documentation but missed the
OpenAPI operation's narrative contract. Schema validation cannot detect a
semantically obsolete description.

## Solution

Describe finalized archival, durable execution quiescence, shared workspace
checks and historical preservation in DELETE. Document `package_run_pinned`
with `details.blockers[]` and each blocker's run ID, status and reasons. Align
upgrade with retained immutable revisions and `historical_revision_missing`.
Replace the Expectations bullet's incorrect directional reference with an
anchor link and restore the original crash-window table formatting.

## Assumptions and verification

This rework changes documentation only. Runtime behavior is checked against
`run-pins.ts`, `attach.ts` and the two route handlers. No production fix or test
behavior is changed. The review reports real-Postgres mutation RED/GREEN,
43/43 attachment tests and 155 contract-scoped integration tests passing; these
are reviewer-supplied results, not reruns performed in this documentation turn.

Local checks passed: `CI=true pnpm validate:docs:all`,
`CI=true pnpm validate:contracts`, and `git diff --check`. Initial sandboxed
validation hit tsx IPC EPERM; both complete validators passed with escalation.
The OpenAPI formatter flags only pre-existing sections outside these edited
descriptions; its output leaves both changed operation descriptions unchanged.

The atomic-test permission assertion is confirmed in source, and neither that
file nor supervisor code changed in the implementation commit. Their reported
host failures are outside this documentation correction; no finding is rejected.

## Prevention

When replacing a guard's lifecycle semantics, sweep its OpenAPI description and
adjacent mutations as well as schemas, implementation and domain docs. Validate
descriptions against the actual refusal payload, since valid YAML can still
describe a retired rule. Avoid unrelated Markdown table reformatting.
