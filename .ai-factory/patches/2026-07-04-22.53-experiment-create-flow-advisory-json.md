# Experiment create flow and advisory JSON contract fixes

**Date:** 2026-07-04 22:53
**Files:** web/components/experiments/create-experiment-modal.tsx, web/components/experiments/__tests__/experiment-list.test.ts, web/app/(app)/projects/[slug]/experiments/page.tsx, web/lib/experiments/service.ts, web/app/api/v1/ext/projects/[slug]/experiments/[experimentId]/advisory/route.ts, web/app/api/v1/ext/projects/[slug]/experiments/[experimentId]/advisory/__tests__/route.test.ts, web/messages/en.json, web/messages/ru.json
**Severity:** high

## Problem

The experiment create modal could create or select tasks that had no launchable
Flow binding. Inline-created tasks omitted `flowId`, while existing task options
included flowless tasks. Those experiments could be created but later failed at
launch when `launchRun` required a Flow. The external experiment advisory route
also let malformed JSON escape before zod validation, producing an unhandled
error instead of the documented 422 `CONFIG`.

## Root Cause

The experiment create UI treated task creation as equivalent to board task
creation, where flowless simple-intent tasks are valid. Experiment launches have
a stricter contract: every member run is a normal run launch and therefore needs
a configured Flow. The modal did not carry that downstream precondition into its
own task picker or inline task payload. The advisory route placed `await
req.json()` directly inside `safeParse`, so JSON parser failures happened before
the route's body-validation response branch.

## Solution

Added a project experiment Flow-option query, passed the options into the modal,
filtered existing task choices to tasks whose `flowId` exists in that option
set, and included a required `flowId` when creating an inline task. Added EN/RU
labels and focused render coverage for the launchable-task picker contract.
Changed the advisory route to parse JSON at the boundary and map malformed JSON
to 422 `CONFIG`, with focused route coverage. Added structured debug logs with
`[FIX:experiment-create-flow]` and `[FIX:experiment-advisory-body]`.

## Prevention

- When a create UI feeds a later launch path, carry downstream launch
  preconditions into the picker and inline-create payload.
- Route body parsing should happen in an explicit boundary step before zod
  validation so syntax failures map to the same contract family as schema
  failures.
- Review tests should cover the user-facing form path, not only direct API
  routes with hand-filled complete payloads.
