# Preserve authority and fidelity in knowledge review

- **Date** 2026-11-22 14:54
- **Files** Knowledge settlement and personal revision reads, retained vault review, Inbox History, vault comparison, and proposal form
- **Severity** high

## Problem

Replaying structured knowledge could return a different reviewer's decision or
mint a second Inbox receipt. A personal revision list could expose a
vault-derived title without the exact vault scope. Redaction hid the selected
review detail while leaving its path in History. Vault comparison paired unequal
content ranges, the proposal form dropped unresolved evidence references, and
an installation history read repeated source checks under an exclusive vault
lock.

## Root Cause

The native decision digest identified the command but omitted the retained
actor. Inbox projected the result after a replay without requiring a local prior
receipt. The new personal revision adapter resolved its token as an ordinary
knowledge principal, which lost the vault-specific disclosure rule. The History
list depended on the pending-queue invalidation counter. Comparison combined
full historical content with one current note page. The evidence field and
submission shared no readiness check. History re-used the write admission path
and checked each base and result independently.

## Solution

Require the original reviewer and current grant plus exact result access for a
native replay. Inbox reuses its original receipt and refuses a replay from a
different decision entry point without one. The personal revision adapter keeps
the exact vault scope in the source authorization context. The selected review
signal revalidates the filtered History page in place. Compare equal bounded
prefixes from the beginning and use complete content hashes for equality. Block
submission while a witness ID remains unresolved. History authorizes the union
of retained sources and holds shared locks on the proposal and payloads.

## Prevention

- Assert original and competing actor outcomes and persisted receipt count
  across both review surfaces. Include revocation while the caller can still
  read the record.
- Use the same vault-derived record to check minimal personal scopes over REST
  and installed MCP. Assert the exact scope omission, including wildcard.
- Test redaction against every visible projection of the selected item,
  including the filtered count. Compare long unchanged and changed note
  revisions. Verify that a delayed witness lookup cannot change the submitted
  evidence silently.
- Measure database statements against small and large sets with identical
  sources. Verify a separate transaction can acquire the vault row write lock
  during retained history inspection.

The sibling sweep used:

```sh
rg -l 'reviewKnowledgeProposal\(|listKnowledgeRevisions\(' web/app web/lib/queries mcp/src --glob '!**/__tests__/**'
rg -l 'readVaultReviewHistory\(|<KnowledgeProposalForm|compareVaultRevision\(' web/app web/components web/lib/queries --glob '!**/__tests__/**'
```

The first command found two native decision routes and the Inbox wrapper.
They share the native replay check. It also found the browser record page and
browser/bearer revision routes. Only the new personal bearer adapter needs the
exact scope, and the personal MCP tool uses that adapter. The second command
found the settled Inbox detail reader, the comparison component and request
helper, and both proposal creation and correction pages. Both forms share the
same evidence guard. Pending decisions still acquire the vault write lock.
