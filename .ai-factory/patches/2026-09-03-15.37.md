# A refused abandon destroyed the sub-tree it refused to abandon

**Date:** 2026-09-03 15:37
**Files:** web/app/api/runs/[runId]/abandon/route.ts, web/lib/reconcile.ts,
web/app/api/runs/[runId]/abandon/__tests__/abandon.integration.test.ts,
docs/system-analytics/orchestrator.md
**Severity:** high

## Problem

Four call sites were filed as sharing an unfenced cascade-then-CAS shape (cascade
the whole run-tree to `Abandoned`, then CAS the root; if the root moved in
between, descendants stay dead with no compensation). Investigating each one
individually, only ONE was a real defect — and it was not the race it was filed
as.

`POST /api/runs/{runId}/abandon` cascaded the orchestrator's whole sub-tree with
**no abandonability check at all**. The only guard was `markAbandoned`'s
status-CAS, which runs AFTER the cascade. So abandoning an already-terminal
orchestrator (`Done`/`Failed`) that still had live descendants **deterministically**
destroyed every one of them and then returned `409 "run is not in an abandonable
state"` — a rejected request with an irreversible side effect, and no signal to
the operator that their children had just been killed. No concurrency required.

The existing `409 on an already-terminal run` test missed it because its run has
no children, so it never enters the cascade branch.

## Root Cause

**Validate-then-mutate was inverted, and the CAS was mistaken for the guard.** A
status-guarded CAS is an excellent *concurrency* control and a terrible
*precondition* check: it fires at the end, so everything irreversible done before
it has already happened when it refuses. The cascade is irreversible by design
(rows-before-teardown, `cascade.ts:213-214`), so ordering it ahead of the only
status check turned a refusal into a destructive operation.

The filing itself had a second cause worth recording: the four sites were grouped
by a *grep for the cascade call*, not by verified control flow. Pattern-matching
found the shape; only reading each caller showed that two of the four have no CAS
exposure at all and a third is already correct.

## Solution

- **Abandon route:** check `run.status` against `ABANDONABLE_STATUSES` (plus
  `HumanWorking`, which the transaction releases to `NeedsInput` first) and return
  the identical 409 **before** the cascade. Scoped to `runKind === "flow"`, the
  only kind that cascades. Test: a terminal orchestrator with a `Running` child
  now gets 409 with the child untouched (failed before the fix with
  `expected 'Abandoned' to be 'Running'`).
- **reconcile `orchestrator-stuck`:** left behaviourally unchanged — the lost CAS
  there IS a genuine narrow race — but its `log.info "skipped crash"` became a
  `log.warn` naming the already-cascaded sub-tree. "Skipped" told an operator the
  tick was a no-op when in fact the coordinator was left `Running` with its whole
  sub-tree `Abandoned` beneath it.
- Recorded the invariant in `docs/system-analytics/orchestrator.md` Edge cases: a
  refused tree-cancel MUST NOT cascade, and a genuinely-lost CAS after a cascade
  MUST be surfaced (409 or WARN), never a silent skip.

**Verdicts — two of four sites needed nothing:**

| Site | Verdict |
|---|---|
| `abandon/route.ts:123` | **REAL, deterministic** → fixed + test |
| `reconcile.ts:1268` | Genuine narrow race, silent → WARN only |
| `workbench-lifecycle/service.ts:1667` | **Nothing** — pre-checked via `requireActionAllowed`, and its policy set (`FLOW_STOP_STATUSES`) matches the CAS guard (`STOP_STATUSES`) exactly; a lost CAS throws `CONFLICT` → 409 |
| `delegate/route.ts:431` | **Nothing — MISFILED.** No CAS follows that cascade; the branch's precondition is that the parent is already terminal, and it returns immediately ("the already-terminal parent is untouched") |

## Prevention

- **A status-guarded CAS is not a precondition check.** If a handler can refuse,
  validate before the first irreversible act. Ask of any destructive call: "if the
  CAS below loses, what did I already do?"
- **A refused request must leave no trace.** Treat a 4xx path that has already
  mutated as a defect regardless of how narrow the trigger looks.
- **Group defects by control flow, not by grep.** A shared callee is a hypothesis;
  confirm each caller actually reaches the hazardous sequence before filing them
  as one class. Here it halved the work and exposed the one real bug.
- **Check whether a "race" is actually deterministic** before writing the fix — the
  test is far cheaper and far more convincing when no interleaving is needed.
- **Misleading log wording is a defect too.** "Skipped" for a path that already
  destroyed a sub-tree will send the next on-call reader in the wrong direction.
- When a test for a refusal exists, check it exercises the *expensive* branch —
  the terminal-run 409 test passed throughout because its run had no children.
