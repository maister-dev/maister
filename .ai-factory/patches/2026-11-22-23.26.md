# Preserve Flow session identity across gate chat and approval

**Date:** 2026-11-22 23:26 MSK

**Severity:** high

**Files:** `web/lib/services/gate-chat.ts`, `web/lib/services/hitl.ts`,
`web/lib/execution-host/owned-session-create.ts`,
`web/lib/execution-host/create-ack.ts`,
`web/lib/flows/graph/runner-core.ts`, and their regression tests.

## Problem

Gate chat on a paused Flow could store a second logical session named
`default` with the planning session's ACP handle and no runner. An approved
plan review then stayed at `NeedsInput` because the graph could not load its
runner. Direct answers after idle checkpointing could also wake the graph with
a released assignment.

## Root Cause

Gate chat passed the active runner and ACP handle to session creation while
omitting the logical session name. The create receipt applied to the implicit
`default` slot, which the graph loader always preferred. The direct idle
answer path changed the run status without minting the next assignment.

## Solution

Gate chat carries the logical name, frozen runner, and ACP handle from one
session. Live reuse requires its host session ID. Admission checks the retained
ACP handle under the logical session lock, and receipt application checks the
same binding before updating it. An obsolete receipt can still be projected as
history. Flow and scratch idle resume already pass their selected session
name. Librarian and scratch launches prepare their single `default` session.
Graph substeps prepare their own named sessions. Compatibility creates and
teardown keep their existing lifecycle contracts.

The project graph loads runner configuration and resume handles from
configured rows. For an all-named Flow, its existing default runner context
can be built from a configured row without carrying the orphan's handles.
Idle human answers use the shared capacity-checked resume transition. Existing
plan-review reconciliation retries delivered answers when the immediate wake is
lost.

## Prevention

Check the session name, ACP handle and runner together at admission and receipt
application. Exercise idle chat, missing live processes, direct idle approval,
and retained binding-only rows using the graph driver and PostgreSQL. Check
the completed attempt and next node, since a successful HITL response alone
only proves delivery.
