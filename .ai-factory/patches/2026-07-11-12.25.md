# Post-commit agent materialization recovery

Date: 2026-07-11 12:25 MSK
Files: `web/lib/agents/launch.ts`, `web/lib/agents/dirty-watchdog.ts`, `web/lib/agents/materialization-manifest.ts`, adapter contract tests and validators
Severity: critical

## Problem

Terminal agent finalization released filesystem materialization inside the DB
transaction. Expected ownership refusals could roll back the terminal status
and leave a crashed run stuck forever. Ownerless locks, preparing intents,
foreign leases, and releasing retries also had incomplete recovery semantics.

## Root Cause

The terminal boundary mixed transactional database state with fallible
filesystem cleanup, while the ownership state machine assumed every run record
had already reached `active`. Lock staleness depended on an owner file that may
not exist after a crash, and preparing rollback treated every uncommitted path
as safe to remove without checking foreign leases.

## Solution

Commit terminal state before releasing materialization and log post-commit
release refusals as structured errors without reverting the run. Make release
state-aware for `preparing`, `active`, and `releasing`; preserve foreign-leased
and corrupt targets; recover stale ownerless locks from the lock-directory
timestamp; accumulate multi-step intents; and check required L2 paths by
membership. Add layered adapter contract coverage, malformed-cache fail-closed
tests, an executable mirror drift guard, and direct crash-window regressions.

## Prevention

Keep filesystem mutation outside terminal DB transactions. Every ownership
state transition must have a direct interruption/retry test, and cleanup must
prove foreign-lease preservation before deletion. Cross-package descriptor
mirrors must pass the root contract validator. Adapter-generic behavior should
be tested once at the shared seam while each adapter separately proves it
reaches that seam.
