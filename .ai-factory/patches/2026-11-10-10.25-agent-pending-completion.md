# Reconciliation must preserve current native agent completion ownership

**Date:** 2026-11-10
**Files:** `web/lib/reconcile.ts`, `web/lib/reconcile-evidence-db.ts`, `web/lib/agents/__tests__/prompt-owners.integration.test.ts`, `web/lib/__tests__/reconcile-classify.test.ts`
**Severity:** high

## Problem

A native agent prompt had canonical terminal evidence but no published result yet. Once its physical session disappeared and launch grace expired, reconciliation crashed the Run as `agent_session_gone` and released its assignment. The actual completion owner subsequently refused the displaced owner and marked application superseded.

## Root Cause

Structured prompt evidence classification was used for Flow agent nodes only. Standalone agents reached the generic missing-session branch even when their exact current command was awaiting application. A second race allowed a stale candidate to overwrite a real Review completion committed before generic crash finalization.

## Solution

Reuse the existing prompt classifier for exact current standalone agent assignment, session, incarnation and turn witnesses. Witnessed pending/applying completion remains with the existing application worker, including persisted retry after deferral. Old applied/superseded commands cannot hold a replacement generation. Missing or invalid evidence still follows explicit failure paths.

Before generic crash application, lock the Run and recheck its observed status, assignment, resume anchor, command and current disposition. A completed owner wins; a newly precise failure is left for its existing classifier on the next sweep. Preparation stays outside the transaction and acquires no retained resource. Existing structured reconciliation logs record the disposition without prompt content.

## Prevention

Test both canonical completion and actual result publication through the real existing application worker. Process disappearance, prompt success and prose are separate from application settlement. Recovery must preserve current owner identity and recheck the same authoritative Run under the canonical lock before applying a stale observation. Exercise actual PostgreSQL ordering with initial, operational, later-turn, lost-turn and foreign-generation controls; retain RED proof rather than adding status-only mirrors.
