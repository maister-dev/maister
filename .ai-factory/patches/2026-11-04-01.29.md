# Recovery probes and concurrency tests must prove their actual participants

**Date:** 2026-11-04 01:29
**Files:** `web/lib/flows/graph/__tests__/crash-recover-continuation.integration.test.ts`, `web/lib/__tests__/reconcile-sweep.integration.test.ts`, `web/lib/runs/__tests__/recover.integration.test.ts`, `docs/system-analytics/reconciliation-gc.md`
**Severity:** medium

## Problem

Seven continuation-worker integration cases exhausted their observation budgets.
The intended network-failure case passed, and two purported recovery races also
passed despite the worker never reaching graph dispatch.

## Root Cause

The injected admin object exposed `listSessions`, while the authoritative
recovery probe now calls `listSessionsForRun(runId)`. An `as never` fixture cast
hid the mismatch. The worker correctly caught the missing-method TypeError and
yielded; the network-failure test checked only the warning's run ID, so it
mistook this fixture error for the fault it intended to inject.

Both race labels ran the same competing marker-update double immediately.
That double could clear the marker before the worker selected it. One winner
therefore proved neither worker participation nor the actual reconcile and
scheduler entry paths. A fixed sleep did not establish contention.

## Solution

Type the scoped inventory function from `HostAdminClient`, filter its records to
the requested run, and assert its current method, run ID and exact injected
network failure. Replace title-only marker races with separate existing-domain
owners: actual reconcile reattach beside the worker, and capped Recover through
actual scheduler promotion and `driveResume` beside the worker. Hold both graph
dispatch callbacks until both callers arrive, then use the existing real
Postgres `claimFlowDriver` serializer. Retain the winning lease until all
contenders finish. Release latches, drain external dispatches, stop workers,
release owned claims and restore scoped environment/spy changes in `finally`.

Observe the scheduler's real newly written marker becoming eligible under the
existing supported grace configuration. Do not forge an older timestamp or
increase a timeout. Keep ordinary unmarked reattach coverage separate from the
committed-marker recovery race.

The inventory-method sweep covered the three recovery suites. The continuation
fixture required correction; the reconcile fixture's host census remains valid
because its existing fake scoped method delegates and filters that census; the
Recover suite uses the same complete fake host. Native supervisor fixtures are
a separate boundary and are not qualified by these domain tests.

## Prevention

- A deliberate probe failure must assert its intended cause, rather than only
  the existence of a warning. Catch-and-yield paths can hide broken fixtures.
- A concurrency test must prove every named participant reached the contested
  operation before releasing it. A final count and a delay are insufficient.
- Own shared serializer behavior once; own each distinct caller's wiring in its
  domain suite. Parameter labels alone do not create distinct coverage.
- Verify discrimination with an isolated worker-absent control. The unchanged
  real-Postgres assertions must fail when worker participation is removed.
- Describe injected graph-dispatch/domain proof accurately. It does not prove
  native process death, production boot, live-provider execution or hosted
  acceptance.
