# M43 graph-only cut-over: deployment safety, contract, and UX hardening

**Date:** 2026-07-12 11:42
**Severity:** critical

## Problem

The PostgreSQL-only / graph-only cut-over could not safely be deployed or
regression-tested. The database CLI imported `server-only` without its required
loader shim, making the migration command and Playwright global setup fail before
connecting to PostgreSQL. Several cut-over refusal paths were also either
untested, contract-inconsistent, or rendered an inaccurate remediation message.
An old web process could continue creating legacy-flow runs after the D2 migration,
and a supervisor session left by a D2-failed run was not reconciled.

## Root Cause

The M43 implementation added server-only modules to a plain `tsx` CLI path without
reviewing all command entry points. Stored-manifest compatibility was not applied
consistently at every API boundary, while one query path reclassified typed errors
by matching the human-readable message. The irreversible migration had no
database-level guard for a stale binary, and reconciliation considered only active
run states.

## Solution

- Load the server-only shim for migrations and E2E setup; use the application
  environment loader for Drizzle.
- Enforce the frozen API error mapping, use typed incompatibility metadata, and
  expose exact legacy, engine, and malformed-manifest remediation in the viewer.
- Add migration-ledger high-water validation, a database trigger rejecting new
  legacy-flow runs, D2 experiment closure, indexed cut-over event lookups, and
  reconciliation that terminates stale D2 supervisor sessions.
- Restore behavioral integration coverage for internal and external launch refusal,
  registration compensation, migration idempotency and pinned authority, and CRASH
  precedence. Restrict graph node identifiers to safe path/object-key values.
- Correct the M43 migrations/ADR numbering and canonical deployment, DSL, schema,
  analytics, environment, and localization documentation.

## Prevention

- Every executable CLI import of a server-only module must have an explicit loader
  smoke test.
- Error handling must branch on typed error metadata, never display text.
- Hard cut-overs require both a database backstop for stale processes and a
  post-migration reconciliation path for orphaned external resources.
- Contract-table rows need a route-level test that proves status, error code,
  locked text, and zero side effects.

## Evidence

- `pnpm --dir web typecheck`
- `pnpm --dir web lint`
- `pnpm --dir web test:unit` (6,168 tests)
- `pnpm --dir web test:integration` (full integration suite)
- `pnpm validate:docs`, `pnpm validate:docs:all`, and `pnpm validate:contracts`
- direct migration CLI smoke reached PostgreSQL connection handling without a
  `server-only` import failure
