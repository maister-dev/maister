# Observatory agentization review fixes

## Problem

The final review identified four correctness gaps in the agentization and
provenance delivery: rebase promotion attempted to check out a branch already
owned by a linked worktree, delivery-root collisions could double-count the
numerator, a reused commit message could retain an inactive node trailer, and
an archived scanner job could remain disabled after its project was active
again.

## Root cause

The rebase helper operated from the parent checkout rather than the source
worktree. Canonical matching enforced only one delivery reference per run, not
one run per delivery reference. The hook rejected absent task/flow metadata but
not a stale node pointer. The scanner seed used conflict-ignore semantics, so
it had no archive reactivation transition.

## Solution

- Rebase inside the source worktree, then fast-forward the parent target.
- Require a one-to-one run-to-delivery-root mapping; any collision makes the
  rate insufficient rather than double-counting lines.
- Reject `Maister-Node` when no active node metadata exists, including
  `git commit -C` reuse.
- Reseed disabled archive-style scanner jobs, while retaining jobs disabled at
  their native failure threshold.
- Record the scanner lifecycle distinction in the SDD and scheduler analytics
  contract.

## Regression coverage

- Real-Git linked-worktree rebase success/conflict cleanup and stale-node
  commit-message tests.
- Pure attribution collision test.
- Postgres scanner lifecycle test for reactivation and threshold poison
  preservation.
- Promotion service contract expectation for the propagated source worktree.
