# Librarian review fixes across recovery, privacy, and release gates

**Date:** 2026-09-28 11:54
**Files:** `web/lib/librarian/`, `web/lib/execution-host/create-intent.ts`, `web/app/api/v1/ext/runs/`, `supervisor/src/workspace-registry.ts`, `web/lib/db/`, `docs/`, `.github/workflows/ci.yml`
**Severity:** high

## Problem

An interrupted external operation could block later librarian turns and reset indefinitely. A clear-history request left Claude transcript files on disk. Recovery could restart a live turn and reuse its session-create key. The review also found missing release coverage, stale contracts, and misleading UI or documentation.

## Root Cause

Operation reconciliation existed but was not wired into admission or the sweep. Unknown outcomes lacked a terminal evidence lookup, while some pre-effect refusals were recorded as unknown. Claude's project-directory encoding was assumed to replace dots only. Turn recovery used the first start time instead of a renewed attempt lease, and create keys did not distinguish attempts. The release gate had no dedicated CI browser lane.

## Solution

Reconcile before admission and in the sweep; settle effects from durable state while preserving uncertainty after a possible effect. Return typed refusals before effects and keep refused HITL cards rejectable. Correct transcript encoding and test the purge. Add a durable start lease, attempt-scoped create and prompt keys, and a transaction guard for late session metadata writes. Add the librarian Playwright command and CI job, reconcile docs and wire contracts, and cover the changed recovery and UI behavior with integration and browser tests. Reserve the merged ADR and migration numbers before this phase.

## Prevention

- Test a recovery path through its production caller and an interrupted effect through the reset barrier.
- Distinguish pre-effect refusal from an unknown post-effect outcome at every external route.
- Derive cleanup path fixtures from the actual runtime encoding.
- Hold a start after session creation while a newer attempt completes, then prove the old attempt cannot prompt or overwrite metadata.
- Run docs, contracts, typechecks, focused Postgres suites, and the browser acceptance lane before declaring the release gate complete.
