# Native Web fault fixtures follow durable launch and physical ownership

**Date:** 2026-11-04 02:06 (Europe/Moscow)
**Files:** Native Web test-support helpers, fault fixtures and their integration controls.
**Severity:** medium
**Scope:** Native test-support fixtures; no production authority or process-lifetime changes.

Supervisor tree-stop controls and leader-only death have distinct scope. The
manager's existing D2c in `command-recovery.integration.test.ts` kills only the
Supervisor leader after capturing the initialized native adapter, proves that
the original create remains pending while that adapter survives, and consumes
the same original receipt after verified retirement. D2b's fixture restart also
retires captured groups and does not supply that survivor proof.

The Flow seed now installs its actual `flow.yaml` in a dedicated asset directory;
the expanding runtime/repository root is not treated as immutable package input.

## Evidence and cause

The full Web failure inventory at
`/private/tmp/maister-web-full-integration-final-failures.json` records three
obsolete assumptions: P1/P2/P3 counted all adapter log rows as prompts; P4 and
Flow-domain boot/death cases sent the old task-only launch request; terminal
barriers parsed the new `session/new` witness as though it already had an ACP
session ID. Actual adapter signals also targeted a gate or assumed the adapter
was a direct child of the Supervisor. O2 exposed a real fixture containment gap:
the inherited watchdog killed only the Supervisor group while detached session
groups survived the fixture parent's death.

## Fixture contracts

- `adapter-invocations.ts` validates complete newline-committed rows through a
  method-discriminated union. `session/new` has no fabricated session ID;
  prompt and terminal rows retain their actual ACP identity and request hash.
- `captureOwnedAdapterProcess` resolves an exact session through run-scoped
  v1 ownership attestation, then proves native adapter → gate → Supervisor
  ancestry, invocation tags and the registered group. Behavioral signals use
  its captured adapter identity; the public gate PID remains unchanged.
- `launchFlowThroughHttp` reads the real preview, submits revision/token with
  Origin and one stable request key, requires HTTP 202 plus the exact Location,
  then waits for that accepted intent's actual Run binding. It grants no
  fixture-only authority and creates no synthetic Run.
- The O2 private watchdog receives captured native group members and parent
  birth identity before readiness. After parent death it rechecks identity and
  complete invocation membership before signaling only those owned groups.
  Its initialization is bounded; it never restores an adapter preload.
