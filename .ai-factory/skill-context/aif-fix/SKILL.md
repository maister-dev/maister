### Renumbering a shared ADR / migration namespace is grep-to-zero, never a global find-replace

5. Verify the migration number against `migrations/meta/_journal.json`, not the prose (`0029` was documented in 5 places but shipped as `0030`).

Do the renumber/re-port as its OWN focused session, AFTER rebasing/merging onto the integration target — never reconcile docs against a branch baseline that is behind main (editing a stale pre-feature copy re-derives corrections main already shipped). macOS BSD-grep gotcha: for glob-unsafe paths like `app/api/[slug]/…`, `grep -rlZE … | xargs -0 perl` malfunctions — use `grep -rlE … | while IFS= read -r f; do perl -pi -e '…' "$f"; done` (quoted `"$f"` prevents `[slug]` shell-globbing; one perl per file).

### Fixing past the point of no return: widened cleanup is a regression, not a fix

**Source**: 2026-07-15-18.10, 2026-07-16-11.20, 2026-09-03-17.21, 2026-09-03-15.37
**Rule**: Before touching any `catch`/rollback/restore, list the side effects that may ALREADY have landed above it (force-push, PR create, publish, a committed cascade). When a review asks to "add cleanup" or "add the missing case to the cleanup path", check the sibling branch the widened compensation now ALSO covers — round N's fix (route the catch through `failResolver`) became round N+1's critical (it restored the worktree after a landed push); a phase past the point of no return needs a FORWARD-SETTLE branch (ask origin, settle `succeeded`), never a restore, and an unproven push is never restored. Model the point of no return with a flag every compensating path consults (`pushCommitted`). Before INVERTING an ordering to close a race (CAS-first vs cascade-first), enumerate the recovery for the NEW partial state — a window with a tested backstop beats a narrower window with none; a prescribed inversion was correctly rejected on that evidence. A refused request must leave no trace: if the handler can refuse, move the check BEFORE the first irreversible act rather than trusting the trailing CAS.
