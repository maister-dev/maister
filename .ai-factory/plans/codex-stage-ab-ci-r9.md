1. Keep `execution-data-plane` as the **web** job with matrix `node: [24.15.0, 24.19.0]` × `shard: [1,2]`, `fail-fast: false`, `ubuntu-latest`, 60 minutes. Each leg checks the runtime, then runs only its explicit web file subset.
2. Add `execution-runtime-supervisor`, two Node legs, for `runtime:check`, `test:runtime`, `test:stage-ab-lane`, and supervisor A/B once per Node. This avoids repetition and gives each web shard its full budget. Both job families run on every push. No larger runners and no timeout increase.
3. `--shard i/n` is a web-only option. Select index `k` iff `k % n === i - 1`. Validate positive safe integers, `1 <= i <= n`, nonempty shards, duplicate/unknown flags and slice compatibility before creating an invocation. Omitted flag preserves existing behavior. Reject sharding supervisor and isolation; preserve the explicit `runStageAbLane({files})` preflight API.
4. Each shard runs and validates the same explicit immutable file list, never a glob. Pin deterministic complete/disjoint partitioning independently of report validation. Validate report membership and uniqueness, not merely total length; omission, duplicates, unexpected suites, empty discovery, skipped cases and runtime errors fail.
5. Artifact names: `execution-data-plane-node-<node>-shard-<i>-of-2`, `execution-runtime-supervisor-node-<node>`, and the existing unique isolation reports/diagnostics names. Upload actual reports with `if: always()` and `if-no-files-found: error`; no placeholder reports.
6. Keep macOS Intel + Colima 0.10.3/Lima 2.2.0 checksums and the existing VZ/virtiofs resources. One `colima start` per workflow invocation; no retry loop or speculative re-pin. Discovery uses `colima --profile maister-s52 status --json`; parse its URI with the installed Node runtime. A missing/invalid URI or missing socket produces a one-line actionable cause, preserves the raw status and fails. No silent guessed fallback is needed.
7. Cleanup uses the same job-owned profile and resolved configuration as provisioning; remove the existing assumption that `$runtime_dir/colima/maister-s52` must exist before cleanup. Record an ownership/start-attempt marker before start so a partially started VM can be cleaned. Do not delete another profile. Preserve actual cleanup failure alongside the original failure.
8. The suite TERM deadline is `min(2340, 3240 - elapsed_since_job_start)` seconds, leaving up to 30 seconds for `--kill-after=30s` and another 30 seconds for shell/trap completion inside both the 40-minute step and the 3300-second suite cut-off. Refuse a nonpositive budget. This preserves the final five-minute job reserve; do not raise either timeout. Record actual start/end and timeout outcomes even on failure. Stop the runtime before the final diagnostics upload so cleanup outcome and final timing are present in the artifact; cleanup and upload both run under `always()`. Report total hosted duration from GitHub, including checkout/setup/upload/cleanup, not only suite time. ### R9

1. One shared transaction-level park-settlement implementation handles node and gate ownership with typed owner-specific proof. Invoke it before verdict/result application and at node/gate reattachment. The mutation core uses the caller transaction: owner application commits command application marker, attempt/run/gate/permission settlement together; reattachment passes its transaction and accepts an already-applied command. Return superseded on lost current ownership/CAS. Do not carry the existing helper's separate transaction or already-applied-only precondition into the owner-application path. A live park keeps the `gate_permission_pending` contract unchanged.
2. `session_crashed` requires positive evidence for the **owned incarnation**. A failed prompt, missing receipt, stale projection, elapsed timeout, outbox-pressure park (ADR-183) or absolute-cap checkpoint (ADR-180) is not that evidence. Read authoritative host/canonical evidence through execution-host boundaries; never read private runtime files from web.
3. Scratch re-drive belongs to the existing continuation worker's scratch arm, using its existing tick and fair cursor. Eligibility age of one tick avoids hot selection; it is not evidence of non-delivery. Under locks, require no command/tombstone for the intended operation key and no unresolved prompt obligation for the current incarnation. A terminal command awaiting owner application belongs to command recovery, not re-dispatch.
4. Amend the request's incarnation-wide absence predicate: older completed prompts do not disqualify a later unsent message. Initial/recovery owners key by assignment + ordinal zero; message owners key by row ID + sequence. D-A8 may legitimately reuse historical content with a new recovery key. Exactly-once is **per logical dispatch operation**, not once per transcript row for all future Recover generations.
5. Scratch lock order is scheduler → run → scratch_runs → message, with current assignment/incarnation and command ledger read only after taking the run lock. Use the existing scheduler lock when capacity/status work needs it; do not introduce a reverse acquisition through an admission callback. One run-lock interval fences absence proof and durable owner/command admission. Wire I/O follows the commit; both live dispatch and sweep use the same immutable key/content comparison.
6. S1 requires a design proof before its fix: existing persisted state must uniquely reconstruct the original owner variant, source row and normalized payload for all dispatchers, including Recover with preexisting queued messages. Do not guess the newest row, repurpose error metadata as an intent journal, or requeue a D-A8 historical message under its old key. If current schema cannot express an unambiguous recovery intent, record the counterexample and revise the no-migration premise before coding the sweep; never silently deliver a partial four-path fix.
7. Stop/Discard close permission rows with `closeOpenScratchPermissions` inside the winning terminal status transaction. A stored answer is superseded. Post-commit cleanup does not resurrect permission delivery. Preserve existing external delete/cancel failure semantics; do not mark a delivery acknowledged merely because termination was requested.
8. Stale scratch terminal guards run **before both** checkpoint permission parking and generic dialog projection, under the same run lock as mutation. Compare the resolved event incarnation ID to the current logical-session binding, including assignment/host identity; never compare ACP handles and never exclude a current incarnation just because lifecycle projection already marked it ended.
9. C1/C3 backstop re-enters `promoteNextPending` through the existing system sweep. Its scheduler lock protects the pool cap; existing claim CAS protects a particular launch/resume. Do not take an outer scheduler lock around a function that owns it. Visit every configured pool, including the current Librarian delegate, without creating a second admission algorithm.
10. CLI liveness uses the existing durable graph-driver lease, widened to CLI-only graphs, after proving every launch path owns a current assignment. A renewable token/lease can protect a driver in another web process. A process-local registry alone or an active assignment alone cannot. Reconcile rechecks token, lease, assignment and status under the run lock immediately before crashing a dead driver past grace.
11. Gate-only Recover requires positive durable evidence tying the crashed gate command/evaluation, owned incarnation, pinned flow revision and completed parent action together. Reuse existing parent-action digest and gate continuation proof where applicable, but do not pretend a crashed park is an answered live permission. Preserve the closed source attempt and immutable command; define the legal recovery attempt/evaluation and new assignment binding explicitly. Only the gate is re-asked, exactly once per won recovery generation, irrespective of the parent's `retry_safe` flag. Missing/conflicting proof refuses through the existing error boundary. Ordinary unsafe CLI action recovery remains refused. API eligibility and the run-detail Recover affordance use the same classifier and evidence.

| Window | Owner / proof | Required outcome and wake |
