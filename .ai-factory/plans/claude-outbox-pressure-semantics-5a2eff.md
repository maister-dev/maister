## Ground truth: corrections and additions to the request

The request's citations were re-verified on `881619a5`; the line numbers hold. **The findings below change the work.** Implementers must not re-derive them.

**C1. Admission is decided in ONE helper, not at every `putReceipt` caller.** `runCommand` (`http-api.ts:698-830`) computes the admission at `:713-726`: `session.create` → `{kind:"producer", outputBindingCount}`; a `live` session with kind ∈ `{session.cancel, session.checkpoint, session.delete}` → `{kind:"teardown", walletId}`; everything else → `undefined`. Three helpers pass no admission at all: `runRestartableUploadCommand` (`:860,865`, `PUT /runtime-objects/:id/content`), `runRuntimeObjectDeleteCommand` (`:936,941`), `runAsyncPromptCommand` (`:1067`, `POST /sessions/:id/prompts`). The gate is `admitReceipt` (`outbox-budget.ts:395` producer arm, `:412` `admission?.kind !== "teardown"` → `assertOutboxAdmission`), wrapped by `host-state.ts:986-1009` which adds the file-pressure check (`runtime_storage_pressure`). Trap 4 therefore reduces to one admission table in `runCommand` plus the three helpers (D-B1). Note a second defect the table fixes: teardown admission is granted ONLY when `entry.record.status === "live"`, so a cancel/checkpoint/delete against a non-live record is gated like new work today.

**C2. `session.steer` reaches the gate** (`http-api.ts:3084` through `runCommand`, admission `undefined`). It is classified `resolve` (admitted under soft, refused under hard) — owner decision Q5.

**C3. Two `pressured` surfaces disagree today.** `runtimeEventOutboxStats().budget.pressured` (`host-state.ts:1972-1988`, also `notifyCapacity` `:940-943`) ORs the outbox bit with runtime FILE pressure and physical admission; `/health?includeStream=true` reads the raw bit from `RUNTIME_EVENT_HEALTH_SNAPSHOT_SQL` (`host-state.ts:308-333`). D-B4 pins the meaning: `stream.pressured` is the unACKed outbox bit and nothing else; file/physical pressure keeps its own refusal (`runtime_storage_pressure` → 503 `EXECUTOR_UNAVAILABLE`, `http-api.ts:280-286`). `shouldDrain()` (`producer-pressure.ts:108`) keeps reading the OR'd stats — a teardown drains under any pressure.

**C4. The refusal is a 409 `PRECONDITION`, and the docs spell it three ways.** `runtimeEventSupervisorError` (`http-api.ts:278-315`) normalizes `event_outbox_soft_limit | event_outbox_hard_limit | event_outbox_terminal_reserve_exhausted` to `event_outbox_backpressure` and mints `SupervisorError("PRECONDITION", …, {details:{reason}})` (409). The web passes a known code through (`supervisorErrorToMaister`, `supervisor-client.ts:2124-2151`; `wire-shape.test.ts:129`), and `deliverCommand` turns any definitive error into `failed` (`deliverer.ts:462-465`) — so the manager sees `PRECONDITION`, not the request's "generic CONFLICT". `docs/error-taxonomy.md:636` lists `event_outbox_backpressured` (extra "d") under `EXECUTOR_UNAVAILABLE`/503 while `:603` and `supervisor.openapi.yaml:3609` (`ReasonToken`) say `event_outbox_backpressure`. T0.6 reconciles to ONE spelling and one host code (409 `PRECONDITION` + `event_outbox_backpressure`, host-minted) and one manager mapping (D-M6).

**C5. `POST /api/runs` never sees the create refusal.** The route creates the run, `tryStartRun` decides `Running`/`Pending` under the scheduler lock (`scheduler.ts:373-430`), then `void runFlow(runId)` (`services/runs.ts:1982`) and answers `{runId, status}` (`:1989-1995`). `session.create` is issued later, inside the driver (`runner-agent.ts:1485-1509`; only a `CHECKPOINT` error triggers the fresh-session fallback). The request's "the launch path refuses with a typed non-terminal `EXECUTOR_UNAVAILABLE {host_pressured}` instead of letting the create's 409 fail it" is therefore TWO arms: a scheduler admission gate that queues (D-M4) and a driver arm that parks instead of failing (D-M3). A 503 from the route would lose the run row — the route keeps answering 201 with `status: "Pending"` and gains `queueReason` (owner decision Q6).

**C6. `pressured` reaches the manager only through the sweep's observation step, and is persisted nowhere.** `stream-health.ts` is DB-only (`findStalledEventStreams`, `:31-66`: `active` stream on a `ready` host, `lastSeenAt < cutoff`, `openCommands > 0`). The host health is fetched by `system_sweeps.ts:408` (`executionHosts.local().platformStatus()`, always `includeStream: true` through `local-direct.ts:159-164`) — every 60 s (`DEFAULT_SYSTEM_SWEEP_CADENCE_SECONDS = 60`, `jobs.ts:147`) and AFTER the stream-health pass (`:382`). `createExecutionObservability` never copies `pressured` (`lag-observation.ts:528-560`), and no code branches on it (grep). The zod schema (`supervisor-client.ts:319-378`) is `.passthrough()`-shaped and already has `pressured: z.boolean()` (`:349`); the OpenAPI already requires it (`supervisor.openapi.yaml:2233,2242`). **C7. ## Decisions

### B — Two meanings, one hard bound (host)

- **D-B1 Pressure is unACKed-only.** `refreshOutboxPressure` (`outbox-budget.ts:195-212`) enters `pressured` when `unacknowledged{Bytes,Count} + reserved{Bytes,Rows} ≥ eventSoft{Bytes,Rows}` (either lane) and clears when BOTH lanes are `< eventLow*`. `retained_*` leaves the predicate. Frame reservations (`runtime_event_frames`, `:214-225`) stay in the unACKed lane: a reserved frame is by definition not ACKed. `atThreshold` splits into `unacknowledgedAtThreshold` and `retainedAtThreshold` (both exported, both unit-tested).
- **D-B2 The episode is host state (owner decision Q7).** `runtime_event_pressure` (SQLite v14) records `since_ms`, `unacknowledged_{count,bytes}_at_start` on 0→1 and clears them on 1→0, incrementing `episodes`. `RUNTIME_EVENT_HEALTH_SNAPSHOT_SQL` exposes them; `/health?includeStream=true` gains `stream.pressure: {since, unacknowledgedCountAtStart, unacknowledgedBytesAtStart, episodes} | null` (null when not pressured). Log `INFO outbox-pressure-changed {pressured, unacknowledgedCount, unacknowledgedBytes, retainedCount, episodes}` on each flip (the existing `runtime-file-pressure-changed` shape).
- **D-B3 Retained is housekeeping.** `pruneAcknowledgedRuntimeEvents(now, {mode})` gains `mode: "grace" | "retained_pressure"`. `retained_pressure` uses `cutoff = now` (no grace), same page bounds (100 rows / 1 MiB per `BEGIN IMMEDIATE`), same protected-span stop, same contiguous prefix, and its page loop stops when `retained{Count,Bytes} < eventLow*` (both lanes) or a page returns nothing prunable. Triggers: (i) `ackRuntimeEvents` — after its commit, when `retainedAtThreshold(soft)` → `pruner.kick("retained_pressure")`; (ii) `appendRuntimeEvent` / `putReceiptWithRuntimeEvent` — same check after commit; (iii) the hourly timer stays the grace backstop (`mode: "grace"`). `startBoundedPruner` gains `kick(mode)` (coalesced: at most one pass in flight; a kick during a pass sets `pending`). Between pages it yields with `setImmediate` as today, so ACK and publisher writes interleave (RED B3d proves an ACK commits within one page time during a 20 000-row prune). Logs, once per episode (episode = first `retained ≥ soft` sighting → `retained < low`; in-memory, restarts once per boot): `WARN outbox-retained-pressure-prune {pruned, retainedBefore, retainedAfter, oldestAgeMs, pages, durationMs}` at episode end; the degenerate case a best-effort policy must state: when a pass under retained pressure prunes nothing because the protected span (or an unACKed prefix) pins the oldest rows, `WARN outbox-retained-pressure-prune-stalled {retainedCount, protectedFromSequence, acknowledgedThrough}` once per episode and the hard bound (D-B4) stays the last line.
- **D-B4 Hard stays on retained, physical stays physical.** `reserveFrameCapacity`'s hard check (`outbox-budget.ts:284-297`) and the hard arm in `assertOutboxAdmission` keep `retained ≥ eventHard*` semantics unchanged; `runtimeMinFreeBytes` (`assertPhysicalAdmission`) unchanged. `stream.pressured` in `/health` = the unACKed bit only (C3).
- **D-B5 Replay floor.** Unchanged code path (`:2067-2075`): the floor advances only over rows the page actually deleted, all ACKed. RED B3 pins: after a retained-pressure prune the manager's `execution_event_streams.last_ack_confirmed` (its watermark) is never below `replay_floor_sequence`, and a consumer resuming from a cursor below the floor gets EDGE-EVT-03 exactly as today.
