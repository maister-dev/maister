## Locked scope and decisions

Locked by the owner on 2026-09-21 (design doc D1–D8 plus three corrections). Never re-ask these.

- **D1 Period.** `windowDays=7|30|90` presets or `from`/`to` (inclusive `YYYY-MM-DD`); `from`/`to` win when both present; absent → 30; `windowDays` clamped `1..365`. Whole UTC days: preset `N` → `[startOfUtcDay(now) − (N−1)d, startOfUtcDay(now) + 1d)`; custom → `[dateStart(from), nextDateStart(to))` (the helpers `/runs` uses). Span > 365 days → `since` moved forward, bar renders effective values. `from > to` or an invalid date → custom range dropped, preset default applies (owner, 2026-09-21). Every windowed read (correction, autonomy, signals, artifacts, harness, node drill-down, budget, agentization, **cost**) switches to `[since, until)`.
- **D2 Launched.** Runs by `runs.started_at ∈ [since, until)` per `run_kind`; orchestrator children count as runs of their kind. Tasks by **overlap**: a task is "in work in the period" when it has ≥ 1 `flow` run with `started_at < until AND (status ∉ {Done, Failed, Abandoned} OR ended_at >= since)`; "taken into work in the period" = tasks whose earliest flow run started in the period. No new column: `tasks.status='InFlight'` is written in the launching run's insert transaction (`web/lib/services/runs.ts:1877`), so `min(runs.started_at)` per task is the durable moment.
- **D3 Outcome bucket.** Ten buckets, one per run: `Queued | Executing | WaitingOnHuman | Review | Crashed | Delivered | PrOpen | ResultOnly | Failed | Abandoned` (rules: design doc D3 table). In-flight names are exactly `WORK_IN_FLIGHT_STAGES`. ONE SQL `CASE` fragment shared by the overview `GROUP BY` and the `/runs` ledger predicate; nothing persisted.
- **D4 Rows.** One row per visible project + totals; a **Platform** row for `project_id IS NULL` runs (today: Studio assistant scratch only — `launchAgentRun` requires `projectId`, `agent_project_links.project_id` / `agent_schedules.project_id` are NOT NULL), global `admin` only, rendered only when non-zero, task cells empty. Project page: own row + per-flow sub-rows + `scratch`/`agent` sub-rows.
- **D5 Cost.** Windowed by `runs.started_at`; new **By flow** card (`run_cost_rollups.flow_id → flows.flow_ref_id`, `scratch`/`agent` pseudo-rows); tokens only.
- **D6 Views.** `view=overview|cost|quality|harness`; default `overview`, default `quality` when `flowId|nodeId|artifactKind|artifactDefId` is present without `view`. Shared `Tabs` in href mode. Quality/Harness render the existing not-applicable state as a whole view for `runKind ∈ {scratch, agent}`. Quality grid: responsive, `items-start`, no fixed aside.
- **D7 Filter bar without Apply.** Client component; `router.replace(href, { scroll: false })` in a transition; `aria-busy` while pending; commit on `change` for presets/selects/dates, on blur/Enter for free text; clearing removes the param. Fields: period + run kind everywhere; `project=<slug>` on the portfolio; flow + node on Quality/Harness; artifact kind/def on Quality. Other screens get their own task later.
- **D8 Drill-down.** Every run cell links to `/runs?project=&from=&to=&kind=&bucket=`; task cells to the project board. `/runs` gains `kind` and `bucket` params (allow-listed) and the two selects.
- Out of scope: USD; state-machine changes; persisted stages; portfolio agentization headline (ADR-134); no-Apply bars elsewhere; instance timezone (UTC like `/runs`); HeroUI `DateRangePicker`.

## Identifiers and trust boundary

No new route. All new inputs are URL search params (untrusted, `url-param` class) and are narrowed before any SQL:

- `view` → allow-list `OBSERVATORY_VIEWS`; `windowDays` → integer clamp `1..365`; `from`/`to` → `validDate` (`YYYY-MM-DD`, real calendar date) + `from ≤ to` + 365-day clamp, otherwise ignored; `project` → resolved against `getVisibleProjects` (server-state) — unknown slug narrows to nothing and is dropped from the bar, never used as a raw predicate; `runKind` → existing allow-list; `kind`/`bucket` on `/runs` → `oneOf` against `RUN_KINDS` / `RUN_OUTCOME_BUCKETS`.
- Visibility predicates stay first in every query (`getVisibleProjects`, `visibleProjectsPredicate`). The Platform row is gated on `auth-context` (`globalRole === "admin"`) and never widens the ledger's visibility.
- Data class in responses: aggregate counts and token totals only — no worktree paths, prompts, diff bodies, or session ids (unchanged Observatory boundary).
