## Incident and failure path

The historical baseline was a detached checkout at `4a0b41b2`. The operator counted 4,934 failed preparations in the November 20 morning window.

**Confirmed Stop mechanism.** Epoch 1 created a session, its prompt failed with `ACP_PROTOCOL: prompt cancelled`, its checkpoint succeeded, and its incarnation still read `active`. Epoch 2 had `placement_reason=resume`, a `claimed` resume turn, **zero execution commands and zero incarnations**. The supervisor listed zero live sessions. Stop inspected epoch 2, could not find an incarnation and returned `EXECUTOR_UNAVAILABLE / agent_execution_quiescence_unproven`. The reason the resume first stalled and the reason the historical projection was missed remain undetermined. The code trace below explains how the supplied stuck state can repeat.

**Post-workaround evidence.** The operator reports that an administrative repair committed `Abandoned`, released the assignment, revoked tokens, superseded the resume turn and recorded cancellation. Historical records and working files were preserved. Physical checkout release and historical prompt-owner disposition were not verified by that report. Use the pre-repair shape for regression; treat the production Run as an already-terminal recovery case. ## Read-only diagnostic for the operator

This query uses existing columns. Independent aggregates keep command/preparation joins from multiplying the counts. It includes a pending prompt even when the retry branch never incremented its counter. Preparation counts reflect durable rows; compare them to the per-Run log rate if failure publication itself was interrupted.

```sql
SELECT r.id AS run_id, r.execution_assignment_id AS current_assignment,
       r.operational_integrity_baseline->>'version' AS baseline_version,
       p.failures, p.last_failure, c.id AS deferred_command,
       c.execution_assignment_id AS command_assignment, c.application_attempts,
       c.application_error->>'reason' AS application_reason,
       c.application_error->>'deferredSince' AS deferred_since,
       c.application_next_retry_at
FROM runs AS r
CROSS JOIN LATERAL (
  SELECT count(*) AS failures, max(p.updated_at) AS last_failure
  FROM agent_preparation_operations AS p
  WHERE p.run_id = r.id AND p.phase = 'failed'
) AS p
LEFT JOIN LATERAL (
  SELECT c.id, c.execution_assignment_id, c.application_attempts,
         c.application_error, c.application_next_retry_at
  FROM execution_commands AS c
  WHERE c.run_id = r.id AND c.kind = 'session.prompt'
    AND c.owner_kind = 'agent_turn' AND c.completion_applied_at IS NULL
    AND c.application_state = 'pending' AND c.application_error IS NOT NULL
  ORDER BY c.updated_at, c.id LIMIT 1
) AS c ON true
WHERE r.run_kind = 'agent' AND r.agent_kind = 'operational'
  AND r.status = 'Running' AND (p.failures >= 2 OR c.id IS NOT NULL)
ORDER BY p.failures DESC, r.id;
```
