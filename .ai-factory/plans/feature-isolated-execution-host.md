# Isolated execution host

**Branch** `feature/isolated-execution-host` · **Created** 2026-11-19 · **Planning baseline** `b06e641d2`

Run each untrusted process under a host-enforced Linux or macOS policy. Web owns authorization, Flow semantics and operator configuration. The execution host owns the process tree, workspace resolution, credentials, network exit and evidence of what actually ran. Security items #1 (workload isolation) and #2 (credential confinement) close on P7 evidence for the supported configurations.

## Settings

P7 reruns those witnesses through release entry points and supplies live provider and clean-install receipts.
- **Logging — structured, verbose diagnostics.** DEBUG for policy decisions using logical IDs, INFO for transitions and counts, WARN for refusals and bounded retries, ERROR for unresolved integrity or cleanup failures. Apply the same redaction before serializing a command, recording a receipt, storing output, or emitting an event. Each task below names its evidence.
- **Docs — yes.** Design and contracts in P0, mandatory operator and EN/RU product documentation checkpoint in P7. Follow the existing docs ownership rules.
- **Performance.** Measure P0 startup and CI lane baselines and get numerical budgets approved **before P2**, as selected by the owner. Preserve the existing mandatory A/B budgets and evidence.

### Decisions and feasibility gates

1. **Linux network attachment (brief Q1).** Start P0 with a private net namespace and a session-owned socket relay to the host proxy. Provide a sandbox-local proxy endpoint for supported clients. Tools that ignore it have no direct route. Grant a host test service through a dedicated forwarder, and publish a preview through a separate inbound mapping. Compare a filtered interface/transparent transport only if a required positive workflow cannot use the relay. Select one topology with working positive and denial evidence. Public `open` means public egress mediated by the selected transport. Document supported protocols.
2. **Toolchains and caches (Q2).** Detect from the trusted host service's configured PATH. Resolve actual binaries, interpreters, libraries and version directories for nvm/asdf/pyenv, Homebrew, Cargo and system tools. Deduplicate canonical roots, refuse writable or sensitive ancestors that would expose home, and show the resolved set in doctor. Key caches by immutable project ID, tool family and incompatible format/runtime version. Keep cache leases through active use, GC on project deletion after quiescence, and isolate company/diagnostic owners. Never execute a workspace-supplied cache or shim under a privileged identity.
3. **Git timing and attribution (Q3).** Check at admission, before each privileged Git operation, after workload quiescence, and during recovery. A sibling's branch name does not identify its writer. Qualify a per-workload writable ref view backed by the existing linked worktree and shared objects, with host-mediated compare-and-swap publication of its own branch. Protect canonical refs from direct unreceipted writes. Bind permitted transitions to ref name, old/new OIDs, owner, epoch and operation receipt. A protected move in the writer's view must be detected, undone and attributed, including a move of a concurrently active sibling's branch. Reconcile canonical changes under the physical common-dir lock and preserve subsequent authorized updates. If the host cannot provide this property on either OS, withhold the writable-worktree capability there. Switching to a per-run object store or shared clone requires a separate ADR. Shared writable objects retain a documented availability/recovery risk. [Git reference transactions](https://git-scm.com/docs/git-update-ref)
4. **Subscriptions (Q4).** P0 decides each adapter × version × OS × auth mode. Require a real model operation, refresh or reconnect as applicable and a post-respawn receipt. A `CONNECT` tunnel cannot insert an HTTP authorization header into an encrypted stream. Use a provider-aware endpoint with its own TLS-verified upstream and explicit credential audience. A generic forward proxy carries no provider credential. Prefer that endpoint for Claude long-lived tokens if proved. Otherwise offer only the separately qualified, ceiling-enabled `exposed` mode. Unsupported combinations have a typed readiness refusal.
5. **Docker (Q5).** Raw daemon access is host-equivalent. Default off. A normal host daemon socket cannot support the stated secret/filesystem/egress guarantees even inside bwrap or Seatbelt. Refuse raw host-equivalent access in the enforced class. If offered locally, require the platform's explicit unisolated exception as well as a ceiling grant and a runner request, and label that attempt host-equivalent in preflight, receipts and history. P0 records operator agreement on this interpretation. A constrained container broker is separate work. An isolated daemon may qualify in future only with its own proof.
6. **Profile persistence (Q6).** Embed a versioned profile in each runner initially. Use the same schema and pure resolver for admin writes, preview, authoritative admission and host validation. Store an independently revisioned platform ceiling/default and project command override. A missing optional allow-list inherits its parent, while an explicit empty list grants nothing. Extra paths and service grants reference reviewed host-owned IDs. Snapshots store logical grants, digests and provenance without host paths or secret values.
7. **Profile lifetime.** Freeze policy once per admitted Run and its selected runner set. New attempts admitted under current configuration get new witnesses. Re-entry of the same admitted attempt, including a newly created ACP incarnation or assignment epoch, uses its original witness. Current reader/launch authority, credential revocation, availability of the exact host driver/policy and current physical resource identity are checked at every dispatch. An unavailable pin produces an explicit refusal. Preserve a stable adapter HOME and cwd across respawns, partitioned by owner/session when separate named sessions should not share credentials or state.
8. **Exceptional grants.** Treat the unisolated opt-out as a privileged platform decision, default off, auditable and visible before dispatch. An absent driver, a weaker exception, and each verified enforcement class have distinct status. Never silently switch to unisolated after a sandbox spawn failure. Seam bypass requires proven isolation even when opt-out is enabled. All host path and port grants exclude credential stores, privileged sockets, runtime state and control-plane services, including aliases. The façade is a scoped application route to authorized ext API operations through the proxy. It grants no general web port.

### Contracts to settle before implementation

- **Process coverage.** Allocate one host sandbox per session or command. All adapter descendants, including stdio MCP and subagents, inherit the boundary. Route independent smoke, version, model and MCP diagnostic workloads through dedicated short-lived diagnostic sandboxes with synthetic or expressly scoped credentials. The data-only host health path invokes no adapter. Claude native sandboxing or Codex workspace-write may further narrow access, but only the host driver's successful enforcement can satisfy admission.
- **Host attestation and command defaults.** Publish versioned driver/policy identity, platform, last verified health and enforced workload classes in `execution_hosts.capabilities.isolation`. Invalidate stale evidence on restart, driver/config change or required broker loss, and verify again at the real spawn point. The platform provides the project command default. Authorized project editors can narrow or configure network, ports, paths and limits within the ceiling; approval, provider credentials and seam bypass are absent from the command schema. Default placement and scheduled launches use the same checks as manual launches.
- **Authority and wire identifiers.** For host routes, manager identity is transport-authenticated. Host key, incarnation, run/operation assignment, epoch and handle in a request are assertions checked against the host registry/fence. Derive cwd, policy bytes, object location, package root and process identity from that state. The façade authenticates its revocable launch principal and binds routes/methods/resources server-side. For admin ceiling/runner writes, authenticated admin authority gates the URL-selected runner or singleton. Project command settings use the URL project and current project-settings authority. Bodies supply only typed policy values and expected revisions. Derive tenant, target host and actor independently. Admin diagnostics show redacted state, project preflight shows only its own grants, and command output inherits the existing source/Run access checks.
- **Resolution.** Validate the runner's request against the ceiling at write and launch. Over-ceiling settings refuse admission and identify the field/layer. Within the ceiling, intersect tools/MCPs and workspace with workload constraints. `none < repo_read < worktree`. Resolve approval by stricter of runner `ask | auto_approve` and the Run's `permissions`, subject to the ceiling. Preserve strict-capability, read-only, and ask requirements even for legacy bypass requests. Save per-field deciding layer, units/limits, explicit host ports and the allowed credential file or integration reference. Command profiles expose only network, ports, paths and limits. Setup gets its fixed install profile.
- **Errors.** Invalid schema/units → `MaisterError(CONFIG)`. Missing enforced class → `PRECONDITION/isolation_unavailable`. Unsupported adapter/mode → `PRECONDITION/adapter_not_sandbox_ready`. Prohibited exposure → `PRECONDITION/credential_exposure_not_allowed`. Prohibited access → `PRECONDITION/access_exceeds_ceiling`. Host sandbox spawn failure → `EXECUTOR_UNAVAILABLE`. Record typed resource-limit, integrity and quiescence outcomes. Preserve the ADR-166 fence, conflict and indeterminate-delivery vocabulary. Use the existing code-to-HTTP mapper and cover the mappings in both contract copies.
- **Delivery.** Persist immutable intent and content digest before delivery. Under the authoritative owner lock, reject terminal/stale state and deduplicate identical canonical payloads. Same key with different payload conflicts. Host fences before any effect, stores durable acceptance/PID identity, and emits bounded output and terminal receipts through the Stage B outbox. Web marks delivery after acknowledgment and projects completion after outcome, quiescence and required object verification. Network failure, timeout or 5xx → retryable/unknown with the same key, bounded backoff and receipt lookup. Auth/validation 4xx → refuse, no execution. Stale epoch/content collision → 409 conflict, reconcile the actual owner. Accepted work lacking a provable terminal outcome after restart stays indeterminate and cannot be re-executed blindly. Use the existing wake/reconciliation owners for sessions and explicit equivalent owners for non-Run operations.
- **Rollout.** P1 independently improves existing installations. P2 may advertise only a qualified offline Linux session class. Provider-backed runners remain unready until P3. Command classes become ready on their P4 evidence, Darwin classes on P5/P6 evidence. Before enforcing the installation-wide boundary, drain or explicitly quarantine older live work, refuse mixed-version dispatch, and disable any uncovered untrusted entry point. Historical rows remain inspectable with legacy status. A witnessless legacy attempt needs an explicit fresh admission before executing again. P7 alone authorizes the full support claim.

## Verification and release

### RED → GREEN → REFACTOR

1. **Select a behavior from the ratified specification.** Record the requirement/edge ID, existing suite and entry point, preconditions, action, observable result and prohibited side effects. Find an existing assertion first. Extend it when it already reaches the correct boundary. Each new test must distinguish a plausible wrong implementation from the specified one.
2. **RED.** Run the selected test against the pre-change implementation with a working fixture. Retain revision, command, environment class, test title and the failing domain assertion or contract mismatch. A broken import, missing DB, unavailable credential or unstarted service is a setup failure. For a new interface, use a publicly observable contract (for example, an expected route that currently returns 404); prove the caller and peer are otherwise healthy. When existing behavior already conforms, record the passing regression baseline and make no change solely to manufacture RED.
3. **GREEN.** Make the smallest correction in the owning layer. Rerun the identical case, including authorized positive controls and assertions on persisted state or effects. One receipt, bounded output, no unauthorized changes and quiescence are observable results where specified. Parameterize equivalent policy combinations at the resolver. Exercise real Git, SQLite, Postgres, operating-system restrictions and proxy connections at the layer that owns them.
4. **REFACTOR.** With GREEN recorded, simplify within the slice, rerun the owning suite and its affected consumers. Follow SOLID, KISS, DRY and repository conventions through concrete boundaries: one pure policy resolver, one typed host launch contract, a small platform-specific driver for enforcement, a single command delivery/reconciliation owner, and existing domain error/authorization paths. Add abstractions only when a second real consumer or an OS boundary needs them. Use strict types, explicit failures and structured redacted logging. Validate formatting, lint without auto-fix for the final check, and both tier typechecks.
5. **Close the slice.** Link the exact primary test, RED and GREEN observations and final regression result to the matrix. Mark **Implemented** only on the approved spec revision. Run specification coverage, contract validators and the full phase suites. Return to the spec if observed behavior requires a requirement change. No trivial field/getter tests, duplicate mock-only route assertions, snapshot-only UI evidence or second copy of the same policy truth table.
