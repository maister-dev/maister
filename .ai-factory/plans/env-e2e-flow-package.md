## Engine grounding — corrections to the original request (verified in platform code)

Implementers MUST follow this section where it conflicts with the request text.

1. **No `failure` transition for check nodes.** Non-zero exit → node `Failed` `PRECONDITION` → **run `Failed`** (`web/lib/flows/runner-cli.ts:144,164`; `runner-graph.ts:3338`); `retry_policy` on `check` silently stripped (`config.schema.ts:1120`). ⇒ script **always exits 0 when tests ran**; verdict routed via `output.result` JSON + `decide: { from: output.verdict }` (needs `output.result`; every producible outcome must be a declared transition key, `runner-graph.ts:4042`). Non-zero exit = environment/config failures only (actionable run-fail; rework can't fix env).
2. **`{{steps.e2e.output}}` → `rework.commentsVar` is NOT automatic.** Injection reads `result.vars[commentsVar]` (`runner-graph.ts:4598`; vars folded from `MAISTER_OUTPUT_FILE` JSON, `node-output.ts:304`) ⇒ failing summary must be a **string field named exactly `e2e_comments`** in the result JSON.
3. **Timeout**: `settings.timeoutMs` is honored on main since `52774495b` (default 300 s, ceiling `MAISTER_MAX_CLI_TIMEOUT_MS` = 1 h) with **process-group kill** — on timeout the script AND its docker children receive the signal; the trap (TERM) still runs teardown and must tolerate group-TERM (it spawns fresh `docker compose down` processes — OK). Flow declares `settings.timeoutMs: 900000`; fixture still sized < 300 s (works on deployments predating the fix).
4. **Artifact files land in the RUN DIR** (`<runtimeRoot>/.maister/<slug>/runs/<runId>/`, `runner-graph.ts:243,3724`), single files only, reachable only via `dirname "$MAISTER_OUTPUT_FILE"` ⇒ report+traces as ONE `tar.gz`, compose logs as one text file; **both produced on every attempt** (produces backstop requires per-attempt currency).

Supporting facts: cli/check run on the **web tier** (cwd = run worktree; Docker socket must live there) · child env: allow-listed per ADR-153 (on main; `MAISTER_CLI_INHERIT_ENV` escape hatch) · **no mechanism reaches the package install dir from a node command today** (skills materialization is agent-session-only; `./`-relative resolution covers only `settings.form_schema`/`output.result.schema`; none of 12 existing packages calls its own files) — T0 creates it; `flowInstallPath` is already resolved per run (`runner-core.ts:322/332`) · `requirements` = `{name, probe, hint?}`, probed in `project.repoPath` BEFORE worktree/session, failure = clean `PRECONDITION` (`requirements-check.ts`; probes are static strings — packaged-script presence can't be probed, the `${MAISTER_FLOW_DIR:?…}` guard covers old platforms) · `artifact_required` gates check presence/currency only, never re-execute (`gates-exec.ts:594`); gate rows + `requiredFor` currency feed evidence-readiness (`evidence-readiness.ts:61`, `readiness-core.ts:164`) ⇒ "one e2e execution for node + gate" holds by construction · run stop/abandon does NOT touch cli children — the trap is the teardown guarantee; hard web-process crash = residual orphan case covered by documented sweep · template vars available in `action.command`: `{{ run.id }}`, `{{ run.projectSlug }}`, `task.*`, `steps.*`.

## Design decisions (locked; spec TS1 elaborates, does not reopen)

- **Package**: `packages/env-e2e`, single flow `env-e2e` (manifest `flows[].id` == flow.yaml `name`), tag `env-e2e/v1.0.0`. No `setup.sh`, no capabilities, no agents.
- **Script delivery**: `scripts/run-e2e.sh` = SSOT file, executed via `bash "${MAISTER_FLOW_DIR:?env-e2e requires MAIster engine >= 3.3.0 (MAISTER_FLOW_DIR missing)}/scripts/run-e2e.sh" "maister-run-{{ run.id }}"`.
- **Graph**: `implement (ai_coding)` → `e2e (check)`; `decide.from: output.verdict`; `transitions: { pass: done, fail: implement }`; `rework: { allowedTargets: [implement], workspacePolicies: [keep], maxLoops: 3, commentsVar: e2e_comments }`; exhaustion = **escalate, never auto-ship** (exact `onExhaustion` syntax pinned in TS1 against `config.schema.ts:518`); e2e node `settings.timeoutMs: 900000`. Greenness enforced by routing (`pass` is the only path to `done`); exhausted-escalated run reaches human review with the red report visible.
- **Node contract**: `output.result: { schema: ./schemas/e2e-result.json, required: true }`; result JSON `{ verdict: "pass"|"fail", summary, e2e_comments, stats? }`; produces `e2e-report` (kind `test_report`, `path: e2e-report.tar.gz`, `requiredFor: [review, merge]`) + `e2e-logs` (kind `log`, `path: e2e-compose-logs.txt`), both every attempt; `pre_finish` blocking `artifact_required` gate on `[e2e-report]`; `implement` produces `impl-diff` (kind `diff`).
- **Per-project config** `.maister-env-e2e.sh` (sourced bash; no yq/jq host dep; sourcing adds no new trust — the run already executes project code):
  ```bash
  E2E_COMPOSE_FILES=(compose.e2e.yml)  # required; repo-relative; multi -f merge order
  E2E_RUNNER_SERVICE="e2e"             # required; compose service (profile "e2e") running Playwright
  E2E_WAIT_TIMEOUT=120                 # optional; seconds for `up --wait`
  E2E_SEED_COMMAND=""                  # optional; host shell after up, before tests
  E2E_ENV=()                           # optional; NAME=VALUE pairs passed into compose/runner
  ```
  Missing file/var/compose-file ⇒ `[env-e2e:config] <actionable>` + exit 1.
- **Playwright** = compose **profile service owned by the project's compose file** (`docker compose … run --rm "$E2E_RUNNER_SERVICE"`); internal DNS only, **zero `ports:`**.
- **Isolation & sweep**: `-p "maister-run-<runId>"`; sweep `docker compose ls | grep maister-run-` / `docker ps --filter "name=maister-run-"`; stray teardown `docker compose -p maister-run-<id> down --volumes --remove-orphans`.
- **Script phases**: trap-setup (EXIT/TERM/INT: best-effort capture → `down --volumes --remove-orphans --timeout 10`) → config → preflight (`docker info`, `docker compose version`) → up (`-d --wait --wait-timeout`) → seed → test (`run --rm`, `set +e` exit-code capture, output tee'd) → capture (tar `playwright-report/`+`test-results/` → `$RUN_DIR/e2e-report.tar.gz`; `compose logs --no-color` → `$RUN_DIR/e2e-compose-logs.txt`) → result (JSON → `$MAISTER_OUTPUT_FILE`; failing block also last on stdout) → exit 0. `RUN_DIR="$(dirname "$MAISTER_OUTPUT_FILE")"`. All docker invocations via `sanitized_env()` (`env -i PATH HOME COMPOSE_PROJECT_NAME + "${E2E_ENV[@]}"`).
- **Requirements (ADR-091)**: `docker info` / `docker compose version` / `test -f .maister-env-e2e.sh`, each with actionable hint (web-tier wording).
- **compat**: `engine_min: 3.3.0`; `runner_profiles`/`metadata`/`defaults` per superpowers exemplar.
- **Fixture** `examples/fixture/`: `web` (nginx:alpine, healthcheck) + `db` (postgres:16-alpine, `pg_isready`, exercised by seed) + `e2e` (playwright image, profile `e2e`, mounts fixture root, `npm ci --no-audit && npx playwright test`); committed lockfile; specs `home.spec.ts` (green) + `red.spec.ts` (`expect(process.env.FIXTURE_RED ?? '').not.toBe('1')`); `examples/bootstrap-fixture.sh [--red] <target>`: refuse non-empty target, copy, git init+commit, write maister.yaml + config (+`E2E_ENV=(FIXTURE_RED=1)` on `--red`), **pre-pull images**, print registration steps. Green+red instances double as the concurrency pair.
