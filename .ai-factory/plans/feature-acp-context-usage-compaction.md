## Decisions

1. **Persist an incarnation-scoped projection.** Use a latest-usage projection and a compaction ledger alongside `run_session_incarnations`. A logical `run_sessions` row and even an ACP handle can survive a respawn. Store run, physical host/session identity, validated attempt attribution when available, source `run_sequence`, and canonical event time. Store sequences as bigint in PostgreSQL and decimal strings on the wire. Render a current gauge by joining to the selected incarnation. Keep historical samples attributable to their own attempt. A reused named session can have one current gauge across turns while each finished attempt retains its final attributable sample. Index the attempt lookup. Use the same indexed last-sample representation for the session scope and for an attributed attempt scope, updated in the same projection transaction.
2. **Define counts and boundaries.** The tooltip counts distinct *completed* compactions observed live in the displayed incarnation. Failed, cancelled, and in-progress markers remain inspectable. The ledger can group completed events by logical run session across incarnations or by the attempt that owned the compaction. Preserve an unknown owner if attribution is unavailable. Deduplicate on the protocol ID within its verified session identity. On resume, distinguish any history replay from new live work. Replaying yesterday’s compaction must neither increment today’s count nor invalidate today’s usage. Keep historical IDs scoped so a new, unrelated ACP session can reuse the same ID.
3. **Keep one responsive horizontal meter.** Scratch, Studio, Run detail and the node inspector use the same labeled track and visible percentage. On narrow widths keep the bar, put full token counts in its focusable details and preserve the send controls. A static outline, glyph and adjacent “Compacting…” / “Идёт сжатие…” highlight the meter while any live compaction in that scope is in progress. Keep the last valid fill or the gray unknown track. Announce entry/exit once per activity change. Summary chunks do not trigger new announcements. No motion is needed. One formatter, band calculation, tooltip, advisory and accessible value serve every placement. Apply green below 60%, amber from 60% to below 85%, red from 85%. Evaluate on the unrounded ratio and use consistent display rounding at boundaries. Omit an auto-compact threshold tick in v1. Its effective value depends on agent settings and reserved capacity. Labels and example text:

   | State | Horizontal bar | Detail |
   | --- | --- | --- |
   | Confirmed sample | `Context 72%` / `Контекст 72%` | `144,000 / 200,000 tokens`, agent-reported window, localized update time and completed count |
   | No current measurement | Neutral track or empty outline, `Not reported` / `Нет данных` | Explain that the current session has yet to report usage. A real zero is displayed as 0%. |
   | Gateway window uncertain | Percentage plus visible warning glyph and `Window unverified` / `Окно не подтверждено` | Explain the adapter may have assumed the limit and point to runner guidance. Also show the advisory while awaiting a first sample. |

   For a measured value expose a labeled `role="meter"` with numeric min, max, now and localized `aria-valuetext`. Keep the raw counts visible in details even when usage exceeds size, clamp only the drawn fill and ARIA range. For an unknown value render accessible text without numeric meter semantics. Give the tooltip a focusable trigger, hover/focus/touch access, Escape dismissal and a usable target on mobile. Preserve dark/light contrast. [W3C meter pattern](https://www.w3.org/WAI/ARIA/apg/patterns/meter/)

4. **Distinguish output limits from exhausted input context.** Keep `ACP_PROTOCOL`. The only new reasons are `context_exhausted` and `max_output_tokens`. A provider ending a response at its output cap can leave room for a new turn. Only proved input exhaustion disqualifies the previous context for resume. Historical outcomes with no reason retain their original meaning.
5. **Runner policy stays advisory.** V1 always pairs the agent’s reported `used` with its reported `size`. A known runner setting may annotate the tooltip (“runner configured”, with the configured value if safe and validated). If it differs from reported size, label the discrepancy and keep the reported pair. A setting alone cannot supply an occupancy percentage. Defer `contextWindowTokens` until the registry can prove the applied setting and Codex has an isolated overlay for its symlinked global config. A future mapping can use Claude’s env, a session-local Codex setting and explicit unsupported results for other adapters. Defer Observatory metrics. Ledger counts deliver the requested query surface now.
6. **Keep compaction agent-owned.** Advertise verified ACP capabilities through the registry and the existing unstable SDK connection seam. A compaction update describes an event inside a session. It cannot complete a prompt, produce an artifact, prove guardrail progress or renew the node deadline. Defer a dedicated “Compact now” button in v1. Scratch already has a command composer. Exercise an advertised `/compact` through its ordinary prompt path. A future shortcut must require the active incarnation’s current `available_commands_update`, ordinary send authority and availability. The current commands reader searches the whole run and would need scoping before it could gate such a shortcut.

## Adapter evidence for implementation

Source inspection used the installed artifacts corresponding to the lockfile. These are sender and receiver code paths. Capture the wire through MAIster before claiming runtime qualification.

The ACP SDK 2.0.2 `/unstable` input contract is `usage_update { used, size, cost? }`, `compaction_update { compactionId, status, summary?, error? }` and `compaction_summary_chunk { compactionId, content }`. Usage projection reads only the token pair. Map known lifecycle statuses `in_progress | completed | failed | cancelled`. Retain and safely skip unfamiliar statuses at the projection boundary.

The shared UI snapshot identifies its scope and carries `usage: { used, size, sizeSource, observedAt, sourceSequence } | null`, `activeCompactions`, `completedCompactions`, a safe window advisory and a projection watermark that advances even when a reset clears usage. Derive highlight from `activeCompactions > 0` within that scope. The safe snapshot carries no vendor-generated compaction ID or free text. Include session incarnation and selected attempt identity in the cache key. Use the projector’s existing `afterCommit` hook to wake the reader. Also wake on committed lifecycle binding or scope changes, even when context projection completed first. Choose the current session against canonical lifecycle evidence. Carry the selecting lifecycle sequence so a stale response from the old process cannot win on a reused logical session. Treat lifecycle, context and transcript sequence positions independently. Snapshot delivery sets no SSE ID, preserving the durable `Last-Event-ID` header and `lastEventId` query semantics, including header precedence. Verify an old detail response cannot overwrite a newer reset.

Claude’s SDK has a prompt-too-long terminal reason internally. The ACP rejection drops that specificity and shares `errorKind: invalid_request` with other errors. In `dist/session-failure-extension.js`, the internal Claude category also groups max output tokens under context exhaustion. Opting into the separate AIR session-failure extension can change a rejection into `end_turn` with failure metadata. Keep its negotiation separate. Recognize verified structured failure metadata before ordinary success, allow-list fields by adapter and never infer context exhaustion from the coarse category alone. Preserve existing auth, timeout, unsupported-resume and cancellation classifications. Keep legacy message handling at the supervisor seam, only when sufficient structured evidence is absent. Unrecognized providers or translated diagnostics may remain generic until the adapter supplies a discriminator.

**Codex delivery prerequisite.** Codex ACP 2.2.2 contains the structured error mapping, but its current-turn handler calls the rejected-request builder for `usageLimitExceeded`. With the normal MAIster capabilities it can emit the context error as assistant text and finish the failed turn with `end_turn`. With AIR enabled its generic `limit` category also covers budget exhaustion. See the shipped `dist/index.js` functions `handleFailedTurn`, `recordTypedSessionFailure`, `createTurnErrorData` and the final prompt return. A decoder for `data.codexErrorInfo` alone cannot recover evidence the adapter dropped.

In tasks 2 and 10 run the real pinned binary over stdio against a controlled Codex app-server for both a terminal error notification and a failed `turn/completed` with no separate notification. Include `willRetry`, out-of-turn, session-budget and ordinary-success controls. If the opaque path is reproduced, prefer the smallest verified upstream pin that propagates the original discriminator via ACP. If no fixed release exists, the implementation decision is a narrow, reviewable pnpm patch to the pinned adapter at these terminal paths, covered by the same wire suite. Keep that dependency delta isolated in the commit history. Verify the binary actually resolved by the registry in local and packaged supervisors, including operator override diagnostics. Qualify only the version/build exercised. Leave Codex overflow acceptance open until both paths yield a typed outcome. Gauge and compaction qualification can proceed independently. **Projection schema.** Task 3 must produce a column/constraint/index map; task 5 delivers it before reason writers or UI consumers. Use an additive latest-sample relation keyed by run, verified assignment/epoch, execution host, host session and optional attempt; use a NULLS NOT DISTINCT unique key (or equivalent partial unique pair) for the session-wide row. An attributed frame updates both scopes atomically with its consumer checkpoint. Keep usage nullable as an all-or-none tuple, enforce nonnegative safe `used`, positive safe `size`, and retain a distinct last-change sequence for resets. Index the run/attempt read. Link by verified physical identity even when the independently scheduled incarnation join is temporarily absent; once identity is available, the same row must become readable without another usage frame. A cross-run attempt or stale assignment never updates the current session. Capture exact command/attempt ownership at observation time.

Use one lifecycle row per physical session and vendor compaction ID, with bounded ID, status, first/last sequences, nullable start/end and before/after evidence. Index scope/status for the active highlight and completed counts. Pin the owning attempt to the first proved live attribution. Keep summary/error content in the transcript owner. Preserve creation sequence and advance mutation sequence for enrichment. A chunk with no matching lifecycle can be retained under the same ID as pending content but cannot establish activity, success, or a completed count. Ignore unknown status for derivation. While A and B overlap, ending A leaves B highlighted. Mark an unterminated ID interrupted on physical exit, with zero active entries and no synthetic adapter cancellation. Cross-incarnation history observed during load/replay requires verified live origin or belongs to history only. Expose the coverage of the observed counts (complete from incarnation start, or partial from the first retained source sequence). Counts always represent observed native lifecycles. The UI qualifies a partial count and never presents it as an exact session lifetime total.

For durable failure state, add a nullable allow-listed reason to `node_attempts` with the appropriate code constraint. Define technical failure evidence on `gate_results` separately from its verdict. Reuse scratch `error_metadata`, existing consensus technical result/partial evidence and platform-agent finalization receipts wherever they round-trip the reason; list any required new nullable column in the same schema map. Document each actual writer and reader. Legacy rows remain nullable. No text-based reclassification of old failures.
