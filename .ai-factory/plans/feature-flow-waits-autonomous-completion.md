# Durable Flow waits and autonomous run completion

Branch `feature/flow-waits-autonomous-completion` · Base `master` at `cd9e37f071f7` · Created 2026-11-20

## Settings

- **Testing:** yes. Specify contracts first, reproduce the missing behavior in the suite that owns it, implement, then refactor with the same assertions green. Use PostgreSQL for claims and races, a real local Git remote for publication, a controllable provider for CI, and Playwright through the normal UI.
- **Logging:** verbose under `LOG_LEVEL=debug`. Use structured identifiers, epochs, outcome/reason, elapsed times and provider request IDs. Exclude credentials, comment bodies, prompts and raw provider payloads. Persist audit independently of log level.
- **Docs:** yes. Phase 0 produces the design contracts. Each implementation phase updates their implementation status and runs the documentation gate.
- **Delivery boundary:** this plan covers project-owned graph runs. Preserve legacy graphs, all existing human gates, operator recovery, agent and scratch behavior. The wait store has a typed owner adapter. Ship only the Flow adapter. MCP-issued waits, librarian/platform scheduling, cross-project automation, permission auto-approval changes and multi-host placement have separate plans.

## Roadmap linkage

Milestone: none assigned. M37 supplies the slot-release precedent, M49 supplies the project boundary, and M23 supplies the Observatory surface. The work spans all three.

## Specification and delivery sequence

Tasks 01–03 own the specification. Before task 04, publish a **Designed** contract for every requirement ID in the acceptance matrix below, with its owner, positive example, refusal or race example, observable outcome and enforcing seam. Resolve each example into an OpenAPI operation, event, database invariant or graph transition. Missing authority, ambiguous outcomes or an example that cannot be expressed in the schema keep Phase 0 open. The design is the input to the first failing test.

For each behavior task, select the matrix row it owns. **RED** — run the smallest discovered test against the prior behavior and record the failing assertion, fixture and command. **GREEN** — implement just the contract through the production entry point and run that test. **REFACTOR** — remove duplication or simplify responsibilities where needed, then rerun the same test and adjacent regressions. Preserve the RED witness in the implementation PR or commit description. Environment setup failures and intentionally skipped tests do not establish RED. A behavior that already passes receives a regression witness only where a later change could break it. Tasks 11, 15 and 21 connect the seams and run qualification; their component assertions belong in the earlier implementation tasks.

| --- | --- |

| 5. Provider reads | Support **GitHub, GitLab and Gitea statuses** in B. Gitea already has an origin-aware REST adapter and a commit-status endpoint. All three must pass the same exact-revision and missing-check contract. Push mode also works independently. |

### Graph, data and timing contracts

Use one versioned condition registry for schema, compiler, runtime and Studio. The manifest names `on`, a bounded `timeout`, kind-specific parameters, and `transitions`. Use positive integer seconds for relative timeout/after and timezone-qualified RFC 3339 instants normalized to UTC for until/deadline. Freeze accepted and refused YAML examples for every kind in the DSL spec and use those examples in compiler and Studio import qualification. Resolve time inputs once using DB time (UTC for absolute timestamps). Validate and persist original values and effective instants. Every possible outcome has exactly one target, including cancellation. A rework visit starts a new occurrence even if its node ID and head SHA repeat. A signal manifest chooses its finite business labels at compile time; the engine freezes that set and reserves lifecycle labels. Bound schema validation by size/depth, disable remote schema references, and admit only the supported schema dialect. Reject reserved-name collisions, missing/extra branches, invalid times and cycles outside a declared bounded `rework` edge. Permit additional transition keys only for explicit engine controls such as `rework.onExhaustion`; those keys are never operator-resolvable condition outcomes. Preserve existing node IDs such as `failed`. Add an explicit typed failure target in C, e.g. `{end: failed, reason: wait_timeout}`, alongside existing string targets. The legacy `done` sentinel continues into normal graph completion/review.

| Kind | Condition and authoritative outcomes |
| --- | --- |
| `timer` | Exactly one of positive `after` or UTC `until`. `elapsed / timeout / cancelled`. An already-due instant resolves immediately. Evaluate the earlier due instant even if the clock job runs late. Timeout wins equal instants. |
| `comment` | Next qualifying committed `task.comment_added` for this run's task after registration, optionally restricted by server-recognized actor type/ID. `commented / timeout / cancelled`. Refuse a task-less owner at preflight. |
| `run` | Resolve one exact different run ID. Prove direct parent/child via runs.parent_run_id or a declared directed task relation via task_relations, joining both endpoint runs and tasks back to the same project. Freeze target run ID, relation kind/direction and witness at entry; two runs of the related task are distinct. A deleted relation loses authority for future input, pending until timeout or operator action. Reject self, missing/ambiguous target, unrelated and cross-project pairs. `done / failed / review / crashed / abandoned / timeout / cancelled`. Observe an already-settled target at registration; consume both child `run.review` and top-level `run.review_opened` for `review`. Never broaden subscription or authorization to related projects. |
| `signal` | Server-frozen signal name and finite manifest enum; optional bounded JSON schema and optional `bind: head_sha`. Only declared business outcomes plus `timeout / cancelled`, and `stale` exactly when bound. Senders cannot mint outcomes or signal engine-reserved ones. |
| `ci` | Required publication and exact source head. Explicit transport `push` or `pull` for a CI wait, with trusted issuer/check selectors. Both reuse the resolver. `success / failure / cancelled / timeout / stale`. Independent obligations use separate waits/gates, so a weak report cannot win a race with a stronger obligation. |
| `pr` | Bind to the recorded provider/repository/PR, publication generation and expected PR source head. `merged / closed / conflict / timeout / cancelled / stale`. PR-close, merge and conflict are separate provider facts. Keep source SHA and merge commit SHA separate. |

The engine produces bounded `steps.<id>.vars` with outcome, reason, source, wait ID, timestamps, bound/observed SHA and typed condition data (CI includes failing check names and bounded summary). Register a typed engine-produced `wait-result` with the existing evidence graph and original node attempt. Persist provenance, input schema/condition digest, source identity and operator override separately from the outcome. Keep external content in a data namespace; render once as escaped, clearly attributed input, including in rework. Block interpolation into shell, tool arguments that select execution, instructions/templates, paths and authority fields. Cover nested template syntax, top-level promoted vars, context/trailer injection and artifact inclusion. Authorized humans can inspect the original bounded data.

### Persistence, delivery and recovery

| Durable record | Identity, constraint and writes |
| --- | --- |
| `run_waits` | Project/run owner, versioned owner kind and occurrence key, optional owner-specific link (Flow requires the exact node attempt when parked), immutable condition/manifest revision, target and head binding, registration boundary, due/deadline/absolute cap, state, version, resolution and continuation disposition. Unique owner occurrence; composite ownership prevents cross-run/project links. Index open deadlines/timer instants and matching event targets. For publish-triggered CI an addressable reservation may precede node entry. |
| Wait deliveries and actions | Scope dedup to wait + authenticated source + idempotency key. Canonical digest covers operation/name, outcome, head, canonical JSON payload, original attempt/publication generation. Same key/body returns original receipt, changed body conflicts. Append bounded audit of duplicates, stale and rejected submissions separately from the immutable original. Audit known-principal authorization failures at ingress without disclosing the target. |
| Evidence and resume | One result per wait and one continuation per occurrence; unique immutable artifact identity. In the resolution transaction, CAS open wait/version, close the wait interval, write the bounded canonical result/vars and an inline wait-result artifact, delivery application, decision history and outbox. CAS the owning run to Pending with the exact resume reason. Abandon/stop invalidates the continuation. Keep the workspace hold through handoff to the ordinary active owner. |
| Publication and completion | Persist operation intent/claim separately from externally observed effect, keyed by run, attempt, generation and action. Store origin, target/base, source head and expected remote head. Close an unused publication reservation without artifact, graph edge or epoch. Once a wait actually parks, operator cancellation produces its declared cancelled result; owner stop/abandon only closes the occurrence. Completion audit carries a deterministic decision key, actor, effective settings, evidence IDs and hashes, reason, resulting state and delivery commit/PR. Reuse current ledgers where they provide those guarantees. Add rows/columns only for missing facts. |

**Registration and clocks.** Serialize registration with owner lifecycle, bind the frozen target and establish a commit-safe boundary. Use the existing domain dispatcher's transaction visibility semantics or lock the common source for check-and-subscribe. Never use a maximum sequence number alone as a commit watermark. Persist the registration snapshot in the transaction that opens the wait. For comments use source transaction visibility against that snapshot (a previously invisible transaction that commits later qualifies); initial run/PR settlement also reads durable current state. The registration event triggers catch-up after commit, even when the shared consumer has already visited an overlapping event. At boot start the resolver cursor from the beginning or an equivalent transaction-safe backfill; the current dispatcher’s start-from-now maximum ID can lose a lower uncommitted ID. Index catch-up by owner/source. Never replay the entire event table per wait. Test both sides of a concurrently committing comment/settlement. Serialize contenders in a fixed order (run, wait, attempt/receipt), using the common workspace/publication lock where head identity is involved. The DB linearization point selects a single result. For each signal or action, take the decision timestamp from the DB **after** acquiring the wait lock. For events, persist the trusted source-recording instant and at settlement inspect eligible source records committed and visible to that transaction before sealing timeout. A not-yet-visible event cannot undo a sealed result. Order multiple eligible observations by source occurrence then durable source identity. Specify the same comparison for catch-up and live resolution. A qualifying fact durably accepted before its deadline remains replayable if delivery application is delayed. Resolve earlier eligible receipts before timeout under the same lock, use timeout at the boundary, refuse late extensions. Close unused pre-publication reservations by their own immutable cap even if graph entry never happens. An incoming wrong SHA records a stale **delivery** only. Independently verified movement of the bound head produces the **wait outcome** stale. If current head cannot be verified by the deadline, timeout wins. Pre-deadline precedence applies to fully validated durable facts; an unverified submission cannot block the deadline job.

**Wire failures.** Use the established `{code,message,details?:{reason,...}}` envelope and explicit serializers. For signal ingress specify 400 malformed JSON, 413 envelope above 32 KiB UTF-8, 422 invalid field/required header/declared schema, 401 invalid or revoked bearer, 403 disallowed kind/scope, 404 hidden run/wait tuple and 409 `wait_key_conflict / wait_closed / wait_wrong_head`. On session writes also distinguish `wait_version_changed` and `wait_deadline_elapsed`. Match repository error codes (`CONFIG`, `UNAUTHORIZED`, `NOT_FOUND`, `CONFLICT`, `PRECONDITION`); exact bytes and reason tokens belong in the contract examples. Bound body before parse. A transport failure **after** receipt commit is retryable under the original key. An audit/receipt transaction failure cannot return an accepted response. Authenticate before reading prior results. The shared ext handler provides its special idempotency branch only to librarian tokens. Keep project signal dedup in the wait store and use the current ext handler for identity and required token audit.

**Event ownership.** In `docs/system-analytics/domain-events.md` freeze event name/version, project/run address, system/user attribution, receipt reference, dedup key, eligible consumers and commit boundary. Include registration, delivery recorded, head/publication change, CI/PR observation, resolved/closed and autonomous decision events; maintain one wait resolver. Transactionally update SQL kind/ownership CHECKs, the TypeScript taxonomy and consumer dispatch registry. New kinds are project-only and excluded from agent triggers and terminal-kind sets unless explicitly classified. Never put payload/comment text into notifications. Use workbench `run.changed` and Desk attention SSE invalidations followed by authorized projection reads on connect/resync. The canonical per-run execution stream keeps its existing host sequence; a web-domain event cannot mint a host cursor. Only host-origin protocol additions update execution-host OpenAPI/AsyncAPI and the ADR-167 skip rules. Document each affected channel in its own AsyncAPI contract.

**Head observations.** Persist the source of the binding: a local workspace head for a workspace-bound signal, or the publication's remote ref and source SHA for CI/PR. Emit change facts from every managed head writer (commit, rework/rewind, sync, panel and Flow publish, reattach). Capture the bound head before assignment release. For a parked local lookup, add an exact-workspace read-only head operation on BoundClient, explicitly admitted for the latest released **wait** epoch. Compare host, workspace generation, run, wait and last epoch; refuse superseded epochs and mutating operations. Do not reacquire a slot to observe. Recheck the witness/generation at wait CAS and again on admission before dispatch of dependent effects. For published refs use a trusted remote-ref observation; push-only CI can verify the ref without a check-run API. The provider scheduler detects out-of-band remote movement, including a newer attempt for the same SHA. Unknown state remains pending up to the absolute deadline. A mismatch against an old notification alone cannot establish current head movement. A pending wait always has its independent deadline, including during host or provider outages.

**Human controls.** Authenticated run-detail read and POST actions under `/api/runs/{runId}/waits/{waitId}` use session, origin protections and a new project `operateWait` action (member/admin by default). Server returns current version and allowed options. Accept manual signal, resolve-now, extend, cancel, each with reason and expected version. Resolve-now can select *any* compiled outcome, including synthetic success; record operator identity and override. Manual signal uses the same schema/head checks as external delivery. Cancel follows `cancelled`; run abandon closes active waits without following any edge. A manual success can advance a graph but cannot attest provider CI, PR merge, or AI review. Restrict payload/comment/detail reads by existing project/source and repository-content permissions; render redacted metadata when appropriate.

Before any next-node effect, claim the continuation for the exact wait/attempt and admitted epoch. For an unapplied pre-deadline fact, replay uses the same owner/epoch/abandon, current-authority and applicable head guards. If authorization changed or the source cannot be verified at expiry, retire the candidate and resolve timeout. A write that already won stays immutable.

The deadline job uses DB time, ordered due indexes, bounded batches with fair advancement, expiring claims, backoff and classified poison rows. It is the sole clock for waits (ADR-180). The domain consumer handles commit-driven hints and durable replay through the existing dispatcher. Recurring provider reads in B run only in the scheduler. Existing publication/finalize preflights and a single effect-bound verification may make an on-demand read. No UI or graph driver loops on provider state. Browser countdown is local presentation over a server deadline; all state changes arrive via SSE. For any changed ADR-167 ingest guard, state whether later evidence could make the event ingestable. Retry transient gaps and record permanently unapplicable events in the skip ledger, allowing stream progress.

### Publication and autonomous decision boundaries

1. **Publication identity.** Resolve the first name under `projects.public_branch_template` and existing ADR-181 collision/upstream rules; refuse conflicting recorded binding. Use an approved origin and target branch, explicit expected remote SHA/lease, exact local HEAD and clean worktree. Refuse unsafe targets and concurrent writers; never push a dirty or moving snapshot as verified. Optional PR mode is none, draft or ready; attach/reuse an exact source/base PR and report actual draft state. Preserve human Open PR and existing semantics for a reused PR. Engine publication needs a reviewed pinned Flow and an explicit launch-time publication grant restricted to the project, origin, target and PR mode. At admission a human session must have the existing promoteRun privilege, or automation must carry an admin-approved equivalent binding; an ordinary launch or signal token conveys no publication right. Recheck current project publication constraints inside the effect claim; enabling the completion lane is a separate choice. Expose launch preconditions to the picker. Keep remote credentials out of graph data.
2. **CI callback address.** A CI system triggered by the push can finish before the driver enters the next node. For a declared push-CI successor, reserve the attempt-specific callback address and binding before push; permit early receipt, apply only after confirmed publication and matching node entry. Provide a minimal authenticated correlation lookup for CI by exact origin/project, published ref, SHA and configured signal name if the integration cannot transport the supplied callback address. Return only its run/wait address on a unique active match; ambiguous lookups refuse. Publish retries adopt the same reservation, rework gets a new generation, skips/failures/expiry close unused reservations. Test a callback delivered between remote push and local acknowledgement. No unscoped signal mailbox.
3. **Evidence contract.** Eligible input is a fulfilled strict gate set, a current successful CI wait with project-approved source identity, exact required checks, an explicit passing reviewed AI verdict with risk and numeric confidence, and measured diff against the intended target/base. Bind all evidence to the same immutable candidate SHA, reviewed base and publication generation, with each item carrying its **own** producer attempt and role. A gate attempt, CI wait attempt and judge attempt are different rows; match their lineage to the same reviewed candidate and required manifest revision. Count files and additions + deletions across both rename paths and disqualify unmeasurable/binary diffs by default. Preserve `HARD_DENY_GLOBS`, ADR-126 dependency restrictions and human/study holds. Older verdicts without risk or confidence and overridden/advisory/skipped gates cannot satisfy this lane. Pin the CI workflow/issuer trust boundary, including GitLab/Gitea workflow definitions and referenced CI configuration. The candidate branch cannot redefine its own required evidence or obtain the callback credential from graph/agent context. A signal token can attest only its named CI contract if approved by the admin; it cannot set policy or perform completion.
4. **Decision authority.** Extend ADR-095/101 `execution_policy` with the proposed axis `autonomousCompletion` (off or evidence_gated), resolved to off when absent. Use the existing preset/override/snapshot representation. Flow declaration + launch snapshot + current project opt-in and platform/project enablement + no per-run hold are required. Existing presets gain no permission implicitly. Freeze ceiling/issuer/gate declarations at launch, cap by current stricter controls at every decision. Use the existing runtime settings store for a live platform stop; honor existing `MAISTER_AUTO_PROMOTION=off` for promotion as well. No configuration widening, subsequent hold release, stale publisher, CLI flag or token can retrofit a missing launch grant. Human actions still evaluate their own existing authorization and readiness guards.
5. **Promotion and failure.** `promoteRun` owns shipping; check eligibility at the actual claim/effect, not just at a sweep or UI preview. On enrolled runs every machine delivery path uses that gate, including legacy auto-on-ready and ADR-126 lanes. Admit only graph-completed review causes; operator stop/takeover, ordinary human review and protected recovery stay human-owned. Refusal leaves the candidate in Review with an actionable reason. An explicitly declared timeout/exhaustion failure route can end Failed through the existing classified terminal transaction when permitted. If autonomy is held/disabled, route a proposed autonomous terminal action to human Review. Successful evidence does not auto-answer an explicit human node.
6. **What reaches Done.** A verified SHA-preserving local delivery may finish immediately. For a PR-backed enrolled run, publish/open keeps the run live; the `pr` wait or matching scanner fact and a fresh merged-only finalization check unlock Done. Use the existing PR-finalize service and `promoteRun` Review path, preserving its readiness and delivery writers. Source head must match the reviewed/published SHA; the provider merge-commit SHA is a separate witness. Changes to the source through rebase, squash or conflict resolution, or unrelated base drift, invalidate dependent evidence. The target naturally moving to the confirmed merge is expected. For merged PRs compare the recorded pre-merge base and reviewed source to the provider merge receipt and verified merge topology. Where the provider merge strategy cannot supply the necessary identity, retain Review with a reason. Re-publish and reverify the new SHA before completion. Unknown, closed-unmerged or externally merged but under-evidenced candidates require human handling. For the reference PR path, require a reachable bounded PR wait before the graph's completion sentinel, with merged → completion, conflict → bounded resolver/rework, closed/timeout → explicit human or failure branch. At Review, use the retained merge fact and verify the current provider receipt.
