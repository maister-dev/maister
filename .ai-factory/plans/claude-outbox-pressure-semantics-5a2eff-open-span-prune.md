## Ground truth (verified 2026-09-27 against `cc9cf20c`)

**G1. The host deletes a contiguous prefix, and everything else assumes it.** `pruneAcknowledgedRuntimeEvents` (`supervisor/src/host-state.ts:2167-2256`) walks the 100 oldest rows and BREAKS at the first row that is `>= protectedSpan`, unACKed, younger than the grace cutoff (grace mode) or over the 1 MiB page (2206-2218); the floor becomes the last deleted row (2224-2232); `DELETE … sequence_sort_key <= last` must delete exactly `count` rows or it throws `stream_corrupt` (2233-2243); ACK ranges `through <= last` go with it (2244-2246). The boot audit (`auditRuntimeEventState`, 2767-2838) refuses to open a store whose rows between floor+1 and the head are not contiguous; the span store (1999-2036) answers `stream_corrupt` → 503 `runtime_storage_unavailable` for an empty page above the floor; SSE catch-up has no gap detection (`runtime-event-subscribers.ts:193-204`). **Consequence: holes are not an option (option B); the floor must stay a prefix.**

**G2. The span stop is the only thing that keeps ACKed rows past an open prompt.** `protectedRuntimeEventSpan` (2383-2397) = min `accepted_sequence` over v2 receipts whose terminal is not yet ACKed; two callers: the prune (2186) and `runtimeEventPruneState` (2257-2276, `protectedFromSequence`, logged by the stall line at 3213-3222). Nothing else on the host reads outbox rows of a command span: receipt retirement (1550-1638), `/commands/{id}`, terminal evidence and the output manifest (`http-api.ts:1075-1120`, `command-event.ts`), runtime objects and sealed stdout segments (`runtime-objects.ts`), boot recovery (`recoverAcceptedPromptReceipts`, 1385-1538) all use receipt columns or separate files. Its origin is plan S2.2 ("V2 pending spans survive host ACK pruning until terminal ACK", commit `78e7f4b3`) and `execution-prompt-lifecycle.md:305-307` ("Host replay pruning must retain a v2 accepted command's event prefix until terminal acknowledgement").

**G3. The only consumer of that retention is the manager's host-span read, and it always starts at `acceptedSequence − 1`.** `hostSpanPages` (`web/lib/execution-host/prompt-host-span.ts:37-120`) asks `(after, through]`; its callers pass `after = acceptedSequence − 1`, `through = terminalSequence` (`prompt-output.ts:207-217`). `readPromptOutput` chooses ALL-host or ALL-canonical: when `execution_event_streams.last_contiguous_sequence` is null or below `terminalSequence` the whole span is read from the host inside `frontierFallback` (`prompt-output.ts:452-483`); otherwise it requires `count(*)` of `execution_events` in `[accepted, terminal]` to equal the span length (`:484-502`, else `event_span_gap`) and pages canonically (`canonicalPages`, `:124-168`). `verifyHostPromptSpan` (`:553-601`, the D-B4 settlement feed) never consults the frontier. No path mixes the two sources.

**G4. What an unreadable span costs today.** `attemptHostSpan` (`prompt-reconciliation.ts:274-398`) records `host_span_verdict = refused` for EVERY `HostSpanUnavailable` reason (including `replay_floor_lost`) and `busy` only for `command_in_progress`/retryable writes. The ADR-177 stream-lost resolver (`web/lib/reconcile-evidence-db.ts:340-397`, crash at `reconcile.ts:596-601`) defers while the verdict is not `refused`; a refusal on a lost stream crashes the run `stream-lost`. Owner output behind the frontier turns any `HostSpanUnavailable`/`HostSpanSignals` into `incomplete("event_frontier")` (`prompt-output.ts:533-546`), deferred without counting only while the stream is not lost (`prompt-owners.ts:82-96`, `prompt-owner-application.ts:423-441`). **So pruning inside an open span with today's reader turns every such span into `replay_floor_lost` → `refused` → a stream-lost crash — the rescue ADR-167 D5 exists for.**

**G5. The manager's frontier bounds the host's floor.** The manager ACKs only a committed contiguous frontier (`events/consumer.ts:305-338, 355-365, 459-468`; `recordConfirmedRuntimeEventAck` refuses `through > lastContiguousSequence`); the host keeps `floor <= acknowledged_through` (boot audit 2771-2776). Hence **host floor ≤ host ACK ≤ manager `last_contiguous_sequence`** — the host always still holds every row above the manager's frontier, pruned or not. The one exception is a manager whose database went back in time (restore), which is today's `replay_floor_lost` (EDGE-EVT-03) and stays so. The rows and the watermark commit in ONE ingest transaction (`events/ingest.ts:905`, watermark set at `:1221-1229`), so a row at or below a frontier the reader has seen is visible to it.

**G6. A sequence at or below the frontier can be absent from `execution_events`.** `promoteContiguousPrefix` (`ingest.ts:740-856`) steps over `execution_event_skips` rows (`reason: unknown_run | payload_unstorable`; unique on `(event_stream_id, host_sequence)`, carries `run_id`, `event_type`; `schema.ts:4132-4165`). Today the canonical count check fails such a span with `event_span_gap` (not deferred — counts toward poisoning), while a host read still served the row. Once ACKed rows inside a span are pruned, a FOREIGN skipped row in the ACKed prefix could never be verified again. An `unknown_run` skip is foreign by definition (the prompt's run is known).

**G7. The acceptance measurement.** R20 at the default budgets on `cc9cf20c` (N19): nine ~10-minute turns at ~390 rows/s; retained reached soft at 205 s with the prune stalling at once on `protectedFromSequence` 9, hard at 253 s; frames refused with nothing unacknowledged; all nine sessions checkpointed at the 5-min bound and parked. The host logs no line when a producer PAUSES (only `producer-pause-exceeded` at the bound, `http-api.ts:590`; the pause itself is `producer-pressure.ts:92-94`), so "no pause" is not observable today.

## Decisions

**D1 — The floor stays a contiguous prefix; only the span stop goes (host).** A row is prunable iff it is confirmed-ACKed (and, in `grace` mode, older than the grace); `protectedRuntimeEventSpan` and its stop are deleted in BOTH modes, because its one consumer (G3) no longer reads ACKed rows from the host (D3). The walk still breaks at the first unACKed row, at the grace cutoff and at the page byte cap; the floor is still the last DELETED row; ACK ranges still go `<= last`; the boot audit, the span store's contiguity check, SSE replay and every host dependent in G2 are untouched. The floor may now pass an open prompt's `accepted_sequence` — never the ACK watermark. `runtimeEventPruneState` drops `protectedFromSequence`; the stall line keeps `retainedCount` and `acknowledgedThrough` and gains `unacknowledgedCount` (a stall now means only unACKed rows remain above low — the manager is behind).

**D2 — Why not holes (option B), and why not only `retained_pressure`.** Holes break the prefix contract G1 lists (prune walk, ACK ranges, boot audit, span 503 guarantee, silent SSE gaps) and change EDGE-EVT-03 — out of scope by the ADR-183 plan. Keeping the stop in `grace` mode would retain the rule without a reader and keep a 24 h pin for no one; one rule ("never an unACKed row") is simpler and is what the analytics already state for EVT-12 (owner decision 2026-09-27, Q2 = A). Premise, stated in the ADR: the supervisor and the web ship together; a new host beside an old manager (no pager) would lose the host-span rescue for a pruned prefix, and that pairing is not a supported deployment.

**D3 — One span pager, two sources (manager).** A single cursor-driven generator (`promptSpanPages`, new `web/lib/execution-host/prompt-span-pages.ts`) replaces BOTH `canonicalPages` and `hostOutputPages` for every reader of a prompt span (owner output and the D-B4 settlement feed):
1. `cursor = acceptedSequence − 1`; loop until `cursor = terminalSequence`.
2. Before each page, re-read `execution_event_streams.last_contiguous_sequence` (`F`) for the stream row.
3. If `cursor < F`: read the canonical page `(cursor, min(F, terminal)]` — `execution_events` rows merged with `execution_event_skips` rows of the same stream by `host_sequence` (≤ 100 rows / 1 MiB, as `canonicalPages`); a sequence present in neither is `incomplete("event_span_gap")` (an integrity fault — the frontier promised it).
4. Else: read the host page `(cursor, terminal]` through `hostSpanPages` semantics (one page per iteration; same normalization and disposition classification).
5. Host `replay_floor_lost`: re-read `F`; if `F > cursor` (the manager ingested and ACKed past the cursor while the host pruned — the race of G5) continue from step 3; otherwise throw `HostSpanUnavailable("replay_floor_lost")` as today (a genuine loss: restore or foreign store). Termination: every retry requires a strict frontier advance, bounded by `terminalSequence`.
6. `stream_identity_changed`, `beyond_emitted`, `request_failed`, identity/cursor faults: unchanged, thrown as today.
7. `settled_from` stays truthful: `verifyHostPromptSpan` whose frontier already covers the terminal at start (`F ≥ terminal`) reads nothing from the host and returns `canonical_available` — `attemptHostSpan` records no verdict and no settlement (outcome `null`), and the canonical feed settles it with `settled_from = canonical`. A settlement labelled `host_span` therefore always read at least its terminal row from the host.

The verifier `commandEvents` (`prompt-output.ts:257-332`) is unchanged in its checks and gains one row kind (owner decision 2026-09-27, Q3 = A): a **skipped row** `{hostSequence, runId, eventType, reason}` it accepts for contiguity ONLY when `runId ≠ command.runId`; a skipped row of the prompt's own run is `incomplete("event_span_gap")` (unverifiable). The accepted-row binding (`assertAcceptedBinding`) applies to the first row whatever its source (a skipped accepted row is own-run, hence a gap).

**D4 — Signal rule over the whole span.** A read is a *fast feed* when the span is not wholly behind the frontier at its start (`F < terminal`) or when it settles (`verifyHostPromptSpan`). A fast feed refuses (`HostSpanSignals`) on an own-session `CONSUMER_SIGNAL_EVENT_TYPES` row from EITHER source — today it inspects only host rows because the whole span came from the host; the canonical prefix now carries the same obligation. A read that starts with `F ≥ terminal` is the canonical path and, as today, does not refuse on signals (the canonical feed delivers them to their consumers). `frontierFallback` keeps mapping `HostSpanUnavailable`/`HostSpanSignals` to `event_frontier`.

**D5 — What stays the same (explicitly).** `hostSpanEligible`, the verdict mapping (`busy | refused`), `settled_from`, the ADR-177 resolver rule ("crash only on a recorded refusal"), the direct binding (`reconcileStoredPromptEvidence`, canonical-only), `confirmHostSpanSettlement`, the prelude's host object reads (manifest/response are runtime objects, not outbox rows), the span route's wire contract and its `replay_floor_lost` answer below the floor. With D1+D3 a live or lost stream's span is always readable (G5), so the refusals the resolver sees are genuine losses only.

**D6 — Producer pauses become observable (host).** `producerPressure` logs INFO `producer-output-paused {sessionId, runId, outboxRefusesFrames}` on the `outputPaused` false→true edge and INFO `producer-output-resumed {sessionId, runId, pausedMs}` on true→false (`producer-pressure.ts:48-56, 92-94`); at most one pair per pause. No health field (a log is enough for the acceptance and for operators; `producer-pause-exceeded` is unchanged).

**D7 — Acceptance at the default budgets (R20, T3.1), replacing the unreachable "retained < soft at every sample".** The retained-prune trigger IS soft (ADR-183 D3) and a pass prunes only to below low, so retained reads ≈ soft at every trigger by construction. The gate: (a) `pressured` never set; (b) no command refused `event_outbox_backpressure`, no manager pressure record; (c) zero `producer-output-paused` and zero `producer-pause-exceeded` lines; (d) retained never reaches the hard budget; (e) every `outbox-retained-pressure-prune` episode ends below low and `outbox-retained-pressure-prune-stalled` never logs; (f) retained ≥ soft for at most **N** consecutive 1 s samples, where N is MEASURED, not guessed: the first acceptance run records every retained-pressure pass (start/end sample, rows pruned, pages) and N = 2 × the longest measured pass, rounded up to whole seconds and capped at 10; N and its measurement are written into ADR-184 and into the harness as a named constant with the measured value in its comment; (g) achieved ≥ 360 rows/s and every existing R20 gate (lag ≤ 2N, ACKs ≤ batches, no server close, no host-span settlement, all nine prompts settled canonically). Ten-minute window, alone, quiet host, mains power (owner decision 2026-09-27, Q1 = A). Accepted consequence: while retained ≥ soft the host is "constrained" (ADR-183 N10) and completion/teardown evidence is funded from producer wallets — a funding source only, nothing is refused or paused; the windows are bounded by (f).

**D8 — Lock/invariant scope.** No new lock. The invariant "host floor ≤ host ACK ≤ manager frontier" is enforced by existing mechanisms (the ACK route's contiguity/beyond-emitted refusals, the ingest transaction, the boot audit); the pager tolerates the one race it opens (D3.5). The prune transaction (`BEGIN IMMEDIATE` per page) is unchanged.

**Recovery windows (normative).** The pager is read-only; the host prune is per-page transactional. W1: host pruned `(cursor, F']` between the pager's frontier read and its host request → `replay_floor_lost` → re-read → canonical (D3.5). W2: the manager crashes mid-read → nothing was written; the next reader starts over. W3: a manager restored behind the host's ACK → frontier < floor → `replay_floor_lost` without advance → `refused` → today's EDGE-EVT-03 path (stream `unrecoverable` / resolver crash on a lost stream). W4: host restart mid-span → boot audit passes (prefix intact); the span resumes from the manager's frontier.
