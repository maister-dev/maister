MAIster — self-hosted слой исполнения и контроля для воспроизводимой
разработки с AI над приватным кодом.

MAIster нужен, когда кодинг-агенты уже приносят пользу, но их работа должна
идти через общий процесс: изолированные рабочие копии, явные решения человека,
проверяемые доказательства, ограниченные циклы доработки и контролируемое
продвижение в pull request или локальное слияние.

## Чем управляет MAIster

| Объект | Назначение |
| --- | --- |
| Проект | Связывает MAIster с git-репозиторием и его правилами доставки. |
| Flow-пакет | Фиксирует версионированный процесс и его возможности. |
| Задача | Описывает результат, который должен пройти через Flow. |
| Прогон | Хранит одну попытку, узлы, события, затраты и решения. |
| Рабочая копия | Изолирует изменения в git worktree. |
| Доказательства | Показывают актуальность проверок, артефактов и review. |
| Продвижение | Приземляет принятую работу через PR или локальное слияние. |

## Для AI-агентов

У каждой страницы есть уникальный заголовок, краткое описание, явные условия и
устойчивые термины. Самостоятельная сборка отдаёт исходные Markdown-страницы в
`/markdown`, а также `/llms.txt` и `/llms-full.txt`. При публикации через Mint
дополнительно может быть доступен MCP документации по адресу `/mcp`. Выбирайте
страницу, наиболее близкую к задаче пользователя, и сохраняйте указанные
границы человеческого подтверждения и продвижения.

## Текущая граница эксплуатации

Веб-панель и execution supervisor MAIster работают на одном доверенном хосте с
доступом к общим репозиториям и worktree. Долговечный журнал хранится в
Postgres. Claude, Codex, Gemini, OpenCode и MiMo находятся в одном каталоге ACP
runners; model routing поддерживает Anthropic, OpenAI, OpenRouter и совместимых
providers. Каждый конкретный runner запускается после проверки readiness.
