`flow.yaml` — контракт пакета процесса доставки. Schema version 1 описывает
метаданные, совместимость, узлы, переходы, входы, выходы, gates и ограниченную
доработку.

## Форма

```yaml
schemaVersion: 1
id: feature
name: Feature delivery
version: 1.0.0
compat:
  engine_min: 3.0.0
start: implement
nodes:
  - id: implement
    kind: agent
    transitions:
      success: verify
  - id: verify
    kind: check
    transitions:
      success: review
      failure: implement
  - id: review
    kind: human_review
    transitions:
      approved: done
      rework: implement
  - id: done
    kind: terminal
```

Это структурный пример. Настройки зависят от вида узла и минимальной версии
движка, объявленной пакетом.

## Правила автора

- Давайте каждому узлу стабильный уникальный id.
- Объявляйте все цели переходов.
- Ограничивайте каждый цикл доработки.
- Выбирайте runner явно или осознанно наследуйте его.
- Объявляйте обязательные входы и доказательства вне текста промпта.
- Используйте setup-скрипты только в доверенных исполняемых пакетах.
- Повышайте `compat.engine_min` только при необходимости нового контракта.

## Контракт установки

До запуска MAIster проверяет граф и совместимость. Ревизия и статус доверия
записываются при установке. Изменение источника не меняет активный прогон.
