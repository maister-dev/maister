MAIster передаёт агентную работу через адаптеры Agent Client Protocol.
Платформенный runner выбирает семейство адаптера, модель, провайдера, политику
разрешений и окружение дочернего процесса.

## Единый runtime-каталог

Профили Claude, Codex, Gemini, OpenCode и MiMo находятся в одном управляемом
каталоге runners. Model routing поддерживает Anthropic, OpenAI, OpenRouter и
другие Anthropic- или OpenAI-compatible endpoints через настройки provider.
Одни и те же продуктовые контроли управляют всеми вариантами исполнения.

Перед launch каждый конкретный runner должен пройти diagnostics и smoke-контракт
своего адаптера. Автоматической подмены adapter, model или provider нет.

## Выбор runner

Приоритет разрешения:

1. runner узла;
2. runner привязки Flow;
3. runner проекта по умолчанию;
4. runner платформы по умолчанию.

Разрешённый профиль фиксируется при запуске, поэтому изменение настроек не
меняет активную сессию.

## Учётные данные

CLI агентов и токены находятся на execution host у пользователя supervisor. В
настройках храните ссылки вида `env:OPENAI_API_KEY`, а значение — только в
окружении supervisor.

## Область возможностей

Сессия получает skills, MCP-серверы, инструменты, настройки, профили окружения и
ограничения, объявленные для проекта, Flow, узла и семейства агента. Этот набор
фиксируется на запуске. Запись в БД сама по себе не переносит локальные файлы
возможностей на другой execution host.
