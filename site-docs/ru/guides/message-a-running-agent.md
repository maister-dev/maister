В scratch-диалоге проекта можно отправить уточнение, пока агент работает.
MAIster сразу сохраняет сообщение и передаёт его в текущий ход через steering
либо ставит в очередь следующего хода. Перезагрузка страницы не удаляет очередь.

## Отправьте уточнение в scratch-диалоге

1. Откройте scratch-прогон проекта и убедитесь, что он **Running**.
2. Отправьте инструкцию через поле сообщения.
3. Проверьте отметку доставки в диалоге и последующий ответ агента.

| Отметка | Значение |
| --- | --- |
| В ход (Steered) | Инструкция передаётся через steering текущего хода. Если доставка ещё уточняется, отметка может смениться на «В очереди». |
| В очереди (Queued) | Сервер сохранил инструкцию для следующего хода. Сообщения отправляются от самого раннего к поздним. |
| Не отправлено (Not sent) | Диалог завершился раньше, чем сообщение из очереди было отправлено. |

Steering зависит от возможностей конкретной сессии адаптера. Если сессия его
не поддерживает или отклоняет попытку, сообщение попадает в очередь. **Steered**
не обещает немедленного выполнения инструкции или отмены уже работающего
инструмента: проверьте диалог и результат работы.

Scratch не принимает сообщение во время первоначального запуска, ожидания
ответа на разрешение и после завершения диалога. На разрешение отвечайте через
[HITL](/ru/guides/human-in-the-loop). Ассистенты Studio и оценивания принимают
следующее сообщение только после окончания текущего хода.

## Восстановите работу с очередью

После сбоя scratch-диалога **Recover** сохраняет прежнюю очередь и добавляет
сообщение восстановления после неё. Если перезапуск Web или временный отказ
в допуске оставил сообщения в очереди, сервер автоматически повторит отправку
самого раннего, когда диалог и сессия хоста будут готовы. **Queued** означает,
что сообщение сохранено; не отправляйте его повторно ради запуска доставки.
После остановки, завершения или терминальной ошибки диалога недоставленные
сообщения видны как **Not sent**.

Recover допускается для диалога после сбоя; это не способ принудительно
перезапустить живой или ожидающий прогон. Если сессия исчезла, но прогон ещё
считается живым, дождитесь автоматического определения состояния. При
**NeedsInputIdle** ответьте на ожидающий запрос для продолжения сохранённой
сессии; возобновление может ждать свободного слота или восстановления хоста.

После сбоя хоста или сессии восстановление может доставить инструкцию повторно.
Перед повторной отправкой команд с внешними эффектами проверьте диалог.

[Личный библиотекарь](/ru/guides/personal-librarian) может передать сообщение
оператора подходящему scratch-прогону или постоянному агентному прогону с
вашими проектными правами. Проверьте результат доставки в записи операции.
Это отдельный путь от интерфейса токена координатора ниже.

## Обратитесь к постоянному дочернему агенту

Координатор через внешний API или MCP `run_message` может обратиться к своему
постоянному дочернему агенту ровно одним полем: `addressableKey` или
`childRunId`. Значение `childRunId` должно быть UUID. Режим `mode: "steer"`
пытается передать сообщение в текущий ход; по умолчанию используется
`mode: "queue"`. Поле `delivery` ответа сообщает `steered` либо `queued`.
При повторе того же сообщения используйте прежний `requestKey`.

Нужен привязанный к прогону токен координатора с правом `runs:delegate`.
У дочерних Flow нет адресуемой агентной сессии для этой операции.
Для получения результатов `run_collect` принимает ровно одно поле:
`childRunId` либо `all: true`. Получение результата само по себе не отправляет
сообщение агенту.
