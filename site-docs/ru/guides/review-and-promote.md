## 1. Проверьте цель

Сверьте проект, задачу, ревизию Flow, базовую и целевую ветки. Если база
изменилась, обновите прогон по подсказке интерфейса до оценки старых
доказательств.

## 2. Изучите результат

Прочитайте сводку и полный diff. Затем проверьте обязательные доказательства,
логи, структурированные результаты, решения людей и историю попыток. Зелёного
агентного узла недостаточно при отсутствующих или устаревших доказательствах.

## 3. Примите решение

- **Принять**, если результат и доказательства актуальны.
- **Вернуть на доработку** с конкретными комментариями.
- **Перехватить**, если работу должен продолжить человек.
- **Остановить**, если задача не должна продолжаться.

## 4. Продвиньте результат

Политика доставки проекта задаёт стратегию по умолчанию. При запуске можно
выбрать другую, а прогон сохраняет стратегию, с которой был запущен.

| Стратегия | Результат | Требование к хосту |
| --- | --- | --- |
| **Merge** | Сливает ветку прогона в выбранную локальную целевую ветку. | Чистый репозиторий и отсутствие конфликтов |
| **Rebase + merge** | Переносит ветку прогона на целевую и затем сливает. При конфликте восстанавливает прежнее состояние. | Чистый репозиторий |
| **AI rebase + merge** | Переносит и сливает; конфликт передаётся ИИ-разрешителю, а прогон возвращается на **Review** для повторного продвижения. | Чистый репозиторий |
| **Pull request** | Публикует ветку и открывает pull request. | Авторизация провайдера и данные для git push |
| **Опубликовать ветку** | Отправляет ветку прогона под её публичным именем и не трогает целевую ветку. | Данные для git push и настроенный remote |

Стратегию **Опубликовать ветку** выбирают при запуске прогона задачи. После
обязательных проверок и ревью MAIster отправляет ветку и показывает remote и
ветку на странице прогона. Если push отклонён, прогон остаётся на **Review** с
ошибкой Git и действием **Повторить доставку**; повтор использует то же
назначение и никогда не делает force-push. Публикация ветки не завершает задачу.

MAIster не развёртывает слитый результат. Deployment остаётся в существующем
CI/CD.

Со стратегией **Pull request** задача завершается сама после того, как
провайдер сообщит о слиянии. Если PR не закрывает задачу целиком, перед продвижением
отметьте **Частичная работа — задача остаётся открытой**. Подробнее —
[когда задача завершается](/ru/guides/run-git#когда-задача-завершается).

## Публикация до завершения

[Git-панель прогона](/ru/guides/run-git) позволяет опубликовать ветку и открыть
PR до завершения прогона. Открытие PR сохраняет состояние прогона. Finalize —
отдельное действие; требования готовности зависят от состояния прогона.

## Конфликты

При конфликте MAIster останавливает продвижение. Разрешите конфликт в
контролируемой рабочей копии, заново выполните затронутые проверки и проведите
review новых доказательств.
