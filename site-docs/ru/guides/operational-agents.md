Операционный агент выполняет действие и сохраняет свидетельства результата.
Агент изменения кода готовит исходники для ревью и продвижения. Вид агента
задаётся в пакете; доступ к рабочей области и разрешения инструментов настраиваются
отдельно.

## Настроить определение

Нужен MAIster с движком 3.9.0 или новее и доверенный пакет, подключённый к проекту.
В манифесте пакета укажите `compat.engine_min: "3.9.0"`, а в определении агента:

```yaml
kind: operational
completion:
  contract: operational_v1
mode: session
workspace: worktree
```

Studio показывает вид агента и контракт завершения. Если вид не указан,
сохраняется поведение агента изменения кода. Сейчас поддерживаются конечные
самостоятельные сессии. Постоянные сессии, режим subagent, привязка к Flow,
конфликтующий профиль результата и общая рабочая область с записью отклоняются
до выполнения.

Оба варианта GitHub Issue Intake используют этот контракт. Выберите **gh**, если
на узле выполнения доступен GitHub CLI, или **MCP**, если проект привязывает
нужное подключение GitHub. Репозиторий и размер пакета обработки задаются для
каждого подключения агента к проекту. Вид агента не включает автоматическое
одобрение инструментов: разрешения, изоляция, бюджеты и решения человека действуют
по обычным правилам.

## Прочитать результат

Завершающий ход должен опубликовать один объект `json maister:output` по
зафиксированным инструкциям платформы. Платформа проверяет счётчики, полноту
обработки, ссылки, диагностику с дальнейшими действиями и целостность исходников.

- **Успех** завершает запуск как **Done**. Полная проверка без новых задач успешна.
- **Частично выполнено**, **заблокировано** и **ошибка** завершают запуск как
  **Failed**. Подтверждённая работа и неопределённые эффекты сохраняются вместе
  с инструкциями по устранению проблемы.
- Отсутствующий или некорректный результат не подтверждает успех. Отмена остаётся
  **Abandoned**, а потеря выполнения — **Crashed**.

GitHub 403 означает ошибку доступа, а не успешную проверку пустого списка.
Неопределённый результат создания задачи или комментария требует сверки перед
повтором. Потерянный ответ сам по себе не разрешает повторить запись.

На странице запуска видны результат операции, диагностика, ссылки, целостность
и состояние очистки. У операционных запусков нет действий ревью, продвижения,
слияния и публикации. Неожиданные изменения исходников приводят к ошибке проверки
и сохраняются для диагностики. Изменения общего репозитория нельзя без проверки
приписывать агенту или удалять как его временную рабочую область.

## Разобрать ошибку и очистить область

История автоматизаций показывает отправку отдельно от фактического состояния
запуска. Ошибки операций и исчерпанные попытки очистки попадают в очередь внимания.
Откройте запуск, выполните указанные действия и подтвердите ознакомление с точной
ревизией ошибки. Подтверждение влияет только на вашу очередь.

Завершённая операция сразу уходит из активных рабочих копий. Платформа сохраняет
свидетельства выполнения до удаления принадлежащих запуску ресурсов. После сбоя
рабочая область остаётся на настроенный срок диагностики — по умолчанию 14 дней.
Срок хранения свидетельств не сокращается из-за немедленной очистки области;
действующие удержания свидетельств и сессий сохраняются. Загрузка свидетельств
требует права чтения файлов репозитория проекта.

Число попыток очистки ограничено. Устранив причину исчерпанной очистки, нажмите
**Повторить очистку рабочей области**. Это повторяет удаление ресурсов, а не внешнюю
операцию. Повтор операции — отдельный запуск. Обновление пакета меняет будущие
запуски; существующие сохраняют исходные вид, контракт и инструкции. Старые агенты
изменения кода продолжают использовать прежние правила ревью.


## Найти историю и повторить запуск с другим runner

Rail показывает каждое активное исполнение агента, включая очередь и ожидание,
в отдельном списке. После завершения строка исчезает. На вкладке **Агенты** проекта
видны число сохранённых запусков и последнее состояние. Страница агента содержит
постраничную историю запусков и попыток срабатывания, закреплённое определение,
память и настройки подключения. После отключения история доступна для чтения.
Число сохранённых запусков не означает число запусков за всё время.
Определение и память требуют чтения репозитория; изменения памяти проверяются по
версии. Промпт меняется через пакет и явное обновление закреплённой версии.

Inbox объединяет проблемы по проекту и агенту. Повтор причины увеличивает счётчик,
но не создаёт новую карточку и не уведомляет снова после подтверждения ознакомления.
Новая причина может потребовать внимания. Решения человека остаются отдельными
запросами с собственными действиями.

**Запустить повторно…** показывает новый запуск с выбранным для него runner.
Действие доступно только при подтверждении, что прежнее исполнение не начало работу.
Проверьте изменения входных данных, выберите готовый runner и подтвердите попытку.
При потере ответа тот же запрос возвращает квитанцию, не создавая второй запуск.
Исходная история, runner исполнения задачи и настройки будущих запусков сохраняются.
Неопределённые эффекты требуют сверки. Повтор очистки только удаляет ресурсы.

## Оценить входящую постановку

Обновлённый core с импортёрами и triager требует движок **3.10.0 или новее** и
политику **Обязательная оценка** в настройках проекта до активации пакета. Новые
проекты используют её по умолчанию; существующие сохраняют исходное правило до
явного изменения. Сброс настройки восстанавливает правило при создании проекта.
Отключение политики не снимает удержания уже управляемых ею задач.

Оба транспорта GitHub сохраняют исходное issue и создают задачу во **Входящих**,
не принимая её в реализацию. Triager использует общую процедуру оценки и доступный
только для чтения снимок SHA целевой ветки, определённой сервером. Он проверяет
цель и границы, критерии приёмки, непротиворечивость, ограничения и зависимости,
дубликаты, актуальность и свидетельства дефекта. Чтение кода не означает
воспроизведение бага: нехватка runtime-свидетельств требует проверки.

Принятая оценка **Допущено в бэклог** переводит задачу в принятый бэклог. **Нужны
сведения**, **Нужна проверка** и **Запрос не требует реализации** остаются во
Входящих с конкретными следующими действиями. Это может быть успешным результатом
операционного агента. Сбой runner/API относится к исполнению и не доказывает
некорректность запроса. Ответ человека продолжает тот же запуск; явный повторный
разбор — отдельное действие.

На странице задачи доступны свидетельства и форма оценки человека. Каждая проверка
требует обоснования; готовность также требует свидетельств репозитория об актуальности.
Изменение постановки и подтверждённые уточнения делают прежний допуск неактуальным.
Перед исполнением сервер сверяет ревизии и исследованный SHA, включая ручной и
принудительный запуск. Кандидат агента остаётся удержанным до проверенного чистого
завершения. Ошибка, частичное выполнение, отмена или изменения исходников не
разрешают публикацию оценки.
