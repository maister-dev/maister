title: "Git-действия с рабочей копией прогона"
description: "Сохранение и отмена изменений, публикация и обновление ветки, создание PR и восстановление удалённого worktree."
---

Откройте Git-панель через действия прогона. Она работает с рабочими копиями
Flow, платформенных агентов и scratch-прогонов, когда агент уже не пишет в них.
Публикация ветки и открытие PR сохраняют текущее состояние прогона.

## Что потребуется

- Роль `member` в проекте или выше.
- Прогон в **Review**, **Crashed**, **Failed**, **Done** или **Abandoned** с
  доступным worktree и без конфликтующей операции.
- В **Human working** Git-действия доступны только владельцу открытого
  перехвата на доработку; завершение, архивирование и удаление пока недоступны.
- Для публикации — настроенный remote и права Git push. Для PR также нужны
  авторизация у провайдера и публикация в `origin`.

Отключённое действие объясняет, какое условие не выполнено. Даже остановленный
или неуспешный прогон может содержать полезные изменения: сначала проверьте diff.

## 1. Закоммитьте или отмените локальные изменения

Раздел **Tree** показывает изменения отслеживаемых и новых файлов. **Commit**
создаёт снимок. **Discard** сначала сохраняет резервный снимок, затем
сбрасывает рабочее дерево и удаляет неотслеживаемые файлы. После операции
появятся rescue-ссылка и команда восстановления. Если staged-версия отличалась
от рабочего дерева, её сохраняет второй родитель rescue-коммита.

Перед обновлением ветки или открытием PR закоммитьте либо отмените изменения.
Rescue-ссылки переживают архивирование и удаление worktree, но не заменяют
резервную копию на remote.

## 2. Опубликуйте ветку

Выберите remote и проверьте публичное имя ветки. Шаблон проекта по умолчанию —
`feature/{task_key}-{slug}`. Внутренняя ветка прогона сохраняет своё имя.
Существующий upstream или записанная публикация фиксирует публичное имя.

Успешная публикация сохраняет remote и ветку и показывает команды checkout.
Если push заменит удалённую историю, MAIster покажет затрагиваемую ссылку и
коммит перед подтверждённым повтором. Новое изменение remote потребует нового
подтверждения.

## 3. Обновите ветку

В **Update** выберите базовую, целевую или опубликованную ветку прогона и
стратегию rebase либо merge. Проверьте опцию push: для опубликованной ветки она
включена по умолчанию. Если будут потеряны коммиты, существующие только на
remote, сначала включите опубликованную ветку либо явно подтвердите замену
показанной удалённой вершины.

При механическом конфликте операция возвращает исходное состояние и показывает
конфликтующие файлы. AI-разрешение доступно только в **Review**. Обновление
недоступно scratch-прогонам, дочерним прогонам оркестратора, общим worktree,
запущенным участникам исследования и уже продвинутым прогонам. Остальные
допустимые Git-действия доступны независимо.

После изменения ветки проверьте результат и заново получите затронутые
доказательства.

## 4. Откройте PR и завершите прогон

После публикации откройте **PR**, задайте заголовок, описание, целевую ветку и
признак draft. Worktree должен быть чистым, а его HEAD — совпадать с
опубликованной вершиной в `origin`. Цель scratch-прогона остаётся фиксированной.
Существующий открытый PR с той же исходной и целевой веткой возвращается без
изменения заголовка или draft. Поддержка draft зависит от провайдера: проверьте
состояние созданного PR у него.

**Finalize** переводит прогон в **Done**; это не означает слияние PR у
провайдера. Из **Review** действуют обычные проверки готовности и смещения
целевой ветки. Из **Crashed**, **Failed** или **Abandoned** требуется отдельное
подтверждение; такое завершение не подтверждает прохождение readiness-проверок.

Завершение проверяет фактическую вершину записанного PR. Закрытый PR не
принимается. Если PR уже слит, а в worktree появились более поздние коммиты,
для них потребуется новый PR.

## 5. Восстановите удалённый worktree

Если рабочая копия отсутствует, вместо остальных разделов появляется
**Reattach**. MAIster последовательно проверяет локальную ветку прогона,
опубликованную ветку и архивную ссылку. Восстановление сохраняет идентичность
прогона и не возобновляет агента. Если источников нет или путь занят другой
директорией, действие объяснит отказ. Для подходящих терминальных прогонов
после восстановления начинается новый срок до очистки worktree.

Подтверждения архивирования и удаления показывают неопубликованную работу и
могут сначала опубликовать её. Убедитесь в успехе публикации, прежде чем
полагаться на удалённую копию.
