## Условия

- Права владельца или администратора проекта с доступом к файлам репозитория
- Основная ветка проекта выбрана в checkout на хосте MAIster
- Чистые рабочая директория и индекс, без незавершённых Git-операций
- Переносимые источники пакетов, соответствующие установленным ревизиям

Подключение, отключение, обновление или откат пакета применяются в MAIster.
Изменение раннера по умолчанию также применяется сразу. Эти действия не меняют
отслеживаемые файлы репозитория. Новые Run используют выбранную конфигурацию;
существующие Run сохраняют закреплённые ревизии.

## Проверка и локальный коммит

1. Откройте **Проект → Настройки → Git → Конфигурация в Git**.
2. Обновите статус. MAIster сравнит экспортируемые runtime-настройки с
   манифестом, закоммиченным в основной ветке. Метка **не проверено** в портфеле
   требует такой свежей проверки.
3. Нажмите **Просмотреть сохранение конфигурации**. Проверьте полный diff
   `maister.yaml`, целевую ветку и точное сообщение коммита. Если Git identity
   задана не полностью, прочитайте уведомление об авторе.
4. Подтвердите **Закоммитить проверенную конфигурацию**.
5. Проверьте результат и SHA. Эта же команда доступна для последующих
   изменений, в том числе при уже существующем манифесте.

Отмена не меняет репозиторий. Если экспортируемые значения уже совпадают с Git,
MAIster сообщит об отсутствии изменений и не создаст пустой коммит. Комментарии
и посторонние разделы манифеста сохраняются.

Экспортируются имя проекта, настройки веток, раннер по умолчанию, режим
продвижения и версии подключённых пакетов. У очереди, Brain, политик
синхронизации и исходных настроек Flow/capabilities отдельные владельцы.
Сохранение этой проекции не экспортирует все runtime-настройки и не заменяет
посторонние разделы манифеста.

## Отдельный push

После локального коммита нажмите **Просмотреть push этого коммита**. Проверьте
SHA, адрес origin, ветку назначения, базу remote и полный список отправляемых
коммитов. Затем подтвердите **Отправить проверенные коммиты**. Локальное
сохранение само не выполняет push. Force push не используется.

Отклонённый push не удаляет локальный коммит. Исправьте доступ к remote или
ошибку hook и создайте новое предложение push. Если результат неизвестен,
сначала проверьте ту же операцию, прежде чем отправлять снова. При этом новое
локальное сохранение доступно через **Заново просмотреть локальную конфигурацию**;
результат предыдущего push остаётся сохранённым.

## Блокировки и прерванное сохранение

- **Локальные или staged-изменения:** вручную проверьте и закоммитьте либо
  переместите их. Это относится и к неотслеживаемому `maister.yaml`, оставшемуся
  после старой регистрации. MAIster не делает stash, не отбрасывает изменения
  и не коммитит посторонние файлы.
- **Устаревшее предложение:** создайте новое и проверьте diff ещё раз.
  Изменения runtime-конфигурации, Git или прав могут отменить старую проверку.
- **Ошибка коммита:** проверьте hooks, автора и политику подписи, устраните
  причину и создайте новое предложение.
- **Потерянный ответ или прерванная операция:** откройте Настройки и проверьте
  результат операции. Используйте **Проверить и восстановить эту операцию**,
  когда команда доступна. Сохраните ID; не запускайте новое сохранение ради
  предположения о результате предыдущего.
- **Сохранённые приватные файлы или неизвестные lock-файлы:** не удаляйте их.
  Попросите оператора хоста проверить указанную операцию перед восстановлением
  или очисткой.

Отказ экспорта не отключает пакеты и не отменяет применённую конфигурацию.
Завершённый локальный коммит сохраняется, даже если push или восстановление
результата требуют внимания.
