MAIster связывает потребление ресурсов с delivery-работой, а не оставляет его
только в логах провайдера. Сейчас учитываются токены и время исполнения; USD
pricing и enforcement `maxCostUsd` не входят в текущий контракт.

## Представления расходов

Проверяйте rollup на уровне Run и node attempt. Observatory агрегирует
потребление по проектам, Flows, моделям и runners и помогает находить дорогие
процессы, повторы и неравномерное использование исполнителей.

Стоимость рассматривается вместе с длительностью, evidence, readiness и
результатом promotion. Более дешёвый Run не считается автоматически лучшим.

## Лестница бюджета

У бюджета исполнения три явные реакции:

1. **Warn** записывает и показывает приближение к лимиту.
2. **Escalate** запрашивает решение человека до дальнейшего расхода.
3. **Terminate** останавливает работу с typed-результатом `BUDGET_EXCEEDED`.

Child Runs и platform agents потребляют управляемые бюджеты внутри видимых run
trees. Не выносите фоновую работу из ledger ради обхода учёта.

## С чего начать

Сначала задайте warning-пороги для квалифицированного Flow. Наблюдайте несколько
реальных Runs, затем добавьте escalation и termination там, где уже понятны
повторы и evidence-поведение.
