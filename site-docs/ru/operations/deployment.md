---
title: "Развёртывание на одном хосте"
description: "Разверните MAIster на Linux с systemd, локальным supervisor, Postgres и TLS reverse proxy."
---

Поддерживаемая production-топология: web и execution supervisor работают как
непривилегированные сервисы хоста, Postgres работает локально, а TLS reverse
proxy публикует только веб-приложение.

## Топология

```text
client → TLS proxy → web :3000 → supervisor :7777
                         │              │
                         └→ Postgres    └→ agent adapters + git worktrees
```

Supervisor и Postgres слушают loopback. Не открывайте их порты во внешнюю сеть.

## Требования к хосту

- Современный Linux с systemd
- Node.js 24, pnpm, git и Docker
- Выделенный непривилегированный пользователь сервиса
- Постоянные директории для checkout, репозиториев, runtime state и данных агентов
- Авторизация провайдера для режима продвижения через pull request

## Сборка и база

```bash
pnpm install --frozen-lockfile
docker compose up -d postgres
pnpm --filter maister-web db:migrate
pnpm --filter maister-web db:migrate:brain
pnpm --filter maister-web build
```

Сборка web также собирает внутренний MCP-фасад для агентов.

Запускайте supervisor и web как отдельные systemd-сервисы под одним доверенным
пользователем. Задайте надёжный `AUTH_SECRET`, production `DB_URL` и URL
supervisor в окружении сервисов.

## Reverse proxy

Завершайте TLS в nginx, Caddy или эквивалентном proxy. Сохраните streaming для
SSE и передавайте исходные заголовки host и protocol. Публикуйте только web;
порт `7777` должен оставаться приватным.

## Обновления

Закрепляйте ревизию исходного кода или тег образа. Перед обновлением дождитесь
завершения активных запусков и остановите оба сервиса. Сохраните Postgres,
состояние supervisor, его данные исполнения и сохранённые рабочие копии в
одном комплекте резервных копий. Установите зависимости по lockfile, выполните
обе линии миграций и запустите `pnpm --filter maister-web build`.
Запустите supervisor перед web. На каждом хосте исполнения проверьте
развёрнутый фасад командой `pnpm --filter @maister/mcp verify:stdio-contract`.
Проверьте готовность адаптеров и выполните некритичный smoke-прогон.

## Как включить хранилище памяти агентов

Примените основные миграции базы данных. В окно обслуживания дождитесь
завершения запусков агентов и остановите службы, которые могут писать в старые
файлы памяти. Вместе сохраните резервные копии Postgres и каталога данных
исполнения. Выполните команды из корня репозитория с настройками подключения
к БД веб-службы. В `MAISTER_RUNTIME_ROOT` укажите исходный каталог данных, в
`ADMIN_ID` — идентификатор действующего глобального администратора.

```bash
pnpm --filter maister-web agent-memory:import
pnpm --filter maister-web agent-memory:import --import --actor-user-id "$ADMIN_ID"
pnpm --filter maister-web agent-memory:import --activate --actor-user-id "$ADMIN_ID"
```

Первая команда показывает, что найдено для переноса. До активации разберите
случаи, когда файл изменился или его владельца не удалось определить.
Активация проверяет импортированные файлы и переключает запись на Postgres.
Запустите обновлённые службы, откройте импортированную заметку на вкладке
**Память** агента и убедитесь, что правка сохраняется. До этой проверки храните
исходные файлы. Для возврата к версии до активации восстановите БД и каталог
данных из одной резервной копии. Память вернётся к состоянию на момент копирования.
