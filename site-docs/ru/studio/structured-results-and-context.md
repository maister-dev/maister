Структурный результат позволяет узлу передать небольшое значение JSON без
разбора свободного текста. MAIster проверяет его по схеме пакета и сохраняет с
конкретной попыткой узла.

## Что потребуется

- Граф Flow и файл `schemas/*.json` в корне пакета.
- Совместимое значение `compat.engine_min`.

## Объявление результата

```yaml
nodes:
  - id: plan
    type: ai_coding
    action:
      prompt: "Спланируй {{ task.prompt }} и верни структурный результат."
    output:
      result:
        schema: ./schemas/plan-output.json
        required: true
      produces:
        - id: plan-document
          kind: plan
          path: plan.md
```

Результат и `plan-document` разделены. В результате удобно хранить риск,
затронутые компоненты или рекомендуемый раннер. Доказательство указывает на
полный текст плана для проверки.

```json
{
  "schemaVersion": 1,
  "fields": [
    {
      "name": "risk",
      "type": "enum",
      "options": ["low", "medium", "high"],
      "required": true
    },
    {
      "name": "components",
      "type": "array",
      "items": { "type": "string" }
    },
    { "name": "details", "type": "json" }
  ]
}
```

Поддерживаются `string`, `number`, `boolean`, `enum`, `array`, `object` и
`json`. Объекты открытые: объявленные поля проверяются, дополнительные
сохраняются. Размер ограничен `MAISTER_NODE_OUTPUT_MAX_BYTES`, по умолчанию
256 КиБ.

## Передача JSON разными узлами

| Узел | Способ |
| --- | --- |
| `ai_coding`, `judge`, `orchestrator` | Завершающий ответ содержит последний корректный блок с пометкой `json maister:output`. |
| `cli`, `check` | Команда записывает JSON в путь текущей попытки из `MAISTER_OUTPUT_FILE`. |
| `consensus` | Проверяется объект, собранный движком консенсуса. |
| `human`, `form` | Ответ человека уже становится переменными; `output.result` здесь запрещён. |

Ответ агента заканчивается так:

````markdown
```json maister:output
{"risk":"medium","components":["web","supervisor"]}
```
````

Отсутствие обязательного блока или файла завершает попытку ошибкой. Переданный,
но неверный JSON всегда считается ошибкой.

## Использование в следующих узлах

```yaml
- id: implement
  type: ai_coding
  action:
    prompt: >-
      Реализуй {{ task.prompt }}.
      Риск по плану: {{ steps.plan.vars.risk }}.
```

Основные пути шаблона:

| Путь | Значение |
| --- | --- |
| `task.id`, `task.title`, `task.prompt` | Задача и требуемый результат. |
| `run.id` | Текущий прогон. |
| `executor.model` | Модель из снимка раннера. |
| `steps.<id>.output` | Сокращённый текст последней попытки узла. |
| `steps.<id>.vars.<field>` | Проверенное поле последней попытки. |
| `steps.<id>.exitCode` | Код завершения команды. |
| `artifacts.<id>.kind`, `.uri`, `.validity`, `.nodeId` | Метаданные актуального доказательства. |
| `artifacts.<id>.content` | Ограниченное тело доказательства для узла с запросом. |

Отсутствующий путь без значения по умолчанию даёт ошибку конфигурации. Если
отсутствие допустимо, напишите:

```text
{{ steps.plan.vars.risk ?? "unknown" }}
```

После повтора выбирается попытка с наибольшим номером, а прошлые остаются в
журнале.

## Маршрутизация по результату

```yaml
decide:
  from: output.risk
transitions:
  low: implement-fast
  medium: implement
  high: human-review
```

Объявите переход для каждого возможного значения. Также можно выбирать путь по
вердикту ИИ или навыка через `from: verdict` и упорядоченную таблицу условий с
одним обязательным вариантом по умолчанию.

## Исправление неверного результата

По умолчанию ошибка схемы завершает прогон. Для ограниченной самостоятельной
доработки задайте `output.result.on_mismatch` и `rework`:

```yaml
output:
  result:
    schema: ./schemas/plan-output.json
    required: true
    on_mismatch: retry
rework:
  allowedTargets: [plan]
  workspacePolicies: [keep]
  maxLoops: 2
  commentsVar: result_errors
```

Причина проверки попадёт в `result_errors`. После исчерпания попыток прогон
завершится ошибкой; неверные данные не будут приняты.

## Файл контекста прогона

MAIster собирает намерение задачи, последние тексты и переменные узлов,
состояния проверок, объединённые значения и необязательный контекст Мозга в
`.maister/run.json` внутри рабочей копии. Каждый запрос агенту получает указатель
на файл. Он пересобирается из журнала и исключён из Git.

Это независимая от сессии общая доска. Правильность Flow опирается на журнал и
строгие шаблоны, поэтому новая или возобновлённая сессия восстанавливает
состояние.

## Публичный результат прогона

Верхнеуровневый `result.export` объявляет результат Flow для родительского
координатора или лаборатории оценки. Он указывает схему и допустимые узлы-
производители, использует закреплённую ревизию и имеет историю версий. Доработка
может сделать старую версию устаревшей.

Для контракта между прогонами используйте публичный результат. Для файлов,
изменений и отчётов используйте `output.produces[]`.

## Признаки ошибки

- Нет обязательных данных: узел не использовал назначенный ему способ передачи.
- Ошибка схемы: сравните путь поля с закреплённой схемой.
- Не определена переменная: добавьте настоящую зависимость или осознанное
  значение по умолчанию.
- Результат устарел после доработки: повторите узел-производитель.
