MCP управляются на трёх уровнях: общий каталог инсталляции, проектные привязки
и локальные серверы, требования пакетов Flow. Flow ссылается на логический
идентификатор, а проект выбирает его конкретную реализацию.

## Что потребуется

- Глобальный администратор для создания и доверия общему MCP.
- Администратор или владелец проекта для привязок и переопределений.
- Значения секретов в окружении процесса супервизора.

## Три уровня

| Уровень | Владелец | Назначение |
| --- | --- | --- |
| Инсталляция | Глобальный администратор | Переиспользуемый каталог серверов `stdio`, `sse` и `http`. |
| Проект | Администратор проекта | Явные привязки, проектные серверы и проектные переопределения. |
| Пакет Flow | Автор пакета | Переносимые требования или шаблоны без локальных секретов. |

Без явной привязки действует приоритет: проект, инсталляция, пакет. Включённая
привязка важнее приоритета. Выключенная означает явный отказ и делает ссылку
недоступной в этом проекте.

## Не храните значения секретов в MAIster

Записи окружения и заголовков MCP — это пары «имя и значение». Значение бывает
ровно двух видов:

- **ссылка** вида `env:GITHUB_TOKEN` — MAIster хранит только ссылку, а узел
  исполнения подставляет значение при запуске или соединении с сервером MCP.
  Значение `GITHUB_TOKEN` задайте в окружении супервизора на каждом узле,
  способном запустить этот MCP;
- **литерал** вида `FASTMCP_LOG_LEVEL=ERROR` — хранится и передаётся ровно так,
  как написан; тем самым вы заявляете, что это не секрет.

Подстановки внутри значения нет: `${HOME}` дойдёт до сервера как эти восемь
символов.

Для всего секретного используйте ссылку. Не помещайте ключи в `flow.yaml`,
файлы пакета, формы проекта, адреса или аргументы. В клиентские снимки и
журналы ссылка попадает как ссылка — значение за ней не появляется там никогда.
Литерал виден каждому, кто может читать каталог, поэтому форма показывает
предупреждение, если литерал стоит под именем, похожим на учётные данные
(`*_TOKEN`, `*_API_KEY`, `Authorization`, …). Это предупреждение, а не отказ.

Для сервера с bearer-аутентификацией используйте поле **bearer token env**, а не
собственный заголовок `Authorization`: укажите в нём ссылку `env:NAME`, и узел
сам соберёт `Authorization: Bearer <значение>`. Задать и то и другое нельзя.

Проектное переопределение меняет **значение**, которое проект использует для
объявленного сервером слота, и никогда не меняет имя — имя является контрактом
самого сервера. Поэтому два проекта могут направить один и тот же слот на
разные учётные данные либо один из них на обычный литерал (например, другой
`GH_HOST`), не копируя сервер и не раскрывая ни одного значения.

## Регистрация общего MCP

1. Откройте **MCP** как глобальный администратор.
2. Добавьте логический идентификатор и поддерживаемые семейства агентов.
3. Выберите `stdio`, `sse` или `http`, задайте команду либо адрес. `sse`
   устарел: спецификация MCP от него отказалась, а runner Codex не умеет его
   вовсе. Предпочитайте `http`.
4. Добавьте строки окружения (для `stdio`) или заголовков (для `sse`/`http`) и,
   если сервер этого требует, ссылку в поле bearer token env.
5. Оставьте сервер недоверенным, пока не проверите источник и команду.
6. Выдайте доверие и включите сервер.
7. Выполните **Проверить соединение** и изучите инициализацию и задержку.

Недоверенный `stdio` виден, но не запускается и не проверяется. Неуспешная
проверка сохраняет понятную причину и завершает созданный процесс.

## Разрешение требований проекта

Откройте **Проект → MCP**. Реестр требований объединяет подключённые пакеты,
включённые узлы Flow и профили платформенных агентов. Каждая ссылка имеет
состояние: привязана, разрешена автоматически, не привязана, настроена неверно
или не готова.

Для обязательной неразрешённой ссылки:

1. выберите совместимую реализацию из инсталляции, проекта или пакета;
2. создайте привязку;
3. при необходимости задайте проектное переопределение — оно меняет значение
   слота и сохраняет его имя;
4. проверьте соединение в контексте проекта;
5. убедитесь, что требование готово.

Неразрешённый обязательный MCP запрещает запуск. Необязательный исключается, а
причина сохраняется в прогоне. Недоступным считается и транспорт, который не
умеет запускающий агент: обязательный `sse`-сервер на runner Codex отклоняет
запуск ещё до создания рабочей копии, а необязательный исключается с причиной,
видимой в прогоне.

## MCP в Flow Studio

Выбирайте логические ссылки MCP в настройках узла. Пакет остаётся переносимым,
поскольку содержит идентификаторы и ссылки на переменные: при заполнении шаблона
из общего сервера литерал превращается в ссылку, поэтому общий пакет никогда не
несёт ваших значений. Привязка проекта и узел исполнения добавляют местные
детали. Разрешённый набор сохраняется в снимке
прогона.

## Признаки ошибки

| Состояние | Что проверить |
| --- | --- |
| Не привязан | Подключите требование в Проект → MCP. |
| Ошибка настройки | Исправьте отсутствующий слот или неизвестное имя в переопределении. |
| Не готов | Проверьте транспорт, адрес/команду, окружение, адаптер и последнюю проверку. |
| Нет доверия | Проверьте и явно доверьте общее определение. |
| Исключён | Откройте сведения о возможностях прогона и причину исключения. |
