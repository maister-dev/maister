MCP управляются на трёх уровнях: общий каталог инсталляции, проектные привязки
и локальные серверы, требования пакетов Flow. Flow ссылается на логический
идентификатор, а проект выбирает его конкретную реализацию.

## Что потребуется

- Глобальный администратор для создания и доверия общему MCP.
- Администратор или владелец проекта для привязок и переопределений.
- Значения секретов в окружении процесса супервизора.

## Три уровня

| Уровень | Владелец | Назначение |
| --- | --- | --- |
| Инсталляция | Глобальный администратор | Переиспользуемый каталог серверов `stdio`, `sse` и `http`. |
| Проект | Администратор проекта | Явные привязки, проектные серверы и проектные переопределения. |
| Пакет Flow | Автор пакета | Переносимые требования или шаблоны без локальных секретов. |

Без явной привязки действует приоритет: проект, инсталляция, пакет. Включённая
привязка важнее приоритета. Выключенная означает явный отказ и делает ссылку
недоступной в этом проекте.

## Не храните значения секретов в MAIster

Конфигурация MCP хранит имена переменных и заголовков. Используйте ссылку вида
`env:GITHUB_TOKEN`, а значение `GITHUB_TOKEN` задайте в окружении супервизора
на каждом узле, способном запустить этот MCP.

Не помещайте ключи в `flow.yaml`, файлы пакета, формы проекта, адреса или
аргументы. Супервизор разрешает имя только при запуске или соединении. В
клиентские снимки и журналы попадает имя, а не значение.

Проектное переопределение может сопоставить слот другому имени переменной или
заголовка. Так два проекта используют разные учётные данные для одного общего
определения.

## Регистрация общего MCP

1. Откройте **MCP** как глобальный администратор.
2. Добавьте логический идентификатор и поддерживаемые семейства агентов.
3. Выберите `stdio`, `sse` или `http`, задайте команду либо адрес.
4. Объявите имена переменных и заголовков.
5. Оставьте сервер недоверенным, пока не проверите источник и команду.
6. Выдайте доверие и включите сервер.
7. Выполните **Проверить соединение** и изучите инициализацию и задержку.

Недоверенный `stdio` виден, но не запускается и не проверяется. Неуспешная
проверка сохраняет понятную причину и завершает созданный процесс.

## Разрешение требований проекта

Откройте **Проект → MCP**. Реестр требований объединяет подключённые пакеты,
включённые узлы Flow и профили платформенных агентов. Каждая ссылка имеет
состояние: привязана, разрешена автоматически, не привязана, настроена неверно
или не готова.

Для обязательной неразрешённой ссылки:

1. выберите совместимую реализацию из инсталляции, проекта или пакета;
2. создайте привязку;
3. при необходимости задайте переопределение только из имён;
4. проверьте соединение в контексте проекта;
5. убедитесь, что требование готово.

Неразрешённый обязательный MCP запрещает запуск. Необязательный исключается, а
причина сохраняется в прогоне.

## MCP в Flow Studio

Выбирайте логические ссылки MCP в настройках узла. Пакет остаётся переносимым,
поскольку содержит идентификаторы и имена переменных. Привязка проекта и узел
исполнения добавляют местные детали. Разрешённый набор сохраняется в снимке
прогона.

## Признаки ошибки

| Состояние | Что проверить |
| --- | --- |
| Не привязан | Подключите требование в Проект → MCP. |
| Ошибка настройки | Исправьте отсутствующий слот или неизвестное имя в переопределении. |
| Не готов | Проверьте транспорт, адрес/команду, окружение, адаптер и последнюю проверку. |
| Нет доверия | Проверьте и явно доверьте общее определение. |
| Исключён | Откройте сведения о возможностях прогона и причину исключения. |
