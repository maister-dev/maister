Определение платформенного агента хранится в версионированном пакете. Проект не
создаёт свою копию файла. Он подключает агента из доверенного пакета и хранит
местные настройки раннера, триггеров, рабочей области, памяти и исполнения.

## 1. Создайте агента в пакете

Создайте локальный пакет в Flow Studio или ответвите установленный. Через дерево
файлов добавьте `maister-agents/<agent-id>.md` и заполните форму агента. Тело
файла станет системной инструкцией. В заголовке задаются:

- имя, описание, режим рабочей области и уровень риска;
- доступные источники запуска и необязательный Flow из того же пакета;
- раннер, требования MCP, защитные правила, параметры, рекомендация частной
  памяти и начальные проектные настройки.

Studio проверяет определение перед коммитом и выпуском среза. Платформенные
агенты лежат в корневой папке пакета `maister-agents/`. Файлы
`capability/**/agents/` описывают подагентов для исполнения и не попадают в
каталог платформенных агентов.

После проверки создайте коммит и срез. Установите срез или внешнюю версию,
подключите пакет к проекту и выдайте ему доверие.

## 2. Подключите агента к проекту

![Подключения и настройки агентов проекта](/assets/screens/ru/project-agents.png)

Откройте **Проект → Агенты**. В нижнем списке находятся агенты из подключённых
доверенных пакетов. Нажмите **Подключить** рядом с нужным агентом. MAIster
заполнит форму рекомендациями автора пакета, а администратор проекта сохранит
подходящие значения.

Перед включением проверьте настройки:

| Настройка | Решение для проекта |
| --- | --- |
| Переопределение раннера | Оставить значение пакета или проекта либо выбрать другой готовый совместимый раннер. |
| Рабочая область | Без репозитория, копия только для чтения или изолированное изменяемое рабочее дерево согласно определению. |
| Основная ветка | Ветка для обслуживания или запусков без задачи. |
| Политика исполнения | Какие разрешения проходят без человека и что делать при превышении бюджета. |
| Мозг проекта | Права чтения и записи выдаются отдельно. |
| Память агента | Частный `memory.md`; эта память отделена от Мозга проекта. |
| Связанные проекты | Межпроектные права и подключаемые только для чтения репозитории, если установка это поддерживает. |

Подключение служит разрешением. После выключения или удаления новые триггеры не
сработают, а действующие токены агента будут отозваны. Агент, который запускает
Flow, не использует частную память агента: его работа идёт через сессии Flow.

## 3. Настройте триггеры

В той же форме редактируются действующие привязки:

| Триггер | Настройка |
| --- | --- |
| Ручной | Запуск из строки агента или задачи. С него стоит начать проверку. |
| Cron | Выражение cron и часовой пояс IANA. Запуск выполняет общий планировщик. |
| Событие | Выбранные события MAIster, например изменение задачи или прогона. |
| Упоминание | Разрешение вызывать `@пакет:агент` в комментарии задачи. |
| Вебхук | Защищённая внешняя точка запуска и проектный токен. |
| Flow | Участие агента в Flow или запуск указанного в определении Flow из того же пакета. |

Во вкладке **Проект → Автоматизация** видны время и последний безопасный
результат cron- и событийных привязок. Для изменения вернитесь в **Агенты**.

## 4. Проверьте запуск

Сначала запустите включённого агента вручную. Самостоятельный агент создаёт
обычный прогон вида `agent`. Если агент управляет Flow из своего пакета, MAIster
создаёт прогон Flow и добавляет роль агента в кодирующие узлы.

На странице прогона видны сессия, запрос, инструменты, обращения к человеку,
токены, стоимость и результат. Если изменяемый агент выйдет за границы своего
контракта, контроль рабочей копии поместит его в карантин. Администратор проекта
должен проверить причину и снять карантин.
