Планировщик — общий фоновый такт MAIster. Платформенные агенты — именованные
исполнители из пакетов, чьи запуски используют обычный журнал прогонов,
каталог раннеров, бюджеты, разрешения и Входящие.

## Что потребуется

- Глобальный администратор для экрана Планировщика.
- Доверенный пакет с определениями `maister-agents/*.md`.
- Администратор или владелец проекта для подключения агента.

## Включение такта

В рабочем окружении предпочтительно вызывать защищённую точку планировщика из
внешней службы cron. Задайте секрет веб-процессу:

```dotenv
MAISTER_CRON_TOKEN=<храните вне системы контроля версий>
```

Вызывайте `GET` или `POST /api/cron/tick` с заголовком
`X-Maister-Cron-Token: <token>` либо `Authorization: Bearer <token>`. Пустой
`MAISTER_CRON_TOKEN` отключает точку с ответом `503`.

Для одной машины можно включить встроенный таймер:

```dotenv
MAISTER_CRON_TOKEN=<храните вне системы контроля версий>
MAISTER_SCHEDULER_TIMER_ENABLED=true
MAISTER_SCHEDULER_TICK_INTERVAL_SECONDS=60
```

Используйте один источник такта. Встроенный таймер запускается в веб-процессе и
предназначен для простой одноузловой установки; внешний cron удобнее наблюдать
в рабочем окружении.

## Экран Планировщика

Здесь видны вид задания, цель, период, следующий запуск, включение, число
ошибок, последняя попытка, разовые намерения запуска, расписания задач и
результаты сверки рабочих областей.

Один такт обслуживает системную очистку, расписания, доставку вебхуков, события,
автозапуск, автопродвижение, проверку репозиториев и pull request, лабораторию
оценки и расписания агентов. Проектные расписания меняются в **Проект →
Автоматизация**.

## Подключение платформенного агента

![Каталог и проектные привязки платформенных агентов](/assets/screens/ru/platform-agents.png)

1. Подключите и доверьте пакет агента.
2. Откройте **Проект → Агенты**.
3. Подключите агента и проверьте пакет, уровень риска и рабочую область.
4. При необходимости выберите другой раннер.
5. Отдельно выдайте чтение или запись Мозга проекта.
6. Настройте триггеры и политику исполнения.
7. Включите привязку и один раз запустите вручную до включения фоновой работы.

Отключение привязки выключает расписания и отзывает живые токены агента.

## Виды триггеров

| Триггер | Применение |
| --- | --- |
| Ручной | Проверка и запуск по запросу. |
| Cron | Регулярный мониторинг, обслуживание и улучшение знаний. |
| Событие предметной области | Реакция на задачу, прогон, проверку или другое событие MAIster. |
| Вебхук | Запуск по защищённому запросу внешней системы. |
| Привязка Flow | Использование пакетного агента как роли узла процесса. |
| Упоминание | Вызов агента через `@agent-id` в комментарии задачи. |

Все пути проходят одну проверку: пакет подключён и доверен, каталог и привязка
включены, определение корректно, раннер готов, бюджет допускает работу.

## Встроенные примеры

| Агент | Ответственность |
| --- | --- |
| `core:triager` | Предлагает Flow, раннер, ветки, приоритет, связи, уточнение и постановку в очередь. |
| `core:improver` | Находит повторяющиеся свидетельства в Мозге проекта и готовит улучшение на проверку. |
| `core:experiment-judge` | Оценивает скрытых участников исследования, но не выбирает и не продвигает победителя. |

За репозиториями и pull request следит планировщик. При конфликте он запускает
отдельную ACP-сессию для разрешения. Это не постоянно работающий скрытый агент,
а ограниченное и наблюдаемое исполнение.

## Автоматизация проекта

Вкладка объединяет разовые намерения запуска, повторяющиеся расписания задач и
действующие триггеры платформенных агентов. Ищите проблему сначала здесь. Если
проект настроен верно, переходите к глобальному Планировщику и его последней
попытке.

## Признаки ошибки

- Нет тактов: проверьте токен, внешний cron или встроенный таймер.
- Повторные ошибки: изучите тип цели и безопасный код последней попытки.
- Агент недоступен: проверьте пакет, доверие, привязку, раннер и рабочую область.
- Событийная петля подавлена: MAIster не запускает агента на собственное событие
  и ограничивает глубину цепочки.
