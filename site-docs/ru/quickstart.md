---
title: "Быстрый старт"
description: "Запустите MAIster локально, войдите, подключите репозиторий и создайте первую управляемую задачу."
---

Это руководство запускает MAIster из исходного кода на одном узле. В Docker
работает только Postgres. Веб-приложение и супервизор работают на узле, потому
что запускают адаптеры агентов и обращаются к локальным git-репозиториям.

## Требования

- Node.js 24
- pnpm
- git с поддержкой worktree
- Docker с Compose
- Локальный git-репозиторий для подключения
- Хотя бы один кодирующий агент для запуска на узле супервизора: Codex,
  Claude Code, OpenCode, Gemini CLI или MiMo

## 1. Установите MAIster

Одна команда клонирует репозиторий в `./maister`, устанавливает зависимости,
создаёт файлы окружения со сгенерированным `AUTH_SECRET`, запускает Postgres в
Docker, применяет миграции и собирает MCP-фасад:

```bash
curl -fsSL https://imaister.dev/quickstart.sh | bash
```

Скрипт лежит в репозитории:
[`scripts/quickstart.sh`](https://github.com/maister-dev/maister/blob/master/scripts/quickstart.sh).
Он не перезаписывает существующие файлы окружения, его можно запускать
повторно. Чтобы использовать уже работающий Postgres, экспортируйте `DB_URL`
перед командой; в этой базе должно быть доступно расширение pgvector.

Те же шаги вручную:

```bash
git clone https://github.com/maister-dev/maister.git
cd maister
pnpm install --frozen-lockfile
cp .env.example .env
cp web/.env.sample web/.env.local
cp supervisor/.env.sample supervisor/.env
```

Задайте в `web/.env.local` надёжный `AUTH_SECRET` (его генерирует
`openssl rand -base64 33`). Токены провайдеров и данные входа агентов храните
на хосте, а не в манифесте проекта.

## 2. Подготовьте кодирующего агента

MAIster не сможет выполнить Flow, пока на узле супервизора нет авторизованного
кодирующего агента. Команда `pnpm install` устанавливает ACP-адаптеры Claude и
Codex. Например, для входа в Codex выполните:

```bash
pnpm --filter @maister/supervisor exec codex-acp login
```

Для Claude Code, OpenCode, Gemini CLI или MiMo выполните штатный вход под тем же
пользователем операционной системы, от которого запускается супервизор.
Исполняемые файлы Gemini, OpenCode и MiMo должны быть доступны в его `PATH`.
Вместо штатного входа можно передать секреты провайдера супервизору через ссылки
на переменные окружения. Не храните секреты в манифесте проекта.

## 3. Запустите Postgres и подготовьте базу

Скрипт быстрого старта уже сделал это. Вручную:

```bash
docker compose up -d --wait postgres
pnpm --filter maister-web db:migrate
pnpm --filter maister-web db:migrate:brain
pnpm --filter @maister/mcp build
```

Для миграции Brain нужен Postgres с pgvector из Compose-файла репозитория.
Миграции создают первого администратора.

## 4. Запустите MAIster

Одна команда запускает супервизор на порту 7777 и веб-приложение на порту 3000;
вывод каждого процесса помечен его именем:

```bash
pnpm dev
```

Чтобы запускать их в разных терминалах:

```bash
pnpm --filter @maister/supervisor dev
```

```bash
pnpm --filter maister-web dev
```

Откройте `http://localhost:3000/login` и войдите как `admin@maister.local` с
паролем `maister-admin`. При первом входе MAIster попросит задать новый пароль.

## 5. Зарегистрируйте кодирующего агента

Откройте **Настройки → ACP-раннеры**, создайте профиль авторизованного агента и
не включайте его, пока диагностика не покажет состояние **Готов**. Затем
включите профиль и при необходимости назначьте его общим раннером по умолчанию.
Не запускайте первую задачу, пока нет хотя бы одного включённого готового
профиля. Подробности о маршрутах провайдеров, переменных окружения и проверке
готовности приведены в разделе [Исполнители ACP и
модели](/ru/administration/runners-and-models).

## 6. Подключите репозиторий

Откройте **Проекты → Добавить проект**, выберите существующую директорию и
отправьте форму. Если `maister.yaml` отсутствует, MAIster создаст минимальный
манифест. Существующий некорректный файл не перезаписывается.

## 7. Запустите задачу

1. Откройте доску проекта.
2. Создайте задачу и выберите Flow.
3. Запустите задачу.
4. Следите за прогоном до завершения или запроса решения человека.
5. До продвижения проверьте изменения, доказательства и состояние готовности.

Успешный результат — прогон с изолированной рабочей копией, записанной ревизией
Flow и наблюдаемым исходом. Продвижение остаётся отдельным явным действием.
