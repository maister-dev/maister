Это руководство запускает MAIster из исходного кода на одном хосте. В Docker
работает только Postgres. Веб-приложение и supervisor работают на хосте, потому
что запускают адаптеры агентов и обращаются к локальным git-репозиториям.

## Требования

- Node.js 24
- pnpm
- git с поддержкой worktree
- Docker с Compose
- Локальный git-репозиторий для подключения
- Учётные данные хотя бы одного настроенного agent runtime

## 1. Установите MAIster

```bash
git clone https://github.com/kanischev/mAIster.git
cd mAIster
pnpm install --frozen-lockfile
cp .env.example .env
```

Задайте в `.env` надёжный `AUTH_SECRET`. Токены провайдеров и данные входа
агентов храните на хосте, а не в манифесте проекта.

## 2. Запустите Postgres и подготовьте базу

```bash
docker compose up -d postgres
pnpm --filter maister-web db:migrate
pnpm --filter maister-web db:migrate:brain
pnpm --filter maister-web db:seed
```

Для миграции Brain нужен Postgres с pgvector из Compose-файла репозитория.

## 3. Запустите MAIster

Выполните команды в разных терминалах:

```bash
pnpm --filter @maister/supervisor dev
```

```bash
pnpm --filter maister-web dev
```

Откройте `http://localhost:3000/login` и войдите с данными администратора из
`.env`, использованными при seed.

## 4. Подключите репозиторий

Откройте **Проекты → Добавить проект**, выберите существующую директорию и
отправьте форму. Если `maister.yaml` отсутствует, MAIster создаст минимальный
манифест. Существующий невалидный файл не перезаписывается.

## 5. Запустите задачу

1. Откройте доску проекта.
2. Создайте задачу и выберите Flow.
3. Запустите задачу.
4. Следите за прогоном до завершения или запроса решения человека.
5. До продвижения проверьте diff, доказательства и состояние готовности.

Успешный результат — прогон с изолированной рабочей копией, записанной ревизией
Flow и наблюдаемым исходом. Продвижение остаётся отдельным явным действием.
