Проект связывает один репозиторий с задачами, процессами поставки, историей
исполнения, интеграциями и правилами контроля. Откройте проект из портфеля.

## Что потребуется

- Репозиторий [зарегистрирован как проект](/ru/guides/register-a-project).
- Проектная роль не ниже наблюдателя.

![Проект открыт на канбан-доске](/assets/screens/ru/project-board.png)

## Вкладки проекта

На узком экране строка вкладок прокручивается по горизонтали. У некоторых
разделов отдельные адреса, поэтому на фильтр или выбранный объект можно дать
прямую ссылку.

| Вкладка | Содержимое |
| --- | --- |
| Доска | Канбан задач, текущая работа, блокировки, последние прогоны и запуск. |
| Активность | События и изменения проекта по времени. |
| Обсерватория | Показатели поставки, вмешательств, доказательств, длительности и токенов в проекте. |
| Мозг | Индексированные источники, сохранённые уроки, история поиска и предложения улучшений. Скрыт, пока Мозг проекта не включён. |
| Оценки | Исследования, сравнивающие несколько прогонов одной задачи. |
| Репозиторий | [Отслеживаемые файлы, ветки и сведения системы контроля версий](/ru/product-tour/project-repository-and-packages). |
| Пакеты | [Подключённые пакеты, закреплённые версии, доверие, обновления и локальные срезы](/ru/product-tour/project-repository-and-packages). |
| Интеграции | Проектные токены API и точки внешнего доступа. |
| MCP | Требования проекта, привязки, локальные серверы, переопределения, доверие и проверка соединения. |
| Автоматизация | Разовые запуски, повторяющиеся расписания задач и привязки платформенных агентов. |
| Агенты | Агенты из подключённых пакетов и их проектные исполнители, условия запуска, доступ к Мозгу, ветки и политики. |
| Участники | Состав проекта и роли владельца, администратора, участника и наблюдателя. |
| Вебхуки | Исходящие подписки на события и диагностика доставки. |
| Настройки | Значения по умолчанию, включение Мозга, поведение агентов и правила Git/продвижения. |

## Порядок настройки нового проекта

1. Проверьте репозиторий и основную ветку в **Репозитории** и **Настройках**.
2. Подключите доверенный пакет в **Пакетах**.
3. Разрешите требования пакета в **MCP**.
4. Задайте значения по умолчанию и подключите нужных агентов в **Агентах**.
5. Добавьте людей в **Участниках**, внешние программы в **Интеграциях**.
6. Создайте задачу на **Доске**. Включайте расписание в **Автоматизации** после
   успешного ручного прогона.

Так каждая причина отказа запуска указывает на конкретный ещё не настроенный
слой.

## Пакеты внутри проекта

Проект хранит используемую ревизию установленного пакета и доверие к её
исполняемому содержимому. По имени пакета открывается состав, по Flow — граф.
Для изменения неизменяемой установленной ревизии выберите **Открыть в Studio**
и создайте ответвление.

Локальный срез подключается как обычная установка. Если его имя совпадает с
именем исходного пакета, переименуйте локальный пакет в Studio, зафиксируйте
изменение и создайте новый срез.

## Проектные роли

| Роль | Значение |
| --- | --- |
| Наблюдатель | Просмотр проекта, прогонов, доказательств и исследований. |
| Участник | Редактирование и запуск обычной работы, ответы на запросы человека. |
| Администратор | Дополнительно управляет участниками, агентами, пакетами, интеграциями и настройками. |
| Владелец | Сейчас имеет те же проектные права, что и администратор, и обозначает ответственность за проект. |

Глобальные администраторы считаются владельцами. Сначала создайте или
активируйте учётную запись человека, затем добавляйте его в проект.

## Готовность к запуску

Для управляемой задачи нужны корректный репозиторий, запускаемый Flow и готовые
раннеры для всех его сессий. Запуск недоступен, если пакет не получил доверие,
MCP не привязан, раннер недоступен, Flow несовместим или связь задач блокирует
допуск. Интерфейс сохраняет объект и показывает причину, не подбирая молча
неподходящую замену.
