Во вкладках **Репозиторий** и **Пакеты** код проекта связывается с
версионированными процессами, которые с ним работают. Участники проекта могут
просматривать оба раздела. Администраторы проекта управляют подключениями, а
глобальный администратор выдаёт доверие исполняемой ревизии пакета.

## Просмотр репозитория

![Просмотр репозитория проекта](/assets/screens/ru/project-repository.png)

Откройте **Проект → Репозиторий**. В дереве видны файлы, которые отслеживает
Git. Выберите файл, чтобы прочитать его, и нужную ветку или ревизию.

Этот раздел работает только на чтение. Прогон меняет код в своей изолированной
рабочей копии, а проверяющий смотрит изменения на вкладке разницы конкретного
прогона. Неотслеживаемые и исключённые через `.gitignore` файлы в проектном
браузере не показываются.

Если раздел не может прочитать репозиторий, проверьте путь проекта и право
участника `readRepoFiles`. Адрес страницы не принимает путь на машине.

## Подключение пакета к проекту

![Пакеты, подключённые к проекту](/assets/screens/ru/project-packages.png)

1. Откройте **Flow Studio → Источники** и обновите источник с нужным пакетом.
2. Установите выбранную версию. MAIster запишет неизменяемую ревизию, но не
   будет исполнять код пакета.
3. Вернитесь в **Проект → Пакеты** и нажмите **Подключить пакет**.
4. Выберите установленный пакет и ревизию. Просмотрите состав: процессы,
   агенты, навыки, MCP, ограничения, схемы и сценарии.
5. Для запуска исполняемого содержимого глобальный администратор должен выдать
   ревизии доверие.
6. Привяжите раннеры и закройте требования MCP в соответствующих вкладках
   проекта.

Подключение действует в одном проекте. MAIster записывает выбранную версию в
`maister.yaml`. Предупреждение о записи означает, что подключение уже сохранено
в базе, а файл репозитория нужно поправить отдельно.

## Подключение локального ответвления

Установленная ревизия не редактируется. Для изменения пакета:

1. Откройте пакет в Flow Studio и выберите **Создать ответвление**.
2. Измените локальный пакет, проверьте разницу и создайте коммит.
3. Выпустите **срез** этого коммита. Срез станет новой неизменяемой установкой.
4. Подключите срез в **Проект → Пакеты** и после проверки выдайте доверие.

Локальный пакет хранит связь с исходной ревизией. **Сравнить с исходной
версией** показывает расхождения, а **Обновить из исходного пакета** выполняет
трёхстороннее слияние. Конфликты остаются в редакторе до решения человеком.

Имя пакета участвует в идентификации подключения. Переименуйте локальный пакет
до выпуска среза, если исходный пакет и ответвление нужны в проекте одновременно.

## Что закрепляет прогон

Новый прогон сохраняет используемые ревизии пакета и Flow. Последующее
обновление пакета не меняет граф, инструкции агентов, доказательства и историю
результатов уже созданного прогона. MAIster не даст отключить пакет, пока от его
ревизии зависит активный прогон.
